# Установка раздела переписок

Один файл, который админка потребителя подключает скриптом. Скрипт объявляет тег `rt-chat-talks`;
где разделу стоять и какого он размера, решает админка:

```html
<script src="https://bus.example/talks.js"></script>
<rt-chat-talks site="ключ-площадки" sign-url="/internal/chat-sign"></rt-chat-talks>
```

Тег рисует рамку со страницей переписок сервиса. Стили админки и стили страницы так не встречаются
вовсе, а каркас в чужую админку не приезжает.

Ключ площадки открыт и лежит в коде страницы: прав, кроме операций площадки с адресов её списка, он
не даёт. Адрес сервиса скрипт берёт оттуда, откуда приехал сам; площадка, которая держит сервис на
своём поддомене, называет его признаком `service`, а иной путь страницы — признаком `page`.

**Подпись потребитель выдаёт сам.** Признак `sign-url` называет точку его собственного сервера; она
отвечает минутой и знаком:

```json
{ "at": 1780000000000, "signature": "64 знака" }
```

Знак считается тайной площадки — той же, которой сервис подписывает свои вызовы наружу. Тайна
остаётся на сервере потребителя: скрипт её не знает и подписи не считает. Образец такой точки —
`apps/message-bus-admin-e2e/stand/serve-admin.mjs`.

- Что показывает страница и чем закрыта — `docs/specs/chat/embedded-talks/spec.md`.
- Сама страница — `apps/chat-talks-page`.
- Сборка: `pnpm exec nx build chat-talks-embed`, выход — `dist/apps/chat-talks-embed/talks.js`.
