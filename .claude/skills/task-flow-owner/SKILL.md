# Work conduct — the owner's word and the session

Rule under the law `docs/constitution/work-conduct.md`. Cold part: `pitfalls.md`; every article whole — `pitfalls-2.md` of `task-flow`.

## How the law applies here

- **What needs the owner's word is taken from a list, not appraised on the spot.**
- **A stop the owner sets on a later step is written down the moment it is said.**
- **A reply to the owner's order begins with the result, not with intent or its justification.**
- **The last run of the main branch is read first thing in a session and after every known merge.**
- **A session does not start work by itself.** An empty message, one word or one path order no work.
- **A refusal by an external limiter removes the way, not the task.** The way is taken from the guard that already described this fix.
- **A question written by a past session does not become a question to the owner.** It goes to the handover's author; some are closed by a work step.
- **The owner's instruction holds until they cancel it, and a new fact against it is a line in the reply about the cost, not a new question.**
- **An answer in the owner's message counts the same as an answer in a document.**
- **The owner's word about the design is a task setting, not a decision.** It is checked against the tree before the edit; diverged — the owner is asked.
- **A tool the owner named is used, and a substitute is named in the same reply.** With the reason.
- **A rule of the tree outweighs a standing instruction of the host.**
- **An instruction to work by a rule or by the progress is an instruction to do all its steps, including those that change history.**
- **A word for a new notion is looked up in the tree's glossary.**
- **Work ordered in words becomes a task in the queue in the same turn.** Postponed work names a date.
- **An improvement of a rule names the metric it should move, and the next report judges it.**
- **Work is judged by the role `goal-critic` against the owner's words.**
- **A mission is set by the owner.** A session only proposes a wording and waits for approval.
- **Building by a sample begins with reading the sample itself, whole, by walking the directories.**
- **Exploration of a tree that holds a code graph begins with the graph.**
- **The path to a sample lies outside the history, the permission to work outside the epic — in the main branch.**

## The agent does the work of the task here

The tree's own section, by the owner's word of 19.11.2026: the agent leads all the work on code,
tasks and their implementation, and the owner fixes nothing of it for the agent.

- **Every step of a task is the executor's own, a step written as the owner's included.** A
  progress line «the owner writes it himself» or an epic row with the owner's step is done by the
  executor in the same work; it never becomes a menu option for the owner.
- **The owner is asked only for decisions and approvals.** A product choice, the approval of a
  plan, and a button a guard keeps with a person stay with the owner; code, tasks, checks and
  their fixes do not.
