# task-flow-owner — what is its own here

The bindings of this tree for the part `task-flow-owner` of the work-conduct rule, next to its `SKILL.md`.
The names of the course of work and the rest of what is its own here are in the companion of
`task-flow`.

## Where the articles are carried out

The first column is the article verbatim, as it is written in the section «How the law applies
here».

- **A refusal by an external limiter removes the way, not the task.** — **Not carried out.** The refusal comes from the runtime environment, not from a guard of the tree: no check sees its text, and the way named by a neighbouring guard cannot be tied to it by a machine. This is held by the article and by the word to the owner about what is left.
- **An instruction to work by a rule or by the progress is an instruction to do all its steps, including those that change history.** — Not checked: the owner word lies outside the tree, and there is nothing to tie it to what the executor did next. It is held by this article, and the exit guard holds a turn whose scenario is not over.
- **An improvement of a rule names the metric it should move, and the next report judges it.** — `.claude/skills/task-flow-cycle/SKILL.md:Metric` — the line of the task; the release of the package holds it by `tools/release-metric.mjs:lineOf`, and a task without the line is stopped by nothing.
- **Work is judged by the role `goal-critic` against the owner's words.** — `.claude/workflows/plan.js:goal` — the call on the plan, and `.claude/workflows/feature.js:goal` — the call on the result; a run where the role did not start fails. Before a PR it is a step of the pattern `task-flow-close`. The delivery guard reads the section heading only in a body passed to `gh pr create`. Nothing checks that a session left the reply unedited: the role itself reads the finished PR description against the replies.
- **A mission is set by the owner.** — **Not checked.** The missions document is `docs/product/missions.md`, and a proposal looks like any other edit of it. It is held by the role `.claude/agents/product-strategist.md` and by the status line of the document.
- **What needs the owner's word is taken from a list, not appraised on the spot.** — **Not checked.** The list stands in the agent config, `.claude/settings.json`, under the access decisions key. A machine has no executable sign for «appraised on the spot»: it sees the call, not what decided it
- **A stop the owner sets on a later step is written down the moment it is said.** — `tools/flow-guard.mjs:judgeDefer` — the mark «отложено» is set and lifted only by the owner's last word naming the task; a stop for the turn is read by `tools/task-flow/measure/owner.mjs:saidStop`. Writing it at once is held by the executor
- **A reply to the owner's order begins with the result, not with intent or its justification.** — **Not checked.** No gate reads the reply to the owner: the texts rule is called only on `.md`, and the form of a remark is judged by nothing. It is held by the author
- **The last run of the main branch is read first thing in a session and after every known merge.** — `.claude/hooks/main-run-context.sh:reading` — the start hook prints the line of `tools/main-run.mjs`. After a merge the command is called by hand. Here the pipeline wakes on `pull_request` alone, so the line says the run was not read. Scenarios `SC-AK-1105`, `SC-AK-1106`.
- **A session does not start work by itself.** — **Not checked.** The model hook no longer judges edits under `apps/` or `libs/`; the plan guard `.claude/hooks/task-flow-guard.sh` refuses an edit of application code without a task folder, and whether the owner ordered the work no machine judges
- **A question written by a past session does not become a question to the owner.** — **Not checked.** The model hook before a question, `.claude/hooks/ask-judge.md`, reads the owner's messages and the rules, not the origin of a question
- **The owner's instruction holds until they cancel it, and a new fact against it is a line in the reply about the cost, not a new question.** — `.claude/hooks/ask-judge.md:answered` — the model hook before a question judges it: a question whose decision the owner already gave in this conversation is held, with the owner's words quoted. Whether the reply names the cost of a new fact in a line is not judged
- **An answer in the owner's message counts the same as an answer in a document.** — `.claude/hooks/ask-judge.md:answered` — the model hook reads the owner's messages of the whole task from the turn record and holds a question already answered there. A question asked in prose is judged by `.claude/hooks/turn-judge.md` at the end of the turn
- **The owner's word about the design is a task setting, not a decision.** — **Not checked:** the reading of the word is invisible to a machine. It is held by the grill — the six mandatory questions of the pattern `task-flow-start` ask exactly about what the owner word named, and reconciling the word with the tree costs one search over the specs and the models.
- **A tool the owner named is used, and a substitute is named in the same reply.** — **Not checked:** whether two tools are equivalent is the owner's call, and no guard reads the request against the tools a turn used.
- **A rule of the tree outweighs a standing instruction of the host.** — **Not checked:** the host's instruction lives in the session context and not in the tree; the difference is found only by reading both.
- **Work ordered in words becomes a task in the queue in the same turn.** — **Not checked:** the owner request sounds as a remark, not as a call, and it has no sign. The queue audit sees a draft folder only after a week — that is the threshold of an abandoned grill, while the work is lost within the same hour
- **A word for a new notion is looked up in the tree's glossary.** — `.claude/hooks/glossary-load.sh:GLOSSARY` — the glossary `docs/GLOSSARY.md`, its own sections in `.claude/rt-kit/overrides/docs/GLOSSARY.md`
- **Building by a sample begins with reading the sample itself, whole, by walking the directories.** — **Not checked.** What the session opened leaves no trace in the tree: the guards judge an edit, not a read. It is held by this article and by the analysis, the record «2026-08-16-sample-judged-by-one-file» in the intake
- **Exploration of a tree that holds a code graph begins with the graph.** — **Not checked.** `has` in `.claude/rt-kit.json` names `graph`, and the pattern `.claude/skills/task-flow-graph/SKILL.md` is laid out with this tree's section from `.claude/rt-kit/overrides/patterns/task-flow-graph.needs-graph.md`. The graphs are built by `tools/graphs-build.mjs`; which exploration a turn began with leaves no trace in the tree, and it is held by the pattern
- **The path to a sample lies outside the history, the permission to work outside the epic — in the main branch.** — `tools/tree-assignment.mjs:assignmentFault` — the permission is a row of `.claude/rt-kit/assignments.md`, read by `.claude/hooks/tree-assignment-guard.sh` and `.claude/hooks/epic-stop-guard.sh`; work outside an epic is created by the owner's word through `tools/task-new.mjs` with `--outside-epic`. The sample path is not checked: it lies in `.claude/handoff/`, which is in `.gitignore`, and is printed by the `SessionStart` hook in `.claude/settings.local.json`
