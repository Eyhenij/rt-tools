# Поставка — формы и подробности этого дерева

Приложение к `implementation.md` рядом: колонки доски, форма имени ветки, формы неизданного
раздела журнала изменений и описания PR.

## Колонки доски

Поле `Status`, в порядке хода работы:

```
🆕 New → 📋 Backlog → 🔖 Ready → 🏗 In progress → 👀 In review → ✅ Done → Deployed
```

`scripts/board.sh status <номер> "<текст>"` ищет по части имени без учёта регистра:

| что произошло   | аргумент команды |
| --------------- | ---------------- |
| работа началась | `"progress"`     |
| PR открыт       | `"review"`       |
| влито           | `"done"`         |
| опубликовано    | `"deployed"`     |

Неоднозначный или несовпавший текст отбивается вслух, а не угадывается.

## Краткое имя в ветке

- Строчными, слова через дефис, только латиница.
- Служебные слова выбрасываются; остаётся три–пять значащих слов из заголовка задачи.
- Задача №14 «Store shouldn't return undefined values» → `fix/14-store-undefined-values`.

Род правки берётся по существу работы и совпадает с родом будущего коммита: `feat`, `fix`,
`refactor`, `docs`, `chore`, `style`, `test`, `perf`.

## Задача заводится под уже начатую работу

Если ветка или PR появились раньше задачи:

1. `command gh issue create --title "<заголовок>" --body "<что и зачем>"`.
2. `scripts/board.sh add <номер>`.
3. `Closes #<номер>` в теле PR.
4. Переименовать ветку в `<род>/<номер>-<имя>` можно только пока PR не открыт: переименование
   ветки с открытым PR его рвёт — тогда открывается новый.

## Связь PR и задачи

- `Closes #<номер>` в теле PR закрывает задачу при слиянии; колонку всё равно двигают явно.
- Поле доски со связанными PR заполняется само, как только PR ссылается на задачу.

## Неизданный раздел журнала изменений

Дописывается над последним выпущенным заголовком. Берутся только подходящие разделы; заголовки
совпадают со сборщиком журнала, чтобы выпуск свернул их без правки.

```md
## [Unreleased]

### Features

- **<область>:** <что теперь может потребитель, в терминах этого дерева>

### Bug Fixes

- **<область>:** <что было сломано и починено>

### BREAKING CHANGES

- **<область>:** <что снято или переименовано> + переход
```

- `<область>` совпадает с областью коммита, например `rt:ui-kit`.
- Один пункт на видимую потребителю правку, а не на коммит. Правки оформления, обслуживания и
  текстов строки в журнале не зарабатывают.
- Раздел уже есть — дописываются его подразделы, второй такой же не заводится.
- Заголовок коммита: `docs(<область>): add unreleased notes for <кратко>`.

## Описание PR

Пишется в файл в рабочем каталоге сессии и передаётся ключом `--body-file`.

```md
## Summary

<одно–три предложения: что и зачем>

- **<главная правка>** — <подробности: новая поверхность, входы, поведение>

## Changes

- <по группам файлов: добавлено / снято / изменено>

## ⚠️ Breaking changes # раздела нет вовсе, если ломающих правок нет

<что ломается> и как перейти:

- `<как было>` → `<как стало>`

## Test plan

- [ ] `pnpm run build:ui-kit`
- [ ] `pnpm test`
- [ ] `pnpm run lint`
- [ ] <проверка на витрине, если правка видимая>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

## Готовые вызовы

```bash
scripts/gather-context.sh main

command git push -u origin "$(command git rev-parse --abbrev-ref HEAD)"

command git add projects/ui-kit/CHANGELOG.md
command git commit -m "docs(rt:ui-kit): add unreleased notes for ..."
command git push

command gh pr create --base main --head "<ветка>" \
  --title "<заголовок по формату коммита>" --body-file <рабочий каталог>/pr-body.md

# уже открытый PR правится, а не дублируется
command gh pr edit <номер> --body-file <рабочий каталог>/pr-body.md
```

## Ловушки

- Голый `gh` или `git` на этой машине уходит в выбор учётной записи — вызов с приставкой
  `command`.
- Слияние PR — обычное: сжатое в репозитории выключено.
- `gh pr create` предупреждает о неподготовленных правках; это законно, пока они не часть этого
  PR. Индекс наполняется явными путями.
- Выпущенные разделы журнала не трогаются, правится только неизданный.
- `board.sh` находит доску по заголовку под владельцем репозитория, разобранным из указателя на
  удалённый репозиторий, — работает в любом клоне без правки идентификаторов. Заголовок
  перебивается переменной `RT_BOARD_TITLE`.
