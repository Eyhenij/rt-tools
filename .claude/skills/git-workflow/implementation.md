# git-workflow — как это устроено здесь

Имена этого дерева при правиле `SKILL.md` рядом. Отдельный файл потому, что правило говорит
приёмом и переносится между репозиториями целиком, а всё, что ниже, верно только здесь и
устаревает при каждом переименовании.

Главное отличие от общего случая: слияние в главную ветку здесь ничего не выкатывает. Дерево
публикует пакеты, и публикация — отдельный ручной запуск рабочего потока, а не следствие
слияния.

## Как это называется здесь

| В правиле                      | Здесь                                                                                                    |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- |
| главная ветка                  | `main`                                                                                                   |
| очередь работ                  | доска проекта на GitHub; задача — это issue на ней                                                       |
| колонка задачи                 | поле `Status`: «In progress» при заведении ветки, «In review» при открытии PR                            |
| ключ задач                     | `RT` — назван в `.claude/rt-kit/checks.json`, ключом `board.taskKey`                                     |
| заголовок задачи               | `[RT-<номер задачи>] <Что не так>`: `[RT-88] Add select button component`                                |
| имя ветки                      | `RT-<номер задачи>-<краткое имя>`: `RT-88-add-select-button`                                             |
| род правки                     | `feat`, `fix`, `refactor`, `docs`, `chore`, `style`, `perf`, `test`, `build`, `ci`                       |
| строка связи с задачей         | `Closes #<номер>` в теле PR                                                                              |
| выкатка                        | ручной запуск рабочего потока публикации, по потоку на пакет                                             |
| журнал изменений               | `projects/<пакет>/CHANGELOG.md`, раздел `## [Unreleased]`                                                |
| учётная запись машинной работы | `rt-tools-agent` — ею подписан коммит, ею заводится задача и открывается отчёт; ревьювером она не бывает |

## Где это лежит

| Что                                | Где                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------- |
| токен машинной учётной записи      | `~/.config/rt-tools-bot-token` — вне дерева, в историю не попадает                    |
| работа с доской                    | `.claude/skills/git-workflow/scripts/board.sh`                                        |
| сбор состояния ветки перед PR      | `.claude/skills/git-workflow/scripts/gather-context.sh`                               |
| формы описания PR и журнала        | `.claude/skills/git-workflow/REFERENCE.md`                                            |
| гард главной ветки, поставки, пуша | `.claude/hooks/git-guard-main.sh`, `git-guard-delivery.sh`, `git-guard-push-tests.sh` |
| гард пары «правка и её документ»   | `.claude/hooks/docs-guard.sh`                                                         |
| профиль дерева для гардов          | `.claude/rt-kit/project.sh`                                                           |
| проверка заголовка коммита         | `commitlint.config.cjs`, вызывается хуком гита из `.husky/commit-msg`                 |
| потоки публикации                  | `.github/workflows/` — `publish.yml` и по потоку на пакет                             |

## Что переносится в новое рабочее дерево

`git worktree add --detach <путь> origin/main` разворачивает индекс и больше ничего. Руками
копируется:

| Что                                | Зачем                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------- |
| `.env`                             | ключи, которыми живут скрипты дерева                                                  |
| `.claude/settings.local.json`      | локальные разрешения; без них заход спрашивает подтверждение на каждую команду        |
| `.claude/rt-kit/browser-device-id` | закреплённый идентификатор устройства браузера — новый не заводится и не спрашивается |

Следом `pnpm install` в новом дереве: `node_modules` рабочие деревья не делят.

## Где исполняются статьи

Первая колонка — статья дословно, как она написана в разделе «Как закон применяется здесь»
(жирная часть пункта). Статья без строки и строка без статьи — расхождение: правило обещает
то, чего в дереве нет, либо в дереве стоит то, о чём правило молчит.

| Статья                                                                                        | Где исполняется                                                                                                                                                                                                                         |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Коммит в главную ветку отбивается гардом.                                                     | `.claude/hooks/git-guard-main.sh`, зарегистрирован в `.claude/settings.json` на вызов оболочки.                                                                                                                                         |
| Ветка без номера задачи PR не открывает.                                                      | `.claude/hooks/git-guard-delivery.sh` + `rt_task_branch_ok` в `.claude/rt-kit/project.sh` — форма `RT-<номер>-<имя>`.                                                                                                                   |
| Заведённая задача подтверждается ответом очереди работ, а не выводом команды заведения.       | `tools/task-new.mjs:describeTaskState` — пятым шагом команда спрашивает борду по номеру и печатает присутствие, колонку и исполнителя; расхождение кончает её ненулевым кодом.                                                          |
| Номер ветки и номер в заголовке PR сверяются на месте, а состояние задачи — по борде.         | `git-guard-delivery.sh` читает номер из имени ветки формы `RT-<номер>-<имя>` и сверяет его с номером в заголовке PR. Второй ярус — `npm run check:board`, он же показывает исполнителя и колонку.                                       |
| Колонка задачи двигается тем же движением, что и работа.                                      | `scripts/board.sh status <номер> "progress"` сразу за заведением ветки и `... "review"` сразу за открытием PR.                                                                                                                          |
| Отставшая колонка находится сверкой очереди, а не глазами.                                    | `scripts/board.sh list` — колонка, род и номер задачи в одной строке; сверяется с открытыми PR.                                                                                                                                         |
| Задачи, чинящиеся одной правкой, сливаются до слияния ветки.                                  | Держится разбором: поглощённая задача дописывается в первую и уходит с доски `scripts/board.sh` до слияния PR.                                                                                                                          |
| Слияние в главную ветку выкатывает прод.                                                      | Не исполняется и не должно: слияние здесь ничего не публикует. Пакет уезжает ручным запуском потока публикации после поднятия версии.                                                                                                   |
| Признак режима объявлен в образе, а не только в составе прода.                                | Не применимо: образов и прода в дереве нет.                                                                                                                                                                                             |
| Образы выкатываются по хешу коммита, а не по метке «последний».                               | Не применимо по той же причине.                                                                                                                                                                                                         |
| Цепочка миграций прогоняется с пустого хранилища до слияния.                                  | Не применимо: хранилища и миграций в дереве нет.                                                                                                                                                                                        |
| Документ едет в том же коммите, что и правка.                                                 | `.claude/hooks/docs-guard.sh` + `rt_docs_pair_for` в профиле: описание компонента второго кита рядом с ним и описание набора токенов при правке самих токенов.                                                                          |
| Заголовок коммита сверяется с форматом на месте.                                              | `.husky/commit-msg` зовёт `commitlint` с набором `@commitlint/config-angular` и `config-conventional`.                                                                                                                                  |
| Перед пушем прогоняются все линтеры, а не один.                                               | `.claude/hooks/git-guard-push-tests.sh` + `rt_push_checks`: линт, типы и спеки по задетому, затем отдельно линтер стилей — линтер кода файлы стилей не читает вовсе.                                                                    |
| Набор гейта пуша не бывает уже набора конвейера.                                              | `tools/check-push-gate.mjs:pipelineSteps` против `pushGate` в `.claude/rt-kit/checks.json`; сама проверка стоит строкой в `rt_push_checks`. Шагов конвейера одиннадцать: три закрыты набором, восемь объявлены исключениями с причиной. |
| После вливания главной ветки набор проверок пересматривается по тому, что ветка везёт теперь. | Не проверяется ничем: гард видит набор, но не знает, что именно принесло вливание. Держится чеклистом перед публикацией отчёта.                                                                                                         |
| Утверждение о главной ветке делается по удалённой ссылке, а не по локальной.                  | `.claude/hooks/git-guard-push-tests.sh:main_branch` — база берётся у удалённой ссылки, а не у локальной вершины. Само утверждение владельцу этим не стережётся: сетевой вызов в разборе команды падал бы вместе со связью.              |

## Что ещё стоит знать при чтении кода

- Слияние PR — только обычным слиянием: сжатое слияние в репозитории выключено.
- **`lint-staged` переформатирует файлы прямо в коммите.** Замена по шаблону, написанная под
  однострочный биндинг, после первого коммита промахивается: форматтер уже разложил его на
  несколько строк, и следующая такая же правка срабатывает не везде. Массовая правка шаблонов
  либо идёт до первого коммита целиком, либо повторяется по факту — а не считается сделанной по
  числу совпадений.
- Файлы к коммиту добавляются явными путями. Сторонние инструменты добавляют в индекс сами,
  поэтому перед каждым коммитом читается, что в индексе на самом деле.
- Голый вызов `git` или `gh` на этой машине может уйти в оболочку выбора учётной записи;
  надёжный вызов — с приставкой `command`.
- **`gh` залогинен учётной записью владельца, и сам по себе от машинной не работает.** Всё, что
  должно идти от неё — заведение задачи, открытие отчёта, перевод колонки, — зовётся с токеном
  в окружении вызова:

    ```bash
    GH_TOKEN=$(cat ~/.config/rt-tools-bot-token) command gh pr create …
    ```

    `gh auth login` под машинной учётной записью не делается: он затрёт вход владельца в
    `hosts.yml`. Токен читается в окружение вызова и не печатается.

- **Машинная учётная запись ограничена хостингом, и заведённое ею видно только ей.** С 14 августа
  2026 года её профиль отвечает «не найдено» всем остальным, лимит запросов у неё срезан до
  анонимного, а задачи, заведённые её токеном, для владельца и для всех сверок не существуют.
  Проверяется одним вызовом: `gh api users/rt-tools-agent` — «не найдено» означает, что
  ограничение ещё стоит. Пока оно стоит, задачи заводятся учётной записью владельца, и её имя
  передаётся ключом `--assignee`: назначение исполнителем по умолчанию падает на скрытом имени.
  Шестнадцать задач так и были заведены дважды — разбор в `docs/postmortems/`, запись за тот же
  день о заведённом, которое не проверено со стороны.

- **Пуш идёт тем же токеном, а не тем, что отдаёт связка ключей.** Помощник `osxkeychain`
  отвечает учётной записью от чужого дерева, и пуш падает на `403` с именем, которого здесь
  быть не должно. Адрес удалённого репозитория токеном не переписывается — он лёг бы открытым
  текстом в `.git/config`:

    ```bash
    git -c credential.helper= \
        -c credential.helper='!f() { echo username=x-access-token; echo "password=$(cat ~/.config/rt-tools-bot-token)"; }; f' \
        push -u origin <ветка>
    ```

- **Подпись коммита задаётся переменными самой команды**, а не `git config user.*`: конфиг общий
  и переписал бы подпись владельцу. Подписи в дереве нет — `commit.gpgsign` включён, а ключ
  лежит за менеджером паролей, поэтому машинный коммит идёт с `-c commit.gpgsign=false`:

    ```bash
    GIT_AUTHOR_NAME="rt-tools-agent" GIT_AUTHOR_EMAIL="314674161+rt-tools-agent@users.noreply.github.com" \
    GIT_COMMITTER_NAME="rt-tools-agent" GIT_COMMITTER_EMAIL="314674161+rt-tools-agent@users.noreply.github.com" \
        git -c commit.gpgsign=false commit -F -
    ```

- Журнал изменений при выпуске собирается из заголовков коммитов: выпущенные разделы не
  переписываются, дописывается только неизданный. Едет он отдельным коммитом после пуша ветки.
- Планы работ живут в репозитории — `docs/plans/<тема>.md` рядом с `docs/adr/`, и едут тем же
  коммитом, что и работа, которую описывают.

## Чем это проверяется

- Гарды сами: `git-guard-main.sh` на коммите, `git-guard-delivery.sh` на заведении ветки и
  открытии PR, `git-guard-push-tests.sh` на пуше.
- От кого пойдёт вызов — до вызова, а не по автору уже открытого отчёта:

    ```bash
    GH_TOKEN=$(cat ~/.config/rt-tools-bot-token) command gh api user -q '.login'   # rt-tools-agent
    ```

- `pnpm run check:affected` — то же, что гоняет гард пуша, только руками.
- `scripts/board.sh list` — сверка колонок с открытыми PR.
