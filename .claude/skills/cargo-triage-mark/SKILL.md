# Чтение груза и отметка его записей

Паттерн правила `cargo-triage`. Что при этом должно быть верно — закон
`docs/constitution/work-conduct.md`.

Вызовы ниже идут строкой запуска и закрыты по-разному: чтение — парой учётной записи службы,
отметка — токеном дерева. И пара, и токен лежат вне дерева, и без них команда отбивает вызов,
не ходя в сеть.

## Когда брать

- Начинается разбор груза, и надо забрать то, что приехало.
- Разбирается приехавший груз, и по записи принято решение.
- Правка по записи влита в главную ветку.
- Опубликована редакция, увёзшая починку к потребителю.
- Вызов отметки вернул отбитую строку.

## Что читается раньше вызова

Список неразобранного забирается командой чтения, отбором по состоянию «новое» и порядком
приезда. Пока список не сужен, разобранное и нетронутое стоят вперемешку, и разбор идёт по
второму кругу.

```bash
npm run cargo:pull -- --kind proposal --state new
npm run cargo:pull -- --kind postmortem --state new --tree <признак дерева>
```

Строка списка несёт ключ отметки, чем запись названа, чьё это дерево, состояние и начало
текста. Ключ берут отсюда и подставляют в отметку как есть: посчитанный по своему диску, он
находит только то, что там ещё лежит.

Тексты целиком печатает `--text` — их читают перед решением; `--brief` тексты не дочитывает и
годится только для обзора: без текста у предложения нет и ключа.

Имя команды, адрес приёма, место пары и слова состояний у каждого дерева свои — они названы в
`implementation.md` правила. Ниже они стоят так, как их зовёт пакет.

## Взятие в работу: задача и отметка одним ходом

Сначала задача — иначе отметка говорит, что запись взяли, и молчит о том, где идёт работа:

```bash
npm run task:new -- --title '<что не так>' --slug <короткое-имя> --label bug < тело.md
```

Отметка идёт следом, тем же ходом, и несёт все записи, которые эта задача закрывает:

```bash
npm run cargo:mark -- --state in_work \
    --postmortem 2026-08-14-structure-invented-beside-the-sample.md \
    --postmortem 2026-08-15-guard-denied-shell-wrote-anyway.md \
    --proposal <признак предложения>
```

Род записи называется своим доводом: разбор происшествия — именем файла, предложение —
признаком текста. Записи обоих родов едут одним вызовом.

Сухим прогоном смотрят, что уехало бы, — он ничего не отправляет и следа наружу не оставляет:

```bash
npm run cargo:mark -- --state in_work --postmortem <файл> --dry-run
```

Сухой прогон вместо настоящего вызова оставляет запись в прежнем состоянии. Отметкой он не
считается.

## Починка: переход вместе с ответом на «чем»

Ставится после того, как правка влита в главную ветку, — не по открытой заявке:

```bash
npm run cargo:mark -- --state fixed \
    --postmortem <файл> \
    --fix 'заведена статья правила о разборе груза и паттерн с готовыми вызовами'
```

Текст отвечает на «чем», а не на «где»: статья правила, гард, проверка, правка кода. Без него
строка отбивается — переход в починку без ответа на «чем» приёмник не принимает.

## Выпуск: версия называется тем, кто публикует

Идёт тем же движением, что и публикация редакции:

```bash
npm run cargo:mark -- --state released --postmortem <файл> --release 'rt-agent-kit@0.10.1'
```

Версия — та, которой назван выпуск, увёзший починку. Не номер редакции приёмника и не время
выкатки.

## Ответ читается

Вызов отвечает тремя числами и списком:

```
переведено 2, уже стояло 1, отбито 1
  строка 3: <ключ> — записи у дерева нет
```

- **Переведено 0, уже стояло N** — этот разбор не двинул ничего: записи отмечены раньше либо
  ключи названы не те.
- **Отбито N** — эти записи остались там, где были. Причина названа при строке, и повтор того
  же вызова отбивается ровно так же.

Причины отбоя и что делать с каждой:

| Что сказано            | Что это значит                                 | Что делать                           |
| ---------------------- | ---------------------------------------------- | ------------------------------------ |
| записи у дерева нет    | ключ назван не тот либо запись прислало не оно | сверить ключ со списком в админке    |
| переход не разрешён    | шаг через состояние либо ход назад             | пройти состояние, которое пропустили |
| перехода без текста    | починка без ответа на «чем»                    | добавить довод с текстом починки     |
| текста не при том шаге | текст приехал с переходом, который не починка  | убрать довод либо сменить состояние  |
| перехода без версии    | выпуск без ответа на «где искать фикс»         | добавить довод с версией выпуска     |
| версии не при том шаге | версия приехала с переходом, который не выпуск | убрать довод либо сменить состояние  |

## Ловушки

- **Вызов без токена отбивается без сети.** Токен лежит вне дерева, и на свежей рабочей копии
  его нет: команда называет это прямо, а не молчит.
- **Своё дерево называется признаком из токена, а не доводом.** Приём сверяет его сам, и
  назваться чужим деревом вызов не может.
- **Записи, отмеченные в одной ветке, в соседней выглядят неотмеченными только в файлах.**
  Состояние лежит в приёме, а не в дереве: смотрят его в админке, а не в рабочей копии.
- **Повторная отметка тем же состоянием промахом не считается.** Рабочий порядок повторяют, и
  вторая та же отметка отбивается ответом «уже стояло», а не отказом.
