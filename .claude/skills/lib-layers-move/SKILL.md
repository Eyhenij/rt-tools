# Перенести код между либами

Паттерн правила `lib-layers`. Что при этом должно быть верно — закон `docs/constitution/lib-imports.md`.

## Когда брать

- Символ переезжает из одной либы в другую.
- Домен переносится в новую раскладку.
- Общий код собирается из копий в одно место.

## Начинать с планов

Решение о том, куда переезжает код, часто уже принято и записано, а принятое заново с ним
расходится — и откатывать приходится целиком. Поиск по документам делается до первой правки:

```bash
grep -rn "<имя либы>" <каталог планов>/
```

## Порядок задаёт граф зависимостей, а не список в плане

Домен переносится после всех, от кого он зависит. Списки доменов в планах отсортированы по
важности, и следование им в лоб заставляет временно расширять границы — а каждая временная
строка в границах и есть та механическая проверка, ради которой нарезка затевалась.

```bash
grep -rn "<алиас домена>" <каталоги кода> | sed 's/:.*//' | sort -u
```

Рёбра выписываются поиском по алиасам домена и сортируются топологически.

## Куда именно кладётся общее

Своя либа заводится тогда, когда ни одна существующая код не видит.

| Кому нужно                                     | Куда                                                          |
| ---------------------------------------------- | ------------------------------------------------------------- |
| серверной стороне и фронту, без каркаса фронта | общая либа утилит                                             |
| только фронтам, тянет каркас                   | либа платформы — служба и токен, либа общих компонентов — вид |
| предмету, у которого уже есть либа             | в неё                                                         |
| всем доменам одной семьи                       | основание семейства                                           |
| всей серверной стороне                         | тот слой утилит, что уже перечислен у каждого домена          |

Новых строк в границах при таком переезде не появляется — кроме права видеть контракт, если код
его читает.

## После переезда

1. **README обеих либ.** У той, откуда файл ушёл, и у той, куда пришёл: README перечисляет, что
   в либе лежит и кто её зовёт. Ни одна проверка эти тексты не читает.
2. **Порядок импортов.** Переезд алиаса его ломает, и приходит это ошибкой линтера, а не
   сборки. Автоправка есть только у линтера — в общий прогон с тестами и сборкой её флаг
   передавать нельзя, падает весь вызов.
3. **Линтер по всем затронутым проектам, а не по одному приложению.** Скрипт ошибается молча и
   не так, как человек: строка импорта не переписывается, а исчезает целиком. Сборка одного
   приложения до таких файлов не доходит — их находит только прогон по списку проектов.

## Проверить

Проверка раскладки — и обязательно проверка повторов: перенос и есть тот момент, когда копия
остаётся на старом месте.

## Частые промахи

- Новый адрес выбран без чтения планов — расходится с уже принятым решением.
- Порядок переноса взят из списка в плане — приходится временно расширять границы.
- README поправлен только у одной либы.
- Линтер прогнан по приложению, а не по списку затронутых проектов — пропавшие импорты не
  видно.
- Копия осталась на старом месте, а проверка повторов не гонялась.
