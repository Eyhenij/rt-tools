# task-flow — что здесь своё

Имена и привязки этого дерева при правиле `SKILL.md` рядом.

Дерево публикует библиотеки и приложений не держит. **Домен здесь — пакет в `projects/`**:
`ui-kit`, `ui-kit-v2`, `core`, `store`, `utils`, `agent-kit`. Спек домена описывает публичную
поверхность пакета — что он обещает потребителю, — а не предметную область продукта.

## Как это называется здесь

| В правиле                      | Здесь                                                                      |
| ------------------------------ | -------------------------------------------------------------------------- |
| домен                          | пакет в `projects/` — по одному каталогу спека на пакет                    |
| очередь работ                  | задачи GitHub и доска `Rt-tools`; номер задачи стоит в имени ветки         |
| папка задачи                   | `docs/tasks/<ветка>/` — путь повторяет имя ветки буквально, вместе с косой |
| работа шире одной ветки        | `docs/plans/<тема>.md` — уже заведён и используется                        |
| разбор просьбы                 | вопросы владельцу инструментом опроса, ответы дословно в `grill.md`        |
| разбор замысла ролями          | `.claude/workflows/plan.js`                                                |
| переименование папки под номер | руками: `git mv docs/tasks/_draft-<slug> docs/tasks/<ветка>`               |

## Где это лежит

| Что                               | Где                                                              |
| --------------------------------- | ---------------------------------------------------------------- |
| Папки задач                       | `docs/tasks/`, образец — `docs/tasks/_template/`                 |
| Договорённость о продукте до кода | `docs/specs/<пакет>/proposed/<фича>/`                            |
| Спек пакета                       | `docs/specs/<пакет>/`                                            |
| Замысел работ шире ветки          | `docs/plans/`                                                    |
| Роли разбора                      | `.claude/agents/spec-writer.md`, `.claude/agents/spec-critic.md` |
| Конвейер после разбора            | `.claude/workflows/plan.js`                                      |

## Как закон применяется здесь

- **Папка задачи заводится вместе с веткой, а не после первой правки.** Путь повторяет имя
  ветки буквально, вместе с косой: `chore/312-sync-agent-kit` →
  `docs/tasks/chore/312-sync-agent-kit/`. Косая на дефис не заменяется — так папку ищут
  `task-context-load.sh` и `task-flow-guard.sh`, и папка, названная иначе, не находится ничем.
- **Просьба владельца ложится в `grill.md` дословно.** Пересказ подгоняется под уже сделанное;
  дословная запись — единственное, с чем можно сверить результат при приёмке.
- **`plan.md` после написания не правится.** Пересмотр этапа пишется в `progress.md` как
  решение по ходу, с доводом.
- **Сделанное отмечается только в `progress.md`.** Вторая запись об этом же — в теле коммита,
  в описании PR, в плане — разъезжается с первой молча.
- **Договорённость о поведении компонента пишется до кода** и живёт в
  `docs/specs/<пакет>/proposed/<фича>/`, пока ветка не влита.

## Чего из закона здесь нет

| Статья                                                          | Почему                                                                                                                                                |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Состояние незаконченной работы восстанавливается без владельца. | **Не исполняется.** Хука, который кладёт состояние работы в контекст на запуске сессии, пакет не везёт, и своего здесь нет: заход начинается вслепую. |
| Код не пишется раньше замысла.                                  | **Не исполняется.** Гарда, отбивающего правку кода без `plan.md`, пакет не везёт. Держится договорённостью.                                           |
| Брошенные черновики и папки закрытых задач находятся проверкой. | **Не исполняется.** Проверки состояния доски в дереве нет; папки разбираются глазами при закрытии.                                                    |
| Готовность договорённости к вливанию проверяется командой.      | **Не исполняется.** Спеков пакетов пока ни одного, сверять нечего.                                                                                    |

Четыре пробела записаны здесь, а не заведены задачами: они закрываются вместе — своими хуками и
своей проверкой, — и до первой заведённой папки задачи проверять им нечего.

## Что ещё стоит знать при чтении кода

- **`docs/plans/` старше этого правила.** Там лежат замыслы работ, каждая из которых шире одной
  ветки; папка задачи их не отменяет и не дублирует — она про одну ветку.
- **Номер задачи приходит из GitHub, а не из имени папки.** Пока задача не заведена, папка
  зовётся `docs/tasks/_draft-<slug>/` и в историю не едет.

## Чем это проверяется

- Глазами при закрытии работы: папка задачи разобрана, `progress.md` дописан, договорённость
  влита в спек пакета.
- `pnpm run agent-kit:check` — правило разложено и его компаньон заполнен.
