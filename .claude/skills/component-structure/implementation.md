# component-structure — как это устроено здесь

Имена этого дерева при правиле `SKILL.md` рядом. Отдельный файл потому, что правило говорит
приёмом и переносится между репозиториями целиком, а всё, что ниже, верно только здесь и
устаревает при каждом переименовании.

Дерево держит два независимых кита. Они не заменяют друг друга и кода не делят: разные
селекторы, свои наборы токенов, свои списки компонентов, — поэтому почти каждая строка ниже
названа для обоих.

## Как это называется здесь

| В правиле                   | Здесь                                                                              |
| --------------------------- | ---------------------------------------------------------------------------------- |
| файл компонента             | тройка рядом: `<имя>.component.ts` + `.html` + `.scss`                             |
| префикс компонента          | `rtui-` в первом ките, `rt-` во втором                                             |
| якорь для спек              | атрибут `qa-dataid` — только во втором ките                                        |
| класс блока на хосте        | `host: { class: BEM_BLOCK }`, где `BEM_BLOCK` — константа рядом с классом          |
| готовое значение шаблона    | `computed()`, в том числе запись модификаторов под `[rtMod]`                       |
| вход, выход, ссылка на узел | `input()`, `output()`, `viewChild()` — декораторов входа и выхода здесь не заводят |

## Где это лежит

| Что                                | Где                                                                              |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| компоненты первого кита            | `projects/ui-kit/src/lib/ui-kit/<фича>/`                                         |
| компоненты второго кита            | `projects/ui-kit-v2/src/lib/components/<фича>/`                                  |
| образец файла компонента           | `projects/ui-kit/src/lib/ui-kit/buttons/unified-button/rtui-button.component.ts` |
| правила линтера этого дерева       | `tools/eslint-rules/rules/`, включены в `eslint.config.mjs`                      |
| поиск по якорю в спеках            | `projects/ui-kit-v2/src/testing/rt-kit-testing.ts` — `qa`, `qaAll`               |
| умолчания компонентов первого кита | `projects/ui-kit/src/lib/ui-kit/config/` — токен `RT_UI_CONFIG`                  |

## Где исполняются статьи

Первая колонка — статья дословно, как она написана в разделе «Как закон применяется здесь»
(жирная часть пункта). Статья без строки и строка без статьи — расхождение: правило обещает
то, чего в дереве нет, либо в дереве стоит то, о чём правило молчит.

| Статья                                                      | Где исполняется                                                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Шаблон не зовёт методов.                                    | `projects/ui-kit/src/lib/ui-kit/buttons/unified-button/rtui-button.component.ts:modifiers` — запись модификаторов собирается вычисляемым и привязывается один раз. Линтером не держится: `@angular-eslint/template/no-call-expression` в `eslint.config.mjs` выключен, пока замечание в шаблоне нечем погасить точечно. |
| Каждый интерактивный элемент несёт `qa-dataid`.             | `projects/ui-kit-v2/src/testing/rt-kit-testing.ts:qa` — искалка по якорю; сами якоря стоят в шаблонах второго кита, в первом их нет ни в одном.                                                                                                                                                                         |
| Компоненту разрешён только элементный селектор.             | **Не проверяется ничем.** Правила линтера на род селектора в конфиге нет; все компоненты обоих китов объявлены элементными, и нарушение поймает разбор.                                                                                                                                                                 |
| Класс блока висит на хосте, а не на обёртке внутри шаблона. | `tools/eslint-rules/rules/require-host-bem-block.ts:RULE_NAME` — правило объявлено замечанием, но роняет прогон наравне с отказом — у цели `lint` стоит `maxWarnings: 0`. В первом ките класс хоста стоит не везде: 39 несогласий, за ними задача #113.                                                                 |

## Что ещё стоит знать при чтении кода

- Классы в шаблоне ставятся директивами `rtBlock` / `rtElem` / `[rtMod]` из `@rt-tools/core`, а
  не строкой в атрибуте. `rt/require-bem-directives` объявлено замечанием, но при `maxWarnings: 0`
  роняет прогон: 24 сырых класса первого кита разбираются задачей #113.
- `rtMod` без `ModDirective` в `imports` собирается молча, а модификаторы пропадают в готовой
  сборке: ровно так их потеряли 13 компонентов. Отсюда `rt/require-mod-directive-import` —
  отказ, а не замечание.
- Умолчания компонента первого кита разрешаются лесенкой «вход экземпляра → `components.<имя>`
  → `global` → умолчание библиотеки» и только в вычисляемом: прочитанное в поле класса
  потребитель уже не перебьёт.
- `<ng-content />` в разных ветках условия не повторяется — спроецированные узлы привязываются
  к первому слоту. Объявляется один раз в `<ng-template>` и разворачивается через
  `[ngTemplateOutlet]`.
- Второй кит целиком на `ViewEncapsulation.None`; что из этого следует для стилей — правило
  `styling-bem` и его `implementation.md`.

## Чем это проверяется

- `pnpm exec nx lint @rt-tools/ui-kit` и `pnpm exec nx lint @rt-tools/ui-kit-v2` — правила
  декоратора, шаблона и собственные правила этого дерева.
- `pnpm exec nx test @rt-tools/ui-kit --testFile=<путь>` — спека компонента; сборка стенда
  зоннезависимая, и пропущенный импорт роняет спеку, а не рисует пустоту.
