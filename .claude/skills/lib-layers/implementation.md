# lib-layers — как это устроено здесь

Имена этого дерева при правиле `SKILL.md` рядом. Отдельный файл потому, что правило говорит
приёмом и переносится между репозиториями целиком, а всё, что ниже, верно только здесь и
устаревает при каждом переименовании.

Здесь либы — это опубликованные пакеты, а не внутренние слои приложения. Отсюда главное
отличие от общего случая: барель — не удобство сборки, а договор с потребителем, и файл, не
попавший ни в один барель, не уезжает вовсе.

## Как это называется здесь

| В правиле           | Здесь                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| либа                | публикуемый пакет `@rt-tools/*` в `projects/<имя>/`                                            |
| барель              | пара `public-api.ts` + `index.ts` в каждой папке фичи                                          |
| точка входа пакета  | `projects/<пакет>/src/index.ts`, у обоих китов — `src/public-api.ts`                           |
| алиас               | запись в `paths` файла `tsconfig.base.json`                                                    |
| слой утилит         | `@rt-tools/utils` — пакет без единой зависимости, кроме вспомогательной библиотеки компилятора |
| основание семейства | `@rt-tools/core` — общие директивы, хранилища, токены; зовут его все остальные                 |
| конфиг границ       | `@nx/enforce-module-boundaries` в `eslint.config.cjs`                                          |

## Где это лежит

| Что                                 | Где                                                     |
| ----------------------------------- | ------------------------------------------------------- |
| алиасы пакетов                      | `tsconfig.base.json`                                    |
| манифест сборки первого кита        | `projects/ui-kit/ng-package.json` — `lib.entryFile`     |
| зависимости и диапазоны версий      | `projects/<пакет>/package.json`                         |
| неявные зависимости для сборки      | `projects/ui-kit/project.json` — `implicitDependencies` |
| проверка состава пакета утилит      | `tools/verify-utils-package.cjs`, цель `verify`         |
| сверка страниц-обзоров второго кита | `tools/verify-ui-kit-v2-docs.cjs`, цель `verify`        |

## Где исполняются статьи

Первая колонка — статья дословно, как она написана в разделе «Что здесь действует» правила
(жирная часть пункта). Статья без строки и строка без статьи — расхождение: правило обещает
то, чего в дереве нет, либо в дереве стоит то, о чём правило молчит.

| Статья                                                                                      | Где исполняется                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Чужой символ не реэкспортируется ни одной из двух форм.                                     | Держится разбором: барели этого дерева перечисляют только собственные файлы пакета относительными путями. Отдельного правила линтера на реэкспорт здесь нет.                                                                                                                                |
| Строка с алиасом чужой либы в бареле — тот же реэкспорт.                                    | `projects/ui-kit/src/public-api.ts` и `projects/*/src/index.ts` — ни одной строки с алиасом `@rt-tools/*`; чужое приходит зависимостью пакета, а не через барель.                                                                                                                           |
| Не хватает права — оно дописывается строкой в конфиге домена с комментарием.                | Не исполняется в буквальном виде: метки проектов пусты, и `depConstraints` в `eslint.config.cjs` состоит из одного разрешающего правила. Направление зависимостей держат `package.json` пакетов: у утилит зависимостей нет, основание зовёт только утилиты, оба кита — основание и утилиты. |
| У либы, общей всем приложениям, список зависимостей пуст, и каркас фронта туда не попадает. | `projects/utils/package.json` — ни одной зависимости на каркас; проверяется `tools/verify-utils-package.cjs`.                                                                                                                                                                               |
| Основание семейства видит только слой утилит.                                               | `projects/core/package.json` — единственная зависимость на другой пакет дерева — `@rt-tools/utils`.                                                                                                                                                                                         |
| Домен заводится под предмет, а не под механику.                                             | Папки китов названы предметом (`buttons`, `table`, `aside`, `chat`), а общая механика живёт в основании и утилитах. Держится разбором.                                                                                                                                                      |

## Что ещё стоит знать при чтении кода

- Файл, который не перечислен ни в одном бареле, не уезжает потребителю. Новая папка фичи —
  это `public-api.ts` со списком модулей и однострочный `index.ts` поверх него.
- Обвязка витрины и спек не публикуется: `src/testing/**` и `src/showcase/**` исключены из
  сборки, а обёртки историй не перечисляются ни в одном бареле.
- Каркас, CDK, Material и библиотека потоков — сопутствующие зависимости во всех пакетах;
  переводить их в обычные нельзя.
- У каждого пакета `"sideEffects": false`. Побочное действие на уровне модуля в бареле молча
  ломает отсечение мёртвого кода у потребителя.
- Второй кит не заменяет первый и кода с ним не делит: разные селекторы, свои наборы токенов,
  свои списки компонентов — одно приложение может держать оба.
- Снятие или переименование экспорта, сужение типа и снятие публичного токена оформления —
  ломающая правка для опубликованного пакета: поднимается версия, дописывается неизданный
  раздел журнала изменений, и это называется в описании PR.

## Чем это проверяется

- `pnpm run build:all` — каждый пакет обязан собраться от своей точки входа.
- `pnpm exec nx run-many -t verify --all` — состав пакета утилит и сверка страниц-обзоров.
- `pnpm run check:affected` — линт, типы, спеки и сборка по задетым пакетам; правило границ
  живёт в линте.
