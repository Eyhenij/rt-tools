# lib-layers — как это устроено здесь

Имена этого дерева при правиле `SKILL.md` рядом. Отдельный файл потому, что правило говорит
приёмом и переносится между репозиториями целиком, а всё, что ниже, верно только здесь и
устаревает при каждом переименовании.

Либы здесь двух родов, и правило действует на оба по-разному. Публикуемые пакеты в `projects/`
— договор с потребителем: барель у них не удобство сборки, а объявление того, что уезжает, и
файл, не попавший ни в один барель, не уезжает вовсе. Внутренние либы приёмника в `libs/` —
обычные слои: у них лесенка, теги и границы, как в общем случае.

## Как это называется здесь

| В правиле           | Здесь                                                                                                    |
| ------------------- | -------------------------------------------------------------------------------------------------------- |
| либа                | публикуемый пакет `@rt-tools/*` в `projects/<имя>/`; внутренняя — `libs/<семья>/<домен>/<слой>`          |
| семья либ           | `libs/message-bus-api` — серверная сторона приёмника; `libs/message-bus-common` вне семей                |
| слой                | `api`, `data-access`, `feature`, `util` — четыре, у серверной стороны `ui` и `shell` нет                 |
| тег                 | `scope:` плюс путь от `libs/` с дефисами: `scope:message-bus-api-trees-util`                             |
| барель              | пара `public-api.ts` + `index.ts` в каждой папке фичи                                                    |
| точка входа пакета  | `projects/<пакет>/src/index.ts`, у обоих китов — `src/public-api.ts`; у внутренней либы — `src/index.ts` |
| алиас               | запись в `paths` файла `tsconfig.base.json`                                                              |
| слой утилит         | `@rt-tools/utils` — пакет без единой зависимости, кроме вспомогательной библиотеки компилятора           |
| основание семейства | `@rt-tools/core` — общие директивы, хранилища, токены; зовут его все остальные                           |
| конфиг границ       | файл домена в `eslint/boundaries/domains`, свод — `eslint/boundaries/index.mjs`                          |

## Где это лежит

| Что                                 | Где                                                     |
| ----------------------------------- | ------------------------------------------------------- |
| алиасы пакетов                      | `tsconfig.base.json`                                    |
| манифест сборки первого кита        | `projects/ui-kit/ng-package.json` — `lib.entryFile`     |
| зависимости и диапазоны версий      | `projects/<пакет>/package.json`                         |
| неявные зависимости для сборки      | `projects/ui-kit/project.json` — `implicitDependencies` |
| проверка состава пакета утилит      | `tools/verify-utils-package.cjs`, цель `verify`         |
| сверка страниц-обзоров второго кита | `tools/verify-ui-kit-v2-docs.cjs`, цель `verify`        |

## Где исполняются статьи

Первая колонка — статья дословно, как она написана в разделе «Как закон применяется здесь»
(жирная часть пункта). Статья без строки и строка без статьи — расхождение: правило обещает
то, чего в дереве нет, либо в дереве стоит то, о чём правило молчит.

| Статья                                                                       | Где исполняется                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Чужой символ не реэкспортируется ни одной из двух форм.                      | `tools/lib-reexports.mjs:checkReexports` — судятся обе формы: `export … from` чужого модуля и пара «импорт плюс `export`». Правила линтера на реэкспорт здесь нет, держит проверка дерева.                                                                                                                                      |
| Строка с алиасом чужой либы в бареле — тот же реэкспорт.                     | `tools/lib-reexports.mjs:checkReexports` — та же проверка судит и барель; в `projects/ui-kit/src/public-api.ts` строк с алиасом `@rt-tools/*` нет, чужое приходит зависимостью пакета.                                                                                                                                          |
| Не хватает права — оно дописывается строкой в конфиге домена с комментарием. | `eslint/boundaries/domains/message-bus-api.config.mjs:PERSISTENCE_UTIL` — каждое ребро семьи приёмника выписано строкой с причиной. У публикуемых пакетов метки пусты, и права им даёт одно разрешающее правило в `eslint/boundaries/domains/packages.config.mjs`: направление между ними держат их собственные `package.json`. |
| У `libs/common/util` список зависимостей пуст, и Angular туда не попадает.   | `tools/lib-boundaries.mjs:checkNoDependencyLibs` — либа с пустым списком зависимостей судится отдельно; здесь ей отвечает `projects/utils/package.json`, где ни одной зависимости на каркас нет.                                                                                                                                |
| Основание семейства видит только `util`.                                     | `tools/lib-boundaries.mjs:checkBoundaries` — права основания судятся тегами; здесь основанию отвечает `projects/core/package.json` с единственной зависимостью `@rt-tools/utils`.                                                                                                                                               |
| Поведение, которого основанию семейства не видно, приходит к нему токеном.   | **Не применимо.** Семей либ с основанием здесь нет: дерево держит пакеты, а не приложение с семьями                                                                                                                                                                                                                             |
| Домен заводится под предмет, а не под механику.                              | **Не проверяется ничем.** Предмет от механики машине не отличить: имя каталога законно и там, и там. Папки китов названы предметом, у приёмника предметом названы все пять доменов; держится разбором.                                                                                                                          |
| Домен, у которого непуст один слой, значится строкой с причиной.             | `tools/lib-domains.mjs:checkDomainIsFilled` — домен с одним непустым слоем называется строкой. Домен деревьев держит непустыми три слоя из четырёх: `api` пуст, потому что наружу он не ходит.                                                                                                                                  |

## Что ещё стоит знать при чтении кода

- Файл, который не перечислен ни в одном бареле, не уезжает потребителю. Новая папка фичи —
  это `public-api.ts` со списком модулей и однострочный `index.ts` поверх него.
- Обвязка витрины и спек не публикуется: `src/testing/**` и `src/showcase/**` исключены из
  сборки, а обёртки историй не перечисляются ни в одном бареле.
- Каркас, CDK, Material и библиотека потоков — сопутствующие зависимости во всех пакетах;
  переводить их в обычные нельзя.
- У каждого пакета `"sideEffects": false`. Побочное действие на уровне модуля в бареле молча
  ломает отсечение мёртвого кода у потребителя.
- Второй кит не заменяет первый и кода с ним не делит: разные селекторы, свои наборы токенов,
  свои списки компонентов — одно приложение может держать оба.
- Форма груза, которую знают обе стороны приёма, объявлена в пакете и берётся у источника
  подпутём `@rt-tools/agent-kit/cargo`. Реэкспорта её из либы приёмника нет намеренно: символ
  импортируется там, где объявлен, а разрешение на этот подпуть выписано строкой в корневом
  конфиге линтера.
- Снятие или переименование экспорта, сужение типа и снятие публичного токена оформления —
  ломающая правка для опубликованного пакета: поднимается версия, дописывается неизданный
  раздел журнала изменений, и это называется в описании PR.

## Чем это проверяется

- `pnpm run build:all` — каждый пакет обязан собраться от своей точки входа.
- `pnpm exec nx run-many -t verify --all` — состав пакета утилит и сверка страниц-обзоров.
- `pnpm run check:affected` — линт, типы, спеки и сборка по задетым пакетам; правило границ
  живёт в линте.
