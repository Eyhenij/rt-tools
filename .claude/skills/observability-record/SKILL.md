# Новая строка лога

Паттерн правила `observability`. Что при этом должно быть верно — закон
`docs/constitution/observability.md`.

## Когда брать

- В домене появилось место, о котором владелец должен узнать: не сработала автоматика,
  отказала внешняя служба, упала процедура.
- Хочется поставить `console.log` — вместо него ставится строка лога.

## Логгер домена берётся один раз

```ts
const LOG_CONTEXT: string = 'PageCache';

readonly #log: ScopedLogger;

constructor(logger: AppLoggerService) {
    this.#log = logger.scope(LOG_CONTEXT);
}
```

Контекст задаётся один раз и константой модуля, а не литералом в вызове: соседние классы одного
домена пишут под тем же источником, а отбор отказов судит именно по нему. Номер обращения,
процедуру и того, кто в системе, логгер подставляет сам — передавать их полями не надо.

## Имя строки постоянное, всё изменяемое — в поля

```ts
✓ this.#log.warn('cache.refresh.rejected', { url, attempt, status, durationMs });
✗ this.#log.warn(`cache refresh rejected for ${url} after ${attempt} attempts`);
```

Первый аргумент — имя строки, а не предложение. По нему строки об одном и том же собираются
вместе, и по нему же они схлопываются в одну строку ленты отказов. Подставленное в имя значение
делает каждую строку уникальной.

Имя пишется точками от общего к частному: `cache.refresh.rejected`, `mail.owner.skipped`.

Поля вычищаются автоматически. Имя строки проходит вычистку только по пути в хранилище отказов
— в выводе оно печатается как есть, — поэтому подставлять в него значения нельзя ещё и по этой
причине.

## Строке нижнего уровня нужна строка в списке отобранных

Уровень отказа и всё, что выше, уезжает в хранилище отказов само. Строка уровнем ниже попадает
туда, только если её имя стоит в списке отобранных имён. Список сравнивается по началу имени и
правится тем же коммитом, что и место, которое эту строку пишет.

Забыли дописать — строка останется только в выводе контейнера, и владелец о ней не узнает. Не
сверяет это ничто.

## Уровень выбирается по тому, сломалось ли что-то

| Уровень     | Когда                                                                                                    |
| ----------- | -------------------------------------------------------------------------------------------------------- |
| отказ       | приложение не сделало того, что должно: упала процедура, не прошла запись в хранилище                    |
| ниже        | не сработала автоматика: перевод, обновление кэша, опрос внешней службы. Сюда же отказ по вводу и правам |
| сообщение   | состоявшееся действие, о котором стоит знать: вызов прошёл, письмо ушло                                  |
| подробность | то, что нужно при разборе, а на проде не нужно                                                           |

Отказ гостя пройти проверку, промах в форме и «не найдено» — это уровень ниже отказа. Проверка
сработала, приложение работает.

## Отказ внешней службы записывается разобранным

```ts
} catch (error: unknown) {
    this.#log.error('mail.send.failed', { to: maskEmail(to), error: describeError(error) });
}
```

Разбор причины кладёт класс, текст, код и срезанный стек одной формой — той же, что у остальных
отказов. Подставлять ошибку в текст (`` `failed: ${String(error)}` ``) нельзя: так в лог уедет
чужой текст целиком, вместе с адресом, ключом или почтой гостя.

Почту маскируют на месте вызова, если она приходит отдельным значением: вычистка узнаёт её по
имени поля, а имя вроде `to` на почту не похоже.

## Отказ наступает только тогда, когда у обращения есть предел ожидания

```ts
/**
 * Ожидание источника курсов. Курс справочный и обновляется раз в сутки: пять
 * секунд ожидания и прежний курс на месте лучше, чем пять минут занятого
 * расписания.
 */
const RATES_TIMEOUT_MS: number = 5_000;

const response: Response = await fetch(RATES_URL, { signal: AbortSignal.timeout(RATES_TIMEOUT_MS) });
```

Без предела соединение с молчащей службой живёт до умолчания среды — минуты, — и всё это время
`catch` не наступает: писать нечего. Число стоит рядом с клиентом со своим доводом, потому что
цена ожидания у каждой службы своя: гость внутри запроса ждёт иначе, чем ночное расписание.

## Частые промахи

- **Одно и то же имя строки стоит в двух местах.** Тогда две разные ситуации читаются как одна.
  Либо имена разные, либо место одно.
- **`console.log` вместо строки лога.** У него нет ни уровня, ни номера обращения, и в отбор он
  не попадает. На проде это строка, которую никто не увидит.
- **Уровень выбран по тому, насколько неприятно.** Отказ гостя пройти проверку неприятен, но
  приложение при этом работает.
- **Ошибка положена в поле как есть, без разбора причины.** Объект ошибки сериализуется в
  пустой `{}`, и в логе не останется ни текста, ни класса.
- **Незаполненная часть ключа группы стоит пропуском, а не пустой строкой.** Два отказа без
  процедуры и без предмета работы обязаны сойтись в одну группу; с пропуском в ключе каждый
  заводит свою, и лента наполняется одиночными строками об одном и том же.
- **Одинаковые отказы, пришедшие разом, дают две группы.** Между «такой группы ещё нет» и
  вставкой успевает пройти второй, поэтому случай разбирается не проверкой перед вставкой, а
  после того, как вставка не прошла.
- **Имя строки лога длиннее предела ключа не записывается вовсе.** Оно собирается подстановкой
  и ничем не ограничено, а у ключа предел есть: без обрезки отказ с длинным именем теряется
  молча — ни строки в ленте, ни отказа в логах.
