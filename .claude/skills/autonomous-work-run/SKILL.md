# Ночь без владельца

Паттерн правила `autonomous-work`. Что при этом должно быть верно — закон
`docs/constitution/autonomous-work.md`.

## Когда брать

- Владелец сказал, что уходит, и просил работать самостоятельно.
- За заход берётся больше одной задачи подряд, и отдать их наружу нельзя.
- Работа упёрлась в вопрос, а спросить некого.

## Череда веток

Первая работа ветвится от главной, каждая следующая — от предыдущей:

```bash
git checkout -b <КЛЮЧ>-<номер-1>-<slug> main           # первая за ночь
git checkout -b <КЛЮЧ>-<номер-2>-<slug> <КЛЮЧ>-<номер-1>-<slug>
git checkout -b <КЛЮЧ>-<номер-3>-<slug> <КЛЮЧ>-<номер-2>-<slug>
```

Порядок вливания — снизу вверх, и он называется в списке к утру номерами. Ветка, заведённая от
главной посреди череды, столкнётся с соседкой в общих файлах — указателях, счётчиках, журналах —
и разбирать это будет владелец.

```bash
git log --oneline --graph --decorate main..HEAD | head -20   # чем стоит череда сейчас
git branch --list '<КЛЮЧ>-*' --format='%(refname:short) %(upstream:short)'
```

## Цикл одной работы

```bash
npm run task:move -- <номер> in-progress                 # взята
git checkout -b <КЛЮЧ>-<номер>-<slug> <прошлая ветка>    # череда, а не веер
cp -r docs/tasks/_template docs/tasks/<КЛЮЧ>-<номер>-<slug>
# разбор просьбы с умолчаниями, замысел, состояние «этап-идёт»
git add docs/tasks/<КЛЮЧ>-<номер>-<slug> && git commit    # папка едет в историю сразу
# работа этапами: каждый кончается коммитом и прогоном признака готовности
# папка разбирается в описание прошлого последним коммитом
```

Наружу за ночь не уходит ничего: ни `git push`, ни `gh pr create`, ни публикация, ни отметка
груза. Ветка остаётся местной, и утром владелец сам решает, что из неё отдавать.

## Умолчание вместо вопроса

Пишется в разбор просьбы, в раздел решений, — там же, где записался бы ответ владельца:

```markdown
- **<что принято>** — <довод>. Спросить было некого: заход автономный. Цена ошибки:
  <что придётся переделать, если владелец решит иначе>.
```

Цена ошибки — не вежливость, а признак: она отделяет умолчание, которое можно переиграть за
десять минут, от того, ради которого работу лучше отложить целиком.

## Отложенная задача

Задача, которой нужно слово владельца, не берётся: состояние на борде остаётся прежним, а в
список к утру идёт строка.

```markdown
- **RT-<номер> — <заголовок>.** Отложена: <какой вопрос и почему умолчания у него нет>.
```

## Список к утру

Дописывается по ходу, после каждой закрытой работы, а не собирается в конце.

```markdown
| Работа | Ветка | Чем подтверждена | Чего ждёт |
| ------ | ----- | ---------------- | --------- |
| RT-… — <что сделано> | `<ветка>` (на `<предыдущей>`) | `<команда>` — <вывод> | заявки и слияния |
```

Порядок строк — порядок вливания. Ниже списка — отложенные задачи с их вопросами.

## Отказ стража

Отказ называет пропущенный шаг: шаг делается, вызов повторяется, работа идёт дальше. Ночь
кончается работой, а не спором со стражем.

- Отказ требует того, что делать нельзя (пуш, заявка), — работа доводится до места, где
  требование исполнимо утром, и уходит в список к утру строкой «ждёт заявки».
- Отказ повторяется на том же месте дважды — значит пропущенный шаг понят неверно: читается
  правило, названное в отказе, а не переписывается формулировка.

## Частые промахи

- **Ветка заведена от главной по привычке.** Череда рвётся молча, и цена всплывает у владельца
  на втором вливании.
- **Умолчание принято и не записано.** Утром оно неотличимо от знания, и владелец узнаёт о нём,
  только когда работа сделана не так.
- **Задача взята и отложена наполовину.** На борде она в работе, в ветке — половина правки;
  следующий заход читает её как начатую и не начинает заново.
- **Список к утру собран по памяти в последнюю минуту.** К этому часу окно уже сжималось, и
  половина ночи в него не попала.
