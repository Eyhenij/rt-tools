# autonomous-work — что здесь своё

Имена и привязки этого дерева при правиле `SKILL.md` рядом.

## Как это называется здесь

| В правиле         | Здесь                                                                 |
| ----------------- | --------------------------------------------------------------------- |
| ключ задач череды | `RT-<номер>`; ветка — `RT-<номер>-<slug>`                             |
| очередь работ     | доска проекта на GitHub; колонки двигает `npm run task:move`          |
| список к утру     | последняя реплика захода владельцу; строка на каждую закрытую работу  |
| описание прошлого | `docs/archive/RT-<номер>-<slug>.md`                                   |
| папка задачи      | `docs/tasks/RT-<номер>-<slug>/` — разбор просьбы, замысел, ход работы |

## Где это лежит

| Что                         | Где                                      |
| --------------------------- | ---------------------------------------- |
| образец папки задачи        | `docs/tasks/_template/`                  |
| заведение задачи            | `npm run task:new`                       |
| перевод колонки             | `npm run task:move -- <номер> <колонка>` |
| прогон набора пакета правил | `bash projects/agent-kit/tests/run.sh`   |
| сверка раскладки            | `pnpm run agent-kit:check`               |

## Где исполняются статьи

Первая колонка — статья дословно. Автономный заход держится приёмом: стража, который отличал бы
ночь от дня, в дереве нет ни одного, и это сказано по каждой статье прямо.

- **Ветка следующей работы заводится от предыдущей, а не от главной.** — **Не проверяется ничем.** Ни один гард основания ветки не судит; держится приёмом `git checkout -b RT-<номер>-<slug> <прошлая ветка>` и порядком в списке к утру
- **Наружу за ночь не уходит ничего.** — **Не проверяется ничем.** Команда пуша ночью ничем не отличается от дневной, и гейт пуша её пропускает; держится словом владельца о заходе
- **Задача, которой нужно слово владельца, не берётся вовсе.** — **Не проверяется ничем.** Борда не знает, чего задача ждёт; держится строкой отложенной задачи в списке к утру
- **Умолчание записывается там же, где записался бы ответ владельца.** — **Не проверяется ничем.** Пишется в раздел «Решения» разбора просьбы — `docs/tasks/RT-<номер>-<slug>/grill.md`; полноту раздела машина не судит
- **Признак готовности называется командой до начала этапа.** — `.claude/hooks/turn-exit-guard.sh:rt_te_deny` — страж выходов хода читает команду из строки «Чем проверяется» замысла и не выпускает ход, где этап объявлен закрытым, а команда не запускалась
- **Красный прогон чинится в той же ветке, а не откладывается.** — `.claude/rt-kit/project.sh:rt_push_checks` — набор гейта пуша; ночью он гоняется тем же вызовом, что и днём
- **Отказ стража — шаг работы, а не конец захода.** — **Не проверяется ничем.** Страж не знает, что было после его отказа; держится приёмом
- **Список к утру пишется по ходу, а не вспоминается в конце.** — **Не проверяется ничем.** Собирается из раздела «Заходы» хода работы — `docs/tasks/RT-<номер>-<slug>/progress.md`; что он дописан вовремя, машине не видно

## Что ещё стоит знать при чтении кода

- Заявка за ночь не открывается, поэтому папка задачи разбирается в описание прошлого последним
  коммитом ветки: ветка остаётся готовой к заявке, которую утром откроет владелец.
- Отметка груза в приёме ночью не ставится: она утверждает, что правка в главной ветке, а ветки
  за ночь не уходят даже на хостинг.

## Чем это проверяется

- `bash projects/agent-kit/tests/run.sh` — наборы пакета правил зелёные после правки ресурсов.
- `pnpm run agent-kit:check` — разложенное сходится с пакетом.
- `npm run check:docs`, `npm run check:specs` — пути документов и спеки без расхождений.
