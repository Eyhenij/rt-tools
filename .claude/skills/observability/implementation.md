# observability — что здесь своё

Имена и привязки этого дерева при правиле `SKILL.md` рядом.

Дерево до этой работы серверной стороны не держало вовсе, и правило было снято списком отказов.
Оно возвращено вместе с приёмником груза — приложением `apps/message-bus`. Приёмник пока
каркасный: у него есть вывод и проба живости, а домена отказов, домена оповещений, номера
обращения и экрана для владельца нет ни одного. Оттого большая часть таблицы ниже — «не
исполняется», и это состояние работы, а не отказ от статьи.

Правило целиком относится только к приёмнику: публикуемые пакеты в `projects/` ничего о себе не
пишут — их вывод принадлежит тому приложению, которое их поставило.

## Как это называется здесь

| В правиле                       | Здесь                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------ |
| то, что приложение о себе пишет | вывод контейнера: `Logger` каркаса, по строке на вызов                         |
| ступень важности                | уровень `Logger`: `log`, `warn`, `error`                                       |
| источник строки                 | первый довод `Logger` — `Db` у клиента хранилища, `Bootstrap` у подъёма службы |
| номер обращения                 | не заведён: обращений у приёмника четыре, и все безымянные                     |
| хранилище отказов               | не заведено: отказы живут в выводе контейнера                                  |

## Где это лежит

| Что                                      | Где                                                                          |
| ---------------------------------------- | ---------------------------------------------------------------------------- |
| строки клиента хранилища                 | `libs/message-bus-api/persistence/data-access/src/lib/prisma.service.ts`     |
| сводка подъёма                           | `apps/message-bus/src/main.ts`                                               |
| проба живости                            | `apps/message-bus/src/app/health/health.controller.ts`                       |
| потолок вывода контейнера                | `docker-compose.yml`, служба `api` — три файла по десять мегабайт            |
| договорённость о том, что пишет приёмник | `docs/specs/message-bus/proposed/intake/spec.md`, раздел о недоехавшем грузе |

## Где исполняются статьи

Первая колонка — статья дословно, как она написана в разделе «Как закон применяется здесь»
(жирная часть пункта). Статья без строки и строка без статьи — расхождение: правило обещает то,
чего в дереве нет, либо в дереве стоит то, о чём правило молчит.

| Статья                                                                                   | Где исполняется                                                                                                                                                               |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Номер обращения заводится один раз на запрос и стоит в каждой строке лога о нём.         | **Не исполняется.** Обращений у приёмника четыре, все безымянные; отбирать строки одного обращения пока не из чего. Заводится вместе с журналом отказов.                      |
| Номер обращения уходит вызывающему заголовком ответа и в подробностях отказа.            | **Не исполняется** по той же причине.                                                                                                                                         |
| Номер, пришедший снаружи, чистится и укорачивается, а пустой заводится заново.           | **Не исполняется** по той же причине.                                                                                                                                         |
| Наружу уходит код и общий текст ошибки, подробности остаются в логах.                    | `docs/specs/message-bus/proposed/intake/spec.md` — правило «Отказ приёмника называет причину дереву, а не подробности своего устройства»; в коде — отказы `HealthController`. |
| Отказ по вводу и правам пишется отдельно от поломки и без стека.                         | **Не исполняется.** Операций приёма ещё нет, а у пробы живости отказ ровно один.                                                                                              |
| Причина отказа разбирается в одном месте.                                                | **Не исполняется.** Мест, где отказ разбирается, пока одно — разбирать нечего.                                                                                                |
| Поля строки лога вычищаются всегда, а не по решению того, кто пишет.                     | **Не исполняется.** Строки пишутся текстом, полей у них нет вовсе. Заводится вместе с журналом отказов.                                                                       |
| Приложение при старте пишет, с чем поднялось.                                            | `apps/message-bus/src/main.ts:bootstrap` — порт и предел веса груза.                                                                                                          |
| В сводке старта стоят имена возможностей и их состояние, но не значения переменных.      | `apps/message-bus/src/main.ts:bootstrap` — в строке стоят число порта и предел веса; адреса хранилища и токенов в ней нет.                                                    |
| Возможность, включаемая парой ключей, знает третье состояние.                            | **Не применимо.** Возможностей, включаемых парой ключей, у приёмника нет.                                                                                                     |
| Порог уровня решает, появится ли строка лога в выводе, но не в хранилище отказов.        | **Не исполняется.** Порога нет, хранилища отказов нет.                                                                                                                        |
| Отобранная строка лога сохраняется в хранилище отказом.                                  | **Не исполняется.** Хранилища отказов нет.                                                                                                                                    |
| Логгер отдаёт отказ приёмнику, а хранилища не видит.                                     | **Не исполняется** по той же причине.                                                                                                                                         |
| Строки лога клиента хранилища, домена отказов и домена оповещений в приёмник не идут.    | `libs/message-bus-api/persistence/data-access/src/lib/prisma.service.ts` — строки клиента идут в вывод и дальше него не уходят; отбирать их некуда.                           |
| Обращение к чужой службе идёт с явным пределом ожидания.                                 | **Не применимо.** Приёмник наружу не ходит: он принимает, а не рассылает.                                                                                                     |
| Отправка наружу заводит свою строку до обращения, а исход дописывается в неё после.      | **Не применимо** по той же причине.                                                                                                                                           |
| Запись отказа не задерживает ответ и не роняет запрос.                                   | **Не исполняется.** Записывать отказ некуда, и задерживать ответ нечему.                                                                                                      |
| Контекст запроса снимается в момент вызова логгера, а не в момент записи.                | **Не исполняется.** Контекста запроса нет.                                                                                                                                    |
| Записанное владелец читает своим разделом, закрытым отдельным правом.                    | **Не исполняется.** Админка приёмника — третья ветка задачи; прав в этой ветке нет вовсе.                                                                                     |
| Хранилище не растёт без предела: раз в сутки лишнее и старое удаляются.                  | **Не исполняется.** Хранилища отказов нет; срок хранения груза — `Q-17` договорённости приёмника.                                                                             |
| Предел хранилища назван числом строк, а не байтами.                                      | **Не исполняется** по той же причине. Потолок вывода контейнера при этом назван байтами — это вывод, а не хранилище.                                                          |
| О новом отказе владелец узнаёт сам — строкой журнала событий и письмом.                  | **Не исполняется.** Ни журнала событий, ни почты у приёмника нет; оповещения прямо выведены из договорённости.                                                                |
| В письме нет ничего, что закрыто правом на экран отказов.                                | **Не применимо**: писем нет.                                                                                                                                                  |
| Частоту отказов владелец читает кривой над лентой: столбик — ведёрко выбранного периода. | **Не исполняется.** Экранов у приёмника нет.                                                                                                                                  |
| Тревогу поднимает рост поломок, а не всех отказов.                                       | **Не исполняется** по той же причине.                                                                                                                                         |
| Всплеск считается по последнему закрытому ведёрку, текущее правилу не отдаётся.          | **Не исполняется** по той же причине.                                                                                                                                         |
| Частоту разбирает такт расписания, а не запрос экрана.                                   | **Не исполняется.** Расписания у приёмника нет.                                                                                                                               |

## Что ещё стоит знать при чтении кода

- **Приёмник ничего не рассылает.** Половина правила говорит о письмах, тревогах и обращениях к
  чужим службам; у приёмника нет ни одного исходящего обращения — он принимает груз и отвечает
  кодом. Оттого «не применимо» в таблице стоит не от бедности, а от устройства.
- **Отказ до подъёма приложения записать некуда.** Хранилища в этот момент ещё нет, и такие
  строки остаются только в выводе контейнера. У приёмника это верно и после подъёма: журнала
  отказов у него пока нет вовсе.
- **Проба живости спрашивает хранилище, а не себя.** Служба считается поднятой, когда она
  выполнила задание: `SELECT 1` в клиенте хранилища и есть это задание.

## Чем это проверяется

- `pnpm exec nx test message-bus` — сценарии `SC-MB-17`, `SC-MB-18` и `SC-MB-29`: проба живости
  отвечает без токена, не называет состава и молчит при недоступном хранилище.
- Живым прогоном: `docker compose stop db`, затем запрос пробы живости — она отвечает отказом, а
  не «поднята».
- `pnpm run agent-kit:check` — что этот компаньон заполнен, а не остался черновиком.
