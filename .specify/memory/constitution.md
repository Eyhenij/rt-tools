# Конституция этого дерева

**Здесь её текста нет, и заводить его здесь нельзя.** Единственный источник — `docs/constitution/`.
Этот файл — указатель на него и перечень того, чем процесс описания работы отличается в этом
дереве от умолчаний Spec Kit.

## Где лежат законы

Закон говорит, что должно быть верно, и не знает ни путей, ни имён файлов. Он раскладывается
из пакета `@rt-tools/agent-kit` командой `pnpm run agent-kit:sync` и сверяется командой
`pnpm run agent-kit:check`.

| Закон                                        | О чём                                                 |
| -------------------------------------------- | ----------------------------------------------------- |
| `docs/constitution/code-structure.md`        | Устройство кода                                       |
| `docs/constitution/delivery.md`              | Поставка: ветки, выкатка, порядок изменений хранилища |
| `docs/constitution/lib-imports.md`           | Импорты между либами                                  |
| `docs/constitution/project-documentation.md` | Документация проекта                                  |
| `docs/constitution/reuse-first.md`           | Единообразие приложения                               |
| `docs/constitution/verifiability.md`         | Проверяемость: чем подтверждается, что работа сделана |

**Закон читается целиком перед решением, которое он задевает.** Пересказ закона по памяти —
не чтение: статьи сформулированы точно, и в них важно каждое слово.

Разложенные файлы правятся не руками, а надстройкой в `.claude/rt-kit/overrides/laws/`:
правка на месте теряется на следующем `agent-kit sync`, и он на неё отказывает.

## Команда `/speckit-constitution` в этом дереве не применяется

Она пишет конституцию сюда, поверх этого указателя. Здесь конституцию везёт пакет, а не
агент: у разложенного закона есть версия, сумма тела и отказ на постороннюю правку, и терять
это ради второго, ничем не проверяемого свода принципов нельзя. Правка закона идёт надстройкой
в `.claude/rt-kit/overrides/laws/`, а не через эту команду.

## Чем процесс отличается от умолчаний Spec Kit

- **Номер спеки — это номер задачи на доске, а не следующий свободный.** Встроенный счётчик
  `specs/` не применяется: у работы уже есть номер, и второй номер той же работы развязывает
  описание с задачей. Каталог называется `specs/<номер задачи>-<короткое имя>`.
- **Ветку заводит доска, а не Spec Kit.** Имя — `type/<номер задачи>-<slug>`, как требует
  правило `rt-tools-board`. Расширение `git`, создающее ветки, здесь не поставлено.
- **Задачи на трекере заводит доска.** `/speckit-taskstoissues` в этом дереве не поставлена:
  задача заводится до ветки и до спеки, а не выводится из неё.
- **Тесты не опциональны.** Умолчание Spec Kit «tests are optional unless requested» здесь
  не действует: `verifiability.md` требует, чтобы обещанное поведение было названо сценарием,
  а сценарий — назван в тесте, который его проверяет. Сценарий без теста помечается
  непокрытым и виден в сводке; молчаливый пропуск — отказ.
- **Правила правки кода выдаёт `.claude/skills/`, а не спека.** Перед правкой файла грузится
  правило по его роду — `rt-tools-component`, `rt-tools-styling`, `rt-tools-testing` и
  остальные; `.claude/hooks/skill-gate.sh` блокирует правку, пока правило не загружено. Это
  действует и внутри `/speckit-implement`.
- **Раскладка кода задана монорепозиторием.** Пакеты живут в `projects/<пакет>/`, спеки —
  рядом с источником в виде `*.spec.ts`. Вариантов `src/ tests/`, `backend/ frontend/` и
  `api/ ios/` из шаблонов Spec Kit здесь нет ни одного.

## Что из этого проверяется

`pnpm run agent-kit:check` — что разложенные законы сходятся с пакетом и никто не правил их
руками. Остальное держится правилами `.claude/skills/` и гейтом `skill-gate.sh`.
