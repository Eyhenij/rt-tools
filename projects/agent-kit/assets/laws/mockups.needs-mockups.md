# Law on mockups

What the owner sees before the code is written. The owner reads a screen by its picture, and a
picture that does not match the screen makes every detail of the code read as broken layout.

**Revision:** 2026-10-15

## Articles

- **An approved mockup is the source of truth for how a screen looks.** Where mockups exist, a
  change of the look starts with a change of the mockup. The changed mockup is shown to the owner,
  and the code is written only after their approval. An agreement in words does not replace the
  mockup: the owner reads the screen by the picture. A detail the code adds past the mockup reads to
  the owner as broken layout, however correct the text behind it.
- **Mockups are kept in step with the screens they draw.** A mockup that lags behind the code no
  longer says what is right, and the next change is checked against a wrong picture. A finding along
  the way that changes the look goes to the mockup first, and only then into the code.
- **A mockup makes a layout claim, and the claim is measured.** A frame is checked by numbers, the
  way a page is: what the eye misses on a screenshot — buttons of one row off one line, frames
  overlapping on the sheet — is read from the node coordinates before the owner sees the frames.
- **A mockup of behaviour the product already has starts from the description of that behaviour.**
  A screen on a sheet looks like work without code, but how a payment is taken or which fields a
  form holds is already written down and carried out. The description is read before the first
  frame.
