# Закрытие работы

Паттерн правила `task-flow`. Что при этом должно быть верно — закон
`docs/constitution/work-conduct.md`.

## Когда брать

- Этапы замысла закрыты, проверки зелёные, отчёт готовится к публикации.
- `npm run check:specs` перечислил договорённость в разделе «Пора вливать».

## 1. Договорённость вливается в спек домена

Последним коммитом отчёта, до слияния. Код к этому моменту написан, поэтому привязки
`файл:символ` известны — правило въезжает в спек домена сразу проверяемым.

```bash
npm run check:specs   # раздел «Пора вливать» называет готовые директории
```

Порядок переезда:

- правила из `proposed/<фича>/spec.md` дописываются в `spec.md` домена, в его разделы;
- сценарии переезжают в `scenarios.md` домена **с прежними номерами**: на них ссылаются
  заголовки тестов, и пересчёт рвёт сверку;
- привязки из `proposed/<фича>/implementation.md` дописываются в `implementation.md` домена
  и проставляются на код, который теперь есть;
- законы, объявленные фичей в шапке, дописываются в шапку спека домена;
- директория `proposed/<фича>/` удаляется, строка о фиче снимается из раздела «Что
  предложено, но ещё не выкачено» в `docs/specs/README.md`;
- домена ещё не было — `proposed/` заменяется полноценным спеком, и домен получает строку в
  таблице `docs/specs/README.md`.

Работа шла несколькими задачами — вливание идёт в последней из них. Какая последняя, видно в
`docs/plans/<линия>.md`; закрытая линия уезжает в `docs/archive/` или удаляется.

```bash
npm run check:specs   # после вливания: привязки на месте, сценарии не потерялись
```

## 2. Папка задачи разбирается

Целиком в архив не переносится: `docs/archive/` — место для записей о состоявшемся, которые
кто-то читает, а не свалка ходов работы.

| Файл          | Куда                                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| `grill.md`    | в `docs/archive/` — ответы владельца невосстановимы, и это единственная запись о том, почему задача поставлена так |
| `progress.md` | в `docs/archive/`, если в нём есть решения по ходу с причинами; иначе удаляется                                    |
| `plan.md`     | удаляется — после выкатки на его вопрос отвечает код, а на «как работает» отвечает спек домена                     |

Уезжающее складывается одним файлом с говорящим именем, а не папкой из трёх:

```bash
cat docs/tasks/<КЛЮЧ>-<номер>-<slug>/grill.md > docs/archive/<ЧТО_РЕШАЛИ>.md
rm -r docs/tasks/<КЛЮЧ>-<номер>-<slug>
```

Разбор идёт в том же отчёте, что и работа: папка, оставленная до мержа, попадает в главную
ветку и читается там как текущая.

## 3. Сверка

```bash
npm run check:board   # папка закрытой задачи среди текущих, брошенные черновики
npm run check:specs   # договорённость влита, привязки на месте
npm run check:docs    # пути, названные в текстах, существуют
```

## Ловушки

- **Папку разбирают до мержа — после него о ней уже никто не вспомнит.** Сверка очереди
  считает задачу закрытой по мержу: до него папка среди текущих законна, а после за неё никто
  не отвечает — работа ушла в следующую задачу, и находка приходит в чужой заход. Дважды
  подряд папка закрытой задачи так и уехала в главную ветку. Разбирают её тем же PR, что и
  работу, а не отдельным заходом «потом».
- **Вливание после мержа не делается.** В главной ветке тогда лежит раздел «предложено, но не
  выкачено» с тем, что работает месяц, — беззвучная ложь, тем убедительнее, чем старше.
- **Номера сценариев при вливании не пересчитываются.** Идентификатор — ключ связи с тестами;
  сдвиг рвёт сверку у соседей, которых правка не касалась.
- **Правило без привязки в спек домена не въезжает.** Кода, который его исполняет, нет —
  значит это намерение, и место ему в открытых вопросах домена, а не в правилах.
- **Архив не обновляется после выкатки.** Уехавшее туда описывает день переезда, и правится
  оно только вместе с признанием, что описывало неверно.
