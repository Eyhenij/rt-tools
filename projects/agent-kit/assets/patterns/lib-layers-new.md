# Завести или удалить либу

Паттерн правила `lib-layers`. Что при этом должно быть верно — закон
`docs/constitution/lib-imports.md`.

## Когда брать

- Заводится новый домен или новый слой существующего домена.
- Либа переименовывается.
- Либа удаляется.

## Сначала — нужна ли либа вообще

У домена есть экраны, состояние и запросы. Механика, общая нескольким доменам, доменом не
заводится: слои под неё останутся пустыми навсегда.

Признак: если ни `feature`, ни `data-access`, ни `api` наполнить не из чего — это утилиты, и
им место в либе, которой они уже видны. У фронта такая либа есть всегда — основание семейства;
у бэкенда — тот слой `util`, что уже перечислен у каждого домена.

Так домен `list` жил девятью либами на три файла кода: семь либ пустых, и у каждой свои
`project.json`, `vitest.config.mts`, барель, тег и алиас.

## Заводится генератором, а не голым `nx g`

```bash
node tools/generate-domain-lib.mjs
```

Генератор кладёт `project.json`, `tsconfig.json`, `vitest.config.mts` и барель. Голый `nx g`
даёт конфиг vitest без `passWithNoTests`, и либа, у которой спек ещё нет, роняет
`nx run-many -t test` строкой «No test files found». Проверка раскладки смотрит на наличие
файла, а не на его содержимое, поэтому такую либу она пропустит.

## Что дописывается руками

1. Тег в `eslint/boundaries/domains/<семья>-<домен>.config.mjs` — один на либу, равный имени и
   пути.
2. Алиас в `tsconfig.base.json`.
3. README либы: что в ней лежит и кто её зовёт.

Права на чужие либы выписываются строками с комментарием, зачем. Импорт, который «просто
заработал», означает, что тег ещё не сужен.

## Удаление

```bash
git rm -r libs/<семья>/<домен>/<слой>
rm -rf libs/<семья>/<домен>/<слой>
```

`git rm -r` оставляет за собой `node_modules/.vite` внутри удаляемого каталога, и проверка
раскладки продолжает видеть его как домен без слоёв. Добивать `rm -rf`.

Следом снимаются тег, алиас и строки прав у тех, кто либу видел.

## Проверить

```bash
npm run check:layers
```

Проверка смотрит слои, единственный тег = имя = путь, алиас, наличие `project.json`,
`vitest.config.mts` и `src/index.ts`, пустой список зависимостей у `common/util`, границы
основания семейства и реэкспорты. Секунды — гонять после любого создания, переименования или
удаления.

## Частые промахи

- Либа заведена под механику: слои пустые и заполнять их нечем.
- Голый `nx g` — конфиг vitest без `passWithNoTests`, и общий прогон тестов краснеет.
- Удаление без `rm -rf` — проверка видит призрак домена без слоёв.
- **Либа, которую никто не импортирует, не проверена ничем.** `nx lint` и `nx test` проверяют
  её саму, а не договор с потребителем. Первый импортёр и есть первая проверка: слой моделей
  принимается после `nx build` и живого прогона сценария, а не по зелёному `lint test`.
