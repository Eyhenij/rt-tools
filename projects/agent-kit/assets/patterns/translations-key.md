# Ключ перевода

Паттерн правила `translations`. Что при этом должно быть верно — закон `{{lawsDir}}/locales.md`.

## Когда брать

- В интерфейсе появляется любой текст, который видит человек.
- Правится подпись, пустое состояние, текст отказа, подпись кнопки подтверждения.

## Куда кладётся ключ

Словари разложены по разделам, и наборы ключей сверяются **внутри раздела**: общее для всех
приложений, публичная часть, внутренняя часть, письма. Ключ заводится во всех локалях сразу —
пустое значение считается пропуском, а не переводом.

## Подстановка

В разметке — преобразователем, в классе — реактивным значением:

```html
<h1 rtElem="title">{{ '<ключ заголовка>' | <перевод> }}</h1>
<table [emptyMessage]="'<ключ пустого списка>' | <перевод>"></table>
```

```typescript
protected readonly title: Signal<string> = translateSignal('<ключ заголовка>');
```

## Дозаполнить и проверить

Дозаполнение недостающего делается командой, а полноту держит тест: он роняет прогон на
недостающем или пустом ключе. Глазами это не проверяется — ключей тысячи.

## Частые промахи

- **Текст строкой прямо в шаблоне:** он уедет в интерфейс на одном языке во всех локалях.
- **Ключ заведён только в паре локалей:** тест полноты падает, но замечают это уже в гейте
  пуша.
- **Пустая строка вместо перевода:** на экране она выглядит как задуманная — кнопка без
  подписи, заголовок без текста.
- **Ключ положен не в свой раздел:** наборы сверяются внутри раздела, и расхождение вылезет как
  недостача в другом.
- **Свой ключ успеха у панели правки записи:** текст успеха принадлежит самой операции и
  заводится во всех локалях сразу.
