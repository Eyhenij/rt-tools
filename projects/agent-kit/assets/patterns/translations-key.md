# Ключ перевода

Паттерн правила `translations`. Что при этом должно быть верно — закон
`docs/constitution/application/locales.md`.

## Когда брать

- В интерфейсе появляется любой текст, который видит человек.
- Правится подпись, пустое состояние, текст отказа, подпись кнопки подтверждения.

## Куда кладётся ключ

`libs/common/i18n/src/lib/dictionaries/<локаль>/<раздел>.json`. Разделов четыре, и наборы
ключей сверяются внутри раздела:

| Раздел        | Что в нём                   |
| ------------- | --------------------------- |
| `common.json` | общее для сайта и админки   |
| `site.json`   | публичный сайт              |
| `admin.json`  | админ-панель                |
| `mail.json`   | письма и документ-основание |

Локалей восемь: `en`, `ru`, `de`, `zh-Hans`, `zh-Hant`, `ko`, `th`, `hi`. Ключ заводится во
всех — пустое значение считается пропуском, а не переводом.

## Подстановка

В разметке — пайпом:

```html
<h1 rtElem="title">{{ 'bookingsTitle' | transloco }}</h1>
<<префикс>-table [emptyMessage]="'bookingsEmpty' | transloco" [ariaLabel]="'bookingsTableAria' | transloco">
```

В классе — сигналом:

```typescript
protected readonly title: Signal<string> = translateSignal('promoCodesTitle');
```

## Дозаполнить и проверить

```bash
npm run i18n:fill        # дозаполняет недостающее в остальных локалях
npx nx test common-i18n  # роняет сборку на недостающем или пустом ключе
```

## Частые промахи

- Текст строкой прямо в шаблоне: он уедет в интерфейс по-английски во всех локалях перевода.
- Ключ заведён только в `en` и `ru`: тест полноты падает, но замечают это уже в гейте пуша.
- Пустая строка вместо перевода: на экране она выглядит как задуманная — кнопка без подписи,
  заголовок без текста.
- Ключ положен не в свой раздел: наборы сверяются внутри раздела, и расхождение вылезет как
  недостача в другом.
- Свой ключ успеха у панели правки записи: текст успеха принадлежит мутации, и заводится он во
  всех локалях перевода сразу.
