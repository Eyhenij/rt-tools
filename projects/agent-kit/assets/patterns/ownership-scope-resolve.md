# Разрешение владеющей сущности в процедуре

Паттерн правила `ownership-scope`. Что при этом должно быть верно — закон
`docs/constitution/application/ownership.md`.

## Когда брать

- Процедура принимает идентификатор владеющей сущности.
- Экран или сводка отвечает сразу по всем действующим.
- Заводится новый домен, записи которого принадлежат владеющей сущности.

## Одна сущность

```typescript
const ownerId: string = await resolveRequestedOwner(this.#db, request.ownerId);
```

Обёртка сама разбирает случаи и переводит их в отказ:

| Что пришло                                            | Что происходит            |
| ----------------------------------------------------- | ------------------------- |
| пусто, действующая одна                               | берётся она               |
| пусто, действующих две и больше                       | `Code.InvalidArgument`    |
| пусто, действующих нет вовсе                          | `Code.FailedPrecondition` |
| названная явно, есть — хоть действующая, хоть скрытая | берётся она               |
| названная явно, такой нет                             | `Code.NotFound`           |

Своего разбора не заводить: чистая функция разбирает случай, обёртка ходит в хранилище. Вторая
реализация того же правила однажды уже жила у обработчика статистики соседнего домена и успела
разойтись порядком выборки.

## Все действующие

Там, где показана сводка, пустой идентификатор означает все действующие:

```typescript
const ownerIds: string[] = await resolveRequestedOwners(this.#db, request.ownerId);
```

Так отвечают списки, статистика и дашборд.

## Отбор вместо своего поля запроса

У списка, переведённого на общую выборку, сущность приходит условием отбора, а не отдельным
полем: прежний номер поля в контракте помечен `reserved`.

```
reserved 4;
reserved "owner_id";
```

## Частые промахи

- Свой разбор пустого идентификатора в обработчике: он разойдётся с общим при первой же правке.
- Один и тот же код отказа на «действующих нет» и «такой сущности нет»: для вызывающего это
  разные случаи.
- Подстановка скрытой, когда действующих нет: скрытая вместо отсутствующей действующей не
  берётся.
- Общая настройка, действующая сразу на все: заведение второй не должно менять поведение
  первой.
- Новое поле идентификатора рядом с выборкой у списка: отбор, живущий отдельно, не виден ни
  стору, ни адресу.
