# Сквозные спеки

Паттерн правила `testing`. Что при этом должно быть верно — закон
`{{lawsDir}}/verifiability.md`.

## Когда брать

- Пишется или правится сквозная спека.
- Надо воспроизвести дефект, который виден только на прод-конфигурации.
- Готовится стенд под прогон против прокси.

## Сквозной спекой закрывается накопленное состояние

Случай для неё — тот, где состояние копится нажатиями: открытая панель, активный маршрут, страж
прошлого экрана. Всё, что проверяется одним заходом по адресу, дешевле закрыть юнитом на чистой
функции или замером экрана.

Отсюда и способ: нажатия по тем же элементам, что нажимает владелец, несколько подряд, без
перезагрузки между ними. Заход по прямому адресу поднимает приложение заново, накопленного
состояния у него нет, и проход читается как «дефект не подтверждается».

Элементы находятся по якорям спек: классы меняются вместе с вёрсткой, а поиск по роли и тексту
ломается на переводах.

## Прогон

По умолчанию конфиг идёт на порт разработки и подхватывает уже поднятый сервер. С заданным
адресом стенда свой сервер не стартует вовсе.

Полный набор спек с настоящей сессией гоняется **одним рабочим**: такие тесты правят одни и те
же записи живого хранилища и в параллельном прогоне мешают друг другу. Одни и те же файлы дают
падения на многих рабочих и ноль на одном.

## Стенд из прод-сборки под настоящим прокси

Дешевле полного состава прода: один контейнер прокси с боевым конфигом, а приложения за ним —
процессы на хосте.

```bash
<сборка всех приложений>
<адрес хранилища> <порт> node <собранный сервер> &
docker run -d --name <стенд> \
  --add-host <имя апстрима>:host-gateway \
  -p <внешний порт>:80 \
  -v "$PWD/<конфиг прокси>:/etc/nginx/conf.d/default.conf:ro" \
  -v "$PWD/<каталог сборки>:/usr/share/nginx/html:ro" \
  <образ прокси>
```

Порты апстримов зашиты в конфиг именами — менять их нельзя, подстановка хоста заменяет только
адрес.

## Выключатели

```
const РАЗРЕШЕНО = окружение['<имя переменной>'] === '1';
тест.пропустить(!РАЗРЕШЕНО, 'меняет живой адрес записи: включается переменной');
```

- Спека, необратимо меняющая данные стенда, по умолчанию пропускается и включается своей
  переменной.
- Проверки, которым нужен прокси, просыпаются вместе с адресом стенда. Голый сервер отдачи
  страниц их не проходит, и падения выглядят регрессией.
- Правило линтера, запрещающее выключенный тест, снимается в конфиге: выключатель здесь — приём,
  а не забытый пропуск.

## Частые промахи

- **Порт приложения занимать осторожно:** стенд разработчика ходит по тому же имени через
  подстановку хоста, и пока на нём висит чужой процесс, стенд отдаёт чужую сборку.
- **Браузер обычно установлен один.** Ошибка «Executable doesn't exist» разобрана в правиле
  `testing`: она же приходит после смены версии прогонщика.
- **Спеки без учётных данных пропускаются молча** — прогон выглядит успешным, а проверено
  меньше половины.
- **Конфиг прокси монтируется каталогом, а не одиночным файлом:** редактор пересоздаёт файл, и
  контейнеру остаётся обрезанная копия.
- **Подменяется не только то, что запрашивает экран, но и то, что запрашивает шапка.** Общий
  запрос идёт на каждом экране; без подмены на него отвечает настоящий сервер, поддельный вход
  он отбивает, перехватчик сбрасывает сессию — и десятки тестов падают на пропавшей шапке, что
  выглядит дефектом экрана.
- **Каталог сборки, удалённый под смонтированным томом, оставляет контейнер с пустым корнем:**
  стенд отвечает отказом на всё, и падают сразу все тесты. Контейнер после такого удаления
  пересоздаётся.
