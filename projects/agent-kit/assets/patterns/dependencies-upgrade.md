# Подъём версий

Паттерн правила `dependencies`. Что при этом должно быть верно — закон
`docs/constitution/delivery.md`.

## Когда брать

- Поднимается версия любого пакета.
- Пришло предупреждение об уязвимости в транзитивной зависимости.
- После установки посыпались замечания линтера или переформатировалось дерево.

## Верхнюю границу задают peer-диапазоны

```bash
npm view @angular/compiler-cli@22.1.0 peerDependencies
npm view typescript versions --json | tail -5
```

Пакет поднимают до последней версии, которая ещё попадает в peer-диапазон каждого, кто от него
зависит, а не до последней в реестре. Проверять приходится по одному пакету: `autoInstallPeers:
true` молча доставляет недостающее, и конфликт peer-диапазонов установку не останавливает.

## Порядок

1. `package.json` — точные номера, ни одного `^` и `~`.
2. `pnpm install`; снимок едет тем же коммитом.
3. `npx nx run-many -t build -p site admin api` — сборка **до** линтеров: о несовместимости
   типов она говорит одной строкой, а линтер на том же дереве даёт сотню замечаний, и
   настоящая причина в них теряется.
4. `npm run lint` и `npm run stylelint`.
5. Тесты — правило `testing`. После смены версии Playwright сначала
   `npx playwright install chromium`.
6. Обход экранов в браузере — правило `browser-verification`: если пакет рисует вёрстку, смену
   его версии тесты не покрывают.

## Переформатирование

Обновлённый форматтер меняет все файлы дерева. Что из этого оставлять, решает не размер дифа,
а то, чьё форматирование проверяет линтер: `.ts` и `.html` — `eslint.config.mjs`, `.scss` —
`stylelint.config.js`. Остальное переформатируется потом, вместе с правкой, которая эти файлы
и так трогает: полный прогон изменил 883 файла, из которых проверяются 85, и осмысленные
правки в такой куче не разглядеть.

## Новые правила линтера

Правило, которое запрещает приём, принятый в этом дереве, выключают один раз в конфиге и
пишут рядом причину. Правило, которое право по существу, обходят точечным
`eslint-disable-next-line` — тоже с причиной. Смешивать нельзя: выключенное в конфиге без
причины через месяц выглядит забытым, а шестьдесят пять точечных обходов одного правила —
списком того, что надо было выключить один раз.

## Частые промахи

- `pnpm install` не двигает пакет, если он назван в `overrides`: строка из списка держит
  прежнюю версию, а установка проходит без ошибок.
- Линтеры до сборки — лишний круг: разбираешь замечания, которых после сборки не будет.
- Обновление, попавшее в ветку с другой задачей, откатится только вместе с ней: у обновления
  зависимостей своя задача и своя ветка.
