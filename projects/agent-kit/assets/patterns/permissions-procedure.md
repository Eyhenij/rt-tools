# Объявление доступа

Паттерн правила `permissions`. Что при этом должно быть верно — закон `{{lawsDir}}/access.md`.

## Когда брать

- Заводится обработчик серверной стороны.
- Раздел интерфейса закрывается правом.
- Обработчик должен отвечать гостю.

## Метка на классе обработчика

Объявление ровно одно; без него приложение не поднимается:

```typescript
@Injectable()
@ConnectProcedure()
@RequiresPermission('<ресурс>:<действие>')
export class LinkEntityProcedure implements IConnectProcedure<typeof DomainService.method.linkEntity> {
    public readonly method: typeof DomainService.method.linkEntity = DomainService.method.linkEntity;
}
```

| Метка                            | Кому доступно                                     |
| -------------------------------- | ------------------------------------------------- |
| требование права                 | вошедшему с этим правом                           |
| требование входа                 | любому вошедшему; так живут профиль и выбор языка |
| публичный доступ                 | гостю без входа                                   |
| публичный доступ с чтением входа | гостю, но токен читается, если он есть            |

Аргумент — причина для читателя кода. Ни в ответ, ни в журнал она не уходит.

## Отбивка

Перехватчик отвечает до тела обработчика:

- нет входа там, где вход нужен, — неаутентифицирован;
- вход есть, права нет — отказ в доступе;
- обработчик, о котором перехватчик ничего не знает, — тоже отказ, а не пропуск.

Сам обработчик решения о допуске не принимает.

## Раздел интерфейса

Пункт меню и адрес закрываются одной декларацией: шапка берёт из неё подписи и адреса, страж —
права. Второго объявления этой связи не заводится.

Закрытие двухслойное: право пользователя и признак незавершённости раздела. Пункт с признаком
объявляется без прав и без адреса — право открывает экран, а экрана нет. Появится экран —
признак снимается, права добавляются.

## Частые промахи

- **Два объявления доступа на одном обработчике:** приложение не поднимется, и увидено это
  будет только при запуске.
- **Проверка права внутри тела:** право проверяется до тела.
- **Своё объявление прав рядом с маршрутами:** оно разойдётся с декларацией меню, и получится
  «пункта не видно, а страница открывается».
- **Страж, повешенный на защищённую группу целиком:** он отрабатывает один раз за загрузку
  страницы и переходов между разделами не видит.
- **Ожидание прав, которое роняется на отказе запроса:** с неизвестными правами не закрывается
  ничего, и пустая шапка выхода владельцу не оставляет.
