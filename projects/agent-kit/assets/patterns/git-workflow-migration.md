# Миграция и прогон цепочки

Паттерн правила `git-workflow`. Что при этом должно быть верно — закон `{{lawsDir}}/delivery.md`.

## Когда брать

- Правится схема хранилища.
- Заводится или переименовывается каталог миграции.
- Ветка с новой миграцией готовится к слиянию.

## Цепочка гоняется на одноразовом хранилище

Линтеры, тесты и сборки порядок миграций не трогают вовсе, а проверка соответствия схемы идёт
уже после слияния. Поэтому ветка прогоняется до слияния на пустом хранилище:

```bash
docker run -d --rm --name <проба> -e <пароль> -p <порт>:<порт> <образ хранилища>
docker exec <проба> <проверка готовности>   # накат до готовности падает на соединении
<адрес хранилища> npx <инструмент> migrate deploy
<адрес хранилища> npx <инструмент> migrate diff --from-config-datasource --to-schema <схема> --exit-code
docker stop <проба>
```

Одноразовое хранилище, а не своё: гард запросов отбивает схемные команды, и завести базу под
проверку иначе нечем. Адрес ставится префиксом самой команды — экспорт между вызовами не живёт.

## Файл миграции пишется тем же хранилищем

Команда разработчика для миграций не запускается: любое расхождение состояния она лечит
предложением сбросить хранилище, а в локальном лежат данные владельца. Файл берётся разницей
между накатанной цепочкой и схемой.

Каталог заводится **после** наката цепочки: пустой каталог, попавший в накат, помечается
применённым, и его содержимое на это хранилище уже не встанет.

## Локальное хранилище догоняет ветку

Переименованная миграция остаётся в нём под прежним именем, и накат падает на «объект уже
существует». Состояние правится отметкой о применении, повторный накат его не чинит.

## Частые промахи

- Метку времени ставит момент создания, а порядок применения лексикографический: миграция из
  ветки, начатой раньше, встаёт перед той, от которой зависит. На существующем хранилище это
  незаметно — падает только накат с нуля.
- Флаги инструмента не те, что в примерах из сети, и на неизвестный флаг он печатает справку, а
  не строку ошибки. Какие флаги есть сейчас, смотрят в его собственной справке.
- Запись в боевое хранилище запрещена совсем: схема меняется миграцией через выкатку, данные —
  через интерфейс.
- Строки адресуются по первичному ключу, а не по маске: удаление по маске уносит вместе с
  пробными записями настоящие.
