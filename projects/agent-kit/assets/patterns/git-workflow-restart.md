# Ручной перезапуск прода

Паттерн правила `git-workflow`. Что при этом должно быть верно — закон `{{lawsDir}}/delivery.md`.

## Когда брать

- Правилось окружение прода, и контейнер надо поднять заново.
- Разбирается, что именно сейчас выкачено.
- Контейнер поднимается на сервере руками, мимо выкатки по слиянию.

## Команда обязана нести хеш коммита

Выкатка ставит образы по хешу коммита. Без явного тега подъём контейнера подставляет умолчание
«последний», а оно в реестре отстаёт от главной ветки — прод молча откатывается на старый образ
и при этом отвечает:

```bash
IMAGE_TAG='<хеш>' docker compose -f <состав прода> --env-file <окружение> pull <службы>
IMAGE_TAG='<хеш>' docker compose -f <состав прода> --env-file <окружение> up -d --no-build --remove-orphans
```

## Хеш берётся до перезапуска

У выкаченного контейнера или у последнего слияния в главную ветку:

```bash
docker inspect <контейнер> --format '{{.Config.Image}}'
```

## Сверка идёт по журналу, а не по коду ответа

Подмена образа видна только по пропавшим строкам нового кода: сводка запуска из журнала
исчезает, хотя строка «приложение поднялось» остаётся на месте. После перезапуска — тот же
осмотр образа и наличие ожидаемых строк в журнале.

## Частые промахи

- Вывод «прод жив, значит выкатилось» — код ответа подмену образа не показывает.
- Переменные окружения, секреты и записи имён ставятся **до** слияния: слияние выкатывает
  сразу, и ветка, зависящая от новой переменной, встаёт на проде до того, как переменную
  заведут.
- Заход на сервер в автоматическом режиме режется правилом — нужен обычный.
