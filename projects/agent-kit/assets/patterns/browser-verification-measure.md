# Замер вместо взгляда

Паттерн правила `browser-verification`. Что при этом должно быть верно — закон
`{{lawsDir}}/verifiability.md`.

## Когда брать

- Правилась вёрстка, и надо подтвердить результат.
- Экран выглядит не так, а искать нечего: поиск по коду отвечает «чисто».
- Проверяется узкий экран.

## Вывод подкрепляется числом

Вычисленный стиль, прямоугольник элемента, контраст, совпадение центров, попадание в видимую
область. «Выглядит нормально» результатом проверки не является.

Замер отвечает только на тот вопрос, который задали. Совпадение перечисленных свойств ничего не
говорит о правиле, которого в списке замера нет. Если исходники образца доступны, расхождение
ищется чтением, а замер остаётся проверкой результата.

Вид элемента, которого сегодня не видно ни на одном экране, замером не подтверждается, и
правило о нём остаётся гипотезой.

## Значение, которого в коде нет

Гарнитуру, межстрочный интервал, цвет и оформление элементам формы задаёт браузер, и в дереве
этих значений нет. Поиск по коду на такой дефект отвечает «чисто», линтер и сборка молчат.
Ищется разбивкой вычисленного значения по всем узлам страницы, а не замером у пары элементов:

```javascript
[...document.querySelectorAll('*')].reduce((acc, el) => {
    const key = getComputedStyle(el).fontFamily;
    acc[key] = (acc[key] ?? 0) + 1;
    return acc;
}, {});
```

Счёт годится любому наследуемому свойству: смотрится не одно значение, а число узлов с
неожиданным. Так находятся десятки элементов, набранных не той гарнитурой, — по одному их не
заметил бы никто.

## Узкий экран

Изменение размера окна не работает, когда браузер в полноэкранном режиме: инструмент рапортует
успех, ширина не меняется, медиазапросы остаются широкими. Узкие ширины проверяются во
вложенной рамке нужной ширины — внутри неё запрос ширины считается от рамки, и рамка своей
толщиной уменьшает внутреннюю ширину.

Правка числа элементов в контейнере — это правка раскладки: она проверяется на узкой ширине, а
не только кодами ответа.

## Ловушки инструмента снимка экрана

- **Координаты нажатия — координаты снимка, а не страницы.** При широком окне снимок приходит
  уже, и нажатие по «увиденной» координате уходит мимо, давая ложный сигнал: пересчитывать по
  фактическому масштабу либо целиться поиском элемента.
- **Область приближения должна целиком лежать внутри видимой области.**
- **Между нажатиями обязательно ожидание:** цикл «нажал — прочитал разметку» без него читает
  состояние до перерисовки и возвращает устаревшие значения.
- **Выбор браузера протухает.** На длинной проверке это срабатывает посреди работы — не сбой
  стенда, а повод повторить вызов и продолжить.

## Поведение маршрутизации воспроизводится нажатиями

Подстановка адреса, программный переход и заход по прямой ссылке поднимают приложение заново, и
накопленного состояния — открытой панели, стража прошлого экрана — у него нет. Чистый проход по
адресам читается как «дефект не подтверждается».

## Частые промахи

- **Комментарий в конфиге — гипотеза наравне с прочими.** Утверждение о поведении кэша
  переживает несколько кругов разбора кода и опровергается одним запросом.
- **Вывод «дефекта нет, это кэш» закрывает разбор**, поэтому принимается только после проверки
  на чистой сборке.
- **Дефект в клиентском куске от компиляции до правки выглядит как дефект кода** — признак
  сборки для разработки — имена файлов без хеша.
