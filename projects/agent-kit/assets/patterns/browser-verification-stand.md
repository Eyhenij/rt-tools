# Честный стенд

Паттерн правила `browser-verification`. Что при этом должно быть верно — закон
`docs/constitution/verifiability.md`.

## Когда брать

- Проверяется то, чего на дев-сервере не видно: разметка от сервера, локали, кэш,
  перенаправления, заголовки, размер бандла.
- Порт отвечает не тем, чего ждали.
- Нужен вход в админку.

## Сначала — что отвечает на порту

До первого запроса, а не после непонятного ответа:

```bash
lsof -nP -iTCP:3333 -sTCP:LISTEN
```

На 3333 регулярно висит собранный артефакт из прошлой сессии
(`node -r dotenv/config dist/apps/api/main.js`): он отвечает 200 старым кодом, а процедуры,
заведённой в ветке, у него нет вовсе. Таких процессов бывает несколько, и снимать надо все —
по PID из `lsof`, каждый: `pkill` по шаблону `nx serve api` не попадает ни в один.

## Прод-сборка сайта

```bash
npx nx build site
PORT=4930 node dist/apps/site/server/server.mjs
```

Это не дев-сервер: гард ловит `nx|ng serve`, пакетные раннеры и статические серверы, а запуск
собранного сервера пропускает.

## Стенд админки

```bash
npx nx build admin --base-href=/
```

Без `--base-href` стенд отдаёт пустую страницу без ошибок в консоли. Стенду, на котором нужен
Angular DevTools, нужна ещё и dev-конфигурация (`--configuration=development`): прод-сборка не
публикует `window.ng`. Выводы о размере бандла и минификации на такой сборке делать нельзя.

Сессия кладётся в `localStorage['vm.admin.token']` **строкой JSON** (`JSON.stringify(token)`),
иначе приложение её не прочитает. Токен не подписывается руками, а берётся у живого API:
`POST /<область>.v1.AuthService/Login`. Команду с паролем классификатор блокирует — обходить не
надо, спрашивать разрешение у владельца.

Взять уже открытую сессию нельзя: чтение `localStorage['vm.admin.token']` из браузера
блокируется. Оба пути к своему стенду упираются в пароль, поэтому остаётся третий — смотреть
на админке владельца, где вход уже сделан. Свой стенд нужен, только когда проверяют
прод-сборку, `--base-href` или конфиг nginx; чтобы просто посмотреть экраны, он не нужен.

## Стенд API

Собранный артефакт поднимается на свободном порту, а не на 3333: на 3333 отвечает API
владельца, и окружение у него не то, которое проверяется.

```bash
npx nx build api
env -u JWT_SECRET NODE_ENV=production API_PORT=3999 DATABASE_URL=… node dist/apps/api/main.js
```

Переменные окружения задаются в самой команде, по одной на проверяемый случай. Отказ на
старте — такой же результат проверки, как ответ 200: приложение, упавшее в фабрике
провайдера, порт не слушает вовсе, и это видно по `lsof`, а не по тексту в консоли.

Процедура зовётся полным именем, как её объявляет контракт:

```bash
curl -sS -X POST http://localhost:3999/<область>.v1.AuthService/GetMe \
    -H 'content-type: application/json' -H "authorization: Bearer $TOKEN" -d '{}'
```

Токен подписывается руками только там, где проверяется сама подпись: доказать, что отладочный
ключ принимается, другого пути не имеет. Во всех остальных случаях токен берётся у живого API
входом — рукописный скрывает расхождение состава притязаний.

## Стенд под настоящим nginx

Кэш, перенаправления и заголовки живут в `deploy/nginx.conf`, а не в приложении. Любой вывод
про `301`, `Cache-Control` и `X-Cache-Status` делается только здесь:

```bash
docker run -d --name <префикс>-stand-nginx \
  --add-host api:host-gateway --add-host ssr:host-gateway \
  -p 8188:80 -p 8189:8081 \
  -v "$PWD/deploy/nginx/main.conf:/etc/nginx/nginx.conf:ro" \
  -v "$PWD/deploy:/etc/nginx/conf.d:ro" \
  -v "$PWD/dist/apps/admin/browser:/usr/share/nginx/html/admin:ro" \
  nginx:1.27-alpine
```

- Конфиг монтируется **каталогом**, а не одиночным файлом: редактор пересоздаёт файл,
  контейнеру остаётся обрезанная копия, и `nginx -t` внутри падает на «unexpected end of file»
  при целом файле снаружи. Лечится пересозданием контейнера, а не правкой конфига.
- Главный конфиг подставляется отдельной строкой: он лежит в `deploy/nginx/`, а не рядом с
  `nginx.conf`, — файл с расширением `.conf` в смонтированном каталоге попал бы в `include`
  и уронил бы nginx на директиве `user`. Без него стенд поднимается на конфиге образа, и
  предел соединений на воркер там свой.
- Сервер отдачи страниц отвечает `400` на чужой `Host`: все запросы идут с
  `-H "Host: localhost"`.
- Переменные окружения стенда обязаны смотреть на процессы стенда. `CACHE_REFRESH_URL`,
  направленный на 4900, сбрасывает кэш мимо того процесса, который держит справочник
  перенаправлений в памяти, — исправный механизм при этом выглядит сломанным.

## Дерево для сравнения

Сказать «это сломала правка» можно, только если видно, что до правки было иначе. Проверяют это
вторым деревом, а не по памяти:

```bash
git worktree add ../<префикс>-base <коммит>   # ветка задачи не трогается
pnpm install --frozen-lockfile         # из ../<префикс>-base: node_modules у него свои
```

- Для сравнения берут не главную ветку, а последний коммит, на котором дерево собирается:
  главная бывает сломана, и тогда «до» и «после» различаются не из-за правки. Собирается ли
  коммит — проверяют сборкой, а не тем, что он в главной ветке.
- Стенд второго дерева поднимают на своих портах: 4900, 4901 и 3333 заняты владельцем, а 4000
  занимать нельзя — стенд разработчика ходит по имени `ssr:4000`.
- Оба стенда держат поднятыми одновременно: если сравнивать по памяти между двумя запусками,
  заметишь только то, что успел запомнить.

## Частые промахи

- Свой дев-сервер не поднимать: сайт на 4900, админка на 4901, API на 3333 уже подняты
  владельцем, и второй экземпляр отбивается гардом.
- **Общая сборка глушит все три дев-сервера владельца, а не только API.** После
  `nx run-many -t build` ложатся и сайт на 4900, и админка на 4901. Собирать надо то, что
  проверяешь (`npx nx build site`), а не всё дерево. Если серверы легли, поднять их обратно
  агент не может — мешает гард, поэтому владельцу говорят об этом сразу, а не в конце сессии.
- Порт 4000 занимать осторожно: стенд разработчика на 4900 ходит по тому же имени `ssr:4000`
  через `host-gateway`, и пока на нём висит чужой процесс, стенд отдаёт чужую сборку.
