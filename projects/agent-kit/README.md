# @rt-tools/agent-kit

Переносимый слой правил для агента: законы, шаблоны правил и паттернов раскладываются в
репозиторий одной командой и обновляются следующей, не затирая того, что проект дописал сам.

## Зачем

Правила, по которым агент правит код, копятся в каждом репозитории заново. Скопированные из
соседнего они устаревают молча: правку в исходнике никто не переносит, а расхождение видно
только по последствиям.

Пакет разделяет текст на три слоя. **Закон** — что должно быть верно; он не знает ни путей, ни
имён файлов. **Правило** — каким приёмом это делается; приём переносится между репозиториями
так же, как закон. **Паттерн** — готовый код приёма.

Все три везёт пакет. В проекте остаётся то, чего пакет знать не может: имена этого дерева. Они
живут при каждом правиле отдельным файлом — `implementation.md`, — и пишет его проект.

## Как пользоваться

```bash
pnpm add -D @rt-tools/agent-kit

npx agent-kit list      # что везёт пакет и что из этого взято здесь
npx agent-kit init      # спросить законы галочками и завести .claude/rt-kit.json
npx agent-kit sync      # разложить выбранное в docs/constitution/
npx agent-kit doctor    # что разложено, что отстало, чего не хватает
```

В гейте пуша:

```bash
npx agent-kit sync --check
```

Команда ничего не пишет и отказывает, если разложенное отстало от пакета или его правили
руками.

## Что где лежит

| Род | Куда ложится | Что это |
| --- | --- | --- |
| `laws` | `docs/constitution/` | что должно быть верно |
| `rules` | `.claude/skills/<имя>/SKILL.md` | каким приёмом это делается |
| `patterns` | `.claude/skills/<имя>/SKILL.md` | готовый код приёма |
| `hooks` | `.claude/hooks/` | что не даёт нарушить |
| `agents`, `commands`, `workflows` | `.claude/` | роли, слеш-команды и многошаговые прогоны |
| `checks` | `tools/` | проверки, которые зовёт гейт |
| `templates` | `.claude/rt-kit/templates/` | формы правила, паттерна, компаньона и карты гейта |

Правило и паттерн ложатся одинаково — оба скилы; различает их `kind` во вступлении файла.

## Правило и его компаньон

Правило говорит приёмом и потому переносимо. Всё, что знает только это дерево — как что здесь
называется, где лежит, чем проверяется, — живёт рядом с ним в `implementation.md`.

Черновик компаньона `sync` кладёт **один раз**, при первой раскладке правила, и больше к нему
не возвращается: своего текста у пакета там нет, а перекладывать значило бы стирать написанное
проектом. Пока в черновике осталась метка `<!-- заполняет проект -->`, `sync --check` отказывает:
правило без имён этого дерева — это закон, и агент по нему работать не может.

## Хуки

Закон и правило, которых никто не открывает, не действуют, поэтому пакет везёт и хуки, которые
их зовут.

**Гейт правил.** `skill-gate.sh` отбивает правку, пока не загружено правило под неё,
`skill-loaded.sh` записывает загрузку, `skill-gate-rearm.sh` взводит гейт заново после сжатия
контекста, `constitution-index.sh` печатает указатель законов на старте сессии.

**Сторожевые хуки.** Главная ветка, поставка, документ в одном коммите с правкой, проверки
перед пушем, линтер по следам правки, пишущие запросы к хранилищу, второй сервер разработки,
якорь для спек, переизобретение готового, формат сообщения коммита, закреплённый профиль
браузера.

**Что при этом остаётся проекту.** Хуки везут механизм, но не знают ни путей, ни команд, ни
инвентаря — это дерево знает только оно само:

| Файл проекта | Что в нём | Кто читает |
| --- | --- | --- |
| `.claude/rt-kit/gate-map.sh` | что правится — какое правило | гейт правил |
| `.claude/rt-kit/project.sh` | команды, стенды, пары «правка — документ», форма имени ветки | сторожевые хуки |
| `.claude/rt-kit/browser-device-id` | закреплённый профиль браузера этой машины | браузерные гарды |

Формы первых двух лежат в шаблонах. Нет файла — хук пропускает: пустой гард лучше гарда,
отбивающего наугад, и это же правило действует на каждую отдельную функцию профиля.

## Выбор законов

Половина законов пакета про то, чего в конкретном приложении нет вовсе: у сервиса без админки
нет ни её списков, ни её навигации. Поэтому `init` спрашивает, какие законы брать, а не кладёт
все пятнадцать молча.

```bash
npx agent-kit init                       # спросить галочками
npx agent-kit init --all                 # взять все, ни о чём не спрашивая
npx agent-kit init --laws access,delivery,verifiability
```

Без терминала — в CI, в конвейере, в чужом скрипте — спрашивать некого, и `init` без флага
отказывает вместо того, чтобы решить за проект: «взять всё» тоже решение, и принимать его
молча он не вправе.

Выбор уезжает в конфиг ключом `only` и оттуда же правится потом: `init` заведённый конфиг не
трогает. Имена законов — из `agent-kit list`, там же видно, что взято, что не выбрано и что
пропущено.

## Конфиг

`.claude/rt-kit.json` коммитится: раскладка обязана повторяться на чужой машине без вопросов.

```json
{
    "vars": { "mainBranch": "main" },
    "layout": { "laws": "docs/constitution" },
    "only": ["laws/access.md", "laws/delivery.md"],
    "skip": ["laws/admin-lists.md"]
}
```

- **`vars`** — значения дырок `{{имя}}` в тексте пакета. Пути раскладки подставляются сами:
  `{{lawsDir}}`, `{{hooksDir}}`, `{{checksDir}}`, `{{agentsDir}}`, `{{templatesDir}}`.
  Неподставленная дырка — отказ раскладки, а не строка в разложенном тексте: `{{mainBranch}}`
  посреди правила агент прочтёт как имя.
- **`layout`** — куда класть каждый род ресурса. Умолчания менять без нужды не стоит: правила
  ссылаются на законы теми же путями.
- **`only`** — что проект выбрал, идентификаторами вида `laws/<закон>.md`. Пусто — берётся всё.
  Ограничивает только те роды, которые сам называет: перечислив законы, проект говорит о
  законах, а не обо всём, что пакет везёт, — шаблоны при нём остаются.
- **`skip`** — ресурсы, от которых проект отказался, теми же идентификаторами. Вычитает из
  выбранного, поэтому отказ от одного закона не требует переписывать список из пятнадцати.

## Надстройки

Проект дописывает своё не в разложенный файл, а рядом — в
`.claude/rt-kit/overrides/<идентификатор ресурса>`. Правка разложенного файла теряется на
следующем `sync`, и пакет на неё отказывает, вместо того чтобы переписать молча.

Слияние идёт по разделам `## `:

| В надстройке | Что происходит |
| --- | --- |
| заголовок, который есть у пакета | раздел замещается целиком |
| заголовок, которого у пакета нет | раздел дописывается в конец |
| заголовок без тела | раздел пакета снимается |

Так правка пакета доезжает во все разделы, которых проект не трогал, а проектная история
решений остаётся при проекте.

## Что разложено

Каждый разложенный файл несёт шапку с версией пакета и суммой тела. По ней `sync` отличает три
случая: файл отстал от пакета, файл правили руками, файл положен вообще не пакетом. Первый
перекладывается, на двух других раскладка отказывает и называет их поимённо.

Отказ хотя бы по одному файлу не пишет ничего: половина разложенного хуже целого.

## Чего в пакете пока нет

Проверок, ролей, слеш-команд и воркфлоу он не везёт: роды заведены, ресурсов в них ещё нет.
Пресета карты хуков для настроек агента тоже нет — раскладка кладёт файлы, а карта хуков живёт
разделом в чужом JSON, и сливать его она пока не умеет. Генератора черновиков правил по закону
нет.
