# Значки: наборы и переход с первого кита

Подключение значков к приложению описано в `README.md` пакета.

## Наборы значков

Имена значков во всех наборах одни — имена кита. Свой набор — это папка SVG с этими именами:

```ts
provideRtIcons({
    sets: [
        { name: 'kit', url: '/static/icons' },
        { name: 'brand', url: '/icons-brand', fallback: 'material' },
    ],
    default: 'brand',
    glyphStrategy: 'map-first',
});
```

| поле       | что значит                                                                    |
| ---------- | ----------------------------------------------------------------------------- |
| `name`     | имя набора: строчные латинские буквы, цифры и одиночный дефис                 |
| `url`      | адрес папки с рисунками `<имя значка>.svg`                                    |
| `fallback` | откуда берётся недостающий рисунок; по умолчанию `kit`                        |
| `names`    | имена со своим рисунком; остальные идут в `fallback` без запроса              |
| `fill`     | есть ли залитые рисунки `<имя значка>.fill.svg` для входа `fill`              |

Запись с именем встроенного набора меняет только названные поля. При негодной записи значки
берутся из `kit`. Полноту набора приложения кит заранее не проверяет. О негодной записи и о
рисунке, которого нет нигде, кит пишет в консоль только в режиме разработки: из рабочей сборки
приложения эти тексты выпадают.

Набор меняется на ходу. Всему приложению — `inject(RtIconSetService).use('brand')`, `use(null)`
возвращает набор из разметки и настройки. Части страницы — директивой:

```html
<section rtIconSet="material">…</section>
```

Директива сильнее `use()`, `use()` сильнее признака material в разметке, а признак сильнее
`default`. Диалог, aside, меню, popover и подтверждение, открытые из части, берут её набор. Пока
новый рисунок не пришёл, виден старый. Уже открытое окно набора не меняет.

Часть держит то, что объявлено внутри неё. Шаблон, объявленный вне части, и содержимое, вставленное
в неё снаружи через `ng-content`, берут набор по месту объявления.

Диалог и aside берут набор у узла с фокусом в минуту открытия. Safari и Firefox на macOS не всегда
ставят фокус на нажатую кнопку: тогда набор называют входом `iconSet` в настройке окна. Aside без
фокуса в части берёт набор части из своего `injector`.

## Значки с первого кита

Приложение, пришедшее с первого кита, называет значки именами Material. Кит их больше не
переводит: приложение заменяет их своими силами. Скрипт из пакета перечисляет места, а с `--write`
заменяет статические атрибуты значков в шаблонах:

```bash
node node_modules/@rt-tools/ui-kit-v2/migrations/rename-icon-names.mjs src
```

```bash
node node_modules/@rt-tools/ui-kit-v2/migrations/rename-icon-names.mjs --write src
```

Свойства объектов, выражения и `glyph="info"` скрипт перечисляет для ручной замены: имя `info` в
ките рисует другой значок. Тег со своим `glyphStrategy="font"` или с `[glyphStrategy]` скрипт не
меняет. Имена, приходящие данными с сервера, он не видит — их переводят там, где они приходят.

Список ручных мест неполный: скрипт ищет их только на строках, где есть слово `icon` или `glyph`,
а при обходе папки читает только `.html` и `.ts`. Все старые имена и их замены лежат рядом, в
`migrations/icon-names.json`: по нему проверяют остальное. Свой тег приложения с приставкой `rt-`
скрипт считает тегом кита, поэтому сначала его запускают без `--write`.

Вход `glyph` у `rt-icon` и вход `icon` у кнопки `rtButton` остаются: имя кита рисуется рисунком,
любое другое значение — лигатурой шрифта Material Symbols. Этот шрифт кит не везёт: приложение
подключает его само, семья переназначается свойством `--rt-icon-glyph-font`.
`glyphStrategy: 'font'` рисует шрифтом любое значение, по умолчанию `map-first` — сначала имя
кита. Приложению с `font` запускать скрипт с `--write` не нужно, но имена у `rt-menu-item` и в
пунктах `rt-side-menu` оно заменяет вручную: меню лигатур не рисуют, и со старым именем пункт
остаётся без значка и под `font`.

## Что изменилось и ломает прежний код

- `provideRtIcons(adres, materialAdres, options)` заменён на
  `provideRtIcons({ sets, default, glyphStrategy })`. Было `provideRtIcons('/a', '/b')`, стало
  `provideRtIcons({ sets: [{ name: 'kit', url: '/a' }, { name: 'material', url: '/b' }] })`.
- Без замены имён значок со старым именем выглядит иначе. `rt-icon`, кнопка и ячейка таблицы
  раньше рисовали переведённое имя рисунком кита без шрифта, теперь это лигатура: без шрифта
  Material Symbols на экране стоит слово, например `delete`. Меню и боковое меню остаются без
  значка и пишут об этом только в сборке для разработки.
- Старое имя `info` есть и в ките, но рисует другой значок. `rt-menu-item` и колонка таблицы
  раньше рисовали по нему `info-circle`, теперь молча рисуют `info`: замените имя вручную.
- Таблица соответствий имён `iconMaterialMap`, тип `IRtIconMaterialEntry` и функция
  `materialPairOf` убраны: имена первого кита не переводятся.
- `RT_ICONS_BASE_URL`, `RT_ICONS_MATERIAL_BASE_URL` и тип `IRtIcon.Drawing` убраны.
- `RtIconRegistry.request` и `symbolHref` берут имя набора и признак заливки.
- Имя значка, которое приходит данными, теперь должно быть именем кита.
- `rt-menu-item` и `rt-side-menu` не рисуют имён первого кита ни при каком `glyphStrategy`.
- Значения `DATA_TABLE_FILTER_OPERATOR_GLYPHS` стали именами кита, а `dataTableIconName` ничего не
  переводит.
- Значок кнопки `rt-speed-menu` без своего `icon` — рисунок кита `bars`, а вход `icon` по умолчанию
  пуст.
