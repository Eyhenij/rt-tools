<Title>AiChatLink — `rt-ai-chat-link`</Title>

Блок `link` ответа ассистента: карточка страницы, которую ассистент предлагает открыть. Модель
отдаёт название, адрес, раздел меню и имя значка. Кит рисует карточку сам, без регистрации
отрисовщика, и никуда не переходит: нажатие уходит из чата событием `linkOpen`, а страницу
открывает приложение. Исход открытия приложение пишет в блок полем `state`.

```ts
// Блок ответа — как его отдала модель.
{ type: 'link', title: 'Продажи за ноябрь', url: '/reports/sales?month=11', section: 'Отчёты · Продажи', icon: 'chart-bar' }
```

Схему блока для модели кит отдаёт значением `RT_AI_CHAT_LINK_SCHEMA` (JSON Schema 2020-12): в ней
`title`, `url`, `section` и `icon`. Полей `state` и `reason` в схеме нет — их ставит приложение
после нажатия. Приведение данных — `rtLinkData`.

## Круг целиком

Приложение слушает `linkOpen`, ставит карточке `pending`, открывает страницу и пишет исход. Событие
приходит синхронно, внутри обработчика нажатия, поэтому новую вкладку браузер открыть разрешает.

```ts
protected onLinkOpen(event: IRtAiChat.LinkOpen): void {
    // Адрес написала модель: свои маршруты приложение узнаёт само, чужой адрес не открывает.
    if (!this.isKnownRoute(event.url)) {
        this.setLinkState(event, { state: 'failed', reason: 'Такой страницы нет' });

        return;
    }
    if (event.newTab) {
        window.open(event.url, '_blank', 'noopener');

        return;
    }
    this.setLinkState(event, { state: 'pending' });
    this.router
        .navigateByUrl(event.url)
        .then((opened: boolean): void =>
            this.setLinkState(event, opened ? { state: 'opened' } : { state: 'failed', reason: 'Нет доступа к разделу' })
        );
}

// Исход пишется в копию ленты: блок с адресом события получает `state` и `reason`.
private setLinkState(event: IRtAiChat.LinkOpen, outcome: Pick<IRtAiChat.LinkBlock, 'state' | 'reason'>): void {
    // Событие несёт адрес без пробелов по краям: адрес блока читается так же, через `rtLinkData`.
    const settle = <T extends IRtAiChat.Block>(block: T): T =>
        block.type === 'link' && rtLinkData(block)?.url === event.url ? { ...block, ...outcome } : block;

    this.messages.update((messages) =>
        messages.map((message) =>
            message.role === 'assistant' && message.id === event.messageId
                ? {
                      ...message,
                      // Карточка стоит и в секции составного ответа, поэтому секция обходится тоже.
                      blocks: message.blocks.map((block) =>
                          block.type === 'section' && Array.isArray(block.blocks) ? { ...block, blocks: block.blocks.map(settle) } : settle(block)
                      ),
                  }
                : message
        )
    );
}
```

```html
<rt-ai-chat [messages]="messages()" (linkOpen)="onLinkOpen($event)" />
```

Круг показан историями **Panel** и **FullScreen**: нажатие пишет событие строкой под чатом, первая
карточка идёт в «Открывается» и «Открыта», вторая получает отказ с причиной. Третья карточка стоит
в секции, и исход доходит до неё тем же обработчиком.

- **Адрес и исход пишет не модель.** Приложение убирает `state` и `reason` из блока, который отдала модель: схема их не называет, но проверка схемой лишних полей не отвергает.
- **Адрес пишет модель.** Кит его не проверяет и не открывает. Перед переходом приложение сверяет
  адрес со своими маршрутами; чужой адрес оно не открывает и пишет карточке `failed` с причиной.
- **Событие называет сообщение и адрес, а не место карточки.** Две карточки одного сообщения с
  одним адресом получают один исход: страница у них одна.

## Когда применять

- Ответ ассистента, где модель ведёт человека на страницу приложения: отчёт, карточку записи, раздел.

## Когда не применять

- **Ссылка в тексте ответа** — блок `markdown`: ссылку рисует `rt-markdown-text`.
- **Список источников ответа** — отдельный блок источников, а не ряд карточек страниц.

## Оси

| ось          | значения                                                       |
| ------------ | -------------------------------------------------------------- |
| исход        | нет, `pending`, `opened`, `failed` с причиной и без            |
| раздел       | есть, нет                                                      |
| значок       | имя из набора кита; без имени и с чужим именем — `link`        |
| ширина ленты | 328 и 386 — узкая панель, 640 — колонка чтения в полном экране |

Исходы показаны историей **States**, ширины макета — **Widths**, раздел и значок — **Parts**.
`Playground` — одна карточка с контролами текста, исхода и ширины.

## Края

| край                              | что происходит                                                       |
| --------------------------------- | -------------------------------------------------------------------- |
| длинное название                  | две строки и многоточие; целое название остаётся в разметке          |
| длинный раздел                    | одна строка и многоточие                                             |
| подписи кнопок длиннее ряда       | «В новой вкладке» уходит под «Открыть», за карточку ничто не выходит |
| `failed` без причины              | метка «Не открылась» без строки причины                              |
| причина при другом исходе         | не рисуется                                                          |
| неизвестный `state`               | карточка без метки исхода                                            |
| имя значка, которого в наборе нет | значок `link`: запроса за рисунком по чужому имени нет               |
| нет названия или адреса           | заглушка ленты на месте блока                                        |

Края показаны историями **Widths** (длинное название), **LongLabels** и **Invalid**.

## Состояния

| состояние    | чем задаётся       | что видно                                                 |
| ------------ | ------------------ | --------------------------------------------------------- |
| без исхода   | блок без `state`   | метки нет, обе кнопки доступны                            |
| открывается  | `state: 'pending'` | нейтральная метка с крутящимся значком, кнопки недоступны |
| открыта      | `state: 'opened'`  | метка успеха с галочкой, кнопки доступны                  |
| не открылась | `state: 'failed'`  | метка ошибки, под ней причина, кнопки доступны            |
| тёмная       | признак темы       | цвета тёмной темы                                         |

Наведение, фокус и нажатие — состояния кнопок кита, карточка своих не добавляет.

## Доступность

- Карточка — группа (`role="group"`) с именем по названию; значок от читалки скрыт.
- В ожидании кнопки несут `aria-disabled`, а не `disabled`: кнопка, нажатая с клавиатуры, держит фокус.
- Смену исхода уже нарисованной карточки зачитывает живая область ленты: «Продажи за ноябрь:
  Открыта», у отказа — с причиной. Карточка, пришедшая сразу с исходом, отдельно не объявляется.
- Исход несёт не только цвет: у метки свой значок и подпись.
- При настройке «меньше движения» значок ожидания не останавливается, а крутится медленно, как
  любой крутящийся `rt-icon`.
- В тёмной теме метка «Не открылась» читается с контрастом 2,94 : 1, строка причины — 3,16 : 1,
  ниже 4,5 : 1. Цвет ошибки в ките один на обе темы.
- При письме справа налево ряд и кнопки зеркалятся — история **Rtl**.
- Текст ответа при копировании несёт карточку одной строкой: название, раздел и адрес через табуляцию.

## Оформление

Рамка — `--rt-color-border-default`, фон `--rt-color-bg-surface`, отступ 12, скругление 12. Коробка
значка 36 на 36 со скруглением 8 на `--rt-color-bg-surface-subtle`, от неё до текста 12, от ряда до
кнопок 12, между кнопками 8. Причина — цветом `--rt-color-state-error-text`. Светлая и тёмная темы —
история **Themes**, наборы оформления — **Presets**.
