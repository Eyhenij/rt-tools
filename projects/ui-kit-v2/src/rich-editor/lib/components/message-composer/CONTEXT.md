# `rt-message-composer`

Поле отправки сообщения — капсула с круглыми кнопками: текст, вложения внутри капсулы,
необязательное форматирование и подсказка про Enter.

```html
<rt-message-composer
    placeholder="Ваш вопрос"
    [attachments]="true"
    [sending]="sending()"
    [droppedFiles]="dropped()"
    (submitted)="send($event)" />
```

| вход                   | тип                    | умолчание                |
| ---------------------- | ---------------------- | ------------------------ |
| `placeholder`          | `string`               | `''` → `chatPlaceholder` |
| `attachments`          | `boolean`              | `false`                  |
| `accept`               | `string`               | `''`                     |
| `sending` / `disabled` | `boolean`              | `false`                  |
| `formatting`           | `boolean`              | `false`                  |
| `hint`                 | `boolean`              | `false`                  |
| `toolbar`              | `TRtRichEditorToolbar` | `'full'`                 |
| `minRows` / `maxRows`  | `number`               | 1 / 6                    |
| `droppedFiles`         | `File[] \| null`       | `null`                   |

Выход: `submitted` — `{ text, delta?, files }`.

## Главное, что нужно знать

**Отправка разблокируется только при непустом содержимом.** Пробелы значением не считаются; один
вложенный файл разблокирует отправку и без текста. Во время `sending` поле и кнопка заблокированы —
иначе второе сообщение ушло бы поверх ещё не доставленного.

**Enter отправляет, Shift+Enter переносит строку.** Набор во время IME-композиции игнорируется.

**`droppedFiles` — вход, а не выход.** Файлы, брошенные в область
[`rt-file-drop`](../../../../lib/components/file-drop/CONTEXT.md) снаружи, передаются сюда входом и добавляются к
вложениям; без `attachments` они игнорируются.

**Капсула высокая, когда в ней больше одной строки.** Признак — высота текста, которую меряет
`ResizeObserver`, вложенный файл или режим форматирования; модификатор `tall` переназначает
скругление на шаг 20.

**Поле держит `content-box`, внешний отступ и место под ползунок.** Автовысота CDK пишет в `height`
высоту текста и на замере обнуляет боковой `padding`, а появившийся ползунок сужал бы поле: без
этих трёх правил текст ложился бы на строку больше, чем поле вмещает.

## Края

- После отправки форма сбрасывается целиком — и текст, и файлы.
- Ширину поле берёт от хозяина. Своей ширины у него нет намеренно: без объявленной ширины её
  задавала бы `textarea` умолчанием браузера по числу колонок, а оно считается от средней ширины
  знака доступного начертания и не держится между запусками — кадры витрины из-за этого месяцами
  давали то 192 точки, то 195.
- В режиме `formatting` текст уезжает пустым, а содержимое едет в `delta` строкой JSON.
