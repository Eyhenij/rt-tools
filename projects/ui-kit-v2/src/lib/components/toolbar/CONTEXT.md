# `rt-toolbar`

Полоса действий с тремя слотами. Слоты объявляются директивами на `ng-template`.

```html
<rt-toolbar dense>
    <ng-template rtToolbarLeft><rt-icon-button icon="arrow-left" ariaLabel="Назад" /></ng-template>
    <ng-template rtToolbarCenter><h3>Заявка №12</h3></ng-template>
    <ng-template rtToolbarRight><rt-menu … /></ng-template>
</rt-toolbar>
```

| вход            | тип       | умолчание |
| --------------- | --------- | --------- |
| `dense`         | `boolean` | `false`   |
| `filtersActive` | `boolean` | `false`   |

| выход          | когда                                          |
| -------------- | ---------------------------------------------- |
| `filtersApply` | нажата «Применить» панели отборов, она закрыта |
| `filtersReset` | нажата «Сбросить» панели отборов, она открыта  |

## Главное, что нужно знать

**Без единого слота панель не рисуется вовсе** — ни одного узла в DOM. Необъявленный слот тоже
не создаёт пустой полосы: пустая полоса занимала бы место и растягивала соседние.

**Отступ полосы сверху и снизу — свойства блока** `--rt-toolbar-padding-top` и
`--rt-toolbar-padding-bottom`, по умолчанию 8px. Список ставит им свои имена.

**Поле ввода в левой части берёт ширину из свойства блока `--rt-toolbar-field-width`**, по
умолчанию 400px (`--rt-size-100`), и не бывает шире самой части. Своей ширины у `rt-input` нет, и
без этого поиск списка сжимался до подсказки. Выпадающие отборы `rt-select` слева держат ширину по
содержимому: они стоят рядами, и по 400px каждый растягивали строку и вылезали за узкий экран. В
центре поле и отбор по-прежнему занимают всю ширину центра. Ширину берёт только поле, стоящее в
левой части прямо: поле внутри своего компонента приложения остаётся по содержимому, иначе обёртка
растёт до 400px и не сжимается, и несколько отборов не влезают в строку. На узком экране левая
часть стекает в колонку и не шире окна: у неё `min-width: 0`, иначе её наименьшая ширина бралась по
полю в 400px, и оно уходило за правый край.

**Плотная полоса остаётся строкой на любой ширине, и её левая часть сжимается.** Длинный
заголовок в ней переносится по словам и не выходит за правый край. Кнопки справа держат свою
ширину. Обычная полоса левую часть не сжимает: на узком экране она стекает в колонку.

**Отборы списка объявляются слотом `rtToolbarFilters`, и на узком месте они уходят за кнопку.** На
широком месте слот стоит в левой части после её содержимого. На узком месте
(`BreakpointsService.narrow`) вместо полей рисуется кнопка фильтров, первой в ряду кнопок правой
части; ниже 768 этот ряд начинается от левого края. Вход `filtersActive` ставит точку в угол значка.
Кнопка открывает панель `RtToolbarFiltersAsideComponent` службой боковых панелей. «Сбросить»
сообщает `filtersReset`, и панель остаётся открытой; «Применить» сообщает `filtersApply` и
закрывает её. Контекст шаблона — место, где он нарисован: `bar` или `panel`. Хозяин панели —
инжектор полосы: уничтожение полосы закрывает панель, и расширение места тоже — иначе поля отборов
стояли бы в полосе и в панели сразу. Панель держит фокус (`trapFocus`), а имя кнопки при
`filtersActive` говорит скринридеру, что отбор включён.
