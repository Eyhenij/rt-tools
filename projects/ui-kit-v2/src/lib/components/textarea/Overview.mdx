<Title>Textarea — `rt-textarea`</Title>

Многострочное поле ввода. Как и однострочное, значение получает только через форму: своего
входа значения у него нет.

```html
<rt-field label="Комментарий" hint="Не короче трёх символов">
    <rt-textarea placeholder="Что произошло" [rows]="4" [formControl]="comment" />
</rt-field>

<rt-textarea resize="none" [rows]="2" [formControl]="note" />
```

## Когда применять

- Текст, в котором ожидаются переносы строк: комментарий, описание, причина отказа.
- Поле, у которого объём ввода заранее не известен, — высота задаётся `rows`, а дальше
  пользователь тянет за угол.

## Когда не применять

- **Одна строка** — [`rt-input`](./?path=/docs/components-input-overview--docs): многострочное
  поле под короткое значение обещает объём, которого не ждут.
- **Форматированный текст** — [`rt-rich-editor`](./?path=/docs/components-richeditor--docs).
- **Сообщение в переписке** — [`rt-message-composer`](./?path=/docs/components-messagecomposer--docs).

## Оси

Оси не перемножаются: размер, число строк и растягивание меняют одну и ту же высоту тремя
способами, и вместе показывают её же.

| ось           | значения                                      | умолчание  |
| ------------- | --------------------------------------------- | ---------- |
| размер        | `sm`, `md`, `lg` — минимальная высота коробки | `md`       |
| строки        | `rows` — 2, 3, 6                              | `3`        |
| растягивание  | `none`, `vertical`                            | `vertical` |
| наполненность | пусто, одна строка, несколько строк           | пусто      |
| рамка         | видна, снята (`bordered=false`)               | видна      |

**Ось, которой не видно.** `clearable` поле унаследовало от основы, но крестик не рисует:
в многострочном поле он нетипичен. Вход остаётся принятым и ни на что не влияет.

## Состояния

| состояние         | чем задаётся                         | что меняется                                     |
| ----------------- | ------------------------------------ | ------------------------------------------------ |
| обычное           | —                                    | рамка `--rt-input-color-border`                  |
| наведение         | —                                    | **ничего:** своего `:hover` у поля нет           |
| фокус с клавиши   | `:focus-visible` на `<textarea>`     | рамка фокуса и `--rt-input-focus-shadow`         |
| ошибка            | контрол `invalid` после касания      | рамка `--rt-input-color-border-error`            |
| отключено         | вход `disabled` или слово формы      | фон `--rt-input-color-bg-disabled`, прозрачность |
| `readonly` у поля | вход `readonly`                      | коробка остаётся, набор запрещён                 |
| только чтение     | `[readonly]` на вмещающем `rt-field` | коробка подменяется плоским текстом с переносами |

**Два разных «только чтение», и это не одно и то же.** Вход `readonly` оставляет поле полем:
рамка на месте, текст выделяется, набирать нельзя. `[readonly]` на
[`rt-field`](./?path=/docs/components-field-overview--docs) убирает поле совсем и печатает
значение обычным текстом. В матрице **States** показаны оба.

Фокус здесь — `:focus-visible` на самом `<textarea>`, а не `:focus-within` на коробке, как у
однострочного поля: рамку рисует сам контрол, коробка у него — простой блок.

## Доступность

- Подпись даёт вмещающий `rt-field` (авто-идентификатор и `<label for>`); без обёртки полю
  нужен `ariaLabel`.
- Ошибка объявляется атрибутом `aria-invalid` на `<textarea>`.
- Переносы строк в режиме чтения сохраняются (`white-space: pre-wrap`) — текст читается тем же
  абзацем, каким его набрали.

## Оформление

Своих свойств два — `--rt-textarea-min-height` (и `-sm` / `-lg`) и `--rt-textarea-line-height`;
всё остальное поле берёт из группы `--rt-input-*`, поэтому в форме стоит заодно с однострочным.
`font-family: inherit` задан явно: без него браузер ставит `<textarea>` моноширинный шрифт.

## Входы

| вход          | тип                    | умолчание    |
| ------------- | ---------------------- | ------------ |
| `placeholder` | `string`               | `''`         |
| `readonly`    | `boolean`              | `false`      |
| `rows`        | `number`               | `3`          |
| `resize`      | `'none' \| 'vertical'` | `'vertical'` |

## Входы от основы полей

Достались от `RtFormControlBase` — общей основы полей кита; в ней же они и меняются, сразу для
всех наследников.

| вход        | тип                    | умолчание | здесь                       |
| ----------- | ---------------------- | --------- | --------------------------- |
| `size`      | `'sm' \| 'md' \| 'lg'` | `'md'`    | минимальная высота          |
| `disabled`  | `boolean`              | `false`   | —                           |
| `controlId` | `string \| null`       | `null`    | —                           |
| `ariaLabel` | `string \| null`       | `null`    | —                           |
| `clearable` | `boolean`              | `true`    | принимается, но не рисуется |
| `bordered`  | `boolean`              | `true`    | —                           |

## Выходы

Своих выходов нет: значение уходит через `ControlValueAccessor`, то есть в связанный контрол
формы.

## Рядом

- [`rt-field`](./?path=/docs/components-field-overview--docs) — подпись, звёздочка, ошибка, режим чтения.
- [`rt-input`](./?path=/docs/components-input-overview--docs) — однострочный ввод.
