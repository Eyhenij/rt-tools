# `rt-table-sort-header`

Заголовок сортируемой колонки. Ставится атрибутом на ячейку шапки таблицы, а ключ колонки —
тот же, что в `cdkColumnDef` и в `[columnsConfig]`.

```html
<th *cdkHeaderCellDef cdk-header-cell rtSortHeader="checkIn">Заезд</th>
```

| вход           | тип      | умолчание    |
| -------------- | -------- | ------------ |
| `rtSortHeader` | `string` | обязательный |

## Главное, что нужно знать

**Сортируемость объявляет таблица, а не заголовок.** Колонка получает кнопку только когда
помечена `sortable` в `[columnsConfig]`; иначе заголовок остаётся обычной подписью, и лишнего
элемента управления в шапке не появляется.

**Направление читается с самой ячейки.** `aria-sort` стоит на `<th>`, а не на кнопке внутри:
скринридер объявляет порядок вместе с колонкой. Глазами то же самое показывает стрелка — обе
стрелки без сортировки, одна выбранная при ней.

**Порядок ходит по кругу из трёх состояний:** по возрастанию → по убыванию → без сортировки.
Третье нужно, чтобы вернуть исходный порядок, не перезагружая список.

**Подпись проецируется внутрь кнопки** и служит её доступным именем — отдельного `aria-label`
у кнопки нет и не должно быть.

## Края

- Блок BEM объявлен в шаблоне, а не только классом на хосте: `rtElem` внутри требует блока в
  своём инжекторе, и без него компонент не поднимался вовсе — потребитель получал `NG0201`.
- Сортировка по соседней колонке эту не помечает: `aria-sort` у неё остаётся `none`, а стрелка
  возвращается к нейтральной.

## Рядом

- [`rt-table`](../CONTEXT.md) — таблица, у которой заголовок спрашивает порядок и которой
  сообщает о нажатии.
