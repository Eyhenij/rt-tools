# `rt-table-filter-header`

Отбор в шапке столбца: вид сравнения слева, поле значения рядом, очистка — там, где есть что
очищать. Ставится в ячейку шапки, к тому же ключу колонки, что в `cdkColumnDef` и в
`[columnsConfig]`.

```html
<th *cdkHeaderCellDef cdk-header-cell>
    Название
    <rt-table-filter-header propertyName="title" [filter]="config.filter" [filters]="filters()" (filtersChange)="filters.set($event)" />
</th>
```

| вход           | тип                               | умолчание    |
| -------------- | --------------------------------- | ------------ |
| `propertyName` | `string`                          | обязательный |
| `filter`       | `IRtTable.ColumnFilter \| null`   | `null`       |
| `filters`      | `readonly IFilterModel<string>[]` | `[]`         |

Выход: `filtersChange`.

## Главное, что нужно знать

**Вид отбора объявляет колонка, а не угадывает значение.** `kind` решает, какую готовую часть
кита позвать: `text` — [`rt-input`](../../input/CONTEXT.md), `number` —
[`rt-input-number`](../../input-number/CONTEXT.md), `select` —
[`rt-select`](../../select/CONTEXT.md) по набору `options`, `date` —
[`rt-date-picker`](../../date-picker/CONTEXT.md). Своих полей ячейка не рисует ни одного.

**Колонка без `filter` не отбирает вовсе** и не рисует ничего: вход необязателен, и обещание
держит кит, а не каждый потребитель по-своему.

**Наружу уходит весь набор условий, а не одно изменившееся.** Потребитель спрашивает сервер
набором; получив одно условие, он держал бы вторую копию набора — две копии расходятся молча.

**Строк ячейка не отбирает.** Она сообщает, чего от списка хотят; список принадлежит тому, кто
его держит.

## Края

- Пустое значение снимает колонку с отбора и не едет наружу пустым условием.
- Повтор того же значения и смена вида сравнения без значения не сообщают ничего: прежний набор
  приходит обратно тем же объектом, и по этому признаку видно, что менять было нечего.
- Дата хранится строкой и сверяется строкой: `Date` не равен строке никогда, и без приведения
  повторный выбор той же даты каждый раз считался бы новым значением.
- Виды сравнения колонка сужает входом `operators` и называет начальный входом `startOperator`;
  молчит — разрешены все семь, начальный «Равно».
- Ширину ячейка берёт от шапки колонки: меряйся она содержимым, пустой список в ней схлопнулся
  бы до одной галочки.
