# `rt-table`

Таблица поверх CDK Table: колонки объявляются директивами CDK, а кит добавляет состояния,
карточки для узкого экрана, меню строки и настройку колонок.

```html
<table rt-table tableId="tours" ariaLabel="Туры" [dataSource]="rows()" [columns]="columns" [loading]="loading()" [columnsConfig]="config">
    <ng-container cdkColumnDef="title">
        <th *cdkHeaderCellDef cdk-header-cell>Название</th>
        <td *cdkCellDef="let row" cdk-cell>{{ row.title }}</td>
    </ng-container>
    <tr *cdkHeaderRowDef="columns" cdk-header-row></tr>
    <tr *cdkRowDef="let row; columns: columns" cdk-row></tr>
</table>
```

## Колонка действий строки

Колонка «…» объявлена в разметке самой таблицы, а не приходит от потребителя, и в реестр
`CdkTable` она вносится вручную в `ngOnInit` — тем же приёмом, каким это делает `CdkTextColumn`
самого CDK. Запрос к разметке взят статическим намеренно: сигнальный резолвится после первой
отрисовки строк, а колонка обязана попасть в реестр до неё. Ячейки колонки получают своё
объявление тем же вызовом: без ручного присвоения CDK падает на разборе шаблона ячейки.

## Строка отбора

Ряд отбора рисует сама таблица, по полю `filter` в `columnsConfig`, и только когда его просят
входом `showFilters`. Ячейку рисует [`rt-table-filter-header`](./filter-header/CONTEXT.md), набор
ячеек собирает `filterCellsOf` — по списку показанных колонок, а не по тем, у кого есть отбор:
колонка без отбора держит своё место пустой ячейкой, иначе ячейки съехали бы под соседние колонки.

Ряд стоит строкой таблицы под шапкой, а не частью ячейки шапки: шапку колонки объявляет
потребитель разметкой колонки, и вставить туда свою ячейку таблице некуда.

**В карточном виде ряда нет.** Карточный вид гасит строки таблицы поимённо, и строка отбора
скрыта тем же правилом: столбцов там не остаётся вовсе. Чем отбирать на узком показе — работа
своя, она стоит открытым вопросом в `docs/specs/ui-kit-v2/table-filter/`.

Набор условий таблица у себя не держит: он приходит входом `filters` и уходит выходом
`filtersChange` целиком, а строки сужает потребитель.

## Состояния показа

Что таблица рисует, решают вместе `[loading]`, `[fetching]` и число строк источника.

| Состояние                  | Что на экране                                                               |
| -------------------------- | --------------------------------------------------------------------------- |
| первая загрузка, строк нет | шапка и N строк-заглушек по `[columns]`                                     |
| догрузка, строки есть      | прежние строки на месте, поверх них закреплённое наложение с бегунком       |
| загрузки нет, строк нет    | пустое место: шаблон `#rtTableEmpty` или `rt-empty-state` по входам подписи |
| загрузки нет, строки есть  | обычный показ строк                                                         |

Наложение бегунка закреплено относительно ближайшего предка с прокруткой, поэтому бегунок виден
в середине окна, а не уезжает с таблицей. Строки-заглушки читают `[columns]` — тот же список имён,
что стоит в объявлении строки CDK: разбирать внутренности CDK ради их числа дороже, чем назвать
список входом.

| вход                                | тип                           | умолчание     |
| ----------------------------------- | ----------------------------- | ------------- |
| `columns`                           | `ReadonlyArray<string>`       | `[]`          |
| `columnsConfig`                     | `ReadonlyArray<ColumnConfig>` | `[]`          |
| `tableId`                           | `string \| null`              | `null`        |
| `density`                           | `'default' \| 'compact'`      | `'default'`   |
| `cards`                             | `boolean`                     | `true`        |
| `clickable`                         | `boolean`                     | `false`       |
| `loading` / `fetching`              | `boolean`                     | `false`       |
| `skeletonRows`                      | `number`                      | 5             |
| `emptyMessage` / `emptyDescription` | `string` / `string \| null`   | `''` / `null` |
| `emptyIcon`                         | `IRtIcon.Name \| null`        | `'inbox'`     |
| `showRowActions`                    | `boolean`                     | `false`       |
| `showFilters`                       | `boolean`                     | `false`       |
| `filters`                           | `ReadonlyArray<IFilterModel>` | `[]`          |
| `sort`                              | `ISortModel<string> \| null`  | `null`        |

Выходы: `sortChange`, `filtersChange`.

## Главное, что нужно знать

**`loading` и `fetching` — разные состояния.** Первая загрузка (`loading` при пустых данных)
подменяет строки заглушками; догрузка (`fetching`) оставляет уже показанное на месте — иначе
таблица мигала бы при каждой смене страницы.

**Карточки — это другая разметка, а не перестроенная стилями таблица.** Компонент сам решает по
ширине вьюпорта (`BreakpointsService.narrow`), что показать. Подписью в карточке служит **ключ
колонки**: заголовки живут в шаблонах ячеек CDK, куда карточка не дотягивается. Осмысленные
подписи даёт `columnsConfig`.

**Настройка колонок требует и `columnsConfig`, и `tableId`.** Выбор хранится в IndexedDB, и без
идентификатора таблицы его некуда положить — поэтому `canConfigure()` останется `false`.

## Края

- Пустой набор рисует заглушку с переведённым `uiNoData`; свой текст перебивает её.
- Колонка `rtRowActions` добавляется китом сама, когда включён `showRowActions`, и рисует
  [`rt-menu`](../menu/CONTEXT.md) в строке.
- Отбор колонки объявляется полем `filter` в `columnsConfig`, и ряд отбора таблица рисует сама —
  см. раздел выше. Колонка без `filter` не отбирает вовсе. Строк таблица не сужает.
- Спеки логики лежат рядом: сортировка и предикат действий строки проверены отдельно.
