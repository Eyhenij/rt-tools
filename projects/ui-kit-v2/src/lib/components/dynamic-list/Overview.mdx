<Title>DynamicList — `rt-dynamic-list`</Title>

Список записей со своей панелью инструментов: поиск, действия над разделом, выбор всех, пустое
место и страницы. Сами записи — таблица потребителя — проецируются внутрь.

```html
<rt-dynamic-list
    [pageModel]="page()"
    [showRefresh]="true"
    [showColumnSettings]="true"
    [showClearFilters]="true"
    [filtered]="hasFilters()"
    (searchChange)="onSearch($event)"
    (refreshed)="reload()"
    (pageChange)="onPage($event)">
    <ng-container *rtDynamicListSelectors>
        <rt-select [options]="stages()" />
    </ng-container>

    <rt-table [rows]="rows()" />
</rt-dynamic-list>
```

## Когда применять

- Раздел, где человек ищет запись среди многих: список заявок, стендов, людей.
- Экран, у которого над записями стоят те же шесть вещей, что и у соседнего: поиск, обновление,
  сброс отбора, настройка колонок, счётчик выбранного и страницы.

## Когда не применять

- **Список без панели над ним** — это `rt-table` сам по себе: обвязка здесь ничего не добавляет.
- **Список переписок** — это `rt-thread-list`: у него свой поиск и свой вид строки.
- **Страница целиком** — это `rt-container`: она раскладывает зоны экрана, а не один раздел.

## Оси

| ось                 | значения                                    | умолчание     |
| ------------------- | ------------------------------------------- | ------------- |
| заказанные действия | обновление, сброс отбора, настройка колонок | все выключены |
| поле поиска         | показано, скрыто                            | показано      |
| выбор записей       | включён, выключен                           | выключен      |
| причина пустоты     | раздел пуст, отбор ничего не нашёл          | —             |
| загрузка            | первая, подгрузка поверх нарисованного      | нет           |

**Высоту списка задаёт потребитель.** Список берёт сто процентов своего хоста; по записям он
вытянулся бы, и панель со страницами разъехались бы по экрану. В показах роль такого хоста играет
коробка ячейки.

## Края

| край                              | что происходит                                             |
| --------------------------------- | ---------------------------------------------------------- |
| действие не заказано              | кнопки нет в разметке вовсе, место она не занимает         |
| отбор не поставлен                | кнопка сброса стоит на месте и выключена                   |
| записей нет, отбора нет           | пустое место раздела, без предложения что-то сбросить      |
| записей нет, отбор стоит          | пустое место с дорогой назад — сбросом отбора              |
| записи влезли в одну страницу     | ряда номеров нет                                           |
| ни одной части панели не заказано | панели нет вовсе: пустая полоса забрала бы место у записей |

## Состояния

| состояние       | чем задаётся    | что меняется                                      |
| --------------- | --------------- | ------------------------------------------------- |
| первая загрузка | вход `loading`  | вместо всего содержимого стоит вертушка           |
| подгрузка       | вход `fetching` | записи остаются на месте, вертушка стоит над ними |
| набранный поиск | ввод человека   | семья говорит о смене, когда значение устоялось   |

Наведение и фокус матрицами не показаны: они живут на кнопках кита, и там же показаны. Ожидание
поиска в статичной ячейке не увидеть — это время, а не вид.

## Доступность

- У каждой кнопки панели есть подпись и подсказка, обе из словаря кита.
- Флажок «выбрать все» несёт подпись и промежуточное состояние, когда выбрана часть записей.
- Поле поиска — обычное поле кита: работает с клавиатуры, очищается крестиком.

## Оформление

Светлая и тёмная темы стоят рядом в истории **Themes**, оба набора оформления — в **Presets**.
Ниже порога кита в 1080 точек поле поиска перестаёт держать свою ширину и занимает всю строку.
Объявлено это медиазапросом, а не входом, поэтому показано отдельной историей **Narrow** с кадром
этой ширины.

Свои свойства блока: `--rt-dynamic-list-gap` — расстояние между панелью, записями и страницами,
`--rt-dynamic-list-search-width` — ширина поля поиска, `--rt-dynamic-list-veil-bg` — фон, сквозь
который видно записи при подгрузке.

## Рядом

- [`rt-table`](./?path=/docs/organisms-table-table-overview--docs) — сами записи; список стоит
  вокруг неё.
- [`rt-pagination`](./?path=/docs/molecules-navigation-pagination-overview--docs) — страницы;
  список зовёт её сам.

## Входы

| вход                 | тип                  | умолчание | что делает                                              |
| -------------------- | -------------------- | --------- | ------------------------------------------------------- |
| `pageModel`          | `IPageModel \| null` | `null`    | страница, по которой считается ряд номеров              |
| `loading`            | `boolean`            | `false`   | первая загрузка: вместо содержимого вертушка            |
| `fetching`           | `boolean`            | `false`   | подгрузка поверх нарисованного                          |
| `empty`              | `boolean`            | `false`   | записей нет                                             |
| `filtered`           | `boolean`            | `false`   | отбор поставлен                                         |
| `showSearch`         | `boolean`            | `true`    | показывать ли поле поиска                               |
| `showRefresh`        | `boolean`            | `false`   | показывать ли кнопку обновления                         |
| `showClearFilters`   | `boolean`            | `false`   | показывать ли кнопку сброса отбора                      |
| `showColumnSettings` | `boolean`            | `false`   | показывать ли кнопку настройки колонок                  |
| `selectable`         | `boolean`            | `false`   | показывать ли флажок «выбрать все» и счётчик выбранного |
| `allSelected`        | `boolean`            | `false`   | выбраны ли все записи                                   |
| `someSelected`       | `boolean`            | `false`   | выбрана ли часть записей                                |
| `selectAllDisabled`  | `boolean`            | `false`   | выключен ли флажок выбора всех                          |
| `selectedCount`      | `number`             | `0`       | сколько записей выбрано                                 |
| `emptyTitle`         | `string`             | `''`      | своя подпись пустого места вместо подписи кита          |
| `emptyDescription`   | `string \| null`     | `null`    | пояснение под подписью пустого места                    |

## Выходы

| выход                  | тип       | когда срабатывает                                |
| ---------------------- | --------- | ------------------------------------------------ |
| `searchChange`         | `string`  | набранное в поиске устоялось                     |
| `refreshed`            | `void`    | нажата кнопка обновления                         |
| `filtersCleared`       | `void`    | нажат сброс отбора — в панели или в пустом месте |
| `columnSettingsOpened` | `void`    | нажата кнопка настройки колонок                  |
| `pageChange`           | `number`  | выбрана другая страница                          |
| `perPageChange`        | `number`  | выбрано другое число записей на странице         |
| `allSelectedChange`    | `boolean` | переключён флажок «выбрать все»                  |

## Переход с первого кита

Семья заменяет пару первого кита — `rtui-dynamic-list` вместе с `rtui-table-container`. Во втором
ките это одна семья: контейнер наружу не выходил, его звал только сам список.

| в первом ките                               | во втором                                |
| ------------------------------------------- | ---------------------------------------- |
| `rtui-dynamic-list`                         | `rt-dynamic-list`                        |
| `rtui-table-container`                      | — часть той же семьи                     |
| `*rtuiDynamicListToolbarSelectorsDirective` | `*rtDynamicListSelectors`                |
| `*rtuiDynamicListToolbarActionsDirective`   | `*rtDynamicListActions`                  |
| `RtuiDynamicListComponent`                  | `RtDynamicListComponent`                 |
| `RtuiDynamicListToolbarSelectorsDirective`  | `RtDynamicListToolbarSelectorsDirective` |
| `RtuiDynamicListToolbarActionsDirective`    | `RtDynamicListToolbarActionsDirective`   |
| класс `rtui-dynamic-list`                   | `rt-dynamic-list`                        |
| класс `table-container__toolbar`            | `rt-dynamic-list__right`                 |

Сверх переименования приложению придётся сделать вот что.

- **Таблица проецируется, а не приходит входом.** В первом ките список брал записи, ключ, отбор и
  порядок своими входами и сам собирал таблицу внутри. Здесь таблицу ставит потребитель — своими
  колонками, ячейками и действиями строки, — а список стоит вокруг неё. Значит, входы `entities`,
  `keyExp`, `currentSortModel`, `filterModel` и выходы про строки переезжают на `rt-table`.
- **Действия панели заказываются по одному.** В первом ките кнопки обновления и настройки колонок
  показывались входами с умолчанием «показано»; здесь умолчание обратное. Экран, где они были,
  включает их прямо.
- **Пустых мест стало два.** Раздел без записей и отбор, ничего не нашедший, теперь говорят разное:
  из второго человеку дают дорогу назад. Приложению надо сказать семье, стоит ли отбор, — вход
  `filtered`.
- **Подписи приходят из словаря кита.** «Найти», «Обновить», «Сбросить отбор», «Настройка колонок»,
  «Выбрать все» и «Выбрано: N» даёт `provideRtKitLabels`; в первом ките они зашиты по-английски.
- **Настройка колонок не открывается сама.** В первом ките кнопка открывала боковую панель
  контейнера; здесь она только говорит о нажатии — панель открывает потребитель той, что есть в
  семье таблицы второго кита.
- **`@angular/material` этой семье больше не нужен вовсе.** Поле, кнопки, флажок, значки и
  подсказки — свои.
- **Прежние правила по классам `table-container__*` молча перестают действовать:** имена блока и
  элементов другие. Расстояния и ширину поиска переопределяют свойствами блока —
  `--rt-dynamic-list-gap`, `--rt-dynamic-list-search-width`, — а не правилом по классу элемента.
