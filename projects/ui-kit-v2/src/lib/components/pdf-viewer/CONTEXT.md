# `rt-pdf-viewer`

Полноэкранный просмотр документа PDF. Открывается через [`RtDialogService`](../dialog/CONTEXT.md)
из отдельного входа `@rt-tools/ui-kit-v2/pdf-viewer`.

```typescript
this.#dialog.open<RtPdfViewerComponent, IRtPdfViewer.Data, void>(RtPdfViewerComponent, {
    data: { source: bytes, fileName: 'Договор.pdf' },
});
```

Данные приходят токеном `RT_DIALOG_DATA`: `source` — байты (`Uint8Array`, `ArrayBuffer`) или
адрес, `fileName` — имя в полосе и имя скачанного файла.

## Главное, что нужно знать

**Рисует `pdfjs-dist`, и он необязателен.** Пакет стоит в `peerDependenciesMeta` как optional и
грузится динамическим `import()` только при открытии окна. Вход отдельный и корнем пакета не
переотдаётся: из корня сборщик разрешал бы `import('pdfjs-dist')` каждому приложению, даже тому,
кто просмотрщик не ставит.

**Воркер приложение кладёт себе само.** Адрес по умолчанию — `assets/pdfjs/pdf.worker.min.mjs`
от `<base href>`, другой задаётся `provideRtPdfViewer({ workerSrc })`. Файл копируется из того же
`node_modules`: версии воркера и рисовальщика обязаны совпадать, и чужой адрес разошёлся бы с ними
на первом же обновлении.

**Рисуются только видимые страницы и по одной соседней.** Места под все страницы ставятся сразу,
по размерам из документа, — прокрутка не прыгает. Холсты дальше трёх страниц от видимых очищаются.
Холст рисуется в точках экрана (`devicePixelRatio`), а не в CSS-пикселях.

**Масштаб «по ширине» — режим, а не число.** При смене ширины окна страница подстраивается заново.
Узкое окно (до 768 включительно) и страница, которая в 100% не влезает, открываются «по ширине»,
остальные — в 100%. Ступени — 50…300%; «по ширине» ими не зажат: на телефоне это около 45%, и
«−» там уже выключен.

**Печать — картинками, а не кадром с файлом.** Каждая страница рисуется в картинку 150 точек на
дюйм и встаёт в лист в конце `<body>`; на время печати корень страницы получает признак
`rt-pdf-viewer-printing`, и печатается только лист. Кадр `<iframe>` с самим файлом отвергнут:
у мобильных браузеров встроенного показа PDF нет, а часть настольных печатает из такого кадра
пустую или только первую страницу. Картинки печатает любой браузер. Лист убирается по
`afterprint` и при закрытии окна.

**Байты уходят рисовальщику копией.** Рисовальщик забирает буфер себе в поток, и без копии
скачать файл после открытия было бы нечем.

## Края

- Документ, который не открылся (битый файл, рисовальщик не загрузился, воркер не найден), даёт
  отказ по центру с кнопкой «Скачать»: файл всё равно у человека.
- Скачивание адреса без загруженного документа отдаёт ссылку как есть — чужой домен может не
  принять имя из `download`.
- Фокус после закрытия возвращается туда, где стоял при открытии: просмотрщик помнит его сам и
  не зависит от `restoreFocus` в настройке открытия.
- Номер видимой страницы — та, что занимает больше высоты окна; в конце прокрутки — последняя.
