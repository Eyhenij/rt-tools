<Title>PdfViewer — `rt-pdf-viewer`</Title>

Полноэкранный просмотр документа PDF: страницы столбцом на тёмном, полоса с именем файла,
печатью и скачиванием, снизу — номер страницы и масштаб. Открывается окном, поэтому затемнение,
`Esc` и блокировку прокрутки фона даёт сам диалог.

```typescript
import { IRtPdfViewer, RtPdfViewerComponent } from '@rt-tools/ui-kit-v2/pdf-viewer';

this.dialogService.open<RtPdfViewerComponent, IRtPdfViewer.Data, void>(RtPdfViewerComponent, {
    data: { source: bytes, fileName: 'Договор.pdf' },
});
```

## Подключение

Страницы рисует `pdfjs-dist`. Это необязательная зависимость кита: ставит её только тот, кто
открывает просмотрщик.

```bash
pnpm add pdfjs-dist
```

Рисовальщик работает в воркере, и файл воркера приложение кладёт себе при сборке. В `angular.json`
среди `assets` приложения:

```json
{ "glob": "pdf.worker.min.mjs", "input": "node_modules/pdfjs-dist/build", "output": "assets/pdfjs" }
```

Адрес по умолчанию — `assets/pdfjs/pdf.worker.min.mjs` от `<base href>`. Другое место или
каталоги данных пакета задаются провайдером:

```typescript
provideRtPdfViewer({
    workerSrc: 'static/pdf.worker.min.mjs',
    // необязательные — для документов со шрифтами без вложения, азиатскими картами и JPEG 2000
    standardFontDataUrl: 'assets/pdfjs/standard_fonts/',
    cMapUrl: 'assets/pdfjs/cmaps/',
    wasmUrl: 'assets/pdfjs/wasm/',
});
```

Файл берётся из того же `node_modules`, что и сам пакет: версии воркера и рисовальщика обязаны
совпадать, иначе документ не откроется и окно покажет отказ.

Вход `@rt-tools/ui-kit-v2/pdf-viewer` отдельный, корнем пакета не переотдаётся: приложение без
просмотрщика собирается без `pdfjs-dist`.

## Когда применять

- Документ нужно прочитать, не скачивая: договор, счёт, вложение переписки.

## Когда не применять

- **Файл, который только скачивают** — [`rt-download-link`](./?path=/docs/atoms-buttons-downloadlink-overview--docs).
- **Фотографии** — [`rt-photo-viewer`](./?path=/docs/organisms-photoviewer-overview--docs).

## Оси

| ось       | значения                                      | умолчание                             |
| --------- | --------------------------------------------- | ------------------------------------- |
| источник  | байты, адрес                                  | —                                     |
| состояние | загрузка, страницы, отказ                     | загрузка                              |
| масштаб   | «по ширине», 50, 75, 100, 125, 150, 200, 300% | «по ширине» на узком окне, иначе 100% |

**Ряда из ячеек у этого компонента нет.** Просмотрщик занимает весь показ — 100 vw на 100 dvh,
— и два экземпляра рядом наложились бы друг на друга. Поэтому каждое состояние показано своей
историей на весь кадр, а сравнивают их переключением между историями.

**Масштаб витриной не перебирается.** Он меняется кнопками плашки, а не данными открытия, и
каждая ступень — это та же раскладка с другим размером листа. История `Playground` открывает
документ в начальном масштабе своего кадра.

**Источник-адрес витриной не показан.** Документ витрины собран байтами на месте: запрос по сети
делает кадр снимка неповторимым.

## Края

| край                     | что происходит                                                          |
| ------------------------ | ----------------------------------------------------------------------- |
| длинное имя файла        | обрезается многоточием, целиком — в подсказке                           |
| документ не открылся     | по центру заголовок, пояснение и кнопка «Скачать»                       |
| верхняя и нижняя ступени | кнопки «+» и «−» выключены                                              |
| «по ширине» ниже 50%     | так бывает на телефоне; «−» выключен, «+» ведёт на 50%                  |
| узкое окно (до 480)      | отдельной кнопки «По ширине» на плашке нет, полоса сверху ниже — 56     |
| большой документ         | рисуются видимые страницы и по одной соседней, дальние холсты очищаются |

## Состояния

| состояние       | чем задаётся           | что меняется                                           |
| --------------- | ---------------------- | ------------------------------------------------------ |
| загрузка        | документ ещё не открыт | полоса с именем видна, по центру индикатор             |
| страницы        | документ открыт        | страницы столбцом, плашка с номером и масштабом        |
| отказ           | документ не открылся   | заголовок, пояснение и белая кнопка «Скачать»          |
| печать          | нажата «Печать»        | кнопка печати показывает загрузку, пока готовится лист |
| фокус с клавиши | `:focus-visible`       | кольцо на кнопке                                       |

## Доступность

- Объявляется `role="dialog"` с `aria-modal`, подписан именем файла; фокус заперт внутри до
  закрытия и после него возвращается туда, откуда окно открыли.
- У каждой кнопки есть переведённая подпись для скринридера; номер страницы читается целой
  фразой «Страница N из M».

## Оформление

Подложка тёмная в обеих темах: белый лист читают на тёмном. Цвета стоят свойствами блока
`--rt-pdf-viewer-*` — подложка, полоса, плашка, лист и его тень — и перекрываются правилом той же
цели. Светлая и тёмная темы стоят рядом в истории **Themes**.

## Рядом

- [`rt-dialog`](./?path=/docs/organisms-dialog-dialog-overview--docs) — окно, поверх которого он открывается.
- [`rt-photo-viewer`](./?path=/docs/organisms-photoviewer-overview--docs) — тот же приём для фотографий.

## Входы

Входов нет: документ и имя файла приходят данными открытия
(`RtDialogService.open(..., { data })`), а не привязкой в разметке.
