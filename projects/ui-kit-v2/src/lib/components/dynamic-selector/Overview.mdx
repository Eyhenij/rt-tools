<Title>DynamicSelector — `rt-dynamic-selector` и `rt-dynamic-input`</Title>

Поле формы со списком выбранных записей. Записи добавляются всплывающим выбором с поиском и
«Выбрать всё», убираются корзиной строки, перетаскиваются ручкой; сброс возвращает список,
записанный формой, очистка оставляет строки только для чтения. Рядом живёт поле списка строк
`rt-dynamic-input`: строки в нём набирают вручную, остальное у них общее.

Страница одна на семью: всплывающий выбор `rt-dynamic-selector-popup` и список выбранного
`rt-dynamic-selector-list` — части селектора и поля строк, в разметку их не ставят.

```html
<rt-dynamic-selector keyExp="id" displayExp="name" draggable [entities]="people()" [formControl]="team" />
<rt-dynamic-input editable [formControl]="emails" />
```

## Когда применять

- Список выбранного важен сам по себе: порядок, удаление по одной строке, возврат к исходному.
- Часть строк нельзя убирать, а остальные человек правит сам.
- Записей много, и выбирать их удобнее во всплывающем окне с поиском.

## Когда не применять

- **Нужно выбрать несколько значений компактно, в одну строку** —
  [`rt-multiselect`](./?path=/docs/molecules-forms-multiselect-overview--docs).
- **Значение одно, и список не нужен** — [`rt-select`](./?path=/docs/molecules-forms-select-overview--docs).

## Оси

| ось                       | значения            | умолчание |
| ------------------------- | ------------------- | --------- |
| режим выбора              | `multi`, `single`   | `multi`   |
| перетаскивание            | включено, выключено | выключено |
| строки только для чтения  | нет, часть строк    | нет       |
| приглашение               | есть, нет           | нет       |
| переключатель «несколько» | показан, скрыт      | скрыт     |
| поиск                     | местный, серверный  | местный   |
| корзина строк             | показана, скрыта    | показана  |
| сброс и очистка           | показаны, скрыты    | показаны  |
| правки в строках          | нет, есть           | нет       |
| начальный запрос          | пустой, задан       | пустой    |

**Оси, которых не видно в кадре.** Серверный поиск и догрузка меняют поведение, а не вид: они
показаны тестами. Всплывающий выбор живёт в оверлее, поэтому его вид показан отдельной историей
`Popup`, где окно стоит прямо в разметке.

## Состояния

| что               | чем задаётся                        | что видно                                                        |
| ----------------- | ----------------------------------- | ---------------------------------------------------------------- |
| список выбранного | значение формы                      | строки с корзиной, под ними «Add», сброс и очистка               |
| только для чтения | `readonlyKeys`                      | корзина строки выключена                                         |
| перетаскивание    | `draggable`                         | ручка в начале каждой строки                                     |
| скругление кнопок | `buttonRadius`                      | кнопки-иконки круглые, по шагу — с другим скруглением            |
| приглашение       | `invitation`                        | значок, описание и кнопка вместо полосы кнопок                   |
| нечего выбрать    | пустое значение и нечего предложить | значок предупреждения и «There are no available items to choose» |
| отключено         | `disabled` или форма                | кнопки, корзины, правка и перетаскивание выключены               |
| без корзины       | `removeShown = false`               | строки без корзины, убирает их только очистка                    |
| без сброса        | `listActionsShown = false`          | под списком одна «Add», сброса и очистки нет                     |
| правки в строках  | `extraChanged`                      | сброс и очистка включены при прежних ключах                      |
| окно с запросом   | `searchTerm`                        | текст уже в поиске, предложены только совпадения                 |
| окно, несколько   | `mode="multi"`                      | поиск, «Select all», флажки, «Cancel» и «Apply»                  |
| окно, одна запись | `mode="single"`                     | поиск, переключатели, «Cancel» и «Apply»                         |
| окно, загрузка    | `loading`                           | кольцо вместо строк, «Apply» выключено                           |
| окно, пусто       | поиск без совпадений                | значок поиска и «No results»                                     |

## Доступность

- Кнопки строк — [`rt-icon-button`](./?path=/docs/atoms-buttons-iconbutton-overview--docs) с
  доступными именами из словаря кита; подсказки на узком экране не показываются.
- Флажки и переключатели окна — `rt-checkbox` и `rt-radio-button` с ролями `checkbox` и `radio`.
- `Escape` закрывает окно и снимает отметки.
- Подпись поля даёт [`rt-field`](./?path=/docs/molecules-forms-field-overview--docs): поле
  строк кладут в него, как любое поле кита, и обёртка рисует подпись, звёздочку обязательности и
  ошибку. У поля строк `<label for>` ведёт к полю новой строки, пока оно открыто.

## Оформление

Строки — тонированные плашки `--rt-color-action-primary-subtle` со скруглением `--rt-radius-sm`,
как у первого кита. Окно выбора шириной 20rem и высотой не больше 30rem, поверхность
`--rt-color-bg-surface`, рамка `--rt-color-border-subtle`, тень `--rt-shadow-lg`. Свои свойства
блоков: `--rt-dynamic-selector-list-*` и `--rt-dynamic-selector-popup-*`.

«Добавить» — серая текстовая кнопка, как «Add» у первого кита. Очистка всего списка по умолчанию
нарисована крестиком, а не корзиной: корзина стоит у каждой строки, и два разных действия не должны
выглядеть одинаково. Корзину с крестом, как у первого кита, ставит вход `clearIcon="trash-x"`.

Свойства, которые приложение переставляет у окна и списка. Окно рисуется в оверлее, вне поля, и
его свойства доходят с любого предка — с панели оверлея, со своего контейнера, с корня страницы:
на самом окне стоят только умолчания с приставкой `-default`. Ширина, наибольшая высота, скругление,
толщина рамки и тень окна — `--rt-dynamic-selector-popup-width`, `-max-height`, `-radius`,
`-border-width`, `-shadow` — читаются так же. Цвет «Добавить», зазоры, отступы ручки и разделитель кнопок
списка тоже доходят с любого предка. Остальные свойства списка задаются правилом на `.rt-dynamic-selector-list`. При заданной `--rt-dynamic-selector-popup-min-height` тело
окна — список, загрузка или пустой результат — занимает всю оставшуюся высоту, и футер стоит у низа.

## Входы

Таблица одна на оба поля — колонка «чей» говорит, к какому из них вход относится. Входы только
поля строк стоят ниже своей таблицей.

Одиннадцать входов вида приложение задаёт один раз на всё приложение, через настройки кита:

```typescript
provideRtKit({
    components: {
        dynamicSelector: {
            invitationButtonIcon: 'ico-plus',
            invitationButtonAppearance: 'text',
            clearIcon: 'trash-x',
            searchAppearance: 'fill',
            searchRadius: 'full',
            emptyResultsText: 'Никого не нашли',
            titleWrap: false,
            highlightSearch: true,
            applyLabel: 'Submit',
            applyLabelCase: 'upper',
            autofocusSearch: true,
        },
    },
});
```

Оба поля берут из них `invitationButtonIcon`, `invitationButtonAppearance`, `clearIcon` и
`titleWrap`; поиск с подсветкой и фокусом, пустой результат и кнопка применения есть только у селектора. Вход, написанный в разметке, сильнее
настроек, а без настроек остаются умолчания из таблицы ниже.

### Двусторонняя привязка селектора

`[(chosenEntities)]` — выбранные записи, `TEntity[]`, по умолчанию `[]`: те же, что уходят выходом
`selectionChange`.

Вход задаёт выбранное и без формы. Непустой список с другими ключами становится и значением, и
списком, к которому возвращает «Сбросить». Список с теми же ключами в любом порядке — это родитель
вернул выбор после `selectionChange`, например в порядке каталога, — не меняет ни строк, ни «Сбросить». Строки рисуются и по записям из `chosenEntities`, которых нет в
`entities`.

`titleWrap="false"` ведёт название строки и подпись пункта окна одной строкой: длинное режется
многоточием, а подсказка показывает его целиком. По умолчанию названия переносятся.

`highlightSearch` выделяет в подписи пункта окна символы, совпавшие со словами поиска, цветом,
начертанием, фоном и скруглением фона из `--rt-dynamic-selector-popup-highlight-*`. Фон по
умолчанию прозрачный. Подпись читается целиком и при подписи одной строкой сохраняет многоточие.
По умолчанию ничего не выделено.

`displayWith` задаёт подпись записи функцией: ею подписаны строка списка и пункт окна, по ней же
ищет поиск. Так приложение делит слитное имя на слова или собирает подпись из двух полей. Без неё
подпись берётся из поля `displayExp`.

`applyLabel` заменяет подпись кнопки применения, а `applyLabelCase` задаёт её регистр: `none`
оставляет как есть, `title` ставит заглавную в начало каждого слова, `upper` пишет всё заглавными.
Регистр действует и на подпись кита.

`autofocusSearch` ставит фокус в поле поиска при открытии окна. По умолчанию фокус остаётся на
элементе, который окно открыл.

### Переключатели и состояние окна

`removeShown = false` убирает корзину строк: строки двигаются и правятся, но убирает их только
очистка. `listActionsShown = false` убирает сброс и очистку, кнопка добавления остаётся;
приглашение, как и прежде, встаёт на место всей полосы.

`extraChanged` говорит, что вызывающий правил строки в своём шаблоне: сброс и очистка включены и
при прежних ключах. Сброс тогда значение не трогает и сообщает `listReset`, очистка сообщает
`listCleared` — по ним вызывающий снимает свои правки.

`searchTerm` — запрос, с которым окно открывается каждый раз; выходом `searchChange` он не
уходит, вызывающий его и так знает. Открыто ли окно, говорит сигнал `popupOpen`, а каждую
перемену — выход `popupOpenChange`.

## Входы от основы полей

Достались от `RtFormControlBase` — общей основы полей кита; в ней же они и меняются, сразу для
всех наследников.

| вход        | тип                    | умолчание |
| ----------- | ---------------------- | --------- |
| `size`      | `'sm' \| 'md' \| 'lg'` | `'md'`    |
| `disabled`  | `boolean`              | `false`   |
| `controlId` | `string \| null`       | `null`    |
| `ariaLabel` | `string \| null`       | `null`    |
| `clearable` | `boolean`              | `true`    |
| `bordered`  | `boolean`              | `true`    |

`invitationGlyph` — имя Material вместо значка кита: уходит во вход `glyph` заглушки, как у
`rt-empty-state`, и рисуется только при пустом `invitationIcon`.

`size`, `clearable` и `bordered` семье не нужны: крестика очистки и рамки поля у неё нет.

## Выходы

| выход                   | чей      | тип         | когда                                            |
| ----------------------- | -------- | ----------- | ------------------------------------------------ |
| `selectionChange`       | селектор | `TEntity[]` | список изменился                                 |
| `listReset`             | оба      | `void`      | нажат сброс                                      |
| `listCleared`           | оба      | `void`      | нажата очистка                                   |
| `popupOpenChange`       | селектор | `boolean`   | окно выбора открылось или закрылось              |
| `searchChange`          | селектор | `string`    | 500 мс после последней клавиши серверного поиска |
| `loadMore`              | селектор | `void`      | конец списка окна показался при `lazyLoad`       |
| `temporaryChoiceChange` | селектор | `TEntity[]` | окно открылось и после каждого поиска            |
