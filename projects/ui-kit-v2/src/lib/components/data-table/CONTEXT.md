# `rt-data-table<ENTITY, SORT, KEY>`

Таблица записей первого кита во втором: шапка, строка отбора, готовые ячейки, колонка выбора и
полоса действий в конце строки. Она стоит рядом с [`rt-table`](../table/CONTEXT.md) и её не
заменяет: приложение выбирает, какую брать на экране. Material тут нет вовсе — всё, что первый
кит рисовал им, рисуют части кита.

```html
<rt-data-table
    rtDataTableSelectors
    [entities]="rows()"
    [currentSortModel]="sort()"
    [filterModel]="filters()"
    [isFiltersShown]="true"
    [isTableRowsClickable]="true"
    [isSelectorColumnShown]="true"
    (sortChange)="onSort($event)"
    (filterChange)="onFilter($event)"
    (rowClick)="onRow($event.row)">
    <ng-template rtDataTableRowActions let-row>
        <rt-menu-item label="Открыть" icon="ico-eye" (selected)="open(row)" />
    </ng-template>
</rt-data-table>
```

| вход                   | тип                  | умолчание      |
| ---------------------- | -------------------- | -------------- |
| `entities`             | `ENTITY[]`           | **обязателен** |
| `currentSortModel`     | `ISortModel \| null` | **обязателен** |
| `filterModel`          | `IFilterModel[]`     | `[]`           |
| `isFiltersShown`       | `boolean`            | `false`        |
| `isTableRowsClickable` | `boolean`            | `false`        |
| `keyExp`               | `keyof ENTITY`       | `'id'`         |

| выход            | тип                      |
| ---------------- | ------------------------ |
| `rowClick`       | `{ row: ENTITY, event }` |
| `rowDoubleClick` | `ENTITY`                 |
| `sortChange`     | `ISortModel`             |
| `filterChange`   | `IFilterModel[]`         |

## Главное, что нужно знать

**Своего порядка, своего отбора и своей страницы таблица не ведёт.** Она просит о них приложение
и рисует то, что придёт обратно: новый набор строк, новый порядок, новый набор условий. Поэтому
сама по себе таблица ничего не «применяет» — ответ всегда за приложением.

**Колонки приходят не входом, а от службы настроек** `RtDataTableConfigService`: порядок колонок,
их видимость и два признака полос прокрутки она читает из базы браузера под ключом приложения и в
той же форме, что писал первый кит. Службу приложение объявляет само — таблица её только читает.

**Отметки строк ведёт директива `rtDataTableSelectors`**, а таблица их рисует. Директива держит
сами записи, а не только ключи: запись, отмеченная на странице, которой на экране уже нет,
остаётся отмеченной и уходит приложению целиком. Без директивы колонки выбора нет вовсе.

**Строки различаются ключом записи** (`keyExp`, по умолчанию `id`): им идёт слежение в цикле, и
флажок строки принадлежит записи, а не месту в списке. Первый кит следил по месту, и при смене
страницы флажок доставался соседней записи.

**Нажатие на строку приходит по нажатию кнопки указателя, а не по отпусканию** — так двойное
нажатие приходит после двух одинарных. Нажатие в ячейке выбора и на кнопке меню строки до строки
не доходит: обе помечены признаком `rt-data-table-stop-row-click`. Тем же признаком приложение
отмечает свои части строки — прямо в разметке или директивой `rtDataTableStopRowClick`.

**Полоса действий висит над концом строки** и проявляется наведением; где наведения нет, она
видна всегда. Действия приложения стоят перед кнопкой меню строки, а место под полосу держит
пустая ячейка — её ширину таблица ставит сама по ширине полосы.

**Значки из описаний колонок рисует набор кита** по перечню соответствий имён первого кита. Своё
приложение отдаёт шаблоном `rtDataTableIcon` внутри таблицы: он получает имя значка, колонку и — в
ячейке — строку, и тогда перечень кита не спрашивается вовсе.

## Части семейства

| Часть                             | Что делает                                                          |
| --------------------------------- | ------------------------------------------------------------------- |
| `rt-data-table-cell`              | готовая ячейка: значение, прочерк у пустого, подсказка, копирование |
| `rt-data-table-header-cell`       | ячейка шапки: подпись, значок, стрелки порядка                      |
| `rt-data-table-filter-cell`       | ячейка строки отбора: поле, число, дата, список и вид сравнения     |
| `rtDataTableCustomCells`          | шаблоны ячеек приложения: колонка типа `custom` рисуется ими        |
| `rtDataTableRowActions`           | пункты меню строки                                                  |
| `rtDataTableAdditionalRowActions` | действия рядом с кнопкой меню                                       |
| `rtDataTableSelectors`            | отметки строк, флажок страницы, признаки колонки выбора             |
| `RtDataTableConfigService`        | настройки таблицы в базе браузера под ключом и в форме первого кита |

## Края

- Колонка типа `custom` без шаблона рисует пустую ячейку: готовую таблица в ней не берёт.
- Признаки `filtering`, `filteringMultiple`, `href`, `className` и `fixed` описание колонки
  принимает и ничего ими не меняет — так же, как в первом ките.
- Флажок страницы таблица сама не пересчитывает при смене строк: состояние остаётся тем, каким
  было на прежней странице. Пересчитать его просит список — `setExistingEntitiesState()`.
- Выбор по одной рисует радиокнопку, и флажка страницы в шапке нет.
- Отметки, названные заранее (`selectedEntitiesKeys`), ставятся один раз — к первым непустым
  строкам; позже присланный набор уже ничего не переписывает.
