# `rt-data-list<ENTITY, SORT, KEY>`

Список записей первого кита во втором: полоса действий сверху, [`rt-data-table`](../data-table/CONTEXT.md)
посередине, полоса страниц снизу. Список ничего не решает сам — он собирает семейство таблицы с
поиском, отбором, страницами и настройкой колонок и отдаёт приложению каждое нажатие. Material тут
нет вовсе: всё, что первый кит рисовал им, рисуют части кита.

```html
<rt-data-list
    rtDataListSelectors
    tableConfigStorageKey="orders"
    [entities]="rows()"
    [pageModel]="page()"
    [currentSortModel]="sort()"
    [filterModel]="filters()"
    [isFiltersShown]="true"
    [loading]="loading()"
    [fetching]="fetching()"
    (searchChange)="onSearch($event)"
    (pageModelChange)="onPage($event)"
    (sortChange)="onSort($event)"
    (filterChange)="onFilter($event)"
    (refresh)="reload()">
    <ng-template rtDataListRowActions let-row>
        <rt-menu-item label="Открыть" icon="ico-eye" (selected)="open(row)" />
    </ng-template>
</rt-data-list>
```

| вход                    | тип                  | умолчание      |
| ----------------------- | -------------------- | -------------- |
| `tableConfigStorageKey` | `string`             | **обязателен** |
| `entities`              | `ENTITY[]`           | **обязателен** |
| `pageModel`             | `IPageModel`         | **обязателен** |
| `currentSortModel`      | `ISortModel \| null` | **обязателен** |
| `filterModel`           | `IFilterModel[]`     | `[]`           |
| `searchTerm`            | `string \| null`     | `''`           |
| `keyExp`                | `keyof ENTITY`       | `'id'`         |
| `loading`               | `boolean`            | `false`        |
| `fetching`              | `boolean`            | `false`        |
| `isFiltersShown`        | `boolean`            | `false`        |
| `isTableRowsClickable`  | `boolean`            | `false`        |
| `isRefreshButtonShown`  | `boolean`            | `true`         |

| выход                | тип                      |
| -------------------- | ------------------------ |
| `searchChange`       | `string`                 |
| `pageModelChange`    | `Partial<IPageModel>`    |
| `sortChange`         | `ISortModel`             |
| `filterChange`       | `IFilterModel[]`         |
| `refresh`            | `void`                   |
| `clearFiltersAction` | `void`                   |
| `rowClick`           | `{ row: ENTITY, event }` |
| `rowDoubleClick`     | `ENTITY`                 |

## Главное, что нужно знать

**Своего состояния список не ведёт вовсе.** Страницу, порядок, условия отбора и набранное в поиске
он просит у приложения и рисует то, что придёт обратно. Поэтому список ничего не «применяет»: ответ
всегда за приложением, и оно же решает, ходить ли за ним на сервер.

**Службу настроек колонок объявляет приложение,** а не список: `RtDataTableConfigService` приложение
и создаёт, и наполняет колонками. Список её только читает и пишет в неё то, что человек сохранил в
боковой панели настройки. Так одна и та же настройка достаётся таблице, панели и приложению.

**Выбор записей ведёт директива `rtDataListSelectors`**, а рисуют его полоса действий и таблица.
Под «отметить все» отмечаются и те страницы, которые ещё не приходили: пришедшая страница отмечается
сама, снятая запись уходит в исключения и приходит неотмеченной каждый раз. Приложение читает и
отмеченные записи, и исключения — действие над всеми записями оно отправляет как «все, кроме этих».
Разведённый вид выключается входом `isMultiSelectExtendedMod`.

**Две загрузки выглядят по-разному.** Первая (`loading`) заменяет список крутилкой: показывать
нечего. Дозагрузка (`fetching`) оставляет строки на месте и кладёт крутилку поверх них с подложкой —
человек видит, что список тот же, а не новый.

**Заглушку показывают только без строк и без условий отбора.** Пустой ответ на заданное условие —
это не пустой список, и тогда видны таблица со строкой отбора и «снять отбор» в полосе действий.

**Панель настройки колонок поднимает служба боковых панелей кита.** Второе нажатие при открытой
панели ничего не открывает: у первого кита настройку сохраняла та панель, что закрылась последней.

## Части семейства

| Часть                            | Что делает                                                   |
| -------------------------------- | ------------------------------------------------------------ |
| `rt-data-list-toolbar`           | поиск, «отметить все» или счётчик, снятие отбора, обновление |
| `rt-data-list-settings-aside`    | боковая панель настройки колонок и полос прокрутки           |
| `rtDataListSelectors`            | отметки по страницам, исключения, счётчик отмеченных         |
| `rtDataListToolbarSelectors`     | селекторы приложения слева в полосе действий                 |
| `rtDataListToolbarActions`       | действия приложения справа в полосе действий                 |
| `rtDataListCustomCells`          | шаблоны ячеек приложения: они уезжают в таблицу              |
| `rtDataListRowActions`           | пункты меню строки                                           |
| `rtDataListAdditionalRowActions` | действия рядом с кнопкой меню строки                         |

## Края

- Вход `isPaginationShown="false"` убирает полосу страниц из разметки; включённая полоса рисуется
  по своим правилам. В первом ките вход ничего не менял.
- Полоса страниц исчезает сама, пока все записи помещаются на самую маленькую страницу.
- Флажок страницы после смены строк остаётся тем, каким был на прежней странице: его пересчитывает
  директива выбора, когда страница приходит.
- Выбор полос прокрутки общий на всю страницу: список ставит их размер на корень страницы, и
  сохранённый одним списком выбор достаётся каждому списку рядом — так было в первом ките. Уходя,
  список снимает эти свойства с корня.
- Исключения не уходят вместе с отметками: `clearSelectedList()` снимает отметки, а исключения
  очищает отдельная просьба `clearExcludedList()`. «Отметить все», поставленное заново, начинает
  без исключений прошлого раза.
- Поле поиска следует за входом `searchTerm`, и непустой поиск приложения держит поле видимым и на
  заглушке. Значение, равное последнему отправленному, поле не трогает: запоздалое эхо ответа
  сервера или адресной строки не стирает дописанное человеком.
- Список и таблица читают базу браузера через `IDBStorageService` из `@rt-tools/core`. Без
  `provideRtIDBStorage()` в провайдерах приложения страница пустая, а в консоли стоит
  `NG0201: No provider found for _IDBStorageService`.
- Шаблон значка `rtDataTableIcon` ставится прямо внутри списка и уезжает в таблицу без обёртки.
- Отступы вокруг тулбара и под содержимым — имена `--rt-list-toolbar-padding-top`,
  `--rt-list-toolbar-padding-bottom`, `--rt-list-toolbar-gap` и `--rt-list-content-padding-bottom`.
  Под материальным набором тулбар стоит в 16px от верха и в 16px от таблицы, как в первом ките;
  нижний отступ содержимого там 0, и приложение ставит его этим именем. Отступ стоит внутри
  прокрутки таблицы: таблица сама прокручивается, и отступ уходит вниз вместе со строками.
- Место под заглушку пустого списка и под крутилку — имена `--rt-list-placeholder-min-height` и
  `--rt-list-placeholder-grow`: в компактной секции приложение ставит `0`, и заглушка не тянется на
  всю высоту.
