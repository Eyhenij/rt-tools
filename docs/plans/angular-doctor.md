# Дерево проходит проверку Angular Doctor без находок

**Эпик:** RT-3476 · **Ветка эпика:** `RT-3476-angular-doctor`

## Что даёт

Angular Doctor (пакет npm abiramcodes/angular-doctor, сайт ngdoctor.dev) проверяет Angular-код
дерева на устаревшие API, ошибки шаблонов, безопасность, доступность и порядок в файлах. После
эпика дерево проходит его без находок, а шаг в `check:all` не даёт появиться новым. Сегодня
оценка 31 из 100, и проверку никто не запускает.

Слово владельца: «изучи https://ngdoctor.dev/, … заведи эпик по исправлению всех замечаний, бери в
работу». Решения 21.11.2026: находки, которые спорят с соглашениями дерева, — «Подогнать код»;
info-миграции — «Все четыре»; проверка — «Да, в check:all».

## Точки

- **A:** скан 21.11.2026, версия 0.3.0, локальная копия main на eeebbb935 — оценка 31 из 100,
  75 ошибок, 1182 предупреждения, 200 info. Проверки в дереве нет.
- **B (RT-3477):** `pnpm run check:ngdoctor` стоит в `check:all`, в конвейере и в наборе перед
  push. Порог — оценка 32.5 вместе с числом находок каждого из 29 правил: одна оценка не видит
  второго предупреждения того же правила и info, а общие суммы — подмены одной находки другой.
  Признак: шаг зелёный при результате, равном порогу, и красный при любом другом, а также когда
  инструмент что-то пропустил или замолчал целый источник находок.
- **C (RT-3478…RT-3483):** ни одной ошибки и предупреждения вне имён файлов и тестов. Признак:
  вывод `--json` не называет правил этих задач, кроме одной `security-bypass` превью cms — оговорка
  в G.
- **D (RT-3484…RT-3487):** ни одной info-находки. Признак: то же.
- **G (веха эпика):** ни одной находки, кроме одной `security-bypass` превью встроенной ссылки
  редактора cms; порог `check:ngdoctor` — это правило со значением 1 и оценка, которую инструмент
  даёт при нём. Признак: `pnpm run check:ngdoctor` на ветке эпика. Оговорка владельца от 22.11.2026
  (RT-3478), ответ «Оставить обход за проверкой»: превью доверяет Angular только разобранный
  https-адрес с хостом.
- **Риск G, найденный на RT-3478:** `pnpm run graph:build` оставляет в каждой `graphify-out/`
  игнорируемый git файл graph.html, а `check:ngdoctor` читает его: на копии, где графы собраны,
  шаг красный (104 находки `inner-html`). Пока сборка графов их оставляет, перед проверкой их
  удаляют; сама правка сборки — задача своя.
- **Риск G, найденный на RT-3508:** главная не мерит себя Angular Doctor, и каждое её слияние в
  эпик поднимает порог правил, которые снимают задачи эпика. Как держать главную вровень с эпиком —
  выпустить проверку RT-3477 в главную раньше эпика или вливать главную перед каждой задачей, —
  решает владелец.
- **Риск G, найденный на RT-3480:** проверка в облаке мерит `check:ngdoctor` только у PR в главную;
  у PR задачи в ветку эпика порог держит один набор перед отправкой.

## Как стоят ветки

Ветка эпика отведена от главной, ветки задач — стопкой: каждая следующая отводится от
предыдущей, база её PR — предыдущая ветка. Каждая задача записывает порог `check:ngdoctor`
командой `node tools/check-ngdoctor.mjs --write` на результате, который она дала.

## Чего эпик не делает

- Выпуск кита. Правки кита попадают к потребителю выпуском, а выпуск — отдельное решение владельца.
  Задача, которая меняет вход, видимый потребителю, называет это в своём PR. RT-3480 меняет
  конструкторы директив БЭМ core: журнал выпуска коммиты `refactor` не берёт, и выпуск core ставит
  строку о ломающей правке сам.
- Правила Angular Doctor не выключаются в настройке: так решил владелец. Если правило нельзя
  выполнить — например, имена сгенерированных файлов prisma задаёт генератор, — задача приносит
  это владельцу меню, а не выключает правило сама. Сканер не читает `.gitignore` и видит 26 файлов
  клиента prisma; проверка считает и их, как решил владелец. Задача, которая добавляет модель в
  схему хранилища, добавляет и находку file-hyphen-case и записывает порог. Правило
  project-layout: четыре его находки требуют `src/main.ts` у корня, у двух наборов end-to-end и
  у правил линтера. Оба вопроса RT-3488 приносит владельцу.
