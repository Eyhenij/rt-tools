# Один вход во все админки: модуль входа на Keycloak

**Эпик:** RT-2528 · **Ветка эпика:** `RT-2528-auth-module`

## Что даёт

Сегодня каждое приложение пишет вход само: свои пароли, свои сессии, свои права, свой экран.
Владелец 5 октября 2026 года: «нужно вынести логин в отдельный модуль который можно подключать в
приложения» и «нам нужно писать много различных админом с разными правами, видимо нужно
реализовать что-то похожее на keyclock». После эпика новая админка подключает готовые пакеты и
получает вход, восстановление пароля, приглашения, вход через Google и Apple и права по ролям — без
своего кода входа. Экраны входа выглядят как сами админки: они собраны из компонентов второго кита.

## Решения владельца

- **Keycloak + Keycloakify.** Один общий Keycloak на все приложения, со своим Postgres.
- **Модуль из трёх частей:** интерфейс, сервер и общий контракт.
- **Права живут в Keycloak** — ролями клиента `resource:action`, по клиенту на админку.
- **Организации остаются в базах приложений.** Модуль даёт только точку подключения «текущая
  организация».
- **Сценарии первой версии:** почта и пароль, смена и восстановление пароля, приглашения и
  подтверждение почты, вход через Google и Apple.
- **Перенос существующих приложений — после модуля, в их собственных репозиториях, с хэшами
  паролей.** Эпик даёт для этого инструмент, но сами приложения не трогает.

## Пакеты

## Как стоят ветки

Ветка эпика отведена от главной. Ветки задач — каждая от ветки эпика, их PR идут в неё. Задача,
которая опирается на другую, отводится после слияния той: клиент и сервер берут контракт уже
влитым, сквозные проверки — все пакеты и стенд.

## Решения по ходу

- **Своих расширений Keycloak на Java нет.** Всё сверх стандартного делается темой, настройкой
  области или на стороне приложения.
- **Хэши паролей.** Keycloak принимает argon2 и pbkdf2 без расширений. Пароли приложения Б (argon2)
  переносятся как есть. Для scrypt приложения А нужен отдельный путь — его выбирает задача RT-2535.

- **Стенд: Keycloak 26.5.5 и keycloak-config-cli 6.5.1-26.5.5 (RT-2529).** Для более нового
  Keycloak сборки config-cli пока нет.
- **Область накладывается из файла при каждом подъёме, без кэша (RT-2529).** С кэшем файл с
  прежней контрольной суммой пропускается, и правка в консоли переживает подъём.
- **Команда подъёма ждёт, пока загрузчик области выйдет с кодом 0 (RT-2529).** Иначе первая
  проверка после подъёма падает не по своей причине.
- **Проверка стенда пока не стоит в наборе перед отправкой (RT-2529).** Ей нужен поднятый стенд.
  В набор и в CI она входит задачей RT-2534.

- **RT-2533 стоит стопкой на RT-2529.** Контракт — поддомен домена, который заводит RT-2529, а
  проверка описаний не принимает поддомен без домена. PR RT-2533 идёт в ветку RT-2529.
- **Таблица функций контракта лежит в README пакета (RT-2533).** Раздел «Contract» описания
  сверяется с серверными процедурами, а их у пакета нет.
- **Четыре правила контракта пока «не проверяются машиной» (RT-2533).** Проверка привязок не видит
  функций, которые баррель подключает через `.js`. Чинит задача RT-2537.

## Чего эпик не делает

- Не переводит существующие приложения на модуль: это работа в их репозиториях.
- Не переносит организации в Keycloak.
- Не поднимает Keycloak в боевой среде приложений: стенд эпика — локальный и для проверок.
