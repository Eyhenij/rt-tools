# Разбор правил по закрытию RT-3682 — ждёт слова владельца

Ответ роли `skill-curator` от 2026-11-27, пересказан по пунктам. Ничего из этого не внесено. Разбор имён шагов
подтверждён по коду исполнителем, остальные пункты он не перепроверял.

## Предложения

1. **Движок задачи читает имя шага только по первой строке** (ресурс пакета `pitfalls/task-flow-plan.md`). Ход работы с
   полными именами не совпадает, и состояние остаётся невыполненным без причины. Записать это в подводные камни.
   Отдельная задача пакету: отказывать при записи плана, если имя шага перенесено, и печатать причину.
2. **Проверка шага не складывает строки таблицы** (тот же ресурс). Доля и заполненность проходят, когда одна часть
   записана дважды. Проверка таблицы, которая делит общий итог, складывает части каждой строки и сверяет с итогом.
3. **Факт в вопросе владельцу не измерен** (ресурс пакета `rules/task-flow-owner.md`). Число о части ничего не говорит о
   целом. Факт в вопросе измеряется на том предмете, который он называет, или называется догадкой.
4. **Набор перед отправкой рядом со вторым кругом на одних текстах** (`.claude/skills/task-delivery-loop/SKILL.md` и
   его образец). Набор останавливался дважды. Для изменения из одних текстов набор ждёт круга, описание PR пишется до
   него. Основание — одна задача.
5. **Заведение задач эпика кладёт папки чужих веток в текущую копию** (ресурс пакета `patterns/epic-flow-declare.md`).
   Записать в частые промахи: сразу после заведения лишние папки убираются из дерева. Отдельная задача пакету: без
   черновика команда папку не создаёт.
