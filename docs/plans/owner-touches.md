# Задача доходит до слияния с минимумом обращений к владельцу

**Эпик:** RT-3693 · **Ветка эпика:** `RT-3693-owner-touches`

## Что даёт

Владелец решает только то, что без него решить нельзя. Задача доходит до слияния с наименьшим
числом обращений к нему и не стоит, пока он не ответил.

Слова владельца 26.11.2026: «Мне нужно, чтобы ты ускорил рабочий процесс… Свести несколько
подтверждений в одно со стороны человека, либо еще как-то другими способами ускорить процесс
разработки и уменьшить количество обращений к человеку… Оно должно свестись к минимуму. Это цель
эпика, и бери этот эпик в работу, в это дерево».

## Точки

- **A:** число обращений к владельцу на задачу не измерено. Измерение — первая задача эпика.
- **B (RT-3695):** обращения к владельцу посчитаны по журналам, предложение по их сокращению лежит в
  этом плане. Признак: таблица измерения и список предложений с ценой каждого, решение владельца по
  ним.
- **G (веха эпика):** обращений к владельцу на задачу меньше. Признак: то же измерение до и после
  эпика; целевое число ставит решение владельца по предложению.

## Измерение до начала

Обращение к владельцу — его ответ в окне вопроса, сообщение между ходами или сообщение во время хода.
Источник — наблюдения дерева `.claude/rt-kit/observations`, события `record-menu` и `record-word`, с
21.11, когда они появились, до 26.11 11:00 UTC — до начала этого эпика. Окна разрешений от хуков
(`guard-ask`) задачи не несут и идут отдельной строкой.

```bash
cat .claude/rt-kit/observations/*.jsonl | jq -rs --arg u 2026-11-26T11:00 '[.[]|select(.t < $u)
  |select(.ev=="record-menu" or .ev=="record-word")|select(.task!=null and (.task|startswith("RT-")))]
  | group_by(.task) | map(length) | sort | {tasks:length, total:add, median:.[(length/2|floor)]}' -c
# → {"tasks":36,"total":277,"median":5}
```

| Вид обращения                          | Число  | Доля |
| -------------------------------------- | ------ | ---- |
| Ответ в окне вопроса                   | 93     | 34%  |
| Сообщение между ходами                 | 103    | 37%  |
| Сообщение во время хода                | 81     | 29%  |
| Всего на 36 задачах, медиана на задачу | 277, 5 | —    |
| Окна разрешений от хуков, за весь срок | 44     | —    |

- По задачам: медиана 5, среднее 6,9, больше всего 40 — у RT-3526 34 сообщения пришли во время хода.
- Окно с пометкой «Recommended» владелец выбрал в 5 из 8 вопросов, где она была; выборка из уцелевших
  журналов мала.
- Треть вызовов окна, 45 из 140, хуки остановили до владельца: это время исполнителя, а не обращения.
- Перечень мест, где правила и хуки требуют слова владельца, — 22 места. На задачу их выходит 3–4:
  слово на начало, разбор, одобрение плана и слияние. Задача кита добавляет до 4: макет, витрина,
  окно на PR кита, показ экрана.
- Пример лишнего окна 26.11: выпуск agent-kit 0.41.0 упал на защите main, которую сессия этого дерева
  сама поменяла в 11:03. Окно подало правку как чужую, и первым вариантом в нём стояло «Я сам поправлю
  правило»: шаг исполнителя уходил владельцу.

## Предложения, которые решает владелец

Цена каждого — что теряется. Ожидание: при П1–П5, П7 и П8 обращений на задачу 1–2 вместо 5 — просьба,
одно окно на эпик и слияние эпика.

- **П1. План задачи без окна.** Планы задач эпика одобряет движок по слову владельца на эпик; окно
  остаётся, только если план меняет закон, публичный API, вид или безопасность. Минус 1 обращение на
  задачу. Цена: план задачи до кода читают только роли.
- **П2. Разбор без вопросов.** Шесть вопросов разбора закрываются допущениями, список приходит одной
  строкой; вопрос задаётся только о выборе в продукте. Минус 0–6 на задачу. Цена: неверное допущение
  стоит правки.
- **П3. Слияние в ветку эпика — дело исполнителя.** PR задач в ветку эпика сливает исполнитель после
  зелёных проверок и ревью; эпик в main сливает владелец. Закон `delivery` уже принимает такое слово,
  названное заранее. Минус 1 на задачу и около 30 минут ожидания. Цена: задачи внутри эпика читают
  только роли.
- **П4. Одно окно на эпик.** Назначение копии, план и состав эпика, допущения разбора — одним окном
  вместо 3–4.
- **П5. Без повторных окон.** Убрать окна, которые повторяют уже полученный ответ: разрешение на PR
  кита после одобрения макета, окно хука конца эпика, окно на замену проверки шага. Окно, где вариант
  по умолчанию отдаёт шаг исполнителя владельцу, судья вопросов держит. Около 44 окон за срок
  наблюдений. Цена: защиту держит запись первого ответа.
- **П6. Витрина кита без второго показа — снято.** Судья вопросов не пустил его в меню: он снимал
  проверку владельца при смене вида кита.
- **П7. Сжатие вместо перезапуска.** На 50% окна сессия сжимает контекст и идёт дальше без перезапуска
  владельцем. Минус 1 на длинную задачу. Цена: часть контекста теряется сжатием.
- **П8. Команда измерения.** Команда дерева считает обращения на задачу для вехи и размечает набранные
  сообщения по видам — поправка, «где стоим», новый приказ, — чтобы закрыть частые. Сама обращений не
  снимает.

## Решение владельца

Слова владельца 26.11 в одном окне: «Одобряю план RT-3695 (Recommended)»; из П1–П4 выбраны все четыре,
из П5, П7, П8 — все три. Варианты были те же семь, каждый с пометкой «Recommended»; П6 в меню не попал.

## Как стоят ветки

Ветка эпика отведена от главной. Ветки задач идут цепочкой в порядке состава: задачи 3–8 правят одни и
те же правила хода работы, судью вопросов и хуки. PR первой задачи идёт в ветку эпика, каждой следующей —
в предыдущую ветку; сливаются снизу вверх. Команда измерения идёт первой: веха меряется ею до и после.
