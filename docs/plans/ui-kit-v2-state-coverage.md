# Покрытие состояний `@rt-tools/ui-kit-v2`: витрина и документация

## Контекст

Витрина второго кита показывает 80 файлов историй, и в 79 из них ровно один экспорт `Default`.
Docs-страниц у компонентов нет вовсе. Чтобы увидеть `outlined` + `warning` + `disabled`, надо
открыть `Button` и выставить три контрола руками — расхождение, видное только при таком
сочетании, не видит ни автор правки, ни ревьюер.

Задача: довести витрину до состояния, где все состояния каждого компонента видны сразу, и
записать это требованием, а не устной договорённостью.

Замеры на 2026-08-06: 94 компонента и директивы в 71 папке; 14 компонентов без историй
(`UI-KIT-V2-ISSUES.md` §2.1); 10 историй рисуют пустой массив (§2.3); 11 папок, где спек меньше,
чем компонентов; 81 спека; 72 покомпонентных `CONTEXT.md` плюс индекс.

Требования записаны и лежат рядом — этот план только исполняет их:
`docs/adr/0002-ui-kit-v2-state-coverage.md` (решения и их цена),
`.claude/rt-kit/overrides/laws/verifiability.md` (раздел «Демонстрация видимого состояния»),
разделы про `ui-kit-v2` в `.claude/skills/rt-tools-storybook/SKILL.md` и
`.claude/skills/rt-tools-testing/SKILL.md`.

## Что считается сделанным

Компонент покрыт, когда **каждая ось входов показана всеми значениями**, а не когда существует
контрол, которым до значения можно доехать. Перемножаются только оси, которые видно влияют друг
на друга (`theme × appearance` — да, `size × theme` — нет). Полный декартов продукт отвергнут:
у `Button` это 1296 ячеек.

## Волна 0 — расчистка

Идёт целиком до первой покомпонентной правки: без неё объём умножит существующие дефекты.

1. **`pnpm run agent-kit:sync`.** Сейчас `agent-kit:check` падает — все шесть законов отстали от
   пакета. Надстройка `verifiability.md` должна слиться со свежей основой, иначе она приклеится
   к устаревшему тексту. После — `agent-kit:check` обязан быть зелёным.

2. **`projects/ui-kit-v2/tsconfig.lib.json`** — в `exclude` дописать `**/stories/**` и
   `src/showcase/**`. Сейчас исключён только `**/*.stories.ts`, и обёртки не уезжают в пакет лишь
   потому, что до них не дотягивается граф от `public-api.ts` (`UI-KIT-V2-ISSUES.md` §2.7).

3. **`eslint.config.cjs`**, блок кастомных правил `rt` (около строки 283, сейчас
   `files: ['**/*.ts'], ignores: ['**/*.spec.ts', '**/*.spec.js']`) — дописать `'**/stories/**'`
   и `'**/showcase/**'` в `ignores`. Снимает 80 предупреждений `rt/require-host-bem-block` на
   демонстрационных обёртках (§2.6), в которых утонет 81-е настоящее.

4. **`.claude/hooks/skill-gate.sh`** — добавить маску `*.mdx` → `rt-tools-storybook` рядом с
   `*.stories.ts`. Иначе 72 новые страницы правятся без выдачи правила витрины.

5. **`projects/ui-kit-v2/.storybook/main.ts`** — в `stories` дописать `'../src/**/*.mdx'`.
   Страница-обзор должна лежать рядом с компонентом, как лежит `CONTEXT.md`; сейчас MDX
   подхватывается только из `../docs/**`.

6. **Аддон состояний.** `storybook-addon-pseudo-states@10.5.6` в `devDependencies`, `storybook`
   поднять с `^10.5.5` до `^10.5.6` (требование peer), зарегистрировать в `addons` в `main.ts`.
   Без него `hover`, `focus-visible` и `active` не увидеть глазами никогда — а они стилизованы
   в 27 SCSS-файлах из 86.

7. **Обвязка сеток — `projects/ui-kit-v2/src/showcase/`.** Один переиспользуемый компонент
   сетки с подписанными осями плюс компонент ряда. Лежит рядом с `src/testing/`, исключён из
   сборки библиотеки тем же пунктом 2, но линтуется как обычный исходник — в отличие от
   `.storybook/`, который ESLint игнорирует целиком.
   Тёмная колонка возможна потому, что тёмная тема объявлена миксином `rt-theme-dark-tokens`
   в `src/styles/_theme-dark.scss` и накладывается на любой селектор. Оговорка: `body`-градиент
   и инверсия `.rt-logo` остаются `:root`-скоупом и в скоупнутый блок не переедут.

8. **`CONTEXT.md` в пакет.** В `projects/ui-kit-v2/ng-package.json` в `assets` дописать
   `"src/**/CONTEXT.md"` (проверено: доезжают все 73, взаимные ссылки вида
   `../icon-button/CONTEXT.md` внутри пакета разрешаются). Вместе с этим — убрать из 72 файлов
   последнюю строку `Проверки: [...spec.ts](./...spec.ts)`: спеки в пакет не едут, и ссылка
   там висячая. Спека лежит в одной папке с `CONTEXT.md` — тот, кто правит код, найдёт её без
   ссылки.

9. **Страж ручных таблиц — `tools/verify-ui-kit-v2-docs.cjs`.** Таблицы входов на
   Overview-страницах пишутся руками, значит появляется 72 копии того, что уже записано в коде
   и в `CONTEXT.md`. Скрипт сверяет имена входов в MDX-таблице с `input()` в исходнике
   компонента и падает на расхождении. Подключается nx-целью `verify` по образцу
   `projects/utils/project.json:48` (`nx:run-commands` → `node tools/verify-…`), добавляется
   в `check:all` и `check:affected`.
   Без этого пункта решение «писать таблицы руками» нарушает закон
   `docs/constitution/project-documentation.md` в 72 местах молча.

**Проверка волны 0:** `pnpm run check:all` зелёный; `pnpm run agent-kit:check` зелёный;

`test-*.component.js`; витрина стартует на 6007 и показывает демо-сетку на `Button`.

## Волны 1–5 — по типам компонентов

Порядок: атомы (~15) → форменные (~12) → оверлеи (13) → составные (~20) → остаток и 14 без
историй. Внутри волны первым идёт компонент с самой богатой матрицей — на нём обвязка либо
выдержит, либо сломается дёшево. В волне атомов это `Button` (9 входов, 6 тем × 3 appearance).

### Повторяемый приём на компонент

Показан на `button`; для остальных те же файлы с другими именами.

| Файл                                                       | Что в нём                                                                                                                                                       |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `button/CONTEXT.md`                                        | без изменений, кроме снятой строки «Проверки» (волна 0)                                                                                                         |
| `button/Overview.mdx`                                      | новый: назначение, когда применять и когда нет, таблицы осей, таблица состояний, доступность, оформление, связанные компоненты, таблица входов и выходов руками |
| `button/stories/button.stories.ts`                         | `Default` переименовывается в `Playground`, args и argTypes остаются                                                                                            |
| `button/stories/button-matrix.stories.ts`                  | новый: по истории на ось + `States` + `Themes`                                                                                                                  |
| `button/stories/component/test-button-matrix.component.ts` | только если ось не выражается конфигом обвязки                                                                                                                  |

Правила, решающие содержимое матрицы:

- Ось показывается всеми значениями сразу и подписывается.
- Оси перемножаются, только если видно влияют друг на друга.
- Ось, которую показать нельзя, объявляется в `Overview` с причиной — молчаливый пропуск
  выглядит как покрытие.
- Историю с пустым набором данных считать непокрытием: десяти компонентам (`rt-table`,
  `rt-chat`, `rt-calendar`, `rt-bar-list`, `rt-night-grid`, `rt-thread-list`, `rt-timeline`,
  `rt-toggle-button-group`, `rt-filter-control`, `rt-split-button`) сначала заводится
  правдоподобный набор, потом матрица.

### Волна 3 — оверлеи, отдельный приём

13 компонентов на CDK Overlay: `aside`, `autocomplete`, `confirm-popover`, `container`,
`dialog`, `file-drop`, `menu`, `multiselect`, `page-header`, `popover`, `select`,
`split-button`, `tooltip`. Декларативный вход `open` есть только у `rt-bottom-sheet`.

Раскладываются надвое: презентационная начинка (шапка диалога, пункт меню, тост, панель — они
уже вынесены отдельными компонентами) матрицируется как обычный компонент; сам оверлей
открывает история с `play`-функцией, жмущей триггер при монтировании нативным `click` — новых
зависимостей для этого не нужно.

### Волна 5 — 14 компонентов без историй

Список в `UI-KIT-V2-ISSUES.md` §2.1. У них нет входов, и обёртку строить не из чего: показывать
их надо разметкой с проекцией содержимого, которая пишется руками. Матрица осей к ним не
применима — в `Overview` это объявляется явно.

### Долг по спекам

Параллельно волнам закрываются 11 папок, где спек меньше, чем компонентов: `table` 3/8,
`aside` 2/4, `dialog` 1/3, `menu` 1/3, `tabs` 1/3, `confirm-popover`, `detail-list`, `field`,
`money-list`, `toast`, `tooltip` — по 1/2 каждая. Список сценариев для спеки берётся из разделов
«Главное, что нужно знать» и «Края» соответствующего `CONTEXT.md`.

## Проверка

На каждой волне, до отметки «сделано»:

```bash
pnpm run check:all                              # lint + typecheck + test + build, все пакеты
pnpm exec nx run @rt-tools/ui-kit-v2:typecheck  # Jest типы не проверяет — эта цель проверяет
pnpm exec nx verify @rt-tools/ui-kit-v2         # таблицы входов в MDX сходятся с исходниками
pnpm run build-storybook:ui-kit-v2              # витрина собирается статикой
pnpm run agent-kit:check                        # законы не разошлись с пакетом
```

Затем — глазами, потому что закон требует показа, а не только зелёной сборки:
`pnpm run storybook:ui-kit-v2`, открыть `localhost:6007` и пройти каждый компонент волны
**в обеих темах**, сверяя, что каждая ось показана всеми значениями и ни одна ячейка не пуста.
Это единственная проверка, которую нельзя заменить командой.

Отдельно после волны 0: `nx build @rt-tools/ui-kit-v2` и убедиться, что в `dist/ui-kit-v2` есть
73 `CONTEXT.md` и нет ни одного файла обёртки.

## Открытые вопросы, вынесенные из объёма

- **Чем проверяется полнота матрицы.** Ось, забытая в матрице, выглядит так же, как ось с одним
  значением. `verify`-скрипт сверяет таблицу входов, но не то, что каждый вход показан сеткой.
- **Нужно ли сравнение снимков.** Матрица ловит расхождение, только когда на неё смотрят.
- **RTL.** Кит написан на логических свойствах, но ни одного `[dir=]` в нём нет, и поведение в
  правостороннем письме не проверено ничем. В объём не входит.
