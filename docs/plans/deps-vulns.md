# Оставшиеся уязвимости зависимостей закрыты

**Эпик:** RT-2822 · **Ветка эпика:** `RT-2822-deps-vulns`

## Что даёт

Владелец попросил: «заведи эпик на оставшиеся уязвимости». После эпика RT-2765 GitHub показывает на
`main` 56 открытых уязвимостей (4 критические, 21 высокая, 25 средних, 6 низких), а `pnpm audit` —
52 записи на 20 пакетов, из них 3 критические. Все пакеты кроме `quill` — транзитивные зависимости
инструментов разработки и Prisma. После эпика закрыты все, у которых есть исправленная версия.

Чинится поднятием пинов в блоке `overrides` файла `pnpm-workspace.yaml`, где часть пинов уже есть.
Версия, выпущенная меньше суток назад, не ставится из-за срока ожидания.

## Как стоят ветки

Ветка эпика отведена от главной, ветки задач — от неё, PR задач идут в неё. Стопкой: каждая ветка
задачи отведена от предыдущей, первая от ветки эпика. Все задачи правят `pnpm-workspace.yaml` и
`pnpm-lock.yaml`, и параллельные ветки спорили бы в этих двух файлах.

## Состав

Порядок такой: сначала безопасные пины, потом две задачи с мажорными подъёмами. Мажорные идут по
одной, чтобы откатывать их по отдельности.

| #   | Задача                                                        | Состояние  |
| --- | ------------------------------------------------------------- | ---------- |
| 1   | RT-2823 — пины инструментов разработки до исправленных версий | на слиянии |
| 2   | RT-2824 — Prisma: mysql2 и deepmerge-ts 7→8                   | на слиянии |
| 3   | RT-2825 — Storybook: webpack-dev-middleware 6→7               | впереди    |

Каждая задача проверяется так: `pnpm audit` до и после, число записей по её пакетам падает до нуля,
проверки перед отправкой зелёные.

## Находки по ходу

- Исправленной версии нет не только у `quill`: у `braces` последняя версия 3.0.3, а нужна выше, у
  `sprintf-js` последняя 1.1.3, а нужна 1.1.4. Оба остаются не закрытыми, как и `quill`.
- Задача 1 сняла 45 записей из 52. Остались 7: три без исправления, `mysql2` ×2 и `deepmerge-ts`
  (задача 2), `webpack-dev-middleware` (задача 3).

## Чего эпик не делает

- `quill` не трогается: у него нет исправленной версии, а это прямая зависимость второго кита.
- `sprintf-js` (через `js-yaml@3`) берётся пином в задаче 1, только если исправленная версия
  поставится. Иначе остаётся не закрытым.
- Оповещения на стороне GitHub вручную не закрываются: это настройка хоста, её делает владелец.
