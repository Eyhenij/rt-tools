# Блочный редактор и CMS нельзя взять из rt-tools: каждое приложение пишет их заново

**Эпик:** RT-2591 · **Ветка эпика:** `RT-2591-cms-packages`

## Что даёт

Приложение на стеке rt-tools ставит три пакета и получает блочный редактор, экраны CMS в админке,
сервер CMS и вывод страниц на сайте. Сегодня в rt-tools есть только `rich-editor` на Quill без
ссылок на страницы и без картинок, и модель контента каждое приложение пишет само.

Пакеты переносят готовую, работающую в приложении реализацию. Её подходы не пересматриваются.

- **Тело страницы** — плоский массив блоков `{id, type, content}`. Текстовый блок держит HTML,
  остальные — JSON строкой; весь массив хранится одной строкой.
- **Редактор** — свой, без сторонней библиотеки. Каждый блок — редактируемый элемент, меню
  выделения обрамляет текст тегами, вставка чистится по белому списку тегов. Блоки и пункты
  списков переставляются перетаскиванием CDK.
- **Модель** — тип контента с настройкой разделов формы и страница: статус, избранное, отложенная
  публикация, главная картинка, SEO-поля, токен предпросмотра, блокировка, связи, теги, медиа.
  Рядом — теги, редиректы 301 и 302, папки медиатеки.

## Как стоят ветки

Ветка эпика отведена от главной, ветки задач — каждая от ветки эпика, заявки задач идут в неё.
Пакеты зависят друг от друга по порядку, поэтому следующая задача берётся после слияния
предыдущей в ветку эпика. Стопкой ветки не ставятся.

## Состав

| 1   | RT-2592 — пакет `@rt-tools/cms-contract`                   | впереди   |

| 4   | RT-2595 — выпуск 0.1.0 трёх пакетов в порядке зависимостей | впереди   |

## Решения

- **Контракт Connect генерируется из `.proto` внутри пакета контракта, и сгенерированный код
  лежит в пакете.** В дереве нет ни одного `.proto` и генератора; сгенерированный код в истории не
  требует генератора у того, кто собирает пакет.
- **Названия прав задаёт приложение.** Пакет сервера принимает их настройкой модуля.
- **Хранилище приходит портом.** Пакет сервера объявляет порт символом, как пакет сервера
  авторизации объявляет свои зависимости, а приложение отдаёт реализацию.

## Чего эпик не делает

- Нынешний `rich-editor` в `ui-kit-v2` остаётся: его берут чат и поле сообщения.
- Перевод приложений на пакеты — работа самих приложений.

## Находки

- **RT-2592: `check:docs` в отдельном рабочем дереве краснеет на пяти адресах.** Имя дерева
  и папка передачи работы закрыты `.gitignore` и лежат только в основной копии, поэтому в рабочее
  дерево не попадают. Ветка их не трогала; проверка вне рабочего дерева
  зелёная.
- **RT-2593: серверный пакет ссылается на пакет контракта как `workspace:*`.** Контракта ещё нет в
  реестре. Выпуск RT-2595 заменяет ссылку на версию до публикации серверного пакета, как дерево
  делало для первых пакетов.
- **RT-2594: экраны админки пакета не открывались в живом приложении.** Их проверяет
  переключение приложения на пакет. Пакет клиента ссылается на пакет контракта как
  `workspace:*`, и выпуск RT-2595 заменяет ссылку на версию.
- **RT-2595: npm показывает свежий пакет с задержкой в несколько минут.** Сразу после выпуска
  реестр отдаёт только `0.0.0-stage`, а короткие сведения, которые читает pnpm, отвечают «Not
  found» ещё дольше. Файл версий обновляется после этого. Выпуск шёл с ветки задачи: в файле
  версий ветки эпика не хватало записи `@rt-tools/utils` пакета Angular, и ветка задачи её добавила.
