# Кит: вернуть остаток веса 0.52.0 и подключать пресеты по маршруту

**Эпик:** RT-3694 · **Ветка эпика:** `RT-3694-kit-weight-remainder`

## Что даёт

Исходная цель — вернуть вес, набранный в 0.52.0, без потери возможностей. Эпик находит причину каждого прироста и
возвращает то, что можно вернуть. По строкам кита владелец рост принял, возврат ищется в байтах приложения вне них. RT-3649 и RT-3650 стартовый вес кода не возвращают: это отдельная польза для стилей.

## Точки

- **A:** состояние после влития RT-3641 в main и выпуска 0.53.0, оба идут в том эпике. По проверке веса набор против
  0.51.0 +1434 байта, gzip +3387; с кнопкой на старте +6907 и +4986 (позднее измерение gzip даёт +4984: два
  измерения расходятся на 2 байта, причина не выяснялась). Часть icon легче и закрывает собой рост других
  частей. Причины роста не установлены.
- **B (RT-3682):** для каждой строки с ростом (popover, input, core, menu, «вне частей», bottom-sheet, icon-button,
  form-control, select, dialog, button, а также gzip набора) названы причина и возвратимые байты. Признак: таблица в
  плане; не меньше 90 процентов прироста отнесено к коммитам или возможностям; каждая причина подтверждена сборкой с
  ней и без неё; возвратимые байты измерены, нулевой возврат обоснован.
- **Развилка после RT-3682:** по каждой возвратимой строке владелец говорит «вернуть» (заводится задача этого эпика)
  или «принять рост» (число записывается в план).
- **B (RT-3647):** стили input легче без изменения вида. До плана задачи — пробное измерение; по нему владелец называет
  цель числом или снимает задачу. Признак: вес части input не больше нынешнего минус названное число; снимки без изменений.
- **B (RT-3649):** значения пресета и тем записаны короче, вычисленный вид тот же, полнота пресета проверяется. Первый
  шаг — измерение без комментариев и в brotli, названные файлы и байты, список браузеров для `light-dark()`; по нему
  владелец называет цель или снимает задачу.
- **B (RT-3650):** пресеты объявляются в данных маршрута. Отдельного файла пресета сборка сегодня не выдаёт, поэтому
  первый шаг — решение владельца, нужен ли он, или маршрут подключает файл местных стилей тем службой из точки
  `scope-styles`. Признак: сценарий серверной отрисовки находит ровно одну ссылку в head, браузерный сценарий
  проверяет переход между маршрутами; стартовый вес не растёт.
- **B (RT-3715):** найденные байты приложения вне двенадцати строк возвращены изменением кита без потери возможностей и
  без смены API. Откат ленивой загрузки меняет принятые строки popover, menu и «вне частей», поэтому он идёт только после
  слова владельца. Признак: то же приложение с `button` тяжелее 0.51.0 не больше чем на 13000 байт; gzip по файлам назван
  числом. Не набирается — это сказано числом, и дальше решает владелец.
- **B (RT-3716):** новая версия в npm. Признак: приложение из `npm pack` измерено против 0.51.0, 0.52.0 и остатка.
- **G (веха эпика):** у каждой строки роста есть причина и исход «возвращено» или «принято владельцем»; версия с этим
  выпущена в npm; пробная сборка из `npm pack` измерена против 0.51.0 и 0.52.0 и укладывается в остаток 13000 байт, если
  владелец не решит иначе. Проверку бюджета у потребителя делает человек.

## Причины роста

Причина обозначена номером из таблицы под этой. «С причиной» и «Без неё» — вес строки в двух соседних сборках.
Не сборки, а арифметика, в трёх видах строк. «Остаток» берёт вес HEAD и вычитает неназванные изменения. «Сумма причин
больше роста» берёт рост строки и сумму причин. К15 получен вычитанием, его «Без неё» не вес какой-то сборки.

«gzip вклада» — это разница gzip всего набора между двумя сборками причины, а не часть строки: по столбцу его не
складывают. Ноль в нём у этих трёх видов строк значит, что gzip не мерялся.

**Как получены сборки:**

- Каждая сделана в отдельной временной копии на названном коммите той же командой, что в разделе весов. Убранные
  коммиты — все, что лежат между двумя названными.
- Ранние коммиты RT-3399 меряются от `6d78ddc38`: это общий предок ветки задачи и main. Слияния main внутрь той ветки
  ростом RT-3399 не считаются: их содержимое уже было в 0.51.0.
- Ранние коммиты RT-3399 не собираются с нынешним `pdfjs-dist`. Во временной копии одна строка типов в
  `rt-pdf-viewer.tokens.ts` получила `as never`. Просмотрщик PDF в набор не входит.
- К15 — прирост `menu` при слиянии сверх двух причин по отдельности: из разницы `ddb6eba56`→`61ae919e1` вычтена
  разница `40fb7b025`→`b498977b3`. Отдельной сборки для него нет.
- Рост вне двенадцати строк из приложения по этим причинам не разложен.
- Почти все байты, не приписанные ни одному файлу, это строки связей между начальными кусками. У HEAD вне файлов 5307
  байт, из них 3937 — операторы `import` и `export` между кусками. У 0.51.0 вне файлов 1210 байт и ни одного такого
  оператора. Из прироста 4097 связями объяснены 3937, остальные 160 байт не разобраны.
- То же приложение с `button` на копии с ленивым куском из раздела ниже: 545573 байта (gzip склейки 155340). Против
  HEAD это −1328 байт и gzip −449, начальных кусков те же четыре. Против 0.51.0 остаётся +12929 байт и gzip +8057,
  по файлам — gzip +9636.
