# Приёмник: поставка, PR и закрытие задач

**Эпик:** RT-2674 · **Ветка эпика:** `RT-2674-cargo-delivery`

## Что даёт

Деревья, которые ставят пакет правил, присылают в приёмник замечания о поставке. Аудит очереди
не видит, что строка `Closes` в PR не в main ничего не закроет. В образцах закрытия и начала
задачи не хватает шагов. Правило поставки на GitHub смешивает аудит очереди с правилами PR и не
принимает базу из предыдущей ветки стопки. Проверка перед push умирает на пределе времени хука
и пускает одну команду с несколькими push. После эпика эти места названы в правилах и
проверках, и исполнитель не повторяет записанные промахи.

## Как стоят ветки

Ветка эпика отведена от главной. Ветки задач стоят стопкой: каждая отведена от предыдущей, а
первая — от ветки эпика. PR каждой задачи идёт в ветку эпика, а в теле PR названа ветка, на
которой задача стоит. Задачи правят одни и те же правила поставки и образцы, и ветки,
отведённые параллельно, давали бы конфликт после каждого слияния.
