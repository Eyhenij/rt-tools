# Проверки пакета правил останавливают работу: переделка

**Эпик:** RT-3269 · **Ветка эпика:** `RT-3269-checks-rework`

Заведён по слову владельца от 13.11.2026: «заведи новый эпик на исправление и рефакторинг проверок».
Взят в работу тем же днём: «бери RT-3269».

## Что даёт

Владелец ставит задачу и получает результат без надзора за каждым шагом. Сегодня это не так:
13.11.2026 один PR эпика шёл пять часов, каждый девятый вызов получал отказ, а три запуска набора
перед отправкой из семи ушли впустую.

## Точки

- **A:** проверки угадывают решение владельца по словам, читают состояние работы из записи
  разговора и отказывают ложно. Набор перед отправкой идёт 25–40 минут внутри сессии.
- **B (RT-3280):** шаг снимков при упавшей истории называет эту историю, а не «эталон без истории».
  Признак: сценарии в `tools/tests/visual-gate.test.sh`.
- **C (RT-3271, RT-3274–RT-3276):** проверка не переспрашивает решение владельца и не теряет его
  после сжатия разговора. Признак: запуск проверок на настоящей записи разговора (RT-3277).
- **D (RT-3272, RT-3273):** набор перед отправкой идёт вне сессии. Признак: отправка ветки не ждёт
  набора внутри сессии.
- **G (веха эпика):** эпик из нескольких задач доходит до `main` без повторных вопросов владельцу и
  без ложных отказов. Признак: отчёт метрик (RT-3270) за этот эпик — ноль повторных вопросов и ноль
  ложных отказов.

## Как стоят ветки

Ветка эпика взята от `main`. Ветки задач стоят стопкой: первая от ветки эпика, каждая следующая от
предыдущей. PR задачи идёт в предыдущую ветку.
