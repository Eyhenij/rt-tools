# Разбор правил по RT-3648 — ждёт слова владельца

Ответ роли `skill-curator` от 2026-11-26, пересказан по пунктам. Ничего из этого не внесено.

## Предложения

1. **Быстрые проверки перед кругом ревью** (`.claude/skills/task-delivery-loop-run/SKILL.md`). В них добавить `verify`: он держит таблицы входов в `Overview.mdx`. Перед коммитом круга запускать `node tools/check-archive-age.mjs`, при правке кита — `check:ngdoctor` и `check:kit-weight`. Там же считать `rt_push_touched`: непредусмотренная планом правка добавляет сквозной набор, которому нужен тест. Причина: набор перед отправкой краснел именно на этом.
2. **Массовая замена имён в витрине** (тот же файл и `.claude/skills/rt-tools-storybook-story/SKILL.md`). После замены в историях или обёртках запускать снимки до первого круга. Каждый класс, уходящий из `styles:`, искать во всей обёртке. Список со смыслом «не имя кита» из замены исключать и перечитывать после неё. Причина: роли не увидели три ошибки замены, их нашли снимки. Лишний запуск снимков стоит около 8 минут.
3. **Скрипт, который может писать, роль читает, а не запускает** — ни с каким ключом, `--help` тоже (ресурсы пакета `agents/qa-engineer.md`, `agents/goal-critic.md`, `agents/product-strategist.md`). Причина: `fetch-material-icons.mjs --help` перезаписал рисунки.
4. **Сборка приложения не выбрасывает вызовы на верхнем уровне файла** (`.claude/rt-kit/overrides/pitfalls/lib-layers.md`). «Сборка это вырежет» говорить только после пробной сборки потребителя. По оценке роли это самый слабый пункт.

## Не предлагается

- Отказ отправки после коммита разбора (RT-3658) уже записан находкой 4 в `docs/plans/kit-presets-by-demand-rules-review-3678.md`; на RT-3648 случай повторился.
- Образец `rt-tools-storybook-story` с встроенным `template:` расходится с отказом проверки `check-reuse` на новой обёртке. Роль не нашла, какая проверка отказала. По журналу набора это `node tools/check-reuse.mjs`, признак `inline-template`.
