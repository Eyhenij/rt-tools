# A red main branch and the open tasks of a chain: the findings about the rules layer

They accumulate along the epic RT-2146 (`docs/plans/board-sees-main-and-chains.md`) and are read
at once when the epic is over. The owner says what of this is right; what they name is made into
an edit or a proposal outward. The file outlives the merge of the branches of the tasks.

At every finding an address is named: **the rules layer** — true for any tree of this class, **the
names of the tree** — true only here, **an override** — here it sounds different from the package.

## The closing of the epic on 16 September — the stack merged after a machine change

The review was made after the epic PR #2166 merged. The day's incident record is
`.claude/rt-kit/postmortems/2026-09-16-red-set-explained-away-into-a-bypass.md`.

- **A red check whose cause lies outside the change is still red.** The check asks one question —
  is the set green — and "whose fault" answers another. The same red on the main branch proves the
  cause is not the change and does not make the check pass. The cause is found where it lies — on
  the machine or in the tree — and the check is made green there. The owner's word on a bypass is
  not asked, and offering the owner to run the refused command by hand is the same miss.
  _The address: the rules layer — the law on verifiability, a new article after "a red check means
  wrong code, not a wrong check"._

- **The refusal of the set before sending names the owner's bypass as a third move.** The text
  itself offered "bring the owner the price of a bypass", and the executor took it. A red set has
  two moves: fix what is named, or take the refusals apart and correct the check. A snapshot set
  red on every frame is read from the machine first.
  _The address: the rules layer — the hook that runs the set before sending, its refusal text._

- **A red set under one's own conflicting PR is not a closed circle.** The conflict check asks for
  the send, the set check asks for green, and neither is lifted by the other: the way through is
  the set made green on this machine. A refused send is not read as "no lawful exit".
  _The address: the rules layer — the delivery rule, after the article about one's own conflicting
  PR; a line in the companion; the conflict check's refusal text._

- **The word "push" inside a heredoc of a commit command runs the whole set.** The probe looks for
  the word over the whole command text; a commit body naming a push is not a push, and the set ran
  on a commit for three minutes. Quoted text and heredoc bodies are blanked before the probe.
  _The address: the rules layer — the same hook, the probe line._

- **A re-taken reference set raises both kits' snapshot steps.** References of both kits and of the
  admin suite are taken on this machine and age together; the pipeline runs both sets on any branch
  with code, while the subject split ran only the touched kit. The first CI run of #2166 was red on
  334 second-kit references no local set had checked.
  _The address: the names of the tree — the profile's subject split; a line in the delivery rule's
  companion next to "the set before sending is never narrower than the pipeline set"._

- **A set red on every frame with references a day old is a changed machine, and the machine is
  asked before the pixels.** `softwareupdate --history` against the references' date, then the
  browser version; the share of the divergence comes after. A change for good is closed by
  re-taking every set on this machine, not by naming the cause.
  _The address: the names of the tree — the pitfalls of the rule about checking a kit component,
  and the first step of "sorting out a fallen run" in its visual pattern._

- **The pointed re-take of the first kit takes the path sample without `--`.** The script already
  carries one; a second reaches the runner as an argument, and the selection is lost. The sample is
  a story path fragment (`table/stories`), not a story name.
  _The address: the names of the tree — the same rule's pitfalls._

- **A number after "PR" in the epic plan's makeup reads as a task number.** The state column
  lawfully says `handed in, PR #2151`; the epic audit reported four PR numbers as tasks not linked
  as sub-issues. The regular expression excludes a number preceded by "PR".
  _The address: the rules layer — the epic audit check, with a scenario next to SC-AK-1107._

- **The epic branch is judged by the turn-exit check as a task branch without a folder.** An epic
  branch has no task folder by design; its record is the plan that names the branch. The check
  exempts a branch a plan names as the epic's.
  _The address: the rules layer — the turn-exit hook._

- **The tree's own word ban trips on the line the package writes into every epic task.** The task
  command writes the epic line with a word the tree's glossary bans, and the epic audit demands
  that exact line. Either the ban is narrowed so the fixed line passes, or the package reads the
  word from a setting.
  _The address: the names of the tree — the glossary bans in the checks config; the rules layer —
  the task command and the epic audit read the word from one setting._

- **The note "the set is not the pipeline set" is stale where the set does carry images and
  snapshots.** It is printed only when the profile's set holds none of them.
  _The address: the rules layer — the same hook, the gap note._

- **The send of the cargo refuses the tree's own rule name as a leak of the tree's address.** The
  observations digest names the rule `rt-tools-styling`, and the leak check reads the tree's name
  inside it; five proposals lie unsent since 1 September for that reason.
  _The address: the rules layer — the leak check of the shipment._
