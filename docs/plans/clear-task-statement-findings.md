# Находки ревью правил по эпику RT-3603

Находки роли `skill-curator` ждут слова владельца. Дословные тексты предложений — в записи сессии 24.11.

## RT-3608 — правило проектирования кода

- **Второй разбор цели записи.** Проверка правил получила свой `rt_gate_is_target` рядом с общим
  `rt_write_targets`. На 13 формах команды ответы расходятся в четырёх, трёх форм не видит никто. Статья
  правила «решение живёт в одном модуле» нарушена веткой, которая её ввела. Задача: RT-3615.
- **Предложение пакету, `patterns/code-design-choose.md`.** Хозяина решения ищут по словам вопроса, а не по
  правимому файлу: описания, найденные по файлу, говорят только о нём. Строка таблицы «A question is
  already answered by another module», команда поиска по описаниям и строка частых промахов: функция,
  появившаяся в правках круга ревью, без строки «Решения».
- **Предложение дереву, `task-delivery-loop-run`.** Перед каждым кругом ревью полный набор проверок хуков
  идёт по коммиту, и его вывод читается до запуска ролей. После первого круга RT-3608 запускались пять
  наборов на выбор, и красный `record-count` нашла роль второго круга через 29 минут.
- **Запас доставки нового компонента — 7 знаков из 10000.** Запись об этом уже есть в
  `checks-rework-4-findings-RT-3427.md`, «No check holds the room the task freed»; теперь она срочная.

## RT-3609 — измерение зацепления

- **Предложение пакету, `patterns/code-design-choose.md`.** У проверки, которая отказывает, три вида ввода: что
  читается; что ветка делает с предметом — создаёт, переименовывает, переносит через границу, делит, удаляет,
  привозит слиянием, правит настройку проверки; чем отказ снимают — причина, её нет, слова самого отказа, образец.
  Строка «Данные» называет все три, у каждой формы ответ и случай. Из этого вышли 35 находок двух кругов. Машинная
  половина — RT-3610.
- **Предложение дереву, `task-delivery-loop-run`.** Паттерн велит `nx affected -t test-hooks` перед отправкой, а
  набор перед отправкой запускает то же ещё раз: 580 секунд. Вместо него — набор правимого ресурса и
  `RT_SUITES_BASE=origin/<base> bash projects/agent-kit/tests/run.sh`. Шапка `run.sh` велит гонять целиком и спорит.
- **Предложение дереву, `agent-kit:sync`.** Команда, которая кладёт файлы пакета, кончается проверкой
  `check-format-ignore`: новый файл без строки в `.prettierignore` виден сразу. В RT-3609 это стоило красного
  набора и повтора.

## RT-3615 — один разбор цели записи

- **Остались три разбора команды с другим вопросом.** `defaults/shell.sh` отвечает, пишет ли команда и какие пути
  называет; его спрашивают проверка правил, проверка готового, ход задачи, линтер после правки и `facts.sh`.
  `flow-guard.mjs` судит шаги задачи, `action-of.mjs` узнаёт действие. Новых форм записи они не знают, и ход,
  который называет отказ, `facts.sh` предсказывает по прежнему разбору. Своя задача: спросить общий разбор там, где
  вопрос один, и оставить профилю дерева только то, что дерево меняет.
- **Метку тела команды читают в двух местах:** `rt_no_heredocs` и `shell-words.sh`. Та же задача.
- **Два образца команды записи остались в хуках:** `lint-after-edit.sh:collect_moved` читает `git mv` сам, а
  `script-files.sh` узнаёт сценарий, который вызов кладёт сам, по имени файла. Та же задача.
- **Папку команды проверки не спрашивают.** Путь после `cd папка &&` стоит от корня: вход проверки папку вызова несёт, а
  разбор её не берёт. Ночью 25.11 ведение `cd` самой строки написано и снято. Чтение ролью нашло 14 ошибок, среди них
  обход проверки переопределений через `cd tools &`, имя папки с точкой и подстановку. Своя задача: папка из входа и
  `cd` самой строки вместе. Черновик — `~/.cache/rt-draft-3615/wide-delta.diff`.
- **Файл, которого в тексте команды нет, правила не получает.** Имя из потока у `xargs`, `{}` у `find -exec` и цикл по
  маске: так идёт правка многих файлов разом. Найдено чтением роли 25.11. Своя задача вместе с формами кода.
- **Проверка переопределений не читает сценарий, который команда запускает.** Запись целиком внутри сценария она
  не видит. Своя задача вместе с предыдущей.
- **Запись кодом по доводу функции, доводам сценария, словарю, списку рядов через имя и склеенному пути не видна.** На
  3000 настоящих командах 169 с вызовом записи в коде, у 62 целей нет. Список на строке записи, наоборот, назван
  целью. Довод функции написан ночью 25.11 и снят: общие имена доводов теряли цели и подвешивали разбор. Туда же
  переменная, которой дана другая переменная: `H=$R/hooks`. Своя задача, вопрос владельцу — нужна ли она.
- **Проверке правил не виден сценарий, запущенный из файла.** Форма чаще прочих: 1026 разных команд с 10.11 против 702
  с телом python. Своя задача о формах начинается с неё. Туда же имя внутри `Path(имя)`, запись внутри `docker run`,
  которую прежний разбор отказывал, и правило на чужой файл после `cd` вне дерева. У `shell-words.sh` запас 6 строк:
  задача о папке начнётся с деления модуля.
- **Импорт без употребления прячет число «taken by nobody» у `check-coupling`.** Экспорт, который взяли и не зовут,
  считается взятым. Своя задача, рядом с RT-3612.

Разбор правил после PR 3633, находки ждут владельца:

- **Проверка слога молчит на `sed` с буквой «s» прямо перед русской буквой.** `prose-style-guard.sh:rt_prose_printed`
  режет команду посимвольно без `LC_ALL=C`, awk macOS останавливается, проверка пропускает текст. Роль измерила на
  функции: 0 байт против 27. Исправление в одну строку и случай с русским словом; статья — в
  `.claude/skills/agent-kit-source/`: «An awk that reads a command sign by sign runs under `LC_ALL=C`».
- **Предложение пакету, `patterns/code-design-choose.md`.** Где есть запись настоящего ввода, формы считаются на ней до
  плана, строка «Данные» идёт от самой частой, пропущенная форма названа с числом. В RT-3615 самая частая форма
  посчитана после кода и осталась не видна.
- **Предложение пакету, `patterns/autonomous-work-run.md`.** Ночная работа до одобрения держит план первым коммитом
  ветки: `plan-red` меряет дерево этого коммита. Вопрос владельцу — собирать ли ветку заново или мерить точку развилки.
- **Предложение дереву, `agent-kit-source`.** Статья «names the harmless parts, not the writing ones» не годится разбору
  целей: там список форм закрыт планом, прочее названо в `NOT SEEN`, прежний и новый ответ сравниваются на нескольких
  тысячах записанных команд перед каждым кругом. Сценарий сравнения лежит вне истории, переносить ли — своя задача.
- **Предложение дереву, `code-design/implementation.md`.** Статья «A decision lives in one module» стоит как «не
  проверено ничем», а разбор цели записи держит `write-parse-one.test.sh:second_parse`, SC-AK-1965.
