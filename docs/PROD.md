# Прод приёмника

Где стоит приёмник, из чего он поднят, как до него доходит запрос и что делать, когда он молчит.
Правится тем же движением, что и `docker-compose.prod.yml`: расхождение здесь копится молча, а
читают этот текст как действующий.

## Узел

| Что             | Значение                                           |
| --------------- | -------------------------------------------------- |
| где             | самый малый узел DigitalOcean, Сингапур            |
| система         | Ubuntu 24.04 LTS, x86_64                           |
| чем поднято     | Docker и Compose, поставленные пакетами системы    |
| учётная запись  | `deploy` — она в группе докера, ей же идёт выкатка |
| каталог выкатки | `/opt/message-bus`                                 |
| имя             | `message-bus.dev` — зона живёт у DigitalOcean      |

Что лежит в каталоге выкатки: состав прода, конфиг дороги, сценарий чистки образов, сценарий
дампа и окружение прода. Кода там нет вовсе — он внутри образов.

## Путь запроса

```
дерево или браузер  →  дорога (Caddy)  →  приёмник  →  хранилище
   HTTPS по имени       80 и 443           3000        5432, наружу закрыт
```

Наружу открыты только два порта дороги. Приёмник и хранилище портов не публикуют: попасть в
приёмник можно лишь через дорогу, в хранилище — только с самого узла.

Дорога делит запросы по адресу: `/api/*` уходит приёмнику, всё остальное отдаётся статикой
админки, лежащей в том же образе. Адрес раздела админки файлом не является — на такой запрос
отдаётся страница приложения, а не отказ.

Сертификат выписывает и продлевает сама дорога. Отдельного тайминга и своего клиента ACME на
узле нет. Состояние выдачи лежит на именованном томе: без него каждая выкатка просила бы новый
сертификат и упёрлась бы в недельный предел выдач.

## Состав прода

Четыре контейнера, и порядок между ними значим:

| Контейнер | Что делает                                              | Когда поднимается                  |
| --------- | ------------------------------------------------------- | ---------------------------------- |
| `db`      | хранилище на именованном томе                           | первым, до готовности пробы        |
| `migrate` | накат миграций и выход                                  | после готовности хранилища, разово |
| `api`     | приёмник                                                | только после удачного наката       |
| `web`     | дорога: имя, сертификат, статика админки, проксирование | после того, как приёмник запущен   |

Метка образов — sha коммита, а не «последний»: подвижная метка отстаёт от главной ветки, и узел
молча остался бы на прежней версии, продолжая отвечать.

## Выкатка

Идёт рукой: рабочий поток `Deploy` запускается кнопкой, из главной ветки. Запуск с ветки доходит
до сборок образов и там кончается — так проверяется правка самого конвейера, не трогая узел.

Что делает выкатка по шагам: собирает оба образа на раннере машины под платформу узла, кладёт их
в реестр под sha коммита, копирует на узел состав прода и сценарии, просит узел вытянуть образы
того же sha и поднять состав, спрашивает пробу живости снаружи по имени и после её ответа чистит
старые образы, оставляя три последних sha.

Секреты выкатки — в настройках репозитория: ключ доступа к узлу, его адрес, учётная запись и
адрес приёмника для пробы. Пароль хранилища живёт только на узле, в `.env.prod`, и выкаткой не
трогается: она правится чаще, чем пароль.

## Дамп

```bash
ssh message-bus 'bash /opt/message-bus/dump.sh save'
ssh message-bus 'bash /opt/message-bus/dump.sh load /opt/message-bus/dumps/<файл>'
```

Дамп несёт хранилище целиком: деревья, токены, учётные записи, записи месяца, предложения и
разборы. Загрузка идёт поверх работающего хранилища и перезапускает приёмник — клиент держит
соединения, снятые загрузкой.

Копии дампа лежат на самом узле, в `/opt/message-bus/dumps`. За пределы узла они не уезжают: это
отдельная работа, и она не сделана.

## Когда приёмник молчит

Порядок разбора — от дешёвого к дорогому:

1. **Имя разрешается?** `dig +short message-bus.dev` — должен ответить адресом узла.
2. **Узел жив?** `ssh message-bus 'uptime'`.
3. **Что с контейнерами?** `ssh message-bus 'cd /opt/message-bus && docker compose -f docker-compose.prod.yml --env-file .env.prod ps'` — здесь видно, какой из четырёх упал.
4. **Что говорит приёмник?** `... logs --tail 100 api`. Отказ хранилища виден здесь же.
5. **Место на диске.** `ssh message-bus 'df -h /; docker system df'` — узлу 24 ГБ, и хранилище, упёршееся в полный диск, гаснет чужим лицом: наружу это выглядит молчащим приёмником.
6. **Сертификат.** `... logs --tail 100 web` — предел выдач Let's Encrypt виден только здесь.

Откат: поднять прежний sha руками.

```bash
ssh message-bus 'cd /opt/message-bus && IMAGE_TAG=<прежний sha> \
    docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --no-build'
```

Три последних sha на узле держит чистка — глубже отката нет.
