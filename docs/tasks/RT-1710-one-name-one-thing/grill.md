# Разбор просьбы

## Просьба владельца

Ночное распоряжение: брать в работу весь груз приёма, править самостоятельно, ветки держать
локально и ставить каскадом друг за другом.

## Записи груза

- `cddb02d6fa5516451af481456def7d2e035f4cd70d08288bb6e69d917059e16c` — форма живёт в трёх местах:
  страницей, панелью правки и окном. У каждого места был свой блок с одинаковыми именами элементов
  в разных значениях: одно имя означало две колонки полей, пару «подпись — значение» и список
  снимков; другое разводило кнопки тремя разными промежутками. Статья об общем слое при этом
  исполнялась — все три блока лежали в слое раскладки приложения, и ни одна проверка не краснела.
  Выбирая имя, исполнитель попадал в чужой словарь и приносил чужой отступ: за один заход владелец
  назвал четыре расхождения подряд.

## Шесть вопросов

1. **Что меняется для владельца.** Имя элемента перестаёт значить в трёх местах три разные вещи, и
   отступ, взятый по имени, приходит тот, который ожидался.
2. **Где это живёт.** Правило `styling-bem` — источник пакета.
3. **Чем это подтверждается.** Сверка раскладки, проверки адресов и слога.
4. **Что из этого правило, а что код.** Только правило: словарь имён машина не считает.
5. **Чего работа не делает.** Не заводит гарда: имя блока судит дерево своим гардом, а число
   словарей не судит никто.
6. **Где ветка.** `RT-1710-one-name-one-thing`, каскадом от `RT-1709-missing-command-not-client`.
