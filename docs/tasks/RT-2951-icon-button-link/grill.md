# Grill

## The owner request

Просьба приложения, переданная соседней сессией (кит 0.34.3), — три пункта про `rt-icon-button` и
`rt-input`; сейчас приложение обходит их через внутреннюю разметку кита:

> 1. `rt-icon-button` как ссылка. Нужен вариант с `href`/`routerLink`, который рисует `<a>` вместо `<button>` и сохраняет тот же вид (размеры, hover, ripple, tooltip). […] Ctrl/cmd/shift-клик и средняя кнопка работают, но в контекстном меню нет «Открыть в новой вкладке», а скринридер называет элемент кнопкой.
> 2. `rt-icon-button`: вход `ariaHaspopup` (или общий проброс `aria-*`) на внутренний `<button>`, по аналогии с `expanded` → `aria-expanded`. […] Фокус после закрытия меню возвращается тоже через `querySelector('button').focus()`, так что нужен ещё публичный `focus()` у `rt-icon-button`.
> 3. `rt-input`: публичный метод `focus()`, который фокусирует внутренний `<input>`. […] Есть только защищённый `focusAfterClear()`.

Слово владельца 27.10.2026:

> бери задачу в работу и открывай пр по готовности только после проверки на регрессии и живой проверке

## What the tree already has

- `rt-menu-item` уже рисует ссылку по входу `link` типа `RouterLink['routerLink']`: образец для пункта 1.
- `rt-icon-button` рисует `<button>` внутри шаблона; `expanded` пишет `aria-expanded` — образец для пункта 2.
- `rt-input` держит `fieldEl` и защищённый `focusAfterClear()`.
- Поведение частей кита, взятое у Material, описано в `docs/specs/ui-kit-v2/component-additions/`.

## What the rules already say

- Просьба приложения делается так, как лучше для кита; новый вход по умолчанию даёт сегодняшнее поведение, вид кита не сдвигается.

## Decisions

- **Ссылка — вход `link` по образцу `rt-menu-item`** — один тип адреса на кит. Rejected: `href` для внешних адресов — просьба о маршруте приложения, вход без читателя.
- **`ariaHaspopup` — отдельный вход** — тот же вид, что `expanded`. Rejected: общий проброс `aria-*` — атрибуты хоста пришлось бы переносить на внутренний элемент, и хост остался бы с ними же.
- **`focus()` — публичные методы обоих компонентов**, `focusAfterClear()` вызывает `focus()` поля.
- **Выпуск версии не входит** — владелец назвал PR, а выпуск отдельное решение.
