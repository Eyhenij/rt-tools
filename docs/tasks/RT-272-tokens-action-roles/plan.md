## Что считается сделанным

- В списке принятого гейта графа остаются только девять имён, общих с первым китом; записей
  «мёртвая ссылка», «запасное значение» и «объявление на корне» нет ни одной.
- В списке принятых литералов остаётся один `#eef0f4` в `rt-toggle-button-group`.
- Правило литералов отбивает `rgb()` в объявлении своего свойства — подтверждено подложенным
  литералом, а не рассуждением.
- Замером в браузере в обеих темах подтверждено: отключённая `danger` берёт нейтраль во всех трёх
  оформлениях, наведение на обводочную и текстовую даёт оттенок марки, а не зелёный.
- Гейты графа, литералов и тёмной темы зелёные; `check:all` зелёный.
- Разошедшиеся эталоны названы поимённо и пересняты; неназванных расхождений нет.

## Этапы

### 1. Назначения действия по ролям

- **Что делается:** в `_semantic.scss` снимаются мёртвые с потребительской стороны
  `--rt-color-action-secondary` и `-on-secondary`, и на их место встаёт полный ряд назначений
  действия — `secondary`, `success`, `warning`, `danger`, `info`, каждое с `-hover`, `-active` и
  `-on-`, плюс `--rt-color-action-disabled` и `-on-disabled`. Значения — ступени шкал;
  недостающая ступень заводится в `_primitives.scss`, а не подбирается в назначении.
- **Признак готовности:** каждое имя, на которое сошлётся кнопка, объявлено слоем; ни одного
  нового литерала в слое назначений.
- **Чем проверяется:** `npm run check:tokens-graph`, `npm run check:tokens-styles`.

### 2. Кнопка переезжает на слой назначений

- **Что делается:** мост на корне страницы (`rt-button.directive.scss:3-8`) снимается целиком;
  все десять запасных значений убираются; палитровые модификаторы и оформления берут назначения
  действия.
- **Признак готовности:** в файле кнопки нет ни `:root`, ни второго аргумента у `var()`, ни
  одного кода цвета.
- **Чем проверяется:** `npm run check:tokens-graph` — записи «объявление на корне» и «запасное
  значение» уходят из списка принятого; `npm run check:tokens-styles` — двадцать записей уходят.

### 3. Отключённость перестаёт проигрывать оформлению

- **Что делается:** блок `&:disabled` переезжает ниже всех вариантов оформления и палитры того же
  блока — специфичность не поднимается. Заливная берёт `--rt-color-action-disabled` и
  `-on-disabled`; текстовая и обводочная держат прозрачный фон и тот же приглушённый текст, рамка
  обводочной — `--rt-color-border-default`.
- **Признак готовности:** во всех восемнадцати ячейках матрицы `Button/Disabled` заливка серая
  только у заливного оформления, а цвет подписи не палитровый ни в одной.
- **Чем проверяется:** замер вычисленных значений в браузере в обеих темах.

### 4. Подсветки наведения и дыра гейта литералов

- **Что делается:** четыре записи `rgb(16 185 129 / …)` у обводочной и текстовой кнопки
  переезжают на оттенки бренда; правило `no-hardcoded-design-tokens` учится судить цветовую
  запись в объявлении своего свойства.
- **Признак готовности:** подложенный `rgb(1 2 3 / 4%)` в объявлении своего свойства отбивается
  линтером с именем правила.
- **Чем проверяется:** прогон линтера на подложенном литерале и `pnpm run lint:styles` на всём
  наборе.

### 5. Мёртвые ссылки вне кнопки

- **Что делается:** пометка строки в `rt-thread-list`, текст двух окон, содержимое
  `rt-rich-editor` и подложка `rt-message-composer` переезжают на ближайшее объявленное
  назначение.
- **Признак готовности:** в списке принятого гейта графа не осталось ни одной записи «мёртвая
  ссылка».
- **Чем проверяется:** `npm run check:tokens-graph`.

### 6. Тёмная тема и пары контраста

- **Что делается:** тёмная тема отвечает на каждое новое назначение — переопределением или
  пометкой общего цвета с причиной; пары «текст и фон» новых назначений дописываются в перечень
  замера.
- **Признак готовности:** гейт тёмной темы зелёный, ни одного молчания без причины; пары ниже
  порога стоят в списке с замеренным отношением.
- **Чем проверяется:** `npm run check:tokens-theme`.

### 7. Тексты кита, договорённость и текст статьи

- **Что делается:** страницы витрины про цвет и темы приводятся к сделанному; описание кнопки —
  тоже; в договорённость линии дописывается третье названное вслух исключение вида и правило про
  порядок блока состояния. Текст статьи закона и приёма правила пишется в ход работы и в тело
  отчёта; файл закона в ветке не правится.
- **Признак готовности:** ни одна страница витрины не называет снятых имён; договорённость
  называет три исключения вида, а не два.
- **Чем проверяется:** `npm run check:specs`, `npm run check:docs`, поиск снятых имён по дереву.

### 8. Замер в браузере и пересъёмка эталонов

- **Что делается:** вид проверяется замером вычисленных значений в обеих темах, затем сверяются
  кадры витрины; каждый разошедшийся кадр объясняется, и только объяснённый переснимается.
- **Признак готовности:** расхождений, которым нет объяснения, нет; переснятые кадры названы
  поимённо в ходе работы.
- **Чем проверяется:** `pnpm test:visual:v2`, точечная пересъёмка `pnpm test:visual:v2:update`.

## Чего эта работа не делает

- **Девять имён, общих с первым китом.** Требуют правки выпущенного первого кита; договорённость
  выводит это за границу всей линии.
- **Свод шкалы нейтрального, off-grid отступы, общая шкала высот контролов** — RT-386, позиция 7.
- **Свои свойства кнопки как настроечный API.** `--rt-btn-*` остаются внутренними и в контракт не
  выводятся — RT-274, позиция 8.
- **Починка пар контраста ниже порога.** Новые пары встают в замер со своим отношением; чинит их
  RT-394.
- **Правило линтера на порядок блоков в файле.** Приём держится памятью — так решено на разборе.
