## Что считается сделанным

- Ход, в котором работа поставлена в зависимость от слова владельца вне списка, находит статья
  правила: признак необратимости берётся из списка, а не выводится общим доводом.
- Страж выходов хода не выпускает ход, в котором папка задачи снята коммитом ветки, а заявки
  по ней не открывали.
- Привязка компаньона правила хода называет файл, в котором список лежит.
- Диспетчер зовёт все ветки события, объявленные файлом, а не только первое объявление.
- Стражи завершения, судящие текст ответа, дожидаются его в записи хода; не дождавшись,
  возвращают ход одним отказом.
- Каждая правка хука закрыта сценарием в наборе, и наборы зелёные.

## Этапы

### 1. Признак необратимости берётся из списка

- **Что делается:** статья в правиле хода пакета рядом со статьёй об отказе от необратимого
  действия, и строка при ней в таблице привязок компаньона.
- **Признак готовности:** правило говорит, что общий довод поверх названного списка не
  применяется, и у статьи есть строка привязки.
- **Чем проверяется:** `node tools/check-specs.mjs` — «расхождений нет» означает, что статья и
  её привязка сошлись.

### 2. Привязка компаньона называет свой файл

- **Что делается:** строка о списке действий в компаньоне правила хода перестаёт называть
  список разделом «этого файла» и называет файл, где он лежит.
- **Признак готовности:** по привязке список находится с первого чтения.
- **Чем проверяется:** `node tools/check-doc-paths.mjs` — «расхождений нет» означает, что
  названный путь существует.

### 3. Снятая папка задачи без заявки ход не кончает

- **Что делается:** ранний выход по снятой папке в страже выходов хода дополняется признаком
  открытой заявки; признак берётся из команд самого хода, а не из сети.
- **Признак готовности:** ход со снятой папкой и без открытой заявки возвращается с названным
  оставшимся шагом; со снятой папкой и открытой заявкой — проходит.
- **Чем проверяется:** `bash projects/agent-kit/tests/turn-exit-guard.test.sh` — «0 провалов».

### 4. Диспетчер читает все объявления события

- **Что делается:** диспетчер перебирает все строки объявления события в файле, а не первую;
  договорённость о диспетчере называет это правилом.
- **Признак готовности:** гард с двумя объявлениями зовётся на обоих событиях.
- **Чем проверяется:** `bash projects/agent-kit/tests/dispatch.test.sh` — «0 провалов».

### 5. Стражи дожидаются текста ответа

- **Что делается:** общая читалка ввода получает ожидание последнего текста хода; гард
  утверждения владеет отказом, когда текст так и не появился; прочие текстовые стражи работают
  по дождавшемуся.
- **Признак готовности:** запись без последнего текста даёт отказ, запись с текстом судится как
  прежде, повторный заход по тому же ходу не отбивается.
- **Чем проверяется:** `bash projects/agent-kit/tests/claim-guard.test.sh` — «0 провалов».

### 6. Тексты приведены, раскладка поднята, набор зелёный

- **Что делается:** сценарии в спеках диспетчера и стражей завершения, привязки при статьях,
  раскладка пакета в дерево.
- **Признак готовности:** сценарии закрыты тестами, разложенное сходится с пакетом.
- **Чем проверяется:** `pnpm run agent-kit:check` — «разложенное сходится с пакетом».

## Чего эта работа не делает

- Не публикует редакцию пакета: выпуск — отдельное слово владельца после слияния.
- Не разбирает, почему запись хода отстаёт не на каждом ходе: ожидание закрывает оба случая, а
  причина отставания лежит вне дерева.
- Не трогает гард ожидания и гард происшествия: текста ответа они не судят.
