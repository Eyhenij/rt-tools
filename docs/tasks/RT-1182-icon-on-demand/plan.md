## Что считается сделанным

- Страница, рисующая три значка, шлёт за файлами значков три запроса, а не весь перечень имён.
- Повторный запрос уже приехавшего имени в сеть не уходит.
- Отсутствие файла у одного имени гасит только его значок: соседние нарисованы.
- Предзагрузки всего набора у кита нет ни одной дорогой.
- Гейт снимков второго кита зелёный, и проба разметок значка тоже.
- Замер числа запросов на админке приёмника назван числами до и после.

## Этапы

### 1. Реестр грузит значок по требованию

- **Что делается:** `RtIconRegistry` заводит поток на имя вместо одного потока на весь перечень:
  первый запрос имени грузит файл и дописывает символ в спрайт, повторный ждёт тот же поток,
  отказ одного имени гасит только его. Спрайт заводится первым пришедшим символом; уже лежащий в
  нём символ запроса не даёт. `preloadAll` снимается.
- **Признак готовности:** сценарии `SC-UKV-58`, `SC-UKV-59`, `SC-UKV-60`, `SC-UKV-62` и
  `SC-UKV-63` закрыты спекой рядом с реестром.
- **Чем проверяется:** `pnpm exec nx test @rt-tools/ui-kit-v2 --testFile=src/lib/components/icon/rt-icon.registry.spec.ts` — все её случаи зелёные, ни одного пропущенного.

### 2. Обе разметки значка просят имя одинаково

- **Что делается:** компонент значка просит имя при его появлении и при смене входа; директива
  кнопки — тем же путём, что и компонент. Имя, спрошенное обеими сразу, едет одним запросом.
- **Признак готовности:** сценарий `SC-UKV-61` закрыт, спеки обеих разметок зелёные.
- **Чем проверяется:** `pnpm exec nx test @rt-tools/ui-kit-v2 --testFile=src/lib/components/icon/rt-icon.component.spec.ts` и `pnpm exec nx test @rt-tools/ui-kit-v2 --testFile=src/lib/components/button/rt-button.directive.spec.ts` — обе зелёные.

### 3. Приём кита остаётся адресом набора и ничего не грузит вперёд

- **Что делается:** `provideRtIcons` перестаёт заводить предзагрузку набора; на сервере запрос
  имени в сеть не уходит вовсе. Приём снаружи прежний — адрес набора.
- **Признак готовности:** сценарий `SC-UKV-64` закрыт; в пакете не осталось ни одного пути,
  грузящего весь перечень.
- **Чем проверяется:** `pnpm run build:ui-kit-v2` — сборка проходит; `grep -rn "iconsName" projects/ui-kit-v2/src/lib/components/icon` — перечень остаётся только источником типа имени.

### 4. Обвязка снимков и проба ждут дорастающий спрайт

- **Что делается:** ожидание значков в кадре перестаёт ждать готовый спрайт целиком и ждёт, что
  каждый видимый значок нарисован; проба разметок судит то же самое.
- **Признак готовности:** сценарий `SC-UKV-65` закрыт, две съёмки подряд без правок сходятся.
- **Чем проверяется:** `node tools/visual-gate.mjs ui-kit-v2` — зелёный, без разошедшихся историй; `npm run check:icons` — проба проходит.

### 5. Замер до и после

- **Что делается:** на админке приёмника считается число запросов к файлам значков при первой
  отрисовке — на главной ветке и на этой; оба числа ложатся в ход работы.
- **Признак готовности:** число «после» равно числу значков, нарисованных страницей, и заметно
  меньше числа «до».
- **Чем проверяется:** `pnpm run serve:admin` и счёт записей о ресурсах страницы в браузере — в
  выводе стоят два числа и перечень имён, которые страница попросила.

### 6. Тексты приведены к сделанному

- **Что делается:** правится документация компонента и README пакета, в раздел изменений

- **Признак готовности:** `proposed/` в ветке не остаётся, привязки правил названы местами в коде.
- **Чем проверяется:** `npm run check:specs` и `npm run check:docs` — обе зелёные.

## Чего эта работа не делает

- Готовый спрайт в пакете и список имён параметром приёма: оба способа разобраны в `grill.md` и
  отвергнуты владельцем.
- Разбор набора значков на нужные и мёртвые — работа про содержание набора, отдельной задачи под
  неё пока нет.
- Правка приложения-потребителя, на котором снят замер: оно живёт в другом дереве и получит
  правку версией пакета.
- Публикация новой версии пакета в реестр: отдельный ход и слово владельца.
