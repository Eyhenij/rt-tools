## Что считается сделанным

- Приёмник с Postgres поднимается контейнерами на машине владельца одной командой.
- Реальный прогон отправки с этого дерева довозит груз трёх родов; ответ называет дерево и
  месяц.
- Отправка без токена дерева и с отозванным получает отказ, а не молчание.
- Второй прогон в том же месяце дописывает прежнюю запись, а не заводит вторую.
- Команда приложения заводит дерево, печатает токен один раз и кладёт в базу только хеш.
- Все двадцать сценариев `SC-MB` покрыты спеками; `nx run-many -t lint typecheck test build`
  зелёный на новых проектах.
- Компаньоны трёх правил и словарь приведены к тому, что в дереве появилось.

## Этапы

### 1. Раскладка заведена

- **Что делается:** `apps/message-bus` на NestJS, семья `libs/message-bus-api/<домен>` из
  четырёх слоёв на каждый из трёх доменов, `libs/message-bus-common` под типы груза, теги
  `scope:api-<домен>-<слой>`, границы линтера, Vitest на новых проектах.
- **Признак готовности:** проекты видны Nx, границы объявлены, пустой прогон спек зелёный,
  пакеты в `projects/` остались на Jest.
- **Чем проверяется:** `pnpm exec nx show projects`, `pnpm exec nx run-many -t lint test build`
  на новых проектах, `npm run check:layers`.

### 2. Хранилище и подъём

- **Что делается:** схема Prisma под пять сущностей договорённости, первая миграция, состав
  контейнеров под локальный подъём приёмника с базой.
- **Признак готовности:** миграция накатывается на пустую базу, приёмник поднимается одной
  командой и отвечает на пробу живости.
- **Чем проверяется:** накат на пустую базу, запрос пробы живости, `npm run check:schema`.

### 3. Приём трёх родов

- **Что делается:** три операции приёма, проверка токена дерева, сверка признака дерева,
  запись месяца с дописыванием, обновление разбора по имени, предел веса груза.
- **Признак готовности:** сценарии `SC-MB-1` … `SC-MB-18` и `SC-MB-20` покрыты спеками, каждый
  заголовок теста несёт свой идентификатор.
- **Чем проверяется:** `pnpm exec nx test message-bus`, `npm run check:specs`.

### 4. Команды деревьев

- **Что делается:** заведение дерева с печатью токена один раз, отзыв токена, список деревьев.
- **Признак готовности:** сценарий `SC-MB-19` покрыт; хеш в базе, токен в выводе, отозванный
  не принимается, а его записи читаются.
- **Чем проверяется:** прогон трёх команд на поднятой базе, `pnpm exec nx test message-bus`.

### 5. Живой прогон с этого дерева

- **Что делается:** дерево заводится в приёмнике, адрес приёмника объявляется настройкой,
  груз трёх родов уезжает настоящей отправкой пакета.
- **Признак готовности:** запись месяца заведена первым прогоном и дописана вторым; отправка
  без токена и с отозванным отбита.
- **Чем проверяется:** прогон отправки пакета против поднятого приёмника, чтение записей в базе.

### 6. Тексты приведены к сделанному

- **Что делается:** компаньоны правил `testing`, `lib-layers` и `task-flow`, словарь дерева,
  указатель спеков и линия работ приводятся к тому, что в дереве появились приложения и либы.
- **Признак готовности:** ни один компаньон не утверждает, что серверной стороны здесь нет;
  `Q-2` линии помечен закрытым; слова приёмника стоят в словаре.
- **Чем проверяется:** `npm run check:docs`, `pnpm run agent-kit:check`,
  `node tools/check-file-size.mjs`.

## Чего эта работа не делает

- Не заводит учётных записей и входа — вторая ветка задачи.
- Не заводит админки, списков и панели подробностей — третья ветка задачи.
- Не выкатывает приёмник на арендованный узел, не выписывает сертификат и не ставит обратный
  проксировщик — третья задача линии работ.
- Не правит отправляющую сторону пакета: `Q-14` закрыт решением владельца, но код отправки
  разборов — четвёртая задача линии.
- Не чинит дефект пометки об отправке в `projects/agent-kit/src/lib/proposals.ts` — своя задача.
