# Разбор просьбы

## Просьба владельца

Дословно, одной репликой.

> заведи конду в package.json

Реплика пришла следом за разговором о заведении дерева в приёмнике: владелец звал команды
приёмника на проде строкой `ssh … docker compose … exec api node main.js tree:add …`, и первая
попытка отказала — перенос строки внутри одинарных кавычек разорвал команду надвое.

## Что установлено до первого вопроса

- Команды приёмника — `tree:add`, `tree:token`, `tree:revoke`, `tree:list`, `account:add`,
  `account:passwd`, `account:disable`, `account:list` — объявлены в `docs/specs/message-bus/spec.md`
  и разбираются `libs/message-bus-api/trees/util/src/lib/tree-command.util.ts`.
- Точка входа образа приёмника — `deploy/message-bus.Dockerfile`: рабочий каталог `/app`,
  `CMD ["node", "main.js"]`. Значит команда зовётся `node main.js <довод>`.
- Прод описан в `docs/PROD.md`: узел зовётся `message-bus` в настройках ssh, каталог выкатки
  `/opt/message-bus`, состав `docker-compose.prod.yml` с `--env-file .env.prod`, служба приёмника
  зовётся `api`.
- В `package.json` команды прода нет ни одной: всё, что там есть, работает на своей машине.

## Решения

- **Команда одна на все доводы приёмника, а не по команде на каждый довод.** Набор доводов
  закрыт самим приёмником и меняется вместе с ним; восемь строк в `package.json` разошлись бы
  с ним молча.
- **Доводы уходят на прод как есть.** Обвязка их не разбирает: разбор уже написан в приёмнике,
  и второй разбор рядом означал бы два ответа на вопрос, что за довод пришёл.
