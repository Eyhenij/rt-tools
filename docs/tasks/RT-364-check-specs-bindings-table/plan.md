## Что считается сделанным

- Привязками считаются только строки таблицы раздела «Где исполняются статьи»; строки таблиц
  «Как это называется здесь» и «Где это лежит» не судятся ни в одну сторону.
- Компаньон, у которого раздела привязок нет вовсе, отличается от компаньона с пустой таблицей:
  первый — отказ с внятным текстом, второй — перечень правил без строк.
- Набор сценариев пакета зелёный, включая сценарии на оба поведения.
- Число расхождений сверки спеков в этом дереве названо владельцу до и после правки, и остаток
  разобран по родам.
- Это дерево разложено свежей редакцией, сверки не дают новых расхождений.

## Этапы

### 1. Договорённость о продукте

- **Что делается:** `docs/specs/agent-kit/proposed/bindings-table-only/` — правила, сценарии и
  привязка на одно исполняемое изменение.
- **Признак готовности:** договорённость лежит, префикс сценариев продолжает нумерацию домена.
- **Чем проверяется:** `npm run check:specs`.

### 2. Выборка сужена до раздела привязок

- **Что делается:** строки берутся из раздела «Где исполняются статьи»; отсутствие раздела —
  свой отказ.
- **Признак готовности:** сценарии набора исполняются, снятая правка роняет свой сценарий.
- **Чем проверяется:** прогон пакета.

### 3. Раскладка, вливание и отчёт

- **Что делается:** раскладка в это дерево, договорённость влита в спек домена, остаток
  расхождений разобран по родам и назван, папка задачи разобрана.
- **Признак готовности:** `sync --check` сходится, `proposed/` в дереве нет.
- **Чем проверяется:** `pnpm run agent-kit:check`, `npm run check:specs`, `npm run check:docs`,
  `npm run check:board`.

## Чего эта работа не делает

- Не заполняет компаньоны: пустые привязки и правила без строки остаются как есть, это своя
  работа.
- Не трогает прочих сверок внутри сверки спеков: сценарии против тестов, процедуры против
  декораторов, коды отказа против бросков.
- Не меняет образца компаньона: набор его разделов остаётся тем же.
