# Разбор просьбы

## Просьба владельца

> я опубликовал новую версию пакета agent kit, обнови раскладку под новую версию

## Что уже есть в дереве

- Разложено было `0.9.0`: шапка `rt-kit v0.9.0` стояла в 155 файлах — законах, правилах,
  паттернах, гардах, проверках, ролях, командах, образцах и словаре.
- В реестре пакетов лежит `0.9.1`; исходники этой версии — в главной ветке, коммит подъёма
  номера стоит её вершиной.
- Раскладка в этом дереве читает собранный пакет из самого дерева, а не из реестра:
  `pnpm run agent-kit:sync` сперва собирает `projects/agent-kit`, потом раскладывает
  собранное. Поэтому «обновить раскладку» здесь означает разложить с вершины главной ветки.
- Сверка раскладки стоит первой строкой набора гейта пуша — пока номер в шапках отстаёт,
  пуш отбивается из любой ветки, а не только из той, что правит пакет.

## Что уже сказано в правилах

- Порядок правки пакета — правило `agent-kit`, раздел «Порядок»: правка, сборка, `sync`.
  Отказ хотя бы по одному файлу не пишет ничего.
- Разложенный файл правится надстройкой, а не на месте — то же правило.
- Оформление работы — правило `git-workflow`: задача на борде, ветка по её номеру, PR,
  слияние нажимает человек.
- Папка задачи заводится под любую работу, без исключений — правило `task-flow`.
- Договорённость о продукте требуется по путям правки (`apps/**`, `libs/**`); правила,
  тексты и обвязка под этот признак не подпадают — то же правило.

## Вопросы и ответы

Вопросов владельцу не задавалось: ответ на каждый из них уже записан в правилах, названных
выше. Заданный было вопрос об оформлении работы отбил гард разговора с тем же доводом.

## Решения

- **Раскладка кладётся с вершины главной ветки, а не из реестра пакетов** — команда дерева
  собирает пакет из своих же исходников, и другого пути у неё нет. Отвергнуто: ставить
  `@rt-tools/agent-kit@0.9.1` зависимостью ради раскладки — дерево само публикует этот пакет.
- **Работа оформляется задачей, веткой и PR** — исключения для служебной правки правила не
  знают, а 155 файлов уезжают в главную ветку.

## Что осталось невыясненным

- Ничего: состав правки известен целиком до её начала — сверка называет каждый расходящийся
  файл поимённо, и все 155 строк были одного рода.
