# Разбор просьбы

## Просьба владельца

Ночное распоряжение: работать непрерывно, править самостоятельно, ветки держать локально и
ставить каскадом друг за другом.

## Находка этого захода

Отбой гарда пришёл без единого слова: «Гард browser-guard-require-select.sh вышел с кодом 2 и
ничего не напечатал: похоже, файл сломан». Файл цел. Гард печатает свой отказ в поток ошибок, а
диспетчер поток ошибок глушит — исполнитель получает сообщение о сломанном файле вместо причины,
по которой его отбили.

За заход это пришло дважды. Первый раз ход ушёл на то, чтобы позвать гард руками и прочитать, чего
он хочет; второй раз причина была уже известна.

Строка о сломанном файле при этом верна по букве: код ненулевой, вывод пуст. Неверен вывод, к
которому она ведёт, — чинить предлагается файл, с которым всё в порядке.

## Шесть вопросов

1. **Что меняется для владельца.** Отказ гарда доходит до исполнителя словами, а не приговором
   сломанному файлу.
2. **Где это живёт.** Диспетчер событий — источник пакета.
3. **Чем это подтверждается.** Набор диспетчера и живой прогон на этом дереве.
4. **Что из этого правило, а что код.** Код диспетчера и статья спеки домена.
5. **Чего работа не делает.** Не отдаёт поток ошибок наружу на удачном ходу: шум веток остаётся
   заглушённым, как и был.
6. **Где ветка.** `RT-1722-dispatch-keeps-stderr`, каскадом от `RT-1721-visual-runner-broken`.
