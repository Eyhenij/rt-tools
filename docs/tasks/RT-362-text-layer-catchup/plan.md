## Что считается сделанным

- Гейт правил требует правило под правилом и паттерном, под конфигом линтера и под проверкой
  повторов; ни один из трёх родов больше не проходит общим исключением каталога агента.
- Сверка путей видит голое имя файла и каталог, дерево спрашивает у системы контроля версий, а
  папки задач из неё выведены.
- Полнота указателя каталога сверяется обеими сторонами и печатается своим списком.
- Три закона несут новые статьи, шесть правил и паттернов — новые утверждения с привязками.
- Наборы сценариев пакета зелёные, включая сценарии на оба новых поведения.
- Это дерево разложено свежей редакцией, и сверки не дают новых расхождений.

## Этапы

### 1. Договорённость о продукте

- **Что делается:** `docs/specs/agent-kit/proposed/text-layer-catchup/` — правила, сценарии и
  привязки на три исполняемых изменения.
- **Признак готовности:** договорённость лежит, префикс сценариев продолжает нумерацию домена.
- **Чем проверяется:** `npm run check:specs`.

### 2. Гейт правил судит три рода файлов

- **Что делается:** правило и паттерн выводятся из общего исключения каталога агента, конфиг
  линтера и проверка повторов получают своё правило в карте гейта.
- **Признак готовности:** сценарии набора исполняются, снятая ветка роняет свой сценарий.
- **Чем проверяется:** прогон пакета.

### 3. Сверка путей и указатель каталога

- **Что делается:** голое имя и каталог судятся наравне с путём; дерево берётся у системы
  контроля версий; папки задач выводятся; полнота указателя каталога сверяется обеими сторонами.
- **Признак готовности:** сверка находит голое имя, не видит папок задач и называет расхождение
  указателя своим списком.
- **Чем проверяется:** прогон пакета, `npm run check:docs`.

### 4. Законы, правила и паттерны

- **Что делается:** три статьи законов, утверждения правил `task-flow`, `git-workflow`,
  `doc-style` и паттернов `task-flow-close`, `task-flow-handoff`, `spec-driven-domain`.
- **Признак готовности:** каждое утверждение привязано, сверка спеков расхождений не даёт.
- **Чем проверяется:** `npm run check:specs`, прогон пакета.

### 5. Раскладка, вливание и отчёт

- **Что делается:** раскладка в это дерево, компаньоны дописаны, договорённость влита в спек
  домена, папка задачи разобрана.
- **Признак готовности:** `sync --check` сходится, сверки без новых расхождений, `proposed/` в
  дереве нет.
- **Чем проверяется:** `pnpm run agent-kit:check`, `npm run check:specs`, `npm run check:board`.

## Чего эта работа не делает

- Не переносит предметного слоя второго дерева: конвейер, реестр образов, раннер, миграции базы,
  законы об организациях, ролях, объектах аренды и наблюдаемости, стенды и источники вида.
- Не переводит передачу захода в домашний каталог: здесь она с самого начала лежит в дереве.
- Не выпускает пакет в реестр: выпуск — отдельное решение владельца.
- Не решает судьбу ветки с переписанными архивными записями.
