## Что уже есть в дереве

- Файл совместимости `_coexist.scss` ставит десять ступеней второго кита на узел набора. Пакет
  его не отдавал: в `exports` не было строки, и путь из README не находился.
- Основа кита в `_scrollbar.scss` ставит `scrollbar-width` и `scrollbar-color` всем узлам через `*`.
- Под набором тёмная тема стоит в файле после набора и перебивает двадцать имён, которые набор
  берёт из `--mat-sys-*`.
- Фон полосы действий таблицы — `--rt-color-bg-surface`. В первом ките у него своё имя
  `--rt-table-actions-container-background-color`.
- Градиент на `body` ставит `_theme-dark-rules.scss` под `html.rt-theme-dark`.

## Что уже говорят правила

- Набор включает приложение атрибутом или классом, кит признак из кода не ставит (`rt-tools-styling`).
  Поэтому ответ на вопрос о настройке — атрибут `data-preset="material"`, отдельного поля в
  `provideRtKit` нет.
- Тёмная тема выигрывает у набора порядком в файле. Пункт 3 меняет это для имён, которые набор
  берёт у Material: Material сам переключает свои цвета вместе с темой приложения.

## Вопросы и ответы

**Как завести новый список, раз #2357 уже влит?**
«2356 в этой?» — продолжать в этой ветке RT-2356.

## Решения

- **Полоса прокрутки кита только на узлах кита** — селектор по классу блока кита с нулевым весом.
  Стандартные свойства и `::-webkit-scrollbar` сужаются вместе: оставленный на всех узлах
  `::-webkit-scrollbar` красил бы полосы приложения.
- **Имена Material под тёмной темой** — у имени, которое набор берёт цепочкой `var(--mat-…)`,
  последняя подстановка заменяется тёмным ответом этого имени. Без Material вид совпадает с
  прежним тёмным до точки, с Material цвета идут от темы приложения. Имена через `color-mix`
  остаются на тёмных ответах: подставить в них тёмный ответ нечем.
- **Фон полосы действий** — ручка приложения `--rt-table-actions-bg`, без неё фон поверхности.
