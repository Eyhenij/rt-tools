- Экран входа встаёт колонкой по центру окна: карточка не шире 400, заголовок по центру, кнопка

## Этапы

### 1. Раскладка входа доезжает до потребителя

- **Что делается:** агрегатор слоя оформления форвардит раскладку входа наравне с остальным.
- **Признак готовности:** в собранном файле стилей приложения есть правила `login__viewport`,
  `login__card`, `login__logo`, `login__title`, `login__form` и `login__submit`.
- **Чем проверяется:** сборка админки и поиск по её файлу стилей.

### 2. Экран замерен в браузере

- **Что делается:** админка поднимается прод-сборкой, экран входа открывается и меряется.
- **Признак готовности:** карточка по центру окна, её ширина и высоты контролов сходятся с
  объявленными; вывод подкреплён числами, а не взглядом.
- **Чем проверяется:** замер вычисленных значений в браузере.

### 3. Обещание записано там, где его прочтут

- **Что делается:** спек кита получает правило о том, что объявленное слоем оформления доезжает
  до потребителя одной точкой входа, и привязку к агрегатору.
- **Признак готовности:** правило стоит с привязкой, `npm run check:specs` расхождений не
  прибавил.
- **Чем проверяется:** `npm run check:specs`, `npm run check:docs`.

## Чего эта работа не делает

- Не правит `_login.scss`: вид экрана она возвращает, а не переоформляет.
- Не заводит витрине истории экрана входа — это своя работа, и она шире одной строки форварда.
- Не трогает стили экрана в админке: пустые файлы там законны, раскладку объявляет кит.
- Не заводит учётных записей и входа в админку не проверяет: записей в хранилище ноль.
