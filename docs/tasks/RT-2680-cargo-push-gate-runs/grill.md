## What the tree already has

- Раскладка пишет запись диспетчера без поля `timeout`, и запись в настройке этого дерева его
  тоже не несёт: долгий набор перед push зависит от предела агента по умолчанию.
- Проверка перед push судит рабочее дерево один раз на вызов; команда с циклом `git push` по
  нескольким веткам проходит по одной проверке.
- Проверка плана эпика читает строки таблицы как есть и повторов номера не видит.
- Правило отчёта о состоянии не велит ставить красный прогон первой строкой.

## What the rules already say

Набор перед push не уже набора конвейера. Каждая клетка отчёта о состоянии подкреплена командой.

## Questions and answers

Вопросов владельцу нет: разборы называют и причину, и правку.

## Decisions

- **Команда с несколькими `git push` или с `git push` после `git checkout` отбивается** — одна
  команда даёт одну проверку одного дерева.
- **Новая запись диспетчера на вызов инструмента несёт `timeout`**; стоящая запись не
  переписывается, раскладка называет её.
- **Повтор номера задачи в таблице эпика — находка проверки плана.**
- **Красный прогон на открытом PR — первая строка отчёта о состоянии**, какой бы ни была причина.
