# Замысел

**Задача:** RT-930 · **Ветка:** `RT-930-roles-switch`
**Поведение:** не меняется — работа идёт по слою правил, а не по коду приложения: продукта, о
котором пишется договорённость, она не задевает.

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## След задачи

Части пакета правил названы словами, а не полными путями: гард хода работы читает пути из текста
команды и признаёт правкой кода любое упоминание пути внутрь пакетов — даже в команде, которая
пишет документ. Наблюдение записано к задаче о границах этого гарда.

| Что     | Где                                                           |
| ------- | ------------------------------------------------------------- |
| Правила | `.claude/skills/agent-kit/`                                   |
| Код     | разборщик настройки пакета правил и его хуки                  |
| Тексты  | словарь пакета правил и его описание                          |
| Тесты   | наборы гарда экзамена и гарда совести в пакете правил         |
| Дерево  | `.claude/rt-kit.json`, `.claude/hooks/`, список команд дерева |

## Что считается сделанным

- В настройке дерева есть одно место, где перечислены выключенные роли, и разборщик настройки
  понимает его наравне с остальными ключами.
- Гард при выключенной роли выходит молча и правки не отбивает; при включённой работает как
  прежде.
- Выключенная роль остаётся разложенной: её зовут руками.
- Сломанное чтение настройки роль не выключает и работу не отбивает.
- В этом дереве экзаменатор выключен, и это видно в настройке одной строкой.
- Правило слоя правил говорит, чем роль выключается и что при этом остаётся верным.

## Этапы

### 1. Ключ выключенных ролей в настройке пакета

- **Что делается:** в разборщике настройки заводится ключ со списком выключенных ролей; рядом с
  хуком наблюдений появляется источаемый помощник, отвечающий на вопрос «выключена ли роль»
  чтением того же файла настройки.
- **Признак готовности:** помощник отвечает «выключена» на роль из списка и «включена» на всякую
  другую; при нехватке разборщика JSON или самой настройки — «включена».
- **Чем проверяется:** `pnpm exec nx test @rt-tools/agent-kit` — спеки зелёные, новый ключ
  разобран.

### 2. Гарды ролей спрашивают настройку

- **Что делается:** дерево получает команду прогона наборов по хукам; гард экзамена и гард
  совести первым делом зовут помощника по имени своей роли и при выключенной выходят нулём.
- **Признак готовности:** правка файла при выключенном экзаменаторе идёт без экзамена; при
  включённом отбивается, как прежде.
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 3. Наборы на выключенную роль

- **Что делается:** в наборы обоих гардов дописываются сценарии выключенной роли, включённой роли
  и сломанного чтения настройки.
- **Признак готовности:** каждый из трёх случаев закрыт сценарием со своим идентификатором.
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 4. Тексты: правило, словарь, описание пакета

- **Что делается:** правило слоя правил получает статью о выключении роли, словарь — слово для
  выключенной роли, описание пакета — строку о ключе настройки.
- **Признак готовности:** читатель находит, чем выключается роль, не открывая исходников хуков.
- **Чем проверяется:** `pnpm run agent-kit:check` — расхождений нет.

### 5. Экзаменатор выключен в этом дереве

- **Что делается:** в настройке дерева встаёт строка с выключенным экзаменатором, разложенные
  копии обновляются раскладкой.
- **Признак готовности:** правка файла идёт без экзамена, роль на месте и зовётся руками.
- **Чем проверяется:** `pnpm run agent-kit:sync` — раскладка прошла без отказа.

## Чего эта работа не делает

- Не выключает роль на один заход: срока у выключения нет, оно живёт в файле дерева.
- Не трогает остальные семь ролей: гарда при них нет, и звать их некому, кроме исполнителя.
- Не снимает строку требования из шапок гардов — по ней держится сверка связности раскладки.
