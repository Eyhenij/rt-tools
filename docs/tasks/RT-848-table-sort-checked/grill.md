# Разбор просьбы

## Просьба владельца

> Работай

Работа взята по задаче #848, заведённой при поднятии предела длины файла (RT-796):

> `rtui-table.component.ts`, метод `onSortChange`: модель сортировки приходит с ключом `string`,
> а наружу отдаётся с ключом домена, и разрыв закрыт приведением. Приведение принимает любую
> строку: колонка, которой в наборе нет, уедет потребителю как законное значение, и ни сборка,
> ни типы этого не увидят. Вместо приведения — проверка: имя сверяется с набором колонок
> таблицы, и несовпавшее не отдаётся вовсе.

## Что уже есть в дереве

- `projects/ui-kit/src/lib/ui-kit/table/components/table/rtui-table.component.ts:228` — метод и
  приведение с меткой задачи в комментарии.
- Набор колонок у компонента уже есть сигналом: `columns()` отдаёт `ITable.Column<ENTITY_TYPE>`
  с полем `propName: keyof ENTITY_TYPE`.
- `ISortModel<T>` из `@rt-tools/utils` несёт `propertyName: T` и направление.

## Что уже сказано в правилах

Правило устройства кода запрещает двухступенчатое приведение и велит сужать проверкой; одно-
ступенчатое `as` не проверяется ничем — это открытый вопрос закона, и здесь как раз тот случай,
где сужение возможно.

## Решения

- **Имя сверяется с набором колонок, а не с перечислением** — набор колонок компонент уже
  держит сигналом, и второго списка заводить не надо.
- **Несовпавшее не отдаётся вовсе** — потребитель ждёт ключ своего домена; отдать ему чужую
  строку хуже, чем промолчать.

## Что осталось невыясненным

- Молчание при несовпадении ничем наружу не видно. Ошибку в консоль кит не пишет нигде, и
  заводить это одной таблицей не стоит.
