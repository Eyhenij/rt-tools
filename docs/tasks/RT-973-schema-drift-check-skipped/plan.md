## Что считается сделанным

- Проверка расхождения схемы и миграций на этой машине **отрабатывает**, а не печатает пропуск:
  её вывод называет сошедшиеся миграции либо расхождение.
- Сломанная обвязка проверки роняет гейт, а недоступная база — по-прежнему пропуск. Оба случая
  различимы по выводу, и каждый назван своей строкой.
- Намеренно сломанная обвязка отбивает прогон, и это показано на месте, а не рассуждением.
- Правка лежит в исходнике пакета правил, а не в разложенной копии; `agent-kit:check` зелен.

## Этапы

### 1. Пропуск воспроизведён и измерен

- **Что делается:** проверка гоняется на этой машине как есть — с адресом базы и без него;
  записывается, что она печатает и каким кодом выходит.
- **Признак готовности:** названо, на каком именно шаге она сходит с пути и какой код возвращает
  в каждом из двух случаев.
- **Чем проверяется:** `node tools/check-schema-drift.mjs; echo $?` при поднятой базе и без неё.

### 2. Пакет объявлен в корне

- **Что делается:** `pg` объявляется в `devDependencies` точным номером той версии, что уже
  лежит в хранилище зависимостей; снимок дерева обновляется той же правкой.
- **Признак готовности:** `node -e "require.resolve('pg')"` отвечает путём, а не отказом.
- **Чем проверяется:** та же команда и `pnpm install --frozen-lockfile`.

### 3. Сломанная обвязка перестаёт быть пропуском

- **Что делается:** в исходнике проверки корневой обработчик перестаёт гасить всё подряд:
  недоступный сервер остаётся пропуском с нулём, любой другой сбой — отказ с ненулевым кодом и
  строкой о том, что сломалась сама проверка, а не схема.
- **Признак готовности:** три исхода различимы по выводу — сошлось, расхождение схемы, обвязка
  сломана; у последнего ненулевой код.
- **Чем проверяется:** прогон с намеренно испорченным именем пакета — отказ; прогон с
  недоступным адресом базы — пропуск и ноль.

### 4. Правка разложена и проверена набором

- **Что делается:** пакет собирается, раскладка обновляется, гоняется набор гейта.
- **Признак готовности:** разложенная копия сходится с пакетом, набор зелёный, и проверка
  схемы в нём отрабатывает, а не пропускается.
- **Чем проверяется:** `pnpm run agent-kit:sync`, `pnpm run agent-kit:check`,
  `pnpm run check:affected`.

### 5. Найденное записывается в правило и спек

- **Что делается:** в правило выкатки дописывается, чем «проверять негде» отличается от
  «обвязка сломана» и почему второе не бывает пропуском; спек проверок пакета получает правило
  и сценарий.
- **Признак готовности:** статья стоит, привязка к коду названа, сценарий заведён.
- **Чем проверяется:** `npm run check:docs` и `npm run check:specs` — код ноль.

## Чего эта работа не делает

- Не переписывает проверку на другой способ доступа к базе: объявленная зависимость дешевле и
  не трогает общий с другими деревьями ресурс сильнее необходимого.
- Не делает пропуск при недоступной базе отказом: пуш правки, к базе не относящейся, отбиваться
  не должен.
- Не трогает половину параллельного захода — правила слоя, гарды и разбор предложений.
