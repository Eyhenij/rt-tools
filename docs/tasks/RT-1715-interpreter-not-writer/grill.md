# Разбор просьбы

## Просьба владельца

Ночное распоряжение: брать в работу весь груз приёма, править самостоятельно, ветки держать
локально и ставить каскадом друг за другом.

## Записи груза

- `ce45169b97affef9348df8a451f32253f549026cb9c063c2ea74557a604c4a15` — имя интерпретатора в наборе
  признака записи делает записью любой запуск проверки дерева по пути её файла. Заход, гонявший
  проверку повторов ради диагностики, получил требование правила общего кода, ничего в нём не
  правя; за две задачи таких отбитий набралось около пятнадцати, и часть пришлась на команды,
  которые не писали ничего. Интерпретатор пишет телом, а не именем файла, который запускает: путь,
  стоящий у него первым доводом, — это то, что он читает.

## Замечено в этом заходе

Тот же промах отбил вызовы дважды за ночь: команда `node tools/check-prose-style.mjs <файл>`,
стоявшая рядом с правкой другого файла, была прочитана как правка разложенной проверки.

## Шесть вопросов

1. **Что меняется для владельца.** Запуск проверки перестаёт стоить хода на разбор чужого отказа.
2. **Где это живёт.** Признак записи оболочкой — умолчание профиля дерева, источник пакета.
3. **Чем это подтверждается.** Наборы гардов, где признак судится, и весь набор пакета.
4. **Что из этого правило, а что код.** Код признака и статья спеки домена.
5. **Чего работа не делает.** Не выводит интерпретатор из-под суда: код телом — heredoc и довод —
   остаётся записью.
6. **Где ветка.** `RT-1715-interpreter-not-writer`, каскадом от `RT-1714-fixture-move-duplicate`.
