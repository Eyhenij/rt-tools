# Разбор

Задача заведена из ревью PR #3024 (RT-3013), не из груза приёмника.

## Просьба владельца

На вопрос, какую задачу брать следующей, владелец выбрал:

> RT-3025 reCAPTCHA (Recommended)

Постановка — тело задачи #3025: после `load` скрипта Google без `grecaptcha` ожидание не вешается
на тот же скрипт повторно; оно заканчивается или переходит на `ready`, если API появится позже.
Сценарий — в спеке темы и в `kc-recaptcha.spec.ts`.

## Что уже есть в дереве

- `projects/auth-keycloak-theme/src/login/kc-recaptcha.ts:whenRecaptchaReady` — по `load` снимает
  слушатели и снова зовёт ожидание. Без `grecaptcha` оно находит тот же скрипт и вешает новый
  `load`, который не придёт.
- Спека темы `docs/specs/auth/theme/`: сценарии SC-AUTH-91…95 о флажке, привязка статьи «The page
  waits for the Google script only while it draws the widget» к `whenRecaptchaReady`.
- `kc-recaptcha.spec.ts` — пять тестов, все зелёные.
- Свободный номер сценария — SC-AUTH-96 (`pnpm run spec:next-id AUTH`).

## Что уже говорят правила

- `spec-driven`: новый сценарий берёт следующий свободный номер, тест и сценарий правятся одним
  изменением.
- `testing`: номер сценария стоит в заголовке теста.

## Вопросы и ответы

**Какую задачу брать следующей?**
«RT-3025 reCAPTCHA (Recommended)».

## Решения

- **После `load` без `grecaptcha` ожидание кончается, а не ждёт API дальше.** Скрипт Google
  ставит `grecaptcha` с заглушкой `ready` сразу при исполнении; если после `load` его нет, скрипт
  подменён или сломан, и ждать нечего. Отвергнуто: опрос `window` по таймеру — он живёт без
  срока и ничего не обещает.

## Что осталось неясным

- Ничего.
