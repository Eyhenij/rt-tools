# Разбор просьбы

## Просьба владельца

Ночное распоряжение: брать в работу весь груз приёма, править самостоятельно, ветки держать
локально и ставить каскадом друг за другом.

## Записи груза

- `794145dcdf0e90e1b3405a7d03d6b4a27cf4c94556d4b57c51334fa8aa7b67ca` — образец объявления
  сверяется с именем инструмента, а на запуске сессии имени инструмента нет вовсе: там образец
  называет род запуска. Через диспетчер не зовётся ни один хук входа — заход стартует без свода
  законов, без словаря, без состояния работы и без передачи прошлого захода. Позванные напрямую,
  те же пять хуков отдают семьдесят два килобайта; через диспетчер — ноль байт.

## Проверено на этом дереве

Прогон `echo '{"source":"startup"}' | bash .claude/hooks/dispatch.sh SessionStart` отдаёт ноль
байт при пяти разложенных хуках входа, объявляющих `SessionStart startup|resume|compact|clear`.

## Шесть вопросов

1. **Что меняется для владельца.** Заход через диспетчер получает свод законов, словарь,
   состояние работы и передачу прошлого захода — то, ради чего эти хуки написаны.
2. **Где это живёт.** Диспетчер событий — источник пакета.
3. **Чем это подтверждается.** Набор сценариев диспетчера и живой прогон на этом дереве.
4. **Что из этого правило, а что код.** Код диспетчера и статья спеки домена.
5. **Чего работа не делает.** Не трогает сами хуки входа: они объявляют род запуска и правы.
6. **Где ветка.** `RT-1707-dispatch-session-source`, каскадом от `RT-1706-intake-address-source`.
