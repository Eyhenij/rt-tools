# Замысел

**Задача:** RT-710 · **Ветка:** RT-710-pr-as-result
**Поведение:** не меняется — правятся тексты законов и правил, которые везёт пакет; состав
ресурсов, механизм раскладки и публичная поверхность пакета те же. Владелец назвал работу
словами «запиши это в законы и правила».

## След задачи

| Что       | Где                                                                                                 |
| --------- | --------------------------------------------------------------------------------------------------- |
| Законы    | `projects/agent-kit/assets/laws/delivery.md` и разложенный `docs/constitution/delivery.md`          |
| Правила   | `projects/agent-kit/assets/rules/git-workflow.*.md`, `assets/rules/task-flow.md`                    |
| Паттерны  | `projects/agent-kit/assets/patterns/git-workflow-commit.*.md`, `assets/patterns/task-flow-close.md` |
| Компаньон | `.claude/skills/git-workflow/implementation.md` — правка по замеру об учётной записи                |
| Спеки     | `docs/specs/agent-kit/` — механизма не задевает, читается на закрытии                               |

## Что считается сделанным

- Закон о поставке требует, чтобы работа, меняющая код, кончалась открытым PR.
- Закон называет черновик PR: не готовое к слиянию помечается им, снятие черновика — отдельный
  ход исполнителя.
- Все три вида правила поставки и оба вида паттерна о ветке, коммите и PR говорят то же, что
  закон, и несут готовую команду открытия черновиком.
- Правило ведения работы не противоречит новому требованию: PR, открытый посреди работы,
  перестал быть нарушением порядка.
- Компаньон правила поставки в этом дереве называет учётную запись, PR которой владелец видит.

## Этапы

### 1. Статьи в закон о поставке

- **Что делается:** три статьи — работа, меняющая код, кончается открытым PR; не готовое к
  слиянию помечается черновиком; снятие черновика — отдельный ход. Текст приносится владельцу
  до правки: закон без его слова не правится, а слово на саму работу уже дано.
- **Признак готовности:** статьи стоят в `assets/laws/delivery.md`, разложены в
  `docs/constitution/delivery.md`, старые статьи о PR не переписаны и не потеряны.
- **Чем проверяется:** `pnpm run agent-kit:sync`, `pnpm run agent-kit:check`.

### 2. Правила и паттерны приведены к статьям

- **Что делается:** три вида правила поставки, правило ведения работы, паттерны о ветке,
  коммите и PR и о закрытии работы. Готовая команда открытия несёт ключ черновика; чеклист
  перед публикацией знает два состояния — черновик и готовность к слиянию.
- **Признак готовности:** ни один текст не говорит, что PR открывается только в конце работы;
  у каждой новой статьи есть место, где сказано, каким приёмом она держится.
- **Чем проверяется:** `bash projects/agent-kit/tests/run.sh`, `pnpm run agent-kit:check`,
  `npm run check:docs`.

### 3. Компаньон правила поправлен по замеру

- **Что делается:** в `.claude/skills/git-workflow/implementation.md` записано, что PR,
  открытый учётной записью машинной работы, владельцу не виден: хостинг отвечает «не найдено»
  по его номеру, а список PR его не показывает. Названо, какой записью PR открывается сейчас и
  чем это проверить.
- **Признак готовности:** утверждение компаньона сходится с ответом хостинга, и рядом стоит
  команда, которой это спрашивают.
- **Чем проверяется:** `npm run check:docs`, вызов проверки из самого текста.

## Чего эта работа не делает

- Машинной проверки «PR открыт без черновика при незакрытых этапах замысла»: признака
  готовности у машины нет, и заводить его здесь не планируется.
- Правки гардов поставки: они судят открытие PR по номеру и ветке, а черновик им не виден.
- Работы эпика RT-702 — ревью текстов слоя правил идёт своими задачами.
