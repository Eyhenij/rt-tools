# Разбор

## Просьба владельца

> Да, завести обе

Ответ владельца 23.11.2026 на вопрос «Завести две найденные дыры отдельными задачами эпика?».
Просьба эпика RT-3476 — «Продолжи работу по эпику ng doctor». Карточка RT-3526: Angular Doctor
берёт настройку и из поля `angularDoctor` файла `package.json`, а `check:ngdoctor` это поле не
смотрит; настройка там может выключить правила или файлы незаметно для проверки.

## Что уже есть в дереве

- `tools/check-ngdoctor.mjs` судит `angular-doctor.config.json` функцией `configProblem`: файл,
  который не разбирается, и любое поле, кроме `reportPath`, краснят проверку. Флаг `--config`
  подменяет путь к файлу для сценариев.
- Инструмент 0.3.0 (`loadConfig`) читает сперва `angular-doctor.config.json`, потом поле
  `angularDoctor` только корневого `package.json` и сливает поле поверх файла: при одинаковых
  ключах побеждает поле, у `rules` ключи сливаются. Ложное значение поля (`null`, `false`, `0`,
  `""`) инструмент пропускает.
- `reportPath` решает, куда инструмент пишет отчёт; `reportPath` в поле переписал бы путь из файла.
- Корневой `package.json`, который не читается или не разбирается, уже останавливает проверку
  (RT-3525). Поля `angularDoctor` в нём сегодня нет.

## Что уже говорят правила

- Правила Angular Doctor не выключаются в настройке — так решил владелец (план эпика, «Чего эпик
  не делает»).
- Большие изменения в этом эпике не делаются — слово владельца 23.11.2026.

## Вопросы и ответы

**Что проверка допускает в поле `angularDoctor` корневого `package.json`?**
Ответ уже стоит в карточке RT-3526, заведённой словом владельца «Да, завести обе»: «Проверка
читает и поле `angularDoctor` в `package.json` и судит его так же, как файл настройки». Вопрос всё
же ушёл владельцу и был лишним — решение взято из карточки.

## Решения

- **Поле `angularDoctor` корневого `package.json` судится так же, как
  `angular-doctor.config.json`: допускается только `reportPath`, любой другой ключ краснит
  проверку с именем `package.json`.** Так велит карточка. Отвергнуто: запрет поля целиком — он
  расходится со словами карточки.
- **Значение поля, которое не объект, краснит проверку,** кроме ложного, которое инструмент
  пропускает: настройка, которую нельзя разобрать как набор ключей, не судится, и проверка не
  может сказать, что она безвредна.

**Описание фичи:** не нужно — правка касается только проверки дерева, поведения приложения она не
меняет.

## Что осталось неясным

- Ничего: устройство суда над файлом настройки уже есть, задача прикладывает его ко второму месту.
