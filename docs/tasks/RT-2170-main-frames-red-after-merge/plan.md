## What counts as done

На главной ветке все три набора кадров зелёные на этой машине, и повторное поднятие даёт тот же
ответ. Величина, по которой кадры расходились, названа браузеру явно — или названа причина, по
которой закрепить её нечем.

## Stages

### 1. Найти величину, по которой расходится растр знаков

Измерение, а не догадка: один и тот же экран снимается с разными аргументами запуска браузера, и
называется тот аргумент, который двигает знаки.

**Сделано, когда:** названа величина и показаны два кадра — с ней и без неё — с числом разошедшихся
точек у каждого. Если ни один аргумент не двигает знаки, названо, что двигает.

### 2. Закрепить величину в обвязке всех трёх наборов

Сквозной набор называет три величины из правила, витрины не называют ни одной. Закрепляется там,
где снимается: `playwright.config.ts` и обе обвязки витрин.

**Сделано, когда:** аргумент стоит во всех трёх местах, и проба показывает, что без него кадр
расходится, а с ним держится.

### 3. Переснять кадры главной на закреплённой отрисовке

27 кадров — 22 сквозного набора и 5 первой витрины — плюс всё, что сдвинется от закрепления.
Каждый кадр перед съёмкой осматривается.

**Сделано, когда:** `pnpm exec nx run message-bus-admin-e2e:e2e`, `node tools/visual-gate.mjs
ui-kit` и `node tools/visual-gate.mjs ui-kit-v2` зелёные, и второе поднятие подряд даёт то же.

### 4. Дописать правило проверяемости

Правило перечисляет три величины растра. Если нашлась четвёртая, она встаёт туда же статьёй с
ценой промаха.

**Сделано, когда:** `npm run check:specs` и `npm run check:file-size` без расхождений, статья
привязана в компаньоне.
