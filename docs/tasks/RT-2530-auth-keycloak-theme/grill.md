# Grill

## The owner request

> изучи как утроен логин на <двух приложениях владельца> - нужно вынести логин в отдельный модуль который можно подключать в приложения

Задача эпика RT-2528, текст карточки:

> Стандартные экраны Keycloak выглядят чужими для админок.
>
> - Тема Keycloak собрана через Keycloakify из компонентов второго кита: вход, восстановление и смена пароля, приглашение, подтверждение почты, вход через Google и Apple.
> - Светлая и тёмная тема, переводы.
> - Своих расширений Keycloak нет.

## What the tree already has

- Стенд `deploy/auth/compose.yml`: Keycloak 26.5.5, область `rt` из файла, языки en и ru, почта
  в Mailpit. Тема входа у области стандартная.
- Экран входа админки приёмника: `libs/message-bus-admin/auth/feature/sign-in` и
  `libs/message-bus-admin/auth/ui/src/lib/sign-in-form`. Он собран из `rt-field`, `rt-input`,
  `rt-message`, `rtButton` и `rt-theme-toggle` на классах `login__*` из
  `projects/ui-kit-v2/src/styles/_login.scss`. Это образец вида.
- Подписи кита идут через `provideRtKitLabels()`, тема — через `ThemeService` второго кита.
- `rt-input` не отдаёт атрибут `name` своему полю. Страница Keycloak отправляет форму обычным
  запросом на адрес действия, поэтому значения нужно класть в скрытые поля с именами.
- Keycloakify 11.16.1 и `@keycloakify/angular` 22.1.0 подходят к Angular 22.1 дерева. Для сборки
  JAR нужен Maven.

## What the rules already say

- `reuse-first`: экран собирается из готовых компонентов кита, а не из своей вёрстки.
- `verifiability`: вид подтверждается кадром и измерением, а не зелёным прогоном.
- В плане эпика: своих расширений Keycloak на Java нет.

## Questions and answers

Новых вопросов владельцу нет: карточка задачи называет экраны, темы и языки. Решения ниже приняты
по умолчанию и названы, чтобы их можно было оспорить на ревью.

## Decisions

- **Тема — приложение Angular в `projects/auth-keycloak-theme`, итог — JAR темы.** Keycloak
  берёт тему только файлом в каталоге провайдеров. Отвергнуто: тема на FreeMarker без
  Keycloakify — тогда компоненты кита не подключить.
- **Своими страницами сделаны вход, сброс пароля, смена пароля, подтверждение почты, сообщение,
  ошибка, выход и истёкшая страница.** Приглашение в Keycloak — письмо с действиями: человек
  приходит на страницу сообщения и затем на смену пароля. Остальные страницы Keycloak рисуются
  стандартной вёрсткой Keycloakify.
- **Форма уходит в Keycloak обычной отправкой.** Значения лежат в полях кита и копируются в
  скрытые поля с именами. Отвергнуто: добавить `name` в `rt-input` — это правка и выпуск кита
  ради одной темы.
- **Тексты страниц — из сообщений Keycloak на языке области.** Подписи самого кита идут через
  его переводчик на том же языке. Отвергнуто: свой словарь темы — он разойдётся с письмами
  Keycloak.
- **Тёмная тема — `ThemeService` в режиме `auto` и переключатель кита над карточкой.**
- **Кнопки входа через Google и Apple рисуются по списку провайдеров области.** Сам провайдер
  Apple в области требует расширения или ручной смены секрета; это решает RT-2534, а не тема.
- **Стенд монтирует собранный JAR, а область называет тему `rt`.** Команда подъёма сначала
  собирает тему: без JAR область с темой `rt` показывает вход без оформления.

## What is left unclear

- Публикация пакета с JAR и его подключение в чужой Keycloak — задача RT-2534 вместе с
  публикацией остальных пакетов. Тему это не блокирует.
