## Что считается сделанным

- Отказ хранилища оставляет в журнале класс ошибки, её текст, код клиента хранилища, его
  подробности, ответ драйвера и срезанный стек.
- Строка журнала машинная: имя постоянно, переменное лежит полями; вне прода печатается
  читаемой.
- Поля вычищаются по имени ключа до вывода, а текст ошибки внутри разобранной причины остаётся
  целиком.
- Десять сценариев `SC-MB-97`…`SC-MB-106` покрыты спеками, привязки проставлены.
- `npm run check:specs` расхождений не прибавил, гейт пуша зелёный.
- `docs/PROD.md` описывает разбор молчания так, как он работает после правки.

## Этапы

### 1. Разбор ошибки и вычистка

- **Что делается:** в либе наблюдаемости приёмника заводятся разбор ошибки в поля и вычистка
  по имени ключа, с пределами глубины, длины и срезом стека.
- **Признак готовности:** обе чистые функции покрыты спеками, включая цепочку причин и текст
  ошибки, который вычистка не съедает.
- **Чем проверяется:** `nx test` по затронутым проектам.

### 2. Машинная строка журнала

- **Что делается:** логгер приложения пишет имя и поля, ставится на всё приложение; вне прода
  печатает читаемый вид.
- **Признак готовности:** уже написанные вызовы журнала выходят в новом виде, ничего в них не
  правя.
- **Чем проверяется:** спеки логгера, ручной подъём приёмника с настройкой прода и без неё.

### 3. Разбор отказов пишет подробности

- **Что делается:** разбор отказов зовёт разбор ошибки и кладёт причину полями; отказ по вводу
  идёт без стека.
- **Признак готовности:** прежние пятнадцать сценариев спеки разбора отказов зелёные, новые
  добавлены.
- **Чем проверяется:** `nx test`, `npm run check:specs`.

### 4. Тексты приведены к сделанному

- **Что делается:** договорённость вливается в спек домена, компаньон правила наблюдаемости
  получает привязки вместо строк «не исполняется», `docs/PROD.md` описывает разбор молчания
  по-новому.
- **Признак готовности:** ни один текст по следу задачи не описывает журнал таким, каким он был
  до правки.
- **Чем проверяется:** `npm run check:specs`, `npm run check:docs`, чтение глазами.

## Чего эта работа не делает

- Не заводит хранилища отказов, экрана владельцу и оповещений: это своя работа с миграцией.
- Не заводит номера обращения на каждый запрос и контекста запроса: строк об одном обращении у
  приёмника пока ровно одна.
- Не пишет в журнал тел запроса и ответа: груз приезжает мегабайтами.
- Не берёт задач вне эпика RT-733.
