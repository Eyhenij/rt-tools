# Разбор просьбы

Работа взята из очереди работ карточкой RT-1794; заведена она находкой предыдущей работы —
RT-1771, где правила видимости подложки панели вынесены из слоя нарочно.

## Просьба владельца

> ## Что не так
>
> Проверка слоя каскада судит две вещи: сколько в файле обёрток `@layer rt-kit.components` и
> нет ли правил до первой. Правила, стоящие **после** закрывающей скобки обёртки, она не видит
> вовсе и печатает про такой файл «все в подслое rt-kit.components».
>
> Из-за этого нарочный вынос правила из слоя и промах «часть файла уехала за скобку» для дерева
> неотличимы. Первый такой вынос уже есть — правила видимости подложки панели в
> `projects/ui-kit-v2/src/lib/components/aside/_rt-aside-overlay.scss`: он нужен по делу, и
> стережёт его своя проба над собранным CSS. Второй такой же файл приедет молча, и стеречь его
> будет нечем.
>
> ## Что сделать
>
> - Научить `tools/check-cascade-layer.mjs` видеть правила после закрытия обёртки.
> - Нарочный вынос отличать по отметке в самом файле — рядом с вынесенными правилами уже стоит
>   пояснение с причиной; промах без отметки роняет проверку.
> - Накопленное — один файл панели — принять списком либо признать отметкой.
>
> ## Как проверить
>
> Дописать правило после закрывающей скобки обёртки в любой файл стилей второго кита:
> `pnpm run check:cascade-layer` сейчас зелёная, после правки — красная.
>
> ## Что не входит
>
> Сам вынос правил видимости подложки не меняется: он сделан по задаче RT-1771.

## Что уже есть в дереве

- `tools/check-cascade-layer.mjs` — проверка судит число обёрток и правила до первой; список
  принятого — `tools/cascade-layer-allowlist.json`, разбор списка даёт модуль настройки
  проверок.
- `projects/ui-kit-v2/src/lib/components/aside/_rt-aside-overlay.scss` — единственный файл с
  правилами после закрывающей скобки; над вынесенными правилами стоит пояснение, начинающееся
  словом `rt-layer-outside`.
- Правило дерева `rt-tools-styling` уже несёт статью о таком выносе: правило, спорящее с
  неслоевым правилом чужой библиотеки, объявляется вне слоя и говорит об этом при себе.

## Что уже сказано в правилах

- `rt-tools-styling`: обёртка одна на файл, снаружи законны только `@use`, `@forward` и
  `@import`; вынос по спору с чужой библиотекой назван исключением.
- `testing`: список известного у проверки именной и объясняет себя сам; запись несёт причину и
  номер задачи.

## Вопросы и ответы

Владельцу не задавалось ничего: карточка называет и способ отличить нарочный вынос от промаха,
и способ проверки.

## Решения

- **Нарочный вынос узнаётся по отметке в самом файле, а не по списку принятого** — список
  говорит «здесь так уже было», отметка говорит «здесь так надо»: второе читается тем, кто
  правит файл, а первое — только тем, кто открыл список. Отвергнуто: принять единственный
  нынешний случай списком — тогда следующий вынос по делу пришлось бы вносить в список,
  то есть заводить его отметкой задним числом.

## Что осталось невыясненным

- Нужна ли такая же отметка первому киту: его стили в слой не обёрнуты вовсе, и проверка их не
  читает. Работу не блокирует.
