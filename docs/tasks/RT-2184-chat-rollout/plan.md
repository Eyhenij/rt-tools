## Что считается сделанным

- Страница чужого приложения берёт виджет по адресу узла и разговаривает с сервисом: браузер
  обращение с чужого адреса не отбивает, а сервис отвечает только адресам из списка площадки.
- Виджет лежит в образе дороги и отдаётся тем же проксировщиком, который отдаёт админку.
- Поддомен чата указывает на тот же узел, и сертификат на него выписывается тем же
  проксировщиком.
- Описание запуска рядом с приёмником называет, что чат живёт внутри него и что отдаёт дорога.
- Выкатка чата идёт тем же шагом конвейера, что и выкатка приёмника, а дампы несут таблицы чата.
- Сценарии `SC-CH-74` и дальше закрыты пробами или несут пометку с причиной.

## Этапы

### 1. Договорённость о выкатке

- **Что делается:** описание в `docs/specs/chat/proposed/rollout/` — чем виджет попадает на чужую
  страницу, чем браузер получает право на обращение, что отдаёт дорога, что везёт какой образ и
  чего стоит отказ каждой из сторон; сценарии к нему.
- **Признак готовности:** аудит описаний не называет по новому описанию ни пропущенного раздела,
  ни занятого номера сценария.
- **Проверяется:** `node tools/check-specs.mjs` — ни строки про пропущенный раздел и ни строки
  про занятый номер.

### 2. Позволение на обращение с чужого адреса

- **Что делается:** открытые операции чата отвечают заголовками о доступе по списку адресов
  площадки — и предварительный запрос браузера тоже; адрес не из списка не получает позволения.
- **Признак готовности:** пробы домена чата зелёные, и среди них проба о том, что чужой адрес
  позволения не получает.
- **Проверяется:** `pnpm exec nx run-many -t test -p message-bus-api-chat-feature message-bus-api-chat-util`
  — «Successfully ran target test for 2 projects».

### 3. Виджет в образе дороги и поддомен

- **Что делается:** сборка виджета в образе дороги, раздача его файла проксировщиком, имя
  поддомена в настройке дороги; описание запуска рядом с приёмником дополняется чатом.
- **Признак готовности:** образ дороги собирается, и файл виджета лежит в нём по названному
  адресу.
- **Проверяется:** `docker build -f deploy/message-bus-web.Dockerfile -t message-bus-web:gate .`
  — «naming to docker.io/library/message-bus-web:gate done»; `docker run --rm message-bus-web:gate ls /srv/widget.js`
  — путь назван.

### 4. Сквозная проба чужой страницы и дампы

- **Что делается:** сквозная проба на то, что страница чужого адреса разговаривает с сервисом;
  проверка того, что дамп несёт таблицы чата.
- **Признак готовности:** сквозной набор зелёный и не короче прежних 153 сценариев.
- **Проверяется:** `pnpm exec nx run message-bus-admin-e2e:e2e` — «153 passed» и больше.

### 5. Договорённость вливается, шаг конвейера и PR

- **Что делается:** описание переезжает в спеку домена вместе с привязками, шаг выкатки
  проверяется на то, что везёт и чат, папка задачи разбирается записью в `docs/archive/`, набор
  перед отправкой прогоняется целиком, PR открывается в ветку эпика готовым.
- **Признак готовности:** аудит описаний — нулевой код, PR открыт с рецензентом.
- **Проверяется:** `node tools/check-specs.mjs` — нулевой код; `gh pr view <номер> --json isDraft,reviewRequests`
  — черновика нет, рецензент назван.

## Чего эта работа не делает

- **Отдельное приложение чата на узле.** Чат живёт внутри приёмника: второй процесс стоил бы
  памяти на узле, где её 961 МБ.
- **Второй узел и перенос приёмника.** Эпик обещал владельцу обратное: тот же узел, тот же
  конвейер, те же дампы.
- **Экран правки настроек площадки.** Его нет ни у приветствия, ни у часов ответа, ни у адреса
  вызова наружу; заводить его эта работа не берётся.
- **Своё имя для приёмника чужого приложения.** Приложение-потребитель принимает вызовы наружу
  по своему адресу, и сервис о его устройстве ничего не знает.
