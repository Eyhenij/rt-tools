# Разбор просьбы

## Просьба владельца

Ночное распоряжение: брать в работу весь груз приёма, править самостоятельно, ветки держать
локально и ставить каскадом друг за другом.

## Находка предыдущей задачи

Помощник целей записи считает признаком записи всякое перенаправление, в том числе в пустое
устройство и в поток ошибок. Внутри тела интерпретатора это оживляет прежний промах целиком:
команда, где после `-e` стоит выражение правки одного файла, а следом — запуск проверки с
`>/dev/null 2>&1`, снова отдаёт все свои пути, и гард места правки отбивает её по чужому пути.

Отбитие это живое: за один заход оно пришло дважды уже после починки, на командах, где путь
разложенного файла стоял доводом запуска.

## Шесть вопросов

1. **Что меняется для владельца.** Заглушённый вывод перестаёт делать чтение записью.
2. **Где это живёт.** Помощник целей записи — источник пакета.
3. **Чем это подтверждается.** Набор гарда места правки и живой прогон помощника.
4. **Что из этого правило, а что код.** Только код помощника: статья домена о теле уже стоит.
5. **Чего работа не делает.** Не трогает настоящую запись рядом с заглушённым потоком — она
   остаётся видной, как и в основной части разбора.
6. **Где ветка.** `RT-1719-null-redirect-not-write`, каскадом от `RT-1718-prose-danniye-noun`.
