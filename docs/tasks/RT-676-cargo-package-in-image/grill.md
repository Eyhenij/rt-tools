# Разбор просьбы

## Просьба владельца дословно

> вмержил, обнови main и пости ветки, продолжай работу по эпику

## Что это значит здесь

Эпик — `docs/plans/agent-kit-observations.md`. Вторая его задача закрыта слиянием PR #694:
приёмник принимает груз, вход заведён, админка читает принятое тремя разделами. Следующей по
порядку стоит третья — узел, имя, TLS, выкатка, дамп.

Взята не она, а #676, и вот почему: третья задача выкатывает образ, а образ приёмника не
собирается вовсе. Проверено командой — `deploy/message-bus.Dockerfile` копирует `apps/message-bus`,
`libs`, `prisma`, `tools` и `eslint`, а каталог `projects/agent-kit` не копирует; при этом
`@rt-tools/agent-kit/cargo` зовут пять файлов серверной стороны. Выкатка отказала бы на первом
же прогоне, и разбирали бы это уже на арендованном узле.

## Вопросы и ответы

Владельцу задавался один вопрос — что брать следующим; остальное нашлось в документах и
вопросом не стало.

| Вопрос                                       | Ответ                                                                                                                                                                                                     |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Меняет ли задача поведение приложения        | Нет. Образ собирается тем же кодом; снаружи меняется только то, что он вообще собирается                                                                                                                  |
| Требует ли правки закона или правила         | Нет. Правило `git-workflow` уже требует, чтобы сборка входила в набор наравне с линтом и юнитами, — эта работа требование исполняет, а не меняет                                                          |
| Одна задача или несколько                    | Одна: копирование каталога в образ и место сборки образа в наборе откатываются вместе                                                                                                                     |
| Что в задачу не входит                       | Узел, имя, TLS, состав прода, дамп — третья задача линии. Образ админки — тоже: он заводится там, где заводится её отдача                                                                                 |
| Чем будет видно, что задача закрыта          | `docker build -f deploy/message-bus.Dockerfile .` проходит на чистом кэше, поднятый из образа приёмник отвечает пробой живости, а сборка образа стоит в конвейере и падает, если каталог снова потеряется |
| Есть ли образец, с которого снимается подход | Да — сам `deploy/message-bus.Dockerfile`: каталоги копируются поимённо, и новый встаёт тем же приёмом. Место в конвейере снимается с шага сквозного набора                                                |

## Решения по разбору

- **Узел о задаче не спрашивается.** Замысел линии его уже назвал — самый малый у DigitalOcean в
  Сингапуре, — и выкатка там объявлена запуском рабочего потока руками, а не следствием слияния.
- **Задача взята вперёд третьей.** Порядок в замысле линии её не знает: она заведена позже
  планирования, замеченным по ходу дефектом.
