## Что считается сделанным

- Пуш из дерева, чей набор гейта уже набора конвейера, отбивается, и отказ называет шаг, которого
  в наборе нет.
- Шаг конвейера, объявленный исключением с причиной, пуш не отбивает; исключение без причины —
  отбивает.
- Дерево объявило соответствие «шаг конвейера → строка гейта» и исключение на снимки витрин со
  ссылкой на задачу, которая его снимет.
- Три вида правила поставки несут статью о наборе гейта и статью о пересмотре набора после
  вливания главной ветки; три вида паттерна отчёта несут пункт о непрогнанном в разделе «Чем
  подтверждено» и о перечитывании состояния отчёта.
- `pnpm run agent-kit:check` зелен, `pnpm exec nx test @rt-tools/agent-kit` зелен, сценарии
  гардов зелены.

## Этапы

### 1. Договорённость о продукте

- **Что делается:** драфт спека `docs/specs/agent-kit/proposed/push-gate-scope/` — статьи о
  полноте набора гейта, о форме объявленного списка, о поведении на дереве без файла конвейера;
  сценарии на отбитый пуш, на объявленное исключение и на исключение без причины.
- **Признак готовности:** каждая статья отвечает на вопрос «что видно снаружи», сценарии имеют
  номера в общей нумерации домена.
- **Чем проверяется:** `pnpm run check:specs`.

### 2. Тексты слоя правил

- **Что делается:** статьи в `rules/git-workflow.github.md`, `.azure.md`, `.gitlab.md` — набор
  гейта не бывает уже набора конвейера; после вливания главной ветки набор пересматривается по
  тому, что ветка везёт теперь; утверждение о главной ветке делается по удалённой ссылке. Пункты
  в `patterns/git-workflow-commit.github.md`, `.azure.md`, `.gitlab.md` — раздел «Чем
  подтверждено» называет непрогнанное; состояние отчёта перечитывается перед тем, как что-либо о
  нём сказать.
- **Признак готовности:** три вида правила и три вида паттерна расходятся только тем, чем
  расходятся хостинги.
- **Чем проверяется:** `node tools/check-doc-paths.mjs`, `node tools/check-file-size.mjs`.

### 3. Механизм сверки

- **Что делается:** проверка в `assets/checks/` читает файл конвейера дерева, сличает его шаги с
  объявленным списком и краснеет на необъявленном шаге; шаг с причиной пропускается. Проверка
  встаёт в `rt_push_checks_default` — приезжает со своим местом, а не одним файлом.
- **Признак готовности:** на этом дереве проверка называет сборку и сверку собранных пакетов как
  недостающие, а снимки витрин — как объявленное исключение.
- **Чем проверяется:** прогон проверки на этом дереве до правки профиля и после неё; сценарий в
  `projects/agent-kit/tests/`.

### 4. Профиль дерева

- **Что делается:** `.claude/rt-kit/project.sh` — `rt_push_checks` дописывается сборкой и
  сверкой собранных пакетов; объявляется соответствие шагов и исключение на снимки витрин с
  причиной и номером задачи, которая его снимет.
- **Признак готовности:** проверка сверки на этом дереве зелена, гейт пуша гоняет пять строк.
- **Чем проверяется:** сценарии гардов и прогон гейта на своей же ветке.

### 5. Раскладка и сведение

- **Что делается:** сборка пакета, `sync`, сверка разложенного, приведение зеркал правил в
  `.claude/skills/` к пакетной редакции.
- **Признак готовности:** `pnpm run agent-kit:check` зелен, разложенное несёт новые статьи.
- **Чем проверяется:** `pnpm run agent-kit:check`, полный набор перед публикацией отчёта.

## Чего эта работа не делает

- **Не чинит ожидание кадров витрины.** Пока кадры ждут отсчётом времени, снимки в гейт не
  встают — это RT-427, и исключение снимается там же.
- **Не правит закон.** Статья о пустом выводе команды несётся владельцу текстом.
- **Не трогает механизм раскладки** — род дерева у ресурса, индекс, вывод `sync`: это RT-428.
- **Не правит правило ведения работы** — имя черновика папки задачи: это RT-429.
