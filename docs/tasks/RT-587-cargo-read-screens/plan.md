## Что считается сделанным

- Три раздела — разборы происшествий, предложения, сводки деревьев — открываются своими адресами,
  собраны одним и тем же списочным экраном и переживают перезагрузку страницы.
- Нажатие на строку открывает панель подробностей маршрутом в аутлете `ro`; закрытая панель
  возвращает список в том же состоянии.
- Выборка живёт в адресе: страница, размер, сортировка и отбор по дереву.
- Отбор по дереву называет деревья именами, а сужает признаком, и переживает переход по страницам.
- Список показывает чтение, пустоту по отбору, пустоту вовсе и отказ с повтором одним действием.
- Подписи экранов и подписи кита идут из словаря приложения.
- Пять компаньонов правил наполнены кодом: строки «предмета здесь нет» заменены привязками.
- Сквозной набор сценариев поднят и закрывает сценарии, чьё «Тогда» называет человека.
- Договорённость влита в `docs/specs/message-bus/spec.md` последним коммитом отчёта.
- `nx affected -t lint typecheck test build verify` зелёный, `npm run check:specs` не прибавил
  расхождений, конвейер на ветке зелёный.

## Этапы

### 1. Общий слой админки

- **Что делается:** словарь приложения и подписи киту; обращение к приёмнику с пределом ожидания
  и разбором отказа с номером обращения; типы выборки и её жизнь в адресе; общая основа
  списочного стора; общий компонент страницы списка; отбор по дереву.
- **Признак готовности:** основа собрана и покрыта спеками решений; ни один раздел ещё не
  заведён, но `nx build message-bus-admin` зелёный.
- **Чем проверяется:** спеки разбора выборки и стора, сборка, линт.

### 2. Раздел разборов происшествий

- **Что делается:** домен целиком — модели и маппер, обращение к операциям, стор, списочный
  экран, панель подробностей, пункт меню; раздел «Обзор» уходит.
- **Признак готовности:** раздел открывается прямой ссылкой, показывает страницы свежими сверху,
  нажатие на строку открывает панель с текстом разбора целиком.
- **Чем проверяется:** спеки домена, замер в браузере против поднятого приёмника.

### 3. Раздел предложений

- **Что делается:** тот же домен для предложений на той же основе; ничего своего, кроме моделей,
  столбцов и полей панели.
- **Признак готовности:** раздел собран той же основой — своей разметки списка в нём нет.
- **Чем проверяется:** спеки домена, замер в браузере.

### 4. Раздел сводок деревьев

- **Что делается:** то же для записей месяца; сводка показывается текстом, а не разметкой.
- **Признак готовности:** раздел собран той же основой; текст с разметкой внутри не исполняется.
- **Чем проверяется:** спеки домена, замер в браузере.

### 5. Сквозной набор сценариев

- **Что делается:** приложение сквозных спек, стенд из прод-сборки приёмника и админки, засев
  хранилища, спеки на сценарии, чьё «Тогда» называет человека.
- **Признак готовности:** набор проходит целиком на чистом хранилище; сценарии в договорённости
  перестают нести пометки «Не покрыто» и «Покрытие: частичное».
- **Чем проверяется:** прогон набора, сверка сценариев с заголовками спек.

### 6. Тексты и отчёт

- **Что делается:** компаньоны пяти правил наполняются кодом; договорённость вливается в спек
  домена; ход работы; отчёт со списком проверенного.
- **Признак готовности:** `npm run check:specs` без прибавленных расхождений, набор гейта зелёный
  целиком, конвейер на ветке зелёный.
- **Чем проверяется:** набор гейта, `check:docs`, `check:specs`, прогон конвейера.

## Чего эта работа не делает

- **Правок груза из админки** — приёмник принимает, админка читает.
- **Ролей и прав внутри админки** — слово владельца: вошедший видит всё.
- **Свода по нескольким деревьям и графиков** — слово владельца: назначается, когда деревьев
  станет три.
- **Узла, домена и сертификата** — задача #588.
- **Второй темы оформления и второго языка** — заводятся, когда их попросят.
