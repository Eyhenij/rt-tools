# Разбор просьбы

## Просьба владельца

Ночное распоряжение: брать в работу весь груз приёма, править самостоятельно, ветки держать
локально и ставить каскадом друг за другом.

## Записи груза

- `b48ef06c16dc1590f24fed01d16a80dbdc178020f02bb2a54e9ea977849379c2` — пакет нигде не говорит,
  откуда потребителю взять сам адрес приёма. Он назван один раз строкой таблицы «куда вписать», и
  ни `init`, ни `doctor`, ни один разложенный ресурс не называют ни примера, ни способа спросить.
  Исполнитель с готовым грузом и кодом приглашения на руках дважды упёрся в отказ и оба раза не
  смог сделать ничего, кроме как спросить владельца.

## Шесть вопросов

1. **Что меняется для владельца.** Дерево, ставящее пакет впервые, узнаёт, у кого спросить адрес,
   из самого пакета, а не из чужой памяти.
2. **Где это живёт.** README пакета и два отказа — приглашения и отправки.
3. **Чем это подтверждается.** Спеки пакета, проверки слога и адресов.
4. **Что из этого правило, а что код.** Текст README и тексты двух отказов.
5. **Чего работа не делает.** Адреса в пакет не вписывает: приём поднимает владелец, и у каждой
   мастерской он свой.
6. **Где ветка.** `RT-1706-intake-address-source`, каскадом от `RT-1705-unfilled-vars-not-drift`.
