## Что считается сделанным

- Порядок назван в правиле и в паттернах один: папка разбирается последним коммитом до
  открытия заявки.
- Открытие заявки с папкой задачи в ветке отбивается на месте, а не читается как промах потом.
- Правка по замечаниям разбора после уборки папки проходит: гард берёт признак не с диска.
- После следующей закрытой задачи в главной ветке папки нет.

## Этапы

### 1. Гард поставки отбивает открытие заявки при папке в ветке

- **Что делается:** к условиям открытия заявки добавляется папка задачи текущей ветки: есть в
  дереве или в истории ветки — отказ с командой разбора. Отказ копится вместе с прочими
  условиями поставки и печатается разом.
- **Признак готовности:** проба набора гардов красит открытие заявки при живой папке и
  пропускает при разобранной.
- **Чем проверяется:** `bash projects/agent-kit/tests/run.sh` — «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 2. Гард хода работы пропускает правку после разбора папки

- **Что делается:** гард получает четвёртый путь — папка задачи разобрана коммитом этой ветки.
  Тогда работа считается отданной, и правка по замечаниям разбора идёт без замысла на диске.
- **Признак готовности:** проба красит правку без папки и без коммита разбора, пропускает при
  коммите разбора в истории ветки.
- **Чем проверяется:** `bash projects/agent-kit/tests/run.sh` — «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 3. Гард снятия черновика и сверка очереди приведены к новому порядку

- **Что делается:** третье условие гарда снятия черновика («ветка не везёт папку своей
  задачи») при новом порядке верно с первой минуты заявки и готовность больше не отличает —
  снимается. Сверка очереди работ называет папку в ветке открытой заявки расхождением всегда,
  а не только после одобрения.
- **Признак готовности:** пробы обоих сходятся с новым порядком.
- **Чем проверяется:** `bash projects/agent-kit/tests/run.sh` — «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 4. Правило и паттерны называют один порядок

- **Что делается:** статья правила `task-flow` о порядке уборки переписывается; паттерны
  закрытия и разбора называют тот же порядок, включая готовые реплики владельцу. Правило
  `git-workflow` получает статью об условии открытия заявки.
- **Признак готовности:** ни один текст слоя правил не называет прежнего порядка.
- **Чем проверяется:** `npm run check:docs` — расхождений нет.

### 5. Раскладка сходится, набор гейта зелёный

- **Что делается:** пакет собирается, ресурсы раскладываются, гоняется весь набор гейта.
- **Признак готовности:** раскладка сходится, гейт зелёный.
- **Чем проверяется:** `pnpm run agent-kit:check` — «разложенное сходится с пакетом».

## Чего эта работа не делает

- Не трогает состояний работы: перечень остаётся прежним, меняется место одного шага в нём.
- Не заводит рубежа в конвейере: владелец выбрал держать порядок на месте, вызовом открытия
  заявки.
- Не выпускает новой редакции пакета — это отдельная работа, как та, что вышла редакцией 0.12.0.
