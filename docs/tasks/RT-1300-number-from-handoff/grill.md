# Разбор просьбы

Одна запись груза из приёма, соседнее дерево, ресурс `patterns/task-flow-resume.md`. Отметить
её этому дереву нечем: токен двигает только свои записи, работа при этом наша.

## Ловушка требует пересчёта только перед делением работы

> Ловушка требует пересчёта только тогда, когда на числе что-то делят. Число, которое просто
> переносится в текст, под неё не попадает: счёт строк из передачи прошлого захода лёг в разбор
> просьбы и в ход работы и разошёлся с деревом на восемь. Нашлось это сценарием подсчёта, а не
> чтением. Правило о формулировках говорит про число, которое пишут по замеру, и молчит про
> число, которое читают из передачи и из раздела «Где стоим».

Здесь ловушка написана тем же узким условием: «до того, как на нём что-то делят».

Владелец разбор не вёл: заход идёт самостоятельно, задачи берутся из приёма одна за другой.

## Что в работу не берётся

Проверки не заводится: передача лежит вне дерева, и сверить число из неё с деревом машине не
по чему — она не знает, что именно считали.
