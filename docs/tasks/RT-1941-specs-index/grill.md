# Grill

Задача эпика RT-1940. Замысел эпика — `docs/plans/intake-proposal-validation.md`.

## Просьба владельца

> агент работающий над пакетами rt-tools обязан иметь чёткое представление как должны работать все
> модули и пакеты, при поступлении новой жалобы или предложения — агент обязан сопоставлять факты
> из базы знаний о том как должно быть с тем что предлагается в жалобах и предложениях

## Что в дереве уже есть

- `docs/specs/agent-kit/` — двадцать с лишним поддоменов: раскладка, гарды, гейт правил, место
  правки, слог, границы пакета, приёмник, очередь работ. Это и есть база знаний: каждый поддомен
  говорит, как его предмет должен работать, и чем это подтверждено.
- `npm run check:specs` — сверяет статьи спек с привязками и сценарии с пробами. Он знает, что
  спека полна; он не знает, какая спека о каком ресурсе.
- Жалоба в приёмнике называет ресурс строкой «место»: `hooks/turn-exit-guard.sh`,
  `rules/task-flow.md`, `skills/agent-kit.md`.

## Что мешает

Между именем ресурса из жалобы и спекой, которая о нём говорит, нет связи. Заход ищет её
перебором: открывает поддомены подряд и читает. На двадцати поддоменах это дороже самого разбора,
и потому разбор идёт по памяти.

## Решения

- **Вход строится по привязкам, а не по новому списку.** Спутник каждого поддомена уже называет
  файлы ресурсов в привязках статей: `projects/agent-kit/assets/hooks/turn-exit-guard.sh:rt_te_deny`.
  Обратный указатель собирается из них. Цена ошибки: второй список разошёлся бы с привязками молча.
- **Указатель собирается командой, а не лежит файлом.** Файл устаревает при первой же новой спеке
  и врёт, не краснея. Цена ошибки: указатель, которому не верят, не читают.

## Что осталось неясным

- Ресурс, о котором не говорит ни одна спека, — законный случай или дыра. Ответ этой работы:
  команда называет такие ресурсы отдельной строкой, а решение о каждом принимает разбор жалобы.
