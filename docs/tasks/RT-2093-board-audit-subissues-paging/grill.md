# Grill

## Откуда взялась работа

Найдено при проверке очереди работ по ходу RT-2090. Владелец разрешил завести задачу словом
14 сентября 2026 года:

> заводи

## Что не так

Проверка очереди работ в каждом запуске печатает строку:

> #1870: the plan names tasks that are not sub-issues of the epic card — #2058, #2074, #2075,
> #2082, #2089, #2090

Все шесть привязаны. Проверено на месте:

- `gh api repos/Eyhenij/rt-tools/issues/1870/sub_issues --jq '[.[].number] | length'` — 30
- тот же вызов с `--paginate` — 36
- «недостающими» проверка называет ровно шесть последних номеров

Хостинг отдаёт список страницами по тридцать, а вызов идёт без пролистывания.

## Что дерево уже имеет

- Проверка подзадач лежит в источнике пакета правил, а в дереве — положенная копия с заголовком
  пакета.
- У проверки есть набор сценариев: 79 испытаний, из них два про подзадачи — SC-AK-1062.
- Помощник хостинга в наборе сценариев отвечает на любой вызов про подзадачи одним и тем же
  списком: пролистывание он не различает, поэтому поломку не видит.

## Чем это не видно сегодня

- Набор сценариев зелёный: его помощник не различает вызов с пролистыванием и без него.
- Строка проверки выглядит как обычное расхождение дерева, а не как поломка самой проверки.
- Цена не в строке, а в привычке: она висит всегда, глаз её перестаёт читать, и настоящее
  расхождение проедет мимо вместе с ней.

## Решения

- **Чинится вызов, а не дерево.** Привязки на месте — измерение сказало это числом.
- **Правится источник пакета, а не копия в дереве.** Копия несёт заголовок пакета: правка в ней
  теряется при следующей укладке.
- **Пролистывание добавляется одному вызову, на котором поломка измерена.** Сплошной пересмотр
  всех вызовов хостинга — работа своего объёма и своей задачи.
- **Помощник хостинга в наборе сценариев учится различать вызов с пролистыванием.** Иначе новый
  сценарий зелёный и на сломанном коде.
