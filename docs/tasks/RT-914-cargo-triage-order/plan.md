Читается дважды: до работы — чтобы снять с неё готовое, после — чтобы поправить устаревшее.
Команда сведения предложений говорит о грузе половину того, что скажет новое правило, и на
закрытии её текст сверяется с ним: два текста об одном не должны говорить разное.

## Что считается сделанным

- Правило разбора груза и паттерн при нём лежат в наборе ресурсов пакета и разложены в дерево;
  сверка раскладки расхождений не находит.
- Договорённость влита в новый поддомен `cargo` спека о пакете правил, директории `proposed/`
  после работы нет.
- Команда сведения предложений ссылается на правило и своей половины порядка больше не
  описывает.
- Порядком разобрана хотя бы одна настоящая запись груза: у неё стоит состояние, поставленное
  командой отметки, и ответ приёма это показывает.

## Этапы

### 1. Правило и паттерн в наборе ресурсов

- **Что делается:** пишется правило разбора груза под закон о ведении работы и паттерн при нём
  с готовыми вызовами команды отметки; в раскладку добавляются оба ресурса.
- **Признак готовности:** оба файла лежат в наборе, правило объявляет свой закон, паттерн —
  своё правило, и раскладка кладёт их в дерево.
- **Чем проверяется:** `pnpm run agent-kit:sync && pnpm run agent-kit:check` — сверка
  раскладки печатает, что расхождений нет.

### 2. Ссылка из команды сведения предложений

- **Что делается:** команда сведения перестаёт описывать порядок разбора груза своими словами и
  отсылает к правилу; остаётся при ней только то, чего в правиле нет, — деление пришедшего на
  повторившееся и разовое.
- **Признак готовности:** об одном предмете говорит один текст; слова о чтении груза и
  заведении задачи стоят в правиле, а не в двух местах.
- **Чем проверяется:** `npm run check:docs` — проверка путей в документах печатает, что
  расхождений нет.

### 3. Порядок прогоняется на живом грузе

- **Что делается:** по правилу разбирается настоящая запись груза — читается отбором, берётся в
  работу, отмечается командой пакета.
- **Признак готовности:** ответ команды называет переведённые записи, и приём отдаёт у записи
  новое состояние.
- **Чем проверяется:** `npx agent-kit mark --dry-run --state in_work --postmortem <файл>` —
  вывод показывает, что уехало бы; затем тот же вызов без сухого прогона, и его ответ называет
  число переведённых записей.

### 4. Вливание договорённости и разбор папки

- **Что делается:** договорённость переезжает в новый поддомен `cargo` спека домена, папка
  задачи разбирается, разбор просьбы уезжает в описание прошлого.
- **Признак готовности:** директории `proposed/cargo-triage/` нет, поддомен `cargo` стоит со
  своими тремя файлами, папки задачи в ветке нет, в описании прошлого прибыла запись.
- **Чем проверяется:** `npm run check:specs` — код возврата 0 и договорённости в списке
  «пора вливать» больше нет.

## Чего эта работа не делает

- **Не правит код приёмника и админки** — состояния, отбор, столбец, приём починки и версия
  выпуска готовы шестью задачами эпика.
- **Не разбирает двенадцать находок о слое правил** — они лежат в
  `docs/plans/intake-cargo-rules-findings.md` и читаются, когда эпик кончится, отдельным ходом
  с владельцем.
- **Не выпускает новую редакцию пакета** — это отдельное решение владельца.
- **Не проходит по 107 накопившимся записям груза** — работа описывает порядок; разбор по нему
  идёт следующей работой.
- **Не заводит состояния отказа и не требует правила гейтом** — оба оставлены открытыми
  вопросами договорённости.
