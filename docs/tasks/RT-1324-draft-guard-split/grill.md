# Разбор просьбы

Одна запись груза из приёма, соседнее дерево, ресурс `hooks/task-flow-guard.sh`. Отметить её
этому дереву нечем: токен двигает только свои записи, работа при этом наша.

## Гард везёт два требования в одном, и дерево теряет оба

> Гард требует в замысле строку `**Драфт:**` и каталог «предложено» в спеке — то есть вместе с
> проверкой «работа идёт по замыслу» навязывает способ записи договорённостей. Дереву, которое
> пишет договорённость прямо в спек, он останавливал бы каждую правку кода, поэтому не берётся
> вовсе — и вместе с ним не берётся единственная машинная проверка того, что у работы есть папка
> задачи.
>
> Разделённый надвое — «у работы есть папка задачи» отдельно от «договорённость лежит в каталоге
> предложено» — он встал бы и там, где вторая половина не подходит.

Соседней задачей той же ночи гард научился принимать второй вид договорённости — строку
`**Спек:**`, называющую спек домена. Это снимает половину повода. Вторая половина остаётся:
дерево, которому договорённость о продукте не нужна вовсе, по-прежнему отказывается от гарда
целиком и теряет вместе с ним требование папки задачи.

Владелец разбор не вёл: заход идёт самостоятельно, задачи берутся из приёма одна за другой.

## Что в работу не берётся

Ярус состояния работы из гарда не выносится: он судит переход, объявленный в самой папке, и
без папки задачи смысла не имеет — эти два требования разделить нечем.
