# Grill

## The owner request

> как сейчас назначается работа для каждого рабочего дерева? где описаны эпики и задачи которыми
> должны заниматься агенты в конкретном дереве?
>
> нужно записывать назначенный эпик для каждого рабочего дерева в одном файле, как это можно
> сделать?

Работа вне эпика — по этому слову владельца.

## Что в дереве уже есть

- Закон о ведении работ: назначение эпика принадлежит рабочей копии, а не ветке, и объявляется в
  главной ветке до создания первой задачи под новым эпиком.
- Спутник правила `task-flow` говорит, что в этом дереве запись лежит в `.claude/handoff/` вне
  истории и не проверяется ничем. Печатает её хук начала сессии из `.claude/settings.local.json`,
  тоже вне истории.
- В рабочей копии `rt-tools` файл `.claude/handoff/main-epic.md` называет эпик RT-907. Все семь его
  задач RT-908…RT-914 закрыты: назначение просрочено.
- Во второй рабочей копии хук на этот файл такой же, а самого файла нет: назначения нет вовсе.
- Ни одна проверка не спрашивает, чьё это дерево: проверка поставки судит принадлежность задачи
  эпику, аудит доски — связь карточек.

## Ответы владельца

- **Как строго держать:** запрещать чужой эпик и просрочку — отказ на создании ветки, заведении
  задачи и переносе карточки, если эпик не тот, строки для копии нет или назначенный эпик кончился.
- **Чем называть рабочую копию:** коротким именем в местном файле копии, а не путём и не веткой.
  Пути машины в репозиторий не пишутся.

## Решения

- **Файл назначений лежит в главной ветке, имя копии — вне истории.** Так требует закон: запись
  принадлежит копии и объявляется в главной ветке. Путь копии — состояние машины, его место рядом с
  местными значениями копии.
- **Просроченным считается назначение, у которого эпик закрыт или все задачи закрыты.** Именно этот
  случай сегодня и прошёл мимо: эпик RT-907 кончился, а строка осталась.
