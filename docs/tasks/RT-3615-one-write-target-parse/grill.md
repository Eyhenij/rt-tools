# Разбор

## Просьба владельца

> Ты … должен следить за зацеплением. Ты … должен следить за изолированностью кода, блоков, модулей

> доведи до прода 3600 и затем бери в работу 3603

Задача выросла из ревью RT-3608: проверка правил получила второй разбор цели записи.

## Что уже есть в дереве

- Общий разбор `rt_write_targets` лежит в `hooks/write-targets.sh`. Его зовут пять хуков: проверка места правки,
  экзамен, слог, атрибуты `qa-dataid`, вход по передаче.
- Второй разбор `rt_gate_is_target` лежит в `skill-gate.sh`. Он отвечает «да» или «нет» про один путь.
- Третий разбор `rt_overwrite_targets` лежит в `override-write-guard.sh`. Он отличает запись целиком от дописывания.
- Описание `edit-place` обещает: «The parse of write targets is declared once, and every guard that judges an
  edit calls it». Второй и третий разборы это обещание нарушают.
- Признак записи `rt_shell_writes` и пути `rt_shell_paths` лежат в `defaults/shell.sh`. Они отвечают на другой
  вопрос: пишет ли команда вообще и какие пути она называет. Проверка правил входит в суд по первому и берёт пути
  у второго, поэтому `>|`, `sed` и `perl` с `;`, копия в папку и путь с пробелом до неё не доходят.

## Что измерено

Черновик, который режет команду на слова, отвечает верно на 125 формах, прежние 29 случаев разбора зелёные. На
3000 настоящих командах ответ нынешнего разбора и черновика один у 2825. В 175 расхождениях ушли пути чтения и
обрывки слов, пришли настоящие цели; ложная пришла одна форма, `/.test` из кода в теле.

| Форма | Сейчас | Черновик |
| --- | --- | --- |
| `printf x >\| a/b.sh` | молчит | `a/b.sh` |
| `sed -E -i '' 's/a/b/' a/b.sh` | молчит | `a/b.sh` |
| `sed -i '' 's/a;b/c/' a/b.sh && node x.mjs` | `x.mjs` | `a/b.sh` |
| `perl -pi -e … a/b.sh` | молчит | `a/b.sh` |
| `node x.mjs && grep -e 'mkdir a/b.sh' c.sh` | `a/b.sh` | молчит |
| `sed -i -e … a/b.sh # note` | `note` | `a/b.sh` |
| `tee -a b/c.md d/e.md` | `b/c.md` | оба |
| `cp a \` и `b/c.sh` на новой строке | `\` | `b/c.sh` |
| `(cd x && printf a > y/z.sh)` | `y/z.sh)` | `y/z.sh` |
| путь с пробелом в кавычках | молчит | путь целиком |

## Что уже говорят правила

- `code-design`: решение живёт в одном модуле; модуль с двумя обязанностями режется.
- `testing`: проверка, пропускающая действие, пропускает его и при сломанном разборе.

## Вопросы и ответы

Новых вопросов владельцу нет: план эпика одобрен 24.11, строка задачи стоит в его составе.

## Решения

- **Команда режется на слова посимвольно, а не подстановками.** Довод: каждая из форм таблицы — это граница
  слова, кавычки или команды, и подстановка видит её только случайно. Отклонено: дописать пять выражений в `sed`:
  `;` внутри кавычек и `&&` они не различают.
- **Разбор слов — отдельный модуль рядом с общим.** Довод: у файла `write-targets.sh` появилась бы вторая
  обязанность; сейчас в нём 270 строк.
- **Код в аргументе толкователя судится теми же функциями, что тело heredoc.** Довод: второй копии признаков
  записи не появляется.
- **Проверка правил берёт цели у общего разбора по самой команде.** Довод: признак записи и список путей
  новых форм не видят. Тело толкователя, которое пишет файл модуля, получает слои наравне с перенаправлением.
- **Проверка переопределений тоже спрашивает общий разбор.** Довод: разбор помечает запись целиком и дописывание
  разными знаками, и третья копия не нужна.
- **Набор отказывает на втором разборе под любым именем.** Довод: обещание одного разбора уже нарушено дважды.

## Решения, пересмотренные после чтения плана ролями

- **Ветвь проверки правил переписана.** Замена одной функции не дала бы правила ни на одну новую форму: до
  сравнения они не доходят.
- **Случаев стало 125 вместо 24.** Роли нашли потерянные `git mv`, `sudo -u`, `bash -euo pipefail -c`, подстановку
  внутри вызова и ложную цель в документе рядом с `node`. Каждая форма названа в плане и в имени случая.
- **Число зацепления проверки переопределений исправлено:** исходящих 5, а не 8.

## Что осталось неясным

- Нет.
