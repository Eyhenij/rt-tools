## Что считается сделанным

- Оператор чата — запись в хранилище, и состав его сайтов читается из своей таблицы чата.
- Список переписок читается страницами с отбором по сайту и по состоянию, и сайты, где оператор
  не состоит, в ответ не попадают вовсе.
- Сообщения одной переписки читаются страницами.
- Состояние переписки меняется операцией, и смена видна в списке отбором.
- Сценарии `SC-CH-15` и дальше закрыты пробами или несут пометку с причиной.

## Этапы

### 1. Договорённость о чтении оператором

- **Что делается:** описание в `docs/specs/chat/proposed/operator-reading/` — кто такой оператор
  чата, чем он представляется, что он видит, какие состояния у переписки и какими кодами отвечает
  отказ; сценарии к нему.
- **Признак готовности:** сверка спек не называет по новому описанию ни пропущенного раздела, ни
  занятого номера сценария.
- **Проверяется:** `node tools/check-specs.mjs` — ни строки про `docs/specs/chat`.

### 2. Записи оператора и состояния переписки

- **Что делается:** записи оператора и его сайтов в схеме, состояние переписки, миграция к ним.
- **Признак готовности:** цепь миграций накатывается начисто, и сравнение схемы с накатанной
  базой не находит разницы.
- **Проверяется:** `node tools/check-schema-drift.mjs` — «the migrations and the schema match».

### 3. Три операции оператора и пробы к ним

- **Что делается:** чтение списка переписок страницами с отбором, чтение сообщений переписки
  страницами и смена состояния переписки; отбор страниц берётся готовым — `pageAsked`,
  `pageSkip`, `IPage`, — а не пишется заново. Пробы с двойником хранилища.
- **Признак готовности:** пробы домена зелёные, и сверка спек не называет ни одного сценария
  `SC-CH` без пробы.
- **Проверяется:** `pnpm exec nx run-many -t test -p message-bus-api-chat-feature message-bus-api-chat-util message-bus-api-chat-data-access`
  — «Successfully ran target test», и `node tools/check-specs.mjs` — нулевой код.

### 4. Договорённость вливается, набор перед отправкой и PR

- **Что делается:** описание переезжает в спеку домена вместе с привязками, папка задачи
  разбирается записью в `docs/archive/`, набор перед отправкой прогоняется целиком, PR
  открывается в ветку задачи RT-2178 готовым.
- **Признак готовности:** набор перед отправкой зелёный, сквозной набор админки зелёный, PR
  открыт с рецензентом.
- **Проверяется:** `pnpm exec nx run message-bus-admin-e2e:e2e` — «133 passed» и больше;
  `gh pr view <номер> --json isDraft,reviewRequests` — черновика нет, рецензент назван.

## Чего эта работа не делает

- **Поток событий, панель оператора, виджет, извещения и выкатка** — задачи RT-2180 … RT-2184.
- **Своя дверь входа для оператора чата.** План эпика её не обещал; запись оператора называет
  учётную запись приёмника, и отдельный вход — работа сверх плана, по слову владельца.
- **Ответ оператора посетителю.** Реплику оператора принимает панель, и это задача RT-2181.
- **Заведение операторов и сайтов человеком.** Пока они заводятся прямой записью в хранилище:
  экрана для них нет до панели.
