  в отказе конца хода. Поиск удалившего коммита вынесен в `removedAt` источника истории: RT-3425
  правит его там.
- **Новые случаи — в отдельном наборе `task-flow-script-archive.test.sh`.** Набор шагов уже 486
  строк при пределе 500 для кода.
- **Очистка прерванного запуска лежит в `task-flow-script.mjs`, как называет след плана.** В
  `flow-step.mjs` она подняла файл до 534 строк при пределе 500; после переноса — 492.
- **Шаг, не повторённый вторым прогоном, теряет отметку после одного несовпадения.** Это шаг за
  пределом 540 с или группа, не начатая в бюджете 1500 с: перемер не может его повторить, и PR
  отказан всё равно.
- **Первый круг ревью: подтверждено и исправлено.** Лишний файл в возвращённой папке оставлял её и
  возвращал тупик — папка теперь убирается целиком. Второй запуск при живом первом мерил чужой ход
  работы и снимал отметку — теперь отказан, отметка цела. Обрыв посреди возврата оставлял неполную
  папку навсегда — отсутствующий файл считается своим, отпечаток пишется до текста. Отказанный
  второй прогон сохранял отметку — теперь остаётся первое несовпадение. Второй прогон группы
  начинается, только если её самый долгий первый прогон помещается в бюджет. Папка у вершины
  больше не «возвращается» из старого коммита. Хук открытия PR называет номера шагов вместо
  `step N.M`. `step --done` на разобранной папке меряет шаги, как перемер. После хода отката отказ
  конца хода называет номер шага. У конвейера `… | grep -c` под строкой шага видны строки провала
  до последней команды. Номер, которого план не знает, отказан без хода отката. Ход отката назван
  только для правки внутри папки.
- **Примитивы возврата папки — в источнике истории `git.mjs`.** В `flow-step.mjs` они не
  помещались в 500 строк, а новый модуль `flow-*.mjs` проверка шагов откажет: след плана его не
  называет. `git.mjs` есть в следе.
- **Суждение конца хода в наборе — настоящий `verdict` на копии описания без шести первых
  состояний.** Так ветка стоит в «этап-идёт» без хостинга.
- **Первый круг: не исправлено, с причиной.** После хода отката измеритель разбора папки считает
  выполненным старый коммит разбора — тупика нет, отказ открытия PR по папке называет свой ход.
  Окно, в котором `git add -A` вернёт возвращённую папку в историю, — время одной проверки; число
  процесса без времени старта; поле состояния в наблюдении отказа; `step` из подкаталога — записаны
  находками эпика. Откат разбора может столкнуться с убранной по сроку записью архива — запись
  архива живёт неделю, откат идёт в тот же день.
- **Форматирование пакета.** `projects/agent-kit/assets/` стоит в `.prettierignore`; запуск
  prettier из каталога пакета этого файла не видит и переформатировал четыре файла. Текст
  возвращён из разложенных копий, которые синхронизация сделала до форматирования.
- **Второй круг ревью: подтверждено и исправлено.** `tee` перед последней трубой ломал `case`,
  `((`, кавычку с обратной косой и `PIPESTATUS` — теперь ставится только перед замыкающим `grep`.
  `step --done` во время живого запуска мерил чужой ход работы — отказан. Оставленную папку
  молчаливый старт хука снимал с учёта — запись помечается оставленной, шаг на ней называет её.
  Папка у вершины давала ложное «уберите руками» — запись снимается молча. Лишний файл в
  разобранной папке отключал возврат — шаг отказан с его именем. Отказ «папка отличается» на
  возвращённой папке не называл хода — теперь называет откат. Второй прогон мог выйти за время хука
  — бюджет считает ушедшее время, предел второго прогона — остаток. Суждение конца хода читало
  историю вне этапа — только в «этап-идёт»; шаг плана без строки в ходе работы считается
  несделанным. Правила пакета запрещали собирать папку снова — добавлено исключение отката.
  Хук без несовпавших шагов давал общий ход — теперь «причина в строках выше». У проверки шагов в
  наборе появилась пара: ручная отметка отказана.
- **Второй круг: не исправлено, с причиной.** Повтор числа процесса, учёт старого коммита разбора
  после отката, окно незакоммиченной папки и `step` из подкаталога — уже записаны находками эпика.
  Слабые проверки шагов плана не правятся: план после одобрения не меняется.
