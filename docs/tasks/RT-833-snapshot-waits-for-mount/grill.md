# Разбор просьбы

## Просьба владельца

> смотри конфликты в твоих пр, сейчас ни один пр не может быть вмержен - это либо драфты либо
> конфликты? где результат твоей работы за 2 дня? ни один пр не готов!

Сказано после того, как четыре PR простояли открытыми: у одного был конфликт с главной веткой,
остальные ждали зелёного прогона. Разведка показала, что прогон валит один и тот же шаг —
снимки второй витрины, — и что причина у всех веток одна.

## Что уже есть в дереве

- **Обвязка снимков** — `projects/ui-kit-v2/.storybook/test-runner.ts`: ждёт шрифты, набор
  значков, глушит движение и добирает отсчётом в 150 мс.
- **Показ редактора** — `projects/ui-kit-v2/src/lib/components/rich-editor/stories/`: Quill
  приезжает динамическим импортом после первой отрисовки, и это записано в комментарии обёртки.
- **Правило** — `.claude/skills/testing/SKILL.md`: «Лечится ожиданием события, а не удлинением
  отсчёта: … положение узла не менялось два кадра подряд».

## Замер до правки

Прогон `pnpm run test:visual:v2 'rich-editor'` на своей машине: один упавший снимок,
`Components/RichEditor › Toolbar` — кадр 1248×109 при эталоне 1248×291. То же самое в трёх
прогонах конвейера на трёх разных ветках.

## Решения

- **Эталон не пересъёмывается.** Он снят с показа, который успел встать; пересъёмка узаконила
  бы пустой кадр и сняла бы историю с учёта навсегда.
- **Ожидание идёт по событию, а не по времени.** Удлинение отсчёта делает исход прогона
  зависящим от загрузки машины — это и есть то, чем прогон уже болеет.

## Шесть обязательных вопросов

Владельцу не задавались: работа взята по прямому слову о том, что ни один PR не готов, и
предмет её — обвязка проверки, а не поведение продукта. Вопрос, который потребовал бы ответа —
пересъёмывать эталон или чинить ожидание, — закрыт правилом проверяемости дерева.
