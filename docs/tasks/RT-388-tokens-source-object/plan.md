## Что считается сделанным

- Все объявления трёх слоёв оформления живут в одном узле — `projects/ui-kit-v2/src/styles/tokens.source.mjs`; ступень светлой темы и её тёмный ответ стоят рядом, а не в разных файлах.
- Три `.scss` слоя оформления пишет генератор, и каждый несёт шапку «правится генератором, не здесь».
- Значения токенов в собранном `tokens.css` те же, что до переноса: сверка имён и значений даёт пустой список расхождений.
- `pnpm run check:tokens-build` красный, если собранное разошлось с источником, и зелёный, когда совпадает.
- Ссылка на имя, которого в источнике нет и которое не названо ручкой потребителя, роняет генерацию, и ни один собранный файл при этом не переписывается (`SC-UKV-51`).
- Пакет отдаёт тип имени токена и перечень имён; оба собраны тем же генератором.
- `check:tokens-graph`, `check:tokens-theme`, `check:tokens-styles`, `check:cascade-layer`, `lint:styles` зелёные; 447 эталонных снимков зелёные без пересъёмки.
- Договорённость `docs/specs/ui-kit-v2/proposed/design-tokens/` влита в спек домена, каталог `proposed/` снят, номера сценариев не менялись.

## Этапы

### 1. Источник

- **Что делается:** сегодняшние объявления трёх слоёв разбираются в узел `projects/ui-kit-v2/src/styles/tokens.source.mjs` — группы с их комментариями, имя, значение, комментарий у строки, пометка общего цвета для обеих тем и тёмный ответ рядом со светлым назначением.
- **Признак готовности:** в источнике 437 объявлений — 163 ступени шкалы, 213 назначений светлой темы, 61 ответ тёмной; ни одна прозаическая записка из трёх файлов не потеряна.
- **Чем проверяется:** счёт объявлений в источнике против счёта в сегодняшних файлах; `git diff` по прозе читается глазами.

### 2. Генератор

- **Что делается:** `tools/build-tokens-v2.mjs` пишет из источника `_primitives.scss`, `_semantic.scss` и `_theme-dark.scss` с шапкой «правится генератором»; нетокеновый хвост тёмной темы — правила `.rt-logo` и подложка обвязки — переезжает в рукописный `_theme-dark-rules.scss`, который форвардит `_index.scss`.
- **Признак готовности:** `pnpm run build:tokens-v2` собирает `tokens.css`; порядок подслоёв, миксины `rt-theme-light-tokens` и `rt-theme-dark-tokens`, включение на `:root` и блок `@media (pointer: coarse)` стоят на прежних местах.
- **Чем проверяется:** `pnpm run build:tokens-v2` зелёный, `pnpm run lint:styles` зелёный.

### 3. Сверка значений

- **Что делается:** собранный `tokens.css` сверяется с тем, что давало дерево до переноса: имена и их значения в обеих темах.
- **Признак готовности:** список расхождений пуст.
- **Чем проверяется:** сборка `tokens.css` из главной ветки и из ветки задачи, сравнение разбором объявлений; расхождение считается дефектом переноса, а не правкой вида.

### 4. Гейт

- **Что делается:** `tools/check-tokens-build.mjs` и команда `check:tokens-build` — пересобирает слой в память и сверяет с файлами на диске; генератор отказывает на ссылке в никуда и файлов не пишет.
- **Признак готовности:** подложенная правка в собранном файле роняет гейт с именем файла; подложенная опечатка в имени роняет генерацию, и файлы на диске остаются прежними.
- **Чем проверяется:** обе подложки прогоняются руками, обе красные, после отката — зелено.

### 5. Типы

- **Что делается:** генератор пишет третий выход — тип-объединение имён токенов и константу со списком; файл экспортируется из `projects/ui-kit-v2/src/public-api.ts`.

## Чего эта работа не делает

- **Свойства компонента — третий слой.** `--rt-btn-*`, `--rt-input-*` и прочие в тринадцати файлах компонентов остаются рукописными: они живут рядом со своими правилами.
- **Уборка пятидесяти неупотребляемых имён.** Переезжают в источник как есть; их разбор — соседняя работа.
- **Первый кит.** Ни его токены, ни его проверки не трогаются; девять общих имён остаются в списке принятого.
- **Чужая библиотека токенов и связь с Фигмой.** Ни зависимостью, ни источником не становятся.
- **Девять имён, общих у двух китов** — задача RT-391.
