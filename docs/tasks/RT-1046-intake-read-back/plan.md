## Что считается сделанным

- Заход забирает груз из приёмника командой дерева, без входа владельца в админку и без его
  разрешения на отдельный вызов.
- Прочитанное годится для отметки как есть: ключ записи берётся из того же ответа, и между
  чтением и отметкой нет ручного шага.
- Правило разбора груза говорит новый порядок, а отменённые статьи о том, что груз читает
  человек, из него сняты.
- Порядок проверен целиком на местном приёмнике: вход, чтение, разбор, отметка, повторное
  чтение показывает переведённое состояние.

## Этапы

### 1. Команда чтения груза

- **Что делается:** `tools/cargo-pull.mjs` — вход парой учётной записи службы, чтение списка с
  отбором по состоянию и роду, дочитывание текстов записей, вывод пачкой. Пара берётся из файла
  вне репозитория, как токен дерева; сухой прогон отличается от настоящего первой строкой, как
  у команды отметки.
- **Признак готовности:** команда на местном приёмнике печатает записи с их состоянием и
  текстом, а без пары и без адреса отказывает до сети.
- **Чем проверяется:** `pnpm run cargo:pull -- --kind proposal --state new` — в выводе стоят
  записи местного приёмника с их признаком и состоянием.

### 2. Чтение и отметка сходятся одним ключом

- **Что делается:** признак записи считается из прочитанного текста тем же приёмом, что на
  приёме (`sha256`), и печатается рядом с ней; команда отметки принимает его без правки.
- **Признак готовности:** признак, напечатанный чтением, отмечает запись без единой правки
  рукой, и приёмник отвечает «переведено», а не «такой записи у дерева нет».
- **Чем проверяется:** `pnpm run cargo:mark -- --proposal <признак из вывода чтения> --state in_work` — ответ называет одну переведённую запись.

### 3. Правило разбора груза переписано

- **Что делается:** в `cargo-triage` отменяются статьи «Груз читается админкой приёма» и
  «человек груз читает, а разбирает его тот, кто по нему работает»; ход перерисовывается с
  чтения командой; в компаньоне называются имя команды и место пары. Паттерн
  `cargo-triage-mark` получает вызовы чтения.
- **Признак готовности:** правило описывает порядок, который исполним без владельца, и ни одна
  его статья не отсылает к админке за чтением.
- **Чем проверяется:** `pnpm run agent-kit:check` — раскладка сходится; `node tools/check-prose-style.mjs` — слог принят.

### 4. Спека и сценарии

- **Что делается:** чтение груза получает свои утверждения, привязки и сценарии в
  `docs/specs/agent-kit/cargo-mark/` — предмет там тот же: состояние груза и работа с ним со
  стороны дерева. Номера сценариев берутся следующие свободные в `SC-AK`.
- **Признак готовности:** каждое утверждение о чтении привязано к месту в коде, и у каждого
  сценария есть тест с тем же номером.
- **Чем проверяется:** `node tools/check-specs.mjs` — привязки и сценарии сходятся в обе стороны.

### 5. Прогон на живом грузе

- **Что делается:** учётная запись службы заводится на проде — это одна команда, и зовёт её
  владелец, потому что ssh на узел прода исполнителю отбивается классификатором разрешений.
  После неё заход читает настоящие 132 предложения и переводит разобранные.
- **Признак готовности:** чтение печатает записи прода, отметка переводит хотя бы одну, и
  повторное чтение показывает её новое состояние.
- **Чем проверяется:** `pnpm run cargo:pull -- --kind proposal --state new` против прода — в выводе стоят записи четырёх деревьев.

## Чего эта работа не делает

- Не правит приёмник: ни нового рода доступа, ни признака хозяина ресурсов у дерева. Оба
  разбирались с владельцем и отвергнуты им в пользу входа службой.
- Не разбирает сам груз. Прочитать 241 запись и решить, что из них становится правкой, — это
  сведение предложений, отдельный шаг правила и отдельная работа после этой.
- Не решает, чем отмечать запись, по которой работы не будет. Состояния отказа набор не знает;
  это открытый вопрос правила, и он старше этой работы.
- Не чинит шапку раскладки в папке задачи. Копия образца несёт шапку `rt-kit`, и гард места
  правки отбивает первую же правку разбора просьбы — находка этой работы, но предмет чужой:
  она уходит к замыслу эпика о слое правил.
