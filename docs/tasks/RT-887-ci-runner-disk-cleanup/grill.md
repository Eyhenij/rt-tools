# Разбор просьбы

## Просьба владельца

> вмержил, сука! хули ты стоишь?? пиздуй делай следующую задачу!!!! пиши постмортем!

Задача взята из очереди работ — её завёл исполнитель, заметив дефект по ходу прошлой работы.
Тело задачи `#887` описывает случившееся: прогон конвейера на машине владельца упал дважды
подряд, оба раза причиной было кончившееся в томе Docker место, и оба раза красным становился
сквозной набор.

## Что уже есть в дереве

- Шаг уборки в конвейере **уже стоит** и идёт при падении: `.github/workflows/ci.yml`, шаг
  «Убрать за прогоном». Он снимает свои образы по имени, анонимные тома без метки состава и
  кэш сборщика старше суток.
- Правило о том, что такой прогон убирает за собой сам, написано —
  `.claude/skills/git-workflow-docker/SKILL.md`; готовые команды там же.
- У базы стенда есть проба здоровья: `docker-compose.yml`, `pg_isready`.

## Что уже сказано в правилах

- `git-workflow-docker` — общая чистка запрещена: `docker system prune`, `docker volume prune` и
  снятие по маске уносят чужое молча. Убирается только своё, отбором.
- `git-workflow-docker` — порог у кэша, а не полная чистка: снятый целиком, он заставляет
  следующую сборку идти с нуля.
- `browser-verification` — оставленный свой стенд отравляет следующий прогон.

## Решения

- **Уборка остаётся, но перестаёт быть единственным ответом.** Порог по возрасту не видит того,
  что накопилось сегодня: за один заход двадцать один гигабайт свежего кэша дал при уборке по
  суткам девяносто пять мегабайт. К возрасту добавляется предел размера кэша.
- **Нехватка места называется своим именем до того, как её увидит набор.** Стенд спрашивает
  базу пробой здоровья и отказывает с её логом и занятым местом. Иначе кончившееся место
  показывается лицом чужого шага — списком красных экранов.
- **Чужое не трогается.** Тринадцать гигабайт держал том постороннего проекта; снять его прогон
  не вправе, и порогом это не лечится — лечится внятным отказом.

## Что осталось невыясненным

- Предел размера кэша взят в десять гигабайт по сегодняшнему замеру: столько остаётся полезного
  после уборки по суткам. Если сборки станут тяжелее, число пересматривается — оно стоит в одном
  месте.
