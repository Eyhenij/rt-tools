## Что считается сделанным

- Правило приложения той же специфичности, объявленное вне слоя, выигрывает у правила кита —
  подтверждено замером `getComputedStyle` в браузере на странице витрины.
- Слой объявлен двумя подслоями в порядке `rt-kit.base, rt-kit.components`; объявления
  `:root { --rt-* }` остались вне слоя, и перекраска бренда работает по-прежнему.
- Файл стилей кита без `@layer` роняет прогон проверки; на подложенном нарушении она красная.
- Обоих `!important` в `rt-table.component.scss` больше нет.
- README кита и страница витрины называют слой, порядок подслоёв и то, что кит больше не
  настаивает на своём важностью.
- 447 эталонных снимков зелёные, кроме нового кадра страницы слоя.
- Записка о переходе называет обе видимые перемены: правило кита теперь проигрывает правилу
  приложения, и карточный вид таблицы у форсящих ширину поедет.
- Пакет выпущен в npm с поднятой версией.

## Этапы

### 1. Слой объявлен, основа обёрнута

- **Что делается:** в `_index.scss` объявляется порядок `@layer rt-kit.base, rt-kit.components;`;
  рисующие правила основы — `_scrollbar.scss`, `_login.scss`, стили директивы кнопки — уходят в
  `rt-kit.base`. Объявления `:root` в `_primitives.scss`, `_semantic.scss` и `_theme-dark.scss`
  остаются вне слоя.
- **Признак готовности:** собранный `tokens.css` содержит объявление порядка первой строкой, а
  объявления свойств — вне блоков `@layer`.
- **Чем проверяется:** `pnpm run build:tokens-v2` и чтение собранного файла.

### 2. Стили компонентов обёрнуты

- **Что делается:** содержимое каждого из 87 файлов `src/lib/**/*.scss` уходит в
  `@layer rt-kit.components { … }`. Правка сценарием, а не по файлу: сценарий считает
  совпадения и отказывается писать при промахе.
- **Признак готовности:** ни одного файла стилей кита без обёртки; вид не изменился.
- **Чем проверяется:** `pnpm run lint:styles`, `pnpm exec nx run @rt-tools/ui-kit-v2:build`,
  прогон эталонов витрины.

### 3. Обходы важностью сняты

- **Что делается:** `min-width: 0 !important` и `min-inline-size: 0 !important` в
  `rt-table.component.scss` снимаются вместе с комментариями, которые их объясняли.
- **Признак готовности:** `!important` в стилях второго кита не осталось.
- **Чем проверяется:** поиск по набору, прогон эталонов таблицы.

### 4. Гейт слоя и надстройка правила

- **Что делается:** заводится проверка «файл стилей кита объявлен в слое» со своим именем
  команды и своим списком принятого; раздел о слое каскада дописывается в
  `.claude/rt-kit/overrides/rules/styling-bem.md`.
- **Признак готовности:** проверка красная на подложенном файле без `@layer` и зелёная на
  дереве; правило называет слой, порядок подслоёв и то, что новый файл заводится обёрнутым.
- **Чем проверяется:** прогон проверки на подложенном нарушении и на чистом дереве.

### 5. Страница витрины и замер

- **Что делается:** история уровня основ рядом с `component-props.stories.ts`: кнопка кита под
  правилом приложения той же специфичности, объявленным вне слоя.
- **Признак готовности:** страница показывает победу правила приложения; замер в браузере
  называет вычисленные значения по обе стороны.
- **Чем проверяется:** `getComputedStyle` на поднятой витрине, новый эталонный кадр.

### 6. Тексты кита, версия и записка о переходе

- **Что делается:** README, `Overview.mdx` и `Theming.mdx` называют слой и порядок подслоёв;
  `CHANGELOG.md` получает записку о переходе с обеими видимыми переменами; версия в
  `package.json` поднимается.
- **Признак готовности:** потребитель, читающий только тексты кита, знает, что изменилось и
  что делать с прежним перебиванием специфичностью.
- **Чем проверяется:** `npm run check:docs`, чтение владельцем на разборе.

### 7. Выпуск пакета

- **Что делается:** после слияния пакет выкатывается в npm выпускающим прогоном.
- **Признак готовности:** опубликованная версия ставится и несёт слой.
- **Чем проверяется:** установка опубликованной версии и чтение её `styles/tokens.css`.
