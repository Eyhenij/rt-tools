# Grill

## Просьба владельца

> Сверка очереди работ делит карточки на задачи и груз по метке. Карточка с меткой груза не
> судится как задача вовсе — ни по исполнителю, ни по доске, ни по связи с эпиком, ни по
> совпадению заголовков.
>
> Дерево при этом ставит эту метку и на задачи, выросшие из груза: так помечены полтора десятка
> карточек, из них две открыты сегодня. Заголовок у них обычный — `[RT-<номер>] <что не так>`, — и
> по определению самой сверки это задачи.
>
> Что из этого выходит: две открытые задачи невидимы для всей задачной половины сверки, а заявка о
> них даёт ложную строку «задачи нет среди открытых — у задачи одна ветка». Настоящее расхождение
> — задача без исполнителя, задача не на доске, две задачи об одном — по такой карточке не
> найдётся никогда.
>
> Где смотреть: `check-board.github.mjs` — отбор `open` по `CARGO_LABELS`. Груз узнаётся по метке,
> а задача — по заголовку с номером; карточка с обоими признаками сегодня читается как груз. Файл
> разложен из пакета правил, значит правка делается там.
>
> Метка груза на эту задачу намеренно не ставится: с ней задача была бы невидима той самой сверке,
> о которой она заведена.
>
> Найдено при закрытии RT-1910.

## Что в дереве уже есть

- `projects/agent-kit/assets/checks/check-board.github.mjs` — отбор `open`: из открытых карточек
  убираются все, несущие любую метку из `CARGO_LABELS`. Комментарий над отбором говорит, что так
  задумано: помеченная запись не судится как задача ни в одной половине.
- Настройка дерева называет меткой груза `agent-kit-feedback`.
- Список карточек с этой меткой: полтора десятка, из них открыты `#1910` и `#1913`, у обеих
  заголовок вида `[RT-<номер>]` и назначенный исполнитель. Закрытые задачи с той же меткой —
  `#951`, `#914`, `#903`, `#902`, `#901`, `#900`, `#899`, `#898`, `#897` и другие.
- `npm run check:board` даёт строку «PR #1914: the task #1910 is not among the open ones» — заявка
  о задаче, которую сверка не видит.
- Настоящий груз в очереди — записи вида «предложение: rules/lists.md»: заголовка с номером у них
  нет.
- `projects/agent-kit/assets/checks/board.github.mjs` — `numberFromTitle`: номер по заголовку.
  Обе стороны сверки уже зовут его, отдельного разбора заголовка заводить не надо.

## Что уже говорят правила

- `git-workflow` — задача в очереди зовётся `[<КЛЮЧ>-<номер>] <что не так>`; заголовок и есть
  признак задачи, а метки на ней те же, что и на заявке.
- `cargo-triage` — груз приходит приёмом и разбирается здесь; запись груза заголовка с номером не
  несёт.

## Решения

- **Задача узнаётся по заголовку с номером, а метка груза при нём не считается** — груз и задача
  различаются тем, чем их различает само дерево, а не одной меткой. Отклонено: снять метку с
  карточек — она стоит на полутора десятках задач намеренно и говорит читателю, откуда работа
  выросла.
- **Настоящий груз по-прежнему узнаётся по метке** — заголовка с номером у него нет, и отбор для
  него не меняется.

## Что осталось неясным

- Карточка с меткой груза и с заголовком задачи может оказаться грузом, которому заголовок
  переписали при разборе. Такой карточки в дереве нет: разбор груза заводит отдельную задачу, а
  запись груза оставляет как была.
