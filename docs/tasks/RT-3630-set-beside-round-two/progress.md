## Решения по ходу

Уточнения из третьего чтения плана (блокирующих и серьёзных находок нет):

- У образца строки «Без записей» нет конца строки: равенство трёх чисел сверяется глазами при записи.

Уточнения из четвёртого чтения свежими ролями (блокирующих нет, серьёзная одна, у обеих про снятие):

- Снятие идёт так: список потомков запуска снимается до сигнала, группе шлётся `INT`, ожидание, затем `TERM`,
  ожидание до 30 секунд, и только потом `KILL` оставшимся из списка. Замер ролей: `TERM` с `KILL` через 5 секунд
  оставляет 89 процессов сценариев в своей группе, без раннего `KILL` nx убирает их сам за 6 секунд; Playwright
  гасит стенд только по `INT`.
- Сценарий снятия получает ребёнка в своей группе: родитель убирает его по сигналу за несколько секунд.
  Мутант «сразу `KILL`» и мутант «без `INT`» его роняют.
- Строка «Снятый набор» пишет число потомков запуска и занятых портов, замер идёт на шаге `nx affected` и
  отдельно на шаге сквозных.
- Мутантов в «сделано» пять: строка «Мутанты» пишется не меньше чем «5 из 5». Строка «Повторный набор»
  называет код 0 и шаги `= green already`.

По ходу кода:

- Список путей грязной копии отдаёт новая функция `rt_push_mark_dirt` в `git-guard-push-marks.sh`: второй
  список исключений в запуске разошёлся бы с первым.
- Шаг получает пустой ввод: прежний вызов отдавал ему список оставшихся шагов.
- Секунды ожидания после `INT` правит `RT_PUSH_STOP_WAIT`; сценарии ставят 1 и 4.
- Номера сценариев до 1973 заняты ветками RT-3603 и RT-3615, взяты 1980–1983.
