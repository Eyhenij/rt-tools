# Разбор

## Просьба владельца

> сейчас рабочий процесс занимает слишком много времени, довольно простые правки идут по несколько часов, сделай анализ на какие шаги сколько времени уходит по текущему task flow и как можно оптимизировать весь процесс

На вопрос «Завести эпик на ускорение процесса?» — «Да, заводи». План эпика одобрен вариантом «Без П5
(Recommended)».

25.11.2026, на вопрос «Какую задачу эпика RT-3624 беру следующей?» — «RT-3629 (Recommended)». Описание
выбранного: «Сначала RT-3629 и RT-3630, потом RT-3627».

Карточка #3630: «Набор ждёт конца второго круга, хотя круг часто ничего не меняет в коде: 8–15 минут на
ветку. Готово, когда набор запускается вместе со вторым кругом, и круг без правок не запускает его второй
раз».

## Что уже есть в дереве

- Порядок держит одно правило дерева — `task-delivery-loop`: «The push set runs once per branch, after the
  last round». Кода, который держал бы этот порядок, нет: запуск — вызов исполнителя.
- Набор вперёд пишет отметку на каждый зелёный шаг. Ключ отметки — строка шага, дерево вершины и коммит
  базы. У шагов сборщика, снимков, сквозных и сборок образов пути задачи, плана и архива из ключа
  исключены (`rt_push_check_unread`), поэтому их отметки переживают коммит хода работы.
- Шаг `bash tools/tests/run.sh` из ключа эти пути не исключает. На RT-3629 после коммита архива он пошёл
  второй раз: 85 секунд, ещё около 30 — лёгкие проверки текстов.
- Пока набор идёт, копию трогать нельзя: отметка пишется только на чистой копии и на том же дереве. Запуск
  об этом не говорит. Он гонит шаги дальше по смешанному содержимому, не пишет отметок и кончает словами
  «the set is green, the push passes from the marks» с кодом 0. Это ложное зелёное; сейчас его прячет
  порядок «набор один, после всех правок».
- Правки второго круга почти всегда трогают код. Из 57 последних вторых кругов с 19.11 без правок вне
  папки задачи, плана и архива прошли 6, с правкой одних тестов — 7, с правкой кода или правил — 44.
- Второй круг ждут 9 минут (медиана 21 ветки), от набора до PR — 25.
- Шаг `nx affected -t lint typecheck test build` кэширует ответы по проектам: второй запуск после правки
  одного проекта платит только за него. Шаг сценариев защит `test-hooks` и съёмка кэша не имеют.
- `session:time --steps` уже считает запуск, начатый внутри второго круга: доставка начинается с конца круга.
- Рамка круга в `task-delivery-loop-run` запрещает ревьюеру git и правку файлов, сборку и браузер — нет.

## Что говорят правила

- `task-delivery-loop-run`: «A heavy run goes alone and in the background», «the showcase frames fall with
  ECONNRESET beside the tests of the packages». Съёмка рядом со сборкой ревьюера краснеет не по делу.
- `agent-kit-source`: «Nothing builds the package while the push set runs».
- Закон `verifiability`: проверка, которая не нашла, с чем сверять, не считается прошедшей. Запуск, чья
  копия сменилась, не зелёный.
- Спека `docs/specs/agent-kit/push-gate-ahead/`: «A mark is not written when the tree changed while the
  check ran»; про слова и код такого запуска она молчит.

## Вопросы и ответы

**Меняет ли это прежнее слово владельца?** Да, порядок «набор после последнего круга» из RT-3408. Его меняет
сама карточка, одобренная с планом эпика. Число кругов и состав набора не меняются.

## Решения

- **Набор запускается тем же сообщением, что и роли второго круга** — по закрытым текстам, со влитой базой
  и с удалёнными записями архива старше недели. Иначе круг без правок всё равно оставляет набору новое
  содержимое.
- **Второго круга нет — набор идёт сразу после правок первого**, как сейчас. На лёгком пути ждать нечего.
- **Нашлось, что править, — набор снимается до первой правки.** Отметки шагов, прошедших до этого, остаются
  и живут там, где правка их ключа не задела.
- **Запуск, под которым сменилась копия, кончает кодом 101 и называет, что сменилось.** Код 3 уже занят
  «не начат», а красный набор кончает числом красных, не больше 100. Грязная копия
  останавливает его сразу: ни один следующий шаг отметки не получит. Отвергнуто: запуск в отдельной
  копии — ей нужны свои `node_modules`, ветка и база, а строка шага несёт имя базы по ветке.
- **Ревьюер рядом с набором не собирает, не открывает браузер и в копию не пишет.** Одиночный сценарий или
  тест в своей временной папке разрешён.
- **Шаг `tools/tests/run.sh` не читает папок задач, планов и архива** — доказывается запуском без них.

## Что осталось неясным

- Выигрыш. Круг без правок — 6 из 57, у него снимается ожидание круга, 9 минут. У остальных 51 ни одна
  отметка правок не переживает, остаётся кэш `nx` и раннее красное. Ключ по предмету шага отвергнут:
  приёмник берёт исходник пакета правил, а съёмка идёт в наборе последней.
- Кэш ответов сценариев защит сократил бы второй запуск у правок правил. Здесь его нет: это новый
  механизм, не порядок шагов.
