## Что считается сделанным

- Заголовок сценария, который выражение не разобрало, назван расхождением, а не пропущен молча.
- Адрес привязки берёт имя файла без расширения — то, чем объявлены описание образа и конфиг.
- Живость символа считается по не-тестам: символ, зовомый только тестом, краснеет своим текстом.
- Строка корней процедур, в которой нет ни путей, ни слова «нет», — отказ, а не пустой список.
- Право процедуры читается по коду без пояснений, как это уже делает разбор привязок.
- В законе о проверяемости стоят две статьи: о проверке, не нашедшей предмета, и об объявлении,
  которое читают текстом.
- В правиле описаний стоят две статьи: тест вызовом не считается; вердикт по невозможности
  записи отличается от вердикта по существу.
- Ветка карты проверок берёт помощников аудита описаний, а не только файл с приставкой `check-`.
- Записи груза, закрытые этой правкой, помечены в приёмнике сделанными.

## Этапы

### 1. Разбор описаний перестаёт молчать на неразобранном

- **Что делается:** заголовок сценария, не взятый выражением, и строка корней процедур без путей
  и без слова «нет» становятся расхождениями; адрес привязки принимает имя файла без расширения
- **Признак готовности:** каждый из трёх случаев называется отдельной строкой с файлом и номером
  строки, а прежние разобранные случаи проходят как раньше
- **Проверено:** `npm run check:specs` — прежние домены зелёные, счёт сценариев сходится с числом
  заголовков в файлах

### 2. Живость привязки считается без тестов

- **Что делается:** владельцы символа помнятся с признаком «тест»; второй владелец считается
  только по не-тестам, а символ, зовомый лишь тестом, получает своё сообщение
- **Признак готовности:** привязка на функцию, зовомую только из теста, краснеет с текстом про
  тест; после появления вызова из приложения зеленеет
- **Проверено:** `bash projects/agent-kit/tests/run.sh` — пробы аудита описаний зелёные

### 3. Право процедуры читается по коду

- **Что делается:** объявление права разбирается без пояснений — тем же приёмом, что разбор
  привязок; образец вызова в пояснении рядом с настоящей меткой её не подменяет
- **Признак готовности:** право, стоящее только в пояснении, в аудит не попадает
- **Проверено:** `bash projects/agent-kit/tests/run.sh` — проба на пояснение рядом с меткой

### 4. Статьи закона и правила

- **Что делается:** две статьи в закон о проверяемости, две в правило описаний, привязки к ним в
  файле привязок дерева
- **Признак готовности:** аудит описаний не называет ни статьи без адреса, ни адреса без статьи
- **Проверено:** `npm run check:specs` — расхождений по слою правил нет

### 5. Карта проверок берёт помощников аудита описаний

- **Что делается:** ветка карты принимает `spec-*.mjs` рядом с `check-specs.mjs`
- **Признак готовности:** правка помощника требует то же правило, что правка самой проверки
- **Проверено:** `bash projects/agent-kit/tests/run.sh` — пробы карты гейта зелёные

### 6. Установка файлов из пакета и пометки в приёмнике

- **Что делается:** пакет собирается и раскладывается, девять записей груза помечаются сделанными
  с указанием, чем закрыты
- **Признак готовности:** аудит установки молчит, записи в приёмнике стоят в состоянии «сделано»
- **Проверено:** `pnpm run agent-kit:check` — расхождений нет

## Чего работа не делает

- Не трогает порядок сдачи и черновик: это задача #2038 и она ждёт слова владельца.
- Не заводит описаний ресурсам, у которых их нет: задачи #1981—#1986.
- Не правит проверки дерева, не относящиеся к аудиту описаний: задача #2034.
