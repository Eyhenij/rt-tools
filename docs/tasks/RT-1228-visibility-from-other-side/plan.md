## След задачи

Ограниченная учётная запись видит своё всегда. Ответ хостинга на «завелось ли» приходит той же
записи, которая заводила, и для неё заведённое есть; тому, для кого оно заводилось, хостинг
отвечает «не найдено». С заводящей стороны оба ответа выглядят успехом.

Второй признак того же ограничения — предел запросов: у ограниченной записи он не исчерпан, а
равен нулю. Отказ по нему — единственный ранний сигнал, и обойдённый вызовом другого рода он
уносит сигнал с собой.

| Что   | Где                                                      |
| ----- | -------------------------------------------------------- |
| Код   | `projects/agent-kit/assets/rules/git-workflow.github.md` |
| Спеки | `docs/specs/agent-kit/texts/`                            |

## Что считается сделанным

- Правило говорит, что видимость заведённого проверяется той стороной, которой оно
  предназначено.
- Правило говорит, что отказ читается прежде, чем его обходят вторым способом.
- Числа обоих случаев лежат в холодной части, а не при статьях.

## Этапы

### 1. Статья о видимости заведённого

- **Что делается:** рядом со статьёй об учётной записи машинной работы встаёт статья о том, что
  видимость проверяется другой стороной.
- **Признак готовности:** статья называет, чем ответ заводящей стороны отличается от
  подтверждения.
- **Чем проверяется:** `node tools/check-file-size.mjs` — предел веса текста не взят.

### 2. Статья об отказе, который собрались обойти

- **Что делается:** встаёт статья о том, что отказ читается прежде обхода, и о нуле в ответе о
  пределах как о признаке ограничения.
- **Признак готовности:** статья разводит «сегодня исчерпали» и «этой записи не положено».
- **Чем проверяется:** `node tools/check-prose-style.mjs` — слог сходится.

### 3. Пакет собран, разложен, сверен

- **Что делается:** числа обоих случаев уезжают в холодную часть, пакет собирается и
  раскладывается, статьи получают адреса в компаньоне.
- **Признак готовности:** разложенное сходится с пакетом, статей без адреса нет.
- **Чем проверяется:** `npm run agent-kit:check` и `npm run check:specs`.

## Чего эта работа не делает

- Не заводит гарда: чем токен читал ответ, машине в самом ответе не видно.
- Не трогает права учётной записи дерева: это решение владельца, а не правка правила.
