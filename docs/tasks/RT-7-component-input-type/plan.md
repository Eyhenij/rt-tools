## Что считается сделанным

- Есть тип набора входов, выводящий имена и принимаемые значения из класса компонента.
- Чужое имя, обычное поле класса и значение не того типа отбиваются сборкой.
- Есть функция, ставящая такой набор созданному компоненту.
- Место, где входы ставились строками, переведено на неё.

## Этапы

### 1. Тип и функция установки

- **Что делается:** пишется `projects/core/src/lib/types/component-inputs.ts` — отбор входов по
  типу поля, вывод принимаемого значения, функция установки; имена вывозятся из пакета.
- **Признак готовности:** пакет собирается, тип виден снаружи.
- **Чем проверяется:** `pnpm exec nx build @rt-tools/core` — сборка без отказов.

### 2. Спека на четыре сценария

- **Что делается:** `component-inputs.spec.ts` — три проверки типов пометками ожидаемой ошибки и
  одна живая: поставленные входы доезжают до компонента.
- **Признак готовности:** четыре сценария зелёные, а пометки ожидаемой ошибки не гаснут.
- **Чем проверяется:** `pnpm exec nx test @rt-tools/core` и `pnpm exec nx typecheck @rt-tools/core` — оба без отказов.

### 3. Место употребления

- **Что делается:** директива подтверждения второго кита переводится со строк на набор.
- **Признак готовности:** входы ставятся одним вызовом, поведение прежнее.
- **Чем проверяется:** `pnpm exec nx test @rt-tools/ui-kit-v2 --testFile=projects/ui-kit-v2/src/lib/components/confirm-popover/rt-confirm.directive.spec.ts` — прогон без провалов.

## Чего эта работа не делает

- Типизации выходов: подписка на них живёт своей жизнью.
- Перевода обвязки спек второго кита: она принимает набор «имя — что угодно» и этим удобна.
