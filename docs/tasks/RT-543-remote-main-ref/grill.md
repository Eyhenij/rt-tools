# Разбор просьбы

## Просьба владельца

> бери остальные задачи одну за другой начиная с самой свежей, работай локально и не пуш ветки
> в репозиторий, работай полностью автономно … создавай новую ветку от предыдущей каскадом

Тело работы — карточка RT-543 «Закрытие захода судит по отставшей локальной главной ветке».
Повод у неё свой: три предложения, приехавших грузом от дерева-потребителя.

## Что уже есть в дереве

- `projects/agent-kit/assets/commands/next-session.md` — команда закрытия захода; шаг 4 зовёт
  `git switch <главная> && git pull --ff-only`, шаг 5 считает влитость от локальной главной.
- `projects/agent-kit/assets/rules/git-workflow.{github,gitlab,azure}.md` — три редакции правила
  поставки; статья об утверждении по удалённой ссылке стоит во всех трёх.
- Статья говорит только про утверждение — про то, что называют владельцу; про действие молчит.

## Что уже сказано в правилах

«Утверждение о главной ветке делается по удалённой ссылке, а не по локальной» — есть. Что
подтягивание, счёт влитого и выбор основания новой ветки берут её же, не сказано нигде.

## Вопросы и ответы

Вопросов владельцу не задавалось: заход автономный.

## Решения

- **Локальная главная двигается без перехода на неё** — `git fetch origin <главная>:<главная>`.
  Рабочее дерево не трогается, и шаг исполним при незакоммиченном, которое команда сама шагом
  раньше велела не трогать. Отвергнуто: `switch` с последующим `pull` — он и отбивался.
- **Счёт влитого судится от `origin/<главная>`.** Смешивать удалённую ссылку для одной стороны и
  локальную для другой нельзя: промах изнутри выглядит верным.
- **Статья дописывается во все три редакции.** Непрочитанная редакция судится наравне с
  выбранной — так велит закон о документации.

## Что осталось невыясненным

- Проверки на то, что команда читает локальную главную, нет: текст команды никто не грепает.
