## Что считается сделанным

- `git-workflow` говорит о ветке эпика: откуда ветвится задача, куда идёт её заявка, когда
  открывается заявка эпика и в каком порядке эпик вливается.
- `task-flow` называет состояния эпика наравне с состояниями задачи: пока эпик не заведён, задачи
  из него не берутся.
- Паттерны поставки показывают команды нового порядка, а не ветку от главной.
- Компаньоны этого дерева называют его имена: ветка эпика, основание заявки, кто вливает.
- Пробы набора пакета зелёные, `pnpm run agent-kit:check` и `node tools/check-specs.mjs` без
  расхождений.

## Этапы

### 1. Правило поставки говорит о ветке эпика

- **Что делается:** в `git-workflow` статьи о ветке от главной и о заявке в главную переписаны
  под эпик; таблица имён получает строку об эпике и его ветке.
- **Признак готовности:** в правиле не осталось статьи, по которой ветка задачи законно стоит на
  главной, и приём стопки не спорит с веткой эпика.
- **Проверяется:** чтение правила целиком, `bash projects/agent-kit/tests/run.sh`.

### 2. Состояния работы знают эпик

- **Что делается:** в `task-flow` таблица состояний получает состояния эпика — эпик заведён и
  его задачи кончились, — и статью о том, что задача берётся только из заведённого эпика.
- **Признак готовности:** по таблице состояний видно, где заводится ветка эпика и где открывается
  его заявка.
- **Проверяется:** чтение правила, пробы набора.

### 3. Паттерны показывают команды нового порядка

- **Что делается:** `git-workflow-commit`, `-pr`, `-stack`, `-merge` получают ветку эпика:
  команда ветвления, основание заявки, порядок вливания эпика.
- **Признак готовности:** ни в одном паттерне не осталось готовой команды, ведущей задачу мимо
  ветки эпика.
- **Проверяется:** поиск по паттернам, пробы набора.

### 4. Компаньоны дерева и тексты

- **Что делается:** компаньоны `git-workflow` и `task-flow` называют имена этого дерева;
  раскладка, спека подобласти и привязки.
- **Признак готовности:** `pnpm run agent-kit:check` и `node tools/check-specs.mjs` без
  расхождений.
- **Проверяется:** обе команды и `bash projects/agent-kit/tests/run.sh`.

## Чего эта работа не делает

- Не правит команду заведения задачи — это #1924.
- Не правит гард поставки — #1925 — и сверку очереди — #1926: до них правила говорят о порядке,
  которого ещё никто не держит, и это законное состояние.
- Не переводит на новый порядок уже открытые заявки.
