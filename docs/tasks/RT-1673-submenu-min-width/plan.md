## Что считается сделанным

- Тяга влево не делает панель уже ширины, заданной оформлением.
- Тяга вправо расширяет панель, как прежде, и её выбор переживает перезагрузку.
- Нижний предел не назван числом в коде кита: он берётся из того же свойства, каким потребитель
  задаёт ширину.

## Этапы

### 1. Ширина панели считается наибольшим из заданного и натянутого

- **Что делается:** тяга пишет своё свойство, а ширина панели и позиция полосы считаются
  наибольшим из ширины оформления и натянутой.
- **Признак готовности:** замер в браузере — тяга влево оставляет ширину равной заданной
  оформлением, тяга вправо её увеличивает.
- **Чем проверяется:** `pnpm exec nx test @rt-tools/ui-kit --testFile=src/lib/ui-kit/side-menu/menu/rtui-side-menu.component.spec.ts` — тесты меню зелёные.

### 2. Дерево осталось зелёным

- **Что делается:** прогон тестов кита и линтера стилей.
- **Признак готовности:** прогоны зелёные.
- **Чем проверяется:** `pnpm run check:tokens-styles` — вывод без строк расхождения.

## Чего эта работа не делает

- Не трогает верхнего предела тяги.
- Не заводит своего умолчания ширины в ките: её задаёт потребитель.
