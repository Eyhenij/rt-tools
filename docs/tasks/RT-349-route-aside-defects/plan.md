# Замысел

Задача: #349. Ветка: `RT-349-route-aside-defects`.

**Задача:** RT-349 · **Ветка:** RT-349-route-aside-defects
**Драфт:** `docs/specs/ui-kit-v2/proposed/route-aside-leave/`
**Поведение:** меняется

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## Что считается сделанным

- Панель с гардом правок и тронутой формой после удачной записи с `closeOnSuccess` уходит с
  адреса, и окно о правках не открывается ни разу.
- Раскладка «маршрут с компонентом → уровень без компонента с `providers` → ro-маршрут»:
  уход по `openRelated()` доходит, `TypeError` не возникает, а при тронутой форме о правках
  спрашивают панель, стоящую на экране.
- Гард ни при одном входе не отвечает отказом навигации: панель, чужой компонент, `null`,
  компонент без метода, упавший поток ответа.
- Разрешение на уход съедается ровно одной навигацией; навигация, отклонённая роутером,
  разрешения не оставляет.
- Учёт отвечает за маршрут, с которого идёт уход: две панели двух контейнеров под именем
  аутлета `ro` не путаются, одна панель за одну навигацию не спрашивается дважды.
- `pnpm run check:specs` зелёный, непокрытых сценариев домена нет, `proposed/` в главную ветку
  не уезжает.
- Починка доехала до npm минорной версией, и оба воспроизведения из разбора сняты замером на
  приложении-потребителе, а не пересказаны.

## Этапы

### 1. Договорённость доведена до непротиворечивой

- **Что делается:** двенадцать находок состязательного разбора закрываются правкой
  `docs/specs/ui-kit-v2/proposed/route-aside-leave/`: запасной путь через компонент от роутера
  назван правилом, учёт переписан на ключ-маршрут вместо «отвечает вставшая последней», названы
  выдача и снятие разрешения, место жительства учёта, границы «на экране», состояние «идёт
  запись», повтор ухода, упавший ответ панели, два контейнера на экране.
- **Признак готовности:** в спеке не осталось открытых вопросов, влияющих на код; у каждой
  строки таблицы состояний есть своё правило и свой сценарий.
- **Чем проверяется:** `pnpm run check:specs`.

### 2. Учёт панелей, ключуемый маршрутом ухода

- **Что делается:** новая корневая служба рядом с `rt-container-state.service.ts`; запись
  ключуется маршрутом панели, ответ ищется сверкой со снимком маршрута, с которого идёт уход;
  снятие на уничтожении. `RtContainerStateService` не трогается — она поставляется на уровне
  компонента, и гард до неё не дотянется.
- **Признак готовности:** спека службы закрывает постановку, снятие, ответ по маршруту, две
  панели двух контейнеров под одним именем аутлета, пустой учёт.
- **Чем проверяется:** `pnpm exec nx test @rt-tools/ui-kit-v2 --testFile=<спека службы>`.

### 3. Гард спрашивает учтённую панель

- **Что делается:** `rt-route-aside.guard.ts` берёт ответ у панели, учтённой под маршрутом
  ухода; при пустом учёте падает на аргумент роутера с проверкой, что метод есть; иначе уход
  разрешён. Комментарий гарда переписывается — сегодня он описывает соседний случай.
- **Признак готовности:** ни при одном входе гард не отдаёт ошибку, и это видно спекой.
- **Чем проверяется:** спека гарда, включая падающий поток ответа.

### 4. Разрешение на уход, привязанное к навигации панели

- **Что делается:** разрешение выдаётся перед вызовом роутера в `#navigateAway()` и
  `#navigateRelated()` — тем самым накрывает закрытие после записи, уход на связанную запись,
  уход при ненайденной записи и рефетч; `canDeactivate()` читает и съедает его до
  `#closeIntent()`; итог обещания навигации снимает невостребованное разрешение.
- **Признак готовности:** отклонённая роутером навигация разрешения не оставляет — следующий
  уход со стороны при тронутой форме открывает окно о правках.
- **Чем проверяется:** спека базового класса, падающая на откате правки.

### 5. Повтор ухода и уход во время записи

- **Что делается:** одновременные вызовы гарда получают одно окно о правках и один ответ;
  уход при идущей записи отменяется молча, как сейчас, но записывается правилом и закрывается
  спекой; порядок «разрешение старше признака записи» назван.
- **Признак готовности:** два вызова гарда подряд при тронутой форме дают одно окно и один
  ответ, второго оверлея нет.
- **Чем проверяется:** спека узла.

### 6. Покрытие сценариев и полный прогон

- **Что делается:** каждый сценарий домена стоит в заголовке спеки, `CONTEXT.md` узла
  переписан под новый учёт, гоняются обязательные проверки.
- **Признак готовности:** непокрытых сценариев нет, проверки зелёные.
- **Чем проверяется:** `pnpm run check:specs`, `pnpm exec nx affected -t lint typecheck test`,
  `pnpm run lint:styles`.

### 7. Договорённость влита в спек домена

- **Что делается:** текст `proposed/route-aside-leave` вливается в спек домена последним
  коммитом отчёта, директория удаляется, номера сценариев не меняются, привязки правил ставятся
  на живые символы.
- **Признак готовности:** `proposed/` в главную ветку не уезжает.
- **Чем проверяется:** `pnpm run check:specs` после удаления.

### 8. Версия опубликована и проверена у потребителя

- **Что делается:** после вливания — публикация `@rt-tools/ui-kit-v2` минорной версией и
  проверка обоих воспроизведений из разбора на приложении-потребителе.
- **Признак готовности:** новая версия видна в реестре; на потребителе запись с
  `closeOnSuccess` закрывает панель без окна о правках, ссылка на связанную запись уводит с
  чистой консолью, при тронутой форме вопрос о правках задан.
- **Чем проверяется:** замер в браузере, а не пересказ.

## Чего эта работа не делает

- Не переделывает окно о несохранённых правках и три его исхода — правятся только условия, при
  которых оно открывается.
- Не правит первый кит (`projects/ui-kit`): этого кода он не держит.
- Не правит приложение-потребитель: чужое дерево правится не отсюда.
- Не заводит роутерную спеку с раскладкой маршрутов: после перехода на учёт гард на обход
  деактивации Angular не опирается, и такая спека проверяла бы чужой код.
- Не разбирает папку задачи #318, въехавшую в главную ветку неразобранной, — это отдельная
  уборка.
