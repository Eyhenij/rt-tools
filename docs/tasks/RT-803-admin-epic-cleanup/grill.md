# Разбор просьбы

## Просьба владельца

Дословно, частью реплики; остальная её часть завела задачу RT-801.

> по текущему состояни эпика с переделкой фронта админки - напиши подробный handloff и опиши
> текущий статус в документации задач по эпику

## Что установлено до первого вопроса

Разведка шла командами по удалённой ссылке, а не по локальной.

- Эпик — задача RT-779 с меткой `epic`; замысел лежит в `docs/plans/admin-ui-to-reference.md`.
- Первая задача эпика, RT-780, влита: PR #791, коммит слияния `25ddd39d`, задача закрыта.
- Уборки после неё не было: в главной ветке лежат `docs/tasks/RT-780-list-page-slots/` и
  `docs/specs/message-bus/proposed/list-page-slots/`. Строки обхода `Task-folder-skip` в теле PR
  нет — значит папка уехала не по объявленному исключению.
- `pnpm run check:specs` называет договорённость готовой к вливанию: сценарии закрыты тестами.
- Остальные задачи эпика — RT-781, RT-782, RT-783, RT-784 — открыты и не начаты, ветвей у них
  нет.
- Замысел эпика говорит, что эпик делает и в каком порядке, но не говорит, где эпик стоит:
  раздела о состоянии в нём нет вовсе. Узнать это можно только обходом задач в очереди работ.

## Решения

- **Уборка за RT-780 и состояние эпика — одна работа.** Обе правки об одном: эпик двинулся на
  задачу вперёд, а следов этого нет ни в главной ветке, ни в замысле. Откатывать их порознь
  незачем.
- **Состояние пишется в замысел эпика, а не в папку задачи.** Папка умирает со слиянием, а
  эпик её переживает — правило работы говорит об этом прямо.
- **Вливание договорённости идёт тем же движением.** Она готова, и `check:specs` называет её
  готовой; оставленная в `proposed/`, она через месяц читается как незакрытая работа.
