## След задачи

Статья о конце прогона говорит про один прогон: фоновая команда возвращает исполнителя к работе
сама. Про серию она молчит, и уведомление на каждый шаг ей не противоречит — а именно оно и
назначает замеру столько ходов, сколько у него шагов. Наполнить их нечем: дерево под серией
трогать нельзя, работы в ходе нет, и ход кончается пересказом того, что придёт следующей строкой.

| Что   | Где                                               |
| ----- | ------------------------------------------------- |
| Код   | `projects/agent-kit/assets/rules/turn-conduct.md` |
| Спеки | `docs/specs/agent-kit/texts/`                     |

## Что считается сделанным

- Правило говорит, что у замера из многих шагов ставится одно ожидание, кончающееся вместе с
  замером.
- Правило называет, где уведомление на событие уместно: там, где на каждое событие надо
  действовать.

## Этапы

### 1. Статья об ожидании своего замера

- **Что делается:** рядом со статьёй о конце прогона встаёт статья о серии.
- **Признак готовности:** статья разводит «надо действовать на каждое событие» и «значим только
  итог».
- **Чем проверяется:** `node tools/check-prose-style.mjs` — слог сходится.

### 2. Привязка статьи в компаньоне

- **Что делается:** статья получает адрес в компаньоне правила.
- **Признак готовности:** статей без адреса нет.
- **Чем проверяется:** `npm run check:specs` — код 0.

### 3. Пакет собран, разложен, сверен

- **Что делается:** сборка, раскладка, сверка.
- **Признак готовности:** разложенное сходится с пакетом.
- **Чем проверяется:** `npm run agent-kit:check`.

## Чего эта работа не делает

- Не трогает стража выходов: он судит последнее действие хода и о числе ожиданий не знает.
