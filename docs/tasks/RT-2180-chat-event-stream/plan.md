## Что считается сделанным

- Новая реплика доходит до открытого экрана без обновления страницы: и до виджета посетителя, и
  до панели оператора.
- Подписка виджета закрыта признаком посетителя, подписка панели — входом человека, и чужих
  событий ни одна не получает.
- Оборвавшаяся подписка восстанавливается, и пропущенное добирается по времени последней реплики.
- Сценарии `SC-CH-28` и дальше закрыты пробами или несут пометку с причиной.

## Этапы

### 1. Договорённость о потоке событий

- **Что делается:** описание в `docs/specs/chat/proposed/event-stream/` — что за события, чем
  закрыта каждая подписка, что приходит при обрыве и как добирается пропущенное; сценарии к нему.
- **Признак готовности:** сверка спек не называет по новому описанию ни пропущенного раздела, ни
  занятого номера сценария.
- **Проверяется:** `node tools/check-specs.mjs` — ни строки про пропущенный раздел.

### 2. Разбор событий и подписчики

- **Что делается:** чистые решения слоя утилит — что считать пропущенным по времени последней
  реплики и как выглядит событие; служба подписчиков в памяти приложения.
- **Признак готовности:** пробы слоя утилит и службы зелёные.
- **Проверяется:** `pnpm exec nx run-many -t test -p message-bus-api-chat-util message-bus-api-chat-feature`
  — «Successfully ran target test».

### 3. Две подписки и пробы к ним

- **Что делается:** поток для виджета по признаку посетителя и поток для панели по входу
  человека; приём реплики и ответ оператора шлют событие подписчикам.
- **Признак готовности:** пробы домена зелёные, и сверка спек не называет ни одного сценария
  `SC-CH` без пробы.
- **Проверяется:** `node tools/check-specs.mjs` — нулевой код.

### 4. Договорённость вливается, набор перед отправкой и PR

- **Что делается:** описание переезжает в спеку домена вместе с привязками, папка задачи
  разбирается записью в `docs/archive/`, набор перед отправкой прогоняется целиком, PR
  открывается в ветку эпика готовым.
- **Признак готовности:** набор перед отправкой зелёный, сквозной набор админки зелёный, PR
  открыт с рецензентом.
- **Проверяется:** `pnpm exec nx run message-bus-admin-e2e:e2e` — «133 passed» и больше;
  `gh pr view <номер> --json isDraft,reviewRequests` — черновика нет, рецензент назван.

## Чего эта работа не делает

- **Панель оператора, виджет, извещения и выкатка** — задачи RT-2181 … RT-2184.
- **Ответ оператора посетителю.** Его принимает панель, задача RT-2181; поток только разносит
  событие о нём.
- **Общая шина событий между процессами.** Приёмник поднят одним процессом, и вторая служба ради
  подписчиков стоила бы денег там, где их держат как можно ниже.
