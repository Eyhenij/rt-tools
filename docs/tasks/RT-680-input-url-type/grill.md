# Разбор просьбы

## Просьба владельца

Задача заведена владельцем карточкой в очереди работ. Дословно:

> [RT-680] У поля ввода нет типа url, и адрес страницы вводится как обычный текст
>
> ## Что не так
>
> У поля ввода четыре типа — `IRtInput.Type` в `rt-input.model.ts`: `text`, `password`, `email`,
> `time`. Типа `url` нет, и приложение, которое просит владельца ввести полный адрес страницы,
> ставит `text`: сборка на `type="url"` падает на несовпадении типов.
>
> Нативное поле `type="url"` даёт браузеру подсказку по клавиатуре на телефоне и разбор адреса
> при вставке. С типом `text` этого нет, и адрес приходится сверять образцом в самом приложении.
>
> ## Что нужно
>
> `url` пятым членом `IRtInput.Type`, дальше — как у остальных четырёх: тип уезжает на нативное
> поле, спека `rt-input.component.spec.ts` перечисляет его наравне с прочими (`it.each` уже
> написан по этому списку).
>
> ## Чем проверить
>
> - `it.each` спеки поля проходит с пятым типом без правки самого теста, кроме списка.
> - Поле с `type="url"` на телефоне показывает клавиатуру для адреса.
> - Остальные четыре типа работают как прежде: проверка формы у поля своя и от типа не зависит.

Работа взята заходом, которому владелец назначил работать самостоятельно и вопросов не задавать.

## Что уже есть в дереве

Разведка идёт по самому компоненту: тело задачи называет и файл модели, и файл спеки.

## Что уже сказано в правилах

- Правило `component-structure`: порядок свойств декоратора и группировка импортов.
- Правило `ui-component-tests`: состояние компонента подтверждается спекой рядом, вид — снимком.

## Вопросы и ответы

Вопросов владельцу не задавалось: он назначил работу самостоятельной, а тело задачи называет и
правку, и способ проверки.

## Решения

- **Проверка адреса образцом не заводится.** Владелец назвал ровно одно: тип уезжает на нативное
  поле. Разбор адреса — работа браузера, а своя проверка формы у поля уже есть и от типа не
  зависит.

## Что осталось невыясненным

- Ничего: тело задачи закрыло и объём, и способ проверки.
