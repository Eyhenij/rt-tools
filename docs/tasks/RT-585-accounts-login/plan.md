## Что считается сделанным

- Учётная запись заводится, меняет пароль и отключается командами строки запуска приёмника, а
  `account:list` называет имена, состояние и время последнего входа.
- Вход заводится годной парой, живёт сроком, обрывается выходом того входа, которым пришли, и
  перестаёт приниматься у отключённой записи.
- Браузеру вход отдаётся кукой, недоступной скриптам и не посылаемой по чужому переходу.
- Ни одна операция чтения груза не отвечает без входа, и ни одна операция приёма не отвечает по
  входу человека; каждая операция объявляет свой способ доступа явно.
- Отказ входа не называет, что не сошлось, и отвечает за то же время при неизвестном имени.
- Пароль не встречается ни в журнале, ни в ответе, ни в адресе; в хранилище лежит только хеш.
- Операции чтения отдают страницы разборов, предложений, записей месяца и список деревьев с общим
  числом записей, порядком, отбором по дереву и границами размера страницы.
- Отказ службы называет номер обращения, и тот же номер стоит в журнале.
- Сценарии `SC-MB-33`…`43`, `56`…`65`, `68`, `72`, `79` закрыты наборами `vitest`; остальные ждут
  задачи #587 — они про то, что видит человек.
- `pnpm exec nx affected -t lint typecheck test build`, `npm run check:specs`, `node
tools/check-push-gate.mjs` зелёные.

## Этапы

### 1. Хранилище: учётная запись и вход

- **Что делается:** модели учётной записи и входа в схеме, миграция, приведение имени к
  единственному виду ограничением хранилища.
- **Признак готовности:** миграция накатывается на пустое хранилище и на нынешнее; вторая запись
  с тем же именем в другом регистре отбивается ограничением, а не проверкой чтением.
- **Чем проверяется:** `docker compose up -d db`, накат миграций, спека на повтор имени.

### 2. Команды учётных записей

- **Что делается:** `account:add`, `account:passwd`, `account:disable`, `account:list` рядом с
  уже написанными командами деревьев; пароль спрашивается, а не приходит доводом.
- **Признак готовности:** заведение печатает имя и не печатает пароля; отключение обрывает входы;
  список называет состояние записи.
- **Чем проверяется:** спеки команд, живой прогон в контейнере.

### 3. Вход: заведение, срок, обрыв

- **Что делается:** операции `login`, `logout`, `session`; кука с запретом чтения скриптом и
  отправки по чужому переходу; срок входа настройкой; сравнение с заглушкой хеша при неизвестном
  имени; удлинение ответа после неудач подряд.
- **Признак готовности:** сценарии `SC-MB-33`…`35`, `37`, `38`, `56`, `57`, `59` зелёные; ответ на
  неизвестное имя и на неверный пароль неотличим ни текстом, ни временем.
- **Чем проверяется:** спеки контроллера входа, замер времени ответа в спеке.

### 4. Объявление доступа на каждой операции

- **Что делается:** гард входа рядом с нынешним гардом токена дерева; умолчание «закрыто»;
  явное объявление способа доступа на каждой операции, включая пробу живости и приём груза.
- **Признак готовности:** сценарии `SC-MB-36`, `39`, `40`, `79` зелёные; операция без объявления
  не отвечает никому.
- **Чем проверяется:** спеки гардов, спека на операцию без объявления.

### 5. Операции чтения груза

- **Что делается:** `trees`, `postmortems`, `proposals`, `summaries` — страница, размер с
  умолчанием и пределом, порядок с разводящим вторым ключом, отбор по признаку дерева, общее
  число записей; отдельная операция на одну запись целиком.
- **Признак готовности:** сценарии `SC-MB-62`…`65`, `68` зелёные; страница за пределом отвечает
  пустой страницей, неразобранный номер — отказом с границами.
- **Чем проверяется:** спеки контроллеров чтения, запросы к поднятому приёмнику.

### 6. Отказ, видимый человеку

- **Что делается:** номер обращения в ответах `500` и `503`, тот же номер в журнале; строка при
  старте о том, что учётных записей нет ни одной.
- **Признак готовности:** сценарии `SC-MB-61`, `72` зелёные.
- **Чем проверяется:** спека разбора отказов, живой подъём с пустым хранилищем.

### 7. Тексты домена и отчёт

- **Что делается:** привязки в компаньоне договорённости, ход работы, отчёт со списком
  проверенного.
- **Признак готовности:** ни одной строки «ждёт кода» у правил, закрытых этой задачей; набор
  проверок перед пушем зелёный целиком.
- **Чем проверяется:** `npm run check:specs`, `node tools/check-push-gate.mjs`.
