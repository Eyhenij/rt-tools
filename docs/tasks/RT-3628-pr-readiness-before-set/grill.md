# Разбор

## Просьба владельца

> сейчас рабочий процесс занимает слишком много времени, довольно простые правки идут по несколько часов, сделай анализ на какие шаги сколько времени уходит по текущему task flow и как можно оптимизировать весь процесс

На вопрос «Завести эпик на ускорение процесса?» — «Да, заводи». План эпика RT-3624 одобрен вариантом «Без П5
(Recommended)». Точка задачи в нём: «готовность к открытию PR проверяется до набора. Признак: ветка без нужного
сквозного теста или с открытой папкой получает отказ до первого тяжёлого шага».

Карточка #3628: «Открытие PR отказывает уже после набора: нет нужного сквозного теста, папка задачи не разобрана.
Набор идёт снова, на каждую такую ветку уходит 10–20 минут. Готово, когда ветка без нужного сквозного теста или с
открытой папкой получает отказ до первого тяжёлого шага набора».

## Что уже есть в дереве

- Набор идёт вперёд командой `git-guard-push-ahead.sh` из пакета. Она судит только чистоту копии, основу и узел.
  О готовности к PR она не спрашивает ничего.
- Отказы при открытии PR дают две защиты: `git-guard-delivery.sh` пакета (папка, база, тело, перемер шагов) и
  `e2e-coverage-guard.sh` этого дерева (сквозной тест).
- Журналы сессий этого дерева 21–25.11: 30 открытых PR, 14 отказов по делу на 11 ветках. Отказы, где просто не
  загружено правило, не считаны.

| нет сквозного теста                                | 3     | RT-3496 — 34 минуты, RT-3478 — 35, RT-3492 — до следующего дня, 42 минуты   |

- Папку, разобранную последним коммитом, набор заново не гонит с RT-3630: ключи тяжёлых шагов записей не читают.
  Порядок цикла с RT-3630 — набор идёт при открытой папке, папка разбирается после зелёного.
- Перемер шагов при открытии PR — часть вызова, который у последних шести веток шёл 24, 118, 60, 90, 32 и 169 секунд.
- Движок хода отвечает за секунду без хостинга: `measure` называет первое невыполненное состояние. Несовпадение папки
  с коммитом плана знает `changedSincePlan` в `flow-step.mjs`.
- Основу набора выбирает `rt_push_base`: ветка эпика, предыдущая ветка цепочки или main; своя удалённая копия основой
  не бывает. Эпик, сдвинутый обычным коммитом, она не берёт и отвечает main: основа PR ищется отдельно.
- Размеры: `task-flow-script.mjs` 497 строк, `project.sh` 497, сценарии `push-gate-ahead` 499 — новое идёт своими
  файлами.

## Что говорят правила

- Закон `verifiability`, «End-to-end coverage of a change»: изменение, которое идёт через набор, несёт его тест.
- `task-delivery-loop`: «The push set runs beside round two», «after green only the record of the round and the
  take-apart commit, then the push» — папка во время набора открыта.
- Закон `delivery`: невыполненные условия отправки называются одним отказом.

## Вопросы и ответы

Вопросов до плана нет: слова карточки о папке сверяются с порядком RT-3630 в решении ниже, и владелец видит это в меню
одобрения плана.

## Решения

- **«Открытая папка» — папка, которую ещё нельзя разобрать.** До набора отказывает папка, чьи этапы не кончились, чей
  след не тронут или чьи файлы разошлись с коммитом плана. Сама по себе открытая папка набор не держит. Отвергнуто:
  разбирать папку до набора — запись второго круга вернула бы её назад, и порядок RT-3630, одобренный владельцем,
  отменился бы. Отказов из-за неразобранной папки в журналах ноль.
- **Проверка стоит в начале команды набора, а не в списке шагов.** Отказ останавливает её до первого шага и называет
  всё невыполненное сразу. Отвергнуто: строка в `rt_push_checks` — её получила бы и всякая отправка, не идущая в PR.
- **До набора судят функции защиты открытия PR.** Отвергнуты два пути. Свой перечень условий судил основу иначе, чем
  открытие PR. Режим готовности внутри самой защиты запирал починку конфликта и первый набор ветки эпика, а условия,
  которые он добавлял, в 14 отказах не встречаются.
- **Незаконченная ветка идёт с `--no-pr '<причина>'`.** У ветки эпика судятся лишь сквозной тест и папки её задач.
  Условия PR всё равно стоят на его открытии.
- **Основа судится словами защиты, пока папка лежит в ветке.** После открытия PR правка по замечаниям идёт без неё.
- **Перемер шагов не входит.** Он стоит около 80 секунд каждой ветке, а повторный набор по нему дала одна RT-3508,
  18 минут против 40 минут цены. Проверки шагов к тому же читают записи, которые второй круг дописывает после старта
  набора.
- **Выгода названа верхней границей.** 34, 35 и 42 минуты — от отказа до PR, с написанием теста и красными снимками.
  Чтение стратега: за 23–25.11 отказов о сквозном тесте нет. Ведёт ли это к вехе — решает владелец на одобрении.
- **Тело PR не входит.** До набора его ещё нет, и отказ по нему набор заново не гонит.

## Что осталось неясным

Ничего: решения выше не меняют кода приложений.
