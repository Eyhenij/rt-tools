## Этапы

### 1. Долг разложен по родам

- **Что делается:** каждый из сорока восьми читается в своём шаблоне вместе со стилями рядом и
  относится к одному из трёх родов: мёртвый класс, недостающее правило, класс у чужого блока.
- **Признак готовности:** у каждой строки списка назван род и способ починки; числа по родам
  сходятся с сорока восемью.
- **Чем проверяется:** перечень в ходе работы против списка известного.

### 2. Мёртвые классы сняты

- **Что делается:** класс, который ничего не значит, убирается из шаблона вместе с директивой;
  узел, оставшийся без единого класса, не переписывается ради красоты.
- **Признак готовности:** снятые классы ушли из списка расхождений проверки, спеки и снимки
  китов зелёные.
- **Чем проверяется:** `node tools/check-styles.mjs`, `pnpm test`, снимки обеих витрин.

### 3. Недостающие правила заведены

- **Что делается:** классу, который в разметке нужен, заводится правило в стилях своего
  компонента — токенами, а не значениями на месте; узлу, вынесенному к `<body>`, правило
  объявляется там, откуда оно до него достаёт.
- **Признак готовности:** проверка о нём молчит, а замер до и после совпадает.
- **Чем проверяется:** `node tools/check-styles.mjs`, замер вычисленных значений на витрине.

### 4. Список известного опустошён

- **Что делается:** строки, которым больше ничего не отвечает, снимаются; причина списка
  переписывается на то, что верно после разбора.
- **Признак готовности:** `debt` пуст, `accepted` пуст, проверка зелёная и стоит в гейте.
- **Чем проверяется:** `node tools/check-styles.mjs`, гейт пуша целиком.

### 5. Тексты приведены к сделанному, работа отдана на разбор

- **Что делается:** перечитываются правило `styling-bem` — его раздел о границе проверки — и
  «Что не входит» спека второго кита; открывается PR черновиком.
- **Признак готовности:** гейт зелёный, PR открыт с меткой и строкой связи, задача в колонке
  разбора.
- **Чем проверяется:** `npm run check:board`, `npm run check:docs`, `npm run check:specs`.

## Чего эта работа не делает

- **Не расширяет проверку.** Пара «блок — элемент» и снятое правило живого класса — её
  известная граница, названная правилом; правка самой проверки закрыта задачей RT-788.
- **Не меняет вид компонентов.** Расхождение кадра здесь — признак промаха правки, а не повод
  пересъёмки эталона.
- **Не трогает списки принятого других проверок.** Литералы, граф токенов и тёмная тема
  разбираются своими задачами.
