## Что считается сделанным

- В настройке кита есть раздел с видом поля ввода.
- Без настройки вид поля остаётся прежним.
- Раздел настройки задаёт вид, а вход на месте его перебивает.
- Разрешённое значение считается один раз, а шаблоны читают его.
- Вложенный компонент получает уже разрешённое значение.

## Этапы

### 1. Раздел настройки и разрешение

- **Что делается:** в настройку добавляется раздел селекторов с видом поля; в общей основе и в
  списке выбранного умолчание входа становится пустотой, а разрешённое значение считается там же;
  шаблоны читают разрешённое.
- **Признак готовности:** пакет собирается, прежний вид без настройки не изменился.
- **Чем проверяется:** `pnpm exec nx build @rt-tools/ui-kit` — сборка без отказов.

### 2. Спека на три сценария

- **Что делается:** спека селектора на порядок разрешения — без настройки, из настройки, входом.
- **Признак готовности:** три сценария зелёные.
- **Чем проверяется:** `pnpm exec nx test @rt-tools/ui-kit --testFile=projects/ui-kit/src/lib/ui-kit/dynamic-selectors/components/dynamic-selector/rtui-dynamic-selector.component.spec.ts` — прогон без провалов.

### 3. Договорённость сведена с кодом

- **Что делается:** привязки статей и сценариев называют настоящие символы.
- **Признак готовности:** сверка спеков без расхождений.
- **Чем проверяется:** `node tools/check-specs.mjs` — код 0.

## Чего эта работа не делает

- Настройки второго кита: у него свои поля и своя настройка.
- Прочих свойств поля — плотности, размера подписи.
