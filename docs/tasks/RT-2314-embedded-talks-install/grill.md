# Grill

## Просьба владельца дословно

«реализуй экраны для админки», затем «делай эпик далее». Задача четвёртая и последняя в эпике
RT-2309, взята по его плану.

## Что выяснено до первой правки

- **Страница готова.** `apps/chat-talks-page` рисует список, ленту, ответ и закрытие; вход берёт
  ключ площадки, адрес сервиса и адрес встроившей админки из адреса рамки, а подпись — сообщением.
- **Виджет посетителя — образец сборки одним файлом.** `apps/chat-widget`: своя сборка `vite`,
  выход `dist/apps/chat-widget/widget.js`, тег объявляется скриптом. Кита с собой не везёт.
- **У стенда уже есть страница потребителя с виджетом** — `apps/message-bus-admin-e2e/stand/widget-page.html`,
  её отдаёт `serve-admin.mjs` оттуда же, откуда админку. Там же стоит приложение площадки, которое
  принимает вызовы наружу: образец стороннего сервера уже есть, и подпись ему считать тем же приёмом.
- **Засев чата держит площадку с тайной** — `CHAT.widget` с `hookSecret`; ею и подписывается вход.
- **Сцены заняты по `SC-CH-91`**, следующая свободная — `SC-CH-92`.

## Решения и доводы

- **Задача написана про тег со ссылкой, а страница входит рамкой.** Слово задачи «одним скриптом»
  остаётся: скрипт тот же один, и ставится так же тегом, но рисует он рамку, а не разметку. Решение
  о рамке принято задачей RT-2313 и записано в плане эпика.
- **Подпись скрипт не считает, а спрашивает.** Тайна площадки лежит у потребителя на сервере; адрес
  этой точки скрипт получает признаком тега. Скрипт, считающий подпись, вынес бы тайну в страницу.
- **Точку выдачи подписи на стенде пишет сам стенд.** Ему уже принадлежит приложение площадки, и
  вторая раздача ради одной подписи развела бы стенд надвое.
