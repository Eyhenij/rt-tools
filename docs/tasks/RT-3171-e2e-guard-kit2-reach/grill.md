# Grill

## The owner request

> Починить проверку (Recommended)

> Отдельный PR проверки (Recommended)

Ответы владельца в меню: на вопрос, как быть с проверкой покрытия, которая на правку календаря
требует сквозной тест в примере входа, — и на вопрос, как довести исправление до хуков сессии.

## What the tree already has

- `.claude/hooks/e2e-coverage-guard.sh` — проверка покрытия при открытии PR, своя для этого дерева.
- `.claude/rt-kit/project.sh` — функция `rt_push_touched`: путь → предмет; `kit2` требовал оба набора.
- Сценарии проверки: `tools/tests/e2e-coverage-guard.test.sh`.
- Статья правила `testing` в надстройке `.claude/rt-kit/overrides/rules/testing.md`.

## What the rules already say

Правило `testing`: набор требуется по предмету пути. Отказ проверки чинится в причине или в самой
проверке, обход не предлагается.

## Questions and answers

**Как быть с проверкой, которая требует тест в приложении без изменённого компонента?**
«Починить проверку (Recommended)»

**Хуки сессии берутся из основной копии со старой проверкой — как довести исправление?**
«Отдельный PR проверки (Recommended)»

## Decisions

- **Набор приложения нужен, только если правка второго кита задевает то, что приложение рисует** —
  компонент, который оно называет, компонент внутри него или файл кита вне компонентов. Отвергнуто:
  карта «компонент → приложение» руками — она отстаёт от кода.
- **Набор перед push по-прежнему гоняет оба набора на правку кита** — он дешевле промаха, а
  проверка покрытия судит, нужен ли новый тест.
