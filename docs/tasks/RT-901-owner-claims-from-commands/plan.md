# Замысел

**Задача:** RT-901 · **Ветка:** `RT-901-owner-claims-from-commands`
**Поведение:** не меняется — работа идёт по слою правил и по гардам, а не по коду приложения:
продукта, о котором пишется договорённость, она не задевает.

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## След задачи

Части пакета правил названы словами, а не полными путями: гард хода работы читает пути из текста
команды и признаёт правкой кода любое упоминание пути внутрь пакетов — даже в команде, которая
пишет документ.

| Что     | Где                                                                   |
| ------- | --------------------------------------------------------------------- |
| Правила | правило ведения работы в пакете правил                                |
| Код     | новый гард утверждения на завершении хода и набор при нём             |
| Тексты  | спек поддомена о гардах завершения хода — правила, сценарии, привязка |
| Дерево  | раскладка нового гарда и его строка в настройках, `.claude/hooks/`    |

## Что считается сделанным

- Ход, в котором исполнитель сказал владельцу о состоянии дерева словом-утверждением, а команды,
  это показавшей, за тот же ход не запускал, отбивается гардом.
- Отказ называет само утверждение, которое гард нашёл, и говорит два хода: запустить команду
  либо убрать утверждение.
- Утверждение, при котором команда за тот же ход была, ход не задерживает.
- Гард отказывает в пользу работы: нет разборщика JSON, нет записи хода, поломка чтения — ход
  разрешается.
- Спек поддомена о гардах завершения хода называет новое требование правилом, сценарием и
  привязкой к коду.
- Правило ведения работы говорит, чем подтверждается утверждение владельцу, и называет границу
  гарда: неверный вывод он не ловит.

## Этапы

### 1. Гард утверждения о дереве

- **Что делается:** заводится гард на завершении хода. Он берёт текст, сказанный владельцу за
  этот ход, ищет в нём слова-утверждения о состоянии дерева — готово, проверено, снято, влито,
  запушено, зелено, такого нет — и сверяет с командами того же хода. Команды нет — ход
  отбивается, и отказ называет найденное утверждение.
- **Признак готовности:** утверждение без команды отбито, утверждение с командой пропущено,
  ход без утверждений не задет, а любая поломка гарда кончается разрешением хода.
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 2. Спек поддомена о гардах завершения хода

- **Что делается:** новое требование записывается правилом поддомена, получает сценарии на все
  случаи набора и строку привязки к коду гарда.
- **Признак готовности:** каждое новое правило поддомена привязано к коду, каждый сценарий
  закрыт заголовком спеки набора.
- **Чем проверяется:** `pnpm run check:specs` — расхождений нет.

### 3. Статьи правила и раскладка

- **Что делается:** правило ведения работы получает статью о том, чем подтверждается утверждение
  владельцу, и две статьи по разборам, которые гард не ловит: об образце судят обходом
  каталогов, а не одним файлом; путь, предложенный человеку, проверяется тем, пойдёт ли он им.
  Там же называется граница гарда. Гард раскладывается в дерево.
- **Признак готовности:** статьи стоят с привязками, разложенная копия сходится с источником,
  новый гард зовётся деревом.
- **Чем проверяется:** `pnpm run agent-kit:check` — расхождений нет.

## Чего эта работа не делает

- Не правит закон о ведении работы: готовая статья приносится владельцу текстом в отчёте по
  задаче, а работа идёт дальше без неё.
- Не учит гард судить неверный вывод — только слово-утверждение. Два разбора группы закрываются
  статьями правила, и граница называется вслух.
- Не судит тело PR и тело задачи отдельным приёмом: они уезжают наружу командой того же хода и
  попадают под общий разбор вместе с ней.
- Не трогает соседние гарды завершения хода: страж выходов и гард ожидания остаются как есть.
