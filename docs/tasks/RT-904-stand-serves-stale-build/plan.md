# Замысел

**Задача:** RT-904 · **Ветка:** RT-904-stand-serves-stale-build
**Поведение:** не меняется — правится объявление выходов таргета сборки; ни строки кода
приёмника, ни его маршрутов работа не трогает. Владельцу сказано, что способ взят без его
ответа.

## След задачи

| Что     | Где                                       |
| ------- | ----------------------------------------- |
| Сборка  | `apps/message-bus/project.json`           |
| Стенд   | `apps/message-bus-admin-e2e/stand/up.mjs` |
| Спеки   | `docs/specs/message-bus/`                 |
| Правила | `.claude/skills/browser-verification/`    |

## Что считается сделанным

- У таргета `build` приёмника объявлены выходы, и `nx show project` их называет.
- Снесённый `dist` приёмника восстанавливается попаданием в кэш, а не остаётся пустым.
- Стенд поднимает сборку, отвечающую исходникам: маршрут выдачи приглашения есть у поднятого
  приёмника.

## Этапы

### 1. Выходы сборки приёмника объявлены

- **Что делается:** таргету `build` в `apps/message-bus/project.json` прописывается каталог
  сборки как выход.
- **Признак готовности:** `nx show project` называет выход, а не пустой список.
- **Чем проверяется:** `npx nx show project message-bus --json` — в `targets.build.outputs`
  стоит каталог сборки, список не пуст.

### 2. Восстановление из кэша проверено сносом сборки

- **Что делается:** каталог сборки приёмника сносится, сборка зовётся заново и попадает в кэш.
- **Признак готовности:** файл входа приёмника на месте и совпадает по содержимому с тем, что
  лежало до сноса.
- **Чем проверяется:** `npx nx build message-bus --configuration production` после сноса —
  вывод говорит о попадании в кэш, а `dist/apps/message-bus/main.js` существует.

### 3. Стенд поднимает сборку, отвечающую исходникам

- **Что делается:** стенд поднимается на своих портах, и у поднятого приёмника спрашивается
  маршрут выдачи приглашения — тот самый, которого не было в пойманном случае.
- **Признак готовности:** маршрут отвечает не отказом «нет такого пути».
- **Чем проверяется:** `pnpm run serve:stand` и запрос к маршруту выдачи — ответ приходит от
  приёмника, а не 404 о неизвестном пути.

## Чего эта работа не делает

- Не трогает семь прочих кэшируемых таргетов без выходов: они проверки и типизация, артефактов
  не оставляют.
- Не отключает кэш ни на стенде, ни в конвейере.
- Не чинит засев стенда — это соседняя задача RT-947.
