## Что уже есть в дереве

Скан Angular Doctor на вершине RT-3480 (23.11.2026) находит 21 находку четырёх правил oxlint:

- `eqeqeq` — 11: сравнения `== null` и `!= null` в `safe-compare.ts` (3), `are-arrays-equal-unordered.ts`
  (2), `deep-equal.ts` utils, `bem.utils.ts` core, `rt-toolbar.component.ts`,
  `rt-workspace-details.component.ts`, `rt-day-stamp.pipe.ts` кита и `admin-fault-text.ts` админки.
  Все одиннадцать — проверка «нет значения»: `null` или `undefined`.
- `no-thenable` — 7: ключ `then` условий JSON Schema в `ai-chat-chart.schema.ts` кита. Схема
  публичная: её экспортирует вход `ai-chat-chart`, спеки сверяют её валидатором Ajv.
- `no-extra-boolean-cast` — 2: `Boolean(value) ?` в `ternary.pipe.ts` core и `!!parseFormatOptions ?`
  в `type-cast.helper.ts` utils.
- `no-useless-spread` — 1: `[...this.#rendered.keys()]` в `rt-pdf-viewer.component.ts`; цикл
  снимает страницы из того же словаря, и копия ключей нужна.

В utils уже есть `isNil` — проверка на `null` и `undefined`; core и кит зовут её из
`@rt-tools/utils` с версии, которую они требуют.

Проба на oxlint 1.94.0: правило `no-thenable` находит ключ `then`, записанный буквой, строкой,
вычисленным ключом и через константу; не находит объект, собранный `Object.fromEntries` по списку
ключевых слов.

## Что уже говорят правила

- Правила Angular Doctor не выключаются в настройке: так решил владелец.
- Видимая правка кита идёт через макет или через слово владельца «вид не меняется».
- Перед новым кодом берётся готовое: проверка «нет значения» — `isNil` из utils.

## Вопросы и ответы

**`no-thenable` на ключе `then` схемы.** Помощник, что собирает ключ так, чтобы сканер его не
видел, — обход правила, а не правка (goal-critic, проверка вопросов). Правило выполняется по сути:
семь условий «если A — то B» переписываются на `anyOf: [{ not: A }, B]`, условие с «иначе» — на
`anyOf: [{ allOf: [A, B] }, { allOf: [{ not: A }, C] }]`. Валидатор принимает и отклоняет те же
графики; текст JSON схемы и тексты ошибок валидатора меняются.
Вопрос: «Подтверждаете смену JSON схемы?» — ответ: «Подтверждаю смену JSON (Recommended)».

**Копия ключей просмотрщика PDF.** Цикл удаляет из словаря только текущий ключ, а удаление во время
обхода `Map` безопасно: правило право, копия не нужна — цикл идёт по `keys()` самого словаря.

**oxlint в дереве.** Владелец спросил: «разве у нас используется oxlint?» — дерево его само не
запускает: oxlint — зависимость Angular Doctor (`oxlint ^1.93.0`), один из его источников находок;
все 21 находка задачи — оттуда.

**Живость источника.** После задачи в пороге нет ни одного правила oxlint, и `check:ngdoctor` не
отличит источник без находок от источника, который не запустился. Ответ: «Отдельной задачей
эпика» — RT-3514, сразу после RT-3481. Порог здесь пишется с `--source-gone oxlint`.

**Правка кита: `isNil` вместо `== null` в `rt-toolbar.component.ts`, `rt-workspace-details.component.ts`
и `rt-day-stamp.pipe.ts`, `Array.from` вместо `[...]` в `rt-pdf-viewer.component.ts`, помощник
условий в `ai-chat-chart.schema.ts`. Вид не меняется — подтверждаете?**
«Подтверждаю, вид не меняется». Вопрос задан до ревью плана; после него просмотрщик идёт по
`keys()` без копии, а схема — через `anyOf`, на что владелец ответил отдельно.

**Behaviour:** unchanged — слово владельца 23.11.2026 «Подтверждаю, вид не меняется»: сравнения,
обход ключей и условия схемы меняют форму записи, а значения и разметка остаются; смену JSON схемы
владелец подтвердил отдельно: «Подтверждаю смену JSON (Recommended)».
