## Что считается сделанным

- Источник оформления объявляет второй набор назначений, и генератор собирает его в тот же файл
  токенов; сборка на месте не правится.
- Признак `data-preset='material'` на корне страницы перекрашивает кит; тот же признак на
  контейнере красит только его содержимое.
- Страница без признака набора выглядит как до работы: эталонные снимки витрины зелёные.
- Метка тёмной темы вместе с меткой набора даёт тёмный базовый вид.
- Скругления и кегли, которые компоненты берут из шкалы прямо и которые набор обязан менять,
  получили своё назначение; перечень таких мест назван в ходе работы.
- Договорённость о продукте влита в спек второго кита поддоменом, каталога «предложено» больше нет.

## Этапы

### 1. Второй набор в источнике оформления

- **Что делается:** в источнике оформления заводится слой назначений материального набора; значения
  снимаются с оформления первого кита числами, а не ссылками на его токены. Генератор собирает
  набор в тот же файл токенов.
- **Признак готовности:** собранный файл содержит объявления материального набора, и сверка
  собранного с источником проходит.
- **Чем проверяется:** `pnpm run check:tokens-build` — молчание и нулевой код возврата значат, что
  собранное сходится с источником.

### 2. Признак набора и его порядок с тёмной темой

- **Что делается:** набор объявляется под признаком `data-preset='material'` и равнозначным классом,
  на корне страницы и на контейнере; правила тёмной темы объявляются после набора, чтобы тёмная
  тема выигрывала.
- **Признак готовности:** признак на контейнере красит только его содержимое, обе метки вместе дают
  тёмный базовый вид, слой каскада не нарушен.
- **Чем проверяется:** `pnpm run check:cascade-layer` — пустой перечень мест значит, что правила
  набора стоят в своём подслое.

### 3. Назначения под скругления и кегли, которые набор меняет

- **Что делается:** места, где компонент берёт скругление или кегль ступенью напрямую и где вид
  первого кита отличается, получают своё назначение; ступени при этом не переписываются.
- **Признак готовности:** ни одно из названных мест не берёт ступень мимо назначения, а базовый
  вид не сдвинулся.
- **Чем проверяется:** `pnpm run check:tokens-graph` — каждое имя объявлено слоем оформления либо
  названо ручкой потребителя, мёртвых ссылок нет.

### 4. Договорённость влита, тексты подтянуты

- **Что делается:** договорённость о продукте вливается в спек второго кита поддоменом; каталог
  «предложено» снимается, номера сценариев не меняются. Правило оформления получает статью о том,
  что наборов назначений у кита два.
- **Признак готовности:** сверка спеков не называет ни одной незакрытой привязки.
- **Чем проверяется:** `npm run check:specs` — перечень пуст.

## Чего эта работа не делает

- Проверку полноты материального набора и считалку контраста в нём — RT-1872.
- Сведение значков первого кита с набором второго — RT-1873.
- Показ двух наборов рядом на витрине — RT-1874.
- Тёмную половину материального набора — не заводится вовсе, решение записано в договорённости.
- Первый кит: ни его токены, ни витрину, ни проверки эта работа не трогает.
