# Разбор

## Просьба владельца

> есть ли готовые фрэймворки или сценарии чтобы закрывать этот процесс и проверки?

На предложение начать с одной из замен (prompt-хук на Stop, CI на PR в эпик, stacked PR) владелец
выбрал:

> Prompt-хук на Stop

Перед этим в той же сессии владелец спросил «какие ты видишь проблемы?» и согласился посчитать долю
ложных отказов: «Да, посчитай (Recommended)».

Работа сначала заведена отдельной задачей RT-3323. Затем нашлась открытая задача RT-3276 эпика
RT-3302 о том же: «Проверки судят разговор регулярными выражениями — запрещают ждать владельца и
спрашивать его». На вопрос, закрыть ли RT-3323 как дубль и вести работу как RT-3276, владелец
ответил:

> Да, в RT-3276

RT-3323 закрыта как дубль, разбор перенесён сюда.

Признаки готовности RT-3276 из её описания:

- ход, который ждёт решения владельца, заканчивается без отказа;
- вопрос владельцу после отказа другой проверки уходит;
- список проверок, судящих разговор, с решением по каждой лежит в плане эпика.

## Что уже есть в дереве

- Журнал отказов `.claude/rt-kit/observations/*.jsonl`, 14.10–14.11.2026: 1775 отказов проверок и
  1144 отказа шлюза правил. Из них `turn-exit-guard` — 921, 55% повторяются в той же сессии меньше
  чем через 5 минут, максимум 156 за одну сессию.
- Разбор 803 отказов `turn-exit-guard` на конце хода по стенограммам: 327 (около 41%) пришлись на ход,
  где владелец задал вопрос (100), сказал остановиться (21) или ругался без поручения (206). Такой ход
  правильно заканчивать ответом, а проверка требует правки дерева. Тип сообщения определялся грубым
  regex, поэтому 41% — нижняя граница.
- Ложный отказ дают уровни `turn-exit-guard`, где отказ звучит «nothing was done in this turn». Слова
  «не сейчас» нет в списке слов остановки (`.claude/hooks/turn-exit-verdict.sh:100`). Текст отказа
  обещает читать цитату слова владельца в ответе, а код читает её только из `progress.md`
  (`.claude/hooks/turn-exit-epic.sh:38`); на `main` этого файла нет.
- `turn-exit-guard` — ресурс пакета `@rt-tools/agent-kit`, раскладывается командой `agent-kit sync`.
  На месте не правится, надстроек для хуков в `.claude/rt-kit/overrides/` нет.
- Спек проверок хода — `docs/specs/agent-kit/turn-guards/`.
- Claude Code 2.1.323. По документации (code.claude.com/docs/en/hooks):
  - Stop поддерживает хуки `prompt` и `agent`. Ответ модели — `{"ok", "reason", "impossible"}`; при
    `ok: false` причина уходит агенту как следующая инструкция, ход продолжается.
  - Prompt-хук получает только вход события: `last_assistant_message`, `transcript_path`,
    `stop_hook_active`, `background_tasks`, `session_crons`. Сообщения владельца в нём нет, а
    стенограмму однократный вызов модели прочитать не может.
  - Agent-хук запускает субагента с Read/Grep/Glob, он может прочитать стенограмму. Помечен как
    экспериментальный, таймаут по умолчанию 60 с.
  - Хуки одного события идут параллельно. Встроенный предел — 8 продолжений подряд от Stop-хуков
    (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`).

## Что уже говорят правила

- Спек `turn-guards`, раздел о ходе без работы: «A turn in which nothing was done about the work does
  not end. A report about what was done is not an exit of a turn» и «Reading, searching and
  conversation do not count as it». Ход-ответ на вопрос владельца по этому тексту не может
  закончиться — эту строку задача меняет.
- Тот же спек: «A word about a stop is judged by the remark of the owner, not by the words of the
  executor». Значит, хук должен видеть сообщение владельца, а не только ответ агента.
- Закон `work-conduct`: «Work with a step that is not done is not finished, and a report about the
  done does not finish it either». Он про работу с незакрытым шагом; ответ на вопрос без начатой
  работы закон не запрещает, править закон не нужно.
- `task-flow-start`: после двух ответов «recommended» подряд остальные вопросы закрываются
  допущениями. Владелец взял рекомендованный вариант дважды: «Да, посчитай (Recommended)» и
  «Prompt-хук на Stop».

## Вопросы и ответы

**Какую замену самописных проверок пробовать первой?** Варианты: prompt-хук на Stop
(рекомендованный), CI на PR в эпик, stacked PR и merge queue, пока ничего.
Ответ владельца: «Prompt-хук на Stop».

**Заводить ли новую рабочую копию `../rt-turn-judge` от свежего `origin/main`?** Варианты: «Да,
заводи» (рекомендованный), «В главной копии».
Ответ владельца: «В главной копии».

**Одобряешь план RT-3276?** Варианты: «Одобряю» (рекомендованный; переключатель в пакете, включён
только здесь, проверки разговора при включённом переключателе уступают agent-хуку), «Всё же
prompt-хук».
Ответ владельца, свой текст: «замени полностью, убери старые проверки совсем».

**Шлюз правил дал около 560 отказов за базовую неделю и не стоит ни в одной задаче эпика — что с
ним делать?** Варианты: «Задача в RT-3302» (рекомендованный), «Пока не трогать».
Ответ владельца: «Задача в RT-3302 (Recommended)».

Остальные вопросы закрыты допущениями — ниже.

## Решения

- **Тип хука — agent, а не prompt.** Спек требует судить остановку по словам владельца, а prompt-хук
  видит только ответ агента. Agent-хук читает последнее сообщение владельца из `transcript_path`.
  Цена: хук экспериментальный, до 60 с и вызов модели на каждом конце хода, где он запускается.
  Отклонено: prompt-хук — не видит сообщения владельца.
- **Объём — по описанию RT-3276: каждая проверка, которая судит разговор, получает решение —
  удалить или отдать модели.** Список проверок с решением по каждой ложится в план эпика. Первой
  идёт `turn-exit-guard`: у неё больше всего отказов (921 за месяц). В ней модели отдаётся уровень
  «nothing was done»; уровни про состояние задачи, план, открытый PR, обещание работы и ожидание
  чужого шага детерминированные и остаются. Отклонено: менять только `turn-exit-guard` — так было в
  RT-3323, но описание RT-3276 шире.
- **Переключателя нет: старые проверки разговора удаляются из пакета, их место занимают agent-хуки.**
  Слово владельца: «замени полностью, убери старые проверки совсем». Пакет раскладывает текст
  agent-хуков файлом, запись в настройках сессии ссылается на него. Отклонено: переключатель,
  включённый только здесь, — его отклонил владелец.
- **Задача эпика RT-3302**, слово владельца «Да, в RT-3276». Эпик RT-3232 закрыт, к этой работе он
  не относится.
- **Поведение приложения не меняется.** Правка в `projects/agent-kit` и `.claude/`, договорённость
  по `apps/**` и `libs/**` не нужна. Меняется спек `turn-guards`.
- **Признак готовности:** на повторе тех же типов хода (вопрос, «не сейчас», «стоп», ругань без
  поручения) ход заканчивается без отказа, а ход с обещанием «сейчас запущу» без запуска по-прежнему
  отказан. Число отказов `turn-exit-guard` за неделю после включения сравнивается с неделей до.

## Что осталось неясным

- У эпика RT-3302 нет ни ветки, ни плана. Описание эпика ссылается на `checks-rework-3.md`, но этого
  файла нет ни в одной ветке и ни в одной рабочей копии (`git log --all` по нему пуст). Ветки
  `RT-3293-…` второй части на сервере тоже нет; осталась ветка
  `revert-3297-RT-3296-always-run-steps`. План третьей части восстанавливается из описания эпика при
  заведении ветки эпика.
- Строки назначения копии `rt-tools` на эпик RT-3302 нет. Таблицу назначений заполняет владелец.

- Сколько стоит agent-хук на каждом конце хода по времени и токенам — станет видно на замере.
