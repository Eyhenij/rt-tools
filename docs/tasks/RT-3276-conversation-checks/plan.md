**Task:** RT-3276 · **Branch:** RT-3276-conversation-checks
**Behaviour:** unchanged — правка пакета правил и настроек сессии, код приложений не меняется. Слово владельца: «Prompt-хук на Stop», «Да, в RT-3276», «замени полностью, убери старые проверки совсем».

**Старые проверки разговора удаляются, переключателя нет.** Их место занимают agent-хуки Claude Code
на Stop и на вызове меню. Владелец выбирал prompt-хук; ставится agent-хук: prompt-хук получает
только последний ответ агента и не видит сообщения владельца. Цена: тип помечен в документации
Claude Code как экспериментальный, до 60 с и вызов модели на каждом конце хода. Что дерево делает
при таймауте и ошибке хука, выясняется на шаге 2.1 по документации и проверяется на шаге 3.4.

Пакет раскладывает текст хуков файлами; запись в `.claude/settings.json` ссылается на файл. Другие
деревья получат удаление проверок с выпуском пакета; без записи в настройках требование у них
остаётся только текстом правила. Выпуск назначает владелец.

## Точки

- **A:** проверки разговора судят текст регулярными выражениями. За 07.11–13.11 (журнал
  `.claude/rt-kit/observations/`, файла за 10.11 нет — шесть дней) четыре из них отказали 228 раз из
  422 отказов всех проверок; по стенограммам за ту же неделю отказов восьми проверок разговора —
  106 записей. По стенограммам 14.10–14.11 около 41% отказов `turn-exit-guard` пришлись на ход,
  который правильно было закончить ответом владельцу: вопрос (100), «стоп» или «не сейчас» (21),
  ругань без поручения (206).
- **Эта задача даёт:** владелец задаёт вопрос, говорит «не сейчас» или «стоп», ругается без
  поручения — агент отвечает, и ход заканчивается без повторов и лишних меню. Вопрос владельцу после
  отказа другой проверки уходит. Ход, который обещает работу и не делает её, по-прежнему не
  заканчивается.
- **Признак:** прогон хука на записанных ходах из стенограмм — пять ложных отказов прежних проверок
  (вопрос, «не сейчас», «стоп», ругань, вопрос после отказа) хук пропускает, пять верных отказов
  (обещание без запуска, отчёт вместо поручённой работы) хук отказывает с меткой
  `BLOCKED by turn-judge:`. Затем то же в живой сессии после замены. Видит владелец; вердикты видны в
  стенограмме.
- **Веха G эпика:** за рабочий день отказов меньше пяти на сто команд, и ни одного тупика, из
  которого исполнитель не может выйти сам.
- **Metric:** отказы проверок разговора на сто вызовов инструментов по стенограммам — отказы
  оставшихся команд и отказы хука (метка `BLOCKED by turn-judge:`) вместе. База 07.11–13.11
  считается скриптом из папки задачи на шаге 1.2 (выполнен: 106 отказов; вызовы инструментов
  считаются на шаге 3.4 тем же скриптом). Направление — вниз, цель — вдвое меньше базы за 7 дней
  после замены. Встречное условие: число `owner-correction` в журнале за те же 7 дней не выше базы.
  Время хука на конце хода: медиана не больше 20 с, иначе владельцу предлагается вернуть prompt-хук.
  Судит отчёт за 7 дней после замены.

## Что считается сделанным

- В плане эпика лежит список проверок, судящих разговор, с решением по каждой.
- В пакете нет уровней и проверок, которые судят текст ответа или сообщения владельца:
  `turn-exit-guard` оставляет только уровни про дерево и команды, восемь проверок удалены вместе со
  сценариями. Оставшиеся сценарии зелёные.
- Пакет раскладывает тексты двух agent-хуков: на Stop и на вызове меню.
- В этом дереве оба хука стоят в `.claude/settings.json`; их отказ начинается с `BLOCKED by turn-judge:`.
- Прогон на записанных ходах и живой прогон из «Признака» прошли.
- Спек `turn-guards` и правила `turn-conduct`, `task-flow` описывают новое разделение.
