## Решения по ходу

- **Объём уровней `turn-exit-guard` шире, чем в разборе.** Кроме «nothing was done» модели отдаётся
  уровень «последнее действие хода — не работа»: он ложно отказал в этой сессии 14.11, и по
  стенограммам эти уровни дают около 650 из примерно 880 отказов проверки. Затронут этап 2.

  сессии не принял вывод `gh pr list` как подтверждение. Один хук на Stop дешевле трёх. Затронуты
  этапы 2 и 3.

- **План переписан по замечаниям `goal-critic` до одобрения владельцем.** Замена prompt-хука на
  agent-хук названа в шапке плана с ценой; модели отдаются и уровни «обещание работы» и «ожидание
  чужого шага» — в описании RT-3276 сказано, что регулярных выражений по тексту ответа не остаётся;
  метрика считает отказы команд и хука вместе по стенограммам; живые проверки идут в новой сессии,
  потому что хуки могут читаться при старте сессии. Затронуты все этапы.
- **База второго числа метрики:** по стенограммам 07.11–13.11 отказов восьми проверок с решением
  «модель» — 106 записей. Считалось по записям `user` со строкой «BLOCKED by <проверка>». Затронут
  этап 1.

- **Поведение agent-хука по документации Claude Code (code.claude.com/docs/en/hooks, 14.11.2026).**
  Отказ: `{"ok": false, "reason": …}` — причина уходит агенту, ход продолжается, как у prompt-хука с
  `continueOnBlock: true`. Таймаут по умолчанию 60 с. Ошибка или таймаут хука действие не
  останавливают: ход заканчивается; `"onFailure": "block"` есть только у хуков `command` и `http`.
  Значит, сломанный agent-хук пропускает всё — это цена замены, её видно по отсутствию меток
  `BLOCKED by turn-judge:` в стенограммах. `stop_hook_active` во входе Stop равен `true`, когда ход
  уже продолжен Stop-хуком; после 8 продолжений подряд Claude Code сам заканчивает ход
  (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`), счёт сбрасывается вызовом инструмента. Правка хуков в файле
  настроек подхватывается наблюдателем файлов без перезапуска. Затронут этап 2.

- **Какие уровни `turn-exit-guard` удаляются на шаге 3.2.** По тексту разговора судят: вопрос прозой
  после отказа (`asked_in_prose`), обещание (`promised`), «работай без остановок» и ожидание слова
  (`standing_work`, `awaits_word`), общая строка «последнее действие не работа» (`ended_working`),
  нижний блок «ничего не сделано» в трёх видах (`archived`, без состояния, с состоянием) и слово
  остановки из сообщений владельца (`told_stop`, `quoted_stop`) в признаке `released`. Остаются:
  взятая задача без работы, вопрос без работы в идущем этапе, рукописная передача при открытом эпике,
  отданная без PR работа, неотданные коммиты, шаги плана, открытый эпик — они судят дерево и вызовы.
  Слово владельца об остановке внутри задачи по-прежнему отпускает эти уровни строкой
  `Waiting for the owner: «…»` в ходе работы. Маркер «Не отправлено:» в ответе пока остаётся: это
  договорённая строка, а не угадывание. Затронут этап 3.
