## Что считается сделанным

- Названо, при каких условиях прогон на пуш заводится, а при каких нет, — и названо замером, а
  не рассуждением: у каждого утверждения стоит коммит, время и ответ хостинга.
- Если дыра остаётся, она закрыта тем, что видно со стороны PR: молчание страницы перестаёт
  выглядеть так же, как зелёный прогон.
- Правило поставки говорит о том, что верно сейчас: статья о прогоне на вершине сверена с
  замерами и правится или подтверждается.

## Этапы

### 1. Опыт поставлен на этой же ветке

- **Что делается:** PR открывается сразу, и каждый следующий коммит — текстовый — пушится
  отдельно; после каждого пуша список прогонов ветки читается тем же движением.
- **Признак готовности:** на каждый пуш известно, завёлся ли прогон, и это записано таблицей.
- **Чем проверяется:** `gh api .../actions/runs?branch=<ветка>` и события репозитория.

### 2. Причина пропажи названа или названа неизвестной

- **Что делается:** пропавшие события сверяются с состоянием хостинга того часа — отказами
  API, очередью раннера и его занятостью; если данных не хватает, это говорится прямо.
- **Признак готовности:** у каждого случая без прогона стоит либо причина, либо строка о том,
  чем её нельзя установить.
- **Чем проверяется:** журнал заданий, список прогонов, события репозитория.

### 3. Молчание страницы перестаёт быть неотличимым от зелёного

- **Что делается:** если прогон способен не завестись, дерево получает способ это увидеть —
  сверкой очереди работ либо шагом закрытия работы, а не памятью исполнителя.
- **Признак готовности:** вершина ветки без прогона называется тем, что читают между шагами.
- **Чем проверяется:** `npm run check:board` на ветке без прогона.

### 4. Тексты приведены к сделанному, работа отдана на разбор

- **Что делается:** статья правила поставки о прогоне на вершине сверяется с замерами;
  открывается PR черновиком.
- **Признак готовности:** гейт зелёный, PR открыт с меткой и строкой связи, задача в колонке
  разбора.
- **Чем проверяется:** `npm run check:docs`, `npm run check:specs`, `npm run check:board`.

## Чего эта работа не делает

- **Не переносит прогон в облако.** Раннер на своей машине — решение дерева, и цена его
  записана в правиле поставки.
- **Не заводит фильтров путей.** Их у конвейера нет намеренно: состав правки судит признак
  внутри задания.
- **Не чинит отказы хостинга.** 429 на загрузке действий и 503 на API — его сторона; работа
  лишь учится отличать их от дефекта ветки.
