## Что считается сделанным

- Личность записи подтверждена ответом хостинга её же токеном: логин `rt-tools-dev` и номер
  приходят вместе, и из номера собран адрес подписи.
- Токен новой записи лежит на машине там, где его ищут команды дерева, и прежний им заменён.
- `board.bot` называет новый логин, а `board.tokenPath` возвращён, если запись видит борду;
  не видит — причина названа в ходе работы, и ключ остаётся снятым.
- Спутник правила поставки говорит о том, что верно сейчас: снятые обходы сняты, оставшиеся
  названы с причиной.
- Проверено вызовом, а не предположением: PR открывается новой записью, владелец его видит и
  назначается ревьювером.

## Этапы

### 1. Токен новой записи лёг на машину

- **Что делается:** в браузере на закреплённом профиле открывается форма ключа доступа новой
  записи — имя, срок, репозиторий, права на содержимое, задачи, PR и проекты; кнопку выпуска
  нажимает владелец. Выпущенный ключ кладётся в файл, который называет спутник правила.
- **Признак готовности:** `gh api user` её токеном отвечает логином `rt-tools-dev` и номером
  317887029.
- **Чем проверяется:** ответ хостинга о себе.

### 2. Дерево называет новую запись

- **Что делается:** `RT_COMMIT_EMAIL` собирается из номера записи, `board.bot` уже назван,
  комментарии рядом приводятся к тому, что верно сейчас.
- **Признак готовности:** гард поставки не отбивает коммит машинной подписью, а сверка очереди
  зелёная.
- **Чем проверяется:** `npm run check:board`, набор гардов.

### 3. Очередь работ возвращается на машинную запись

- **Что делается:** её токеном спрашивается квота на язык запросов и сама борда; отвечает —
  `board.tokenPath` называется снова, не отвечает — ключ остаётся снятым, а причина ложится в
  ход работы.
- **Признак готовности:** перевод колонки и сверка очереди идут тем токеном, который назван
  настройками.
- **Чем проверяется:** `npm run check:board`, `npm run task:move`.

### 4. Тексты о поставке приведены к тому, что верно сейчас

- **Что делается:** четыре абзаца спутника правила поставки перечитываются целиком; снятое
  ограничение убирается, оставшееся называется с причиной.
- **Признак готовности:** ни один абзац не описывает обхода, которого больше нет.
- **Чем проверяется:** `npm run check:docs`, `npm run check:specs`.

### 5. Обещания проверены вызовом

- **Что делается:** PR этой ветки открывается токеном новой записи, владелец назначается
  ревьювером, и оба обещания читаются со стороны владельца, а не со стороны исполнителя.
- **Признак готовности:** PR виден владельцу по номеру, ревьювер у него стоит, прогон на
  вершине заведён.
- **Чем проверяется:** список PR и список прогонов ветки от учётной записи владельца.

## Чего эта работа не делает

- **Не заводит саму запись и не входит в неё.** Регистрация и ввод пароля — ход владельца.
- **Не снимает прежнюю запись и её токен.** Пока новая не проверена вызовом, старый путь
  остаётся рабочим откатом.
- **Не чинит прогон, не заводящийся на пуш.** Версия о помеченной записи этой веткой только
  проверяется; окажется верной — заводится своя задача.
