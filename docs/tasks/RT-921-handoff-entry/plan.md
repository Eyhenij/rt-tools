# Замысел

**Задача:** RT-921 · **Ветка:** RT-921-handoff-entry
**Поведение:** не меняется — правка задевает правило, паттерн и гард слоя правил, кода
приложения в ней нет ни строки.

## След задачи

| Что      | Где                                             |
| -------- | ----------------------------------------------- |
| Законы   | читается, не правится: закон о ведении работы   |
| Правила  | пакет слоя правил: правило ведения работы       |
| Паттерны | пакет слоя правил: паттерн возвращения к работе |
| Гарды    | пакет слоя правил: гард входа из передачи       |

## Что считается сделанным

- Вход из передачи объявлен порядком из четырёх шагов, а не общими словами.
- Порядок короткий: он не повторяет паттерн возвращения, а называет то, чем вход из передачи от
  обычного захода отличается.
- Гард отбивает первую правку захода, начатого с передачи, пока правило ведения работы не
  загружено и состояние работы не сверено с деревом.
- Сценарии на каждый исход; прогон зелёный.

## Этапы

### 1. Вход из передачи объявлен правилом

- **Что делается:** статья в правиле и раздел в паттерне возвращения: четыре шага входа и то,
  чем передача не является.
- **Признак готовности:** порядок читается за минуту и не повторяет соседних разделов.
- **Чем проверяется:** `node tools/check-specs.mjs` — зелено; сверка длины — правило короче предела.

### 2. Гард входа из передачи

- **Что делается:** гард на правке файла отбивает работу, пока в заходе, начатом с передачи, не
  загружено правило ведения работы.
- **Признак готовности:** сценарий на заход с передачей и без правила, с передачей и с правилом,
  без передачи вовсе.
- **Чем проверяется:** `bash tests/run.sh` — набор гарда зелёный и краснеет на его поломке.

## Чего эта работа не делает

- Правку самого паттерна закрытия захода: передача пишется тем же порядком.
- Роли совести, экзаменатора и редактора — задачи RT-918, RT-919 и RT-920.
