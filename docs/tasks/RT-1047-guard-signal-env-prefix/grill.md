# Разбор просьбы

## Просьба владельца, дословно

> почини дыру в признаке гарда

Сказано после того, как заход выяснил замером, чем именно гард был обойдён. До этого владелец
велел: «не делай никаких работ пока не выяснишь как ты обошёл гард».

## Откуда взялась просьба

Коммит `69c42f9f` уехал в главную ветку с подписью, набранной по памяти: имя учётной записи
верное, число служебного адреса чужое. Хостинг сопоставляет такой адрес по числу, и коммит
приписан постороннему человеку. Нашёл это владелец, читая историю.

Гард подписи заведён как раз против этого и предмет судит верно. До предмета дело не дошло: он
не узнал в команде вызов пуша.

## Что выяснено замером до просьбы

Признак вызова у гардов один и тот же:

```
(^|[;&|(]|&&|\|\|)[[:space:]]*<команда>([[:space:]]|$)
```

Он ищет команду в начале строки либо сразу за разделителем. Присваивание переменной окружения
перед именем команды под это не подпадает.

| Команда                                     | Признак |
| ------------------------------------------- | ------- |
| `git push origin <ветка>`                   | ловит   |
| `GH_TOKEN="$TOKEN" git push origin <ветка>` | мимо    |
| `gh pr create --draft`                      | ловит   |
| `GH_TOKEN="$TOKEN" gh pr create --draft`    | мимо    |
| `GH_TOKEN="$TOKEN" gh pr ready <номер>`     | мимо    |
| `GH_TOKEN="$TOKEN" gh pr merge <номер>`     | мимо    |

Последняя строка дороже прочих: запрет на слияние агентом снимается подстановкой токена.

Форму с подстановкой требует соседнее правило того же набора — иначе из текста команды не
видно, кто её делает. То есть форма, обязательная по одному требованию, снимает проверку по
другому.

## Ответы владельца

| Вопрос                                       | Ответ                                                        |
| -------------------------------------------- | ------------------------------------------------------------ |
| Чинить дыру или только разобрать?            | «почини дыру в признаке гарда» — чинить                      |
| Что делать с коммитом в главной ветке?       | не сказано; заход не трогает и ждёт слова                    |
| Чинить один гард подписи или признак вообще? | сказано «в признаке», а признак общий — чинятся все носители |

## Решения захода и доводы

- **Чинится признак, а не гард подписи.** Владелец назвал предметом признак. Замер показал, что
  тот же образец несут десять хуков, и слепота у них общая: починка одного оставила бы обойдённым
  запрет слияния.
- **Признак ошибается в сторону лишнего срабатывания.** Гард, не узнавший вызов, молчит и
  выглядит исправным; гард, сработавший на лишнем, виден сразу и правится.
- **Правка идёт в ресурс пакета.** Файлы несут шапку раскладки, и правка разложенной копии
  теряется на первой же раскладке.
- **Коммит с чужой подписью в главной ветке этой работой не трогается.** Починка его —
  переписывание истории с силовой отправкой, а это рвёт основание у открытых веток и рабочих
  копий соседнего захода. Решение владельца, и он его не сказал.

## Деление работ

Гарды в этом заходе ведёт соседняя рабочая копия. Работу отдал владелец прямо, поэтому она
делается здесь; соседнему заходу это сказано.

## Находка при заведении папки

Папка задачи собирается копией образца, и копия уносит шапку раскладки. Гард места правки
читает шапку и отбивает первую же правку рабочего файла, называя его разложенным ресурсом.
Снимается шапка руками — то есть команда заведения оставляет файлы, которые нельзя править,
пока не выполнишь лишний шаг, о котором она не говорит.
