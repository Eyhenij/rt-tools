# План

**Task:** RT-3696 · **Branch:** RT-3696-owner-touch-count
**Behaviour:** unchanged — правятся счётчик наблюдений пакета правил и команда дерева, код приложения не трогается

## Точки

- **A:** обращения к владельцу считаются однострочником `jq` из плана эпика; в наблюдениях 27 лишних
  строк `record-word`, одно сообщение во время хода записано до 7 раз; о чём владелец пишет сам, не
  видно — две трети обращений.
- **Эта задача доводит до:** команда `pnpm run owner:touches` печатает обращения к владельцу на задачу
  без повторов и раскладывает набранные сообщения по видам; счётчик пакета больше не пишет одно
  сообщение дважды.
- **Признак:** `pnpm run owner:touches -- --since 2026-11-21 --until 2026-11-26T11:00` даёт 43 задачи,
  итог 237, медиану 4 и 37 окон разрешений; сценарии счётчика зелёные. Задачи берутся из взятых
  (`task-taken`) и из тех, у кого есть обращения; задача без обращений идёт с нулём, медиана честная —
  при чётном числе средняя двух. Записи одного сообщения схлопываются по задаче, сессии, виду и
  секунде — у RT-3526 одно сообщение лежит до 5 раз в одну секунду. Виды набранных сообщений — поправка
  (тот же набор `RT_CORRECTION_PATTERNS`), «где стоим», новый приказ, прочее — появляются только у
  записей после раскладки счётчика в `tools/`: текст в файлы не попадает, и дни до эпика разметить нечем.
  «Прочее» — вид сверх слов владельца: туда идёт то, что не узнал ни один образец, и команда печатает его
  долю. Итог 237 несопоставим с новыми строками по повторам старой записи — у RT-3526 повторы
  разнесены по 22 секундам; медиана сопоставима: при схлопывании всех записей задачи и сессии в одну
  минуту итог 203, медиана та же 4. Веха мерится медианой. Цель вехи от базы 4 владелец выбирает в окне
  одобрения этого плана, и она записывается в план эпика.
- **Веха G эпика:** медиана обращений на задачу не выше числа, которое владелец выберет в окне одобрения
  этого плана, и окон разрешений не больше 5 за шесть дней после слияния эпика; число записывается в план
  эпика шагом 2.5.
- **Метрика:** обращения к владельцу на задачу, медиана; до эпика 4 на 43 задачах, должна снижаться.

## Решение

| Часть | Что выбрано |
| --- | --- |
| Модули | `projects/agent-kit/assets/checks/record-count.mjs:ownerWords` — сообщение во время хода, повторённое тем же текстом в пределах одного хода, считается один раз, а два настоящих одинаковых сообщения в разных ходах — дважды; `projects/agent-kit/assets/checks/record-count.mjs:aboutOf` — вид набранного сообщения по образцам слов: поправка — по тому же набору `--patterns`, «где стоим», новый приказ, прочее; `projects/agent-kit/assets/checks/record-turn.mjs:observationsOf` — пишет вид полем `about`; `tools/owner-touches.mjs:countTouches` — считает обращения на задачу из строк наблюдений, каждую различную строку один раз |
| Зависимости | `record-turn.mjs` импортирует `record-count.mjs`; `tools/owner-touches.mjs` не импортирует пакет, а читает файлы наблюдений; `record-count.mjs` по-прежнему никого не импортирует |
| Зацепление | `projects/agent-kit/assets/checks/record-count.mjs` исходящие 0 → 0; `projects/agent-kit/assets/checks/record-turn.mjs` исходящие 1 → 1; `tools/owner-touches.mjs` исходящие 0 → 0, файл новый; циклов нет; импортов мимо входа нет |
| Паттерны | паттерна нет: две функции и одна команда, подсчёт — простая свёртка строк; отброшено: общий модуль чтения с `session-time` — тот читает журналы, а не наблюдения |
| Термины | обращение к владельцу и вид сообщения определены в плане эпика `docs/plans/owner-touches.md`; новых слов словаря нет |
| Данные | строки наблюдений `.claude/rt-kit/observations/*.jsonl`: `record-menu`, `record-word` с `kind` typed и queued, `guard-ask`, `record-interrupt`; строка-повтор считается один раз; строка без задачи `RT-` в медиану не входит; битая строка пропускается и считается. SC-AK-2004, SC-AK-2005, `projects/agent-kit/tests/record-count.test.sh`; SC-AK-2006, `tools/tests/owner-touches.test.sh` |
| Границы | текст разговора не попадает в файл — из сообщения уходит только вид; старые строки наблюдений читаются как были; формат строк не меняется, поле `about` добавляется |
| Приоритет | точность счёта важнее скорости: веха меряется этой командой; разбор всех наблюдений за секунды |
| Бюджет | `projects/agent-kit/assets/checks/record-count.mjs` плюс 30; `projects/agent-kit/assets/checks/record-turn.mjs` плюс 3; `tools/owner-touches.mjs` до 140 строк; новых файлов кода: 1; новых зависимостей: 0 |

### 2. Команда измерения

- **Steps:**
    1. Команда считает обращения на задачу без повторов строк
       Check: `set -o pipefail; node tools/owner-touches.mjs --since 2026-11-21 --until 2026-11-26T11:00 --json | jq -c '{tasks,total,median,windows}'` → `{"tasks":43,"total":237,"median":4,"windows":37}`
    2. Сценарии команды
       Check: `set -o pipefail; bash tools/tests/owner-touches.test.sh 2>&1 | tail -1` → /, 0 провалов$/
    3. План эпика называет команду вместо однострочника и базу 43 / 237 / 4
       Check: `grep -c 'pnpm run owner:touches' docs/plans/owner-touches.md` → >= 1
    4. Команда печатает таблицу видов с долей «прочего»
       Check: `set -o pipefail; node tools/owner-touches.mjs --json | jq -c '.kinds|keys'` → `["correction","order","other","status"]`
    5. Цель вехи по слову владельца записана в план эпика
       Check: `grep -cE 'Цель вехи — слово владельца: медиана не выше [0-9]' docs/plans/owner-touches.md` → >= 1
    6. В плане эпика не осталось старой базы и старой цели
       Check: `! grep -qE 'медиана 5|не больше 3' docs/plans/owner-touches.md` → exit 0
- **Readiness sign:** команда даёт записанный ответ плана эпика.
- **Verified by:** `pnpm run -s owner:touches -- --since 2026-11-21 --until 2026-11-26T11:00` — 43 задачи,
  237, медиана 4, 37 окон; в плане эпика база пересчитана с 5 на 4.
