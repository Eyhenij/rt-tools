# Замысел

**Задача:** RT-788 · **Ветка:** RT-788-styles-check-package-rules
**Поведение:** не меняется — правка идёт в проверку дерева, её сценарии и список известного;
ни одного приложения дерева она не задевает, а договорённость о поведении самой проверки живёт
в спеке поддомена и дописывается этой же веткой.

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## Что считается сделанным

- Класс, чьё правило объявлено в пакете, подключённом самим приложением, расхождением не
  считается: объявления добираются разрешением модуля, а каталог зависимостей в корни
  исходников не попадает.
- Разросшийся долг называется своим родом — перечисляются добавившиеся файлы; указания «строку
  убрать» при этом нет, и новая строка не предлагается. Сократившийся перечень называется так
  же, своим родом.
- Оба рода закрыты сценариями в `docs/specs/agent-kit/checks/scenarios.md` и набором
  `projects/agent-kit/tests/checks-styles.test.sh`; до правки набор на них краснеет, после —
  зелёный.
- В дереве проверка зелёная, список известного не вырос ни на строку и сократился на то, что
  перестало быть расхождением.

## Этапы

### 1. Сценарии обоих родов записаны до кода

- **Что делается:** в `docs/specs/agent-kit/checks/scenarios.md` заводятся сценарии на правило
  из подключённого пакета и на изменившийся перечень файлов — с новыми номерами, не занимая
  номеров снятых; в `spec.md` поддомена дописываются правила, которым они отвечают, а в
  `implementation.md` — привязки.
- **Признак готовности:** каждый новый сценарий несёт пометку «Не покрыто» с причиной, пока
  набор не заведён.
- **Чем проверяется:** `npm run check:specs`.

### 2. Набор сценариев заведён и краснеет на нынешней проверке

- **Что делается:** `projects/agent-kit/tests/checks-styles.test.sh` по образцу соседних
  наборов: своё дерево на время прогона, случай на сценарий, идентификатор сценария в заголовке.
- **Признак готовности:** набор гоняется и падает ровно на тех случаях, которые описывают оба
  дефекта, а остальные его случаи зелёные.
- **Чем проверяется:** `bash projects/agent-kit/tests/checks-styles.test.sh`.

### 3. Правило из подключённого пакета читается объявлением

- **Что делается:** в источнике проверки строки `@use` и `@forward` из файлов стилей дерева
  разбираются, спецификатор пакета разрешается разрешением модуля, найденный файл обходится
  наравне с исходниками. Обход односложный: подключения внутри пакетного файла не разбираются.
- **Признак готовности:** случай набора на пакетное правило стал зелёным, каталог зависимостей
  в корни исходников не попал.
- **Чем проверяется:** набор сценариев и прогон проверки в дереве.

### 4. Изменившийся перечень файлов назван своим родом

- **Что делается:** расхождение сверяется по имени элемента, а не по склеенному ключу; рост
  перечня печатается как разросшийся долг с добавившимися файлами, сокращение — как
  сократившийся, с тем, что из строки пора убрать. Указание «строку убрать» остаётся только
  там, где класс подкреплён правилом.
- **Признак готовности:** случаи набора на рост и на сокращение зелёные, взаимоисключающей пары
  указаний не выдаётся ни в одном из них.
- **Чем проверяется:** набор сценариев.

### 5. Правка разложена в дерево, список известного сокращён

- **Что делается:** `pnpm run agent-kit:sync`, прогон проверки в дереве; строки списка, которым
  больше ничего не отвечает, снимаются.
- **Признак готовности:** проверка зелёная, список известного не вырос ни на строку, число
  снятых строк названо.
- **Чем проверяется:** `node tools/check-styles.mjs`, `pnpm run agent-kit:check`.

### 6. Тексты приведены к сделанному, работа отдана на разбор

- **Что делается:** перечитываются правило `styling-bem` — граница проверки описана там — и
  раздел «Что не входит» спека поддомена; открывается PR черновиком.
- **Признак готовности:** гейт пуша зелёный, PR открыт с метками и строкой связи, задача
  переставлена в колонку разбора.
- **Чем проверяется:** набор гейта пуша, `npm run check:board`, `npm run check:docs`.

## Чего эта работа не делает

- **Не разбирает сами сорок восемь классов.** Это RT-809, четвёртая задача эпика.
- **Не разбирает подключения внутри пакетного файла.** Обход односложный — так предложено
  записью; объявленным считается то, что приложение назвало само.
- **Не добавляет каталог зависимостей в корни исходников.** Их читают ещё четыре проверки, и
  пакет пошёл бы под сверку повторов, единообразия, сценариев и слоёв.
- **Не поднимает версию пакета и ничего не публикует.** Публикация идёт своим потоком и словом
  владельца.
