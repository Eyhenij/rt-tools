# Plan

**Task:** RT-3678 · **Branch:** RT-3678-kit-weight-single-count
**Behaviour:** unchanged — «Починить сторож»: меняется только проверка веса, кит и приложения не меняются

## Points

- **A:** проверка веса считает стили и шаблоны каждого компонента дважды и не связывает файлы кита. Набор на старте показан 316864 байта. Настоящая сборка приложения этого набора даёт 195263.
- **This task reaches:** проверка показывает собственные байты кита после связывания, как их считает сборка приложения; в плане эпика стоят пересчитанные веса версий и закрытых задач.
- **Sign:** `pnpm run check:kit-weight` проходит с порогом от 185000 до 197000 байт; в плане эпика есть раздел «Пересчитанный вес».
- **Milestone G of the epic:** проверке веса, которая держит вес кита в наборе проверок, можно верить.
- **Metric:** расхождение проверки с разовой сборкой приложения на том же `dist`: было 62 % (316864 против 195263), станет не больше 0,5 %.

## Decision

| Part | What is chosen |
| --- | --- |
| Modules | `tools/check-kit-weight.mjs:linkFiles` — плагин esbuild: каждый файл `.mjs` и `.js` сборки проходит преобразование приложения, лишнее оно пропускает само. `tools/check-kit-weight.mjs:unlinkedMarks` — ищет в коде набора строки `ngDeclare`, `setClassMetadata`, `ngDevMode`; найденное — отказ `measure`. `tools/check-kit-weight.mjs:measure` берёт каталог собранного пакета параметром (по умолчанию `dist/ui-kit-v2`), ключ `--package` с `--print` меряет любой другой каталог |
| Dependencies | `JavaScriptTransformer` из `@angular/build/private` через уже стоящий `createRequire`, с `sourcemap: false` и `advancedOptimizations: true`, как в продакшен-сборке приложения: без второй настройки набор на 2,5 % тяжелее, и остаток это не поймает. Кэша нет, поэтому хэш не нужен; новых пакетов нет |
| Coupling | `tools/check-kit-weight.mjs` outgoing 6 → 7: добавляется только `@angular/build/private` |
| Patterns | no pattern: один плагин и одна функция проверки остатка, выделять нечего |
| Terms | новых слов нет |
| Input | файлы `dist/ui-kit-v2/fesm2022`; переменная `RT_KIT_WEIGHT_NO_LINK=1` выключает связывание для сценария отказа. Отказ — остаток служебной строки или преобразование не поднялось. Сценарии в `tools/tests/check-kit-weight-live.test.sh` идут по настоящему пути измерения; номера нет: проверки дерева не описаны спеком, и сценарии называются словами |
| Bounds | состав набора, формат порога, команды и коды возврата не меняются; внешние пакеты в набор по-прежнему не входят |
| Priority | числа, близкие к сборке приложения, важнее независимости от частного входа пакета; поломка входа обязана быть громкой |
| Budget | `tools/check-kit-weight.mjs` плюс 60 строк; new code files: 0; new dependencies: 0 |

## What counts as done

- В коде набора, который меряет проверка, нет строк `ngDeclare`, `setClassMetadata`, `ngDevMode`.
- Без связывания проверка отказывает и называет остаток; это держит сценарий по настоящему пути измерения.
- Стиль компонента лежит в коде набора один раз, и это держит второй сценарий.
- Проверка один раз сверена со сборкой приложения на том же `dist`: расхождение не больше 0,5 %. В ходе задачи и в разделе эпика записаны вход пробного приложения, настройки `buildApplication`, список внешних пакетов, команда, версия Angular и оба числа.
- Порог переписан командой `pnpm run check:kit-weight -- --write`.
- В плане эпика есть раздел «Пересчитанный вес»: набор и части для 0.51.0, 0.52.0, до RT-3645, после RT-3645 и после RT-3646, байты и gzip, у каждой колонки источник и команда замера. Колонка после RT-3646 равна новому порогу. 0.51.0 и 0.52.0 берутся из пакетов npm, промежуточные состояния собираются в этой рабочей копии из названных коммитов.
- Старые числа в разделах «Что даёт», «Точки» и в итоге RT-3645 названы завышенными и ссылаются на новый раздел; архивные записи не правятся.
- Раздел называет, что меняется в целях: рост набора в 0.52.0 меньше, цель popover больше всего его роста, весь рост input стоит у нижней границы цели RT-3647, часть выигрыша — ушедшая из набора часть `button`, и сколько роста ещё не возвращено.
- Для каждой выросшей в 0.52.0 части раздел называет задачу, которая вернёт рост, или пишет «причина не установлена, задачи нет».
- Раздел пишет, что RT-3647 не начинается, пока владелец не назвал цель по пересчитанным числам; эти числа владелец получает вопросом после задачи.
- Раздел называет, что число проверки — верхняя граница: взяты все экспорты частей, Angular и прочие внешние пакеты не входят.
- Строка RT-3678 есть в составе эпика.

## Stages

### 1. Проверка веса меряет то, что считает сборка приложения

- **Steps:**
    1. Проверка связывает файлы кита преобразованием сборки приложения
       Check: `set -o pipefail; pnpm exec nx build @rt-tools/ui-kit-v2 --skip-nx-cache >/dev/null 2>&1 && pnpm run build:tokens-v2 >/dev/null 2>&1 && node --input-type=module -e "const { measure } = await import(process.cwd() + '/tools/check-kit-weight.mjs'); const r = await measure(); const parts = ['select','menu','input','icon','popover','dialog','bottom-sheet']; console.log(r.total >= 185000 && r.total <= 197000 && parts.every((p) => r.parts[p] > 1000))"` → `true`
    2. Остаток служебного вызова назван отказом, и это держат два сценария по настоящему пути
       Check: `set -o pipefail; VERBOSE=1 bash tools/tests/check-kit-weight-live.test.sh 2>&1 | grep -cE '^  ok +(without linking the check refuses and names the leftover|a style of a kit component lands in the set once)'` → = 2
    3. Порог записан по новому измерению
       Check: `set -o pipefail; pnpm run check:kit-weight >/dev/null 2>&1 && node -p "const t = require('./tools/kit-weight-threshold.json'); t.total >= 185000 && t.total <= 197000"` → `true`
    4. В плане эпика стоят пересчитанные веса версий и закрытых задач
       Check: `set -o pipefail; awk '/^## Пересчитанный вес$/{f=1;next} /^## /{f=0} f' docs/plans/kit-presets-by-demand.md | grep -oE '0\.51\.0|0\.52\.0|cafe965b1|c315de61b|675e9c84b|184366|203182|194999' | sort -u | wc -l | tr -d ' '` → = 8
- **Readiness sign:** проверка проходит с новым порогом, без связывания отказывает, а план эпика называет пересчитанные веса и что они меняют.
- **Verified by:** `bash tools/tests/check-kit-weight-live.test.sh`, `pnpm run check:all`, набор перед пушем; отдельно разовая сверка вручную со сборкой приложения, её способ и числа — в ходе задачи.

## What this work does not do

- Не снижает вес кита: это делают RT-3647…RT-3650.
- Не меняет состав набора и формат порога.
- Не меняет цели закрытых задач и номера выпусков: новую цель RT-3647 и посылку эпика называет владелец по пересчитанным числам.
- Не меряет сборки потребителей и их бюджеты.
- Не проверяет свежесть `dist` перед замером: это отдельная находка.
