# Разбор

## Просьба владельца

> изучи https://ngdoctor.dev/, прогони проверки и заведи эпик по исправлению всех замечаний, бери в работу

Просьба эпика RT-3476. По ней заведена задача RT-3478: находки `inner-html` (4 ошибки) и
`security-bypass` (3 предупреждения). Слово владельца 22.11.2026: «Продолжи работу по эпику ng
doctor». Решение эпика от 21.11.2026: находки, которые спорят с соглашениями дерева, — «Подогнать
код», правила в настройке не выключаются.

## Что уже есть в дереве

- `apps/chat-widget/src/lib/chat-widget.element.ts:340` — виджет чата рисует себя целиком строкой
  через `innerHTML` теневого корня. Шаблоны собраны строками; текст реплик вставляется в них.
- `projects/cms-angular/admin/src/lib/editor/cms-editable.directive.ts:23` и `:28` — правка блока
  в contenteditable: разметка блока кладётся в элемент один раз, пустой текст очищает элемент.
- `projects/ui-kit-v2/src/lib/components/icon/rt-icon.registry.ts:144` — реестр значков кладёт
  внутренности SVG-файла кита в `<symbol>` спрайта. Файлы — свои ассеты кита.
- `projects/core/src/lib/pipes/sanitize.pipe.ts:15` — опубликованный пайп `sanitize` пакета
  `@rt-tools/core`. Его назначение и есть обход очистки: он отдаёт `bypassSecurityTrustHtml`. В
  дереве его никто не вызывает, кроме его теста.
- `projects/cms-angular/admin/src/lib/editor/cms-editor-embed/cms-editor-embed.component.ts:44` —
  превью встроенной ссылки в редакторе cms: адрес, введённый редактором, с `https://`, идёт в
  iframe через `bypassSecurityTrustResourceUrl`.
- `projects/ui-kit-v2/src/lib/components/data-table/cell/rt-data-table-cell.component.ts:162` —
  стиль значка ячейки, посчитанный `iconTransform` колонки, идёт через `bypassSecurityTrustStyle`.
  Angular не очищает стили с версии 10: строка стиля привязывается и без обхода.

## Что уже говорят правила

- Решение эпика: правила Angular Doctor не выключаются; если правило нельзя выполнить, задача
  приносит это владельцу меню.
- Задача RT-3478: каждое место переписать без прямой записи `innerHTML` и без
  `bypassSecurityTrust*`, а где без них нельзя — показать тестом, что вход очищен.
- Выпуск кита — отдельное решение владельца; задача, меняющая видимое потребителю, называет это
  в своём PR.

## Вопросы и ответы

**Пайп `sanitize` из опубликованного `@rt-tools/core` ничего не чистит, а снимает защиту Angular с
HTML. Что с ним сделать?**
«Проверь во всех проектах на этой машине где и как используется этот пайп». Проверка 22.11.2026:
пакет `@rt-tools/core` ставят три проекта на машине, ни один не вызывает ни `SanitizePipe`, ни
`| sanitize`. После этого ответ: «Убрать пайп».

**Какие адреса пускать в превью встроенной ссылки редактора cms?**
«Любой https, проверенный».

**Превью честно без обхода защиты не сделать: Angular не пускает строку в `src` у iframe, а запись
адреса мимо Angular — тот же обход, спрятанный от Angular Doctor. Как поступить?**
«Оставить обход за проверкой (Recommended)»: адрес разбирается как URL, пускается только https,
тест это показывает, и только потом идёт доверие Angular. Одна находка `security-bypass` остаётся
и считается в пороге; оценка 100 в конце эпика будет с этой оговоркой.

## Решения

- **Пайп `sanitize` удаляется из `@rt-tools/core`** — слово владельца; вызовов нет ни в дереве, ни
  в проектах на машине. Отклонено: оставить пайп с настоящей очисткой — имя без вызовов не нужно.
- **Стиль значка ячейки таблицы привязывается строкой без обхода** — Angular не очищает стили с
  версии 10, и `bypassSecurityTrustStyle` ничего не даёт. Вид не меняется.
- **Пример `| sanitize` уходит из README core, удаление названо в коммите и в PR** — журнал
  изменений core пишет конвейер выпуска по коммитам.
- **Реестр значков разбирает SVG через `DOMParser`, убирает `script` и атрибуты `on*` и переносит
  узлы** — адрес файлов задают токены `RT_ICONS_BASE_URL` и `RT_ICONS_MATERIAL_BASE_URL`, их может
  заменить потребитель, поэтому «файлы свои» не довод. Вид не меняется.
- **Превью встраивания cms оставляет `bypassSecurityTrustResourceUrl` за разбором URL** — слово
  владельца; тест показывает, что https доходит до `src`, а `javascript:`, `http:` и неразборный
  адрес — нет. Отклонено: запись адреса мимо Angular — тот же обход, спрятанный от проверки.
- **Правка блока cms очищает разметку DOMPurify с белым списком вставки и кладёт узлы** — очистка
  Angular снимает `style` у выделений, и жирный с курсивом пропали бы. DOMPurify с тем же белым
  списком уже чистит вставку (`editor-paste.function.ts`). Пустой текст очищает элемент через
  `replaceChildren()`.
- **Виджет чата строит разметку узлами DOM, тексты идут в `textContent`** — текст реплики уже
  экранирован, а слово об отказе с пределом от сервиса и сторона реплики — нет; тест целит в них.
  Вид виджета не меняется.
- **Порог записывается на результате задачи, и ни одно правило в нём не растёт против порога
  ветки эпика** — иначе запись порога проглотила бы новые находки.

**Описание фичи:** не нужно — виджет чата, редактор cms, значки и таблица кита выглядят и ведут себя
для человека как прежде; удаление пайпа — решение владельца «Убрать пайп», записанное выше.

## Что осталось неясным

- Как именно Angular Doctor 0.3.0 узнаёт запись `innerHTML`: по присваиванию свойства или по любому
  упоминанию. Это выясняет первый шаг плана замером, не вопрос владельцу.
