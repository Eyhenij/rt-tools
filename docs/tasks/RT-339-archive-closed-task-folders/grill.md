# Разбор просьбы

**Задача:** RT-339 · **Ветка:** RT-339-archive-closed-task-folders

## С чего началось

Задача #336 завела гард, отбивающий слияние, пока ветка везёт папку своей задачи. Её
собственный отчёт #337 был слит через веб-интерфейс — гард видит только команды агента, — и
папка `docs/tasks/RT-336-guard-task-folder-on-pr/` уехала в главную ветку.

Сверка очереди работ, научившаяся в той же задаче видеть вложенные папки, назвала сразу шесть
папок закрытых задач. Владелец завёл две задачи: #338 на ярус проверки в CI и эту — на разбор
накопленного.

## Что уже есть в дереве

- **Механика разбора описана правилом** `task-flow-close`, раздел «Папка задачи разбирается»:
  `grill.md` — в архив всегда (ответы владельца невосстановимы), `progress.md` — в архив,
  если в нём есть решения по ходу с причинами, иначе удаляется, `plan.md` — удаляется.
  Уезжающее складывается одним файлом с говорящим именем, а не папкой из трёх.
- **Закон о ведении работы** велит переносить в архив то, что объясняет принятые решения.
- **Каталога `docs/archive/` в дереве нет вовсе** — его ещё ни разу не заводили. Образца,
  с которого снять раскладку, нет; образец — сам порядок из `task-flow-close`.
- **У всех шести папок полный набор** из `grill.md`, `plan.md`, `progress.md`.
- **Гард поставки требует** от ветки, снёсшей папку, прибавить запись в архив. Что именно
  перенесли, он не судит — это смотрит владелец на ревью.

Шесть папок, названных сверкой:

```
docs/tasks/RT-317-agent-kit-task-key/
docs/tasks/RT-324-sync-agent-kit-040/
docs/tasks/RT-326-ui-kit-v2-visual-snapshots/
docs/tasks/RT-328-ui-kit-v2-snapshot-baselines/
docs/tasks/RT-336-guard-task-folder-on-pr/
docs/tasks/chore/312-sync-agent-kit/
```

## Ответы владельца

**Что уезжает в архив из каждой папки.** По правилу, пофайлово: `grill.md` всегда;
`progress.md` — только если в нём есть решения по ходу с причинами; `plan.md` удаляется.
Каждая папка читается, и выбор по `progress.md` показывается в отчёте.

**Как называются записи в архиве.** `RT-<номер>-<slug>.md` — тем же номером, что у задачи,
ветки и отчёта: читается как одно, и от записи есть дорога к PR и коммитам. Правило требует
«говорящее имя» и один файл вместо папки из трёх; номер этому не мешает.

**У архива есть README.** Короткий: что сюда попадает, что нет, и строка на каждую запись.
Без указателя архив становится свалкой — ровно тем, от чего правило предостерегает.

**Поведение не меняется.** Правка только в `docs/**`, код не трогается. Договорённость о
продукте не требуется — подтверждено владельцем.

**Шесть папок разбираются одной веткой.** Делить стоит то, что откатывается порознь; шесть
папок порознь никто откатывать не будет.

**Чем видно, что закрыто:** `npm run check:board` молчит по папкам; в `docs/archive/` есть
запись на каждую из шести работ, и в каждой — слова владельца; `npm run check:docs` зелёный.

- **Правка гарда папки и правил.** Гард уже стоит; ярус на веб-слияние — задача #338.

  переезда, и правится только вместе с признанием, что описывал неверно.
- **Выпуск пакета в реестр** — отдельным запуском позже.
