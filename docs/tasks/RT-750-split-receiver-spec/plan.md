## Этапы

### 1. Префикс принадлежит домену вместе с поддоменами

- **Что делается:** сверка спеков перестаёт считать владельцем префикса отдельный каталог.
- **Признак готовности:** сценарии с общим префиксом законны в поддоменах одного домена и
  по-прежнему незаконны в чужом.
- **Чем проверяется:** `npm run check:specs`.

### 2. Домен поделён на поддомены

- **Что делается:** правила, сценарии и привязки разъезжаются по четырём поддоменам, каждый со
  своим полным набором разделов; корневой спек остаётся с общим.
- **Признак готовности:** ни один файл не длиннее предела, ни одно правило и ни один сценарий
  не потерялись при переезде.
- **Чем проверяется:** `npm run check:specs`, пересчёт правил, сценариев и привязок до и после.

### 3. Тексты приведены к сделанному

- **Что делается:** корневой спек называет поддомены и то, чем держится общий префикс.
- **Признак готовности:** читатель находит нужный поддомен, не открывая всех четырёх.
- **Чем проверяется:** `npm run check:docs`, чтение глазами.

## Чего эта работа не делает

- Не пересчитывает номера сценариев: номер связывает сценарий с заголовком теста.
- Не переписывает самих правил: они переезжают дословно.
- Не делит спеки других доменов: предел перерос только этот.
- Не берёт задач вне эпика RT-733.
