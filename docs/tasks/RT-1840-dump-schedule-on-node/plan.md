# Замысел

**Задача:** RT-1840 · **Ветка:** RT-1840-dump-schedule-on-node
**Поведение:** не меняется — эпик RT-733 разбирает приёмник, а не расширяет его: расписание
подтверждает обещанное замыслом эпика. Кода приложения правка не задевает: сценарий дампа,
файл задания, конвейер выкатки и тексты.

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## Что считается сделанным

- Выгрузка `save` оставляет на узле семь последних дампов, число — переменная сценария.
- В `deploy/` лежит файл задания расписания: раз в сутки ночью `dump.sh save` с выводом в
  журнал рядом с дампами.
- Шаг конвейера выкатки ставит это задание в расписание пользователя узла, не трогая чужих
  строк; повторная выкатка не удваивает строку.
- Спек узла несёт правило о расписании с привязкой и сценарий; описание прода называет, чем
  проверить расписание на узле.

## Этапы

### 1. Предел хранимых дампов

- **Что делается:** `save` после выгрузки удаляет дампы старше семи последних; число —
  переменная `KEEP_DUMPS`.
- **Признак готовности:** после восьмой выгрузки в каталоге семь файлов, самый старый снят.
- **Чем проверяется:** `bash -n deploy/dump.sh` — код 0; на местной копии состава прода восемь
  вызовов `save` подряд оставляют семь файлов.

### 2. Задание расписания и шаг конвейера

- **Что делается:** файл `deploy/dump.crontab` со строкой задания; шаг выкатки после переноса
  файлов сливает её в расписание пользователя узла: прежние строки без имени сценария
  остаются, своя строка стоит один раз.
- **Признак готовности:** конвейер разбирается как yaml; строка слияния расписания, прогнанная
  дважды на местной копии, оставляет одну свою строку и все чужие.
- **Чем проверяется:** `node -e` с `js-yaml` по `.github/workflows/deploy.yml` — код 0;
  `bash` со сценарием слияния на временном файле расписания — одна своя строка после двух
  прогонов.

### 3. Тексты

- **Что делается:** спек узла получает правило о расписании и пределе хранимых дампов с
  привязкой и сценарий SC-MB-286; описание прода называет расписание и команду проверки
  на узле.
- **Признак готовности:** сверка спеков без новых расхождений.
- **Чем проверяется:** `npm run check:specs` — код 0.

## Чего эта работа не делает

- Не увозит копии дампа с узла: спек узла называет это отдельной работой.
- Не ставит задание на узел рукой: оно приезжает выкаткой после слияния, и проверка на узле —
  `ssh message-bus 'crontab -l'` — остаётся на шаге владельца, как и проба дампа из RT-1839.
