# Разбор

Работа начата не из груза приёмника, а из разбора закрытой задачи RT-3022 по правилам. Находки
лежат в `.claude/rt-kit/proposals/2026-10-31-RT-3022-interface-review-skill.md`.

## Просьба владельца

На вопрос, что делать с четырьмя правками правил из разбора RT-3022, владелец выбрал:

> Все четыре одним PR

И следом написал:

> делай все правки и гони проверки снова

> и гони код ревью тоже

## Что уже есть в дереве

- `projects/agent-kit/assets/skills/write-a-skill.md` — навык пакета о форме навыка: 113 строк,
  5 056 символов. Предел описания там — 1024 символа.
- Проверка описаний пакета `tools/check-descriptions.mjs` отказывает описанию длиннее 300
  символов у любого навыка.
- `.claude/skills/agent-kit-source/SKILL.md` — навык этого дерева о правке исходников пакета, без
  заголовка раскладки: 110 строк, 6 670 символов.
- `.claude/rt-kit/gate-map.sh` — ветка `*/projects/agent-kit/assets/skills/*` требует
  `spec-driven` и `agent-kit-source`, но не `write-a-skill`.

## Что уже говорят правила

- `spec-driven`: переносимый текст называет соседний ресурс с условием — проверку описаний в
  `write-a-skill` надо называть так же.
- `agent-kit-source`: правка ресурса пакета идёт по порядку «правка, сборка, раскладка».
- Правила о дословном переносе текста владельца нет нигде.

## Вопросы и ответы

**Что делать с четырьмя правками правил из разбора RT-3022?**
«Все четыре одним PR».

## Решения

- **Раздел о тексте владельца — в `write-a-skill`, а не в `agent-kit-source`.** Перенос чужого
  текста в навык верен для любого дерева, ставящего пакет. Отвергнуто: навык этого дерева —
  потребитель пакета такую ошибку повторит.
- **Ветка карты для навыков пакета выделяется из общей.** Законы, правила и образцы `write-a-skill`
  не требуют: их форму держит `spec-driven-rule`. Отвергнуто: добавить `write-a-skill` в общую ветку.

## Что осталось неясным

- Ничего.
