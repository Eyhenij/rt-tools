# Замысел

**Задача:** RT-1040 · **Ветка:** RT-1040-deploy-manual-in-rule
**Поведение:** не меняется — работа правит тексты слоя правил и надстройку дерева; ни выкатки,
ни конвейера она не трогает.

## След задачи

| Что                     | Где                                    |
| ----------------------- | -------------------------------------- |
| Конвейер выкатки        | `.github/workflows/deploy.yml`         |
| Надстройки дерева       | `.claude/rt-kit/overrides/rules/`      |
| Правило выкатки         | `.claude/skills/deploy-flow/SKILL.md`  |
| Правило поставки        | `.claude/skills/git-workflow/SKILL.md` |
| Компаньоны обоих правил | `implementation.md` рядом с каждым     |
| Сверка очереди работ    | `tools/check-board.mjs`                |

## Что считается сделанным

- Правило, прочитанное в этом дереве, называет выкатку ручной и говорит, чем она запускается.
- Ни один текст слоя правил в этом дереве не утверждает, что слияние выкатывает прод.
- Сверка очереди работ либо видит отставший прод, либо говорит прямо, что при ручной выкатке
  не видит его.

## Этапы

### 1. Надстройка дерева называет выкатку ручной

- **Что делается:** заводится `.claude/rt-kit/overrides/rules/deploy-flow.github.md`, которая
  замещает раздел имён и раздел применения закона в части выкатки: слияние прода не трогает,
  выкатка идёт ручным запуском, и назван способ спросить, что накачено.
- **Признак готовности:** разложенное правило говорит о ручной выкатке.
- **Чем проверяется:** `pnpm run agent-kit:check` — «разложенное сходится с пакетом»; в
  `.claude/skills/deploy-flow/SKILL.md` нет строки о том, что мерж выкатывает прод.

### 2. Правило поставки не повторяет то же утверждение

- **Что делается:** строка таблицы имён в `git-workflow` о том, что мерж запускает выкатку,
  замещается надстройкой дерева.
- **Признак готовности:** в разложенном правиле поставки этой строки нет.
- **Чем проверяется:** `grep -n 'запускает выкатку' .claude/skills/*/SKILL.md` — пусто.

### 3. Сверка очереди работ говорит о проде честно

- **Что делается:** сверка судит прод не по последнему прогону главной ветки, а по последней
  выкатке: сравнивается вершина главной ветки с коммитом последней успешной выкатки. Нет
  выкатки вовсе — так и говорится.
- **Признак готовности:** сверка называет расхождение прода числом коммитов.
- **Чем проверяется:** `npm run check:board` — строка о проде либо называет отставание, либо
  молчит при сошедшихся вершинах.

### 4. Набор гейта прогнан целиком

- **Что делается:** гоняются наборы пакета, сверки текстов и affected-набор.
- **Признак готовности:** всё зелёное.
- **Чем проверяется:** `bash projects/agent-kit/tests/run.sh` — «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

## Чего эта работа не делает

- Не заводит выкатку по мержу: как выкатывать прод — решение владельца о продукте, а не о
  тексте.
- Не правит `rules/deploy-flow.github.md` в источнике пакета: правило переносимое, и в дереве с
  автоматической выкаткой оно право.
- Не догоняет прод: выкатку уже сделал соседний заход по слову владельца.
