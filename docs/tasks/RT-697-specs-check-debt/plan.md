## Что считается сделанным

- `node tools/check-specs.mjs` не печатает ни одной строки видов «пустая привязка», «правило без
  привязки», «привязка без пункта».
- Утверждение, которому места в коде нет, стоит в открытых вопросах своего слоя, а не в правилах.
- Названо, чем красная сверка будет замечена: строкой в наборе гейта пуша либо шагом конвейера.
- Число расхождений в каждом коммите пересчитано командой, а не перенесено из тела задачи.

## Этапы

### 1. Компаньон `git-workflow` — 41 строка

- **Что делается:** привязки проставляются, безадресные утверждения уезжают в открытые вопросы.
- **Признак готовности:** сверка о `git-workflow` молчит.
- **Чем проверяется:** `node tools/check-specs.mjs | grep git-workflow`.

### 2. Компаньоны `task-flow`, `observability` — 43 строки

- **Что делается:** то же по двум следующим по величине долга.
- **Признак готовности:** сверка о них молчит.
- **Чем проверяется:** та же команда с их именами.

### 3. Остальные компаньоны и спек домена

- **Что делается:** оставшиеся одиннадцать компаньонов и `docs/specs/agent-kit`.
- **Признак готовности:** видов «пустая привязка», «правило без привязки» и «привязка без
  пункта» в выводе нет.
- **Чем проверяется:** полный прогон сверки.

### 4. Два непокрытых сценария и одна несходящаяся привязка

- **Что делается:** сценарии получают пометку либо тест, привязка — живое место.
- **Признак готовности:** обе строки уходят.
- **Чем проверяется:** полный прогон сверки.

### 5. Красное больше не молчит

- **Что делается:** сверка встаёт в набор гейта пуша либо объявляется исключением с причиной.
- **Признак готовности:** красная сверка отбивает пуш, и это подтверждено прогоном.
- **Чем проверяется:** заведомо красная привязка в фикстуре, прогон гейта.

## Чего эта работа не делает

- Не переписывает сами утверждения правил: это граница, заданная задачей.
- Не заводит паттернов трём правилам этого дерева, у которых их нет, — три строки другого вида.
- Не трогает разложенные копии на месте: их привязки правятся в ресурсе пакета.
