# Разбор

## Запрос владельца

Замечание владельца по пакету, дословно:

> В меню оператора фильтра показывается уже выбранный оператор. Кит строит operatorItems из всех
> операторов колонки и только помечает текущий как current. На v1 текущий оператор в меню не
> показывается: для Role Name с оператором Contains на dev в меню только «Equal». Нужно не выводить
> current-пункт или дать параметр, чтобы его скрыть. В приложении это решается только правилом
> display: none на классе кита, поэтому это правка для кита.

Следом: «почему блядь изменилась логика отображения опций для фильтров по сравнению спервым киом?» и
«поправь».

## Что уже есть в дереве

- Разметка первого кита ставит каждый пункт меню под условие «оператор не текущий».
- Второй кит с RT-2378 выводит все операторы колонки и помечает текущий входом `current`.

## Что уже говорят правила

- Правило описания таблицы `table-full-port` и сценарий SC-UKV-371 обещают «все, текущий помечен» —
  их и меняет эта работа.

## Вопросы и ответы

«поправь» — ответ на предложение вернуть поведение первого кита без отдельного параметра.

## Решения

- **Текущий оператор в меню не выводится, как в первом ките.** Параметра нет: у первого кита его
  нет, а приложению нужно именно это поведение.
- **Вход `current` у пункта меню остаётся** — общий вход пункта, меню оператора его больше не зовёт.

## Что осталось неясным

- Нет.
