## Что считается сделанным

- Скил слоя правил называет, что загруженное правило бывает показано не целиком и чем это
  проверяется, и почему обрыв бьёт по хвосту.
- Правило поставки называет, что рабочее дерево не опустошается ради прогона инструмента.
- Пределы длины и веса выдержаны, слог правленых файлов чист, раскладка сходится.

## Этапы

### 1. Статья о неполном тексте правила

- **Что делается:** статья в скил слоя правил — там, где сказано, как пакетный текст и надстройка
  складываются в один файл.
- **Признак готовности:** статья стоит, пределы выдержаны.
- **Чем проверяется:** `node tools/check-file-size.mjs` — длиннее предела 0.

### 2. Статья о рабочем дереве

- **Что делается:** статья в правило поставки о том, что сравнение с прежним состоянием делается
  на второй копии дерева, а не опустошением рабочей.
- **Признак готовности:** статья стоит, привязка в компаньоне названа.
- **Чем проверяется:** `npm run check:specs` — новых расхождений нет.

### 3. Раскладка и закрытие

- **Что делается:** правки разложены, тексты приведены, папка разобрана, заявка открыта черновиком.
- **Признак готовности:** раскладка сходится, набор зелёный.
- **Чем проверяется:** `pnpm run agent-kit:check && npm run check:all` — ни одной новой строки
  расхождения.

## Чего эта работа не делает

- Гардов не заводит: показанную длину текста машине не видно, а прятанье от законного
  переключения ветки формой команды не отличается.
- Порядок разделов при раскладке не трогает: перенос надстроек вперёд пакетного текста —
  отдельная работа и отдельное решение владельца.
