# Разбор просьбы

## Просьба владельца

Ночное распоряжение: брать в работу весь груз приёма, править самостоятельно, ветки держать
локально и ставить каскадом друг за другом.

## Записи груза

- `a742c53e62d8bb6e7b7a8d8dd65c64ede045097819e7d2786497b44fbfb87b72` — паттерн зовёт команду
  заведения задачи по имени и написан утверждением, без оговорки «если она заведена». Раскладка
  кладёт файл проверки под неё, а записи в манифесте потребителя не кладёт никто: дерево, взявшее
  пакет впервые, получает тексты, зовущие команду, которой у него нет. Исполнитель заменил её
  вызовами клиента хостинга, сделал три шага из четырёх и оставил карточку вне колонок на всё
  время работы — два коммита и два закрытых этапа.

## Шесть вопросов

1. **Что меняется для владельца.** Дерево, взявшее пакет впервые, не теряет третий шаг заведения
   задачи и не оставляет карточку вне колонок.
2. **Где это живёт.** Паттерн `git-workflow-commit` вида для этого хостинга — источник пакета.
3. **Чем это подтверждается.** Сверка раскладки, проверки адресов и слога.
4. **Что из этого правило, а что код.** Только текст паттерна: чем дерево зовёт заведение, машина
   не знает.
5. **Чего работа не делает.** Не заводит команду за дерево: манифест потребителя раскладке не
   принадлежит.
6. **Где ветка.** `RT-1709-missing-command-not-client`, каскадом от `RT-1708-finding-mid-stage`.
