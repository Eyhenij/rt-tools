## Что считается сделанным

- `POST /api/invites` выдаёт приглашение по имени, отвечает кодом один раз и закрыт входом
  человека: ни без входа, ни токеном дерева не открывается.
- В тулбаре раздела приглашений стоит кнопка «Пригласить дерево», и она открывает панель своим
  адресом в аутлете `ro`.
- Панель показывает выданный код с кнопкой копирования и сроком годности, остаётся открытой
  после выдачи, а список за ней уже несёт новую строку.
- Занятое имя — годным приглашением или заведённым деревом — отбивается с названной причиной, и
  введённое имя из поля не пропадает.
- Сценарии `SC-MB-154`…`SC-MB-162` покрыты спеками, `pnpm run check:specs` зелёная.

## Этапы

### 1. Операция выдачи в приёмнике

- **Что делается:** `POST /api/invites` в контроллере приглашений: имя из тела, проверка
  занятости имени годным приглашением и заведённым деревом, выпуск кода, запись хеша, ответ с
  кодом, именем и сроками. Доступ — вход человека.
- **Признак готовности:** спека контроллера покрывает выдачу, оба отказа занятости, отказ без
  входа и отказ по токену дерева; кода и хеша нет ни в одной строке журнала.
- **Чем проверяется:** прогон спек домена деревьев приёмника.

### 2. Слой чтения и записи в админке

- **Что делается:** вызов выдачи в службе запросов раздела, действие в сторе раздела, строки
  раздела в словаре админки, объявление маршрута панели рядом с маршрутом списка.
- **Признак готовности:** стор отдаёт состояние выдачи — идёт, выдано, отказ — и обновляет
  список после успеха; маршрут панели совпадает по форме с маршрутами панелей соседних
  разделов.
- **Чем проверяется:** прогон спек слоя данных раздела приглашений.

### 3. Панель создания и вход в тулбаре

- **Что делается:** компонент панели рядом со списочным экраном раздела, поле имени, кнопка
  выдачи, показ кода с копированием и сроком; кнопка «Пригласить дерево» в слоте тулбара
  раздела; пустое состояние называет кнопку вместо команды узла.
- **Признак готовности:** спека панели проходит все шесть её состояний из договорённости;
  закрытая и открытая заново панель кода не показывает.
- **Чем проверяется:** прогон спек панели и списочного экрана раздела.

### 4. Проверка на стенде и полный набор гейта

- **Что делается:** прогон стенда, выдача приглашения глазами и замером, прогон линтеров,
  спек, сборок и сверок дерева.
- **Признак готовности:** приглашение, выданное на стенде, годится для заведения дерева;
  набор гейта пуша зелёный целиком.
- **Чем проверяется:** `pnpm run serve:stand`, замер в браузере, `pnpm run check:all`,
  `pnpm run check:specs`.

### 5. Отдача работы

- **Что делается:** PR черновиком с телом по образцу, перевод задачи в разбор; после зелёного
  прогона — вливание договорённости в спеки поддоменов, разбор папки задачи, снятие черновика.
- **Признак готовности:** договорённости в предложенных на диске не осталось, сценарии стоят в
  спеках поддоменов прежними номерами, папка задачи разобрана.
- **Чем проверяется:** `pnpm run check:specs`, `npm run check:board`.

## Чего эта работа не делает

- Выдача и отзыв токена дерева из интерфейса — правило спека приёма остаётся в силе.
- Раздел деревьев в админке.
- Разбор устройства приёма: признак дерева, сверка признака с токеном, команды деревьев в
  строке запуска. Владелец назвал устройство неверным — работа по нему не заведена и ждёт его
  слова.
