# Разбор просьбы

## Просьба владельца

Ночное распоряжение: брать в работу весь груз приёма, править самостоятельно, ветки держать
локально и ставить каскадом друг за другом.

## Записи груза

- `1edcf971e4c6b56d99c6f149e9cdb1b31ef6c17ca4977fb4e36a6f3823846b4a` — двойник, переехавший из
  спеки в общий файл набора, вышел из-под исключения проверки повторов и столкнулся именем с
  настройкой чужого домена. Проверка покраснела на файле, которого правка не касалась, и разбор
  занял отдельный ход.

## Шесть вопросов

1. **Что меняется для владельца.** Красная проверка повторов на чужом файле перестаёт стоить
   отдельного хода.
2. **Где это живёт.** Паттерн `testing-e2e` — источник пакета.
3. **Чем это подтверждается.** Сверка раскладки, проверки адресов и слога.
4. **Что из этого правило, а что код.** Только текст паттерна: переезд двойника машина видит как
   обычную правку двух файлов.
5. **Чего работа не делает.** Не трогает саму проверку повторов и её список известного.
6. **Где ветка.** `RT-1714-fixture-move-duplicate`, каскадом от `RT-1713-board-read-after-write`.
