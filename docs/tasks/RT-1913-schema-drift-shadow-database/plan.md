## Что считается сделанным

- Проверка заводит теневую базу сама и на поднятой базе доходит до сравнения.
- Отказ о недоступном сервере отличается от отказа о ненайденной базе: первый — «негде
  проверить», второй — поломка проверки, и она о ней говорит.
- Шаг проверки стоит в конвейере, а не только в гейте пуша.
- Пробы пакета проверяют оба случая.

## Этапы

### 1. Теневая база заводится своей командой

- **Что делается:** после `DROP DATABASE IF EXISTS` идёт `CREATE DATABASE` тем же клиентом;
  комментарий о том, что база заводится сама, уходит.
- **Признак готовности:** на поднятой базе проверка доходит до сравнения и говорит о согласии
  схемы с цепочкой.
- **Проверяется:** `node tools/check-schema-drift.mjs` при поднятой базе — «the migrations and
  the schema match».

### 2. Отказ о недоступном сервере разведён с поломкой проверки

- **Что делается:** `P1001` при живом сервере больше не читается как «негде проверить».
- **Признак готовности:** отказ называет, что именно не сошлось, и не выдаёт зелёного.
- **Проверяется:** пробы набора пакета — `bash projects/agent-kit/tests/run.sh`.

### 3. Шаг проверки стоит в конвейере

- **Что делается:** описание конвейера получает шаг сверки схемы с цепочкой.
- **Признак готовности:** проверка, стоящая в гейте пуша, есть и в конвейере.
- **Проверяется:** `npm run check:gate-set` или разбор описаний конвейера — по тому, что дерево
  умеет.

### 4. Раскладка и тексты

- **Что делается:** `pnpm run agent-kit:sync`, спека поддомена проверок и её привязки.
- **Признак готовности:** `agent-kit sync --check` без расхождений, `npm run check:specs` тоже.
- **Проверяется:** `pnpm run agent-kit:check` и `npm run check:specs`.

## Чего эта работа не делает

- Не трогает саму цепочку миграций и схему: расхождения в них нет — это замерено рукой.
- Не заводит проверке своей базы на машине: адрес берётся оттуда же, откуда и брался.
