## Этапы

### 1. Разложенное догоняет пакет

- **Что делается:** `pnpm run agent-kit:sync` в чистом дереве, отдельным коммитом. RT-396
  привезла правки в исходники пакета, но разложенного за ними не погнала — 15 расхождений,
  из них три файла в дереве отсутствуют вовсе.
- **Признак готовности:** `pnpm run agent-kit:check` зелен на ветке до единой правки от руки.
- **Чем проверяется:** `pnpm run agent-kit:check`; в диффе коммита — только шапки раскладки и
  тела ресурсов, ни одного файла из `projects/`.

### 2. Материалы прошлого захода переезжают в ветку

- **Что делается:** каталог `docs/postmortems/` с README и записью от 13 августа, раздел
  «Разбор происшествий» в надстройке словаря — переносятся из корневого рабочего дерева, где
  лежат некоммиченными на чужой ветке.
- **Признак готовности:** файлы в индексе этой ветки; словарь после раскладки несёт три слова —
  «Происшествие», «Постмортем», «Механизм».
- **Чем проверяется:** `pnpm run agent-kit:sync` и чтение `docs/GLOSSARY.md`; `git diff` в
  корневом дереве по этим путям пуст.

### 3. Договорённость о продукте

- **Что делается:** `docs/specs/agent-kit/proposed/rules-layer-gaps/` — спек и сценарии на то,
  что меняется в поведении: связь ресурсов, отказ хука без профиля, вывод `doctor`, запись о
  происшествии, момент проверки хода с вопросом.
- **Признак готовности:** у каждого сценария номер с префиксом домена; на каждое изменение
  поведения есть сценарий, на который сошлётся заголовок теста.
- **Чем проверяется:** `pnpm run check:specs`; сверка с `grill.md` построчно.

### 4. Тексты потока работы — П-1…П-6

- **Что делается:** статья про очевидный ответ и статья про форму остановки в закон о ведении
  работы (П-1, П-4); список действий, которые исполнитель не делает сам, — статья закона и
  строка правила работы (П-5); абзац про уже выданный номер и перестановка шагов, кладущих
  образец, — в паттерн начала работы (П-2, П-3); шестая строка про отчёт — в паттерн
  возвращения к работе (П-6).
- **Признак готовности:** каждый из шести пунктов закрыт текстом в исходниках пакета; готовые
  формулировки из файла предложений подняты как есть или с доводом изменены.
- **Чем проверяется:** `projects/agent-kit/tests/texts.test.sh`; греп по закону и правилам —
  ни одного места, где требование стоит без противовеса.

### 5. Вопрос впереди разведки

- **Что делается:** две статьи в закон о ведении работы — вопрос задаётся после того, как ответ
  искали в дереве командой, и отрицание о дереве произносится только как вывод команды; замена
  ловушки про меню и абзац про гард разговора в правило работы; два абзаца в паттерн начала
  работы — чем подтверждается разведка и что рамка переданного текста не переносится; два блока
  в скил пакета — предложение работу не выправляет, признак по подстроке пути судит и внешнее;
  `rt_is_app_code_default` приводит путь к корню дерева; карта гейта знает заведение рабочего
  дерева; ловушка про новое рабочее дерево в правило поставки и раздел с именами — в компаньон.
- **Признак готовности:** все девять блоков файла предложений закрыты, кроме помеченного
  оговоркой момента гарда разговора — он этапом 10.
- **Чем проверяется:** `projects/agent-kit/tests/defaults.test.sh` — новый случай на путь вне
  корня дерева; чтение компаньона.

### 6. П-7 — ресурс молча зависит от ресурса

- **Что делается:** строка `**Требует:**` в шапке ресурса; `sync --check` предупреждает о
  выбранном ресурсе, чьё требование не выбрано; `doctor` называет такие ресурсы поимённо, а не
  сводит невыбранное в число.
- **Признак готовности:** предупреждение — не отказ: код возврата не меняется, дерево вправе
  закрыть требование своим средством. Паттерн возвращения к работе несёт требование на хук
  запуска сессии.
- **Чем проверяется:** `nx test @rt-tools/agent-kit` — случаи на разорванную связь;
  `pnpm run agent-kit:check` на этом дереве печатает предупреждения и остаётся зелёным.

### 7. П-8 — хук без профиля молча превращается в пустышку

- **Что делается:** хук, которому нужна функция профиля, при её отсутствии не выходит молча:
  один раз за сессию говорит, какой функции не хватает и в каком файле её определяют. `doctor`
  перечисляет функции профиля, которых ждут разложенные хуки, и те из них, что не определены.
- **Признак готовности:** пять хуков, выходящих с нулём, и четыре, теряющих часть поведения,
  докладывают о нехватке; в этом дереве `doctor` называет `rt_is_app_code` — профиль его не
  определяет, и гард хода работы здесь мёртв.
- **Чем проверяется:** `projects/agent-kit/tests/run.sh`; `doctor` в этом дереве.

### 8. П-9 — текст пакета утверждает про дерево то, чего дерево не поправит

- **Что делается:** хук запуска сессии говорит о соседнем гарде условно и по имени; статья о
  том, как ресурс пакета говорит о соседе, — в закон о документации проекта и правило устройства
  текстов.
- **Признак готовности:** греп по хукам не находит утверждений о состоянии дерева, поданных как
  факт.
- **Чем проверяется:** `projects/agent-kit/tests/texts.test.sh`; чтение вывода хука в этом
  дереве, где обещанный гард мёртв.

### 9. П-10 — механизм записи о происшествии

- **Что делается:** признак происшествия — статья закона; каталог записей и требования к ним —
  ресурс пакета; гард на завершение хода: признал промах — ход не закрывается, пока записи нет;
  запись без правки слоя правил закрытой не считается.
- **Признак готовности:** гард отбивает ход с признанием промаха и пропускает его, когда запись
  появилась; набор образцов признания живёт в одном месте и назван в тексте.
- **Чем проверяется:** новый набор сценариев в `projects/agent-kit/tests/`; ручной прогон хука
  на образце реплики.

### 10. Момент срабатывания гарда разговора

- **Что делается:** ход с вопросом проверяется на инструменте вопроса, до отправки; проверка на
  завершении хода остаётся для вопроса, заданного прозой.
- **Признак готовности:** отказ приходит раньше, чем вопрос уходит владельцу; вопрос прозой
  по-прежнему ловится на завершении хода.
- **Чем проверяется:** `projects/agent-kit/tests/grill-gate.test.sh` — случаи на оба момента.

### 11. Спек домена, раскладка, снятые предложения

- **Что делается:** договорённость вливается в спек домена и его сценарии; `agent-kit:sync`
  раскладывает всё, что накопилось; оба файла предложений удаляются.
- **Признак готовности:** директории «предложено» в ветке нет; `pnpm run agent-kit:check` зелен;
  в `.claude/rt-kit/proposals/` не осталось закрытого.
- **Чем проверяется:** `pnpm run check:specs`, `pnpm run agent-kit:check`, `pnpm run check:docs`.

### 12. Проверка на дереве-потребителе

- **Что делается:** собранный пакет ставится в дерево, откуда пришли замечания; там гоняются
  `sync --check` и `doctor`.
- **Признак готовности:** оба говорят новое — предупреждения о разорванных связях ресурсов и
  список недостающих функций профиля; ни одно из девяти замечаний на том дереве больше не
  воспроизводится.
- **Чем проверяется:** вывод обеих команд на том дереве, записанный в ход работы.

## Чего эта работа не делает

- **Не трогает гарды этого дерева отдельной правкой.** Всё, что здесь меняется в хуках, меняется
  в исходниках пакета и доезжает раскладкой. Исключение объявлено владельцем: момент
  срабатывания гарда разговора доедет сюда и начнёт действовать.
- **Не чинит команду заведения задачи**, молча собирающую папку с образца при несовпадении имени
  черновика, — замечено на RT-396, названо в теле задачи 400 примыкающим. Заводится отдельной
  задачей.
- **Не вливает `rules-feedback`** — директорию «предложено», пережившую мерж RT-396, — если
  этап 11 покажет, что её вливание тянет за собой правку текстов той работы. Тогда заводится
  отдельная задача, а причина пишется в ход работы.
- **Не публикует пакет в реестр.** Версия поднимается, публикация — отдельным движением по слову
  владельца.
