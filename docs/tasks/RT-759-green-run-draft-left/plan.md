## Что считается сделанным

- Гард отбивает завершение хода, когда у текущей ветки открыт PR-черновик и прогон на его
  вершине завершён зелёным, и называет вызов, которым черновик снимается.
- Гард отказывает в пользу работы: нет сети, нет помощника хостинга, нет разборщика, не
  репозиторий, повторный заход — ход разрешается.
- Гард не будит хостинг на каждом завершении хода: ответ кладётся в кэш с пределом годности.
- Разбор происшествия лежит в `docs/postmortems/` и назван в правиле `task-flow`.
- `npm run check:docs` расхождений не прибавил.

## Этапы

### 1. Разбор происшествия записан

- **Что делается:** механизм промаха записывается по шагам — что было доступно, чем ловилось,
  что из этого уходит в слой правил.
- **Признак готовности:** запись лежит в `docs/postmortems/`, указатель каталога её называет.
- **Чем проверяется:** `npm run check:docs`.

### 2. Гард положен и зарегистрирован

- **Что делается:** сценарий на событии завершения хода спрашивает PR текущей ветки и прогон на
  его вершине; черновик при зелёном прогоне отбивает ход.
- **Признак готовности:** сценарий лежит в `.claude/hooks/`, назван в `.claude/settings.json`,
  на этой ветке молчит (PR ещё нет) и отбивает на ветке с зелёным черновиком.
- **Чем проверяется:** прогон сценария руками с подставленным вводом — оба исхода.

### 3. Правило названо гардом

- **Что делается:** правило `task-flow` получает утверждение о том, что снятие черновика держит
  гард, а не память; имена этого дерева — в спутнике рядом.
- **Признак готовности:** утверждение стоит, `npm run check:docs` и `npm run check:specs`
  расхождений не прибавили.
- **Чем проверяется:** `npm run check:docs`, `npm run check:specs`.

## Чего эта работа не делает

- Не снимает черновик с PR #758: это отдельный ход, и он идёт по слову владельца.
- Не трогает гард происшествия и гард разговора: они ловят другое и работают.
- Не заводит слежения за красным прогоном — гард говорит только о готовности к слиянию.
