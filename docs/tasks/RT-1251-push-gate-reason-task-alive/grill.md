# Разбор просьбы

Запись груза из приёма, своё дерево, ресурс `checks/push-gate.mjs`.

- **место:** проверка полноты набора гейта пуша — там, где у пропущенного шага читается
  причина. Рядом с проверкой наличия причины встаёт проверка того, что названная в ней задача
  жива.
- **повод:** причина, называющая задачу сроком, читается как отсрочка с назначенным концом.
  Проверка судит наличие причины, а не то, что за номером кто-то стоит, — и отсрочка с мёртвым
  номером выглядит ровно как отсрочка с живым. Два исключения одного дерева называли сроком
  задачу, которой нет: по её номеру хостинг не отдаёт ничего, как и по трём соседним. Простояли
  они так, пока их не нашёл разбор закрытых работ; ни полнота гейта, ни проверка путей их не
  видели — номер задачи путём не является, а настройку проверок она не читает вовсе.
- **готовый текст:** «Причина исключения, называющая задачу, судится на живость этой задачи.
  Отсрочка со сроком и отсрочка без срока выглядят одинаково, пока номер никто не спросил;
  мёртвый номер в причине делает исключение бессрочным, не сказав об этом ни строкой.
  Спрашивается тем же ярусом, что состояние задачи у гарда поставки: есть чем спросить —
  спрашивает, нет сети или доступа — пропускает молча.»
- **чем закрывается:** ничего из надстроек этого дерева. Набор гейта — свой в каждом дереве, а
  форма причины и её проверка общие.

Владелец разбор не вёл: заход идёт самостоятельно, задачи берутся из приёма одна за другой.
