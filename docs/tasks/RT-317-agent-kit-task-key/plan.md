# Замысел

Задача: RT-317 · Ветка: `RT-317-agent-kit-task-key`

**Поведение:** не меняется — правка задевает правила, проверки и обвязку заведения работы;
кода библиотек, которые дерево публикует, она не касается.

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## Что считается сделанным

- В чистом дереве без ключа задач раскладка отказывает и называет, где ключ задаётся; тихого
  прохода с `[-317]` не остаётся.
- Ключ задан — команда заведения задачи строит `[RT-<номер>] …`, гард пропускает ветку
  `RT-<номер>-<slug>` и отбивает прежнюю форму, сверка очереди не печатает ни строки про заголовок.
- `npm run task:new -- --slug <slug>` доходит до конца и переименовывает черновик папки; код
  выхода нулевой.
- Ни одно разложенное правило не называет пути, которого в дереве нет.
- `check-dupes` и `check-lib-layers` на дереве без `libs` и без настройки границ отвечают словами
  и выходят нулём, как соседние девять.

## Этапы

### 1. Ключ задач в дереве

- **Что делается:** дерево называет свой ключ, гард ветки читает ту же форму, что строит команда
  заведения задачи; все задачи репозитория получают номер в заголовке.
- **Признак готовности:** `check:board` молчит про заголовки; ветка новой формы заводится, старой —
  отбивается.
- **Чем проверяется:** `npm run check:board`, попытка завести ветку обеих форм.

### 2. Ключ задач в законе пакета

- **Что делается:** имя задачи и имя ветки становятся статьёй закона о поставке; ключ остаётся
  настройкой дерева, пустое значение перестаёт быть законным умолчанием.
- **Признак готовности:** свежее дерево не может разложить пакет, не назвав ключ, и узнаёт об этом
  из отказа с готовой строкой настройки, а не из падения проверки.
- **Чем проверяется:** одноразовое дерево, `init --all` + `sync` без ключа и с ключом.

### 3. Команда заведения задачи доходит до конца

- **Что делается:** недостающие импорты в ресурсе `task-new`; корень дерева берётся не от места,
  куда лёг файл.
- **Признак готовности:** прогон со `--slug` и черновиком папки завершается нулём.
- **Чем проверяется:** прогон в одноразовом дереве.

### 4. Адресность уезжает в спутники

- **Что делается:** 14 правил и паттернов перестают называть пути и прогонщики конкретного дерева;
  названное уезжает в `implementation.md` рядом.
- **Признак готовности:** греп по разложенному не находит пути, которого в дереве нет.
- **Чем проверяется:** `init --all` + `sync` в одноразовое дерево, греп, проверка существования.

### 5. Две проверки читают настройку

- **Что делается:** `check-dupes` и `check-lib-layers` берут корни и путь к настройке границ из
  конфигурации и молчат по делу, когда их предмета в дереве нет.
- **Признак готовности:** обе выходят нулём с внятным ответом на дереве без `libs`.
- **Чем проверяется:** прогон обеих в этом дереве и в одноразовом.

## Чего эта работа не делает

- Не снимает с доски 13 отчётов, стоящих там вместо задач, и не расставляет исполнителей
  задачам, у которых их нет: сверка очереди называет и то и другое поимённо, это отдельная уборка.
- Не заводит виды `gitlab` и `azure` у проверок доски — пункт аудита о видах не проверялся прогоном
  и задачей пока не стал.
- Не трогает заголовки отчётов: они история слияний, и сверка судит по ним только открытые.
