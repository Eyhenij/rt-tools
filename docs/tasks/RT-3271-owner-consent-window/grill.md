# Разбор

## Просьба владельца

Задача #3271 заведена по эпику RT-3302. Её текст:

> Проверки ищут согласие владельца в тексте разговора по словам. Настоящее «да» не засчитывается, и
> владельца переспрашивают: 13.11.2026 — три раза об одном решении. Постороннее «да» засчитывается:
> на настоящей записи разговора проверка конца эпика пускает восемь посторонних ответов из двадцати
> трёх.
>
> На создание задачи, новую ветку и открытие PR проверка возвращает приложению решение «спросить».
> Владелец видит окно «разрешить / запретить» на конкретную команду. Чтение согласия из записи
> разговора удалить из проверки конца эпика, проверки разбора и проверки одобрения.

Работа идёт без владельца, по его слову «работай дальше в автономном режиме» (16.11.2026).

## Что уже есть в дереве

- `epic-stop-guard.sh` после конца эпика дважды читает запись разговора. Первый раз ищет номер
  работы в сообщении владельца или в ответе меню. Второй раз ищет по словам согласие на создание
  задачи. Отказ — `permissionDecision: "deny"`. Сценарии лежат в `docs/specs/agent-kit/epic-stop/`,
  тест — `epic-stop-guard.test.sh`, в нём 78 сценариев.
- `check-kit-approval.mjs` ищет цитаты одобрения макета и витрины во всех записях разговоров машины.
- Проверки разбора, которые судили текст разговора, удалены в RT-3276. Их место занял agent-хук
  меню.
- Ни одна проверка дерева пока не возвращает `permissionDecision: "ask"`.

## Что уже говорят правила

- `git-workflow` и `epic-flow`: после конца эпика новую работу берут по слову владельца.
- `kit-approval`: правку кита одобряет владелец, и запись одобрения лежит в дереве.

## Вопросы и ответы

Владелец ушёл и разрешил работать без него. Шесть вопросов закрыты решениями по умолчанию в разделе
«Решения»: у каждого записано, что взято, откуда и чего стоит ошибка.

## Решения

- **Поведение приложения меняется.** Вместо отказа владелец видит окно разрешения. Откуда: текст
  задачи. Цена ошибки — правка описания подобласти `epic-stop`.
- **Закон не меняется. Правила `git-workflow` и `epic-flow` меняются** в строках о слове владельца
  после конца эпика. Откуда: текст задачи. Цена ошибки — одна правка правила.
- **Одна задача.** Проверки переходят с одного приёма на другой и откатываются вместе.
- **Не входит:** правила поставки на хостинге (RT-3272), таблица решений (RT-3275), подпись метки
  шага (RT-3332).
- **Признак готовности — три пункта задачи.** После конца эпика окно вместо отказа. Ни одна проверка
  не читает ответ владельца из записи разговора. Прогон на записи от 13.11.2026 не даёт повторного
  вопроса.
- **Образец:** решение `ask` в документации хуков Claude Code. В дереве образца нет.
- **Проверка одобрения кита остаётся в наборе перед отправкой.** В наборе нет приложения, которое
  показало бы окно. Цитата там ищется дословно, а не угадывается по словам. Цена ошибки — третий
  пункт задачи выполнен не целиком, нужна отдельная задача.

## Договорённость

**Описание фичи:** не нужно — правка не трогает приложений; поведение проверки описано в подобласти
`docs/specs/agent-kit/epic-stop/`, и её сценарии правятся тем же этапом, что и код.
