# Замысел

Задача: #511. Ветка: `RT-511-agent-kit-extend`.

**Поведение:** не меняется — работа целиком в слое правил, приложений дерева не задевает.

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## Что считается сделанным

- Скил заведён, и в нём есть готовый пример на каждый род расширения: надстройка текста, ветка
  карты гейта, функция профиля, свой признак и своя проверка, свой закон с правилом.
- Каждый пример назван вместе с тем, чем правка проверяется и чем кончается ошибка.
- Скил `agent-kit` называет соседа, чтобы его загружали.
- Файл читается целиком за один заход, соседа не пересказывает.
- Разложенное сходится с пакетом: `pnpm run agent-kit:check` зелёный.

## Этапы

### 1. Скил заведён и разложен

- **Что делается:** пишется `agent-kit-extend.md` с примерами, снятыми с живых надстроек этого
  дерева; в `agent-kit.md` появляется ссылка на него.
- **Признак готовности:** оба файла разложены, шапки несут новую сумму.
- **Чем проверяется:** `pnpm run agent-kit:sync`, затем `pnpm run agent-kit:check`.

### 2. Примеры сверены с механизмом, а не приняты по виду

- **Что делается:** каждый пример прогоняется тем, что его исполняет: надстройка — раскладкой,
  ветка карты гейта — сценариями гейта, функция профиля — сценариями гардов.
- **Признак готовности:** ни один пример не разошёлся с тем, как механизм читает файл.
- **Чем проверяется:** `bash projects/agent-kit/tests/run.sh`, `node tools/check-doc-paths.mjs`.

## Чего эта работа не делает

- Не заводит скриптов рядом со скилом: всё, что в нём делается, — правка файла и вызовы,
  которые пакет уже везёт.
- Не трогает механизм раскладки, гарды и проверки: работа объясняет их, а не меняет.
- Выпуск пакета не запускается — отдельное решение владельца.
