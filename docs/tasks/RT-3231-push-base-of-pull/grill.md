# Grill

## The owner request

> ты трогаешь компоненты кита?

> так а нахуй ты гоняешь тесты тогда?

> поправь хук

Сказано 12.11.2026, когда набор перед push на ветке RT-3195 дважды упал на снимках витрин. Ветка
меняет только тексты пакета правил.

## What the tree already has

- Базу набора выбирает `rt_push_base` в `projects/agent-kit/assets/hooks/git-guard-push-marks.sh`.
  Она читает из истории ветки строку «Created from» и берёт родителя, если его копия на сервере
  есть и входит в вершину. Иначе база — главная ветка.
- У ветки RT-3195 родитель — ветка задачи RT-3194. PR #3222 влили, сервер ветку удалил, база стала
  `origin/main`. Первая строка журнала набора: `push ahead: base origin/main`.
- Состав тяжёлых шагов считает `rt_push_touched` в профиле дерева `.claude/rt-kit/project.sh`. От
  `origin/main` в разнице есть шесть корневых файлов, которые принесли первые задачи эпика:
  `package.json`, `eslint.config.mjs`, `.gitattributes`, `.gitignore`, `.nxignore`,
  `.prettierignore`. Путь, которого правило не узнаёт, даёт «тронуто всё».
- От ветки эпика в разнице только тексты, пакет правил, `tools/` и графы — тяжёлых шагов нет.
- Базу PR задачи эпика уже умеет спрашивать помощник `git-guard-delivery-epic.sh`.

## What the rules already say

- Правило `git-workflow`: «A stacked branch is counted against the branch it was created from» —
  комментарий самой функции; откат на главную ветку назван допустимым: «the gate may turn out
  stricter than needed, never weaker».
- Правило `task-flow`: работа вне эпика требует слова владельца.

## Questions and answers

**Правка начнёт экономить время, только когда дойдёт до главной копии: набор перед push запускают
её хуки. Как её туда довести?**
Отдельным PR в main

## Decisions

- **База — ближайшая ветка сервера, которая входит в вершину.** Она считается по ссылкам копии
  после одного `git fetch`: без вызовов хоста, одинаково из любого каталога и на первой отправке,
  когда запроса ещё нет. Rejected: спрашивать базу открытого запроса у хоста — первый круг ревью
  показал, что такой путь молчит на первой отправке, зависит от каталога запуска и от ответа сети,
  а один сбой сети возвращает полный набор.
- **Запись «Created from» из журнала ветки больше не читается.** Ближайшая ветка сервера в истории
  вершины даёт тот же ответ для цепочки и верный — для ветки, взятой в другой копии или записанной
  как «Created from HEAD». Rejected: оставить оба пути — два правила на один вопрос.
- **Ссылки снятых с сервера веток не вычищаются.** Нижняя ветка цепочки, влитая и снятая, остаётся
  ближайшей для ветки над ней: её содержимое уже прошло набор и ревью. С вычисткой такая ветка
  считалась бы от главной, пока не примет базу, а правило поставки велит принимать её только при
  конфликте.
- **Задача идёт вне эпика, веткой от главной.** Слово владельца: «Отдельным PR в main». Первый
  набросок в цепочке эпика RT-3227 остался в местной ветке и не отправлен.

## What is left unclear

- Хуки запускает главная копия, она стоит на ветке другого эпика. После слияния этого PR главную
  ветку нужно принять в ветку главной копии и в ветку эпика RT-3227 — тогда набор их веток
  считается по-новому.
- PR эпика в главную ветку считается от главной ветки по определению и платит за всё, что эпик
  задел. Правка этого не меняет.
