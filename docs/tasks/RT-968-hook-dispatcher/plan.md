## Куда уходит время

Замер своей машиной, вызовом самих хуков с готовым вводом:

    вызов Bash, все хуки PreToolUse   826 мс, 18 хуков
    один гард                          43–83 мс
    вызов jq                            6,5 мс
    запуск пустой оболочки              4,7 мс

Гард зовёт `jq` шесть-семь раз: имя инструмента, командная строка, путь правки, рабочий
каталог. Восемнадцать гардов на вызов — это больше сотни разборов одного и того же ввода.
Отсюда и число: восемнадцать оболочек стоят 85 мс, а сто с лишним разборов — семьсот.

## Что считается сделанным

- На событие приходится один вызов из настроек агента, а не восемнадцать.
- Ввод разбирается однажды: диспетчер достаёт поля одним вызовом разборщика и отдаёт их
  веткам окружением.
- Гард, позванный напрямую, работает как прежде: наборы сценариев зовут их именно так.
- Ни один отказ не пропал: набор сценариев гардов зелёный целиком.
- Замер после правки лежит рядом с замером до неё.

## Этапы

### 1. Диспетчер зовёт ветки события

- **Что делается:** заводится `hooks/dispatch.sh <событие>`: читает ввод, разбирает его один
  раз, зовёт гарды этого события по карте и возвращает первый ненулевой код с его выводом.
  Карта событий и образцов собирается из строк `rt-hook` в шапках самих гардов.
- **Признак готовности:** отказ любого гарда доходит до агента через диспетчер тем же текстом
  и тем же кодом.
- **Чем проверяется:** `npm run agent-kit:hooks` — «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ» означает «сошлось».

### 2. Гарды берут разобранное из окружения

- **Что делается:** гарды спрашивают поля у окружения и разбирают ввод сами только тогда,
  когда окружение пусто, — то есть при прямом вызове.
- **Признак готовности:** замер того же вызова стал заметно меньше; наборы зелёные.
- **Чем проверяется:** тот же замер, что и до правки, — вызов `Bash` через все хуки события.

### 3. Настройки, сценарии и спек

- **Что делается:** настройки агента получают по одной строке на событие; заводятся сценарии
  на диспетчер, предмет описывается спеком домена.
- **Признак готовности:** сверка спеков не называет расхождений, раскладка сходится.
- **Чем проверяется:** `npm run check:specs` и `pnpm run agent-kit:check`.

## Чего эта работа не делает

- **Ни один гард не ослабевает.** Что каждый судит, остаётся как есть.
- **Отдельные файлы гардов не сливаются в один.** Меняется точка входа, а не устройство.
- **Порядок гардов внутри события не пересматривается.** Он тот же, что в настройках сейчас.
