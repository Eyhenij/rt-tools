# План работы

**Задача:** RT-2256 · **Ветка:** RT-2256-table-draws-filter-row
**Поведение:** меняется — у таблицы появляются вход набора условий, выход о его изменении и
признак показа строки отбора. Договорённость пишется поддоменом `table-filter`, где уже описана
сама ячейка.

## Что считается сделанным

Потребитель объявляет отбор одним полем в настройке колонки и получает строку отбора под шапкой;
набор условий приходит входом и уходит выходом, а строк таблица не сужает — этим занимается
потребитель.

## Этапы

### Этап 1 — договорённость

В поддомен `table-filter` дописываются правила о строке отбора: кто её рисует, по какому признаку
она видна, что происходит с колонкой без отбора и с колонкой действий строки. Сценарии получают
свободные номера командой `npm run spec:next-id SC-UKV`.

Признак готовности: `npm run check:specs` зелёная, новые сценарии стоят без тестов и названы
причиной.

### Этап 2 — таблица рисует строку отбора

Входы `filters` и `showFilters`, выход `filtersChange`; строка рисуется под шапкой по
`displayedColumns`, колонка без отбора даёт пустую ячейку, колонка действий строки — тоже.

Мерка до правки: таблица не читает поле `filter` ни разу.

Признак готовности: тесты на новые сценарии зелёные, `pnpm exec nx test @rt-tools/ui-kit-v2`
зелёный.

### Этап 3 — показы и кадры

Показ строки отбора в таблице; кадры сняты после того, как показ просмотрен глазами.

Признак готовности: `node tools/visual-gate.mjs ui-kit-v2` зелёный, обход историй без пустых
показов.

### Этап 4 — тексты и разбор папки

Описание семьи таблицы рассказывает про строку отбора и переход с первого кита; папка задачи
разбирается последним коммитом.

Признак готовности: `npm run check:docs` зелёная, папки задачи в ветке нет, запись в
`docs/archive/` есть.

## Чего работа не делает

Не сужает строки сама: набор условий уходит наружу, а что с ним делать, решает потребитель. Не
переносит отметки строк — это отдельное расхождение с первым китом, записанное в ловушки плана
эпика.
