# Замысел

**Задача:** RT-1588 · **Ветка:** RT-1588-awk-locale-compare
**Поведение:** меняется — под локалью с национальными настройками хуки перестают путать заголовки

## След задачи

| Что    | Где                                                                  |
| ------ | -------------------------------------------------------------------- |
| Код    | `projects/agent-kit/assets/hooks/` — четыре хука, сравнивающие текст |
| Пробы  | `projects/agent-kit/tests/handoff-write.test.sh`                     |
| Спек   | `docs/specs/agent-kit/`                                              |
| Задача | #1588                                                                |

## Что считается сделанным

- Ни один хук не сравнивает строки по правилам локали: сравнение идёт байтами.
- Проба падает на непочиненном хуке под локалью конвейера и проходит на починенном.
- Полный набор проб зелёный под обеими локалями.

## Этапы

### 1. Сравнение в хуках идёт байтами

- **Что делается:** вызовы `awk`, сравнивающие кириллический заголовок, зовутся с `LC_ALL=C`.
- **Признак готовности:** выемка раздела передачи под `en_US.UTF-8` оставляет «Где стоим» на месте.
- **Чем проверяется:** `LC_ALL=en_US.UTF-8 bash projects/agent-kit/tests/handoff-write.test.sh` — 0 провалов.

### 2. Промах закрыт пробой под обеими локалями

- **Что делается:** набор хука передачи гоняет свои утверждения под локалью конвейера, а не
  только под той, что стоит в оболочке исполнителя.
- **Признак готовности:** проба краснеет, если байтовое сравнение снять.
- **Чем проверяется:** `npm run agent-kit:hooks` — все наборы зелёные.

## Чего эта работа не делает

- Не трогает проверки на узле: там сравнение строк от локали не зависит.
- Не чинит `awk` системы: правится то, как его зовут.
