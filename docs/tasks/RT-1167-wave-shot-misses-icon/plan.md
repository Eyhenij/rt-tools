## Что считается сделанным

- Названо замером, чего именно не дожидается обвязка: не шрифта и не самого узла, а набора
  значков — узел на месте, а ожидание его не видит.
- Ожидание перебирает значки обеих разметок кита, а не одной.
- Страница со значками требует набора: отличить её от страницы без значков ожидание умеет.
- Отказ называет, чего не хватило, и не молчит.
- Волновая пересъёмка на неправленом дереве даёт кадры, которые повторная сверка принимает с
  первого раза.

## Этапы

### 1. Промах назван замером, а не чтением

- **Что делается:** на поднятой витрине снимается перечень значков страницы составной кнопки —
  сколько на ней узлов `rt-icon` и сколько `<use href="#rt-icon-…">`. Тем же замером берётся
  страница, где значок рисует компонент, — для сравнения.
- **Признак готовности:** на странице составной кнопки узлов `rt-icon` ноль, а `<use>` со
  ссылкой на набор — больше нуля. Значит ожидание выходит `true` первой же строкой и набора не
  ждёт вовсе.
- **Чем проверяется:** `node /private/tmp/claude-501/-Users-eyhenij-WebstormProjects-rt-tools/2acb9e16-f01d-4f4c-98f6-e9d1c8e71163/scratchpad/icons.mjs` — вывод печатает по строке
  на историю: имя, число `rt-icon`, число `use`; расхождение этих чисел на составной кнопке и
  есть промах.

### 2. Ожидание переписано на сам предмет

- **Что делается:** в `quiet` из `test-runner.ts` перебор `rt-icon` заменяется перебором
  `use[href^="#rt-icon-"]`; набор требуется, как только на странице есть хоть один такой узел
  или хоть один `rt-icon`; отказ поднимается своей строкой и называет, чего не хватило.
- **Признак готовности:** ожидание не выходит `true` на странице, где значки есть, а набора
  нет; отказ по времени приходит с текстом, называющим историю и недостачу.
- **Чем проверяется:** `pnpm run test:visual:v2 -- --testNamePattern 'SplitButton'` — сверка
  четырёх кадров составной кнопки сходится с первого вызова.

### 3. Проба ожидания стережёт откат

- **Что делается:** к прогону снимков добавляется проба: страница со значками открывается с
  задержанным набором, и обвязка обязана не отпустить съёмку. Проба живёт рядом с прогонщиком
  снимков, отдельной командой, а не разовым сценарием во временном каталоге.
- **Признак готовности:** на неправленой обвязке проба краснеет, на правленой — зелёная.
- **Чем проверяется:** `pnpm run test:visual:v2:probe` — вывод называет, сколько пар кадров
  снято и сошлись ли они.

### 4. Волна и повторная сверка

- **Что делается:** эталоны второй витрины переснимаются волной на неправленом дереве, и сразу
  за пересъёмкой идёт повторная сверка.
- **Признак готовности:** повторная сверка сходится с первого раза — ни одного расхождения.
- **Чем проверяется:** `pnpm run test:visual:v2:update-all && pnpm run test:visual:v2` — во
  втором выводе число сошедшихся снимков равно числу всех.

## Чего эта работа не делает

- Ожидание первой витрины не трогает: обвязки разведены намеренно, и правка ради второго кита
  сдвинула бы момент съёмки у первого, то есть уронила бы его эталоны. Согласие двух копий
  держит текст правила `ui-component-tests`, а не общий модуль.
- Мерцающая проба отрисовки (RT-1129) — соседняя работа со своей веткой; сюда не тащится.
- Пять проверок слоя токенов, которых не зовёт ни гейт, ни конвейер, заведены задачей RT-1170.
