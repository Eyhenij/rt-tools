# Замысел

**Задача:** RT-951 · **Ветка:** `RT-951-conflicting-pr-guard`
**Поведение:** не меняется — работа идёт по гардам поставки и проверкам дерева, кода приложения
она не задевает.

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## След задачи

Части пакета правил названы словами, а не полными путями: гард хода работы читает пути из текста
команды и признаёт правкой кода любое упоминание пути внутрь пакетов.

| Что     | Где                                                       |
| ------- | --------------------------------------------------------- |
| Правила | правило поставки в пакете правил                          |
| Код     | гард снятия черновика и сверка очереди работ этого дерева |
| Тексты  | спек поддомена о гардах поставки и спек проверок дерева   |
| Тесты   | набор гардов поставки в пакете и набор сверки очереди     |

## Что считается сделанным

- Снятие черновика у конфликтующей заявки отбито, и в отказе названы её номер и то, чем чинится:
  влить главную ветку и разобрать конфликт.
- Заявка без конфликта черновик снимает по-прежнему.
- Нет сети, нет токена, хостинг молчит — снятие проходит: гард отказывает в пользу работы.
- Сверка очереди работ печатает строку на каждую открытую конфликтующую заявку.
- Правило поставки называет оба требования, и каждое привязано к коду.

## Этапы

### 1. Гард снятия черновика спрашивает сливаемость

- **Что делается:** к запросу о ревьювере и отзыве добавляются поля сливаемости; конфликтующая
  заявка снятие черновика не проходит. Отказ называет номер и способ починки.
- **Признак готовности:** конфликтующая отбита, сливаемая проходит, молчание хостинга работу не
  отбивает.
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 2. Сверка очереди работ называет конфликтующую заявку

- **Что делается:** к четырём проверкам заявки добавляется пятая — сливаемость; строка встаёт
  рядом с вершиной без прогона и черновиком при зелёном прогоне.
- **Признак готовности:** сверка печатает строку на каждую конфликтующую открытую заявку и
  молчит, когда конфликтов нет.
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 3. Тексты

- **Что делается:** правило поставки получает две статьи, спеки — правила, сценарии и привязки.
- **Признак готовности:** каждое утверждение привязано к коду, каждый сценарий закрыт набором,
  разложенное сходится с пакетом.
- **Чем проверяется:** `pnpm run check:specs` — расхождений нет.

## Чего эта работа не делает

- Не судит состояние `UNSTABLE`: красный прогон на вершине уже несёт свою строку сверки.
- Не трогает гард ожидания и стража выходов хода.
- Не чинит указатель описания прошлого, на котором конфликт и случился: место дописи — не
  причина, причина в том, что конфликт никем не спрашивался.
