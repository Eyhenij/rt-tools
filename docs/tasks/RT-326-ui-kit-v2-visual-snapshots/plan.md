# Замысел

Задача: #326. Ветка: `RT-326-ui-kit-v2-visual-snapshots`.

**Задача:** RT-326 · **Ветка:** RT-326-ui-kit-v2-visual-snapshots
**Драфт:** `docs/specs/ui-kit-v2/proposed/visual-snapshots/`
**Поведение:** меняется

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## Что считается сделанным

- Прогон снимков второй витрины идёт дважды подряд без правок и оба раза зелёный.
- Намеренно удалённый эталон роняет прогон с именем истории, и файл не появляется сам.
- Выключенная функция показа роняет прогон, а не отдаёт кадр с закрытой панелью.
- Двенадцать панельных историй снимаются с открытой панелью в безголовом браузере.
- Каталог `projects/ui-kit/.storybook/__snapshots__` не изменён ни одним файлом.
- Порог расхождения и время прогона названы числами с указанием, чем замерены; время пересчитано
  на полный объём витрины.
- Договорённость в `docs/specs/ui-kit-v2/proposed/visual-snapshots/` не содержит ни одного из
  шестнадцати расхождений, названных состязательным разбором.
- `pnpm run check:all`, `nx run @rt-tools/ui-kit-v2:typecheck`, `pnpm run build-storybook:ui-kit-v2`
  и `pnpm run agent-kit:check` зелёные.

## Этапы

### 1. Договорённость доведена до принятых решений

- **Что делается:** правка трёх файлов в `docs/specs/ui-kit-v2/proposed/visual-snapshots/` под
  решения владельца второго захода и под шестнадцать находок состязательного разбора. Закрываются
  решениями: набор кадров (матрицы, `Themes`, по кадру на открытое перекрытие); область кадра
  (корень сетки, не вся страница); язык кадра (английский, прибит обвязкой); хранение эталонов
  (обычные файлы); порядок работ (обвязка и эталоны первыми, волны 4–5 привозят свои эталоны);
  как история попадает в набор и что происходит с забытой; кто снимает эталон нового компонента;
  эталон без истории; узкий кадр по каждому порогу компонента, а не один, включая порог шире
  базового кадра; тема кадра; что берёт пересъёмка; повторы и флаки; поведение при чужой или
  молчащей витрине по названному адресу; куда идут картинки различий и чем закрыт их коммит;
  предел починки. Шапка «Зависимости: нет» заменяется перечнем. Каждому правилу даётся сценарий.
- **Признак готовности:** ни одной находки разбора не осталось; порядок и объём совпадают со
  словом владельца в `grill.md`; ни одно правило не осталось без сценария и ни один сценарий не
  проверяет чтение документа.
- **Чем проверяется:** вычитка по списку находок; `pnpm run check:docs`; `pnpm run check:all`.

### 2. Конвенция параметров съёмки в помощниках витрины

- **Что делается:** объявление параметров истории в `projects/ui-kit-v2/src/showcase/` —
  исключение из съёмки с причиной, перечень порогов узкого кадра, область кадра, размер окна под
  перекрытие; экспорт из `showcase/index.ts`; раздел о них в правиле витрины, по которому волны
  4–5 будут писать истории.
- **Признак готовности:** параметры экспортированы и применены хотя бы на одной существующей
  матрице волн 1–3; правило витрины называет параметр и случай, когда он обязателен.
- **Чем проверяется:** `nx run @rt-tools/ui-kit-v2:typecheck`; `pnpm run check:all`.

### 3. Успокоение кадра переписано с кадров отрисовки на макрозадачу

- **Что делается:** `settle()` в `src/showcase/story-overlay.ts` перестаёт ждать два
  `requestAnimationFrame`. В фоновой вкладке и в безголовом браузере кадры отрисовки не приходят,
  функция показа виснет до жеста, панель не открывается — и кадр неотличим от исправной истории с
  закрытой панелью.
- **Признак готовности:** двенадцать панельных историй открывают панель в безголовом браузере;
  ни одна история, державшаяся на кадрах отрисовки, не осталась на старом приёме.
- **Чем проверяется:** прогон снимков по группе панельных историй; глазами по статике витрины;
  `nx run @rt-tools/ui-kit-v2:typecheck`.

### 4. Обвязка снимков второй витрины

- **Что делается:** свой `test-runner` при `projects/ui-kit-v2/.storybook` со своим каталогом
  эталонов рядом; команды прогона и точечной пересъёмки со своим адресом витрины; чтение
  параметров съёмки; отказ при отсутствующем эталоне и при неоткрывшемся перекрытии; маска для
  картинок различий.
- **Признак готовности:** прогон читает набор из параметров, а не из перечня в конфигурации;
  отсутствующий эталон роняет прогон и не досъёмывается молча; картинки различий после красного
  прогона не остаются файлами на коммит.
- **Чем проверяется:** прогон с намеренно удалённым эталоном; прогон с выключенной функцией
  показа; `git status` после красного прогона.

### 5. Замер порога и времени на одной группе

- **Что делается:** эталоны заводятся у одной группы компонентов; меряются порог расхождения на
  матрице и время прогона; числа и способ замера записываются в договорённость вместо
  унаследованного `0.0002`.
- **Признак готовности:** две съёмки подряд без правок сходятся; порог назван числом с указанием,
  чем замерен; время прогона пересчитано на полный объём витрины.
- **Чем проверяется:** двойной прогон по группе; замер длительности; запись числа в спек.

### 6. Правило проверки компонента знает обе витрины

- **Что делается:** раздел о второй витрине в `.claude/skills/ui-component-tests/` — свои команды,
  свой порт, свой каталог эталонов, ловушки съёмки матрицы.
- **Признак готовности:** правило не говорит о снимках так, будто витрина одна.
- **Чем проверяется:** `pnpm run agent-kit:check`; правило не правлено на месте — надстройка лежит
  в `.claude/rt-kit/overrides/`, если файл разложенный.

## Чего эта работа не делает

- **Эталоны на всю витрину, починка вскрытого и шаг прогона в CI** — следующая задача той же
  линии. Здесь эталоны заводятся только у группы, на которой меряются порог и время.
- **Волны 4 и 5 покрытия** (составные компоненты и двенадцать без историй) — свои задачи по
  `docs/plans/ui-kit-v2-state-coverage.md`; после разворота порядка они привозят свои эталоны
  собственными изменениями.
- **Проверка доступности** — своя задача: в дереве её нет ни следа, число нарушений неизвестно, и
  красный прогон доступности не должен держать зелёные снимки.
- **Долг по спекам компонентов** — одиннадцать папок, где спек меньше, чем компонентов; своя
  строка в плане покрытия, к съёмке отношения не имеет.
- **Правка выпущенных компонентов** — починка вида `rt-button.directive.scss` (#272) меняет
  поведение у потребителей пакета и едет отдельным изменением, с отметкой в примечаниях к версии.
- **Сведение разошедшихся порогов SCSS** (1441, 700, 640, 374) к конвенции — это правка вёрстки
  выпущенных компонентов под видом настройки тестов. Снимается по факту написанного.
- **Витрина первого кита** — её обвязка не трогается, эталоны не пересъёмываются.
