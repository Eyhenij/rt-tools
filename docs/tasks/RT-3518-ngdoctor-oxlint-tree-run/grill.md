## Что уже есть в дереве

- `tools/check-ngdoctor.mjs` после RT-3514 прогоняет образец из двух компонентов перед деревом и
  судит дерево по порогу. Образец показывает, что источник запускается, но не что он прошёл каждый
  файл дерева.
- Инструмент 0.3.0 (`node_modules/@abiramcodes/angular-doctor/dist/cli.js`):
    - список файлов — `**/*.ts` и `**/*.html` без `node_modules`, `dist`, `.angular`, `coverage`,
      `*.spec.ts` и полей `ignore` настройки; на дереве — 2689 файлов;
    - oxlint запускается одним процессом на все файлы с настройкой, которую инструмент пишет во
      временный каталог; пустой вывод читается как «находок нет», а не как пропуск. Упавший на одном
      файле oxlint теряет находки oxlint всего дерева;
    - шаблонный линтер разбирает каждый `.html` и каждый встроенный шаблон отдельно; сообщение об
      ошибке разбора приходит без правила и выбрасывается;
    - файл, который не прочёлся, пропускается молча, а `filesScanned` всегда равен `filesTotal`.
- Замер 23.11.2026 на дереве:
    - oxlint с настройкой инструмента по 3053 файлам `*.ts` — 0.08 с; все 248 его находок лежат в
      `*.spec.ts`, которые инструмент не сканирует, а по файлам инструмента находок oxlint — 0, как и
      в выводе инструмента;
    - разбор каждого шаблона по 3454 файлам — 0.9 с, ошибок разбора 0;
    - `check:ngdoctor` целиком — около 6 с.

## Что уже говорят правила

- Правила Angular Doctor не выключаются в настройке: так решил владелец; RT-3514 держит это
  проверкой — в настройке только `reportPath`.
- Веха B эпика обещает красный, когда инструмент замолчал целый источник находок.

## Вопросы и ответы

**Как ловить потерю файла и сколько это может стоить?** Предложение: после скана дерева проверка
проходит по тем же файлам сама — читает каждый, разбирает каждый шаблон, прогоняет oxlint с
настройкой инструмента; красный, если файл не прочёлся, шаблон не разобран, oxlint упал или дал
другое число находок, чем в выводе инструмента; отказ называет файл; около 1 с к 6 с; другой
список файлов у новой версии инструмента — красный с просьбой обновить его. Ответ: «Да, так
(Recommended)».

**Behaviour:** unchanged — задача правит только проверку дерева `tools/check-ngdoctor.mjs` и её
сценарии; кода приложений, кита и пакетов она не трогает.

## Решения

- **Проход по файлам дерева после скана, в `check:ngdoctor`** — слово владельца выше. Отвергнуто:
  ловить потерю по числам вывода инструмента — версия 0.3.0 пишет `filesScanned` равным
  `filesTotal` и выбрасывает ошибку разбора, числа ничего не скажут.
