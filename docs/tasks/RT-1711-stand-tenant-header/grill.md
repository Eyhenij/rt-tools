# Разбор просьбы

## Просьба владельца

Ночное распоряжение: брать в работу весь груз приёма, править самостоятельно, ветки держать
локально и ставить каскадом друг за другом.

## Записи груза

- `fab702ec156bd005542b85ca1a518f23d3752d29eed53f97eb16ec7e1b27709a` — правило говорит, чего не
  знает голый сервер отдачи страниц, и молчит о самом дорогом случае: сервер отрисовки кладёт в
  заголовок арендатора свой собственный хост, и приложение отвечает отказом на каждый вызов.
  Наружу это выходит страницей 404 — то есть выглядит поломкой приложения, а не стенда. Замер
  дерева-отправителя тремя заголовками на одном стенде: свой хост с портом — 404, свой хост без
  порта — 404, имя арендатора — 200. Час ушёл на то, чтобы отличить одно от другого.

## Шесть вопросов

1. **Что меняется для владельца.** Отказ стенда перестаёт разбираться как дефект кода.
2. **Где это живёт.** Правило `browser-verification` — источник пакета.
3. **Чем это подтверждается.** Сверка раскладки, проверки адресов и слога.
4. **Что из этого правило, а что код.** Только правило: чем стенд представляется приложению,
   машина не знает.
5. **Чего работа не делает.** Не описывает настройку стенда за дерево: имя арендатора у каждого
   своё.
6. **Где ветка.** `RT-1711-stand-tenant-header`, каскадом от `RT-1710-one-name-one-thing`.
