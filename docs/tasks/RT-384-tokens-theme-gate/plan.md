## Что считается сделанным

- Проверка зелёная на текущем дереве и печатает числом: цветовых назначений, ответов прямых, через
  цепочку, помеченных общими, принятых списком.
- Пробы роняют прогон каждая своим сообщением: снятое из тёмной темы переопределение;
  переопределение без назначения в светлой; новый тёмный блок в стилях компонента; новое
  переопределение ступени шкалы; пара ниже порога; пара из перечня без строки в таблице замера.
- Двадцать одно молчащее назначение разнесено: помеченные общими стоят пометкой в строке, забытые
  — в списке принятого с номером задачи.
- Считалка печатает отношение по каждой паре перечня в обеих темах; ни одна пара не остаётся без
  строки в таблице замера.
- Рукописных подсчётов контраста в шкалах и назначениях не остаётся.
- Замеры договорённости пересняты и воспроизводятся командами из её `implementation.md`.
- `pnpm run lint:styles`, `pnpm run check:tokens-styles`, `pnpm run check:tokens-graph` и
  `pnpm run agent-kit:check` остаются зелёными; кадры витрины не пересматриваются.

## Этапы

### 1. Граф значений и три состояния ответа

- **Что делается:** `tools/check-tokens-theme.mjs` читает три файла слоя оформления, собирает
  объявления светлой темы, тёмной и шкалы, разбирает ссылки до ступени и разводит цветовое
  назначение на отвечающее прямо, отвечающее через цепочку и молчащее. Цветом считается значение,
  которое доходит по ссылкам до кода цвета; составные значения теней и переходов назначением не
  считаются.
- **Признак готовности:** проверка печатает четыре числа, и они сходятся с замером разведки —
  88 цветовых назначений, 52 прямых ответа, 15 через цепочку, 21 молчание.
- **Чем проверяется:** запуск; сверка с числами разведки.

### 2. Пометка общего цвета и список принятого

- **Что делается:** молчащее назначение получает либо пометку в строке светлой темы с причиной,
  либо запись в списке принятого. Пустая причина пометкой не считается. Заводится отказ на записи,
  которой больше ничего не отвечает, и на пометке у назначения, которое тёмная тема
  переопределяет.
- **Признак готовности:** зелёный прогон при разнесённом двадцать одном молчании; красный — на
  снятом переопределении и на переопределении без назначения в светлой.
- **Чем проверяется:** пробы заводятся и снимаются в этой же ветке.

### 3. Тёмный ответ мимо слоя оформления

- **Что делается:** два рода расхождений. Тёмный блок в стилях компонента — если он не объявляет
  своё свойство компонента; шесть сегодняшних принимаются поимённо. Переопределение ступени шкалы
  тёмной темой — сегодняшнее одно, тоже списком.
- **Признак готовности:** новый тёмный блок и новое переопределение ступени роняют прогон;
  сегодняшние семь мест — нет.
- **Чем проверяется:** две пробы.

### 4. Считалка контраста

- **Что делается:** перечень пар «цвет текста и его фон» уезжает в свой файл данных; считалка
  разрешает оба имени до кода цвета в каждой теме и считает отношение яркостей. Порог 4.5:1 один
  на все пары. Пара ниже порога роняет прогон; исключение стоит с названной причиной.
- **Признак готовности:** перечень собран по стилям кита, а не выведен перебором имён; каждая пара
  посчитана в обеих темах; пара с заведомо низким контрастом роняет прогон.
- **Чем проверяется:** проба с парой ниже порога; сверка перечня со стилями руками на выборке.

### 5. Таблица замера и рукописные подсчёты

- **Что делается:** `Colors.mdx` получает таблицу замера контраста, проверка сверяет её с
  перечнем пар. Рукописные подсчёты в `_primitives.scss` и `_semantic.scss` снимаются: число,
  которое не пересчитывается при правке значения, стареет молча.
- **Признак готовности:** пара, снятая из одного перечня, роняет прогон; подсчётов в шкалах не
  остаётся.
- **Чем проверяется:** проба; `node tools/check-doc-paths.mjs`.

### 6. Правило, замеры и разбор договорённости

- **Что делается:** надстройка `styling-bem` называет третью проверку линии, её данные и границу.
  Замеры договорённости пересчитываются командами и едут в `implementation.md` и в раздел
  «Замеры» спека; правило про полноту тёмной темы получает привязку к проверке.
- **Признак готовности:** `pnpm run agent-kit:check` зелёный, `node tools/check-specs.mjs`
  зелёный, каждое число замера воспроизводится напечатанной рядом командой.
- **Чем проверяется:** обе команды; повторный прогон команд замера.

## Чего эта работа не делает

- Не перекрашивает ни одного назначения: `--rt-color-bg-surface-subtle-2` принимается списком и
  заводится своей задачей.
- Не переводит шесть компонентных тёмных блоков на слой оформления — принимает их списком.
- Не заводит линейку бренда и не трогает кольцо фокуса: это позиция 5 линии.
- Не чинит мёртвые ссылки и не объявляет недостающих токенов — позиция 6.
- Не трогает проверки литералов и графа токенов и их списки.
