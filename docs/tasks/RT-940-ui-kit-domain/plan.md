## Что считается сделанным

- `docs/specs/ui-kit/` держит `spec.md`, `scenarios.md` и `implementation.md`; каталога
  `proposed/` в нём нет.
- Сценарии `SC-UK-05`…`SC-UK-08` и сценарии двух других договорённостей лежат в `scenarios.md`
  с теми же номерами, с какими были написаны.
- Каждое правило спека несёт строку привязки `файл:символ`, и `npm run check:specs` не называет
  ни правила без привязки, ни привязки без правила.
- Указатель спеков называет домен `ui-kit` в разделе «Что уже написано», префикс `SC-UK` стоит
  в таблице префиксов, а раздел «Что предложено, но ещё не выкачено» этих трёх больше не
  перечисляет.

## Этапы

### 1. Спек домена собирается из трёх договорённостей

- **Что делается:** три `proposed/` сводятся в один спек домена с обязательным набором
  разделов; сценарии и их номера переезжают как есть, привязки проставляются на уже
  написанный код.
- **Признак готовности:** каталога `proposed/` под `docs/specs/ui-kit/` нет, а сверка спеков
  не называет ни одного расхождения по этому домену.
- **Чем проверяется:** `pnpm run check:specs` — в выводе нет ни строки с `docs/specs/ui-kit/`
  и нет раздела «Пора вливать» с этими тремя.

### 2. Указатель спеков приводится к сделанному

- **Что делается:** домен получает строку в разделе «Что уже написано» и префикс в таблице;
  раздел о предложенном перестаёт называть влитое.
- **Признак готовности:** указатель описывает то, что в дереве есть, и ни один названный им
  путь не мёртв.
- **Чем проверяется:** `pnpm run check:docs` — «расхождений нет».

## Чего эта работа не делает

- Не правит код первого кита: три правки уже выкачены своими ветками.
- Не делит домен на поддомены: делится он, когда перерастёт предел длины.
- Не заводит домен `store` — его договорённость ждёт своего слова владельца.
