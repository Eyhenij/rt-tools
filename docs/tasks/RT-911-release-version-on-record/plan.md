## Что считается сделанным

- У обеих таблиц записей груза есть необязательная колонка версии выпуска, и миграция едет этой же веткой.
- Строка правки состояния принимает пятое поле; переход в «выпущено» без версии отбивается построчно пятой причиной, а строка с версией и другим переходом отбивается целиком шестой.
- Версия длиннее предела отбивает запрос целиком; формы версии приёмник не разбирает.
- Отбитая строка не пишет ни состояния, ни версии и попадает в журнал приёмника наравне с прежними причинами.
- Панель подробностей показывает версию у обоих родов записей; у записи без версии строки в панели нет вовсе.
- Команда строки запуска несёт версию доводом выпуска.
- Живой прогон на стенде: запись отмечается командой, версия видна в панели, перевод без версии отбит.
- Договорённость влита в спек поддомена правки состояния, правило показа уехало в спек админки, довод команды — в спек наблюдений пакета; сценарии начинаются с `SC-MB-193`, каждое правило привязано, сверка спеков зелёная.

## Этапы

### 1. Колонка у обоих родов записей

- **Что делается:** моделям записей груза добавляется необязательное текстовое поле версии выпуска; миграция пишется через `migrate diff` и накатывается на местную базу. Ограничений и индексов колонка не несёт: отбор и порядок по ней держит RT-913.
- **Признак готовности:** миграция лежит рядом с прежними, местная база её приняла, клиент хранилища пересобран; лежащие записи получили пустоту.
- **Чем проверяется:** `pnpm run check:schema` — расхождения схемы и миграций не названо.

### 2. Приём версии приёмником

- **Что делается:** разбор строки правки принимает пятое необязательное поле и судит его предел длины; просьба о переходе несёт версию; заводится решение о годности версии при переходе и две причины отбоя — переход в «выпущено» без версии и версия не при том переходе; отбор пишущих строк учитывает версию наравне с текстом починки; запись состояния кладёт версию тем же запросом; отбитая строка идёт в журнал прежней строкой.
- **Признак готовности:** пустая версия и строка из пробелов отбиваются наравне с отсутствующим полем; версия длиннее предела отбивает запрос целиком; строка, несущая разом текст починки и версию, отбита; отбитая строка не пишет ни состояния, ни версии.
- **Чем проверяется:** `pnpm exec nx run-many -t test -p message-bus-api-cargo-state-feature message-bus-api-cargo-state-util message-bus-common` — спеки новых сценариев зелёные.

### 3. Версия доезжает до админки и видна в панели

- **Что делается:** чтение одной записи отдаёт поле у обоих родов; модель и маппер админки его принимают; панель подробностей показывает строку «В какой версии», а у записи без версии строки нет вовсе; подпись заводится ключом рядом с подписями соседних свойств.
- **Признак готовности:** запись с версией показывает её в панели, запись без версии не показывает ни подписи, ни пустого значения; список раздела не тронут.
- **Чем проверяется:** `pnpm exec nx run-many -t test -p message-bus-admin-postmortems-ui message-bus-admin-proposals-ui message-bus-admin-postmortems-util message-bus-admin-proposals-util` — спеки обоих родов зелёные.

### 4. Довод командной строки

- **Что делается:** довод версии выпуска встаёт в перечень доводов команды отметки, разбор доводов кладёт версию в запись груза, запись груза получает необязательное поле; подсказка помощи и описание пакета называют довод.
- **Признак готовности:** команда с доводом собирает тело с версией, без довода — прежнее тело; неизвестный довод отбивается как прежде.
- **Чем проверяется:** `pnpm exec nx test @rt-tools/agent-kit` — спеки команды зелёные.

### 5. Живой прогон на стенде

- **Что делается:** на поднятом стенде запись груза переводится командой в «выпущено» с версией, панель админки открывается в браузере, перевод без версии зовётся отдельно и читается его отбой.
- **Признак готовности:** версия видна в панели у обоих родов; вызов без версии кончился ненулевым кодом и назвал причину; в журнале приёмника стоит строка об отбое.
- **Чем проверяется:** `pnpm run serve:stand` — стенд поднят, и замер значения строки панели снят в браузере.

### 6. Договорённость вливается в спеки

- **Что делается:** последним коммитом заявки правила вливаются в спек поддомена правки состояния, правило показа уезжает в спек админки, довод команды — в спек наблюдений пакета, каталог договорённости удаляется.
- **Признак готовности:** ни одного правила без привязки, ни одного сценария без теста с тем же номером в заголовке, номера не переиспользованы.
- **Чем проверяется:** `pnpm run check:specs` — сценарии, привязки и коды отказа сошлись.

## Чего эта работа не делает

- **Проставление версии потоком публикации** — слово владельца: версию шлёт дерево поимённо, потоки публикации не трогаются.
- **Показ текста разметкой** — RT-912; панель показывает значения как есть.
- **Отбор, столбец и порядок по состоянию и версии** — RT-913.
- **Рабочий порядок разбора груза** — RT-914.
- **Правка версии из админки** — админка груз читает, правит его дерево.
- **Индекс по колонке версии** — до задачи об отборе он был бы поставлен вслепую.
