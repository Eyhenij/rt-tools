## Этапы

### 1. Две статьи в правиле

- **Что делается:** в `projects/agent-kit/assets/rules/task-flow.md` заводится статья о
  безопасной части, а статья о списке слова владельца дописывается о плывущей оценке.
- **Признак готовности:** статья о безопасной части говорит, что делится работа, а не ход.
- **Чем проверяется:** чтение раздела целиком.

### 2. Привязка и разбор

- **Что делается:** обе статьи получают строку в компаньоне правила; запись разбора уезжает в
  `docs/postmortems/handled/` с номером задачи в шапке.
- **Признак готовности:** сверка спеков видит обе статьи привязанными, в корне разборов записи
  нет.
- **Чем проверяется:** `npm run check:specs`, `npm run check:docs`.

### 3. Раскладка и проверки

- **Что делается:** гоняется раскладка и проверки текстов и гардов.
- **Признак готовности:** все нули.
- **Чем проверяется:** `pnpm run agent-kit:check`, `npm run check:docs`, `check:specs`,
  `check:hooks`, наборы сценариев пакета.

## Чего эта работа не делает

- **Не расширяет гард ожидания на ход с красным прогоном.** Признак «прогон красный» надо
  доставать из самого хода, не ходя в сеть, — это отдельный вопрос и отдельная работа.
- **Не правит закон.** Статья закона — договорённость с владельцем; здесь правится правило.
- **Не трогает список «Что не делается без слова владельца».** Он свой у каждого дерева, и
  правка в него — решение владельца этого дерева, а не пакета.
