## Что считается сделанным

- Конфликтующая заявка, ветку которой эта рабочая копия не вела, работу не запрещает: она названа
  отдельной строкой, и сессия говорит о ней владельцу.
- Своя конфликтующая заявка запрещает взятие работы, как и раньше.
- Форма имени ветки судится профилем того дерева, в каталоге которого исполняется команда; у
  дерева без профиля форма не судится вовсе.
- Push, позванный из другой рабочей копии, отбивается с указанием, что набор идёт в копии сессии.
- В правиле поставки стоят три статьи с привязками: о чужой конфликтующей заявке, о форме имени
  ветки соседнего дерева и о второй рабочей копии.
- Записи груза, закрытые этой правкой, помечены в приёмнике сделанными.

## Этапы

### 1. Чужая конфликтующая заявка не считается своей

- **Что делается:** ярус конфликта делит список заявок на свои и соседские по тому, вела ли эта
  рабочая копия ветку; свои запрещают взятие работы, соседские называются и не запрещают
- **Признак готовности:** при одной соседской заявке взятие работы проходит, а её номер и ветка
  названы в выводе; при своей — отказ как прежде
- **Проверено:** `bash projects/agent-kit/tests/git-guard-delivery.test.sh` — пробы яруса зелёные

### 2. Форма имени ветки судится деревом исполнения

- **Что делается:** каталог исполнения берётся из самой команды; форма спрашивается у профиля
  найденного дерева, а при отсутствии профиля не спрашивается вовсе
- **Признак готовности:** законное имя ветки соседнего дерева проходит, а промах в имени своего
  дерева отбивается как прежде
- **Проверено:** `bash projects/agent-kit/tests/git-guard-delivery.test.sh` — пробы формы имени

### 3. Push идёт из копии сессии

- **Что делается:** push, у которого в тексте команды назван переход в другой каталог дерева,
  отбивается с указанием, где идёт набор проверок
- **Признак готовности:** обычный push проходит, push с переходом в чужой каталог отбивается
- **Проверено:** `bash projects/agent-kit/tests/git-guard-delivery.test.sh` — пробы push

### 4. Статьи правила и привязки

- **Что делается:** три статьи в правило поставки, привязки к ним в файле привязок дерева, новые
  сценарии в описаниях обеих областей
- **Признак готовности:** аудит описаний не называет ни статьи без адреса, ни адреса без статьи
- **Проверено:** `npm run check:specs` — расхождений нет

### 5. Установка файлов из пакета и пометки в приёмнике

- **Что делается:** пакет собирается и раскладывается, четыре записи груза помечаются сделанными
- **Признак готовности:** аудит установки молчит, записи стоят в состоянии «сделано»
- **Проверено:** `pnpm run agent-kit:check` — расхождений нет

## Чего работа не делает

- Не трогает порядок сдачи и черновик: это задача #2038, и она ждёт слова владельца.
- Не правит установку файлов из пакета и подъём версии: задача #2032.
- Не заводит признака владения заявкой на стороне доски: список заявок даёт профиль дерева.
