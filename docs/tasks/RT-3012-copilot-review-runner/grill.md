# Разбор

## Просьба владельца

> напиши локальный раннер для github copilot, пример можно глянуть на […]

## Что уже есть в дереве

- Ревью Copilot в PR уже приходит: запуски «Running Copilot Code Review» 30.10.2026 зелёные. Идут
  они на облачной машине GitHub: файла с заданием `copilot-setup-steps` в `.github/workflows/` нет.
- Репозиторий публичный. Облачные минуты Actions ему сейчас ничего не стоят.
- Раннер проверок `Yauhenis-MacBook-Pro`: метки `self-hosted, macOS, ARM64, mac-m1`, каталог
  `~/actions-runner`, служба launchd. На нём идут `ci.yml` и первое задание `deploy.yml`.
- На той же машине стоит раннер другого репозитория. Правило `git-workflow`: пути от домашней
  папки общие, поэтому каталог, контейнер, сборщик и сеть называются по проекту.
- Каталог `deploy/` держит файлы выкатки приёмника и входа. Своего раннера в контейнере в дереве
  ещё не было.

## Что уже сказано в правилах

- Раннер ревью Copilot в документации не найден. Искал по словам `copilot`, `copilot-setup-steps`,
  `ephemeral`. Ответ взят со страницы GitHub о раннерах для агента Copilot: ревью идёт только на
  Ubuntu x64, задание называется `copilot-setup-steps`.
- Правило `git-workflow`, «On a machine with several runners»: имена на общей машине — по проекту.

## Вопросы и ответы

Меню не задавалось: два ответа «рекомендую» подряд в этой сессии закрывают вопросы допущением.

| Вопрос                                | Ответ                                                                                                                        |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Меняет ли задача поведение приложения | нет, допущение: меняется только машина, на которой идёт ревью                                                                |
| Нужна ли правка закона или правила    | нет, допущение                                                                                                               |
| Одна задача или несколько             | одна, допущение: раннер, его сеть и файл запуска откатываются вместе                                                         |
| Что в задачу не входит                | раннер проверок `~/actions-runner`, `ci.yml`, `deploy.yml`, биллинг GitHub                                                   |
| Чем видно, что задача закрыта         | раннер с меткой `rt-copilot-review` на связи; задание `copilot-setup-steps` прошло на нём; прокси не пускает хост вне списка |
| Есть ли образец                       | да, владелец назвал готовый раннер того же устройства                                                                        |

## Решения

- **Раннер — одноразовый контейнер Ubuntu x64 под эмуляцией.** Ревью Copilot идёт только на
  Ubuntu x64, а машина — Apple Silicon. Нынешний раннер отвергнут: он macOS ARM64, рядом с ним
  ключ прода и сокет Docker.
- **На каждое задание раннер регистрируется заново, после задания контейнер удаляется.** Код ревью
  не оставляет следов для следующего задания.
- **Сеть контейнера закрыта, наружу только через прокси со списком хостов GitHub и Copilot.**
- **Имена — с приставкой `rt-copilot-`.** На машине стоит раннер другого репозитория.
- **Сборка образов идёт своим сборщиком с пределом кэша.** Стандартный сборщик машины кэширует
  без предела.

## Что осталось неясным

- Облачное ревью сейчас бесплатно, своё пойдёт под эмуляцией x64 и медленнее. Работа не стоит:
  просьба прямая, цена названа владельцу в отчёте.
