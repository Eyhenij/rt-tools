## The owner request

Текст задачи #3283:

> ## Что не так
>
> Набор перед отправкой не считает, какая его проверка приносит пользу. Проверка может месяцами
> идти на каждой отправке, ни разу не отказать и ни разу не найти ошибку. Другая отказывает ложно,
> и её просто перезапускают. Сейчас это видно только по разборам инцидентов: 13.11.2026 набор шёл
> семь раз, три запуска ушли впустую, а шаг сценариев проверок пакета шёл 13–19 минут на ветках,
> где сами проверки никто не трогал.
>
> Отчёт метрик пакета считает отказы проверок разговора. О проверках набора в нём нет ни строки.
>
> ## Что сделать
>
> Завести метрику бесполезности проверок набора. По каждой проверке набора за период отчёт
> показывает:
>
> - сколько раз она шла и сколько секунд заняла в сумме;
> - сколько раз отказала;
> - сколько отказов были ложными: повтор на том же дереве прошёл зелёным;
> - сколько раз она шла на ветке, которая не меняла её предмет;
> - цену одного найденного дефекта: секунды работы на один настоящий отказ.
>
> Набор уже пишет строку о каждом запуске шага. К ней добавить дерево, базу, исход и время, чтобы
> повтор на том же дереве можно было узнать.
>
> Отчёт отдельно называет проверки, которые за период ни разу не отказали по делу, и проверки, у
> которых ложных отказов больше, чем настоящих.
>
> ## Как поймём, что готово
>
> - Команда отчёта метрик печатает таблицу проверок набора с пятью числами по каждой.
> - Сценарий: проверка отказала, повтор на том же дереве зелёный — отказ посчитан ложным.
> - Сценарий: проверка шла на ветке без изменений её предмета — запуск посчитан лишним.
> - За первую неделю отчёт называет хотя бы одну проверку, которую стоит убрать из набора или
>   перенести в конвейер.

## What the tree already has

- Оба исполнителя набора — `git-guard-push-ahead.sh` и `push-set.sh` — зовут на каждый шаг
  `rt_run_note <подпись содержимого> <начало> <green|red|skipped> <команда>`

  `image`, `stand`, `tests`, `check`), секунды, `wasted` — секунды прошлого красного запуска той же
  команды на той же подписи. Имени проверки в наблюдении нет. [В]
- Отметки дня живут месяц; на машине они есть с 07.11: 10 591 зелёный, 254 красных, 140

- Отчёт `metrics` уже печатает «пустые запуски» по видам шага (`runsOf` в `metrics.ts`): число
  запусков, минуты, пустые запуски и их минуты. По проверке он не разбивает. [В]

- 17.11 набор этой ветки RT-3270 шёл трижды: два красных прогона, `test-hooks` занял 538 и 394 с. [К]

## Decisions

- **Поведение меняется только у отчёта пакета.** Задача просит таблицу в команде отчёта; приёмник
  и экран она не называет. Код — `projects/agent-kit`, договорённость — поддомен спеки метрик
  пакета. Отвергнуто: слать таблицу в приёмник — в просьбе этого нет.
- **Закон и правило не правятся.** Метрика — код пакета.
- **Одна задача.** Запись запуска и отчёт по ней откатываются вместе: отчёт без записи пуст.
- **Источник отчёта — отметки дня `runs-<день>`, а не наблюдения.** Они уже хранят подпись
  содержимого и команду по каждому запуску, за месяц; наблюдение уходит наружу и имени проверки
  нести не может. Строка отметки дописывается временем, cksum базы и признаком «предмет не
  тронут». Старые строки без новых полей считаются в четырёх числах из пяти.
- **Имя проверки — её команда из текущего набора дерева**, найденная по cksum. Команда, которой в
  наборе уже нет, печатается своим cksum.
- **Ложный отказ — красный запуск, после которого та же команда на той же подписи содержимого
  прошла зелёной.** Это слова просьбы «повтор на том же дереве прошёл зелёным»; подпись содержимого
  и есть дерево.
- **Настоящий отказ — красный запуск, после которого на той же подписи зелёного не было.**
- **Предмет шага — то, что он читает.** Для шага из таблицы `push-inputs.json` — его записанные
  чтения: `select` судит тем же правилом. Для шага `nx affected` — корни проектов, которые он
  затрагивает. Для шага, у которого предмет не записан, отчёт пишет «предмет не записан», а не ноль.
- **Цена дефекта — секунды всех запусков проверки на один настоящий отказ.** Без настоящих отказов
  цена — «ни одного дефекта», а проверка попадает в список «ни разу не отказала по делу».
- **«Стоит убрать или перенести в конвейер»** — проверка без настоящих отказов за период или с
  ложными отказами больше настоящих; обе группы отчёт называет отдельно, как в просьбе.
- **Признак готовности на данных этой машины:** отчёт за неделю 11–17.11 называет хотя бы одну
  такую проверку.
