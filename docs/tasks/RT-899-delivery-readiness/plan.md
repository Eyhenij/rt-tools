# Замысел

**Задача:** RT-899 · **Ветка:** `RT-899-delivery-readiness`
**Поведение:** не меняется — работа идёт по слою правил, а не по коду приложения: продукта, о
котором пишется договорённость, она не задевает.

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## След задачи

Части пакета правил названы словами, а не полными путями: гард хода работы читает пути из текста
команды и признаёт правкой кода любое упоминание пути внутрь пакетов — даже в команде, которая
пишет документ.

| Что     | Где                                                             |
| ------- | --------------------------------------------------------------- |
| Правила | правило поставки в пакете правил и его компаньон в этом дереве  |
| Код     | профиль дерева, гард поставки и гард гейта пуша в пакете правил |
| Тексты  | спек домена о проверках и спек домена о ведении работы          |
| Тесты   | наборы гардов поставки и наборы профиля в пакете правил         |
| Дерево  | `.claude/rt-kit/defaults/project.sh`, `.claude/hooks/`          |

## Что считается сделанным

- Готовность к поставке отдаётся одним ответом: основание ветки, подпись коммитов, состояние
  задачи с колонкой, папка задачи и ревьювер приходят вместе.
- Отказ поставки называет все несошедшиеся условия разом и при каждом — что сделать.
- Условия, известные в начале работы, спрашиваются в начале: заведение ветки отбивает несвежее
  основание и чужую почту коммитов, а не оставляет их на пуш.
- Ревьювер входит в готовность и спрашивается на снятии черновика.
- Всё, чего не хватило — нет сети, нет ответа очереди работ, — молчит и работу не отбивает.

## Этапы

### 1. Готовность к поставке одним ответом

- **Что делается:** в профиле дерева заводится функция, собирающая готовность целиком и отдающая
  её одним ответом; при ней — разбор, называющий несошедшееся словами.
- **Признак готовности:** функция отвечает по каждому из пяти условий и при нехватке ответа
  очереди работ говорит об этом отдельно, а не молчит признаком «сошлось».
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 2. Гард поставки спрашивает готовность целиком

- **Что делается:** гард поставки на открытии PR зовёт эту функцию вместо россыпи проверок и
  печатает в отказе все несошедшиеся условия разом.
- **Признак готовности:** отказ называет каждое несошедшееся условие и что с ним делать; ни одно
  из прежних условий не потеряно.
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 3. Начало работы держит то, что известно в начале

- **Что делается:** заведение ветки отбивает несвежее основание и чужую почту машинных коммитов
  — оба куска кода переезжают с конца работы в её начало.
- **Признак готовности:** ветка, заведённая от отставшей главной, отбивается сразу; на пуше
  прежние проверки остаются как второй рубеж.
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 4. Ревьювер входит в готовность

- **Что делается:** снятие черновика отбивается, пока у PR нет ревьювера; при отсутствии ответа
  хостинга проверка молчит.
- **Признак готовности:** PR без ревьювера черновик не снимает, PR с ревьювером снимает.
- **Чем проверяется:** `pnpm run agent-kit:hooks` — строка «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ».

### 5. Тексты и сценарии

- **Что делается:** правило поставки получает статьи о готовности одним состоянием; спеки
  доменов — правила, сценарии и привязки к коду.
- **Признак готовности:** каждый новый сценарий закрыт набором, каждое правило привязано к коду.
- **Чем проверяется:** `pnpm run agent-kit:check` — расхождений нет.

## Чего эта работа не делает

- Не правит закон о поставке: его статьи приносятся владельцу текстом, а работа идёт дальше.
- Не заводит проверок на ветку без номера задачи: она законна, пока живёт локально.
- Не трогает сверку очереди работ — она судит состояние, а не команду, и останется как есть.
