## Язык описания task flow

Слово владельца: «держать описание таск флоу на подобном языке что бы в будущем расширять и
дополнять таск флоу более гибко»; в меню — «Свой по образцу HighScript». Сценарий не пишется
плоским JSON: он описан на узком языке данных, а движок, заготовки и тексты правил берутся из
этого описания.

**Источник** — `projects/agent-kit/assets/task-flow/flow.js`: один объект в скобках с точкой с
запятой, как `project.js` у HighScript. Парсер читает его по токенам и ничего не исполняет.
`flow.md` рядом генерируется из него; `flow-sync.mjs --check` сравнивает файл с генерацией как текст.

**Значения** — только литералы (строка в кавычках, число, `true`, `false`, `null`), ссылки
`секция.имя[.поле…]` без кавычек, вызовы ссылок с такими же аргументами, условия, массивы и
объекты из них. Функций, выражений, `require` и импортов нет. Имена — `[A-Za-z][A-Za-z0-9]*`;
русское имя состояния — литерал `title`.

**Условия** — объект с одним ключом: `{ all: [...] }`, `{ any: [...] }` или `{ not: … }` над
ссылками на измерители и другими условиями. Условие стоит там же, где ссылка: в `exit` состояния и
в `when` случая отпуска. Выход из готовых измерителей собирается без JS; новый факт — новый
измеритель. Условие проверяет и вычисляет `flow-condition.mjs`: ссылка ведёт только на
возможность измерителя этого описания, у объекта ровно один ключ. Результата измерителя нет —
условие не выполнено. Пока у движка нет команды `measure` (шаг 1.10), выход состояния по
результатам печатает `node flow-model.mjs <flow.js> --exit <состояние> <results.json>`; `measure`
зовёт ту же функцию. У модуля условий нет своей командной строки: он и модель импортировали бы
друг друга.

**Данные** — `words`, `expect` и порядок `release` — проверяет `flow-data.mjs`: известные ключи
`words`, списки непустых строк, образец `nudge` собирается с флагами `iu`; у формы ожидаемого
образец собирается, `compare` — один из четырёх способов; `order` — целое от 1 без повторов.
Модель отдаёт `release` списком в порядке `order`. Там же читатели данных: `saysStop`,
`isWriteCommand`, `compareExpected`. Правила спека о них пишутся шагом, который их зовёт: `step` —
шаг 2.4, отпуск хода — шаг 3.7; до того привязка вела бы в код, который зовёт только набор.

**Секции** — ровно шесть:

| Секция | Что в ней | Файл |
| ------ | --------- | ---- |
| `source` | источники данных: `git` — история ветки, `tree` — рабочая копия, `host` — хостинг, `marks` — метки, `owner` — сообщения владельца, `session` — вызовы сессии, `steps` — разбор плана и хода работы через `work-steps-lib.mjs`; порты `{}`, кэш и его срок — константы в файле источника | `task-flow/source/<имя>.mjs` |
| `measure` | измерители выходов и условий; capability — именованный экспорт, порты — ссылки на `source` | `task-flow/measure/<имя>.mjs` |
| `state` | 13 состояний по порядку: `title`, `action`, `pattern`, `exit` — ссылка на измеритель или условие, `end` у последнего; `after` — у состояния надстройки | — |
| `release` | случаи отпуска хода: `when` — ссылка или условие, `order` — порядок проверки, `log` — запись в журнал | — |
| `words` | литералы: слова остановки `stop`, исключения `stopExcept` и `holdAfter`, образец подталкивания `nudge`, команды записи `write`, варианты меню отказа `menu`, ветки планов до движка `legacyBranches` | — |
| `expect` | формы ожидаемого у шага плана: образец `pattern` и способ сравнения `compare` — `exit`, `line`, `regex` или `number` | — |

```js
({
  source: { git: { open: {} }, marks: { open: {} }, steps: { open: {} }, owner: { open: {} }, session: { open: {} } },
  measure: {
    plan: { approved: { git: source.git, marks: source.marks, steps: source.steps } },
    owner: { saidStop: { owner: source.owner }, nudged: { owner: source.owner } },
    session: { wrote: { session: source.session } },
  },
  state: {
    taken: { title: 'задача-взята', action: 'write the plan', pattern: 'task-flow-start', exit: measure.plan.approved },
  },
  release: {
    stopWord: { when: measure.owner.saidStop, order: 2, log: 'a stop word of the owner' },
    noWrite: { when: { all: [{ not: measure.session.wrote }, { not: measure.owner.nudged }] }, order: 3, log: 'no write' },
  },
  words: { stop: ['стоп', 'стой', 'хватит'], stopExcept: ['продолжай', 'делай'], menu: ['отложить RT-N', 'сделаю сам', 'стоп'] },
  expect: { exit: { pattern: '^exit (\\d+)$', compare: 'exit' } },
});
```

**Контракт.** Порты измерителя и источника — ключи объекта под capability — точно равны сигнатуре
фабрики: `()` или `({ a, b })` без значений по умолчанию, переименований и вложенных шаблонов.
Иначе движок не стартует и называет компонент. Любой файл каталога `measure/` — измеритель и его
соседи — импортирует только файлы того же каталога, путь начинается с `./`; `import()`, `require`,
`createRequire`, `process` и `globalThis` в нём отказаны. Данные приходят только портами, тест
подставляет двойника источника. Значение порта — только ссылка на компонент: литерал вроде срока
кэша в порт не ставится. Фабрика измерителя возвращает читателя; движок зовёт его с данными
описания `{ words, expect }` — так измеритель получает слова и формы ожидаемого без порта.

Фабрика, которую ещё не написал её шаг, бросает `Not implemented` — та же форма, что даёт
генератор заготовок. Неизмеренный выход поэтому никогда не читается выполненным. Описание пакета
называет все 13 выходов с шага 1.6, а каждую фабрику пишет шаг, который меряет её выход.

Разложенный `flow.js` несёт шапку раскладки строкой-комментарием перед `({`; парсер её пропускает.
Описание исключено из линта: линтер принимает ссылки описания за необъявленные переменные, а форму
описания проверяют модель и её набор. Случаи 6 и 7 раздела «Когда ход отпускается» — сбой движка
и предел Claude Code — описанием не выражаются: их ловит обвязка движка в `dispatch.sh` и хуке на
Stop. Поэтому в `release` описания пакета шесть случаев с `order` 1–5 и 8.

Движок находит описание рядом с собой: `task-flow/flow.js` у разложенного движка,
`../task-flow/flow.js` в пакете; `--flow <путь>` называет другое.

**Надстройка дерева** — `.claude/rt-kit/overrides/task-flow/flow.js`, тот же язык. Ключ добавляет или
заменяет состояние, измеритель, случай, слово с той же сверкой контракта. Состояние надстройки
встаёт после состояния, которое называет его поле `after`, без поля — в конец; случай отпуска — по
`order`, повтор `order` отказан. Убрать ключ пакета можно только значением `null` и строкой причины
рядом (`reason: '…'`); без причины описание не собирается, а `measure` печатает убранное. Тексты по
надстройке пишутся в спутник дерева `implementation.md` правила `task-flow` между пометками
`<!-- flow:tree -->`: разложенное правило надстройку не видит и не меняется.

**Охрана описания.** Слово владельца: «Только по твоему слову или в задаче с этим следом». Страж
`flow-step-guard.sh` отказывает Edit, Write и записи оболочкой:

- в надстройку дерева — если последнее сообщение владельца не называет ключ, который меняет правка;
  причина у `null` — цитата из этого сообщения. Подпись варианта меню засчитывается словом владельца,
  поэтому меню о правке надстройки показывает ключ в подписи варианта;
- в `projects/agent-kit/assets/task-flow/`, в разложенный `tools/task-flow/` и в движок
  `task-flow-script.mjs`, `flow-*.mjs` — если план текущей задачи не одобрен или ни одна строка
  «(правится)» её следа не называет этот путь. Одобрен — значит, есть метка `plan-red`, или план
  добавлен в ветку раньше движка (раздел «Сценарий»): так охрана не запирает саму RT-3329 на этапе 6.

Разложенный `tools/task-flow/` охраняет и страж шапки раскладки.

**Заготовки** — `flow-scaffold.mjs`. Новый измеритель или источник получает файл с фабрикой, которая
бросает `Not implemented`, и случай теста-заглушку. Готовый код не трогается. Предупреждения:
`CONTRACT_CHANGED` — порты разошлись с сигнатурой; `UNREACHABLE_MEASURE` — измеритель не назван ни
одним состоянием и случаем; `MEASURE_REMOVED` — файл есть, в описании нет, файл остаётся.

**Генерация текстов** — `flow-sync.mjs`. Из описания пакета пишутся пять представлений, каждое между
пометками `<!-- flow:… -->`: `flow.md`, таблица «Work states» правила `task-flow`, карта хода,
раздел о конце хода правила `turn-conduct`, таблица форм ожидаемого шаблона плана. Ручная правка
между пометками отказывается проверкой `--check`, она стоит в наборе перед push. В дереве с
надстройкой `--check` сверяет и шестое представление — её текст в спутнике.

Надстройка, заготовки и генерация текстов — этап 6, после раскладки движка: этапы 1–5 дают
сценарий на описании пакета, а тексты этапа 4 правятся рукой.

## Сценарий: выход каждого состояния

- Выход — факт истории, который остаётся верным и в поздних состояниях. Строку `State` ни один

## Метки и кто их пишет

Метки шагов, метка одобрения и кэш выходов 2 и 4 лежат в
`$(git rev-parse --git-common-dir)/rt-kit/`: метка одобрения — `approval/<ветка>.json`, метка шага —
`steps/<ветка>/<N.M>.json`. Метка, которая не читается как JSON, считается отсутствующей. Пишет их только движок; проба 2.8 ничего не хранит.
Страж `flow-step-guard.sh` отказывает Edit, Write и команде оболочки, которая пишет в этот каталог
и не является вызовом `task-flow-script.mjs`. Тот же страж отказывает записи оболочкой в
`progress.md`, `plan.md` и план эпика под `docs/plans/`. Страж судит текст команды: скрипт, который
вычисляет путь к каталогу сам и не называет его в команде, он не видит. Подписи у метки нет — пункт 12
раздела «Цена».

## Когда ход отпускается

Ход под открытым эпиком отпускается только так:

1. Измерен конец сценария: выход 13, а вне эпика — выход 10.
2. Последнее сообщение владельца — набранное или свободный текст ответа меню — начинается со слова
   остановки (список ниже). Слово не действует, если дальше в том же сообщении стоит «продолжай»,
   «делай», «работай» или «доделывай» без «не» перед ним, или если «хватит» стоит перед «стоять»,
   «останавлива…», «ждать». «Стоп, не делай этого» отпускает ход.
3. Сессия ни разу не писала в дерево, или ветка вне сценария. Запись в дерево — это вызов Edit,
   Write или NotebookEdit, команда работы (`git commit`, `git push`, `gh pr`, `task:new`,
   `task:move`, `agent-kit:sync`) или слияние PR. Для сессии без записи случай не действует, если
   последнее сообщение владельца совпадает с образцом подталкивания или называет задачу или эпик:
   «ну что там?» в новой сессии держит ход. Ветку вне сценария подталкивание не держит: движку
   нечего назвать следующим шагом.
4. Сессия роли (`turn-exit-role.sh`): роль отдаёт отчёт главному агенту.
5. Хостинг не ответил дважды, и первый невыполненный выход читает хостинг.
6. Движок упал, вышел за свой предел 75 с, или `dispatch.sh` не смог его вызвать. Исход явный: ход
   отпущен, в журнал пишется «движок упал» с причиной, и следующий ход начинается строкой о сбое:
   хук начала хода читает журнал. Хук на Stop получает timeout 90 с, поэтому свой предел движка срабатывает раньше.
7. Claude Code сам кончил ход после 8 продолжений подряд. Восьмой отказ подряд пишется в журнал.
8. Отказ назвал меню владельцу, а меню не дошло до него второй раз подряд: его задержал хук меню
   или вызов отказан. Ход отпущен, в журнал пишется «меню не дошло».

Отказ называет всегда один ход: следующий шаг сценария. Если этот шаг запрещает другая проверка
или он принадлежит владельцу, ход один — меню владельцу. В меню отказа три варианта: «отложить
RT-N», «сделаю сам», «стоп». Ответ владельца, и подпись варианта тоже, — его слово: «отложить RT-N»
ставит отметку «отложено» и даёт следующую задачу; «сделаю сам» блокирует задачу шагом владельца с
цитатой и даёт следующую; «стоп» отпускает ход; свободный текст судится как любое его сообщение.
Меню ждёт ответа внутри хода. Хук меню пропускает меню отказа с этими тремя вариантами; вариант, в
котором агент снимает или ослабляет хук или проверку, задерживается и здесь: так в RT-3304 проверку
снял владелец сам.

## Шаг плана и его проверка

Каждый шаг плана — две строки. Разбор принимает и «Проверка:», и «Check:».

```
    1. <что сделано>
       Проверка: `<команда>` → <ожидаемое>
```

| Ожидаемое | Совпадение |
| --------- | ---------- |
| `exit N` | код выхода N, вывод не сравнивается |
| `` `текст` `` | код 0, последняя непустая строка вывода равна тексту |
| `/выражение/` | код 0, последняя непустая строка совпадает с выражением |
| `= N`, `>= N`, `<= N` | код 0, последняя непустая строка — целое число, сравнение верно |

Формы и способ сравнения берутся из секции `expect` описания: новая форма — строка описания.

- `node tools/task-flow-script.mjs step <N.M>` берёт команду из коммита, добавившего план, и
  запускает её с пределом 540 с. Печатает `ожидалось … · получено … · совпало` и выходит с кодом 0,
  или `… · не совпало` с кодом 1. При совпадении пишет метку шага: ветка, шаг, отпечаток плана,
  вершина, последняя строка.
- Страж правки хода работы читает только метку и ничего не запускает. Предел вышел — шаг не совпал.
- Команда работы проверкой шага быть не может. Такая проверка отказана, и план с ней не записывается.
- Форма ожидаемого не распознана — план не записывается: страж отказывает записи `plan.md`.
- `step --done` перемеряет все шаги, уже отмеченные `[x]`, и пишет их метки.
- Счёт случаев набора — по именам: `required-cases.mjs` берёт из таблицы «Обязательные случаи»
  коммита плана номера случаев группы и ищет каждый в строках `ok` набора.
- Вердикты хуков модели (шаги 3.15, 3.16) пишет субагент по подсказке, которую печатает
  `judge-prompt.mjs`: текст хука и записанные ходы. Ожидаемые вердикты лежат отдельно, в
  `projects/agent-kit/tests/turn-replay.expected.json`, и подсказка запрещает читать файлы дерева.
  Отчёт субагента кончается строкой `hook <отпечаток хука> verdicts <отпечаток вердиктов>`.
  `judge-verdicts.mjs` находит в записи разговора вызов Agent, у которого отпечаток входа равен
  отпечатку подсказки, собранной заново, а в его результате — полный id и эту строку. Вердикты,
  вписанные рукой, исправленные после вызова или полученные по другой подсказке, не сходятся.
  Вызов — общий субагент (`general-purpose`) без фона: свой тип субагента несёт свою системную
  подсказку, а фоновый вызов не возвращает отчёт в результат того же вызова.
  Субагент с Read может открыть файл ожидаемых вердиктов вопреки подсказке — пункт 13 раздела
  «Цена».

## Что считается сделанным

- Task flow описан на своём языке данных в `flow.js`: 13 состояний, случаи отпуска с порядком,
  слова, команды записи, варианты меню и формы ожидаемого со способом сравнения; выходы и случаи
  собираются из условий `all`, `any`, `not`. Парсер ничего не исполняет, контракты измерителей
  сверены с сигнатурами, измеритель импортирует только файлы рядом. Надстройка дерева сливается по
  ключу, генератор даёт заготовки, пять текстов правил генерируются из описания. Надстройку правит
  только слово владельца с её ключом, описание пакета — только задача с этим следом. Движок меряет
  выходы и печатает «ожидалось / получено».
- Строку `State` нельзя поставить впереди измеренного состояния, метку `[x]` — без зелёной метки
  шага, метку — мимо движка. `[x]` и `[>]` не по порядку отказаны. `progress.md`, `plan.md` и план
  эпика нельзя писать командой оболочки. «Отложено» без слова владельца отказано.
- У каждого шага нового плана есть проверка известной формы и записанный красный вывод.
- Ход отпускается только в восьми случаях раздела «Когда ход отпускается»; каждый обязательный
  случай прошёл по имени.
- Agent-хук модели не судит открытую работу и оставляет обязанности о словах владельца, среди них
  «the owner's latest word orders work the turn has not done». Хук меню отказывает меню, которое
  снимает проверку без слова владельца об этом, и пропускает меню, которое назвал отказ проверки
  выхода. Вердикты обоих хуков на записанных ходах совпали с ожидаемыми.
- Правила, карта хода, шаблоны, описание миссии и подобласть `flow-script/` говорят то же; ни один
  текст следа не называет старые выходы; все наборы пакета зелёные.

## Слова владельца, которые отпускают ход

Последнее сообщение владельца — набранное или свободный текст ответа меню — начинается с одного из
слов: «стоп», «стой», «хватит», «остановись», «прекрати», «не сейчас», «подожди», «погоди», «жди»,
«пауза», «отбой», «на сегодня всё», «stop», «wait», «not now», «pause». После слова идёт пробел,
знак препинания или конец сообщения. Регистр не важен. Исключения — в случае 2 выше.

Замер 15.11 по времени сообщения, по записям всех шести копий дерева: 682 набранных сообщения
владельца с 13.10. Список ловит все пять остановок: «Стой …» 02.11, «жди конца …» 29.10, «жди
соседа» 30.10, «Остановись на логической точке…» 13.10, «Не сейчас» 14.11. 13 других сообщений с
похожими словами — вопросы и ругань, среди них «…ты остановился…»; ни одно не ловится.

За «жди соседа» 30.10 через 22 минуты пришло «ну что там?»: владелец ждал, но ход не держал. Слова
«жди», «подожди», «погоди», «wait», «пауза» отпускают ход по ответу «Только твоё «стоп»», где
владелец назвал «остановиться или подождать». Держать ли на них ход вызовом, который ждёт, —
вопрос меню одобрения.

Не отпускают: «не останавливайся», «почему стоишь?», «хватит останавливаться, продолжай», «Стой, не
туда — делай RT-N», ругань, подпись варианта меню вне меню отказа, отказ вызову без набранного слова,

## Цена, которую план называет владельцу

Ответ «Только твоё «стоп»» других выходов не называет. Без случаев 3–8 раздела «Когда ход
отпускается» агент застрял бы или пошёл бы против закона. Каждый — вопрос меню одобрения:

1. **Хостинг не отвечает (случай 5).** Без отпуска агент повторял бы чтение без конца.
2. **Сессия без записи и сессия роли (случаи 3, 4).** Закон: «A session does not start work by
   itself». Роль, которую держат, не отдаёт отчёт.
3. **Движок упал (случай 6).** Без явного исхода сбой выглядит как законный конец.
4. **Предел Claude Code — 8 продолжений подряд (случай 7).** Его меняет одна строка
   `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` в настройках. Оставить или поднять предел.
5. **Меню не дошло (случай 8).** Без него отказ и задержанное меню повторяются без конца, а вызов
   меню сбрасывает предел 8.
6. **Хвост эпика.** Агент ждёт CI внутри хода и вливает PR сам — по слову владельца от 05.09.2026
   «мержи твои пр от моего имени» — и держит ход, пока PR эпика не откроется. Это расходится со
   статьями закона «Work is not spent waiting for the machine» и концом эпика «until the owner's

## Риски

- **Проба 2.8 зовёт `claude -p`, а его вход истёк** («OAuth session expired»). Войти может только
  владелец: `claude`, затем `/login` в терминале. Он ответил «Войду позже», поэтому проба стоит
  последним шагом этапа 2: этапы 1 и 2 идут без входа, а этап 3 ждёт ответа пробы. Ответ пробы
  `allow wins` значит, что agent-хук отпускает ход в обход командного. Тогда работа встаёт после
  шага 2.8, и владельцу уходит меню с этим фактом: обхода план не строит.
- **Свой тупик.** План не правится, а страж не даёт `[x]` без метки. Ошибка в проверке шага
  лечится только заменой проверки с цитатой владельца. Поэтому каждая проверка выше запущена в
  минуту записи, а файлы, которые проверки зовут, лежат в коммите плана.
- **Раскладка меняет хуки всех сессий этой копии.** Обязательные случаи гоняются на источнике до
  раскладки (шаги 3.2–3.16), раскладка — только после прогноза не выше 4 на сто (шаг 3.17).
- **Прогноз выше 4 на сто.** Тогда шаг 3.17 красный, и решение до раскладки принимает владелец:
  заменить проверку можно только с его цитатой.
- **Сборка пакета общая.** Роли и соседние сессии не собирают пакет, пока идёт набор или раскладка.
- **RT-3276 ждёт живой проверки владельца.** Её шесть ходов входят в записанные ходы (шаг 3.13).
