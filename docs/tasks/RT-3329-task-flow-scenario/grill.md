# Разбор

## Просьба владельца

> пиши исполняемый сценарий как говорит тимур шамсединов, нужно чтобы агент шёл исключительно по шагам этого сценария и на каждом шаге в сценарии нужно прописать какие должны быть измеряемые результаты и агент не может двинуться на следующий шаг пока не выполнил условия предыдущего, агент хук должен сравнивать измеряемый результат на каждом шаге и исключать остановки агента пока не выполненны следующие шаги сценария. любые остановки как это было ранее должны быть исключены, агент должен всегда доводить сценарий до конца

Я начал искать это понятие в интернете. Владелец прервал поиск и уточнил:

> сценарий должен реализовывать task flow, […] читай task flow

Значит, сценарий — это ход работы правила `task-flow`: его состояния и обязательные действия. Шаг
сценария — состояние работы, а внутри состояния `этап-идёт` — шаг плана.

## Что уже есть в дереве

- Правило `task-flow`, таблица «Work states»: 13 состояний, у каждого вход, обязательное действие
  и паттерн. Выхода, который можно измерить, у состояний нет.
- Состояние объявляет сам исполнитель строкой `- **State:**` в `progress.md`. Файл привязок правила
  `.claude/skills/task-flow/implementation.md` прямо говорит: строку состояния не проверяет ничего,
  «there is no source of the state other than this line at all, and the guard turn-exit-guard.sh is
  obliged to believe it». Переход вперёд сейчас ничем не измеряется.
- Шаблон плана `docs/tasks/_template/plan.md`: у этапа есть строка «Verified by: `<command>` —
  <what in its output means it matched>». У шагов внутри этапа есть только название. Статья правила
  «A stage's readiness sign is taken from the output of a command run while the plan is written» —
  «Not checked by anything».
- `tools/check-work-steps.mjs` сверяет шаги плана и хода работы по номеру и названию и считает
  метку `[>]`. Результат шага он не измеряет.
- На Stop стоят два хука: диспетчер команд (`dispatch.sh Stop`, в нём `turn-exit-guard.sh` с
  уровнями про дерево и команды) и agent-хук `turn-judge.md` — модель с Read, Grep и Glob, таймаут
  120 с.
- RT-3275 эпика RT-3302 — «таблица решений вместо цепочки условий» по всем 93 проверкам пакета.
  Тема близкая, но шире: там все проверки, здесь — ход работы task flow.
- Документация Claude Code, записанная в RT-3276: вход Stop содержит `stop_hook_active`,
  `last_assistant_message`, `transcript_path` и `background_tasks`. После 8 продолжений подряд
  Claude Code сам заканчивает ход (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`), счёт сбрасывает вызов
  инструмента. Agent-хук получает Read, Grep и Glob — запустить команду и измерить её вывод он не
  может.

## Что уже говорят правила

- Карта хода `turn-map`: ход кончается четырьмя путями, «While the epic runs the fourth does not
  end a turn», и только конец эпика ждёт слова владельца — «The end of the epic is a fifth way, and
  only it waits».
- Закон `work-conduct`: «A transition from state to state does not stop the executor» и «The end of
  a task is no sign to stop; the epic's end is, until the owner's word».
- Вопрос владельцу задаётся меню, а меню не кончает ход: ход ждёт ответа внутри себя.

## Вопросы и ответы

**Кто сравнивает измеренный результат шага с ожидаемым?** Варианты: «Скрипт-хук (Recommended)» —
хук-скрипт сам меряет файлы, git, задачу на доске, запускает команду шага и пишет в отказе
«ожидалось X, получено Y», agent-хук модели остаётся только на слова владельца; «Только agent-хук
модели» — модель читает сценарий и файлы, команду запустить не может.

> Скрипт-хук (Recommended)

**Когда хук отпускает ход раньше конца сценария (конец сценария — конец эпика)?** Варианты:
«Только твоё «стоп» (Recommended)» — ход кончается до конца сценария, только если последнее
сообщение владельца говорит остановиться или подождать, хук проверяет это по записи разговора,
строку ожидания от агента не засчитывает; «Никогда, только Esc» — до конца сценария ход не
кончается ничем, остановить можно только прерыванием.

> Только твоё «стоп» (Recommended)

Два ответа «Recommended» подряд: остальные вопросы из шести закрыты допущениями ниже, по паттерну
`task-flow-start`.

## Решения

- **Одна задача в эпике RT-3302, вторая по порядку, сразу после RT-3276.** Допущение: работа о
  том же, о чём эпик, — проверки останавливают работу. Сценарий, хук и шаблоны откатываются
  вместе, делить их не на что. Ветка отводится от `RT-3276-conversation-checks`, PR идёт в неё —
  каскадом. Отклонено: внутрь RT-3276 — её план одобрен и не правится; внутрь RT-3275 — её
  описание пишет владелец, и она про все 93 проверки.
- **Готовность видна по измерениям, а не по словам.** Допущение: (1) в сценарии все 13 состояний,
  у каждого есть измеряемый выход; (2) хук на записанных ходах: остановку 14.11 отказывает и
  называет неизмеренный результат, ход в конце сценария отпускает, ход со словом владельца
  «стоп» отпускает; (3) строка состояния впереди невыполненного выхода отказывается; (4) метка
  `[x]` у шага плана, чья команда не дала ожидаемого, отказывается; (5) живой ход: следующая задача
  эпика идёт от разбора до PR без подталкивания владельцем.
- **Образец — сам task flow.** Владелец назвал подход, а сценарий — правило `task-flow`. Кода-образца
  нет, внешнего источника не ищем.
- **Пока у сессии идёт фоновая задача, ход может кончиться.** Допущение: приложение само вернёт
  агента, когда фоновая задача закончится, работа не ждёт владельца. Отклонено: держать ход и тут —
  агент получает отказ за отказом, а после 8 подряд Claude Code кончает ход сам.

- **Сценарий кончается концом эпика.** Так говорят карта хода и закон: пока в эпике есть задачи,
  отданная работа ход не кончает. Отклонено: конец сценария на открытом PR задачи — это та самая
  остановка после каждой задачи, которую владелец исключает.
- **Измеряемый результат есть у каждого состояния task flow и у каждого шага плана.** Владелец
  сказал «на каждом шаге»; внутри состояния `этап-идёт` шаги — это шаги плана. Отклонено: результат
  только у этапа — между шагами этапа агент снова идёт без измерения.
- **Приложения не меняются.** Правятся хуки, правило `task-flow`, шаблоны плана и хода работы в
  источнике пакета `projects/agent-kit/`. Код `apps/` и `libs/` не трогается, описание фичи для
  приложения не нужно.

**Описание фичи:** не нужно — правка пакета правил и хуков, код приложений не меняется.
- **Закон `work-conduct` не правится.** Он говорит, что должно быть верно, и сценарий его не
  меняет; если статья понадобится, её текст уходит владельцу.
- **Выпуск пакета в задачу не входит.** Его назначает владелец отдельно, как и во всём эпике.
