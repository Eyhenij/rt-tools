## Что считается сделанным

- Заведение дерева принимает выданный в админке токен доводом, кладёт его в файл правами
  «читает и пишет только владелец файла» и в сеть не идёт вовсе.
- Два довода вместе отбиваются; ни одного — отказ называет оба пути.
- Защита лежащего токена и намеренная перезапись работают у обоих путей одинаково.
- Сценарии `SC-AK-283`…`SC-AK-287` покрыты спеками, `pnpm run check:specs` зелёная.
- README пакета и подсказка команды называют оба пути.

## Этапы

### 1. Второй путь заведения

- **Что делается:** довод выданного токена в разборе строки запуска и в самой команде; общие
  обоим путям проверки вынесены до развилки; README и подсказка команды знают оба пути.
- **Признак готовности:** спека покрывает все пять сценариев; прежние спеки обмена по коду
  зелёные.
- **Чем проверяется:** прогон спек пакета, линт, сборка, `pnpm run check:specs`.

## Чего эта работа не делает

- Снос признака дерева и его сверки с токеном: владелец назначил только правку пакета.
- Прямую выдачу токена в админке приёмника — это сторона приёма.
- Эпик о самостоятельной регистрации потребителя.
