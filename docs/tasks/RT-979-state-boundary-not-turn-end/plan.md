# Замысел

**Задача:** RT-979 · **Ветка:** RT-979-state-boundary-not-turn-end
**Драфт:** `docs/specs/agent-kit/proposed/state-boundary-not-turn-end/`
**Поведение:** меняется

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## След задачи

Работа целиком лежит в слое правил: тексты пакета, их разложенные копии и одна новая проверка.
Кода приложения она не задевает.

| Что       | Где                                                                         |
| --------- | --------------------------------------------------------------------------- |
| Спеки     | `docs/specs/agent-kit/turn-guards/`, драфт рядом в `proposed/`              |
| Законы    | `docs/constitution/work-conduct.md`                                         |
| Правила   | `.claude/skills/task-flow/`, `.claude/skills/task-flow-start/`              |
| Паттерны  | `.claude/skills/task-flow-resume/`, `.claude/skills/task-flow-close/`       |
| Умолчания | `.claude/rt-kit/defaults/turn-map.md`, `.claude/rt-kit/defaults/project.sh` |
| Код       | `projects/agent-kit/assets/`, `tools/`                                      |

Разложенная копия правится не на месте: источник лежит в наборе пакета, а в дерево приходит
раскладкой. Свои файлы дерева здесь — обёртка проверки в `tools/` и команда в `package.json`.

## Что считается сделанным

- У каждого раздела состояния во всех трёх ведущих паттернах стоит строка следующего движения,
  и хвост у неё свой.
- Правило ведения работы называет переход между состояниями среди того, чем ход не кончается;
  карта хода говорит то же самое.
- Закон о ведении работы называет границу состояния статьёй.
- Своя проверка читает эти строки, отказывает с именем состояния и раздела и стоит своей
  строкой в наборе гейта пуша.
- Сценарии `SC-AK-447` … `SC-AK-458` покрыты набором пакета.

## Этапы

### 1. Закон, правило и карта говорят о границе состояния

- **Что делается:** статья в законе о ведении работы; строка о переходе между состояниями в
  перечне «чем ход не кончается» у правила ведения работы; та же строка в карте хода. Правится
  набор пакета, в дерево кладётся раскладкой.
- **Признак готовности:** три текста называют переход между состояниями, разложенные копии
  сошлись с источником, ни один файл не перерос предела длины.
- **Чем проверяется:** `pnpm run agent-kit:check && node tools/check-file-size.mjs` — раскладка
  без расхождений, файлов длиннее предела ноль.

### 2. Строка следующего движения встаёт в каждый раздел состояния

- **Что делается:** в каждый раздел «Состояние `имя`» трёх ведущих паттернов кладётся строка с
  общим зачином и своим хвостом — что делается сразу за обязательным действием этого раздела.
- **Признак готовности:** раздела без строки нет, двух дословно совпавших хвостов нет.
- **Чем проверяется:** `node tools/check-states.mjs && node tools/check-file-size.mjs` —
  состояний одиннадцать, у каждого есть раздел в ведущем паттерне, длина в пределе.

### 3. Проверка строк следующего движения

- **Что делается:** новая проверка в наборе пакета и её обёртка в дереве: читает перечень
  состояний, разделы ведущих паттернов, статью правила и строку карты; отказывает именем
  состояния, паттерна и заголовка раздела; без правила ведения работы проходит молча, на
  сломанном перечне отказывает.
- **Признак готовности:** проверка зелёная на дереве и красная на подделанном разделе.
- **Чем проверяется:** `pnpm run check:state-next` — разделы прочитаны, расхождений нет.

### 4. Проверка стоит в наборе гейта пуша

- **Что делается:** команда в `package.json`, строка набора гейта пуша у пакета и в его
  разложенной копии.
- **Признак готовности:** гейт зовёт проверку наравне с прочими сверками, и её отказ роняет
  гейт.
- **Чем проверяется:** `node tools/check-push-gate.mjs` — набор гейта полон, шага без строки
  нет.

### 5. Набор под сценарии договорённости

- **Что делается:** сценарный набор пакета под новую проверку — раздел без строки, списанный
  хвост, зачин без движения, дерево без правила, сломанный перечень, полное дерево целиком.
- **Признак готовности:** заголовки тестов несут идентификаторы `SC-AK-447` … `SC-AK-458`, а
  пометки «Не покрыто» в договорённости сняты.
- **Чем проверяется:** `pnpm run agent-kit:hooks && node tools/check-specs.mjs` — набор пакета
  зелёный, сценарии договорённости связаны с заголовками тестов.

Команда пишется обратными кавычками: страж выходов хода читает её и не выпускает ход, в котором
этап объявлен закрытым, а команда не запускалась. Приём, записанный прозой, подтвердить нечем.

## Чего эта работа не делает

- Стража выходов хода не правит: владелец запретил прямо.
- Сверку состояний не расширяет — за ней остаётся её предмет, имена разделов.
- Перечни состояний и выходов хода не трогает: ни нового состояния, ни нового выхода.
- Тексты отказов хука входа в заход и стража оставляет прежними.
