# Разбор просьбы

Две записи груза из приёма, соседнее дерево, ресурс `rules/reuse-first.md`. Отметить их этому
дереву нечем — токен двигает только свои записи; работа при этом наша, ресурс живёт здесь.

## Вторая половина интеграции сделана иначе, чем первая

У внешней службы редко один параметр. Ключ был сделан как положено — токеном, значением
окружения, подстановкой при сборке, — а идентификатор той же службы стоял константой в двадцати
семи строках от него, в том же файле. Заход прочитал обе строки и увидел две независимые детали,
а не пару, у которой одна половина сделана. Ни линтер, ни сборка, ни тест такое не отбивают:
значение синтаксически исправно и просто не принадлежит дереву — демонстрационное значение из
документации поставщика уехало в прод-сборку двух приложений.

## Соседство в файле способа хранения не назначает

Вторая запись правит первую: статья, написанная по горячим следам, учит повторять соседа по
файлу, не спрашивая, тот ли это сосед. Работа, которая её писала, ровно так и ошиблась — взяла
образцом соседнюю строку вместо того рода значений, который в дереве уже устроен.

Владелец разбор не вёл: заход идёт самостоятельно, задачи берутся из приёма одна за другой.
