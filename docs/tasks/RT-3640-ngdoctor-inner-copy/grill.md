# Разбор

## Просьба владельца

> Да, перед RT-3627

Ответ 25.11.2026 на вопрос «Завести задачу на check:ngdoctor (до 7 минут на набор) в этом эпике?». Задача встаёт
в эпик RT-3624 перед RT-3627. Просьба эпика: «сейчас рабочий процесс занимает слишком много времени, довольно
простые правки идут по несколько часов…».

## Что уже есть в дереве

- `tools/check-ngdoctor.mjs` зовёт `pnpm run ngdoctor --json` (angular-doctor 0.3.0), потом сам обходит те же файлы
  модулями инструмента (`tools/check-ngdoctor-pass.mjs`) и краснеет, если списки разошлись.
- Инструмент ищет файлы через fast-glob с `dot: false` и пропуском `**/node_modules/**`. Пропуск судится с тем же
  `dot: false`: путь `.claude/worktrees/<копия>/node_modules` проходит через папку с точкой, шаблон его не узнаёт, и
  fast-glob обходит пакеты копии вместе со ссылками pnpm. Файлы оттуда в ответ не попадают: имена с точкой шаблон
  поиска не берёт.
- Измерено 25.11: 426 и 359 секунд с копией соседней сессии внутри дерева, 6–8 секунд на том же коммите в копии вне
  дерева. Из 560 тысяч чтений папок за 15 секунд 554 тысячи — `node_modules` этой копии.
- Проба: тот же инструмент с добавленным пропуском `**/.*/**` при живой соседней копии — 5,4 секунды, 94,75, 1209
  находок, 2702 файла. Порог дерева — те же 94,75 и 1209.
- Настройка инструмента не подходит: слово владельца держит в ней одно поле `reportPath`, а пропуск из настроек
  инструмент кладёт только на список файлов, не на поиск `package.json` и стилей.
- Правка пакета через pnpm не подходит: образы приёмника ставят пакеты из манифеста и замка, без каталога правок.

## Что говорят правила

- Закон `verifiability`: проверка, которая не нашла, с чем сверять, не зелёная. Потерянный файл дерева по-прежнему
  краснит проверку.

## Вопросы и ответы

**Меняет ли это ответ проверки?** Нет: список файлов и находки те же, папки с точкой инструмент и так не отдаёт.

## Решения

- **Инструмент зовётся узлом с подгруженным модулем, который добавляет пропуск папок с точкой в его fast-glob.**
  Отвергнуто: правка пакета через pnpm; настройка инструмента; перенос копий сессий — их место выбирает приложение.
- **Обход проверки получает тот же пропуск** — иначе он сам шёл бы по пакетам копии.
- **Нет того места в fast-glob, куда встаёт пропуск, — проверка красная с этими словами**, а не медленная молча.

## Что осталось неясным

- Другие проверки дерева, которые обходят каталоги, на копию внутри не смотрят: их шаги шли 0–9 секунд в том же
  наборе. Новых замеров не нужно.
