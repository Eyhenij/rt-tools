# Grill

## The owner request

> исправь ci сейчас в этом эпике, заведи задачу и бери в работу

Позже: «делай #3373».

## What the tree already has

- В `.github/workflows/ci.yml` шаг «Migrations against a clean database» поднимает контейнер `rt-ci-schema` и ждёт готовности базы циклом `until docker exec rt-ci-schema pg_isready ...; do sleep 1; done`. У цикла нет предела по времени, у шага нет `timeout-minutes`.
- 18.11.2026 контейнера не стало до готовности базы (причина не установлена), цикл ждал вечно, CI стоял 36 минут на единственном раннере. Разбор лежит в приёмнике: «Ждал CI и не смотрел, на каком шаге он стоит».
- Имя контейнера общее для всех запусков, и в начале шага `docker rm -f rt-ci-schema` снимает контейнер любого другого запуска с тем же именем.

## What the rules already say

- Правило поставки требует, чтобы CI сам не зависал молча; отдельной статьи про предел ожидания в шагах нет.

## Questions and answers

Вопросов владельцу нет: причина найдена по логу, исправление одно.

## Decisions

- **Ожидание готовности ограничено 90 секундами и обрывается сразу, если контейнера уже нет.** Причина падения называется в логе шага. Rejected: только `timeout-minutes` на шаге: он оборвал бы зависание через 10 минут, но не сказал бы, что контейнера нет.
- **Имя контейнера включает номер запуска.** Соседний запуск не может снять чужой контейнер по имени. Rejected: оставить общее имя: именно оно могло убрать контейнер.
- **Контейнер снимается при любом выходе из шага.** Обрыв больше не оставляет контейнер, который занимает порт 55452 для следующего запуска.
