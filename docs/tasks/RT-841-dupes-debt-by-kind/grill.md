# Разбор просьбы

## Просьба владельца

Задача заведена исполнителем по замыслу эпика RT-806: там записано, что задачи под долг
повторов и единообразия заводятся, когда кончится четвёртая задача порядка, — числами того дня.
Четвёртая (RT-809) влита, числа сняты 18 августа 2026 года.

## Что уже есть в дереве

- `npm run check:dupes` — повторов 26, принято 0, долг 26. Состав читается
  `node tools/check-dupes.mjs --baseline`.
- Проверка ловит повтор четырьмя признаками: одно имя из двух либ; два перечисления с одним
  набором членов; настройка `SCREAMING_SNAKE_CASE` в двух либах; перечисление, повторяющее
  набор из внешнего пакета.
- Список принятого — `tools/dupes-allowlist.json`, поля `accepted` и `debt`, оба плоскими
  строками ключей. Причина в этом дереве оформляется полем `reason` на весь файл: так сделано
  в `tools/styles-allowlist.json` и `tools/file-size-allowlist.json`.
- Второй кит по устройству независим от первого: разные селекторы, свой набор токенов
  оформления, свой список компонентов, кода они не делят. Это записано в `CLAUDE.md` и в
  `projects/ui-kit-v2/README.md`.

## Что уже сказано в правилах

- Замысел эпика RT-806: «Разбор — это либо правка кода, либо строка в списке принятого с
  причиной»; «Список принятого не пополняется под красную проверку» — принимается накопленное
  на день заведения проверки, а не то, что нашлось после.
- Правило `reuse-first`: готовое берётся раньше своего, а разовое отступление объявляется
  маркером.
- Правило `lib-layers`: где живёт общий символ, решается слоем и семьёй либы, а не удобством.
