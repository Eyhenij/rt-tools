# Grill

## The owner request

> доведи все задачи эпика до завершения

Слово владельца от 19.11.2026. Задача заведена 20.11: без неё свежая main не вливается в ветку эпика
RT-3302, и следующая задача эпика не берётся.

## What the tree already has

- В ветке эпика `RT-3302-checks-rework-3` номер SC-AK-1598 занят сценарием хуков из RT-3277:
  `docs/specs/agent-kit/hooks/scenarios.md:157` и заголовки в `projects/agent-kit/tests/real-record.test.sh`.
- В main тот же номер получил сценарий из RT-3450: `docs/specs/agent-kit/layout/scenarios.md:125`,
  строка привязки в `docs/specs/agent-kit/layout/implementation.md:24` и 15 строк в
  `projects/agent-kit/tests/checks-lib-layers.test.sh`.
- После слияния main в эпик `node tools/check-specs.mjs` отказывает: «the identifier SC-AK-1598 is
  already taken». Проверено 20.11 на пробном слиянии.
- Свободный номер даёт `pnpm run spec:next-id SC-AK`: 20.11 он назвал SC-AK-1795.

## What the rules already say

- Правило `spec-driven`: номер сценария выдаётся один раз и не используется повторно; сценарий и
  заголовок его теста меняются вместе.
- Правило `git-workflow`: ветка эпика несёт только план и слияния задач, своих правок у неё нет.
  Проверка плана запрещает менять тестовый файл в ветке эпика.

## Questions and answers

**Где менять номер: в ветке эпика при слиянии или отдельной задачей от main?**
Меню с этим вопросом остановила проверка вопросов. Второй вариант обходил требование свежей main у
ветки задачи эпика. Законный путь один, и вопрос не задан: задача от main.

## Decisions

- **Новый номер получает сценарий из RT-3450, а не сценарий хуков.** Номер хуков выдан раньше, в
  RT-3277, и на него ссылаются запись в архиве и тесты эпика. Отвергнуто: менять номер хуков в ветке
  эпика — там правка теста запрещена.
- **Запись в архиве `RT-3450-lib-test-runner-forms.md` не правится.** Запись описывает прошлое как
  было; путь проверки архив не читает.
