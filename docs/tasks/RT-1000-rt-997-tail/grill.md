## Что уже сказано в правилах

Поиск по словам темы: `папка задачи`, `вливание договорённости`, `эпик кончился`.

- Правило ведения работы: договорённость вливается в спек домена последним коммитом PR; папка
  закрытой задачи разбирается, а не переносится целиком; неразобранную ловит сверка очереди.
- Паттерн закрытия работы: порядок переезда, три исхода разбора папки, закрытый эпик уезжает в
  описание прошлого.
- Правило поставки: слияние отбивается, пока ветка везёт папку своей задачи, — гард сюда не
  достал, потому что заявку влили раньше, чем ветка получила закрывающий коммит.

Ответа на один вопрос в правилах нет: куда вливать договорённость, предмет которой лежит в двух
поддоменах сразу. Он решается разбором самого текста, а не владельцем.

## Вопросы и ответы

Владельцу не задавались: работа выведена из его слова и из правил. Спрашивать было нечего.

## Решения

- **Договорённость делится между двумя поддоменами по предмету, а не вливается целиком в
  один.** Пять правил о числах и их сверке — предмет поддомена передачи захода и входа: пороги
  назначают ту самую минуту, в которую заход переходит в следующий. Одно правило о поведении
  стража — предмет поддомена гардов завершения хода, где уже лежат четыре его правила.
  Отвергнуто: влить всё в гарды завершения хода — их файл сценариев встал бы на 520 строк при
  пределе 500, то есть работа кончилась бы вторым делением подряд.
- **Номера сценариев при делении не пересчитываются.** Идентификатор связывает сценарий с
  заголовком теста.
