# Находки разбора закрытой работы

Разбор трёх задач — RT-703, RT-710, RT-716 — ролью разбора закрытой задачи, 16 августа 2026
года. Наружу без слова владельца не уезжает: он читает их разом, когда кончится эпик RT-702.
При разборе папки файл переезжает к замыслу эпика — `docs/plans/agent-kit-rules-review.md`.

Загружено за сессию: `task-flow`, `task-flow-start`, `spec-driven`, `doc-style`, `git-workflow`,
`git-workflow-commit`. Ни одно не простояло вхолостую. Все потери — в паре правил о поставке:
правило прямо утверждало неверное про машинную учётную запись, а про отказ `gh pr create` на
квоте, про исполнителя задачи, пустое тело задачи, отказ раннера и отсутствующий прогон не
говорило ничего.

## Пакет

**1. Закон о поставке: заведённое видно тому, кто это читает.** Статья в `assets/laws/delivery.md`:
заведённое в очереди работ видно той стороне, для которой заводилось. Учётная запись, чьи
объекты хостинг показывает не всем, оставляет за собой работу, которой для остальных не
существует, — и снаружи это неотличимо от сделанного. Вызвано PR #708.

**2. Правило поставки: PR перечитывается токеном разбирающего.** Статья в
`assets/rules/git-workflow.github.md`: успешный ответ команды открытия значит «вызов прошёл», а
не «PR виден разбирающему». Виды `.gitlab`/`.azure` не трогаются — механика чужая.

**3. Правило поставки: снять противоречие в ловушке «Учётная запись для пуша и автор PR
выбираются отдельно».** Прежняя формулировка прямо диктовала открывать PR токеном машинной
записи и была исполнена буквально.

**4. Паттерн о ветке и PR: `gh pr create` отбивается на GraphQL.** Запись с урезанной квотой
языка запросов получает `API rate limit already exceeded`, и PR не заводится вовсе. Обход —
открытие через REST `gh api -X POST repos/<репозиторий>/pulls`, метки и ревьювер вызовами
следом. Текст отказа читается как временный, но квота не исчерпана, а равна нулю.

**5. Паттерн начала работы: тело задачи пустым не бывает.** `< /dev/null` заводит задачу, по
которой нечего читать, а дописать потом нельзя — правка тела уже заведённой задачи идёт только
со слова владельца. Вызвано RT-716.

**6. Паттерн о ветке и PR: команды дерева зовутся из корня.** В каталоге пакета `npm run` берёт
его собственный манифест и отвечает «Missing script», хотя команда есть.

**7. Паттерн закрытия работы: чем возвращаются к прогону.** Статья «ожидание прогона работой не
занимают» есть, приёма под неё не было. Прямой `sleep` харнесс отбивает; ждёт фоновая команда
циклом `until`, и она же приводит ход за собой.

**8. Правило поставки: отсутствие прогона зелёным не бывает.** Пуш в уже открытый PR иногда не
заводит ни одной проверки; страница показывает отметки прошлого пуша. Пустой список читается как
«проверок не было». Вызвано PR #713.

**9. Правило поставки: отказ раннера на подготовке задания — не про правку.** Задание падает до
первого своего шага, в логе только эта строка. Перезапускается, а не разбирается по коду.

**10. Правило слоя правил: гейт судит все пути команды.** Признак записи считается по всей
команде: перенаправление или вызов интерпретатора делают правкой строку целиком, и дальше под
требование попадает то, что команда только читает. Отбитое чтение каталога спеков — отсюда.

## Компаньон этого дерева

**11. Строка «учётная запись машинной работы» врёт.** Таблица «Как это называется здесь»
говорит, что ею заводится задача и открывается PR, — и противоречит блоку об ограничении в том
же файле. Пока хостинг её скрывает, задача заводится, PR открывается и борда правится записью
владельца; ею подписан только коммит.

**12. Подтягивание идёт тем же токеном, что и пуш.** Голый `git fetch origin main` отвечает
«Repository not found»: связка ключей отдаёт учётную запись чужого дерева.

**13. Раннер на этой машине не один.** Рядом стоит очередь другого дерева, и её прогон занимает
процессор целиком. Прогон, кончившийся потерей связи на подготовке задания, перезапускается.

## Дерево: карта гейта

**Исходники пакета правились без правила устройства текстов.** Разложенную копию гейт закрывает
правилом `spec-driven`, а исходник, из которого её кладут, уходил в общую ветку `*.md` — то есть
в правило формулировок. Сорок файлов законов, правил и паттернов за три задачи правились именно
там. Роль проверила на действующих картах: `assets/laws/delivery.md` → `doc-style`,
`assets/rules/git-workflow.github.md` → `doc-style`, `assets/hooks/*` и `assets/checks/*` →
ничего. `spec-driven` в этой сессии загрузилось попутно, из-за разложенных копий.

Правится ветками в `.claude/rt-kit/gate-map.sh` — путь есть только здесь, пакет о нём знать не
может: законы, правила, паттерны и скилы пакета → `spec-driven`; хуки, проверки, умолчания и
роли → `agent-kit`.

## Отдельной задачей, а не строкой правила

Признак записи и список путей в `assets/defaults/project.sh` стоит развести: когда признак дал
только перенаправление, судить один путь после `>` или `>>`, а не всю строку. Это правка кода.
