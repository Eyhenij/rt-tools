# Замысел

**Задача:** RT-716 · **Ветка:** RT-716-work-never-waits
**Поведение:** не меняется — правятся тексты законов и правил, конвейер дерева и состав очереди
работ; состав ресурсов пакета и механизм раскладки те же. Владелец назвал работу словами
«заведи на это статьи законов правил и скилов».

## След задачи

| Что      | Где                                                                                          |
| -------- | -------------------------------------------------------------------------------------------- |
| Законы   | `projects/agent-kit/assets/laws/work-conduct.md`, `assets/laws/delivery.md`                  |
| Правила  | `projects/agent-kit/assets/rules/task-flow.md`, `assets/rules/git-workflow.*.md`             |
| Паттерны | `projects/agent-kit/assets/patterns/task-flow-close.md`, `patterns/git-workflow-commit.*.md` |
| Команда  | `projects/agent-kit/assets/commands/skill-curator.md`                                        |
| Конвейер | `.github/workflows/ci.yml`                                                                   |
| Очередь  | борда проекта: десять карточек PR снимаются                                                  |

## Что считается сделанным

- Закон о ведении работы требует, чтобы работа не стояла в ожидании прогона, разбора владельцем
  и разбора закрытой задачи.
- Закон требует называть блокировку владельцу явно, когда ожидание всё-таки останавливает работу.
- Разбор закрытой задачи запускается фоновой ролью и не занимает ход: его находки ложатся в
  папку задачи и переезжают к замыслу эпика.
- В пакет без слова владельца уезжает только сводка наблюдений; предложения — после его разбора.
- Конвейер на ветке из одних текстов не гоняет ни сквозного набора, ни снимков, ни образов.
- В очереди работ стоят задачи, а не PR о них: статья есть, десять висящих карточек сняты,
  сверка очереди зелена по этой строке.

## Этапы

### 1. Статьи в два закона

- **Что делается:** в закон о ведении работы — работа не стоит в ожидании чужого шага; названная
  блокировка; разбор закрытой задачи идёт своим ходом и работу не занимает. В закон о поставке —
  в очереди работ стоят задачи, а не PR о них; проверка не гоняет того, что правка не может
  сломать.
- **Признак готовности:** статьи стоят в законах пакета и разложены в `docs/constitution/`.
- **Чем проверяется:** `pnpm run agent-kit:sync`, `pnpm run agent-kit:check`.

### 2. Правила и паттерны приведены к статьям

- **Что делается:** правило ведения работы — параллельный ход работы и подсветка блокировки;
  паттерн закрытия работы — фоновый запуск разбора, файл находок в папке задачи, переезд к
  замыслу эпика при разборе папки; три вида правила поставки и паттернов при них — состав
  очереди работ и набор конвейера по роду правки.
- **Признак готовности:** ни один текст не велит ждать прогона; у каждой новой статьи есть
  место, где сказано, каким приёмом она держится.
- **Чем проверяется:** `bash projects/agent-kit/tests/run.sh`, `npm run check:docs`.

### 3. Команда разбора закрытой задачи

- **Что делается:** `assets/commands/skill-curator.md` переписывается под фоновый запуск: сводка
  собирается до запуска, роль уходит в фон, ход продолжается; вернувшиеся находки ложатся в
  `docs/tasks/<ветка>/curator.md`. В пакет уезжает только сводка наблюдений — предложения ждут
  разбора владельцем по концу эпика.
- **Признак готовности:** в команде нет шага, который останавливает работу; сказано, что и когда
  уезжает в пакет, а что ждёт владельца.
- **Чем проверяется:** `pnpm run agent-kit:check`, чтение владельцем.

### 4. Конвейер по роду правки

- **Что делается:** шаг, который считает состав правки от главной ветки и объявляет ветку
  текстовой; тяжёлые шаги — сквозной набор, снимки двух витрин, `verify`, обе сборки образов и
  линтер стилей — получают условие пропуска.
- **Признак готовности:** на ветке из одних текстов прогон зелёный и короткий, тяжёлые шаги
  помечены пропущенными; на ветке с правкой кода набор прежний.
- **Чем проверяется:** прогон конвейера на этой ветке, `node tools/check-push-gate.mjs`.

### 5. Очередь работ без карточек PR

- **Что делается:** десять карточек PR снимаются с борды; проверяется, что новые не появляются
  сами.
- **Признак готовности:** `npm run check:board` не печатает ни одной строки «на борде стоят
  задачи, а не PR о них».
- **Чем проверяется:** `npm run check:board`.

## Чего эта работа не делает

- Машинной проверки на то, что исполнитель и вправду не простаивал: признака у машины нет.
- Отправки предложений куратора в пакет без разбора владельцем — это прямое решение владельца.
- Правки самого гейта пуша: он и так короче конвейера.
- Работы эпика RT-702 — ревью текстов слоя правил идёт своими задачами.
