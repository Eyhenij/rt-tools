# Замысел

**Задача:** RT-322 · **Ветка:** `RT-322-agent-kit-defects`
**Драфт:** `docs/specs/agent-kit/proposed/clean-install/`
**Поведение:** меняется

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## Что считается сделанным

- В одноразовом дереве с видом хостинга, отличным от вида этого дерева, `init --all` и `sync`
  проходят, а `doctor` после них не называет ни одного отказа — и ни один шаг не сделан руками.
- Прогон пакета гоняет сценарии на исполняемые ресурсы: сломанная строка в любом гарде или
  проверке роняет `nx run-many -t lint test build --projects=agent-kit`.
- Раскладка отказывает, когда выбранный вид оставляет разложенное правило без инструмента,
  который правило называет, и называет обоих поимённо.
- В текстах `assets/rules` и `assets/patterns` не осталось путей к доменам, портов и селекторов
  конкретного дерева — только безымянные образцы.
- Каждое утверждение из разбора либо подтверждено выводом команды в отчёте, либо отмечено
  неподтверждённым и не чинилось.

## Этапы

### 1. Прогон утверждений в одноразовом дереве

- **Что делается:** восемь утверждений разбора проверяются каждое своим прогоном; сначала
  пишется команда, которая показала бы, что дефекта нет. Дерево — одноразовое (`mktemp -d`,
  `git init`, минимальный `package.json`): пункты про виды, устаревшую сборку и карту хуков в
  дереве, где пакет уже стоит, не проявляются.
- **Признак готовности:** у каждого утверждения в `progress.md` стоит «подтвердилось» или
  «не подтвердилось» с выводом команды.
- **Чем проверяется:** `pnpm exec nx build agent-kit`, затем
  `node dist/agent-kit/bin/agent-kit.js <команда> --root <одноразовое дерево>`.

### 2. Наборы сценариев на исполняемые ресурсы

- **Что делается:** заводится прогон гардов, проверок и умолчаний: разбор командной строки,
  вложенные вызовы, границы команд, отказ в пользу работы. Сценарии не знают ни карты, ни
  доменов, ни портов конкретного дерева. Место — решением по ходу: внутри проекта пакета или
  ресурсом в дерево-потребитель (`Q-1` договорённости).
- **Признак готовности:** сломанная строка в любом гарде роняет прогон пакета.
- **Чем проверяется:** `nx run-many -t lint test build --projects=agent-kit` на целом дереве и
  он же на дереве с одной испорченной строкой.

### 3. Виды у инструментов и отказ вместо молчания

- **Что делается:** проверки, которые зовёт правило поставки, получают виды по оси хостинга;
  раскладка учится отказывать, когда выбранный вид оставляет правило без инструмента.
- **Признак готовности:** `sync` в дерево с чужим видом либо кладёт инструменты, либо
  отказывает с именем правила и именем недостающего.
- **Чем проверяется:** `init --all --host gitlab`, `sync`, чтение разложенного правила и
  сверка названных им команд с тем, что легло на диск.

### 4. Раскладка не выдаёт устаревшее за свежее

- **Что делается:** пакет учится замечать, что строка запуска читает не то, что правлено в
  источнике.
- **Признак готовности:** правка ресурса без сборки даёт на `sync` сообщение о расхождении, а
  не «всё уже разложено».
- **Чем проверяется:** правка ресурса в источнике без сборки, затем `sync` в одноразовое дерево.

### 5. Карта хуков доезжает до настройки агента

- **Что делается:** решается `Q-2` договорённости — вносить запись в чужой JSON или отдавать
  готовый кусок и проверять его наличие; выбранное реализуется.
- **Признак готовности:** после `init --all` и `sync` в чистом дереве видно, позовёт ли
  кто-нибудь разложенные гарды, и если нет — пакет говорит, чего не хватает.
- **Чем проверяется:** `sync` в одноразовое дерево и подача входа разложенному гарду напрямую —
  чтобы отделить неработающую связку от неработающего гарда.

### 6. Четыре тихих отказа

- **Что делается:** слияние надстройки настроек проверок по вложенным ключам; сверка
  разложенного по телу, а не по номеру редакции; корни проверки слоёв из настройки вместо кода;
  генератор черновиков компаньонов.
- **Признак готовности:** названный ключ вложенного объекта не сносит соседние; `doctor`
  показывает расхождение тела при совпавшей шапке; проверка слоёв ходит по пути из настройки;
  черновики компаньонов заводятся командой.
- **Чем проверяется:** по прогону на каждый пункт в одноразовом дереве, вывод — в отчёт.

### 7. Вычистка адресности из текстов

- **Что делается:** найденное грепом делится на три рода — соглашение мастерской, верное
  везде; значение, которое подставляется; имя, которого в другом дереве нет вовсе. Чинятся
  второй и третий: адресность переезжает в компаньона рядом с правилом, в тексте остаётся
  безымянный образец.
- **Признак готовности:** греп по путям к доменам, портам и селекторам конкретного дерева по
  `assets/rules` и `assets/patterns` пуст.
- **Чем проверяется:** тот же греп и чтение десяти самых задетых файлов подряд.

### 8. Переход чужого файла в управление пакетом

- **Что делается:** решается, чем становится переход — командой, флагом или описанным ручным
  порядком; молчаливая перезапись не рассматривается.
- **Признак готовности:** у потребителя есть названный способ отдать файл пакету, и прежнее
  содержимое при этом не теряется молча.
- **Чем проверяется:** файл под пакетным именем без шапки кладётся в одноразовое дерево, затем
  `sync` и выбранный способ перехода.

### 9. Сводный прогон и вливание договорённости

- **Что считается сделанным:** чистая установка с чужим видом хостинга проходит без ручной
  доводки; договорённость из `proposed/clean-install/` вливается в спек пакета последним
  коммитом, каталог снимается.
- **Чем проверяется:** `init --all --host gitlab` → `sync` → `doctor` в свежем одноразовом
  дереве; `npm run check:specs`; `npm run check:board`.

## Чего эта работа не делает

- Не публикует новую редакцию пакета в реестр.
- Не перекладывает это дерево починенными текстами: `agent-kit:sync` здесь идёт отдельным
  заходом после мержа.
- Не трогает состав предметного слоя законов и правил — что дерево берёт, а что выключает.
- Не заводит генератор черновиков правил по закону: он про заведение нового правила, а не про
  установку. Остаётся строкой «Что осталось» в `docs/plans/agent-kit-rules-layer.md`.
- Не трогает `RUNNER-MONITOR.md` в корне: он про другую работу.
