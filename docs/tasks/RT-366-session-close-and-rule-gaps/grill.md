# Разбор просьбы

## Просьба владельца

> проверь все замечания и предложения из avalon-proposals.md

> так же напиши в agent kit команду для того чтобы подтянуть свежий main, почистить ветки и
> написать передачу для следующей сессии, чтобы всё это выполнять одной командой, проверь чтобы
> название этой команды не пересекалось с уже установленными командами

## Что уже есть в дереве

Разведка по исходникам пакета, не по выпущенной версии:

- Команда у пакета одна — `assets/commands/skill-curator.md`; в дереве установлена тоже одна.
  Замыслы ролей лежат отдельно, в `assets/workflows/`.
- Форму передачи захода и место, куда она кладётся, уже описывает паттерн `task-flow-handoff`:
  один файл на ветку, каталог называет профиль дерева, в историю не едет.
- Шаги работы разложены по трём паттернам: `task-flow-start` считает 1–5, `task-flow-close`
  начинает счёт заново 1–4, `task-flow-resume` не нумерует вовсе. Сплошного списка нет ни в
  правиле `task-flow`, ни в замыслах ролей.
- Про номер сценария правило `spec-driven` говорит три вещи, и лишь одна — о жизни номера:
  «номера при разрешении конфликта не пересчитываются» (ловушка). Жизненного цикла — выдача,
  удаление, добавление — нет; `spec-driven-domain` при этом прямо разрешает делению домена
  переписать номера.
- `assets/checks/check-specs.mjs` ищет заголовок сценария по `\d{2,3}` (строка 66) и ссылку в
  тесте по `\d{2,3}` (строка 72). Заголовок, не подошедший под шаблон, сценария не заводит и
  отказа не даёт (`parseScenarios`, строки 606–621): однозначный номер не виден ни в покрытии,
  ни в долгах, а проверка остаётся зелёной.
- В правиле `doc-style` шесть разделов, и места под скилы проекта среди них нет. Слияние
  надстройки идёт разделом `## ` (`src/lib/sections.ts`): одноимённый раздел проекта замещает
  пакетный целиком — поэтому своё дописывают в «Ловушки», теряя пакетные пункты.
- Словарь пакет уже везёт: `assets/docs/GLOSSARY.md` лёг коммитом `1bb3d66` — после выпуска
  0.5.0 (`942c155`), поэтому в дерево-потребитель он не приехал. Правки под это не нужно.

## Вопросы и ответы

**Как назвать команду, чтобы имя не пересеклось с уже установленными?**
`/next-session`.

**Что команда чистит из веток?**
Влитые локальные + prune мёртвых удалённых отслеживаний.

**Кому команда достаётся — пакету или только этому дереву?**
Пакету, для всех деревьев.

**Что делаем с четырьмя подтверждёнными предложениями?**
«делай всё сразу в одной задаче и в одной ветке».

**Как чинить однозначные номера сценариев?**
Шаблоны принимают 1–3 цифры.

**Насколько глубоко правим счёт шагов?**
Список в правиле + сплошной счёт через три паттерна.

**Что в задачу не входит?**
Выпуск в реестр.

**Что делаем с файлом предложений в корне дерева?**
Снести в конце задачи.

**«Подтянуть свежий main» — что команда делает, когда её зовут из ветки задачи?**
«команда обычно вызывается после того как вмержен открытый пр по текущей задаче из текущей
ветки, поэтому нужно понимать выполняется ли задача по task flow и если да - задача закрыта и
ветка будет удалена, нужно переходить на main и пуллить изменения из ремоута, если это не в
рамках task flow - нужно влить main в текущую ветку».

**Чем будет видно, что задача закрыта?**
Команда прогнана вживую; тест на шаблоны с однозначным номером; зелёные `sync --check` и
`check:specs`; все тесты пакета зелёные.

**Нужна ли договорённость о продукте?**
Завести драфт со сценариями.

## Решения

- **Работа ведётся одной задачей и одной веткой** — решение владельца, названное дословно.
  Отвергнуто: четыре отдельные задачи по числу предложений — владелец отказался.
- **Команда зовётся `/next-session`** — проверено на пересечение: у пакета одна команда
  (`skill-curator`), у дерева тоже она одна, среди встроенных команд и личных скилов имени
  `next-session` нет. Отвергнуто: `/session-close` и `/wrap-up`.
- **Поведение команды зависит от того, ведётся ли работа по правилу ведения работы.** Работа
  по правилу и отчёт влит — переход на главную ветку и подтягивание из удалённого; работа вне
  правила — главная ветка вливается в текущую.
- **Шаблоны сверки принимают 1–3 цифры** — уже стоящие однозначные номера начинают видеться
  без переименования, а переименование рвёт связь с тестами. Отвергнуто: требовать две цифры
  текстом правила — тогда стоящие номера остаются невидимыми молча.
- **Счёт шагов становится сплошным через три паттерна, а единый список встаёт в правило
  `task-flow`** — номер шага называют вслух, и два разных первых шага мешают разговору.
- **Пятое предложение о словаре закрыто до этой работы** — пакет уже везёт словарь, ждёт
  только выпуска. Правки под него нет.
- **Файл предложений в корне сносится последним шагом** — четыре записи закрывает эта работа,
  пятая закрыта раньше. Держать его в корне нельзя: имя файла называет чужое дерево, и сверка
  адресов на него краснеет.

## Что осталось невыясненным

- Что делать с расхождениями сверки спеков, которые прибавит терпимый шаблон, — за границей
  задачи по решению владельца. Число до и после называется в ходе работы.
- Выпуск минорной версии — отдельное решение владельца; без него ни команда, ни правки текстов
  до второго дерева не доедут.
