# Разбор

## Просьба владельца

> сейчас рабочий процесс занимает слишком много времени, довольно простые правки идут по несколько часов, сделай анализ на какие шаги сколько времени уходит по текущему task flow и как можно оптимизировать весь процесс

На вопрос «Завести эпик на ускорение процесса?» — «Да, заводи». На вопрос об одобрении плана эпика —
«Без П5 (Recommended)» из вариантов «Без П5», «План целиком», «Без П1–П5»: предложения П1–П4 одобрены.

25.11.2026, на вопрос «Что делаю первым?» — «Продолжай эпик (Recommended)» из вариантов «Продолжай
эпик», «Сначала защита», «Отложить RT-3626», «Подскажу путь». Описание выбранного: «PR по RT-3625 в
ветку эпика, затем RT-3626: разбор, план, код. RT-3612 не начата, ветки у неё нет, поэтому RT-3626
идёт раньше неё».

## Что уже есть в дереве

- Правило `task-delivery-loop` и его холодная часть говорят «два круга, без исключений»; то же повторяют
  надстройки `overrides/rules/task-flow.md` и `overrides/pitfalls/task-flow.2.md`.
- Чтение плана ролями требует и движок: `flow-plan.mjs` держит список `ROLES` и без вызова обеих ролей
  не пишет отметку одобрения. Это ресурс пакета правил, утверждение стоит в
  `docs/specs/agent-kit/turn-guards/flow-script/spec.md`, сценарий SC-AK-1873.
- Круги ревью не считает ни одна защита: правило само пишет «Not checked by anything».
- Состав правки по путям уже делят `rt_push_touched` в `project.sh` и `isVisibleKitFile` в
  `check-kit-approval.mjs`: строка «Без вида» в записи согласия снимает признак вида.
- Настройки проверок дерева лежат в `.claude/rt-kit/checks.json`, их читает `rt-kit-checks.config.mjs`.
- Шесть мелких задач исходного числа, строки кода без тестов и текстов: RT-3526 — 91, RT-3525 — 106,
  RT-3481 — около 100, RT-3585 — 225, RT-3518 — 240, RT-3514 — 249. RT-3525 и RT-3526 правят
  `tools/check-ngdoctor*`.
- `session-time-steps.mjs` выбрасывает ветку без второго круга, RT-3625 отдала это сюда.

## Что говорят правила

- Закон `verifiability`: работу читает не автор. Один круг это держит.
- Закон `work-conduct`: ослабление проверки — слово владельца; П1 и П2 одобрены 24.11.
- `agent-kit-source`: ресурс пакета правится в исходнике, затем сборка и раскладка.

## Вопросы и ответы

**Меняет ли поведение приложений?** Нет: правка касается правил и инструментов.

**Порядок с RT-3612?** RT-3626 раньше: выбранный вариант меню 25.11 прямо об этом.

## Решения

- **Путь выбирает команда, а не исполнитель** — `tools/review-path.mjs`: до кода по следу плана и
  названному объёму, после кода по разнице ветки с базой. Отвергнуто: признак словами в правиле, его
  нельзя проверить сценарием.
- **Защиты правил — это крючки, карта ворот, профиль, движок хода и ресурсы пакета, а не любая
  проверка `tools/check-*`** — иначе RT-3526, ради которой путь заведён, осталась бы на полном. Цена
  ошибки: правка проверки дерева до 150 строк пройдёт один круг.
- **Смена вида** — стили, шаблоны, токены и значки кита и админки, а также видимый файл кита без строки
  «Без вида». Цена ошибки: правка одного списка.
- **Публичный API** — изменённая строка с `export`, входом или выходом компонента в исходнике
  опубликованного пакета, и входной файл пакета.
- **Движок спрашивает дерево, чьи голоса нужны плану** — новый ключ настроек проверок. Нет ключа,
  отказ команды или непонятный ответ — обе роли, как сейчас.
- **Обман объёмом ловится после кода** — план с пометкой лёгкого пути и разницей полного пути
  отказан перед отправкой.
- **Второй круг на полном пути** нужен при серьёзной находке первого или правке поведения кита, защит,
  безопасности; он читает исправления первого круга.
- **Ветка с одним кругом получает строки шагов отдельной группой** — медианы полного хода, сверенные с
  24.11, не меняются.
- **Эта задача идёт по полному пути с двумя кругами** — она правит сами защиты.

## Что осталось неясным

- Какие задачи считать мелкими при сравнении «после» — слово владельца на вехе эпика, работе не мешает.
