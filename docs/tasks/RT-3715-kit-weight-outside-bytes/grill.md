# RT-3715 — байты старта приложения вне двенадцати строк веса

## Просьба владельца

Задачу владелец завёл ответами в меню при разборе RT-3682, 27.11:

> Разобрать задачей

> Держать +13000 разбором

## Что уже есть в дереве

- Точка этой задачи в плане эпика `docs/plans/kit-weight-remainder.md`: приложение с `button` тяжелее 0.51.0 не больше
  чем на 13000 байт. Возможности и API не меняются, gzip по файлам назван числом. Откат ленивых загрузок идёт только
  после слова владельца.
- Сегодня приложение тяжелее на 14257 байт: не хватает 1257.
- Кеш файлов значков лежит в `projects/ui-kit-v2/src/lib/components/icon/rt-icon.registry.ts` и держится оператором
  `shareReplay(1)`. Другой код стартового набора этот оператор не берёт.
- Поведение кеша держат сценарии `SC-UKV-59` и `SC-UKV-1882`: повторный запрос сеть не трогает, отказ по адресу
  запоминается.
- Во временной копии кеш переписан на `AsyncSubject`. Приложение с `button` весит 545266 байт против 546901: легче на
  1635 и тяжелее 0.51.0 на 12622. gzip по файлам 156665 против 157260. Тесты кита без правок: 4456 из 4456.

## Вопросы и ответы

- Что делать с байтами вне строк? Ответ владельца 27.11: «Разобрать задачей».
- Как держать остаток 13000 без ленивого куска листа? Ответ владельца 27.11: «Держать +13000 разбором».

## Что уже говорят правила

Правка не видна на экране и не меняет открытые имена: согласование вида ей не нужно.

**Задач в разборе:** 1

## Решения

- **Кеш значка пишется на `AsyncSubject`.** Он хранит один ответ и отдаёт его поздним подписчикам, как `shareReplay(1)`.
  Отброшено: обещание с `from` — оно меняет порядок ответа на микрозадачу.
- **Ленивые загрузки не откатываются.** Остаток набирается без них.
