## Что считается сделанным

- Сборка приёмника при пропавшем клиенте хранилища останавливается до компиляции и печатает
  одну строку: каталог, которого нет, и команду, которой он заводится.
- Каталог без входного файла считается пропажей наравне с отсутствующим.
- При живом клиенте сборка идёт как прежде, и проверка не печатает ничего.
- Сценарии `SC-MB-107`…`SC-MB-109` покрыты спеками, привязки проставлены.
- Конвейер собирает приёмник, и отказ сборки роняет прогон.
- `npm run check:specs` расхождений не прибавил, гейт пуша зелёный.

## Этапы

### 1. Отказ сборки

- **Что делается:** рядом с конфигом сборки приёмника заводится чистая функция, судящая
  наличие клиента; конфиг зовёт её до компиляции и останавливает сборку с одной строкой.
- **Признак готовности:** сборка при убранном каталоге печатает строку с каталогом и командой,
  а ошибок типов в выводе нет.
- **Чем проверяется:** спека на функцию, ручной прогон сборки с убранным каталогом.

### 2. Конвейер держит проверку

- **Что делается:** сборка приёмника стоит шагом конвейера так, что её отказ роняет прогон.
- **Признак готовности:** шаг виден в прогоне, и красная сборка кончает его ненулевым кодом.
- **Чем проверяется:** чтение файла конвейера, прогон на своей ветке.

### 3. Тексты приведены к сделанному

- **Что делается:** договорённость вливается в спек домена, привязки проставляются, памятка
  дерева и описание прода говорят о пропаже клиента то, что теперь верно.
- **Признак готовности:** ни один текст по следу задачи не описывает сборку такой, какой она
  была до правки.
- **Чем проверяется:** `npm run check:specs`, `npm run check:docs`, чтение глазами.

## Чего эта работа не делает

- Не разбирает кеш сборок: успех из кеша после пропажи клиента — своя работа.
- Не заводит проверки другим приложениям: клиента зовёт только приёмник.
- Не запускает генератор вместо отказа: сборка, чинящая себя сама, прячет половинную установку.
- Не судит соответствие клиента схеме — это делает своя проверка дерева.
- Не берёт задач вне эпика RT-733.
