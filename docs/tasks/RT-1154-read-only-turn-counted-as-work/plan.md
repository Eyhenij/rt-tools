**Поведение:** не меняется — правка касается слоя правил и хуков, кода приложения не задевает

После написания этот файл не правится. Пересмотр этапа идёт в `progress.md` решением по ходу.

## Что считается сделанным

- Ход, в котором были только чтение истории, переключение ветки и вызовы клиента хостинга на
  чтение, стражем выходов хода не отпускается.
- Ход, в котором рядом с чтением была хоть одна меняющая команда, отпускается как прежде.
- Составная команда судится по частям: читающая часть работой не считается, меняющая — считается.
- Набор стража краснеет, если признак чтения выключить.

## Этапы

### 1. Признак работы отделён от признака чтения

- **Что делается:** страж разбивает команды хода на части и судит каждую: часть, совпавшая с
  образцом чтения, работой не считается.
- **Признак готовности:** в хуке есть образец чтения, и суждение идёт по частям команды.
- **Чем проверяется:** `bash projects/agent-kit/tests/turn-exit-guard.test.sh` — все сценарии зелёные.

### 2. Сценарии на новый признак

- **Что делается:** заводятся сценарии на ход из одного чтения, на чтение вперемешку с работой и
  на составную команду.
- **Признак готовности:** набор краснеет при выключенном признаке чтения.
- **Чем проверяется:** `bash projects/agent-kit/tests/turn-exit-guard.test.sh` — счёт сценариев вырос.

### 3. Статья правила и разбор происшествия

- **Что делается:** в `turn-conduct` встаёт статья о том, что разведка ходом не кончается; разбор
  ложится в `docs/postmortems/`.
- **Признак готовности:** статья привязана, тексты сходятся с деревом.
- **Чем проверяется:** `npm run check:docs` — путей-призраков нет.

## Чего эта работа не делает

- Не трогает признак «работа отдана» и ярус взятой работы — они судят раньше и по-своему.
- Не заводит своего признака у клиента хостинга на запись: `gh pr create`, `gh pr ready` и
  `gh api -X` остаются работой без исключений.
