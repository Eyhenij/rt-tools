## Что считается сделанным

- Признак «не для везения» объявлен правилом и назван двумя вопросами к ресурсу.
- Проверка границы заведена, зовётся своей командой и печатает перечень ресурсов, а не одну
  строку отказа.
- Проверка входит в набор гейта пуша этого дерева.
- Проверка краснеет на нынешнем дереве: ресурсы разбора груза ещё в пакете, и это её первый
  ожидаемый вывод.

## Этапы

### 1. Признак объявлен правилом

- **Что делается:** в правило о пакете дописывается раздел о границе — два вопроса к ресурсу и
  то, что перечень отменяемого границу не закрывает.
- **Признак готовности:** раздел стоит в правиле, слова взяты из договорённости.
- **Чем проверяется:** `npm run check:specs` — код возврата ноль и ни одной строки про
  `package-boundary`.

### 2. Проверка границы заведена

- **Что делается:** заводится своя проверка дерева: обходит ресурсы пакета, отбирает те, что
  говорят о приёме или о дереве пакета, печатает перечень с причиной по каждому.
- **Признак готовности:** проверка зовётся своей командой и на нынешнем дереве краснеет,
  называя ресурсы разбора груза и сведения предложений.
- **Чем проверяется:** `npm run check:boundary` — ненулевой код возврата и перечень, в котором
  стоят правило разбора груза, паттерн при нём и команда сведения предложений.

### 3. Проверка встала в гейт пуша

- **Что делается:** проверка добавляется в набор гейта пуша рядом с остальными.
- **Признак готовности:** гейт зовёт её и отбивает пуш её отказом.
- **Чем проверяется:** `grep -n 'check:boundary' package.json .claude/rt-kit/project.sh` —
  строка найдена в наборе гейта.

### 4. Спека проверки закрывает сценарии

- **Что делается:** пишется спека проверки, закрывающая четыре сценария договорённости.
- **Признак готовности:** сценарии `SC-AK-501`…`SC-AK-504` и `SC-AK-506` перестали быть
  непокрытыми.
- **Чем проверяется:** `npm run check:specs` — строк «нет теста SC-AK-50…» в выводе не осталось.
