# Разбор просьбы

## Просьба владельца

> Почему правила и документы как работать с отчетами в message bus сервисе уехали в законы и
> правила agent kit? Это только локальные правила должны быть, для самого приложения message
> bus, и для агента в этом проекте который будет работать с message bus отчетами

> В пакете должны остаться только то что затрагивает работу приложения потребителя, то есть
> того кто шлет репорты в message bus, все остальное нужно перенести в локальные правила

## Что уже есть в дереве

Разведка командами по этому дереву.

**В пакете лежит и уезжает во все деревья, которые его ставят:**

| Ресурс                                            | Путь                                  | Чья сторона                               |
| ------------------------------------------------- | ------------------------------------- | ----------------------------------------- |
| правило `cargo-triage`                            | `projects/agent-kit/assets/rules/`    | принимающая                               |
| паттерн `cargo-triage-mark`                       | `projects/agent-kit/assets/patterns/` | принимающая                               |
| форма груза `cargo.ts`                            | `projects/agent-kit/src/lib/`         | обе: объявляет отправляющая, читает приём |
| состояния записи `cargo-state.ts` и спека при нём | `projects/agent-kit/src/lib/`         | принимающая                               |
| отправка `shipment.ts`, `ship.ts`                 | `projects/agent-kit/src/lib/`         | отправляющая                              |
| команда `propose`                                 | строка запуска пакета                 | отправляющая                              |
| команда `mark`                                    | строка запуска пакета                 | принимающая                               |
| команды `feedback`, `agent-kit-digest`            | `projects/agent-kit/assets/commands/` | отправляющая                              |

**Спеки.** Порядок разбора лежит поддоменом домена пакета — `docs/specs/agent-kit/cargo/`.
Состояние и версия записи лежат у приёмника — `docs/specs/message-bus/cargo-state/` и
`docs/specs/message-bus/cargo-version/`. Один предмет разрезан по двум доменам.

**Законы груза не знают.** В `docs/constitution/` слова о нём нет: правило встало под
существующий закон о ведении работы.

**Образец переноса в дереве есть.** Пять скилов живут своими, без шапки пакета:
`rt-tools-storybook` с паттерном при нём и `ui-component-tests` с двумя паттернами. Оба
объявлены в своей карте гейта `.claude/rt-kit/gate-map.sh`; ветки для груза там нет.

**Компаньон правила уже держит имена, которых нет ни в одном другом дереве:** приложение
`message-bus`, админка `message-bus-admin`, разделы «Разборы» и «Предложения», доводы
`--state new|in_work|fixed|released`.

## Что уже сказано в правилах

- **Правило переносится между репозиториями, раскладка — нет.** Так говорит и правило ведения
  работы, и само правило разбора груза: пути живут в компаньоне, потому что у каждого дерева
  они свои. Здесь непереносима не раскладка, а сам предмет: приёмник один на мастерскую.
- **Дерево дописывает своё поверх пакета, а чего не везёт пакет — заводит само.** Памятка
  дерева называет два таких правила и причину: пакет их не везёт.
- **Находка эпика об этом уже записана.** В файле находок стоит: готовые вызовы паттерна зовут
  пакет из реестра, а дерево, которое пакет и пишет, зовёт свою сборку. Разошлись два
  потребителя одного текста.
- **Решения спека о месте не было.** Записаны два выбора: правило вместо паттерна при ведении
  работы, и то, что договорённость пишется вообще. Выбор «в пакет, а не локально» не обсуждался.

## Вопросы и ответы

**Что входит в работу: только тексты или вместе с кодом принимающей стороны?**
Тексты и код разом. Уезжают правило, паттерн, спек, а с ними команда отметки и состояния
записи.

**Входят ли в работу прочие ресурсы, бессмысленные у потребителя?**
Всё, что бессмысленно у потребителя. Пакет чистится по этому признаку целиком, а не только
по грузу.

**Одна задача или серия?**
Серия из трёх задач эпиком: признак границы, груз, остальные ресурсы дерева пакета.

**Что не входит?**
Не входит код приёмника и админки, не входит отправляющая сторона, не входит отметка
накопившихся записей груза. Правка законов из списка исключений не выбрана — значит статья
закона из работы выйти может; в ветке закон при этом не правится, а приносится владельцу
текстом, как велит правило ведения работы.

**Чем будет видно, что работа закрыта?**
Проверка границы зелёная и входит в гейт пуша: ни один ресурс пакета не говорит о приёме и о
дереве пакета. Последующие задачи закрываются тем, что она перестала краснеть.

**Где живёт проверка границы?**
Своя проверка дерева, рядом с остальными его проверками. Образец — уже живущие свои проверки
и своя карта гейта. Чужому дереву она не едет.

## Что нашлось после первого ответа

Пакет сам называет ресурсы, которые у потребителя бессмысленны. Команда сведения предложений
говорит прямо: зовётся в репозитории самого пакета, а в чужом дереве бессмысленна — там есть
только своя половина картины. Такой оговоркой помечены пять ресурсов: сведение предложений,
ревью слоя правил, умолчания профиля, гард подписи поставки и памятка о самом пакете.

На правило разбора груза ссылается одна команда — сведение предложений. Больше в пакете на
него не ссылается ничто.
