# What it is carried out by — load error and placeholder states of the conversation components

The first column is the rule of the spec next to it verbatim. The second is where it is carried out
in the tree; the scenario it is checked by is named there too, and what exactly every scenario is
covered by is said in `scenarios.md`.

A rule without a line and a line without a rule is a divergence: the spec promises what is not in the
tree, or the tree holds what the spec is silent about.

- **The error wins over loading and emptiness.** — `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list.component.ts:hasError` — the rows branch asks the error before loading and emptiness; the chat and the details panel ask `projects/ui-kit-v2/src/rich-editor/lib/components/chat/rt-chat.component.ts:loadError` and `projects/ui-kit-v2/src/lib/components/workspace-details/rt-workspace-details.component.ts:loadError` before their content; scenario `SC-UKV-1267`
- **A load more error keeps the rows.** — `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list.component.html:load-error` — the error row stands after the rows and inside the same list; scenario `SC-UKV-1268`
- **The retry button emits `retry` and nothing else.** — `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list.component.ts:retry`, `projects/ui-kit-v2/src/rich-editor/lib/components/chat/rt-chat.component.ts:retry` and `projects/ui-kit-v2/src/lib/components/workspace-details/rt-workspace-details.component.ts:retry` — the outputs; no component reloads by itself; scenarios `SC-UKV-1269`, `SC-UKV-1277`, `SC-UKV-1278`
- **The default error view is `rt-empty-state` with the alert icon, a title, a hint and an outlined «Повторить» button.** — `projects/ui-kit-v2/src/lib/components/empty-state/rt-load-error.ts:rtLoadErrorView` — the title, the hint and the template context of the chat and the details panel; the thread list computes the same in `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list.component.ts:errorTitle`; scenario `SC-UKV-1270`
- **The empty and nothing-found texts of `rt-thread-list` are inputs.** — `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list.component.ts:nothingFoundTitle` and `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list.component.ts:filtered` — the inputs and the sign of active search or filters; scenario `SC-UKV-1271`
- **An own view replaces the default one whole.** — `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list.component.ts:emptyContext`, `projects/ui-kit-v2/src/rich-editor/lib/components/chat/rt-chat.component.ts:errorTemplate` and `projects/ui-kit-v2/src/lib/components/workspace-details/rt-workspace-details.component.ts:errorTemplate` — a declared template is rendered instead of the default placeholder; scenarios `SC-UKV-1272`, `SC-UKV-1273`
- **The chat placeholder without a conversation has a title, a hint and an icon.** — `projects/ui-kit-v2/src/rich-editor/lib/components/chat/rt-chat.component.ts:emptyHintText` and `projects/ui-kit-v2/src/rich-editor/lib/components/chat/rt-chat.component.ts:emptyIcon` — the hint falls back to the kit label; scenario `SC-UKV-1276`
- **The width of the placeholder is set by a variable, not by an own view.** — `projects/ui-kit-v2/src/lib/components/empty-state/rt-empty-state.component.scss:rt-empty-state-max-width` and `projects/ui-kit-v2/src/rich-editor/lib/components/chat/rt-chat.component.scss:rt-empty-state-max-width` — the kit default and the chat value; no scenario: the width is measured in the showcase against the approved frame
- **The thread list header has no side padding of its own.** — `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list-messenger.scss:padding-inline` — the messenger header drops the side padding; scenario `SC-UKV-1274`
- **The tab switch stands 8 px from the header line and 8 px from the content.** — `projects/ui-kit-v2/src/lib/components/thread-list/rt-thread-list-messenger.scss:rt-thread-list__tabs` — the switch padding and the column gap; scenario `SC-UKV-1275`
