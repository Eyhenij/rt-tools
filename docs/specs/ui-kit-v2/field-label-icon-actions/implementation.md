# What it is carried out by — the field's label on the border, actionable icons and the clearing cross

The first column is the rule of the spec next to it verbatim. The second is where it is carried out
in the tree, and the scenarios it is checked by; what exactly every scenario is covered by is said in
`scenarios.md`.

- **The select draws the consumer's option template in place of the row label.** — `projects/ui-kit-v2/src/lib/components/select/rt-select-option.directive.ts:RtSelectOptionDirective`, `projects/ui-kit-v2/src/lib/components/select/rt-select.component.ts:optionTpl`; scenario `SC-UKV-948`
- **The chosen value in the field is drawn by the same option template.** — `projects/ui-kit-v2/src/lib/components/select/rt-select.component.ts:chosenOwn`, `projects/ui-kit-v2/src/lib/components/select/rt-select.component.html:select-value-content`; scenario `SC-UKV-946`
- **Without an option template the row is drawn as before.** — `projects/ui-kit-v2/src/lib/components/select/rt-select.component.html:option-label`; scenario `SC-UKV-973`
- **The label on the border lies at the placeholder's place while the field is empty and at rest.** — `projects/ui-kit-v2/src/lib/components/input/rt-input-floating-label.scss:rt-input-floating-label-rest-start`, the placeholder hidden — `projects/ui-kit-v2/src/lib/components/select/rt-select-floating-label.scss:__label--placeholder`; scenario `SC-UKV-974`
- **The label rises onto the top border when the field holds a value or is in use.** — `projects/ui-kit-v2/src/lib/components/input/rt-input-floating-label.scss:rt-input-floating-label-raised-start`, the cut of the border — `projects/ui-kit-v2/src/lib/components/form-control/rt-notch-width.ts:rtNotchWidth`; scenarios `SC-UKV-975`, `SC-UKV-976`
- **The label on the border names the control for assistive technology when no aria label is given.** — `projects/ui-kit-v2/src/lib/components/input/rt-input.component.ts:labelledBy`, `projects/ui-kit-v2/src/lib/components/select/rt-select.component.ts:labelledBy`; scenario `SC-UKV-977`
- **The label on the border is drawn only under the material preset.** — `projects/ui-kit-v2/src/lib/components/input/rt-input-floating-label.scss:__floating-label`, `projects/ui-kit-v2/src/lib/components/select/rt-select-floating-label.scss:__floating-label`; scenario `SC-UKV-974`
- **A field without the label on the border is drawn as before.** — `projects/ui-kit-v2/src/lib/components/input/rt-input.component.html:floatingLabel`, `projects/ui-kit-v2/src/lib/components/select/rt-select.component.html:floatingLabel` — the label stands behind its own condition; scenario `SC-UKV-974`
- **An icon of the input marked as actionable is a button.** — `projects/ui-kit-v2/src/lib/components/input/rt-input.component.html:input-icon-left-action`, `projects/ui-kit-v2/src/lib/components/input/rt-input.component.ts:iconLeftClick`; scenario `SC-UKV-978`
- **Pressing an actionable icon does not move focus into the native field.** — `projects/ui-kit-v2/src/lib/components/input/rt-input.component.ts:onHostMousedown`; scenario `SC-UKV-978`
- **An actionable icon may carry a tooltip.** — `projects/ui-kit-v2/src/lib/components/input/rt-input.component.html:iconRightTooltip`; scenario `SC-UKV-1008`
- **The right icon of a password field with a show switch is not made actionable.** — `projects/ui-kit-v2/src/lib/components/input/rt-input.component.html:showPasswordToggle` — the switch takes the branch before the right icon
- **An icon not marked as actionable is drawn as before.** — `projects/ui-kit-v2/src/lib/components/input/rt-input.component.html:iconLeftAction` — the branch without the mark draws `rt-icon`; scenario `SC-UKV-1009`
- **An actionable icon is disabled by its own input while the field stays usable.** — `projects/ui-kit-v2/src/lib/components/input/rt-input.component.ts:isIconLeftDisabled`, `projects/ui-kit-v2/src/lib/components/input/rt-input.component.ts:isIconRightDisabled`; scenario `SC-UKV-954`
- **The clearing cross of the input and the select is reached by the Tab key when the field asks for it.** — `projects/ui-kit-v2/src/lib/components/form-control/rt-form-control.base.ts:clearTabIndex`, `projects/ui-kit-v2/src/lib/components/select/rt-select.component.html:clearTabbable`; scenario `SC-UKV-1010`
- **The kit settings name whether the clearing cross goes by Tab.** — `projects/ui-kit-v2/src/lib/components/form-control/rt-form-control.base.ts:clearTabbable`, the node — `projects/ui-kit-v2/src/lib/config/rt-kit-config.model.ts:FormControl`; scenario `SC-UKV-1083`
- **Every control of the shared base with a clearing cross obeys `clearTabbable`.** — `projects/ui-kit-v2/src/lib/components/form-control/rt-form-control.base.ts:clearTabIndex`, read by the templates of the autocomplete, the number field, the date picker and the date range; scenario `SC-UKV-1084`
- **The cross of the multiselect goes by Tab as a button next to the trigger.** — `projects/ui-kit-v2/src/lib/components/multiselect/rt-multiselect.component.html:multiselect-clear`; scenario `SC-UKV-1086`
- **Clearing reports to the host after the value is reset and the change is sent to the form.** — `projects/ui-kit-v2/src/lib/components/form-control/rt-form-control.base.ts:cleared`; scenario `SC-UKV-1011`
- **The cross is shown by default.** — `projects/ui-kit-v2/src/lib/components/form-control/rt-form-control.base.ts:clearable`, the docs — `projects/ui-kit-v2/src/lib/components/input/Overview.mdx:clearable`, `projects/ui-kit-v2/src/lib/components/select/Overview.mdx:clearable`
- **An input and a textarea take a length limit that goes onto the native field.** — `projects/ui-kit-v2/src/lib/components/form-control/rt-maxlength.ts:rtMaxlength`, `projects/ui-kit-v2/src/lib/components/input/rt-input.component.html:maxlength`, `projects/ui-kit-v2/src/lib/components/textarea/rt-textarea.component.html:maxlength`; scenarios `SC-UKV-1015`, `SC-UKV-1016`
