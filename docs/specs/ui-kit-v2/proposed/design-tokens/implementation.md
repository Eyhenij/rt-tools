# Чем будет исполнено — оформление второго кита

Кода на эту договорённость ещё нет, поэтому привязки к символам здесь нет и сверка спеков её не
спрашивает. Вторая колонка называет место, где правило встанет, третья — сценарий, которым оно
проверяется. Таблица правится тем же изменением, что и код: место, оказавшееся другим,
переписывается здесь, а не запоминается.

## Набор, который судят проверки

«Стили компонента второго кита» — это `projects/ui-kit-v2/src/lib/**/*.scss`, восемьдесят семь
файлов. Никакого другого набора у проверок линии нет: их пишут против этой строки, а не против
списка папок.

Что в набор не входит и почему:

| Что                                                        | Почему                                                                                          |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `src/showcase/*.scss` — три файла                          | обвязка витрины, в пакет не едет                                                                |
| `.storybook/storybook.scss`                                | оформление самой витрины, не кита                                                               |
| `src/styles/_login.scss`                                   | экран входа: раскладка приложения, а не компонент                                               |
| `src/styles/_scrollbar.scss`                               | слой оформления, а не компонент; литералы в нём судит правило слоя назначений                   |
| `src/styles/_primitives.scss`                              | шкала — единственное место, где литерал законен по определению                                  |
| `src/styles/_semantic.scss`, `src/styles/_theme-dark.scss` | слой назначений: судится своим правилом — ссылка на ступень вместо литерала, — а не этим        |
| стиль в шаблоне `.ts` под `**/stories/**`                  | обёртки историй: демонстрационный код, в пакет не едет. Файлов `.scss` под `stories/` нет вовсе |

**Порог ширины числом в медиазапросе литералом не считается.** Пользовательские свойства CSS в
`@media` не работают — об этом прямо сказано в `src/styles/_index.scss`, — и порог берётся
переменной препроцессора из `src/styles/_breakpoints.scss`. В наборе таких чисел девятнадцать; не
исключи их, и правило нарушают девятнадцать законных мест в день своего включения.

Команда счёта по набору — ею сняты все числа раздела «Замеры»:

```bash
cd projects/ui-kit-v2
find src/lib -name '*.scss' | wc -l                                                           # файлов
find src/lib -name '*.scss' -exec grep -hv -E '@media' {} \; | grep -oE '\b[0-9]+px' | wc -l   # пиксельных чисел
find src/lib -name '*.scss' -exec grep -h -E '^\s*--rt-[a-z0-9-]+\s*:' {} \; | grep -oE '\b[0-9]+px' | wc -l   # из них в своих свойствах
find src/lib -name '*.scss' -exec grep -ho -E '#[0-9a-fA-F]{3,8}\b' {} \; | wc -l             # кодов цвета
grep -rl --include='*.scss' -E '^[[:space:]]+--rt-[a-z-]+:' src/lib | wc -l                   # файлов со своими свойствами
grep -rn --include='*.scss' '::ng-deep' src/lib | wc -l                                       # обходов чужой вёрстки
```

**Пиксельное число и литерал — не одно и то же.** Из двухсот восьми пиксельных чисел набора
шестьдесят одно стоит в объявлениях своих свойств компонента — там значение и должно быть, это
третий слой, — а сто сорок семь приходится на размеры: `width`, `height`, `inline-size`,
`block-size`, `outline`. Размеры проверка не судит вовсе, и это её граница, а не пропуск: своей
шкалы высот у кита пока нет (RT-386), и до неё размер числом законен. Мест, которые проверка
действительно судит, двадцать четыре, и все они коды цвета. Зелёный прогон значит «новых кодов
цвета нет», а не «литералов не осталось».

Что судит проверка — `pnpm run check:tokens-styles`.

## Чего проверкой не закрыть

- **Совпадение имён токенов у двух китов.** Девять общих имён объявляют оба кита с разными
  значениями. Правила против сегодняшних совпадений здесь нет: починка задевает выпущенный первый
  кит, выведенный за границу линии. Проверка графа токенов принимает эти девять списком и
  отбивает новое совпадение — то есть стережёт не сегодняшнее положение, а его ухудшение.
  Открытый вопрос `Q-3` в спеке.
- **Полнота набора свойств у компонента.** Проверка видит, что свойство объявлено, но не судит,
  все ли настраиваемые снаружи места компонента им покрыты. Судит это разбор изменения.
- **Момент, когда слой каскада поехал у потребителя.** Кадры витрины его не поймают: чужих
  переопределений в витрине нет. Держится записью о переходе и разбором изменения.
