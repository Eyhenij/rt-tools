# Чем исполняется — значок по требованию

Первая колонка — правило спека рядом дословно. Вторая — где оно исполняется в дереве; там же
назван сценарий, которым это проверяется, а чем именно покрыт каждый сценарий, сказано в
`scenarios.md`.

Привязки заполняются по ходу работы: до кода их нет, и правило без строки здесь — обещание, а не
расхождение. К вливанию в спек домена пустых строк не остаётся.

- **Значок едет по запросу имени, а не вперёд.** — привязка появится с правкой реестра; сценарий `SC-UKV-58`
- **Повторный запрос того же имени сети не трогает.** — привязка появится с правкой реестра; сценарий `SC-UKV-59`
- **Отказ одного имени гасит только его значок.** — привязка появится с правкой реестра; сценарий `SC-UKV-60`
- **Обе разметки значка просят одинаково.** — привязка появится с правкой компонента значка и директивы кнопки; сценарий `SC-UKV-61`
- **Символ, уже лежащий в спрайте страницы, запроса не даёт.** — привязка появится с правкой реестра; сценарий `SC-UKV-63`
- **Смена имени у нарисованного значка тянет новое имя.** — привязка появится с правкой компонента значка; сценарий `SC-UKV-62`
- **На сервере набор не грузится.** — привязка появится с правкой приёма кита; сценарий `SC-UKV-64`
- **Предзагрузки всего набора у кита нет.** — привязка появится со снятием прежнего приёма; сценарий `SC-UKV-65`
