# Чем исполняется — уход с route-панели второго кита

Кода под эту договорённость ещё нет, поэтому привязки к символам здесь не стоят: сверка спеков
их у `proposed/` и не спрашивает. Таблица называет узел, в котором правило встанет, чтобы при
вливании в спек пакета было видно, где искать место исполнения и не разъехалось ли оно с
обещанием.

Все названные файлы лежат в `projects/ui-kit-v2/src/lib/components/container/`. Учёт панелей —
новый файл там же: существующая служба состояния каркаса поставляется на уровне компонента, а
роутерный гард живёт в инжекторе маршрута и до неё не дотягивается.

| Правило                                                                                    | В каком узле встанет                                                                        |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| Панель, начавшая уход сама, о правках не спрашивает.                                       | `rt-route-aside.base.ts` — выдача разрешения и ответ на вопрос о правках                    |
| Разрешение выдаётся в одной точке — перед тем, как панель зовёт роутер.                    | `rt-route-aside.base.ts` — единственное место, откуда панель зовёт роутер                   |
| Разрешение действует ровно на один уход и не переживает навигацию, которая не состоялась.  | `rt-route-aside.base.ts` — чтение разрешения и снятие его по итогу обещания навигации       |

| Уход во время записи отменяется молча.                                                     | `rt-route-aside.base.ts` — ответ на вопрос о правках, признак записи старше разрешения      |

## Что проверяет прогон

Модульные спеки трёх узлов, без раскладки маршрутов:

- **учёт панелей** — постановка и снятие, ответ по маршруту, две панели двух каркасов под
  одинаково названными аутлетами, пустой учёт: `SC-UKV-27`, `SC-UKV-28`;
- **роутерный гард** — спрашивает учтённую панель, падает на компонент от роутера, когда учёт
  под маршрутом пуст, переживает компонент без ответа, не отвечает отказом навигации ни при
  одном входе, включая отказавший ответ: `SC-UKV-24`, `SC-UKV-26`, `SC-UKV-30`, `SC-UKV-31`;
- **базовый класс панели** — выдача и съедание разрешения, несостоявшаяся навигация, уход со
  стороны при тронутой и чистой форме, повтор ухода, уход во время записи: `SC-UKV-21`,
  `SC-UKV-22`, `SC-UKV-23`, `SC-UKV-25`, `SC-UKV-29`, `SC-UKV-32`, `SC-UKV-33`, `SC-UKV-34`.

Каждый сценарий закрыт ровно одной из трёх спек; сценария, который не проверяет ни один прогон,
в договорённости не осталось. Идентификаторы ставятся в заголовки спек при написании кода; до
тех пор все сценарии помечены непокрытыми.
