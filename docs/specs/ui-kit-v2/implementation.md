# Чем исполняется — второй кит

Первая колонка — правило спека дословно. Вторая — где оно исполняется в дереве. Третья —
сценарий, которым это проверяется; чем именно покрыт каждый сценарий, сказано в `scenarios.md`.

Правило без строки и строка без правила — расхождение: спек обещает то, чего в дереве нет, либо
в дереве стоит то, о чём спек молчит.

## Набор, который судят проверки оформления

«Стили компонента второго кита» — это `projects/ui-kit-v2/src/lib/**/*.scss`, восемьдесят семь
файлов. Никакого другого набора у проверок оформления нет: их пишут против этой строки, а не
против списка папок. Слой оформления в набор не входит: литерал в шкале законен по определению,
а литерал в назначениях судит своё правило — ссылка на ступень вместо значения.

**Порог ширины числом в медиазапросе литералом не считается.** Пользовательские свойства CSS в
`@media` не работают, и порог берётся переменной препроцессора из
`projects/ui-kit-v2/src/styles/_breakpoints.scss`.

**Пиксельное число и литерал — не одно и то же.** Числа в объявлениях своих свойств компонента
законны: это третий слой. Размеры — `width`, `height`, `inline-size`, `outline` — проверка не
судит вовсе, и это её граница, а не пропуск: расширение набора — своя работа.

Команды счёта — ими сняты числа раздела «Замеры»:

```bash
cd projects/ui-kit-v2
find src/lib -name '*.scss' | wc -l                                                           # файлов
find src/lib -name '*.scss' -exec grep -hv -E '@media' {} \; | grep -oE '\b[0-9]+px' | wc -l   # пиксельных чисел
find src/lib -name '*.scss' -exec grep -ho -E '#[0-9a-fA-F]{3,8}\b' {} \; | wc -l             # кодов цвета
grep -rl --include='*.scss' -E '^[[:space:]]+--rt-[a-z-]+:' src/lib | wc -l                   # файлов со своими свойствами
grep -rn --include='*.scss' '::ng-deep' src/lib | wc -l                                       # обходов чужой вёрстки
```

```bash
node tools/check-tokens-theme.mjs            # назначения, ответы, пометки, принятое
node tools/check-tokens-theme.mjs --measure  # отношение по каждой паре в обеих темах
```

## Чего проверками оформления не закрыть

- **Совпадение имён токенов у двух китов.** Девять общих имён приняты списком: починка задевает
  выпущенный первый кит, выведенный за границу. Проверка графа стережёт не сегодняшнее
  положение, а его ухудшение. Открытый вопрос `Q-3` в спеке.
- **Полнота набора свойств у компонента.** Проверка видит, что свойство объявлено, но не судит,
  все ли настраиваемые снаружи места им покрыты. Судит это разбор изменения.
- **Полнота перечня пар «текст и фон».** Считается контраст ровно тех пар, что названы в
  перечне, и забытая пара молчит так же, как её нет. Вывести пары перебором имён нельзя:
  сочетаний выходит на порядок больше, чем встречается на экране.
- **Момент, когда слой каскада поехал у потребителя.** Кадры витрины его не поймают: чужих
  переопределений в витрине нет. Держится записью о переходе и разбором изменения.
- **Прозаические записки источника.** Что ряд посчитан ровным, видно только чтением: генератор
  переносит записку как есть и не сверяет её с числами.

## Что осталось за спеком

- **Кадры на семи языках из восьми.** Кадр снимается на одном языке; обрезка подписи на длинном
  языке этой работой не ловится. Записано долгом, а не выдано за покрытие.
- **Восемнадцать историй, рисующих пустой набор.** Сняты со съёмки поимённо, у каждой своя
  причина при пометке. Наполнение — волна покрытия составных компонентов, своя работа.
- **Пороги ширины шести папок из одиннадцати.** У `photo-viewer` историй нет вовсе, `rt-toolbar`
  витриной не показан ни одной историей, а `calendar`, `toast`, `workspace` и `table` сняты со
  съёмки как пустые. Кадр порога вернётся к ним вместе с наполнением.
- **Заголовок сортировки таблицы.** Подпись он берёт из проекции, и вне таблицы ей взяться
  неоткуда: показ пуст даже с двойником таблицы.
