# Спеки пакетов

**Домен здесь — пакет в `projects/`.** По каталогу на пакет: `ui-kit`, `ui-kit-v2`, `core`,
`store`, `utils`, `agent-kit`.

Спек описывает публичную поверхность пакета — что он обещает потребителю — и пишется до кода,
который это обещание исполняет. Написанный после, он пишется по коду и повторяет его ошибки:
разойтись ему уже не с чем.

## Раскладка

```
docs/specs/<пакет>/
    spec.md          — что пакет обещает: поверхность, договорённости, границы
    scenarios.md     — сценарии с идентификаторами; на них ссылаются заголовки тестов
    implementation.md — чем каждое обещание исполнено в коде
    proposed/<фича>/ — договорённость по незакрытой работе; переживает мерж и вливается в spec.md
```

Договорённость лежит в `proposed/<фича>/`, пока ветка не влита; последним коммитом работы она
вливается в спек пакета, а каталог снимается.

Правило — `.claude/skills/spec-driven/`, закон — `docs/constitution/project-documentation.md`.
Ведение работы — `.claude/skills/task-flow/`.

## Что уже написано

`agent-kit` — что пакет обещает потребителю на установке с нуля, в каком месте он обязан
отказать вместо молчания и что происходит с потомками отвергнутого закона.

`ui-kit-v2` — сверка кадров витрины с эталонами: что снимается, чем кадр держится одинаковым
между прогонами и где прогон обязан отказать вместо зелёного. Двадцать сценариев `SC-UKV`,
двадцать четыре правила с привязкой к коду. Поверхности пакета — компонентов, токенов, служб —
спек пока не описывает.

## Префиксы сценариев

| пакет       | префикс  |
| ----------- | -------- |
| `agent-kit` | `SC-AK`  |
| `ui-kit-v2` | `SC-UKV` |

Префикс на пакет один и после вливания не меняется: на идентификаторы ссылаются заголовки тестов.
