# Как это сделано — закреплённое подменю и поиск по нему

## Где что лежит

| Что                      | Где                                                                           |
| ------------------------ | ----------------------------------------------------------------------------- |
| Контракт входов          | `projects/ui-kit/src/lib/ui-kit/side-menu/side-menu.types.ts`                 |
| Отбор пунктов            | `projects/ui-kit/src/lib/ui-kit/side-menu/side-menu.logic.ts`                 |
| Входы, выходы, состояние | `projects/ui-kit/src/lib/ui-kit/side-menu/menu/rtui-side-menu.component.ts`   |
| Разметка обеих раскладок | `projects/ui-kit/src/lib/ui-kit/side-menu/menu/rtui-side-menu.component.html` |
| Оформление               | `projects/ui-kit/src/lib/ui-kit/side-menu/menu/rtui-side-menu.component.scss` |
| Витрина                  | `projects/ui-kit/src/lib/ui-kit/side-menu/stories/`                           |

## Решения

- **Отбор считает чистая функция в `side-menu.logic.ts`.** Разметка компонента держит две
  раскладки разом; ветвление отбора в ней читается хуже вызова и проверяется тяжелее.
- **Мода — вход, нажатие переключателя — выход.** Образец рядом: активность пунктов приходит
  входом `activeMenuIds`, а нажатие подпункта только уходит наружу.
- **Закреплённая шторка идёт без подложки.** Вход `hasBackdrop` у контейнера ставится по моде.
- **Значок переключателя берётся у Material** — так же, как остальные значки этого кита.
- **Запрос живёт сигналом компонента.** Он не предпочтение и умирает вместе с открытым
  подменю; образец рядом — `selectedSubMenu` в том же классе.

## Чего здесь нет

- Своего вычисления активного пункта по адресу: кит берёт его входом.
- Словаря подписей: три новые подписи зашиты по-английски, как кнопка возврата рядом.
