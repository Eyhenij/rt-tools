# Binding — the guard of the course of work

A statement of the spec and the place where it is carried out. The link goes by the text of the
statement: a removed statement is removed together with its line.

- **A step of a plan with checks is marked done in the progress only by the engine, never by an edit.** — `projects/agent-kit/assets/checks/flow-guard.mjs:newlyDone` — the steps the edit marks done; `projects/agent-kit/assets/checks/flow-guard.mjs:judgeProgress` — the refusal of each; scenario `SC-AK-1414`
- **Done steps go first in the progress, and the one current step right after them.** — `projects/agent-kit/assets/checks/flow-guard.mjs:marksOutOfOrder` — the order of the marks; scenario `SC-AK-1415`
- **The state line of the progress is not set ahead of the state the engine measures.** — `projects/agent-kit/assets/checks/flow-guard.mjs:declaredState` — the state line; `projects/agent-kit/assets/checks/task-flow-script.mjs:runGuard` — the measured state; scenario `SC-AK-1416`
- **The progress, the plan, the epic plan and the marks are written by no shell command, and the marks by no tool but the engine.** — `projects/agent-kit/assets/checks/flow-guard.mjs:judgeShell` — a simple command that names a guarded file passes only as a reader; `projects/agent-kit/assets/checks/flow-guard.mjs:shellCommands` — the simple commands of a call with their heredocs; `projects/agent-kit/assets/checks/flow-guard.mjs:scriptWrites` — the signs of a write in an interpreter script; `projects/agent-kit/assets/checks/flow-guard.mjs:judgeCall` — the directory of the marks; scenarios `SC-AK-1417`, `SC-AK-1418`, `SC-AK-1419`, `SC-AK-1420`
- **A plan without check lines and the plan of a branch planned before the engine keep the done marks as written.** — `projects/agent-kit/assets/checks/flow-guard.mjs:judgeProgress` — the closed list `words.legacyBranches`; scenarios `SC-AK-1421`, `SC-AK-1422`, `SC-AK-1536`
- **«отложено» in the epic plan is set and lifted only by the owner's last word naming the task.** — `projects/agent-kit/assets/checks/flow-guard.mjs:deferChanges` — the tasks whose word changes; scenarios `SC-AK-1423`, `SC-AK-1424`, `SC-AK-1425`, `SC-AK-1426`
- **The tree override is edited only by the owner's last word naming the key it changes, and the reason of a removed key quotes that word.** — `projects/agent-kit/assets/checks/flow-guard.mjs:changedKeys` — the keys and the reasons of the lines that differ; scenarios `SC-AK-1521`, `SC-AK-1522`, `SC-AK-1523`
- **The description, its measurers and sources and the engine are edited only in a task whose approved plan names their path in a footprint row marked «(правится)».** — `projects/agent-kit/assets/checks/flow-guard.mjs:editedPaths` — the paths of the edited rows; `projects/agent-kit/assets/checks/flow-guard.mjs:namedBy` — a file or the directory that holds it; scenarios `SC-AK-1524`, `SC-AK-1525`, `SC-AK-1526`, `SC-AK-1530`, `SC-AK-1532`
- **While a merge of a reviewed base runs, a side of a conflict block is taken in a guarded file without a plan.** — `projects/agent-kit/assets/checks/flow-guard-run.mjs:reviewedMerge` — the merge, its base and its unmerged paths; `projects/agent-kit/assets/checks/flow-merge.mjs:resolvesBlock` — an edit that replaces a whole block by a side; `projects/agent-kit/assets/checks/flow-merge.mjs:choosesSide` — `git checkout` and `git restore` with `--ours` or `--theirs`; `projects/agent-kit/assets/checks/flow-guard.mjs:judgeCall` and `projects/agent-kit/assets/checks/flow-guard.mjs:judgeShell` ask them before the rule of the guarded files; scenario `SC-AK-2016`
- **The owner's last word is a message the owner typed or the options the owner chose in a menu.** — `projects/agent-kit/assets/task-flow/source/owner.mjs:wordOf` — a typed message, a menu answer, no hook message; `projects/agent-kit/assets/checks/flow-guard-run.mjs:guardContext` hands the source to the decisions of the guard; scenario `SC-AK-1531`
- **A plan with no approval mark is refused a check whose form hides its result, when it is written.** — `projects/agent-kit/assets/checks/flow-plan.mjs:writtenPlanProblem` — called by `projects/agent-kit/assets/hooks/flow-step-guard.sh:write_plan_check` on a write of the plan of the branch; scenario `SC-AK-1940`
- **A plan with no approval mark is refused a decision that is not complete, and all it lacks is named at once.** — `projects/agent-kit/assets/checks/flow-plan.mjs:decisionRefusal` — one line for a write of the plan, for `plan-check` and for `plan-red`; `projects/agent-kit/assets/checks/flow-plan.mjs:answersForDecision` — a plan written before the engine read decisions is not asked by `plan-red`; the action of the table is `projects/agent-kit/assets/hooks/flow-step-guard.sh:write_plan_decision`; scenario `SC-AK-1973`
- **The decision is a table of nine rows, or one line with the reason there is none.** — `projects/agent-kit/assets/checks/flow-decision.mjs:decisionRows` — the section and what each cell names; `projects/agent-kit/assets/checks/flow-decision.mjs:decisionProblems` — what it lacks; scenarios `SC-AK-1971`, `SC-AK-1972`
- **The guard lets a call through when the engine is absent, fails or prints nothing.** — `projects/agent-kit/assets/hooks/flow-step-guard.sh:verdict` — an absent engine, a failed run or an empty line passes, as the `FAIL-OPEN` line of its header declares
- **A tree override that does not build does not lift the hooks: they judge by the package description.** — `projects/agent-kit/assets/checks/task-flow-script.mjs:HOOK_COMMANDS` — the commands `guard` and `verdict` build the model again without the override and name the failure on the error stream; scenarios `SC-AK-1521`, `SC-AK-1523`, `SC-AK-1524`
