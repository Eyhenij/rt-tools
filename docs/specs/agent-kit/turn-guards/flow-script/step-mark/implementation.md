# Binding — a mark is measured again, not believed

A statement of the spec and the place where it is carried out. The link goes by the text of the
statement: a removed statement is removed together with its line.

## The step

- **On a match the engine marks the step done in the progress itself, next to writing its mark.** — `projects/agent-kit/assets/checks/flow-step.mjs:markedProgress` — the done mark and the next current one; `projects/agent-kit/assets/checks/flow-step.mjs:measureStep` — the write on a match; scenarios `SC-AK-1702`, `SC-AK-1726`, `SC-AK-1736`
- **An edit that newly marks done a step of a plan with checks is refused, whatever mark lies on disk.** — `projects/agent-kit/assets/checks/flow-guard.mjs:judgeProgress` — the refusal; `projects/agent-kit/assets/checks/flow-guard.mjs:newlyDone` — the steps the edit marks done; scenario `SC-AK-1703`
- **Whether a plan has checks, and which, is read from the commit that added the plan, never from the working copy.** — `projects/agent-kit/assets/checks/flow-guard-run.mjs:guardContext` — `committed`, the text of the oldest commit that added the file; scenario `SC-AK-1716`
- **The marks are kept by branch, and the latest measurement of a step in any working copy is the one that holds.** — `projects/agent-kit/assets/task-flow/source/marks.mjs:marksDir` — the common directory of git, one per repository; `projects/agent-kit/assets/task-flow/measure/progress.mjs:done` reads the mark by branch; scenario `SC-AK-1729`
- **On a taken-apart task folder the step command puts the folder back from the history for its run.** — `projects/agent-kit/assets/task-flow/source/git.mjs:putBack` — the files of the parent of `projects/agent-kit/assets/task-flow/source/git.mjs:removedAt`; `projects/agent-kit/assets/checks/flow-step.mjs:measureStep` — the run on the folder put back; `projects/agent-kit/assets/checks/flow-step.mjs:progressOfStep` — the progress of the measurement; `projects/agent-kit/assets/task-flow/source/git.mjs:release` — the folder removed with all it holds; scenario `SC-AK-1822`
- **A step the last progress of the history does not mark done is refused on a taken-apart folder, with the move `git revert` of the commit that took it apart.** — `projects/agent-kit/assets/checks/flow-step.mjs:measureStep` — the refusal, after the plan is asked for the number; scenario `SC-AK-1823`
- **A folder put back for a run is cleaned at a start of the engine only when its process is gone, the head lacks it and each recorded file is absent or holds a text the run wrote.** — `projects/agent-kit/assets/task-flow/source/git.mjs:recordPath` — the record in the git directory of the copy; `projects/agent-kit/assets/task-flow/source/git.mjs:rewritePutBack` — a digest before its text; `projects/agent-kit/assets/task-flow/source/git.mjs:cleanBroken` — the cleanup; `projects/agent-kit/assets/checks/task-flow-script.mjs:cleanBrokenRun` — before any command, a kept folder named on stderr; scenario `SC-AK-1824`
- **A step run while another live run holds the folder put back is refused, and its mark stays.** — `projects/agent-kit/assets/task-flow/source/git.mjs:liveRun` — the live run of another process; `projects/agent-kit/assets/checks/flow-step.mjs:restoreFolder` — the refusal; scenario `SC-AK-1822`
- **`step --done` on a taken-apart folder measures the done steps the way the final rerun does.** — `projects/agent-kit/assets/checks/flow-step.mjs:runStepCommand` — the turn to `runBeforePull`; scenario `SC-AK-1822`

## The stage

- **`step <N>` measures the steps of stage N that lack a done mark with a green one, side by side; with none lacking it measures them all.** — `projects/agent-kit/assets/checks/flow-stage.mjs:runStage` — the steps of the stage and the choice of those measured; `projects/agent-kit/assets/checks/flow-step.mjs:measureSteps` — the runs side by side; scenarios `SC-AK-1997`, `SC-AK-2001`
- **After the measurement `step <N>` marks the matched steps done in the order of the whole plan, up to the first step that stays open.** — `projects/agent-kit/assets/checks/flow-stage.mjs:markedStage` — the order and the first open step; scenarios `SC-AK-1997`, `SC-AK-1998`, `SC-AK-1999`, `SC-AK-2000`
- **`step <N>` exits with 0 only when every measured step matched and is marked done.** — `projects/agent-kit/assets/checks/flow-stage.mjs:runStage` — the code; scenarios `SC-AK-1998`, `SC-AK-2000`, `SC-AK-2002`
- **`step <N>` is refused on a stage the plan does not name and on a taken-apart task folder, one standing on disk and not in the head included.** — `projects/agent-kit/assets/checks/flow-stage.mjs:runStage` — both refusals; scenario `SC-AK-2002`

## The final rerun

- **The PR of a task does not open until every done step matches on the final rerun.** — `projects/agent-kit/assets/hooks/git-guard-delivery-rerun.sh:rt_delivery_rerun` — the fact `steps_remeasured` of the opening; `projects/agent-kit/assets/checks/flow-step.mjs:runBeforePull` — the rerun over `projects/agent-kit/assets/checks/flow-step.mjs:doneSteps`; scenarios `SC-AK-1731`, `SC-AK-1732`
- **The refusal of the PR names every step that did not match, with its expected result and what it got.** — `projects/agent-kit/assets/checks/flow-step.mjs:runBeforePull` — a line per step; scenarios `SC-AK-1706`, `SC-AK-1707`, `SC-AK-1731`
- **The final rerun reads the plan and the progress from the history when the task folder is already taken apart.** — `projects/agent-kit/assets/checks/flow-step.mjs:runBeforePull` — the folder restored from the commit before the one that removed it; scenario `SC-AK-1733`
- **The final rerun runs on the node the tree pins in `.nvmrc` when that version is installed.** — `projects/agent-kit/assets/hooks/git-guard-delivery-rerun.sh:rt_delivery_rerun` — the bin of that version first in the PATH of the run; scenario `SC-AK-1740`
- **On the final rerun a check sees the progress as it stood before the first commit that marks its step done.** — `projects/agent-kit/assets/checks/flow-step.mjs:runBeforePull` — the versions of the progress in the history of the branch; scenario `SC-AK-1739`
- **The replacement lines of a step come to that progress from the last one.** — `projects/agent-kit/assets/checks/flow-step.mjs:withReplacements` — called by `runBeforePull`; scenario `SC-AK-1794`
- **A check that changes a tracked file does not match.** — `projects/agent-kit/assets/checks/flow-step.mjs:runBeforePull` — the tracked changes before and after each check; scenario `SC-AK-1724`
- **A check that fails on the network does not match, and the refusal names the network as the cause.** — `projects/agent-kit/assets/checks/flow-step.mjs:runBeforePull` — the cause named after the line of the step; scenario `SC-AK-1725`
- **A step past its limit of 540 seconds, or whose command does not run, does not match on the final rerun.** — `projects/agent-kit/assets/checks/flow-step.mjs:runCheck` — the limit `projects/agent-kit/assets/checks/flow-step.mjs:STEP_LIMIT_MS` and the code of a command that does not run; scenarios `SC-AK-1704`, `SC-AK-1705`
- **A step that does not match on the final rerun runs once more in its group while its longest first run still fits the budget of 1500 seconds, and loses its mark only on the second mismatch.** — `projects/agent-kit/assets/checks/flow-step.mjs:runBeforePull` — the second run of the groups, each with its progress written again; `projects/agent-kit/assets/checks/flow-step.mjs:RERUN_BUDGET_MS` — the budget; scenario `SC-AK-1825`
- **The line of an unmatched step names its command and the last three lines of its output, of its errors and of what a pipe fed its last command.** — `projects/agent-kit/assets/checks/flow-step.mjs:detailLines` — the lines under the step; `projects/agent-kit/assets/checks/flow-step.mjs:tapped` — `tee` before the last pipe; scenario `SC-AK-1826`
- **A step that does not match on a taken-apart folder gets the move `git revert` of the commit that took it apart.** — `projects/agent-kit/assets/checks/flow-step.mjs:runBeforePull` — the line after the steps; `projects/agent-kit/assets/checks/flow-step.mjs:runStepCommand` — the lines after one step; `projects/agent-kit/assets/checks/flow-step.mjs:revertMove` — the move; scenario `SC-AK-1833`
- **The refusal of the PR names the command of each unmatched step by its number.** — `projects/agent-kit/assets/hooks/git-guard-delivery-rerun.sh:rt_delivery_rerun` — the numbers read from the lines of the engine; scenario `SC-AK-1833`

## The approval

- **An edit of the description and the engine needs the owner's approving answer found at the place the approval mark names.** — `projects/agent-kit/assets/checks/flow-guard.mjs:judgeProtected` — the refusal; `projects/agent-kit/assets/task-flow/source/records.mjs:approvalFault` — the answer at its place; the place is written by `projects/agent-kit/assets/checks/flow-plan.mjs:runPlanRed`; scenario `SC-AK-1708`
- **An approval mark whose place holds no approving answer counts as no approval.** — `projects/agent-kit/assets/task-flow/source/records.mjs:approvalFault` — the entry at the place; `projects/agent-kit/assets/checks/flow-plan.mjs:approvingEntry` — the same test when the mark is written; scenario `SC-AK-1709`
- **The tree may name the plans that need no roles.** — `projects/agent-kit/assets/checks/flow-plan.mjs:rolesOfPlan` — the command of the tree and its answer; `projects/agent-kit/assets/checks/flow-plan.mjs:approvingEntry` — the moment of the plan commit where there are no roles to wait for; scenario `SC-AK-1950`
- **An approval given in any working copy of the repository holds in every other.** — `projects/agent-kit/assets/task-flow/source/records.mjs:openAt` — the record directories of the copies `git worktree list` names; scenario `SC-AK-1734`
- **A record outside the record directories gives no approval, the one `RT_FLOW_TRANSCRIPT` names included.** — `projects/agent-kit/assets/checks/flow-plan.mjs:runPlanRed` — the record of the answer; `projects/agent-kit/assets/task-flow/source/records.mjs:approvalFault` — the record of the mark; scenarios `SC-AK-1411`, `SC-AK-1720`
- **An approval holds only for the plan commit it names.** — `projects/agent-kit/assets/task-flow/source/records.mjs:approvalFault` — the commit of the mark against the oldest commit that added the plan; scenario `SC-AK-1721`
- **An approval mark that names no place counts as no approval outside `words.legacyBranches`.** — `projects/agent-kit/assets/task-flow/source/records.mjs:approvalFault` — the place; `projects/agent-kit/assets/checks/flow-guard.mjs:judgeProtected` — the closed list; scenario `SC-AK-1728`
- **`plan-red` on a plan whose approval mark names the same commit and fingerprint takes the red output from that mark.** — `projects/agent-kit/assets/checks/flow-plan.mjs:runPlanRed` — the red output of the mark in place of the runs; scenario `SC-AK-1738`
- **`plan-red` runs the checks on the tree of the plan commit.** — `projects/agent-kit/assets/checks/flow-plan.mjs:planTree` — in place or a detached worktree with `node_modules` linked, and its removal; `projects/agent-kit/assets/checks/flow-plan.mjs:runPlanRed` — the run there and the removal in `finally`; `projects/agent-kit/assets/checks/flow-step.mjs:runCheck` — the directory of the run; scenarios `SC-AK-1738`, `SC-AK-1749`, `SC-AK-1751`
- **A worktree that cannot be made is a refusal with its reason, and no check runs.** — `projects/agent-kit/assets/checks/flow-plan.mjs:planTree` — `StepRefused` with the reason; `projects/agent-kit/assets/checks/flow-plan.mjs:runPlanRed` — the refusal before any run; scenario `SC-AK-1750`
- **An answer that can no longer be found at its place is refused, and the refusal names the move: run `plan-red`, which finds the answer in the record; the owner is asked only when it finds none.** — `projects/agent-kit/assets/checks/flow-guard.mjs:judgeProtected` — the move after the reason; the text maps to the action `edit_flow_description` in `projects/agent-kit/assets/hooks/flow-step-guard.sh:verdict`; scenarios `SC-AK-1710`, `SC-AK-1721`, `SC-AK-1730`
- **Exit 5 confirms the approval at its place as the guard does, and does not read the answer from the mark.** — `projects/agent-kit/assets/task-flow/measure/plan.mjs:approved` — `approvalFault` of the source `records`; scenario `SC-AK-1718`
