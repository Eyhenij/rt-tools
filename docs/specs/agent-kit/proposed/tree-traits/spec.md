# Свойства дерева и ресурсы, которые их требуют

**Статус:** предложено · **Ревизия:** 2026-08-14 · **Префикс сценариев:** `SC-AK`
**Зависимости:** нет
**Законы:** `project-documentation`
**Процедуры:** нет

## Зачем

Пакет везёт правила для деревьев разного устройства. Часть из них верна только там, где есть
хранилище, админка или процедуры: наблюдаемость говорит про строки лога и номер обращения,
владеющая сущность захода — про запись, которой заход принадлежит. Дереву, которое публикует
библиотеки, эти правила не нужны ни одной статьёй.

Сегодня они всё равно кладутся. Раскладка проходит молча, а расхождение всплывает потом и в
другом месте: сверка отказывает на пустом компаньоне, и выясняется это перебором. Заполнить
компаньон нечем — статей двадцать восемь и одиннадцать, и ни одной из них здесь не отвечает ни
файл, ни символ. Отказ при этом говорит «остался черновиком», то есть предлагает заполнить, — а
верное действие противоположное: снять ресурс вовсе.

Ось видов эту разницу не описывает. Она отвечает на вопрос «какой из трёх», и невыбранная ось
значит «дерево промолчало». Здесь вопрос другой: чего у дерева нет вовсе, и таких вещей у одного
дерева сразу несколько. Дерево, которое публикует пакеты и держит приложение, одним значением не
описывается — а назвавшись неточно, оно теряет либо правила приложения, либо правила поставки
пакетов.

Договорённость называет, чем дерево описывает себя, чем ресурс называет нужное ему, и что
происходит, когда одно другому не отвечает.

## Терминология

| Термин                  | Что это                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| Свойство дерева         | то, что у дерева есть и без чего часть правил бессмысленна: хранилище, админка, публикуемые пакеты, приложение |
| Набор свойств           | все свойства одного дерева, объявленные его настройкой; пусто — дерево о себе ничего не сказало                |
| Требуемое свойство      | свойство, без которого ресурс дереву не нужен; ресурс называет его в своём имени                               |
| Неотвеченное требование | требуемое свойство, которого в наборе свойств дерева нет                                                       |
| Свойство пакета         | свойство, объявленное пакетом перечнем: только объявленное можно требовать и называть своим                    |

### Как это называется в интерфейсе

Интерфейса у пакета нет, кроме строки запуска. Набор свойств дерево пишет в свою настройку,
требуемое свойство стоит в имени файла ресурса, а перечень свойств пакета лежит рядом с
перечнем осей.

| В договорённости    | В настройке и в строке запуска                             |
| ------------------- | ---------------------------------------------------------- |
| набор свойств       | ключ `has` в настройке дерева                              |
| требуемое свойство  | часть имени файла ресурса: `observability.needs-db.md`     |
| свойство пакета     | запись в перечне свойств рядом с перечнем осей различия    |
| неположенный ресурс | строка перечня раскладки: «требует свойства, которого нет» |

## Правила

- **Ресурс с неотвеченным требованием дереву не кладётся.** Не кладётся ни он сам, ни черновик
  его компаньона: файл, который нечем заполнить, хуже отсутствующего — он выглядит долгом
  дерева, а долгом не является.
- **Молчание дерева о себе требованию не отвечает.** Дерево с пустым набором свойств не получает
  ни одного помеченного ресурса. Класть наугад дороже: пустой компаньон возвращает ровно ту
  работу, ради которой договорённость и написана.
- **Отбор поимённо сильнее требования.** Ресурс, названный деревом поимённо, кладётся и тогда,
  когда его требование не отвечено: выбор словом сильнее вывода по признаку. Раскладка при этом
  называет неотвеченное требование вслух — молчаливое исключение через месяц читается как
  правило.
- **Отказ по компаньону называет требование, а не только состояние файла.** Пустой компаньон
  ресурса, требующего свойства, которого у дерева нет, — не черновик, а лишний файл: отказ
  говорит требуемое свойство и то, что ресурс снимается строкой отказа.
- **Требовать можно только объявленное свойство.** Ресурс, требующий свойства, которого пакет не
  объявлял, — опечатка в имени файла, и раскладка называет её. Иначе такой ресурс не кладётся
  никуда и никогда, а причину в имени не разглядеть.
- **Своим можно назвать только объявленное свойство.** Свойство в настройке дерева, которого нет
  в перечне пакета, — та же опечатка, и отказ у неё тот же.
- **Требование стоит в имени файла рядом с видом и от него отличимо.** Вид отвечает на «какой из
  трёх», требование — на «есть ли»; читаются они по разным перечням, и перепутать их пакет не
  может.
- **Перечень ресурсов называет неположенное требованием отдельно от снятого деревом.** «В этом
  дереве такого не существует» и «дерево от этого отказалось» — разные состояния, и разбирает их
  тот, кто читает перечень.

## Что не входит

- **Счёт статей без адреса в компаньонах.** Сделан отдельной работой и здесь не трогается.
- **Разбор того, какие правила пакета помечать требованием.** Договорённость называет механизм;
  этой работой помечаются два правила — наблюдаемость и владеющая сущность захода, — с которых
  всё началось.
- **Свойства, выводимые из дерева самим пакетом.** Набор свойств пишет дерево, и проверять его
  по содержимому дерева пакет не берётся: приложение без админки и приложение с админкой снаружи
  неразличимы.

## Открытые вопросы

- **Q-TT-1.** Перечень свойств пакета заводится минимальным — хранилище, админка, публикуемые
  пакеты, приложение. Чем он дополняется, решает первый ресурс, которому нечего потребовать из
  объявленного.
