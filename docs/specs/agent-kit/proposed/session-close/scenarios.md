# Сценарии — закрытие захода командой

Префикс `SC-AK`. Номера продолжают нумерацию спека домена и после вливания не меняются: на них
ссылаются заголовки тестов.

### SC-AK-59 — незакоммиченная правка останавливает закрытие захода

Дано в рабочем дереве есть незакоммиченная правка
Когда исполнитель зовёт закрытие захода
Тогда ни одна ветка не снимается, дерево остаётся на текущей ветке, а исполнителю называются
незакоммиченные файлы

Не покрыто: команду исполняет агент, и прогоном она не проверяется — проверка идёт вызовом в
дереве.

### SC-AK-60 — работа по правилу с влитым отчётом возвращает дерево на главную ветку

Дано работа ведётся в ветке под номером задачи, её отчёт влит, рабочее дерево чистое
Когда исполнитель зовёт закрытие захода
Тогда дерево переходит на главную ветку и подтягивает её из удалённого

Не покрыто: команду исполняет агент, и прогоном она не проверяется — проверка идёт вызовом в
дереве.

### SC-AK-61 — работа вне правила оставляет дерево в своей ветке

Дано работа идёт в ветке, за которой задачи нет, рабочее дерево чистое
Когда исполнитель зовёт закрытие захода
Тогда главная ветка вливается в текущую, а дерево остаётся на ней

Не покрыто: команду исполняет агент, и прогоном она не проверяется — проверка идёт вызовом в
дереве.

### SC-AK-62 — снимаются влитые ветки, невлитая остаётся названной

Дано среди локальных веток есть влитая в главную и есть ветка с коммитами, которых в главной нет
Когда исполнитель зовёт закрытие захода
Тогда влитая снимается, невлитая остаётся, и её имя вместе с числом несвёденных коммитов
называется исполнителю

Не покрыто: команду исполняет агент, и прогоном она не проверяется — проверка идёт вызовом в
дереве.

### SC-AK-63 — мёртвые отслеживания снимаются тем же вызовом

Дано в дереве есть ссылка на удалённую ветку, которой в удалённом больше нет
Когда исполнитель зовёт закрытие захода
Тогда ссылка снимается вместе с остальной уборкой

Не покрыто: команду исполняет агент, и прогоном она не проверяется — проверка идёт вызовом в
дереве.

### SC-AK-64 — передача пишется последней и лежит вне дерева

Дано закрытие захода дошло до записи передачи
Когда команда её пишет
Тогда файл ложится в каталог передачи из профиля дерева, одним файлом на ветку, в историю не
попадает, а путь к нему называется исполнителю последней строкой

Не покрыто: команду исполняет агент, и прогоном она не проверяется — проверка идёт вызовом в
дереве.

### SC-AK-65 — сценарий с однозначным номером виден сверке

Дано в спеке домена стоит сценарий с номером из одной цифры
Когда идёт сверка спеков
Тогда сценарий попадает в разбор наравне с двузначными: без теста он назван непокрытым, а не
пропущен молча

### SC-AK-66 — ссылка на однозначный номер засчитывается покрытием

Дано заголовок теста начинается идентификатором сценария с номером из одной цифры
Когда идёт сверка спеков
Тогда сценарий считается покрытым, а идентификатор — известным сверке

### SC-AK-67 — счёт шагов работы сплошной через все паттерны

Дано шаги работы описаны паттернами начала, продолжения и закрытия работы
Когда номера шагов читаются подряд по всем трём
Тогда каждый номер встречается один раз, а полный их список стоит в правиле ведения работы

### SC-AK-68 — правилу об оформлении документов есть куда вписать скилы дерева

Дано дерево ведёт свои скилы о документах
Когда оно дописывает их надстройкой
Тогда в правиле есть раздел под них, и надстройка ложится в него, не замещая раздела ловушек

### SC-AK-69 — жизнь номера сценария описана правилом

Дано сценарий добавляют, меняют или удаляют
Когда исполнитель ищет, что делать с его номером
Тогда правило о документации проекта отвечает на все три случая, а не только на конфликт мержа

Не покрыто: судится чтением — что написано в тексте правила, машине не видно.
