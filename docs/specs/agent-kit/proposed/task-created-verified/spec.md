# Подтверждение заведённой задачи

**Статус:** предложено · **Ревизия:** 2026-08-14 · **Префикс сценариев:** `SC-AK`
**Зависимости:** нет
**Законы:** `work-conduct`, `delivery`
**Процедуры:** нет

## Зачем

Команда заведения делает четыре шага — задача, номер в её заголовке, добавление в очередь работ,
начальная колонка — и печатает номер со ссылкой. Этот вывод говорит о вызовах команды, а читается
как состояние очереди. Разница между ними стоила захода: шестнадцать задач были заведены подряд,
каждая напечатала номер, и ни одна не попала в очередь так, чтобы её увидел владелец.

Команда сама знает этот исход: её разбор ошибок называет случай «задача есть, а в очереди её нет»
и печатает про него отдельную строку. Но ловится он только тогда, когда вызов отказал вслух;
молчаливое расхождение — учётная запись ограничена, добавление прошло, а заведённое видно только
ей самой — выглядит ровно как успех.

Договорённость закрывает разрыв тем, что вывод команды перестаёт быть словом о самой себе: после
четвёртого шага она спрашивает очередь работ о заведённой задаче и печатает её ответ.

## Терминология

| Термин             | Что это                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------ |
| Ответ очереди      | состояние задачи, прочитанное у очереди работ по номеру: присутствие, колонка, исполнитель |
| Подтверждение      | ответ очереди, в котором задача присутствует; вывод команды подтверждением не бывает       |
| Молчаливый разброс | заведение прошло без единого отказа, а задачи в очереди нет                                |

### Как это называется в интерфейсе

Интерфейса у команды нет — она печатает в поток вывода. Строки: `в очереди работ: колонка
«Backlog», исполнитель <имя>` и `в очереди работ: НЕТ`.

## Правила

- **Заведение кончается ответом очереди работ, а не выводом команды.** После четвёртого шага
  команда спрашивает очередь по номеру и печатает прочитанное; напечатанный номер значит «вызов
  прошёл», а не «задача видна тому, кто по ней работает».
- **Задача, которой нет в очереди, кончает команду ненулевым кодом.** Работой она не обеспечена:
  по ней никто не придёт, и молчание тут дороже отказа.
- **Отсутствие исполнителя называется отдельной строкой.** Задача без исполнителя стоит в очереди
  ничьей, и видно это только тому, кто откроет её карточку.
- **Отсутствие связи подтверждением не является.** Не спросив очередь, команда не говорит о ней
  ничего: она называет, что спросить не удалось, и кончается ненулевым кодом.
- **Ответ очереди складывается в строки чистой функцией.** Решение о том, что напечатать и чем
  кончиться, отделено от вызовов сети: иначе оно проверяется только живой очередью работ.

## Что не входит

- Сокрытие машинной учётной записи хостингом. Ограничение приходит снаружи, и порядок работы,
  пока оно стоит, описывает компаньон правила поставки — задача #559.
- Сплошная сверка очереди работ: её слепые пятна разбираются задачей #540. Здесь спрашивается одна
  задача — та, которую только что завели.
- Серия заведений подряд. Проверять её по последней задаче нельзя, и паттерн отчёта называет для
  неё сверку очереди целиком — текстом, а не проверкой.

## Контракт

Команда заведения — `checks/task-new.<хостинг>.mjs`, дерево зовёт её как `task:new`.

| Что                        | Как                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------- |
| вход                       | `--title`, `--label`, `--assignee`, `--slug`, тело задачи со стандартного ввода       |
| выход при подтверждении    | номер, ссылка, строка ответа очереди, подсказки о ветке и колонке; код 0              |
| выход без задачи в очереди | те же строки, строка об отсутствии и что делать; код 1                                |
| источник ответа            | состояние задачи у модуля борды: присутствие, колонка, исполнитель, номер в заголовке |

### Коды отказов

| Код | Когда                                                                        |
| --- | ---------------------------------------------------------------------------- |
| 0   | задача заведена и присутствует в очереди работ                               |
| 1   | задача не заведена вовсе; заведена, но в очереди её нет; очередь не спрошена |

## Решения

- **Спрашивается одна задача, а не вся очередь.** Сплошная сверка есть отдельно и стоит дороже;
  здесь нужен ответ о той задаче, которую только что завели, и он приходит одним вызовом.
- **Ненулевой код вместо предупреждения.** Напечатанное предупреждение исполнитель читает как
  разрешение — это уже проверено на гейте пуша, где статья о непрогнанной сборке стояла в
  чеклисте и была прочитана.
- **Строки складывает чистая функция.** Ответ очереди приходит из сети, а решение о выводе и коде
  — нет; так оно закрывается сценариями без живой очереди.

## Открытые вопросы

- Q-1 — печатать ли ответ очереди при каждом заведении или только при расхождении. Взято первое:
  вывод одной задачи короток, а молчание в успешном случае снова делает подтверждение невидимым.
