# Полнота набора гейта пуша

**Статус:** предложено · **Ревизия:** 2026-08-14 · **Префикс сценариев:** `SC-AK`
**Зависимости:** нет
**Законы:** `verifiability`, `delivery`
**Процедуры:** нет

## Зачем

Гейт пуша — обещание, что пуш не приедет красным. Пока его набор уже набора конвейера, обещание
шире того, что гейт проверяет, и неверно оно молча: ни гейт, ни его вывод не говорят, чего в нём
нет. Дважды подряд правка, прошедшая гейт целиком, была отбита конвейером; оба раза зелёный гейт
был прочитан как «локально всё зелено», и отчёт ушёл со словом «проверено».

Договорённость закрывает разрыв не текстом, а отказом: расхождение между набором гейта и файлом
конвейера отбивает пуш. Напечатанное предупреждение исполнитель читает как разрешение — это
проверено на том же дереве: статья о том, что гейт сборки не гоняет, стояла в чеклисте и была
прочитана.

## Терминология

| Термин             | Что это                                                                                                  |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| Набор гейта        | строки, которые печатает `rt_push_checks` профиля дерева; гард гоняет их перед пушем                     |
| Файл конвейера     | описание прогона на стороне хостинга; у каждого вида хостинга своё имя, и дерево называет его настройкой |
| Объявленный список | соответствие «шаг конвейера → строка набора гейта», которое дерево пишет в своей настройке               |
| Исключение         | шаг конвейера, объявленный не входящим в гейт, вместе с причиной                                         |

### Как это называется в интерфейсе

Не применимо: у пакета нет экранов. Отказ гарда читает исполнитель, и его текст назван в разделе
«Коды отказов».

## Правила

- **Набор гейта пуша не бывает уже набора конвейера.** Шаг конвейера, которому в наборе гейта
  нет ни строки, ни объявленного исключения, отбивает пуш. Гейт, обещающий больше, чем
  проверяет, хуже отсутствующего: отсутствующий не читается как подтверждение.
- **Полнота держится объявленным списком, а не разбором файла конвейера.** Шаги там произвольны,
  и часть их локально неисполнима — кэш, выгрузка следов, вход в реестр. Дерево объявляет, чем
  каждый шаг закрывается в гейте, и необъявленный шаг краснеет: дыра видна на месте, а не
  выводится сверкой двух списков глазами.
- **Исключение объявляется с причиной и рядом с набором.** Причина — единственное, чем
  постоянная дыра отличается от забытой строки; пустая причина исключением не считается.
- **Дерево без файла конвейера сверку не получает.** Проверка, падающая там, где конвейера нет,
  отбивала бы работу вместо промаха. Это тот же отказ в пользу работы, что у остальных гардов.
- **Проверка полноты сама стоит в наборе гейта.** Проверка, которую надо помнить, до второго
  месяца не доживает; заведённая проверка встаёт туда, где её зовут без человека.

## Что не входит

- **Разбор файла конвейера машиной.** Отвергнуто решением владельца: три вида хостинга дали бы
  три разбора чужого формата, а половина шагов локально не исполняется вовсе.
- **Совпадение команд шаг в шаг.** Сверяется покрытие, а не текст: конвейер зовёт цель прогонщика
  со своими ключами, гейт — свою.
- **Снимки витрин в гейте этого дерева.** Пока кадры ждут отсчётом времени, они плавают под
  нагрузкой и отбивали бы пуш без вины правки. Объявлены исключением; исключение снимается
  задачей RT-427.
- **Свежесть самого файла конвейера.** Правка конвейера проверяется своим прогоном — это уже
  сказано в правиле поставки.

## Контракт

Проверка полноты — файл в каталоге проверок пакета. Читает настройку дерева и файл конвейера,
печатает расхождения, отдаёт ненулевой код при непустом списке.

| Вход                   | Откуда                                                      |
| ---------------------- | ----------------------------------------------------------- |
| путь к файлу конвейера | настройка проверок дерева                                   |
| объявленный список     | настройка проверок дерева: шаг → строка набора либо причина |
| набор гейта            | `rt_push_checks` профиля дерева                             |

### Коды отказов

| Что случилось                                          | Что печатается                                                         |
| ------------------------------------------------------ | ---------------------------------------------------------------------- |
| шаг конвейера не объявлен ни строкой, ни исключением   | имя шага и подсказка: закрыть строкой набора либо объявить исключением |
| исключение объявлено без причины                       | имя шага и требование причины                                          |
| объявленная строка набора в наборе гейта не печатается | имя шага и строка, которой в наборе нет                                |
| файла конвейера нет                                    | ничего: проверка молчит и отдаёт нулевой код                           |

## Решения

- **Отбивать, а не печатать.** Первая запись предложений просила печатать расхождение вслух,
  вторая — после второго красного конвейера — отбивать. Взята вторая: напечатанное
  предупреждение читается как разрешение.
- **Список объявляет дерево, а не пакет.** Пакет не знает ни имён шагов, ни того, чем они
  закрываются: у каждого дерева свой конвейер и свои цели прогонщика.
- **Проверка молчит там, где конвейера нет.** Иначе первое же дерево без него получает красную
  проверку на пустом месте и снимает её из набора целиком.

## Открытые вопросы

- **Q-1. Где живёт объявленный список — в настройке проверок или отдельной функцией профиля.**
  Настройка читается проверкой напрямую, функция профиля — оболочкой; выбор делается на первом
  прогоне и записывается сюда же.
