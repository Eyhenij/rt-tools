# Признаки единообразия объявляются деревом, а не зашиты в проверку

**Статус:** предложено · **Ревизия:** 2026-08-14 · **Префикс сценариев:** `SC-AK`
**Зависимости:** нет
**Законы:** `reuse-first`, `verifiability`, `project-documentation`
**Процедуры:** нет

## Зачем

Сплошная проверка единообразия держит признаки списком в своём коде, и в этом списке стоят имена
классов и компонентов конкретного приложения. Пакет ставится в разные деревья: там таких имён нет
и не будет, поэтому правильно собранный компонент числится расхождением. Починить это в
дереве-потребителе нечем — класса с ожидаемым именем у него не существует.

Гард той же темы устроен иначе: имён он не знает вовсе и печатает то, что вернула функция профиля
дерева. Своё утверждение «признаки те же, что у гарда, и берутся оттуда же» проверка сегодня не
исполняет.

Вторая половина зачем — набор признаков не бывает общим. Дерево берёт из rt-tools то, что ему
нужно: одно — только утилиты, другое — оба кита и хранилище. Признак, называющий готовое из
пакета, которого в дереве нет, отвечает ложно ровно так же, как имя чужого приложения.

## Терминология

- **Признак** — правило вида «в тексте есть такое-то, значит готовое обошли», вместе с тем, чем
  его заменить.
- **Набор признаков** — признаки одного пакета rt-tools, объявленные одним файлом: что этот пакет
  везёт и чем в нём пользуются вместо своего.
- **Объявленный набор** — набор, который дерево назвало своим в настройке проверок.
- **Свои признаки** — признаки самого дерева-потребителя, объявленные им у себя и приезжающие
  поверх объявленных наборов.
- **Область признака** — что признак читает: только новый текст правки или файл целиком.
- **Отмена признака** — образец, при котором признак не срабатывает: основа уже унаследована,
  готовое уже позвано.

### Как это называется в интерфейсе

| В договорённости  | В настройке и в строке запуска            |
| ----------------- | ----------------------------------------- |
| объявленный набор | ключ `reuse.bundles` в настройке проверок |
| свои признаки     | файл, названный ключом `reuse.signals`    |
| сплошная проверка | команда сверки единообразия               |
| гард на правке    | гард единообразия, событие правки файла   |

## Правила

- **Признак живёт данными, а не кодом проверки.** Проверка и гард читают одни и те же объявленные
  файлы: расхождение между ними становится невозможным по устройству, а не по внимательности.
- **Набор признаков режется по пакетам rt-tools.** У каждого пакета свой файл, и в нём только то,
  что везёт он сам: имена его компонентов, его основ и его директив.
- **Дерево получает признаки тех пакетов, которые назвало.** Не названный набор не читается вовсе:
  признак о готовом из пакета, которого в дереве нет, отвечает ложно.
- **Пакет называет только свои имена.** Имя класса или компонента, принадлежащего
  дереву-потребителю, в ресурсах пакета не стоит: его объявляет само дерево своими признаками.
- **Своё дерево дописывает признаки, а не правит чужие.** Свои признаки приезжают поверх
  объявленных наборов; совпавший ключ замещает пакетный, новый дописывается.
- **Признак называет свою область.** Наследование основы и метка класса в точечную правку не
  попадают, и признак, судящий их по добавленному тексту, молчит всегда.
- **Пустое поле признака не съезжает в соседнее.** Признак с пустой отменой читается так же, как
  признак без неё: разбор, теряющий пустое поле, превращает совет в образец и гасит гард целиком.
- **Гард, не получивший ни одного признака, говорит об этом.** Молчаливый гард неотличим от
  гарда, которому нечего отбивать; дерево без объявленных наборов узнаёт об этом при первой правке.

## Что не входит

- Признаки, не называющие ничьих имён: сырой тег таблицы, шаблон внутри декоратора, тысячный
  порядок наложения. Они верны любому дереву и остаются при проверке.
- Проверка того, что дерево объявило наборы верно: назвало кит, которого не ставит, — его дело.
- Отказ гарда за ненайденный файл своих признаков: пропуск дешевле остановки работы.
- Перенос накопленного долга: снимок расхождений дерева перечитывается той же работой, но
  правилом продукта это не является.
- Сплошная сверка предметных имён по всем ресурсам пакета: здесь чинится один ресурс.

## Контракт

Сетевого контракта нет. Поверхность — настройка проверок дерева и два читателя признаков.

| Вход               | Откуда                                                           |
| ------------------ | ---------------------------------------------------------------- |
| объявленные наборы | ключ `reuse.bundles` в настройке проверок дерева                 |
| свои признаки      | файл, названный ключом `reuse.signals`                           |
| признаки пакета    | файлы наборов при пакете, по одному на пакет rt-tools            |
| текст под проверку | добавленный текст правки у гарда, файл целиком у сплошной сверки |

### Коды отказов

| Что случилось                             | Код | Что говорит                                      |
| ----------------------------------------- | --- | ------------------------------------------------ |
| дерево не объявило ни одного набора       | `0` | что признаков нет и каким ключом они объявляются |
| названный набор при пакете не найден      | `1` | имя набора и то, какие наборы есть               |
| файл своих признаков назван, но не найден | `0` | что своих признаков нет, и работа идёт дальше    |
| в тексте найден признак                   | `1` | ключ признака, файл и чем это заменить           |

### Мультиобъектность

Наборы читаются от того дерева, из которого позвали: файлы одни, а объявлено в каждом дереве своё.

## Решения

- **Признаки данными, а не кодом.** Гард написан на оболочке, проверка — на JS; общего кода между
  ними быть не может, а общие данные — могут. Отвергнуто: держать признаки в функции профиля
  дерева — тогда сплошной проверке пришлось бы звать оболочку на каждый файл.
- **Резать по пакетам rt-tools, а не по родам файлов.** Дерево выбирает пакеты, а не рода: оно
  знает, ставит ли кит, и не знает, какие рода файлов при этом задеты.
- **Функция профиля остаётся у гарда.** Деревья её уже написали; она читается вместе с
  объявленными наборами и ничего не отменяет.

## Открытые вопросы

- `Q-18` — сверять ли объявленные наборы с зависимостями дерева. Сейчас нет: дерево называет их
  само, и назвать кит, которого оно не ставит, ему никто не мешает.
- `Q-20` — чем подтверждается, что имя в наборе принадлежит пакету, а не дереву-потребителю.
  Признак читает человек: машине его не дать, ровно как и признак приёма в законе.
- `Q-19` — что делать с накопленным долгом при смене наборов. Сейчас снимок перечитывается руками
  той же работой, которая набор поменяла.
