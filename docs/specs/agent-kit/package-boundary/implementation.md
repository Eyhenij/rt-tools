# Where this is carried out — the boundary of the rules package

The key of the link is the text of the rule itself. The places are named as they became: the work
ended, and every rule points at a live symbol.

## The rules and their places

- **The package carries to a consumer only what the consumer carries out.** — `tools/check-boundary.mjs:CARRIED` — what is judged is the resources and the code the layout carries
- **The sign "not for carrying" is not an appraisal but two questions to the resource.** — `tools/check-boundary.mjs:MARKS` — the samples of both questions and the reason of the refusal at each
- **A resource not for carrying lives as a resource of the tree's own, it is not cancelled by the list.** — `tools/check-boundary.mjs:ROOT` — what is judged is the composition of the package, and the list of the cancelled is not read at all
- **The sending side stays in the package whole.** — Not carried out by a machine: it is held by the composition of the resources, which the check does not touch
- **A resource that has not moved yet stands in the list of the debt and is named with the address of its move.** — `tools/check-boundary.mjs:DEBT` — the list is read if it lies next to it; an empty one is removed from the tree
- **The boundary is held by a check, not by reading.** — `.claude/rt-kit/project.sh:rt_push_checks` — the check stands in the suite of the push gate on a par with the rest
- **A rule of the tree's own is declared on a par with a package one.** — `.claude/rt-kit/gate-map.sh:skill_for` — its own branch demands the rule of the tree at an edit of its subject
- **A law describing the subject of an application, not of a class of applications, is never a package resource.** — **Not checked by a machine.** The sign demands an understanding of the text: the boundary check judges the mention of the intake and of the package tree, not the subjectness of a law. - **A package edition laid out over a rich local one turns out to be neither.** — **Not checked by a machine.** The layout compares the header and the body, and it measures the richness of an edition by nothing
- **A rule is removed together with the law it stands under.** — `projects/agent-kit/src/lib/cascade.ts:cascadeCuts` — a refusal of a law carries away the rules and the patterns at it; the removal from the package is done by the same composition by hand
- **A removed resource, alive in the package tree, stays a resource of the tree's own.** — `.claude/rt-kit/gate-map.sh:permissions` — the access rule is called at the guard of the receiver and at the guard of the admin panel route; it no longer has the layout header

## What here is the tree's own

The boundary check is a check of this tree's own, not a package resource: a foreign tree has nothing
to judge the resources of the package by. It lives in the same place as the rest of the tree's own
checks and is called the same way.

There is no list of the debt on disk now: it emptied when the last resource moved, and was removed
together with the epic. The check still holds the reading of it — created anew, it will start
holding the known silently again.

The rules of the tree's own are created after the sample of the package ones: they have the same
shape, a companion next to them and their own branch in the gate map. By the end of the epic the
tree's own became the rule of taking the cargo apart with the pattern at it, both commands of the
package tree and the memo about editing the source.
