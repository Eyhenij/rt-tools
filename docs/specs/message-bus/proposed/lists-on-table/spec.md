# Списки говорят одним языком разметки

**Статус:** предложено · **Ревизия:** 2026-08-17 · **Префикс сценариев:** `SC-MB`
**Зависимости:** поддомен «чтение принятого»
**Законы:** `lists`, `reuse-first`, `frontend-application`
**Процедуры:** нет — правка идёт по стороне показа

Договорённость задачи RT-781, задача 2 эпика RT-779. Вливается в спек поддомена
`docs/specs/message-bus/admin/` последним коммитом её PR.

## Зачем

Четыре раздела админки показывают список одним и тем же приёмом, но пишут его по-разному:
таблица объявлена атрибутом на голой разметке, признак проверки записан у каждого элемента
строкой, а пустой список говорит человеку одной серой фразой внутри таблицы — там же, где он
ждёт записей.

Человеку это стоит двух вещей. Пустой раздел неотличим от раздела, который не догрузился: и то
и другое — пустая таблица с фразой в середине. А работа, правящая показ, стоит вчетверо дороже
своей цены: приём, записанный четырьмя разными способами, читают в четырёх местах прежде, чем
поправят в одном.

## Терминология

Словарь домена целиком — в спеке домена. Здесь только то, что заводит эта договорённость:

| Термин           | Что это                                                                                        |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| Пустое состояние | Вид раздела, у которого записей нет: значок, заголовок и слово о том, откуда записи берутся    |
| Признак проверки | Значение `qa-dataid`; собирается из префикса раздела, а не пишется строкой у каждого элемента  |
| Язык разметки    | Форма, которой экран объявляет готовый компонент: элемент кита, а не атрибут на своей разметке |

### Как это называется в интерфейсе

| В договорённости | На экране                                                        |
| ---------------- | ---------------------------------------------------------------- |
| Пустое состояние | Значок, строка «Записей нет» и строка о том, откуда они приходят |
| Отбор раздела    | Выпадашка в левой части тулбара над таблицей                     |

## Правила

**Список.**

- **Таблицу раздел объявляет элементом кита, а не атрибутом на своей разметке.** Атрибут на
  `<table>` оставляет разделу собственную разметку, которую кит не видит: расхождение вида между
  разделами тогда лечится в разделе, а не в ките, и лечится столько раз, сколько разделов.
- **Признаки проверки на странице раздела собраны из его префикса.** Записанные строкой у
  каждого элемента, они расходятся с префиксом молча, и спека, открывшая не тот раздел, находит
  тот же признак и проходит зелёной.
- **Пустой список показывает пустое состояние, а не фразу внутри таблицы.** Пустой раздел и
  раздел, который не догрузился, иначе выглядят одинаково — таблицей без строк.
- **Пустое состояние называет, откуда записи приходят.** «Записей нет» отвечает на вопрос
  «сломано ли», но не на вопрос «что мне сделать»; у раздела груза записи приносит дерево, у
  раздела приглашений — команда владельца.
- **Свой отбор раздел кладёт в слот тулбара общей страницы.** Вход страницы под каждый вид
  отбора растёт числом с каждым новым разделом, а слот у неё один и тот же.
- **Раздел без своего отбора слота не занимает.** Пустая половина тулбара читается поломкой
  разметки, а не свободным местом.

## Что не входит

- Столбцы, их состав и порядок: этого правка не касается.
- Панель подробностей и её разметка — задача 3 эпика.
- Эталонные снимки экранов — задача 5 эпика.
- Многоязычие подписей: словарь приложения требованию спека домена отвечает.

## Контракт

Процедур эта договорённость не заводит и не меняет: правка идёт по стороне показа, запросы к
приёмнику остаются теми же.

### Коды отказов

Своих кодов отказа нет. Отказ чтения списка подаётся тостом, как и прежде.

## Данные

Своих данных договорённость не заводит. Строка списка приходит той же короткой моделью, что и
сейчас.

## Экраны и состояния

| Экран                | Состояние         | Что видно                                                          |
| -------------------- | ----------------- | ------------------------------------------------------------------ |
| Любой список         | Записи есть       | Таблица со строками, тулбар над ней, переключатель страниц под ней |
| Любой список         | Записей нет       | Пустое состояние вместо строк: значок, заголовок, откуда записи    |
| Любой список         | Чтение идёт       | Скелетоны таблицы; пустого состояния при этом нет                  |
| Любой список         | Чтение отказало   | Тост отказа; таблица остаётся в прежнем состоянии                  |
| Сводки, приглашения  | Свой отбор есть   | Выпадашка в левой части тулбара                                    |
| Предложения, разборы | Своего отбора нет | Левая часть тулбара не занята вовсе                                |

## Сквозные требования

### Локали

Язык здесь один: подписи берутся из словаря приложения. Пустое состояние берёт свои две строки
оттуда же.

### SEO

Не применимо: админка закрыта входом и наружу не показывается.

### Мобильная раскладка

Карточки на узком экране даёт сам компонент таблицы кита — раздел их не пишет. Пустое состояние
на узком экране показывается тем же видом.

### Мультиобъектность

Не применимо: приёмник один, разделы читают его же груз.

## Решения

- **Экран приглашений входит в эту работу наравне с тремя названными.** Решение владельца при
  разборе: он собран тем же приёмом, а заведён после того, как эпик был расписан. Оставленный в
  стороне, он через задачу читается как принятый приём.
- **Паттерн дерева о списочном экране правится той же работой.** Решение владельца при разборе:
  готовый код паттерна пишет таблицу атрибутом, и следующий раздел собрали бы по нему. Правка
  экранов без правки паттерна вернула бы прежний язык первым же новым разделом.
