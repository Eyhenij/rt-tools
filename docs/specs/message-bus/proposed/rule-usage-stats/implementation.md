# The binding — usage of the rules in the sessions of the trees, the receiving side

There is no code yet: the lines name the place foreseen for every rule, and the addresses are filled
in by the work and checked by the spec audit at the merge. The paths are from the root of the tree;
the ones that do not exist yet are named without the file extension, so the address check does not
read them as a dead link.

| Rule                                                                                                                                                     | Where it is foreseen                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The observation cargo is taken in by an operation of its own, by the tree token.                                                                         | the intake of the lines, a controller `observations-intake` in `libs/message-bus-api/observations/feature/` under the tree operation decorator                             |
| A line lands as a row of its own, as it arrived.                                                                                                         | the writing of the day, `observation.queries` in `libs/message-bus-api/observations/data-access/` — a row per line                                                         |
| A day of one working copy is replaced whole.                                                                                                             | the same writing — delete by "tree — origin — day" and insert in one transaction                                                                                           |
| A day of another working copy of the same tree is not touched.                                                                                           | the same writing — the key of the delete carries the origin                                                                                                                |
| A line of an unknown event kind or without a session sign refuses the cargo whole.                                                                       | the check of the form of the cargo, `observation.const` in `libs/message-bus-api/observations/util/` next to the fields of the digest                                      |
| A field of a line longer than its cap refuses the cargo, it is not trimmed.                                                                              | the same check — the caps per field                                                                                                                                        |
| A cargo with more lines than the cap is refused without a row.                                                                                           | the same check — the line cap, its number in a setting of the intake next to `apps/message-bus/src/app/cargo-limit.ts`                                                     |
| A row is kept a year from the day of the line, and older rows are removed by the cleaning of the intake every night.                                     | a service of the keeping term, `observation-retention` in `libs/message-bus-api/observations/feature/` — the nightly schedule and the journal line                         |
| The digest of a month stays as it was.                                                                                                                   | `libs/message-bus-api/observations/feature/src/lib/summary-intake.controller.ts` — untouched                                                                               |
| The usage is counted by the storage, not by the rows in memory.                                                                                          | the reading, `usage.queries` in `libs/message-bus-api/observations/data-access/` — a grouped query of the storage                                                          |
| The usage of a skill counts three numbers: the loads, the sessions with a load, the refusals of the gate.                                                | the same query — the count, the distinct session signs and the count of the gate rows                                                                                      |
| The rows go in descending order of loads, and at equal loads by name.                                                                                    | the same query — its order                                                                                                                                                 |
| The period is at most four hundred days, and a longer one is refused.                                                                                    | the check of the period, `usage-period` in `libs/message-bus-api/observations/util/` — pure, checked by a call                                                             |
| The sessions of a skill are read by a request of their own: the day, the session sign and how many times the session loaded the skill, newest day first. | the second query of `usage.queries` and the second operation of the controller `usage-read`                                                                                |
| The reading is closed by the right `usage:read`.                                                                                                         | `libs/message-bus-common/src/lib/rights.ts:TRight` — the right added to the closed set; the controller names it                                                            |
| An empty period answers with an empty list, not a refusal.                                                                                               | the controller `usage-read` — an empty answer of the query goes as it is                                                                                                   |
| The section is a list page of the admin application, on the common base.                                                                                 | a list component of the section `usage` in the admin feature lib of the section, inheriting `libs/message-bus-admin/common/core/feature/src/lib/admin-list-screen.base.ts` |
| The filters are the tree and the period, and a change of either re-reads the table.                                                                      | the store of the section in its data-access lib — the filters are its state, the reading follows them                                                                      |
| A row of the table shows the skill, its kind, the loads, the sessions and the refusals.                                                                  | the columns of the section in its util lib and the mapper of the kind to the word of the dictionary                                                                        |
| A row opens the panel of the sessions of its skill.                                                                                                      | the aside of the sessions in the admin feature lib of the section, on the aside base of the shared core                                                                    |
| While the table re-reads, the former rows stay dimmed under the sign of reading.                                                                         | the store of the section — the rows are replaced when the answer arrives, the busyness is a sign of its own                                                                |
| An empty period draws the empty state of the base, not a text of its own.                                                                                | the list component of the section — no empty text of its own                                                                                                               |
| A failure of the reading is one message of the shared bus for the section.                                                                               | the store of the section — the refusal goes to the bus                                                                                                                     |
| The labels of the section, the columns, the kinds and the panel lie in the dictionary of the application.                                                | the dictionary of the admin application, the namespace of the section                                                                                                      |
| The numbers of the section are checked against the print of the digest at the tree.                                                                      | the end-to-end spec of the section in `apps/message-bus-admin-e2e/` — the stand seeds the lines, the spec reads the table                                                  |
