# Сборка приёмника требует клиента хранилища

**Статус:** предложено · **Ревизия:** 2026-08-16 · **Префикс сценариев:** `SC-MB`
**Зависимости:** нет
**Законы:** `delivery`, `verifiability`
**Процедуры:** нет — работа о сборке, а не об операциях приёмника

## Зачем

Клиент хранилища кладётся генератором и в историю не едет: его каталог закрыт от системы
контроля версий, и пропажу не показывает ни состояние дерева, ни линтер. Пропасть он может
буднично — свежий чекаут без установки зависимостей, оборванная установка, чистка каталогов
руками.

Сборка приёмника при этом останавливается, но объясняет себя плохо: первой строкой идёт
«не удаётся разрешить `./generated/prisma/client`», а следом — сотня ошибок типов на каждом
обращении к таблицам, потому что тип клиента подставился пустым. Настоящая причина тонет в
этом выводе, а команда, которой клиент заводится, в нём не названа вовсе.

Договорённость называет, чем сборка отвечает на пропажу клиента.

## Терминология

| Термин           | Что это                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------------- |
| Клиент хранилища | Код доступа к базе, который кладёт генератор схемы; в историю не едет                     |
| Каталог клиента  | Место, куда генератор его кладёт; названо в схеме хранилища блоком генератора             |
| Пропажа клиента  | Каталога нет вовсе или в нём нет входного файла, который зовёт барель либы хранилища      |
| Отказ сборки     | Сборка останавливается до компиляции и печатает одну строку: чего нет и чем это заводится |

### Как это называется в интерфейсе

Своего интерфейса у работы нет: отказ читает тот, кто зовёт сборку, — в выводе команды или в
логе прогона конвейера.

## Правила

- **Сборка приёмника отказывает, когда клиента хранилища нет.** Отсутствие каталога и каталог
  без входного файла — одна и та же пропажа: собранное по половине клиента отвечает отказом уже
  на узле.
- **Отказ называет и причину, и починку.** В строке стоит каталог, которого не хватает, и
  команда, которой он заводится. Причина без команды заставляет искать её по памяти дерева, а
  команда без причины не объясняет, почему сборка встала.
- **Проверка идёт до компиляции.** Иначе к одной верной строке добавляется сотня ошибок типов,
  и первой читается не она.
- **Решение живёт чистой функцией, а конфиг сборки её зовёт.** Ветвление внутри конфига
  проверяется только запуском сборки, а функция — вызовом.
- **Конвейер собирает приёмник, и отказ сборки роняет прогон.** Проверка, живущая только на
  машине исполнителя, отвечает тому, кто её вспомнил.

## Что не входит

- **Кеш сборок.** Успех, отвечающий из кеша после пропажи клиента, разбирается своей работой:
  при пропаже сборка отказывает, и класть в кеш ей нечего.
- **Другие приложения дерева.** Клиента хранилища зовёт только приёмник; второго потребителя у
  него нет.
- **Автоматический запуск генератора вместо отказа.** Сборка, чинящая себя сама, прячет то, что
  дерево установлено наполовину.
- **Проверка соответствия клиента схеме.** Расхождение схемы с миграциями меряет своя проверка
  дерева; здесь судится только наличие.

## Контракт

Поверхность приёмника не меняется: ни одной операции, ни одного кода ответа. Меняется то, чем
кончается сборка при пропаже клиента.

| Что                      | Было                                           | Стало                             |
| ------------------------ | ---------------------------------------------- | --------------------------------- |
| сборка без клиента       | отказ: не разрешён импорт и сотня ошибок типов | отказ одной строкой до компиляции |
| причина в выводе         | первой строкой, следом сотня чужих             | единственная строка вывода        |
| команда починки          | не названа                                     | названа в той же строке           |
| сборка при живом клиенте | идёт                                           | идёт, проверка молчит             |

## Решения

- **Отказ ставится в конфиг сборки, а не отдельной проверкой дерева.** Так он срабатывает при
  любом вызове сборки — локальном, конвейерном, из образа. Отвергнуто: своя цель в раскладке
  приёмника — она кешируется отдельно и способна ответить успехом из кеша.
- **Сборка себя не чинит.** Запустить генератор из конфига дешевле для того, кто собирает, и
  дороже для всех: дерево, установленное наполовину, продолжает выглядеть целым.
- **Пустой каталог считается пропажей наравне с отсутствующим.** Оборванная генерация оставляет
  каталог, и судить по его наличию значило бы пропустить ровно тот случай, ради которого
  проверка заводится.
