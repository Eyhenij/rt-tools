# Дерево заводит себя само по приглашению

**Статус:** предложено · **Ревизия:** 2026-08-17 · **Префикс сценариев:** `SC-MB`
**Зависимости:** `agent-kit` (признак дерева и место токена на дереве)
**Законы:** `access`, `observability`, `verifiability`, `entity-models`, `lists`, `navigation`
**Процедуры:** нет — операции объявлены контроллерами приёмника

Договорённость по незакрытой работе. Вливается в `docs/specs/message-bus/spec.md` и
`docs/specs/message-bus/admin/spec.md` последним коммитом задачи; сценарии нумеруются вместе с
доменом и переезд переживают.

## Зачем

Токен дерева выдаёт только команда строки запуска на самом приёме. Значит завести дерево может
лишь тот, у кого есть доступ к проду: он зовёт команду, читает напечатанный один раз токен и
передаёт его тому, кто дерево заводит. Передача идёт перепиской, то есть тем самым каналом, от
которого токен и защищают.

Пакет при этом умеет всё остальное сам: считает признак дерева, знает адрес приёма, кладёт токен
в файл вне дерева. Не хватает одного шага — попросить токен.

Открытой записи здесь быть не может: приём закрыт по устройству, и операция, отдающая токен
всякому, кто её позвал, открывает наружу всё, что за токеном стоит. Поэтому дерево заводит себя
само, но по приглашению, которое выдал владелец.

## Терминология

| Термин                    | Что это                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Приглашение               | Одноразовый код, выданный владельцем под одно дерево. Даёт право один раз получить токен и после этого гаснет |
| Срок годности приглашения | Время, после которого приглашение не принимается, даже если им не пользовались                                |
| Обращение за токеном      | Чем дерево просит токен: приглашение и признак дерева. Отвечает приём токеном либо отказом                    |
| Погашенное приглашение    | Приглашение, по которому токен уже выдан. Не удаляется: по нему читается, когда и какое дерево завелось       |
| Отозванное приглашение    | Приглашение, снятое владельцем до того, как им воспользовались                                                |

### Как это называется в интерфейсе

| В договорённости      | В строке запуска и на экране                            |
| --------------------- | ------------------------------------------------------- |
| выдача приглашения    | `message-bus tree:invite <имя>` — печатает код один раз |
| отзыв приглашения     | `message-bus tree:uninvite <имя>`                       |
| список приглашений    | `message-bus tree:invites`                              |
| обращение дерева      | `npx agent-kit enroll --code <код>`                     |
| раздел админки        | «Приглашения» — свой пункт меню                         |
| состояния приглашения | «ждёт», «погашено», «просрочено», «отозвано»            |

## Правила

- **Токен выдаётся только по годному приглашению.** Обращение без приглашения, с погашенным,
  просроченным или отозванным отвечает одинаково — отказом, не называя, что именно не сошлось.
  Разница в ответах говорила бы, какие коды заведены.
- **Приглашение гаснет в той же записи хранилища, которой выпущен токен.** Иначе два обращения,
  пришедшие разом, получают по токену на одно приглашение: между проверкой и выдачей стоит
  сеть, и второй запрос успевает пройти проверку до того, как первый погасил код.
- **Имя дерева задаёт владелец при выдаче приглашения, а не обращение.** Имя — то, чем дерево
  зовётся в админке и в сводках; принятое из обращения, оно позволяет назваться чужим именем
  тому, кто добыл код.
- **Признак дерева, уже заведённый, обращением не перезаводится.** Отказ, а не тихая выдача нового
  токена: иначе добытый код угоняет существующее дерево вместе с его грузом.
- **Приглашение годно ограниченное время.** Код, лежащий в переписке месяцами, ничем не
  отличается от общего секрета установки.
- **Обращение за токеном — публичная операция, заводящая запись, и закрыто ограничителем частоты.** Права его
  не сторожат, и без предела скорость роста таблицы задаёт отправитель.
- **В хранилище лежит только хеш приглашения.** Тем же приёмом, что и токен: снятый дамп не
  даёт ни одного годного кода.
- **Токен уходит дереву единственным ответом на обращение.** Второго пути забрать его нет — у
  приёма его нет тоже.
- **Обращение идёт только по защищённому соединению.** Пакет отбивает адрес приёма без TLS сам, не
  доходя до сети; исключение — локальная машина, где приём поднят для проверки.
- **Ни приглашение, ни токен не попадают в наблюдения и логи.** Пишется, что обращение пришло, чем
  кончилось и какое дерево завелось, — сами значения вычищаются.
- **Пакет не перезаписывает уже лежащий токен, не спросив.** Дерево с годным токеном, позвавшее
  заведение второй раз, теряло бы связь с прежним грузом молча.

## Что не входит

- Срок годности самого токена дерева. Токен по-прежнему годен, пока не отозван: срок требует
  продления, иначе сводки перестают ездить посреди месяца и молча.
- Перевыпуск токена самим деревом. Потерянный токен выдаётся новым приглашением от владельца —
  иначе операция перевыпуска становится вторым путём к токену.
- Смена имени и признака заведённого дерева.
- Заведение учётных записей людей: приглашение выдаётся дереву, а не человеку.

## Контракт

| Операция                  | Кто зовёт | Чем закрыта                    | Что отдаёт                  |
| ------------------------- | --------- | ------------------------------ | --------------------------- |
| `POST /api/intake/enroll` | дерево    | публично, ограничитель частоты | токен дерева либо отказ     |
| выдача приглашения        | владелец  | команда строки запуска         | код, напечатанный один раз  |
| отзыв приглашения         | владелец  | команда строки запуска         | подтверждение               |
| чтение приглашений        | админка   | вход человека                  | список с состоянием каждого |

Обращение несёт приглашение и признак дерева. Имя в нём не передаётся вовсе: приём берёт его из
приглашения.

### Коды отказов

| Код               | Когда                                                     |
| ----------------- | --------------------------------------------------------- |
| `Unauthorized`    | приглашение не найдено, погашено, просрочено или отозвано |
| `Conflict`        | признак дерева уже заведён                                |
| `TooManyRequests` | обращений с одного ключа клиента больше предела           |
| `BadRequest`      | обращение без приглашения или без признака дерева         |

## Данные

Приглашение: хеш кода, имя будущего дерева, время выдачи, срок годности, время погашения,
время отзыва и ссылка на заведённое дерево — она заполняется в момент погашения. Уникальность
имени держит хранилище: два годных приглашения на одно имя означали бы два дерева с одним
именем.

Заведённое дерево и его токен не меняются: те же записи, что и при заведении рукой.

## Экраны и состояния

Приглашения получают свой пункт меню и свой списочный экран — тот же, каким собраны разделы
груза. Вкладкой раздела «Деревья» они не приезжают: раздела «Деревья» в админке нет вовсе —
деревья живут выпадашкой отбора, — а вкладок нет ни у одного раздела.

| Состояние экрана     | Что видно                                                              |
| -------------------- | ---------------------------------------------------------------------- |
| список пуст          | «Приглашений нет» и подсказка, какой командой выдаётся                 |
| список есть          | имя, состояние, когда выдано, до когда годно, признак дерева           |
| приглашение ждёт     | строка с действием «Отозвать» в меню строки; отзыв спрашивает согласия |
| приглашение погашено | строка называет заведённое дерево признаком; действий нет              |
| чтение отказало      | отказ на месте списка и повтор рядом с причиной                        |

Заведённое дерево называется признаком, а не ссылкой: вести ссылке некуда — своего экрана у
дерева нет. Отказ чтения занимает место списка вместо тоста тем же приёмом, что у разделов
груза: тост уходит сам, а вернувшемуся к экрану повторять было бы нечем.

Сам код на экране не показывается никогда — в хранилище его нет.

## Разбор безопасности

Разбор идёт по тому, что решение открывает наружу: до него у приёма не было ни одной операции,
заводящей запись без входа.

| Угроза                           | Чем закрыта                                                                                         |
| -------------------------------- | --------------------------------------------------------------------------------------------------- |
| Кто угодно заводит себе дерево   | Обращение без годного приглашения отбивается; приглашение выдаёт только владелец командой на проде  |
| Подбор кода перебором            | Код — 32 случайных байта; ограничитель частоты по ключу клиента; сверка по хешу за постоянное время |
| Разведка по разнице ответов      | Ненайденное, погашенное, просроченное и отозванное приглашение отвечают одинаково                   |
| Два токена по одному приглашению | Погашение и выпуск идут одной записью хранилища, а не двумя шагами вокруг сети                      |
| Угон уже заведённого дерева      | Признак, который уже есть, обращением не перезаводится: отказ, а не выдача нового токена            |
| Дерево называется чужим именем   | Имя приходит из приглашения, а не из обращения                                                      |
| Перехват токена в ответе         | Обращение только по TLS; адрес без него пакет отбивает у себя, не доходя до сети                    |
| Утечка кода из переписки         | Срок годности и одноразовость; отзыв владельцем до первого использования                            |
| Утечка из дампа хранилища        | В хранилище лежат только хеши — и токена, и приглашения                                             |
| Токен в логах и наблюдениях      | Значения вычищаются; пишется событие, а не его содержимое                                           |
| Токен на диске потребителя       | Файл вне дерева, права только владельцу файла; путь объявлен настройкой, а не выдуман пакетом       |
| Наводнение обращениеми           | Ограничитель частоты и предел веса тела, общий с остальным приёмом                                  |
| Потеря связи с прежним грузом    | Пакет не перезаписывает лежащий токен без прямого слова                                             |

Что остаётся открытым и принимается осознанно: владелец, потерявший код, выдаёт новый —
приглашение восстановлению не подлежит; и обращение, пришедшая с годным кодом раньше законного
дерева, заведёт дерево вместо него — от этого защищает только срок годности и то, что код
передаётся один раз.

## Сквозные требования

### Локали

Язык админки один. Отказы приёма — машинные строки; на экране показывается разобранный текст.

### SEO

Не применимо: админка закрыта входом и наружу не индексируется.

### Мобильная раскладка

Вкладка приглашений повторяет раскладку соседних списков раздела и своей не заводит.

### Мультиобъектность

Не применимо: у приёма один владелец и одна установка.

## Решения

- **Приглашение выбрано вместо общего секрета установки.** Секрет один на все деревья: утёкший
  у одного открывает заведение всем, и смена требует обхода каждого дерева сразу. Приглашение
  привязано к одному дереву и гаснет само.
- **Приглашение выбрано вместо обращения с подтверждением владельцем.** Подтверждение переносит
  решение в админку, но обращение до него может послать кто угодно: очередь ожидающих становится
  местом, куда шлют мусор. При приглашении незваная обращение отбивается на месте.

## Открытые вопросы

- **Q-MB-INV-1. Ключ клиента у ограничителя частоты.** Приём стоит за дорогой, и адрес клиента
  приходит заголовком, которому доверять можно лишь потому, что дорога своя. Своего ключа у
  обращения нет; годится ли адрес — решается при написании.
