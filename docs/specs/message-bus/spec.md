# Приёмник груза

**Статус:** действует · **Ревизия:** 2026-08-19 · **Префикс сценариев:** `SC-MB`
**Зависимости:** `agent-kit` (что дерево о себе знает и что уезжает наружу)
**Законы:** `verifiability`, `code-structure`, `lib-imports`, `delivery`, `observability`,
`frontend-application`, `reuse-first`, `lists`, `entity-editing`, `entity-models`, `navigation`
**Процедуры:** нет — операции объявлены контроллерами приёмника

## Зачем

Пакет правил стоит в нескольких деревьях, и то, чем в нём пользуются, известно только каждому
дереву про себя. Спек пакета правил — `docs/specs/agent-kit/` — описал, что дерево о себе
знает и что из этого уезжает наружу; куда именно уезжает — он не описывает вовсе, и отправке
обращаться некуда.

Открытая очередь работ приёмником быть не может: груз говорит о рабочих привычках команды —
чем пользуются, обо что спотыкаются, сколько раз признавали промах. Отсюда закрытая своя
служба.

Эта договорённость называет приёмник: что он принимает, чем отличает одно дерево от другого,
что делает с повторной отправкой и где обязан отказать вместо молчания.

Она же называет вторую половину службы — чтение принятого. Прочитать груз запросом к базе с
самого узла может только тот, у кого есть доступ к узлу, а служба уезжает в интернет: знающая
одни лишь токены деревьев, она отдавала бы принятое всякому, кто дошёл до её адреса, и не
отвечала бы на вопрос, кто читал. Отсюда вход человека и админка: чем человек представляется
приёмнику и что он видит после входа. Разделов три — по роду груза.

## Терминология

| Термин             | Что это                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| Приёмник           | Закрытая служба, принимающая груз запросом. Своя, а не чужая очередь работ                             |
| Груз               | То, что уезжает прогоном отправки: сводка со снимком надстроек, предложения, разборы происшествий      |
| Род груза          | Одно из трёх: сводка, предложение, разбор происшествия. У каждого своя операция приёма                 |
| Дерево             | Запись о репозитории, от которого приезжает груз. Деревья различаются признаком, а не адресом          |
| Токен дерева       | То, чем дерево представляется приёмнику. Приёмник держит только хеш; сам токен печатается один раз     |
| Отзыв токена       | Пометка о том, что токен больше не принимается. Токен не удаляется: по нему читается прежний груз      |
| Запись месяца      | Свод одного дерева за один календарный месяц. Одна на пару «дерево — месяц»                            |
| Прогон             | Одна отправка с дерева: до трёх запросов подряд, по одному на род груза                                |
| Снимок надстроек   | Состояние дерева на момент прогона: какие разделы каких ресурсов пакета оно правит и чего не разложило |
| Версия схемы груза | Номер формата запроса приёма. Меняется, когда меняется состав полей самого груза                       |
| Версия схемы строк | Номер формата строки наблюдения на дереве. Их в одной сводке встречается несколько                     |

Вторая половина словаря — про чтение принятого:

| Термин              | Что это                                                                                |
| ------------------- | -------------------------------------------------------------------------------------- |
| Админка             | Приложение, которым человек читает принятый груз. Правок груза в ней нет вовсе         |
| Учётная запись      | Имя и пароль одного человека. Заводится командой строки запуска                        |
| Вход                | Состояние, в котором приёмник знает, кто спрашивает. Живёт сроком и обрывается выходом |
| Срок входа          | Время, после которого вход перестаёт приниматься и человек представляется заново       |
| Раздел              | Экран админки со своим адресом. В раздел ведёт пункт меню                              |
| Список              | Страница раздела: строка на запись, тулбар над ней и пагинация под ней                 |
| Панель подробностей | Панель с одной записью целиком, выезжающая по нажатию на строку                        |
| Отбор               | Условие, сужающее список. Стоит в тулбаре и виден на экране                            |
| Страница списка     | Отрезок списка, приезжающий одним запросом. Номер страницы и размер называет запрос    |
| Выборка             | Страница, размер, сортировка и отбор вместе. Живёт в адресе раздела                    |

Третья — про то, где приёмник стоит и чем поднимается:

| Термин       | Что это                                                                                                                |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Узел         | Арендованная машина, на которой живёт приёмник. Своего кода не несёт — только состав прода и его окружение             |
| Имя          | Доменное имя, которым приёмник находят снаружи; за ним стоит адрес узла                                                |
| Проксировщик | Контейнер перед приёмником: держит имя, выписывает и продлевает сертификат, отдаёт статику админки и запросы приёмнику |
| Состав прода | Описание контейнеров узла: база, накат миграций, приёмник, проксировщик                                                |
| Выкатка      | Прогон, который собирает образ, кладёт его в реестр и просит узел поднять именно этот образ                            |
| Дамп         | Выгрузка хранилища одним файлом: свод, деревья, токены и учётные записи целиком                                        |
| Откат        | Подъём прежнего образа по его sha, когда новый не поднялся                                                             |

Четвёртая — про то, что приёмник пишет о себе:

| Термин              | Что это                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------- |
| Строка журнала      | Одна запись вывода приёмника: имя, уровень и поля                                           |
| Имя строки          | Постоянная часть записи, по которой строки одного рода собираются вместе                    |
| Поля строки         | Всё переменное, что приёмник знает о случившемся, объектом рядом с именем                   |
| Разобранная причина | Ошибка полями: класс, текст, код хранилища, его подробности, ответ драйвера, срезанный стек |
| Вычистка            | Замена значения поля по имени ключа до того, как строка ушла в вывод                        |
| Срезанный стек      | Первые строки стека — дальше идёт обвязка каркаса, одинаковая у всех отказов                |

Пятая — про то, из чего приёмник собирается:

| Термин           | Что это                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------------- |
| Клиент хранилища | Код доступа к базе, который кладёт генератор схемы; в историю не едет                     |
| Каталог клиента  | Место, куда генератор его кладёт; названо в схеме хранилища блоком генератора             |
| Пропажа клиента  | Каталога нет вовсе или в нём нет входного файла, который зовёт барель либы хранилища      |
| Отказ сборки     | Сборка останавливается до компиляции и печатает одну строку: чего нет и чем это заводится |

| отключение учётной записи | `message-bus account:disable <имя>`                      |

| панель подробностей       | панель, выезжающая по нажатию на строку                  |

## Правила

Предметные правила живут в поддоменах — домен вырос вдвое против предела длины, и читать его
целиком ради одной подробности стало дороже, чем найти её. Границы между поддоменами те же, что
были проведены группами правил; переросший предел поддомен делится дальше тем же приёмом.

- **Префикс сценариев принадлежит домену вместе с поддоменами.** Домен делится тогда, когда его
  спек перерос предел длины, и сценарии переезжают прежними: номер связывает сценарий с
  заголовком теста, и своя нумерация у каждого поддомена означала бы пересчёт всех номеров
  разом.

## Что не входит

Границы предметов названы в поддоменах. Общее для домена:

- **Свод по нескольким деревьям и графики.** Слово владельца: показываются списки, а свод
  назначается тогда, когда деревьев станет три.
- **Правка принятого груза.** Приёмник принимает, админка читает; правок нет ни у той, ни у
  другой стороны.
- **Оповещения о приехавшем грузе.** Ни почты, ни оповещений: груз читают, когда за ним
  приходят.
- **Чистка старых записей по сроку.** Приёмник свой и малый; срок хранения назначается тогда,
  когда объём станет виден.

## Контракт

Поверхность — операции HTTP и восемь команд строки запуска. Дерево представляется заголовком
`X-Tree-Token`, человек — входом; одно вместо другого не принимается. Операции приёма перечислены
в поддомене приёма, операции чтения — в поддомене чтения.

### Коды отказов

Не применимо: приёмник отвечает кодом ответа HTTP, а не именованными кодами домена. Где он
обязан отказать вместо молчания — таблицы в поддоменах приёма и чтения.

## Данные

Хранилище — Postgres, схема правится миграциями. Семь сущностей: дерево, токен дерева, запись
месяца, предложение, разбор происшествия, учётная запись, вход. Что в каждой и какие пары
уникальны — в поддоменах, которые их кладут.

## Экраны и состояния

У приёмника экранов нет; экраны есть у админки — таблица состояний в поддомене чтения. Состояние
узла читается двумя ответами и описано в поддомене узла.

## Сквозные требования

### Локали

Язык один — русский. Приёмник читают владелец и исполнитель, а подписи админки лежат в словаре
приложения, а не в разметке. Оттуда же берутся подписи кита: у него свой словарь на восемь
языков, и без этого пагинация и пустое состояние выходят по-английски рядом с русскими
заголовками. Второй язык дешевле добавить потом.

### SEO

Не применимо: служба закрытая, всё, кроме экрана входа, стоит за входом, и поисковикам не
показывается ничего.

### Мобильная раскладка

Строка списка на узком экране показывается карточкой — это вход таблицы кита, а не своя
разметка. Экран, собранный мимо неё, узкую раскладку теряет молча.

### Мультиобъектность

Деревьев много, и каждое видит только свой груз: операция приёма работает от токена, а не от
переданного признака дерева. Признак, названный в грузе, с деревом токена сверяется, и
расхождение отбивает приём.

Вошедший человек при этом видит груз всех деревьев: учётная запись принадлежит службе, а не
дереву, и отбор по дереву сужает показанное, а не доступ.

## Решения

- **Приёмник — закрытая своя служба.** Решение владельца. Очередь работ репозитория пакета
  открыта всему свету. Отвергнуто: приватный репозиторий вместо службы — роль, разбиравшая
  нужность, предлагала именно это, владелец довод прочитал и решение подтвердил.
- **Три ветки, а не одна.** Решение владельца. Откатывается порознь: приёмник без админки
  осмыслен, админка без приёмника неисполнима. У каждой ветки своя задача в очереди работ, и
  заводится она перед своей веткой. Отвергнуто: одна ветка на всё; и две ветки.
- **Приём всех трёх родов груза в первой ветке.** Роды отличаются формой записи, но не тем, как
  приезжают. Отвергнуто: только сводка в первой ветке — тогда веток становится четыре.
- **Слои семьи бэкенда — `api`, `data-access`, `feature`, `util`.** Решение владельца, списано с
  дерева-образца дословно; закрывает `Q-2` эпика. Тег и алиас выведены из пути либы, как
  того требует сверка раскладки. Отвергнуто: те же слои со своими именами тегов.
- **Спеки новых приложений и либ гоняет Vitest.** Решение владельца. Пакеты в `projects/`
  остаются на Jest, граница проходит по каталогу. Отвергнуто: Jest везде.
- **Разбор происшествия уезжает текстом целиком.** Решение владельца; закрывает `Q-14`
  договорённости пакета. При вливании переписываются две статьи спека отправителя: о том, что
  проверка на адрес дерева накрывает весь груз, и о выдаче токена из админки. Отвергнуто: одна
  шапка; и текст с проверкой на адрес дерева.
- **Сводка последнего прогона замещает прежнюю.** Решение владельца. Окна прогонов
  перекрываются, и сложение завышало бы числа молча. Отвергнуто: сложение счётчиков; и хранение
  прогонов порознь — оно отменяет одну запись на пару «дерево — месяц».
- **Закон о наблюдаемости раскладывается этой веткой, правило слоя API остаётся снятым.**
  Решение владельца. Журнал отказов нужен с первого живого прогона; правило слоя API требует
  процедур Connect, которых здесь не будет.
- **Первый токен выдаёт команда самого приложения.** Решение владельца. Она же останется после
  админки — для первой учётной записи. Отвергнуто: начальный засев Prisma.
- **Признак дерева называется доводом команды заведения — допущение исполнителя.** Довод: иначе
  приёмник узнаёт признак из груза и принимает за своё присланное. Отменяется одной правкой.
- **Разбор опознаётся именем файла — допущение исполнителя.** Заголовок правится вместе с
  текстом, имя файла переживает правку. Открыто как `Q-19`.
- **Признак предложения — хеш его текста, а область уникальности — дерево.** Довод исполнителя:
  уникальность по полю в килобайты упирается в предел размера строки индекса, а граница месяца
  от повтора не защищает — он приезжает в любом месяце. Закрывает `Q-16`. Отвергнуто:
  уникальность по паре «дерево — текст»; признак, назначаемый отправителем — его пришлось бы
  хранить в файле предложения, то есть там же, где живёт отметка, теряющаяся при переключении
  ветки.
- **Ответ приёма расширяется, а не заводится вторым.** Отправитель уже читает этот ответ, и
  второй запрос ради счёта повторов добавил бы прогону ещё одно место, где он рвётся.
- **Вход паролем, а учётные записи заводит команда строки запуска.** Служба уезжает в интернет —
  вход нужен; заведение из веба — это экран, право и вопрос о первой записи. Отвергнуто: заведение
  записей из интерфейса и экран учёток. Цена: человека без доступа к узлу завести нечем.
- **Три списочных экрана, а не один.** Слово владельца на расхождение, принесённое разбором:
  разборы, предложения и сводки одной работой. Отвергнуто: один экран с окупаемостью каркаса на
  нём. Цена: ветка длиннее, и откат уносит все три.
- **Вид списочного экрана — требование приёмки.** Слово владельца: таблица с тулбаром и
  пагинацией, нажатие на строку открывает панель подробностей. Собранное иначе не принимается.
- **Сквозной набор сценариев заводится этой работой.** Слово владельца на расхождение: правило
  `testing` требует такого набора для сценария, чьё «Тогда» называет человека и то, что он видит,
  а в дереве его нет вовсе. Отвергнуто: закрыть обещание юнитами и замерами. Цена: стенд из
  прод-сборки, засев базы и прогон одним воркером — работа заметного размера.
- **Раскладываются пять законов: о списке записей, о правке сущности, о моделях сущностей, о
  навигации и о доступе.** Слово владельца: четыре названных им и закон о доступе сверх того —
  работа заводит вход, а закон под него стоял снятым. Цена: у правил правки записи и навигации
  компаньоны выйдут из строк «не исполняется», и их придётся обслуживать на каждой сверке спеков.
- **Вход несёт кука, недоступная скриптам.** Админка и приём отдаются с одного имени, поэтому
  второго источника у куки нет; чужой переход её не посылает. Отвергнуто: заголовок с токеном —
  он требует держать значение там, куда дотягивается скрипт страницы.
- **Отдача самого приложения входом не сторожится.** Закрытая статика — это проксировщик, а он в
  отдельной задаче; без груза приложение пусто. Цена: адрес админки виден всякому.
- **Текст груза показывается текстом.** Дерево с токеном иначе получает исполнение своей разметки
  в браузере вошедшего. Отвергнуто: показ размеченным текстом с вычисткой — вычистка стоит
  дороже, а читаемость от неё выигрывает мало.
- **Выборка живёт в адресе.** Иначе правило о перезагрузке нарушается буквой. Цена: разбор и
  сборка параметров адреса на каждом разделе.
- **Порядок по умолчанию — свежие сверху, второй ключ — идентификатор записи.** Без второго ключа
  записи с равным временем перескакивают между страницами.
- **Отказ чтения занимает место списка, а не подаётся тостом.** Расхождение с правилом списочного
  экрана, названное расхождением: тост уходит сам, и человеку, вернувшемуся к экрану, повторять
  нечем. Причина, номер обращения и повтор стоят на месте таблицы.
- **Число попыток входа не ограничивается, а ответ удлиняется — допущение исполнителя.** Запертую
  запись отпирать некому: админки учёток нет. Отменяется одной правкой.
- **Язык один и тема одна — допущение исполнителя.** В границах работы владелец их не назвал.
  Отменяется одной правкой, пока подписи лежат в словаре.
- **Команды смены пароля и отключения записи заводятся вместе с заведением — допущение
  исполнителя.** Иначе утёкший пароль закрывать нечем вовсе, а стоят они строкой рядом с уже
  написанными командами деревьев.
- **Проксировщик берётся готовым образом, а не ставится на узел пакетом.** Всё, что живёт на
  узле, поднимается одним составом: пакет, поставленный руками, переживает пересоздание узла
  только в памяти того, кто его ставил.
- **Домен занят целиком, приёмник стоит на корне.** Решение владельца, принятое до этой работы.
- **Секреты узла лежат файлом на самом узле, а не в конвейере.** Конвейер знает, к какому узлу
  идти и каким ключом, но не знает ни пароля базы, ни ключей службы: выкатка правится чаще,
  чем пароль, и каждая её правка иначе трогала бы секреты.

## Открытые вопросы

- `Q-17` — сколько груз хранится. Срок назначается тогда, когда объём станет виден; до тех пор
  не удаляется ничего.
- `Q-18` — читается ли в админке груз дерева, чей токен отозван. Отказ приёма решён; чтение
  прежнего груза работа админки не решила — она его показывает.
- `Q-19` — чем опознаётся разбор происшествия. Работа идёт допущением «именем файла».
  Переименованный на дереве разбор приедет вторым экземпляром, и это цена допущения.
- `Q-20` — все ли разборы уезжают каждым прогоном или только новые. Отбор назначает
  отправитель, и до его правки приёмник принимает сколько прислали; при росте числа разборов
  груз упрётся в предел веса.
- `Q-21` — сколько живёт вход и продлевается ли он работой человека. Работа идёт допущением
  «двенадцать часов, продления нет»; число называет владелец, и меняется оно настройкой.
- `Q-22` — что делать с предложением, текст которого правили после отправки. Приезжает новой
  записью; сшивать их нечем, пока у предложения нет имени, переживающего правку текста.
- `Q-25` — какие свойства записи стоят столбцами у каждого из трёх разделов. Работа идёт
  допущением: у разборов — дерево, имя файла, состояние, время приезда и время обновления; у
  предложений — дерево, ресурс, адрес, состояние, время приезда; у сводок — дерево, месяц, число
  заходов, время прогона.
- `Q-26` — что делает выкатка, когда проба живости не дождалась ответа. Сейчас она объявляет
  себя отказавшей и оставляет узел с новым образом; откат остаётся рукой человека. Само
  возвращение прежнего sha описано, но кто его зовёт — человек или прогон, — решается по первой
  же настоящей поломке, а не заранее.
- `Q-28` — оставлять ли команду `tree:invite` после того, как выдача появилась в админке. Пока
  остаётся: узел доступен владельцу и тогда, когда админка не поднята.
- `Q-30` — как сторожится порядок переходов состояния записи груза. Договорённость называет
  порядок — вперёд, и назад только из «в работе» в «новое», — а исполнять его пока нечему:
  единственный переход, который делает приёмник, это сброс приездом с другим текстом. Судить
  порядок будет тот путь, которым состояние ставят, и до него правило остаётся намерением.
