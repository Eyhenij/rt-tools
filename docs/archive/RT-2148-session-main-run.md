## Что было не так

Ни правило, ни хук старта сессии не велели прочитать исход последнего запуска CI главной ветки.
Слияние читалось как конец работы, и красная главная ветка после него жила, пока её не замечал
владелец. Аудит очереди после RT-2147 читает этот запуск, но аудит ждёт вызова, а слияние
посреди сессии двигает главную ветку без него.

## Решения

- **Одна команда, два читателя.** `main-run` печатает одну строку: нет запуска, идёт, зелёный,
  красный, вытеснен — с коммитом, днём и адресом; где прочитать нельзя, строка говорит об этом.
  Хук старта печатает её в контекст; после известного слияния её вызывает рука. Код выхода 1 на
  красном и вытесненном — чтобы цепочка после слияния на нём встала.
- **Хук старта запуск не отказывает.** Без node, без разложенного чтения, с пустым ответом —
  молчит: пустую строку нельзя выдать за зелёную. Каталог проверок берётся из настройки дерева,
  как у чтения «эпик кончился».
- **Ветка стоит на RT-2147.** Команда берёт чтение запуска оттуда; план эпика называл ветки
  независимыми, и это исправлено в нём: RT-2148 — череда, PR идёт в ветку RT-2147.
- **Статья — в правиле task-flow.** Семь доводов там свёрнуты ради предела веса; строка
  «Requires» называет новый хук.
