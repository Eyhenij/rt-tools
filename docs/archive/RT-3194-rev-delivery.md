# RT-3194 — ревизия семьи закона о поставке

Задача RT-3194 эпика RT-3190, ветка `RT-3194-rev-delivery` от ветки задачи RT-3193 — стопка эпика
`RT-3190-agent-kit-revision`, 11.11.2026. Папка `docs/tasks/RT-3194-rev-delivery/` разобрана в эту
запись.

## Просьба

Слово владельца: «заведи новый эпик на актуализацию обвязки agent kit и разбей на задачи. нужно
сделать ревизию всей документации, правил и скилов в agent kit. так же нужно начать с построения
графа graphify для каждого из проектов в этом репозитории, если это будет необходимо - построить
некое подобие графа для понятий и правил в agent kit». На вопрос, как делить ревизию и когда
править: «По семьям законов, правки сразу».

## Что сделано

Семья — закон `delivery`, правила `git-workflow` и `deploy-flow` в трёх вариантах хостинга,
`dependencies`, `queue-audit`, семнадцать паттернов и три файла ловушек. Её прочитала роль
`rules-reviewer`, а второй агент сверил каждую статью четырёх правил дерева со строкой привязки в
компаньоне и с кодом хуков. Правки внесены в исходники пакета и разложены.

## Находки и чем закрыты

Роль `rules-reviewer`, расхождения:

- Схемы `git-workflow` разбирали папку задачи после PR, а правило `task-flow` — до него. Схемы,
  пункт 10 списка перед PR во всех трёх вариантах и статья о «двух признаках» черновика
  исправлены, ловушка о черновике с папкой убрана. Статья об отказе PR с папкой осталась только в
  `task-flow`, статья о создании задачи командой — только в `git-workflow`.
- Тексты сливали main в ветку задачи и сравнивали с `main...HEAD`, закон велит сливать ветку эпика.
  В паттернах PR всех трёх вариантов, свежести и слияния теперь база ветки; `rebase` в паттернах
  стопки и слияния заменён слиянием. Строка сверки очереди о конфликте называет базу по имени.
- Сверка прода: схема и «чего здесь нет» говорили о прогоне main, текст — о последней успешной
  выкатке. Везде выкатка. Первая половина задачи RT-3074 этим закрыта.
- Остановленная база при миграции: один текст «пропускает молча», другой «отказывает». Отказывает.
- PR на базу без прогона: тексты расходились, ждать ли прогона. Пустой прогон теперь назван двумя
  смыслами, таблица свежести разделена.
- Список перед PR: проверки на самом PR, сборка в пункте 6, шесть разделов тела, устаревший номер
  пункта — приведены к правилам. У GitLab и Azure в образце тела по-прежнему четыре раздела без
  таблиц точек и цели — задача RT-3219.
- Безусловное «слияние выкатывает», путь `deploy.yml` для всех хостингов, ключ задачи в заголовке
  Azure, список областей коммита — исправлены.

Роль `rules-reviewer`, пробелы:

- Сверка очереди называла меньше строк, чем обещает семья, — четыре строки ходов добавлены.
- Откат ссылался на разбиение миграции, которого нет, — описан выпуск в два шага.
- В правилах GitLab и Azure нет слоя эпика, статьи «готовым, где конвейер не просыпается», текста
  «вливает человек» и четырёх статей выкатки; у статьи закона о требовании перед необратимым шагом
  нет строки правила — задача RT-3219.

Сверка с привязками:

- `git-workflow`: принудительный push и `rebase` не отказывает ни один хук — отметка «не
  проверяется». Неотправленные коммиты считает проверка выхода, тело PR читает проверка при
  открытии, совпадение автора с ревьюером отказывается при открытии — отметки «не проверяется»
  заменены привязками. Строка о подписи стояла дважды с противоположными выводами, ветка main
  берётся из профиля, набор — 38 строк из 53.
- `deploy-flow`: выкатка дерева — образы `deploy.yml`, а не публикация пакетов; цепочка миграций
  от пустой базы проверяется `check-schema-drift`. Сборка выкатки за собой не убирает — задача
  RT-3220.
- `dependencies`: срок ожидания свежей версии не задан — задача RT-3220; список исключений есть;
  команда подсчёта потолков считала и полы; граница переформатирования ничем не держится. Правило
  больше не говорит, что установка с замороженным снимком стоит только в выкатке.
- `queue-audit`: функции названы в их файлах. Сверка длинной работы здесь не включена. Отставание
  заявки задачи считалось от main — теперь от её базы, сценарий SC-AK-1337. Конфликтующая заявка в
  ветку эпика получала строку «прогона не будет, пока конфликт» — больше не получает, сценарий
  SC-AK-1338.

Закон о ведении работы после правки в RT-3193 вышел за предел длины на 13 символов; сокращён в
ветке RT-3193 и влит сюда.

## Повторы

Ловушка о наборе перед push повторяла статью правила слово в слово — её заголовок назван по
случаю. Остальные пары семьи оставлены: статья закона и её повтор в правиле — так устроен слой;
«документ в том же коммите» стоит и в `doc-style`, и в `git-workflow` под двумя разными законами;
статья об отставании у GitLab и Azure повторяет `queue-audit.github`, потому что своего правила
сверки у этих хостингов нет.

## Метрика

Статьи семьи без исполнителя в отчёте графа правил: 43 до ревизии, 43 после — отметки стали
честными в обе стороны: одни получили привязку к хуку, у других она оказалась ложной. Пар
повторов во всём пакете: 23 → 17.

Новый долг: у правила `dependencies` единственная привязка к коду оказалась ложной, и отчёт
называет его в разделе правил без исполнителя (было 0, стало 1). Исполнитель — задача RT-3220.
