# RT-3194 — ревизия семьи закона о поставке

Задача RT-3194 эпика RT-3227 (вынесена из RT-3190 по слову владельца «окей, бей на 2 эпика»), PR
#3222, ветка `RT-3194-rev-delivery` от ветки задачи RT-3193, 11.11.2026; 12.11.2026 PR идёт в ветку
эпика `RT-3227-agent-kit-revision-day1`. Папка `docs/tasks/RT-3194-rev-delivery/` разобрана в эту
запись.

## Просьба

Слово владельца: «заведи новый эпик на актуализацию обвязки agent kit и разбей на задачи. нужно
сделать ревизию всей документации, правил и скилов в agent kit. так же нужно начать с построения
графа graphify для каждого из проектов в этом репозитории, если это будет необходимо - построить
некое подобие графа для понятий и правил в agent kit». На вопрос, как делить ревизию и когда
править: «По семьям законов, правки сразу».

## Что сделано

Семья — закон `delivery`, правила `git-workflow` и `deploy-flow` в трёх вариантах хостинга,
`dependencies`, `queue-audit`, семнадцать паттернов и три файла ловушек. Её прочитала роль
`rules-reviewer`, а второй агент сверил каждую статью четырёх правил дерева со строкой привязки в
компаньоне и с кодом хуков. Правки внесены в исходники пакета и разложены.

## Находки и чем закрыты

Роль `rules-reviewer`, расхождения:

- Схемы `git-workflow` разбирали папку задачи после PR, а правило `task-flow` — до него. Схемы,
  пункт 10 списка перед PR во всех трёх вариантах и статья о «двух признаках» черновика
  исправлены, ловушка о черновике с папкой убрана. Статья об отказе PR с папкой осталась только в
  `task-flow`, статья о создании задачи командой — только в `git-workflow`.
- Тексты сливали main в ветку задачи и сравнивали с `main...HEAD`, закон велит сливать ветку эпика.
  В паттернах PR всех трёх вариантов, свежести и слияния теперь база ветки; `rebase` в паттернах
  стопки и слияния заменён слиянием. Строка сверки очереди о конфликте называет базу по имени.
- Сверка прода: схема и «чего здесь нет» говорили о прогоне main, текст — о последней успешной
  выкатке. Везде выкатка. Первая половина задачи RT-3074 этим закрыта.
- Остановленная база при миграции: один текст «пропускает молча», другой «отказывает». Отказывает.
- PR на базу без прогона: тексты расходились, ждать ли прогона. Пустой прогон теперь назван двумя
  смыслами, таблица свежести разделена.
- Список перед PR: проверки на самом PR, сборка в пункте 6, шесть разделов тела, устаревший номер
  пункта — приведены к правилам. У GitLab и Azure в образце тела по-прежнему четыре раздела без
  таблиц точек и цели — задача RT-3219.
- Безусловное «слияние выкатывает», путь `deploy.yml` для всех хостингов, ключ задачи в заголовке
  Azure, список областей коммита — исправлены.

Роль `rules-reviewer`, пробелы:

- Сверка очереди называла меньше строк, чем обещает семья, — четыре строки ходов добавлены.
- Откат ссылался на разбиение миграции, которого нет, — описан выпуск в два шага.
- В правилах GitLab и Azure нет слоя эпика, статьи «готовым, где конвейер не просыпается», текста
  «вливает человек» и четырёх статей выкатки; у статьи закона о требовании перед необратимым шагом
  нет строки правила — задача RT-3219.

Сверка с привязками:

- `git-workflow`: принудительный push и `rebase` не отказывает ни один хук — отметка «не
  проверяется». Неотправленные коммиты считает проверка выхода, тело PR читает проверка при
  открытии, совпадение автора с ревьюером отказывается при открытии — отметки «не проверяется»
  заменены привязками. Строка о подписи стояла дважды с противоположными выводами, ветка main
  берётся из профиля, набор — 38 строк из 53.
- `deploy-flow`: выкатка дерева — образы `deploy.yml`, а не публикация пакетов; цепочка миграций
  от пустой базы проверяется `check-schema-drift`. Сборка выкатки за собой не убирает — задача
  RT-3220.
- `dependencies`: срок ожидания свежей версии в дереве не записан, действует умолчание pnpm 11 —
  сутки (первая запись «срок не задан» была неверна, исправлена в первом круге ревью); список
  исключений есть;
  команда подсчёта потолков считала и полы; граница переформатирования ничем не держится. Правило
  больше не говорит, что установка с замороженным снимком стоит только в выкатке.
- `queue-audit`: функции названы в их файлах. Сверка длинной работы здесь не включена. Отставание
  заявки задачи считалось от main — теперь от её базы, сценарий SC-AK-1337. Конфликтующая заявка в
  ветку эпика получала строку «прогона не будет, пока конфликт» — больше не получает, сценарий
  SC-AK-1338.

Закон о ведении работы после правки в RT-3193 вышел за предел длины на 13 символов; сокращён в
ветке RT-3193 и влит сюда.

Статей закона владельцу в этой задаче нет: закон о поставке не правился.

## Первый круг ревью PR

12.11.2026 четыре роли прочли `57b2beb83`: ревью кода, `project-manager`, `product-strategist`,
`goal-critic`. Ветка несёт и правки двух кругов ревью RT-3193: PR #3221 влили до их отправки, и
они вошли сюда слиянием `e0e3794f6`. Закрыто в этом PR:

- «База, а не main» не была доведена: правило GitHub и паттерн стопки вливали main в ветки
  цепочки, одна строка стопки неверно называла, чего требует проверка поставки. Теперь везде база
  ветки: ветка эпика или нижняя ветка, main — только для ветки эпика.
- Отставшая ветка без конфликта: стопка велела не трогать, свежесть и чтение сверки — вливать
  базу. Владелец выбрал «Вливать только при конфликте»; паттерны свежести, слияния и чтения сверки
  приведены к стопке. Строка сверки по-прежнему считает простое отставание расхождением — это код,
  он правится в задаче RT-3220.
- Сверка прода у GitLab и Azure всё ещё говорила о прогоне main; запись выше «везде выкатка» была
  верна только для GitHub. Исправлены оба правила.
- Пункт 14 списка перед PR называл набор перед push «уже конвейера», правило — «не уже». Исправлен
  во всех трёх вариантах.
- «Черновик открывается раньше, пока идёт работа» невыполнимо: проверка отказывает PR с папкой
  задачи. Теперь черновик открывается после разбора папки.
- Области коммита правило отсылало в компаньон, а там их не было — строка добавлена.
- Компаньоны: проверку схемы зовут набор и конвейер PR, а не выкатка; потолки версий держат только
  Jest; все файлы форматирует первая строка хука коммита; подпись коммитов судит проверка
  поставки, а не набор. Паттерн миграции не называет шаг чужого конвейера. Проверка, которой негде
  проверять, возвращает код пропуска, а не ноль.

Не закрыто здесь и чем закрывается:

- RT-3219 и RT-3220 по слову владельца «Взять в эпик RT-3227» входят в состав эпика. В RT-3219
  уходят статьи GitLab и Azure о слиянии main в ветку задачи. В RT-3220 — статья о ревьюере в
  `queue-audit`, которую не исполняет и код пакета, и ходы для строк сверки об упавшей выкатке и
  о папке в ветке PR.
- Имена одной машины в общих паттернах — полный путь к `gh`, `docs/BACKLOG.md`,
  `-p site admin api` — остались: в этом дереве короткое имя `gh` подменено, и замена сломала бы
  примеры. Уходит в RT-3219.
- Строки сверки об отставании и о папке задачи обещают прогон и снятие черновика, которых на базе
  без конвейера нет, — код, уходит в RT-3220.

## Второй круг ревью PR

Те же четыре роли прочли `4614aed46`. Закрыто в этом PR:

- Граница решения «вливать только при конфликте» не была записана. Теперь она стоит в правиле и в
  паттерне стопки: до открытия PR ветка берёт базу, этого требует проверка поставки; ветка эпика
  берёт main, пока идёт работа; у открытого PR база вливается только при конфликте. Список перед
  PR, паттерны свежести и слияния приведены к этой границе.
- Ловушка об объединяемом индексе обещала слияние main после каждого чужого слияния — теперь
  отсылает к проверке слиянием без драйвера.
- Остатки «main» там, где речь о базе, в правиле GitHub, паттернах свежести, стопки и готовности PR
  и в пункте 15 списка перед PR у GitLab и Azure.
- Код пропуска вместо нуля и «набор и конвейер» вместо «набор и выкатка» перенесены в правила
  выкатки GitLab и Azure: первый круг исправил только вариант GitHub.
- Пункт 14 списка перед PR спорил сам с собой — теперь говорит об объявленных исключениях набора.

Строка сверки об отставании по-прежнему велит вливать базу; паттерн чтения сверки это называет,
код правится в RT-3220.
