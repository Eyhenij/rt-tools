## Согласия владельца

Правка кита — метка класса `@Injectable({ providedIn: 'root' })` → `@Service()` в десяти сервисах
и хранилищах кита и в сервисе витрины; вида она не касается. План, который это называет, владелец
одобрил.

- **Без вида:** «Одобряю plan.md RT-3485»

## Что нашли

- Angular Doctor 0.3.0 даёт одну находку на файл, где вне комментария стоит
  `@Injectable({ … providedIn: 'root' … })`. Находок было 60 в 60 файлах, классов — 62: по два в
  двух файлах API медиа cms. У всех декоратор — только `{ providedIn: 'root' }`, параметров
  конструктора в цепочке наследования нет.
- `@Service()` из `@angular/core` 22 даёт классу ту же запись в корневом инжекторе, что
  `providedIn: 'root'`; `{ autoProvided: false }` — только список провайдеров. `@Service` есть уже
  в 22.0.0, а все пакеты дерева требуют `@angular/core` `^22.0.0`. Проверки `@Service` компилятор
  делает только при сборке AOT.
- Своё правило линтера `require-suffix-declaration` обещало в файле `*.service.ts` метку
  `@Injectable` или имя на `Service`: с `@Service` шина уведомлений кита стала бы красной.
- Образцы пакета правил и README `@rt-tools/store` учили `@Injectable({ providedIn: 'root' })`;
  код по ним снова давал находку.

## Что решили и почему

- **Все 62 класса получили `@Service()` вместо `@Injectable({ providedIn: 'root' })`.** Поведение
  то же. Вместе с ними — сервис переводов витрины и тестовое хранилище спеки админки: инструмент их
  не читает, но образец и код не должны расходиться.
- **Правило линтера принимает метку `@Service` наравне с `@Injectable`.** Спек проверяет и допуск,
  и отказ сервису без метки и без имени.
- **Образцы `angular-patterns-state`, `api-layer-pair`, `platform-access-di` и README хранилища
  учат `@Service()`.** Образец `entity-store` остался на `@Injectable()`: его хранилище даётся
  списком провайдеров экрана, а `@Service()` сделал бы его общим на всё приложение.
- **`@Injectable` без `providedIn: 'root'` и NestJS не тронуты.** Правило их не судит.
- Первый круг ревью нашёл третий пример README хранилища без своего конструктора — скопированный,
  он не собирается; пример получил конструктор.

## Цена

- Образцы пакета правил теперь требуют Angular 22: дерево на Angular 21 по ним не соберётся.
- Перевод `@Injectable()` на `@Service({ autoProvided: false })` не делался: инструмент его не
  судит, это отдельная задача, если понадобится одна метка на всё.
