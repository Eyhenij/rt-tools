# RT-2245 — мутация поля доски стирала статусы карточек, и правила её не называли

**Ветка:** `RT-2245-board-field-mutation` (от `RT-2240-cargo-triage-september`) · **Разобрано:** 2026-09-18

## Просьба владельца

> заводи эпик на разбор жалоб и предложений из приёмника и заводи задачи под каждый груз, бери в рработу в этом рабочем дереве

Ответ владельца о числе задач: «Пять задач, девять отметить». Эта задача пятая в стопке эпика
RT-2240. Груз: разбор `2026-09-14-board-options-recreated-by-api.md`.

## Что было не так

Столбец доски добавили запросом `updateProjectV2Field` с полным списком вариантов. Хостинг
пересоздал все варианты с новыми идентификаторами, статус у 835 карточек стёрся, закрытые ушли в
архив доски рабочим процессом. Ни один текст дерева не говорил, как добавляется столбец, а список
действий «не без слова владельца» правки поля доски не называл.

## Решения

- **Строка о столбце доски — в имена доски файла привязок правила поставки** — там читают, как
  устроена доска этого дерева; сказано и почему мутация губит статусы.
- **Запрос, меняющий поле или варианты доски целиком, — в список «не без слова владельца» файла
  привязок правила `task-flow`** со снимком «карточка — столбец» перед ним. Список лежит там, а не
  у правила о ходе: так говорит сам файл привязок правила о ходе.
- **Случай в холодную часть правила поставки не пошёл** — разложенная копия стояла на пределе в
  330 строк, и одна запись вывела её за предел. Причина мутации записана в файле привязок поставки;
  соседним деревьям этого хостинга она дойдёт следующим разбором, когда холодная часть будет
  разделена.
- **Проверка запросов к хостингу не заводится** — разбор её не просил; список держится памятью
  исполнителя, как и остальные его строки.

## Цена

Две записи в файлах привязок. Холодная часть поставки для этого хостинга стоит на пределе длины —
329 строк из 330 в разложенной копии: следующая запись в неё требует разделения файла.
