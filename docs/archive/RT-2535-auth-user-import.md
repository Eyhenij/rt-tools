# Grill

## The owner request

> изучи как утроен логин на <двух приложениях владельца> - нужно вынести логин в отдельный модуль который можно подключать в приложения

Задача эпика RT-2528, текст карточки:

> У существующих приложений свои пользователи с хэшами паролей разных алгоритмов.
>
> - Инструмент переноса пользователей в Keycloak с хэшами паролей, без сброса.
> - Описано, какие алгоритмы хэша Keycloak принимает без расширений и что делать с остальными.

## What the tree already has

- План эпика: перенос приложений — после модуля, в их репозиториях; эпик даёт инструмент.
- План эпика: пароли приложения Б (argon2) переносятся как есть, для scrypt приложения А путь
  выбирает эта задача. Своих расширений Keycloak на Java нет.
- Стенд Keycloak 26.5.5 с областью `rt` и клиентом `rt-example-admin`, вход администратора стенда
  `admin`/`admin`.

## Проба на стенде

Разовый скрипт во временном каталоге, в дерево не входит:

- pbkdf2-sha256, ключ 32 байта, 27500 повторов: импорт через `partialImport` принят, верный пароль
  даёт токен, неверный — 401.
- argon2id в формате PHC из `hash-wasm` (m=65536, t=3, p=4): то же — принят, верный пароль даёт
  токен, неверный — 401.

## Questions and answers

Вопрос владельцу о scrypt не прошёл проверку разбора дважды. Решение ниже принято по
рекомендованному варианту и названо, чтобы его можно было оспорить на ревью.

## Decisions

- **Пользователь со scrypt, bcrypt или неизвестным хэшем переносится без пароля, с обязательным
  действием «задать пароль».** По флагу инструмент шлёт ему письмо Keycloak со ссылкой. Цена: такой
  человек один раз задаёт пароль заново. Отвергнуто: Java-расширение для scrypt — эпик запретил свои
  расширения, их пришлось бы собирать под каждую версию Keycloak.
- **Отдельный пакет `@rt-tools/auth-import` с командой для терминала.** Приложения живут в своих
  репозиториях и ставят инструмент из npm. В серверный пакет он не идёт: тот подключается в
  NestJS, а перенос запускают один раз из терминала.
- **Хэш принимается строкой PHC (argon2, pbkdf2) или объектом с алгоритмом, солью и повторами.**
  PHC пишут библиотеки argon2 любого языка; объект нужен для pbkdf2, который приложения хранят
  каждое по-своему.
- **Повторный запуск пропускает уже перенесённых.** Иначе он затёр бы пароль, который человек
  успел сменить.
- **Инструмент входит в Keycloak своим клиентом с ролью `manage-users`, секрет — из переменной
  среды.** Секрет в аргументах остался бы в истории терминала.
- **Права переносятся вместе с пользователем** — ролями клиента админки.

## Решения по ходу

- Привязки описания ведут в файлы пакета, которых ещё нет: имена решены до кода.
- SC-AUTH-46 проверяется проверкой стенда, как SC-AUTH-1…5: она не тест и в отчёте описаний
  числится «no test».
- Частичный импорт области требует управления всей областью (на стенде 403 при `manage-users`).
  Люди создаются по одному через API пользователей, роли — привязкой после создания.
- Роли сверяются с ролями клиента в Keycloak, а не по форме из контракта: проверка строже, и пакет
  не ждёт публикации контракта.
- Keycloak 26 требует имя, фамилию и подтверждённую почту; без них он спрашивает их при первом
  входе. Это описано в README и в разделе Data описания.
