# Разбор: пустой вход у вернувшегося посетителя после выкатки темы

## Исходная просьба

Замер на проде 14.10.2026: страница регистрации пустая. На меню способов починки владелец
ответил: «Имя main.js с хэшем».

## Что уже есть в дереве

- Сервер входа отдаёт файлы темы с `cache-control: max-age=2592000`. Путь
  `resources/<версия>/login/rt/dist/` после выкатки темы не меняется.
- Сборка темы `projects/auth-keycloak-theme/project.json`, цель `build-app`, стоит
  `"outputHashing": "none"`. Точка входа зовётся `main.js`, кускам хэш даётся всегда.
- Шаблоны страниц keycloakify собирает из `index.html` сборки. Новое имя файла попадёт в них само.
- Проверка темы в `.github/workflows/deploy-auth.yml` скачивает с прода `main.js` по старому имени.

## Решения

**1. Хэш получают все файлы сборки: `outputHashing: "all"`.** Картинки и шрифты лежат под тем же
кэшем на 30 дней, и правка картинки марки иначе не дошла бы до вернувшегося посетителя.

**2. Проверка темы берёт имя точки входа со страницы входа.** Совпало имя с хэшем, совпало и
содержимое; содержимое сверяется всё равно, как раньше.

## Шесть вопросов

| Вопрос                               | Ответ                                                                                    |

| Требует ли правки закона или правила | нет                                                                                      |
| Одна задача или несколько            | одна                                                                                     |
| Что в задачу не входит               | заголовки кэша на узле входа, путь ресурсов Keycloak                                     |

| Есть ли образец                      | нет, правка одной настройки сборки                                                       |
