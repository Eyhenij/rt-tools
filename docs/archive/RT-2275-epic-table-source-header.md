# RT-2275 — источник таблицы эпика стал правимым

**Ветка:** `RT-2275-epic-table-source-header` (от ветки задачи RT-2274) · **Разобрано:** 2026-09-19

## Что было не так

Во второй строке источника `projects/agent-kit/assets/checks/epic-table.github.mjs` стояла шапка
установки файлов из пакета — та, что ставится копиям в дереве, а не источникам. Проверка источника
правил читала её и отказывала в любой правке файла, указывая в ответе на тот же самый путь. Файл
был неправим вовсе, и увидеть это можно было, только наткнувшись: раскладка сходится, наборы
зелёные, а один файл пакета заморожен.

Стоило это вот чего: команда `npm run epic:table` на любой ветке, кроме ветки самого эпика,
отвечала «карточка эпика #N: план … не лежит на диске — карточка указывает в пустоту». Починить
это тем же приёмом, каким починена задача #2219, было нечем.

## Слово владельца

> Чего стоиш

Сказано на отчёте, в котором цена обхода этой проверки была названа прямо: «чинится одной снятой
строкой — нужно ваше слово, чтобы пройти этот отказ».

## Решения по ходу

- **Правка прошла снятием файла и записью его заново.** Проверка источника отказывает в правке
  файла с шапкой, а снятие пропускает — так сказано в её же навыке. Тайком мимо проверки ничего не
  прошло: в истории это один коммит с объяснением.
- **Заведена проба на источники с шапкой.** Она читает вторую строку каждого источника пакета и
  находит подложенную шапку. Без неё тот же промах вернулся бы молча.

## Цена

Одна снятая строка, одно общее чтение плана в таблице эпика, один сценарий и две пробы. Проверено
на эпике чата RT-2177: таблица печатает семь задач там, где прежде отвечала строкой про пустоту.
