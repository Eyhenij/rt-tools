# RT-3036 — PR показывает чужие коммиты: GitHub не пересчитывает базу после слияния main

Задача RT-3036, ветка `RT-3036-pr-base-refresh` от `main`, 02.11.2026. Работа вне эпика. Папка
задачи разобрана в эту запись.

## Просьба владельца

> обнови гит флоу правила чтобы правильно открывать пр

Перед этим, о PR #3014:

> я вижу в github 153 коммита в этом пр

## Что случилось

1. PR #3014 открыт 31.10.2026 с базой `main`. GitHub запомнил `base.sha` = `35edc2edf`, main
   30 октября.
2. В ветку несколько раз вливали main, потом ветку отправили. PR всё ещё показывал 153 коммита и
   371 файл: GitHub считал их от `35edc2edf`.
3. Сравнение `compare/main...RT-2994-service-block-gap` в ту же минуту отвечало: впереди 30, сзади 0.
4. Повторная установка той же базы (`PATCH pulls/3014 base=main`) заставила GitHub пересчитать PR:
   `base.sha` = `ebc5980ec`, 30 коммитов, 227 файлов.
5. Локальная ветка `RT-2994-service-block-canon` продолжала PR с веткой `RT-2994-service-block-gap`
   и не была с ней связана. Проверка конца хода считала её 30 коммитов неотправленными, хотя все они
   уже стояли в PR.

## Разбор

Владелец в этой сессии трижды подряд брал рекомендованный вариант (макет, копия кита, витрина),
поэтому оставшиеся вопросы закрыты допущением:

- поведение приложения не меняется — это текст слоя правил;
- правится шаблон, закон не трогается: владелец сам попросил править правила git-flow;
- одна задача — оба пункта про PR после пуша;
- новой проверки, которая сама сверяет число коммитов PR, не делается: просили правила;
- готово, когда оба шага стоят в шаблонах с готовыми командами, а проверки пакета зелёные.

## Что сделано

- Шаблон PR (`git-workflow-pr`): после пуша со слиянием базы число коммитов PR сверяется с
  `ahead_by` сравнения веток, а расхождение лечится повторной установкой той же базы. Пункт 13
  проверочного списка требует того же.
- Шаблон коммита (`git-workflow-commit`): локальная ветка, продолжающая открытый PR под другим
  именем, связывается с веткой PR до первого пуша и пушит в неё по имени.

## Чем подтверждено

- `agent-kit:check` — разложенное сходится с пакетом v0.33.1.
- `check-file-size`, `check-descriptions`, `check-specs`, `check-doc-paths`, `check-glossary` — без
  находок.
- Тесты пакета правил `projects/agent-kit/tests/run.sh` — все наборы зелёные, 475 с.

## Что осталось открытым

- Пересчитывает ли GitHub базу сам спустя время — не замерено. Готовая команда от этого не зависит.
