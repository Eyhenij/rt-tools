# RT-2364 — посетитель не узнаёт, что оператор закрыл разговор

**Ветка:** `RT-2364-widget-talk-closed` (от `RT-2367-visitor-talks-and-operator`, эпик RT-2370) · **Разобрано:** 2026-09-30

## Просьба владельца

> бери в работу эпик 2370, перетяни тикет на борде в колонку in progress, создавай ветку и выполняй задачи друг за другом, ветки делай каскадом чтобы при слиянии веток по очереди не было мерж-конфликтов

Задача в очереди: оператор закрывает разговор в панели, а посетитель в виджете об этом не узнаёт
и пишет дальше в разговор, которого никто не ждёт. Решить поведение, дописать его в спеку виджета
и сделать. Набросок в макете: черта «Разговор завершён · 12:50» и поле «Новый вопрос? Напишите
нам».

Владелец отвечал рекомендованным вариантом во всех меню эпика. Меню этой задачи проверка разбора
не пропустила; вопрос закрыт тем вариантом, который меню рекомендовало.

## Решения и куда они ушли

- **Следующая реплика из закрытого разговора заводит новое обращение.** Закрытое остаётся
  закрытым и читается из списка. Ушло в спеку виджета `docs/specs/chat/widget/`. Отвергнуто:
  открывать тот же разговор снова — при списке обращений новый вопрос смешался бы с ответом,
  который оператор уже закрыл. Правило сервиса об открытии закрытого разговора репликой осталось
  для других пишущих.
- **Хранилище помнит минуту закрытия**, открытие снова её снимает. Ушло в спеку чата
  `docs/specs/chat/`.
- **Закрытие доходит до открытого виджета потоком**, отдельным видом события; поток оператора его
  не получает. Ушло в спеку потока `docs/specs/chat/event-stream/`.
- **Кадр закрытого обращения снят на засеве** — закрытое обращение вернувшегося посетителя
  получило постоянную минуту закрытия.

## Что нашлось по дороге

- Вторая реплика любого разговора не уходила из виджета: отправка находила пузырь ленты вместо
  поля по общей метке части. Промах пришёл с RT-2367; исправление ушло туда отдельным коммитом со
  сценарием SC-CH-116 и влито сюда.
