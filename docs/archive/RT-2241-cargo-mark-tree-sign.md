# RT-2241 — команда отметки груза теряет признак дерева

**Ветка:** `RT-2241-cargo-mark-tree-sign` (от `RT-2240-cargo-triage-september`) · **Разобрано:** 2026-09-18

## Просьба владельца

> заводи эпик на разбор жалоб и предложений из приёмника и заводи задачи под каждый груз, бери в рработу в этом рабочем дереве

Ответ владельца о числе задач: «Пять задач, девять отметить». Эта задача шестая, первая в стопке
эпика RT-2240: без неё ни одна отметка не ставилась.

## Что было не так

Команда отметки ввозила функцию признака дерева из модуля отправки собранного пакета, а функция с
коммита 05689b9f0 живёт в модуле tree-mark. Ошибка ввоза глоталась, признак уходил пустым, и
приёмник отвечал 400 «признак дерева в грузе принадлежит другому дереву» на каждую отметку. Тест
SC-AK-558 считал эталон тем же ввозом с подавленным stderr и сравнивал две пустые строки.

## Решения

- **Признак берётся из tree-mark, а не из модуля отправки** — там функция объявлена. Отклонено: свой
  счёт в команде — вторая копия, что уже расходилась.
- **Пустой признак — отказ до сети с названной причиной** — молчаливый пустой признак и дал 400.
  Отклонено: предупреждение и отправка — приёмник всё равно откажет.
- **Тест проверяет признак положительно** — двенадцать шестнадцатеричных знаков, потом равенство.
- **Отметки девяти записей поставлены этой же задачей** — как проверка на живом приёмнике: путь
  new → in_work → fixed → released 0.29.0, потому что приёмник не пускает через состояние.

## Цена

Одна строка ввоза, один отказ до сети, два теста, статья с привязкой и сценарий SC-AK-1130. Набор
команды отметки вырос с 34 до 37. Первая попытка отметок из состояния new в fixed отклонена
приёмником: порядок состояний не обходится, и записи прошли через «в работе».
