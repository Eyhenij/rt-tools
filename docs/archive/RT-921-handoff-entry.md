# Вход в работу из передачи захода

Задача #921, PR #928, закрывалась 19 августа 2026 года. Запись собрана из разбора просьбы и
решений по ходу, когда задачу закрывали. После выкатки не правится. Прежний адрес —
`docs/tasks/RT-921-handoff-entry/`.

## Просьба владельца

> каждая новая сессия которая начинается с handoff файла обязана следовать task flow, предложы
> оптимизированный вариант рабочего процесса для таких случев

## Что уже есть в дереве

- Передача захода лежит вне дерева и пересказывает состояние работы для вставки в новый заход.
- Хук запуска сессии отдаёт замысел и ход работы целиком, а разбор просьбы — путём.
- Паттерн возвращения к работе называет, что уже пришло в контекст и чего не спрашивать у
  владельца.

## Что уже сказано в правилах

- Число из передачи пересчитывается на текущем коммите: она описывает день, когда её писали.
- Рамка переданного текста на текущее дерево не переносится.
- Состояние работы объявлено строкой в ходе работы, и гард читает её.

## Вопросы и ответы

**Что владелец назвал промахом?** Сессия, начатая с передачи, берётся за работу мимо правила:
состояние не сверяется с деревом, правило и паттерн возвращения не грузятся.

**Каким должен быть вход?** Коротким: владелец просил оптимизированный порядок, а не ещё один
обряд.

## Решения по ходу

- **19 августа 2026. Вход из передачи стережёт гард, а не порядок в тексте.** Порядок,
  записанный только словами, исполняется, пока о нём помнят; передачу читают как задание и
  берутся за работу мимо правила. Затронутый этап: 2.
