# RT-3404 — конец эпика доходит до PR эпика без отметки последней задачи

Задача RT-3404, запись от 2026-11-19.

## Просьба владельца

> продолжай работу по эпику

Постоянное указание владельца по эпику RT-3302. Карточку завела роль `product-strategist` при
проверке RT-3395: после слияния последней задачи эпика движок не доходил до PR эпика. Выход 12
ждал слово «влито» у каждой неотложенной задачи, а ставит его ветка следующей задачи, и у последней
её нет. Ход стоял в `влито`, отпускало только меню владельца.

## Что нашли

- Выход 12 читал влитость только из слова в плане эпика и не сверял его с хостингом.
- Последней вливается не обязательно последняя строка плана: RT-3392 (строка 11) влилась после
  строк 12 и 13.
- В плане эпика RT-3392 так и стояла «идёт», хотя её PR #3411 влит.

## Что сделано

- Слово «влито» нужно каждой задаче с влитым PR, кроме влитой последней по времени слияния и задачи
  последней строки: им ставить отметку нечем.
- «Влито» у задачи с открытым PR или с PR, закрытым без слияния, держит выход 12; отметка без PR в
  окне хостинга засчитывается, как раньше.
- Верхняя ветка цепочки отмечает нижние задачи заранее, если цепочку вливают одним заходом.
- Выход 11 не держит неотмеченную задачу с влитым PR, чью ветку хостинг удалил.
- Свежая ветка без PR влитой не считается.
- Действие состояния `влито` и шаблон `task-flow-resume` называют слияние цепочки снизу вверх.
- Сценарии SC-AK-1752, SC-AK-1753, SC-AK-1754; второй случай SC-AK-1391 переписан.
- RT-3392 отмечена «влито» в плане эпика.

## Решения

- Влитость берётся по влитому PR, а не по вершине ветки в ветке эпика: свежая ветка следующей
  задачи стоит на вершине эпика и иначе засчиталась бы влитой.
- Правило карточки об отметке сохранено: проверка вопросов отклонила вариант «хватает влитого PR».
  Цепочки этого эпика вливали и сверху вниз (#3405 → #3403), поэтому освобождена и последняя строка.
- По слову владельца 19.11 в надстройку правила `task-flow-owner` добавлен раздел: работу по коду и
  задачам ведёт агент, шаг «за владельцем» делает исполнитель.

## Что не доделано

- Хостинг отдаёт последние 300 влитых PR. Задача, влитая раньше, считается по своему слову, как до
  этой работы.
- `measure` останавливается на первом невыполненном выходе и на ветке задачи до выхода 12 не
  доходит; выход 12 на настоящем эпике читался отдельным вызовом.
