# RT-408 — слеш-команды пакета названы в его описании

Задача #408, отчёт открыт этой же работой. Запись собрана при закрытии задачи; после выкатки
не правится.

## Просьба владельца

> где описано какие команды доступны? например /next-session - где это описано?

и следом, на ответ:

> опиши это в readme.md у agent kit

## Что уже сказано в правилах

- **Скил `agent-kit`** называет команды строкой запуска (`doctor`, `sync`, `stats`, `propose`),
  но о слеш-командах агента говорит только в разделе про обратную связь — и то одной строкой
  про `/skill-curator` и `/agent-kit-digest`.
- **Правило `doc-style`** — правка едет в том же коммите, что и документ, который её описывает;
  формулировки — паттерн `doc-style-write`.
- **Правило `spec-driven`** — README пакета документом-спеком не является: обязательных
  разделов у него нет, привязок он не требует.

## Вопросы и ответы

Работа мелкая и предметом не спорная, поэтому шесть обязательных вопросов закрыты чтением, а не
разговором; спрошенное владельцем — сам предмет.

**Меняет ли задача поведение приложения.** Нет. Правится README пакета — текст для человека;
ни ресурсов, ни кода, ни раскладки правка не задевает. Договорённость о продукте поэтому не
пишется, обход объявлен в замысле.

**Требует ли правки закона или правила.** Нет. Скил `agent-kit` о командах уже говорит там, где
это нужно агенту; здесь дописывается README, который читает человек.

**Одна задача или несколько.** Одна: один раздел в одном файле.

**Чем будет видно, что задача закрыта.** В README есть раздел, из которого видно все три
команды, где они лежат в дереве, чем задаётся имя команды и как её править.

**Есть ли образец.** Есть: соседние разделы README — «Роли и конвейеры», «Проверки», «Хуки»:
таблица рода ресурса плюс проза о том, чем он живёт.

## Решения

- **Команды выносятся в свой раздел, а не дописываются в «Роли и конвейеры».** Тот раздел про
  субагентов и прогоны из них; две команды стояли в его хвосте потому, что своего места у них не
  было. Пересказ оттуда переезжает целиком — иначе одно и то же будет написано дважды.
- **Список команд в README не заводится вторым перечнем.** Имя команды задаёт имя файла, и
  таблица README называет ресурсы пакета, а не объявляет команды: разойтись с каталогом она
  может, объявить несуществующее — нет.

## Решение по ходу

- **Папка задачи заведена, хотя работа мелкая.** Гард замысла судит по путям правки, и
  `projects/**` для него код: правка описания пакета без замысла на диске отбивается. Обход
  требования договорённости объявлен строкой поведения — описание поведения пакета не меняет.
- **Папка разобрана до открытия отчёта, а не после разбора.** Владелец сливает отчёты сразу,
  и папка, оставленная до слияния, уехала бы в главную ветку — так уже было с RT-400.
  Понадобится правка по замечаниям — замысел восстанавливается на диске на время правки.
