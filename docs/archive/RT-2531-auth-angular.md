# Grill

## The owner request

> изучи как утроен логин на <двух приложениях владельца> - нужно вынести логин в отдельный модуль который можно подключать в приложения

Задача эпика RT-2528, текст карточки:

> Админке нечем войти через Keycloak и держать сессию.
>
> - Angular-пакет: вход по OIDC с PKCE, токены только в памяти, восстановление сессии после перезагрузки, ответ 401 обновляет токен и повторяет запрос один раз, выход через Keycloak.
> - Проверки маршрутов по входу и по праву, скрытие пунктов меню по правам.
> - Точка подключения «текущая организация».

## What the tree already has

- Контракт `@rt-tools/auth-contract`: `callerFromClaims`, `hasPermission`, `hasEveryPermission`,
  `hasSomePermission`, `definePermissions`. Клиент читает права тем же кодом, что и сервер.
- Стенд Keycloak: клиент `rt-example-admin` публичный, PKCE S256, адрес возврата
  `localhost:4210`, вход по паролю через токен запрещён.
- Вход админки приёмника — свой: форма, cookie сессии, проверка маршрута, перехват истёкшей
  сессии (`libs/message-bus-admin/auth/`). Его модуль не заменяет: перенос — после эпика.
- Сборка Angular-пакета — ng-packagr, как у `projects/ui-kit-v2`.

## What the rules already say

- План эпика: права живут в Keycloak ролями клиента, организации — в базах приложений; модуль
  даёт только точку подключения «текущая организация».
- Разбор эпика: токен в localStorage отпадает — он доступен скриптам страницы.

## Questions and answers

Новых вопросов владельцу нет: карточка задачи называет всё, что пакет делает. Решения ниже приняты
по умолчанию и названы, чтобы их можно было оспорить на ревью.

## Decisions

- **Протокол ведёт официальный адаптер `keycloak-js`.** Он держит токены в памяти, делает PKCE,
  тихую проверку входа и обновление токена. Отвергнуто: свой разбор OIDC — это повтор адаптера с
  его ошибками; `angular-oauth2-oidc` — по умолчанию кладёт токены в sessionStorage.
- **Сессия после перезагрузки восстанавливается тихой проверкой входа в Keycloak.** Страница
  тихой проверки лежит в пакете, приложение публикует её своей статикой. Токен в браузерном
  хранилище не кладётся.
- **Пакет `@rt-tools/auth-angular` даёт:** подключение одним вызовом, службу с сигналами
  «кто вошёл» и «его права», перехватчики HttpClient и Connect, проверки маршрутов по входу и по
  праву, директиву показа по праву.
- **Ответ 401 обновляет токен и повторяет запрос ровно один раз.** Второй 401 уводит на вход.
- **Текущая организация — токен, который приложение заполняет само.** Пакет читает из него
  значение и кладёт его в заголовок запроса; имя заголовка задаёт приложение.
- **Права читаются функциями контракта** по клиенту админки.

## What is left unclear

- Живой вход через браузер на стенде проверяет RT-2534 вместе с примером админки. Здесь адаптер
  подменяется двойником в тестах.

## Решения по ходу

- Привязки описания ведут в файлы, которых ещё нет: проверка описаний называет их до этапов 3–5.
  Так записано сразу, чтобы имена файлов пакета были решены до кода.
- Перехватчик Connect — во втором входе пакета `@rt-tools/auth-angular/connect`: админке без
  Connect он не нужен.
- `@rt-tools/auth-contract` попал в манифест пакета после выхода версии 0.1.0 в npm; до неё код и
  тесты брали контракт из исходников дерева.
- Публикацию контракта из ветки RT-2530 (в ней уже есть строка lockfile) запретил классификатор.
  Публикация остаётся за владельцем.
- Пробное слияние 2026-10-06: ветка эпика + #2543 + #2544 сливаются; #2544 после #2543 даёт
  конфликты в `package.json` (скрипты стенда), плане эпика и `pnpm-lock.yaml`. Эта ветка правит те же
  три файла и описание доменов: после слияний в неё вливается ветка эпика, конфликты решаются здесь.
