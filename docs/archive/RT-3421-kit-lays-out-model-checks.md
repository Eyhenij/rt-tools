# RT-3421 — раскладка пакета пишет в настройку дерева записи двух модельных проверок

Задача RT-3421 эпика RT-3302, запись от 2026-11-20. Прежний адрес: `docs/tasks/RT-3421-kit-lays-out-model-checks/`.

## Просьба владельца

> я ухожу спать, переключайся в ночной автономный режим, доведи все задачи эпика до завершения и сам эпик до пр в main

Слово владельца от 19.11.2026; задача — строка 20 плана эпика RT-3302. Карточку завели роли
`product-strategist` и `goal-critic` при разборе RT-3276: выпуск пакета снимает восемь проверок
разговора у деревьев, которые его ставят, а две модельные проверки, пришедшие на их место, в настройку
дерева не записываются. После выпуска там не остаётся ничего. Карточка просит, чтобы раскладка
записывала обе проверки в настройку, и чтобы после раскладки в чистое дерево обе стояли в ней.

План одобрен владельцем 20.11 ответом «Одобряю plan.md RT-3421, модель остаётся (Recommended)». Прежний
ответ «Одобряю RT-3420 и RT-3421» движок не принял: отметка пишется только по ответу меню после ролей.

## Что нашли

- Раскладка читала объявления только у скриптовых гардов, у модельных объявлений не было вовсе.
  Записи двух проверок в настройке этого дерева стояли написанные руками.
- Две роли прочли план до одобрения и нашли пробелы: требование к хосту, смешанное состояние при
  перенесённом каталоге хуков, замер секунд, который стоил бы вызовов модели без пользы, и модель,
  зашитая в запись каждого потребителя.

## Что решили и почему

- **Проверка объявляет себя строкой-комментарием в своём файле.** Событие, образец, предел, модель и
  слова вызова. Список проверок в коде раскладки разошёлся бы с набором файлов на первой же новой
  проверке. Комментарий разметки, а не заголовок: модель, читающая файл, не должна считать его текстом.
- **Запись не идёт через диспетчера.** Дерево, не взявшее его, получает записи тоже; перенесённый
  каталог хуков называется в записи по новому пути.
- **Стоящая запись не дублируется и не переписывается.** Отличия называются обеими сторонами. Другие слова,
  другой образец и предел ниже объявленного отказывают проверке раскладки; другая модель и больший
  предел только называются, чтобы дерево без доступа к модели осталось зелёным.
- **Модель остаётся в объявлении судьи конца хода.** Судья мерился на ней. Цена ошибки — одно поле
  объявления. Решение принято владельцем отдельным ответом.
- **Файл без записи отказывает проверке раскладки и называет имя для `skip`.** Хост без хуков вида
  `agent` выходит из отказа списком отказа.
- **Код вынесен в новый файл `agent-checks.ts`.** В `hooks-map.ts` уже 405 строк, линтер держит 500.
- **Замер медианы секунд убран из плана.** Объявление — один комментарий.

## Чем подтверждено

- Раскладка настоящего пакета в пустое дерево: обе записи вида `agent` с первого раза, вторая раскладка
  ничего не дописала, проверка о модельных проверках молчала.
- Сценарии SC-AK-1766–1774 зелёные, записи, собранные из настоящих файлов, равны записям этого дерева.
  Набор `commands.spec.ts` — 86 ok. Повтор записанных ходов — 97 ok.
- Два круга ревью по трём ролям. Второй круг нашёл настоящий пробел: зелёная проверка молчала о расхождениях
  «только названо», хотя описание обещало; найдено ещё и своим тестом.

## Цена

- Записи пишутся только в `.claude/settings.json`: запись в другом файле настроек не видна и дублируется.
- Старая запись после переноса каталога хуков остаётся и не называется.
- Раннего выхода раскладки при отказе в других файлах отдельный сценарий не держит: смешанное состояние держит
  SC-AK-1774.
- Пока владелец не выпустил пакет, «задача достигла вехи» верно только для этого дерева.
- Параллельные запуски `commands.spec.ts` два раза оставляли в `projects/agent-kit/assets/laws/delivery.md`
  обломок теста; файл возвращён из коммита. Причина — пять одновременных измерений шагов, которые пишут один
  и тот же ресурс. Это отдельная находка, задачей не заведена.
