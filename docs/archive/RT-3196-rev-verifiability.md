# RT-3196 — ревизия семьи закона о проверяемости

Задача RT-3196 эпика RT-3227, PR #3224, ветка `RT-3196-rev-verifiability`, база — ветка эпика
`RT-3227-agent-kit-revision-day1`, 12.11.2026. Папка `docs/tasks/RT-3196-rev-verifiability/`
разобрана в эту запись.

## Просьба

Слово владельца: «заведи новый эпик на актуализацию обвязки agent kit и разбей на задачи. нужно
сделать ревизию всей документации, правил и скилов в agent kit. так же нужно начать с построения
графа graphify для каждого из проектов в этом репозитории, если это будет необходимо - построить
некое подобие графа для понятий и правил в agent kit». На вопрос, как делить ревизию и когда
править: «По семьям законов, правки сразу».

## Что сделано

Семья — закон `verifiability`, правила `testing` и `browser-verification`, четыре паттерна
(`testing-unit`, `testing-e2e`, `browser-verification-stand`, `browser-verification-measure`) и
холодный файл `testing`. Её прочитала роль `rules-reviewer`, второй агент сверил статьи обоих
правил с привязками в компаньонах и с кодом. Правки внесены в исходники пакета и разложены.

## Находки и чем закрыты

Роль `rules-reviewer`, расхождения закона и правила:

- Правило разрешало дописывать в список известного проверки «по слову владельца», закон —
  только сокращать. Правило приведено к закону.
- Правило отправляло спорную красную проверку владельцу, закон говорит, что вопрос владельцу —
  не выход. Теперь: правится код, а сломанная проверка правится сама, разбором, который называет
  закон.
- Закон: сломанная проверка работу не останавливает. Правило: при ненастроенном профиле Chrome
  браузер не открывается. Вопрос владельцу, ответ: «Не открывать браузер (Recommended)». Роль
  нашла слово владельца от 13.10 в надстройке дерева: «если открыт все один браузер то открывать
  его». Второй вопрос — что делать, когда профиль не настроен, а браузер подключён один. Ответ:
  «Открывать его (Recommended)». Правило оставлено, надстройка тоже, исключение названо в
  привязке. Оговорка в статью закона закон в ветке не меняет. Её текст:

    > A check that is not configured is not a broken one: where the target of an action cannot be
    > told apart without it, the action waits until the owner configures it.

Роль, расхождения внутри семьи:

- Частичное покрытие требовалось от любого теста не по пути человека, а статья ниже — только для
  обещания человеку. Статья и схема уточнены.
- Правило велело брать уже поднятое приложение, паттерн — стенд с ветки правки. Правило теперь
  говорит, что поднятое берётся, только если собрано с этой ветки.
- Вход на экран: правило делало подменённый ответ входа основным путём, паттерн — запасным.
  Теперь основной путь — форма с засеянной учётной записью стенда.
- Замер при смене числа элементов: одна ширина против всех порогов раскладки. Везде все пороги с
  обеих сторон; в паттерне замера наборы ширин стали образцом, а пороги берутся из дерева.
- Схема `testing` вела выключенный переменной тест в «не покрытие», паттерн — в частичное
  покрытие с причиной. Схема приведена к паттерну.
- Ловушка велела повторить прогон после установки браузера и верить второму; другая ловушка и
  правило — что упавший и прошедший отдельно тест нестабилен. Первая ловушка исправлена.
- Ссылка на «правило `testing`» вела в холодный файл, мёртвая ссылка `Q-FA-1` убрана; та же
  ссылка в правилах `angular-patterns` и `component-structure` записана в карточку RT-3198.
- В переносимых текстах стояли пути одного дерева — заменены заполнителями; «main» для ветки
  задачи — база; русские отметки покрытия — английские с прежними как допустимыми.

Роль, пробелы: у статей закона о тесте до кода, о правке без красного, о возврате общего
состояния, о пустом вводе, о сказанном списке проверок и о разборе сломанной проверки нет
исполнителя — они названы в разделе правила о том, чего закона здесь нет. Набор перед push и
снятая проверка — правило `git-workflow`, пороги раскладки — `browser-verification`.

Роль, повторы: шестнадцать почти дословных пар внутри семьи. Текст остался там, где
принимается решение, вторая сторона ссылается на него. Отчёт графа считает другие пары —
повторы статей между ресурсами пакета; там у семьи одна пара, закон и правило о выключателе
переменной, и она оставлена: так устроен слой.

Сверка привязок с кодом: в `testing` верны были 27 строк из 42, в `browser-verification` — 19 из 23.

- Отметки «не проверяется» сняты там, где аудит спеков уже отказывает: сценарий без теста,
  частичное покрытие, ссылка теста на несуществующий сценарий, прямой вызов приёмника из набора.
- Ложные привязки заменены настоящим исполнителем или честной отметкой: помощник навигации
  вместо проверки экрана, константа пароля вместо проверки выключателей, проверка слога для
  файлов тестов, самодельная раздача стенда вместо настоящего прокси Caddy, разбор списка
  известного без проверки его первого поля.
- Символы названы в файлах, где объявлены; факты о дереве исправлены: девять приложений, отметки
  непокрытого в `scenarios.md`, а не в `UI-KIT-V2-ISSUES.md`, набор конвейера, эталоны снимков в
  истории. Перебор историй проверка браузера отказывает только при прямом запуске файла; через
  команду пакета `pnpm run test:stories:v2` она его не видит.
- Набор примера входа не стоял в `e2eRoots`, и его тесты считались модульным покрытием — добавлен.
- Надстройка паттерна сквозных тестов называла один набор — теперь оба.
- Надстройка `testing` говорила, что у китов нет нумерованных сценариев, — исправлено.

Что править в этой ветке нельзя, ушло в задачи: оговорка в законе — RT-3258, расхождения хуков и
проверок с правилами — RT-3259. Проверку второго экземпляра дерево выключило решением, это не долг.

## Первый круг ревью PR

Четыре роли прочли ветку на вершине `339b2da8d`: ревью кода, `project-manager`,
`product-strategist`, `goal-critic`. Исправлено:

- Схема правила `testing` вела сценарий с обещанием человеку, закрытый вызовом, не в ту сторону:
  вопрос узла перевёрнут, теперь схема и статья говорят одно.
- Схема правила о браузере велела останавливать экземпляр, собранный из другой ветки. Теперь у
  узла три выхода: свой экземпляр используется, чужой остаётся и стенд идёт на свободный порт,
  остаток прошлого запуска останавливается.
- Надстройка `testing` носила имя раздела пакета и стирала его целиком: из семи статей, которые
  держит только автор, в разложенном правиле оставалось четыре. Раздел надстройки переименован,
  раздел пакета вернулся.
- Надстройка паттерна стенда не читалась при ревизии и была неверна в трёх местах: порт 6007
  занят витриной второго кита, стендов три вида, прокси у дерева есть — Caddy, но ни один стенд
  его не поднимает.
- Надстройка о браузере теперь называет две статьи правила, которые она ограничивает.
- В описании привязок правила о браузере два ложных утверждения: отставание от ветки эпика
  проверка судит; перебор историй отказывается только при прямом запуске. Замер там же назван на
  всех порогах, а не «на узком экране».
- В описании привязок `testing`: привязки по номеру строки заменены символами; выключенный тест
  сценария без человека по-прежнему считается покрытием — названо непроверяемым; две проверки,
  которые сами предлагают список известного, названы.
- Ловушка о первом запуске после установки браузера озаглавлена по своему тексту; соседняя не
  ссылается на убранную фразу.
- В переносимых текстах заменены имена одного дерева и две русские строки в образцах. Слова
  «doors», «goes blind», «taciturn», «serves the past» заменены прямыми.

## Второй круг ревью PR

Те же четыре роли на вершине `660110819`. Исправлено:

- Правка схемы браузера из первого круга повторила имя узла, и схема слила два узла в один. Узел
  переименован.
- Описание привязок о занятом порте спорило с исправленной статьёй — приведено к ней.
- Нумерованные сценарии есть не у каждого домена: у `core` и `store` только предложения.
- Надстройка стенда: сервер входа общий для обоих стендов и поднимается `pnpm run serve:auth`;
  стенд примера входа поднимает `up.mjs`; витрины отдаёт свой сервер разработки.
- Надстройка паттерна сквозных тестов давала рецепт, который падает: набор поднимает стенд сам, а
  поднятый заранее занимает его порты. Команды названы как два разных пути.
- Правило `testing` называло счёт одного дерева — «в шестидесяти пяти местах». Убрано.
- Набору нужен только запущенный Docker: базу и сервер входа он поднимает сам.
- Статья о вызове процедуры сквозным набором была привязана к примеру, который ничего не
  запрещает. Теперь она названа непроверяемой; статей семьи «на памяти» стало 25, было 26.

`AuthService/GetMe` и `CACHE_REFRESH_URL` в образцах паттернов оставлены как примеры.
