# Десять шагов набора шли на любую правку

Задача RT-3296 · эпик RT-3293 · запись от 13.11.2026

Папка задачи лежала по адресу `docs/tasks/RT-3296-always-run-steps/`.

## Просьба владельца

> исправляй флоу проверок чтобы не гонять лишнее

> переноси в новый эпик все задачи которые не были сделаны в текущем

План одобрен словами «Одобряю, делай».

## Что было

После RT-3273 набор запускал шаг, только если правка задевает то, что шаг читает. Десять шагов
шли на любую правку: отбор не видел их чтений, потому что они запускали npm, npx, prisma, bash или
читали историю git. На правке одних текстов они шли все, вместе около 30 с.

## Что сделано

- Вызов npm, npx, pnpm или bash связан со своей записью чтений меткой в окружении.
- Бинарник пакета, запущенный прослеженным процессом, читает то, что ему передал этот процесс.
- Копирование файла и загрузка модуля считаются чтением.
- Обход каталога — список одного каталога, а не дерева под ним. Новый каталог под таким списком
  по-прежнему запускает шаг.
- `git log` и `git diff` с путём после `--` читают историю этого пути.
- bash записывается ловушкой `DEBUG` с подставленными словами команды.
- `check-kit-approval` объявляет фильтр правки той же функцией, которой фильтрует.
  `check-archive-age` объявляет, что идёт на каждую правку: он считает дни.

## Решения по ходу

- **Обход корня делал шаг видимым для всего дерева.** `agent-kit:check` шёл на любую правку, потому
  что `pnpm` при старте читает список корня, а любой обход считался рекурсивным.
- **Без обхода корня всплыли пропущенные чтения.** Сборка пакета копирует правила через
  `copyFile`, и правка правила перестала запускать `agent-kit:check`. Копирование и загрузку модулей
  пришлось записывать.
- **Новый каталог миграции чуть не пропал из отбора.** Prisma читает список `prisma/migrations`, а
  файлы внутри открывает напрямую. Добавление в глубине каталога задевает шаг, если в его списке
  появилась новая строка — это сверяется с базой.
- **bash 3.2 не умеет писать трассировку в свой файл.** Ловушка `DEBUG` пишет сама. Перенаправление
  `<` у цикла она не видит: такой файл делает шаг слепым, и шаг идёт на каждую правку.
- **Запись идёт без кэша графа nx.** Из кэша nx не грузит плагины и читает меньше файлов: сверка
  таблицы краснела сразу после того, как prettier переписал таблицу и сбросил кэш.
- **Фильтр правки не пишется списком рядом с проверкой.** Отбор зовёт ту же функцию, которой
  проверка фильтрует сама, поэтому они не разойдутся.

## Цена

- На правке текстов из десяти шагов идут два: `check-archive-age` (дни) и `tools/tests/run.sh` —
  его план не трогал, он выбирает свои наборы сам и идёт 1 с.
- Правки, которые задевают шаги, их запускают: спека — `check-specs`, хук — `check-hooks`, схема и
  новая миграция — `check-schema-drift`, правило пакета — `agent-kit:check`, видимый файл кита —
  `check-kit-approval`.
- Таблица чтений выросла: обходы теперь названы по каталогам.
- Шаг bash, который читает файл через подстановку внутри `$(…)` с перенаправлением, по-прежнему
  виден только через сверку таблицы.
