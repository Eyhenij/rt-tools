# Съёмка витрины ждёт компонент, чья начинка приезжает позже первой отрисовки

Задача RT-833, PR #836; заведена посреди чужой работы — один и тот же снимок валил прогоны всех
открытых PR.
Прежний адрес записи — `docs/tasks/RT-833-snapshot-waits-for-mount/`.

## Просьба владельца

> смотри конфликты в твоих пр, сейчас ни один пр не может быть вмержен - это либо драфты либо
> конфликты? где результат твоей работы за 2 дня? ни один пр не готов!

Шесть обязательных вопросов владельцу не задавались: работа взята по прямому слову о том, что
ни один PR не готов, а предмет её — обвязка проверки, не поведение продукта. Единственный
вопрос, который потребовал бы ответа, — пересъёмывать эталон или чинить ожидание — закрыт
правилом проверяемости этого дерева.

## Что было верно на день работы

- Обвязка снимков второй витрины ждала шрифты и набор значков, глушила движение и добирала
  отсчётом в 150 мс.
- Показ редактора поднимает Quill динамическим импортом уже после первой отрисовки, и обвязка
  успевала снять кадр раньше: `Components/RichEditor › Toolbar` выходил 1248×109 при эталоне
  1248×291.
- То же расхождение приходило в трёх прогонах конвейера на трёх разных ветках — то есть валило
  чужую работу, а не свою.

## Решения и куда они ушли

| Решение                                                           | Куда ушло                                                                   |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Эталон не пересъёмывается                                         | решение захода: пересъёмка узаконила бы пустой кадр и сняла историю с учёта |
| Ожидание идёт по событию, а не удлинением отсчёта                 | обвязка снимков второй витрины                                              |
| Компонент, чья начинка приезжает позже, объявляет свою готовность | показ редактора и его спека                                                 |
| Договорённость о снимках дописана сценариями                      | поддомен снимков второго кита — спек, сценарии и привязки                   |

## На чём споткнулись

Отсчёт в 150 мс выглядел ожиданием и им не был: на свободной машине он успевал, на занятой —
нет, и какой именно кадр не успеет, решала загрузка. Пока ожидание идёт по времени, зелёный
прогон означает «машина была свободна», а перезапуск, давший зелёное, этого не отменяет, а
прячет.
