# Один номер сценария снова означает один сценарий

Задача RT-726, PR #730; папка разобрана 16 августа 2026 года последним коммитом той же ветки.
Прежний адрес записи — `docs/tasks/RT-726-orphan-proposed-feedback-loop/`.

Просьбы владельца за этой работой нет: дефект замечен замером посреди соседней задачи и заведён
задачей тем же движением. Две ветки, шедшие рядом, выдали своим сценариям одни и те же номера
`SC-AK-152`…`SC-AK-158`; одна влилась, у второй те же номера остались в директории
договорённости. По номеру после этого находились два разных сценария с разным смыслом, а
заголовки тестов при них разошлись.

Куда ушло каждое решение:

- **какую сторону двигать** — двинута та, чьи сценарии живут только в директории
  договорённости: у влитой номера уже стоят в заголовках тестов главной ветки;
- **новые номера** — `SC-AK-231`…`SC-AK-237`, и заголовки шести тестов правлены тем же
  изменением;
- **директория остаётся** — вливание сделано наполовину, девять сценариев не влиты вовсе, и на
  шесть из них ссылаются живые тесты. Полное вливание заведено задачей RT-729.

## Решения по ходу и их доводы

- **Границы работы пересмотрены на первом же чтении состава.** Замысел писался по замеру,
  который показывал три двойных номера, и требовал удалить директорию. Чтение показало другое:
  удаление стёрло бы описание работающего кода. Замер сказал, что что-то не так, но не сказал,
  что именно, — состав читается до того, как замысел объявляет способ.
- **Свободный диапазон номеров считается после вливания главной ветки, а не до него.** Первый
  выбор `SC-AK-211`…`217` столкнулся с договорённостью соседней задачи, приехавшей вливанием
  посреди работы, — то есть повторил ровно ту ошибку, которую эта работа чинила.

## Чем кончилось

Сверка спеков перестала печатать десять строк из 213. Остальные 203 — долг главной ветки, и эта
работа их не трогала.
