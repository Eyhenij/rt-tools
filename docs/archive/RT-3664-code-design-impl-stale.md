Задача вышла из шага, который владелец велел сделать: довести эпик RT-3603 до главной ветки и выпуска кита. Ответ

## Что решили при разборе

- **Переписываются семь строк `.claude/skills/code-design/implementation.md`:** четыре называли проверки раздела
  «Решение» будущими задачами RT-3610 и RT-3611, три несли ложную пометку «Not checked by anything». Пометка
  остаётся у трёх статей, которые ничто не проверяет: чтение кода, одна обязанность модуля, одно решение в одном
  модуле.

## Что решили по ходу

- **План записан дважды.** Первая запись называла четыре строки и проверку `node tools/check-specs.mjs`. Обе роли на
  плане нашли семь строк, а `plan-red` отказал: `check-specs` зелёный и до работы. Коммиты плана не были отправлены,
  они отмотаны через `git reset --soft`, план записан с двумя признаками в шагах и одобрен владельцем заново.
- **Строка 31 называла `held` за касание путей следа.** Касание делает `tools/task-flow/measure/footprint.mjs:touched`,
  только у строк с пометкой «(правится)». Нашли все три роли первого круга.
- **Строки обещали больше кода.** «Решения нет» заменяет таблицу и в конце этапов отказывает каждому новому файлу и
  символу; «паттерна нет», «номера нет» и «ввода нет» снимают требования; порог строки — два слова; «до N»
  сравнивается с длиной файла; любое расхождение `held` снимается строкой решений.
- **Тот же устаревший факт в `.claude/skills/task-flow-plan/implementation.md`** — вне условий плана, своя задача
  эпика следом.
