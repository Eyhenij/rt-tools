## Что было не так

`git reset --hard` снёс незакоммиченные правки соседней сессии в семи файлах; в объектах гита их
не было. Ни одна проверка пакета не судила разрушительные команды, а правило поставки не говорило,
что снятие коммита — это `--soft`.

## Что сделано

Проверка `git-guard-discard.sh`: `reset --hard`, `checkout -- <путь>`, `restore <путь>`,
`clean -f` при непустом дереве отбиваются с перечнем файлов; обход — `# discard: <причина>`.
Статья в трёх вариантах правила поставки; спека `docs/specs/agent-kit/discard-guard/` с пятью
сценариями.

## Почему так, а не иначе

- **Обход — комментарий в команде** — флаг сломал бы саму команду гита; так же устроен обход
  проверки папки задачи. Спросить было некого: сессия автономная.
- **`clean` судится по неотслеживаемым файлам, остальные — по изменённым отслеживаемым** —
  каждая команда теряет свою часть дерева; один список отбивал бы `reset --hard` на дереве,
  которого он не трогает.
- **Спека — свой поддомен, а не раздел `delivery-gate`** — файл сценариев соседа стоит у предела
  длины (492 строки).
