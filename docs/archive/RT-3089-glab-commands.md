# RT-3089 — сторожа хода узнают команды glab

Задача RT-3089, ветка `RT-3089-glab-commands` от ветки `RT-3091-skip-hosting-variant`, работа вне
эпика по слову владельца. Папка задачи `docs/tasks/RT-3089-glab-commands/` разобрана в эту запись.

## Просьба владельца

> если по текущей открыт пр то бери след задачу, только сначала удали влитые ветки, и проверь перетащились ли тикеты куда нужно

Постоянное поручение: когда PR по текущей задаче открыт, следующая задача вне эпика берётся без
вопроса. В очереди RT-3089 звучит так: в дереве на GitLab четыре сторожа пакета правил ждут только
команд `gh`. Снятие черновика и чтение конвейера через `glab` не засчитываются, открытая через
`glab` заявка не считается отданной работой, утверждения о слиянии и конвейере не подтверждаются
командами `glab`, а перезапуск задания `glab ci retry` проходит без прочитанного журнала.

Во время работы владелец сказал: «после этой задачи стоп» — следующая задача не берётся.

## Решения по ходу

- **Формы `glab` стоят рядом с формами `gh` в тех же образцах, а не в профиле дерева.** Так уже
  был устроен образец открытия заявки, а слово в профиле — ещё одна настройка, которую забудут.
- **Сторож перезапуска узнаёт `glab` при любом клиенте профиля.** Перезапуск второго клиента
  узнаётся по своим словам `ci retry`, и две формы не пересекаются.
- **По ревью статьи разложены по своим поддоменам.** Сторож ожидания продлевает SC-AK-583, выход
  из хода — SC-AK-296, SC-AK-298, SC-AK-647, SC-AK-880, перезапуск — SC-AK-411 и SC-AK-412. В
  утверждениях хода осталась своя часть, сценарий SC-AK-1270. Номер SC-AK-1262 занят соседней
  веткой. Ревью нашло и места, где `glab` ещё не знали: образец работы и чтения, ярус отдачи,
  строку очереди работ, подтверждение отрицания и короткий флаг `-r`.

## Проверено

- Наборы сторожей: перезапуск 14, утверждения 42, ожидание 47, выход из хода 115 — без провалов;
  новые строки падали до правки.
- Проверка спек проходит, разложенные копии сходятся с пакетом v0.33.1.
