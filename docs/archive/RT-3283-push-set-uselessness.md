# RT-3283 — польза проверок набора

Задача RT-3283 эпика RT-3302, ветка `RT-3283-push-set-uselessness` от ветки эпика
`RT-3302-checks-rework-3`, 18.11.2026. Бывший адрес: `docs/tasks/RT-3283-push-set-uselessness/`.
Что стало правилом:

- польза проверок набора — поддомен `docs/specs/agent-kit/push-set-usefulness/`, сценарии
  SC-AK-1657…1668;
- строка запуска шага набора — семь полей: подпись, сумма проверки, исход, секунды, момент, сумма
  базы, отметка предмета;
- раздел «Проверки набора» команды `metrics` — строка в README пакета.

## Просьба

Текст задачи #3283, дословно:

> Набор перед отправкой не считает, какая его проверка приносит пользу. Проверка может месяцами
> идти на каждой отправке, ни разу не отказать и ни разу не найти ошибку. Другая отказывает ложно,
> и её просто перезапускают. Сейчас это видно только по разборам инцидентов: 13.11.2026 набор шёл
> семь раз, три запуска ушли впустую, а шаг сценариев проверок пакета шёл 13–19 минут на ветках,
> где сами проверки никто не трогал.
>
> Завести метрику бесполезности проверок набора. По каждой проверке набора за период отчёт
> показывает: сколько раз она шла и сколько секунд заняла; сколько раз отказала; сколько отказов
> были ложными — повтор на том же дереве прошёл зелёным; сколько раз она шла на ветке, которая не
> меняла её предмет; цену одного найденного дефекта.
>
> Отчёт отдельно называет проверки, которые за период ни разу не отказали по делу, и проверки, у
> которых ложных отказов больше, чем настоящих.
>
> За первую неделю отчёт называет хотя бы одну проверку, которую стоит убрать из набора или
> перенести в конвейер.

Вопросов владельцу не задано: два последних ответа в сессии шли рекомендованным вариантом, и
остальное закрыто допущением. План одобрен словами «Одобряю plan.md RT-3283 (Recommended)».

## Решения по ходу

- **План переписан ролями до показа владельцу.** Признак готовности был выполнен до первой
  строки кода; корень пакета как предмет сценариев хуков прятал пример самого владельца; одна
  проверка распадалась на строки по базе; шаг, который `select` не запустил, никогда не считался
  лишним. Все четыре закрыты в договорённости.
- **Сумма проверки — команда без базы целиком.** С меткой вместо базы шаг, который профиль печатает
  без базы, стоял отдельной строкой. Старые строки с базой внутри сводятся к общей сумме по каждой
  ветке, которую знает дерево.
- **Отчёт берёт сумму у хука, а не считает своей копией.** Первая версия считала `cksum` в
  TypeScript; линтер отказал на побитовых операциях, а правило дерева требует брать общее значение
  у объявляющей стороны. Теперь одна оболочка зовёт `rt_check_id` разложенного хука.
- **Предмет шага `nx affected -t lint typecheck test build` объявлен после роли.** `goal-critic`
  нашёл, что решение разбора «корни проектов» до профиля не дошло и шаг всегда читался
  «unknown». Профиль называет корни проектов и корневые настройки; правка только текстов и правил
  теперь даёт лишний запуск. Остальные находки ролей — в файле находок эпика.
- **Числа отчёта расходятся с ручным подсчётом.** Вручную по сырым строкам — 45 ложных из 58 у
  снимков кита и 19 из 30 у сквозного набора админки; отчёт даёт 44 из 57 и 17 из 28: строки
  команд, которых в наборе больше нет, остаются под своей суммой. SC-AK-1666 несёт числа отчёта.

## Цена

Неделя 11–17.11 этой машины: снимки второго кита — 76 044 секунды, 44 ложных отказа из 57;
сквозной набор админки — 29 846 секунд, 17 из 28; сценарии хуков пакета — 30 954 секунды без
единого ложного. Лишние запуски по старым строкам не видны: отметка предмета пишется только с этой
работы, и первую неделю с ней отчёт покажет после слияния.
