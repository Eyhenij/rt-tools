# RT-3100 — стрелка в кавычках не считается записью в файл

Задача RT-3100, ветка `RT-3100-shell-arrow-in-quotes` от ветки `RT-3086-scenario-long-prefixes`,
работа вне эпика по слову владельца. Папка задачи `docs/tasks/RT-3100-shell-arrow-in-quotes/`
разобрана в эту запись.

## Просьба владельца

> RT-3100 (Рекомендуется)

Владелец выбрал её из трёх описанных задач. В очереди задача звучит так: разбор путей записи
принимает `>` внутри кавычек за перенаправление, и команды `echo "a->b"` или
`node -e "[1].map(x => x)"` гард отбивает как правку файлов `b` и `x)`. Вторая часть: отказ гарда
экзамена терял путь настройки дерева — обратные кавычки в строке оболочки выполнялись как команда.

## Решения по ходу

- **Стрелка в кавычках выбрасывается до того, как кавычки стираются.** Отдельный шаг awk идёт по
  строке знак за знаком и помнит, открыта ли кавычка. Обратная косая вне одинарных кавычек
  экранирует следующий знак, а каждая новая строка начинается вне кавычек.
- **Путь в отказе экзамена взят в «ёлочки».** Так отказы дерева уже называют имена. Проверка на это
  стоит под сценарием SC-AK-312 — отказом без экзамена.
- **Разбор тел интерпретаторов не тронут.** Он читает сырой текст отдельно, и стрелка без косой черты
  путём там не считается.

## Проверено

- Разбор путей записи: 29 проверок, 0 провалов. Пять новых строк SC-AK-1251, три из них падали до
  правки.
- Гард экзамена: 41 проверка, 0 провалов. Новая строка про путь падала до правки.
- Соседние наборы без провалов: гард места правки — 29, гарды поставки — 110.
- Разложенные копии сходятся с пакетом v0.33.1.
