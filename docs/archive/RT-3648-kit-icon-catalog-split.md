# RT-3648 — одни имена значков и смена наборов на ходу

Задача RT-3648 эпика RT-3641, запись от 2026-11-26. RT-3684 влита в неё. Прежний адрес:
`docs/tasks/RT-3648-kit-icon-catalog-split/`.

## Просьба владельца

> Выпуск `@rt-tools/ui-kit-v2` 0.52.0 заметно тяжелее 0.51.0, и два потребителя вышли за бюджет стартового пакета. Задача: найти, что утяжелило части кита, и вернуть вес без потери возможностей 0.52.0.

Сначала задача была о переносе таблицы пар значков. На вопрос о ней владелец ответил: «Перепиши эту логику, какие библиотеки можно использовать? Как менять наборы иконок динамически?» Первый план не одобрен: имена значков во всех наборах должны быть одинаковыми. Ответы после описания новой системы:

- задача одна, вместе с RT-3684;
- старые имена — «Удалить сразу»;
- сильнее — «Явный выбор» набора, а не признак темы material;
- окна и боковые панели, открытые из части, получают её набор — «Да, получают»;
- незнакомый `glyph` шрифтом Material — «Оставить»;
- свой код, новых библиотек нет.

План одобрен ответом в меню «Одобряю». Позже на вопрос, убрать ли таблицу категорий значков из приложений, которые ею не пользуются, ответ «Да, убрать».

## Согласия владельца

- **Без вида:** «Одобряю»

## Что сделано

- Имя значка во всех наборах одно — имя кита. Таблица пар живёт только в переходном скрипте `migrations/rename-icon-names.mjs`, который заменяет старые имена в шаблонах приложения.
- Набор значков — это данные: имя, адрес, запасной набор. Менять его на ходу можно службой у всего приложения и директивой `rtIconSet` у части страницы. Диалог, подтверждение меню, боковая панель и меню вкладки берут набор своей части.
- Таблица категорий значков не попадает в приложение, которое ею не пользуется.
- Вес набора на старте: 194999 → 185800 байт, gzip 47394 → 46632. Предел плана 186000.
- Разделы README о наборах и о переходе перенесены в `projects/ui-kit-v2/ICONS.md`, он уезжает в пакете.
- Сквозные тесты SC-MB-459 и SC-AUTH-122: у каждого значка на экране есть символ в спрайте.

## Что решили и почему

- **Признак material у предка по-прежнему выбирает набор material**, пока приложение ничего не выбирало: вид под ним не меняется.
- **Уже открытое окно набора не меняет.** Так решено планом.
- **Предупреждения о наборах выпадают из рабочей сборки.** С ними набор весил 187728 байт, выше предела.
- **Категории переписаны без вызовов на верхнем уровне файла.** Предположение разбора, что сборка вырежет таблицу сама, оказалось неверным: пробная сборка это показала.

## Что нашли проверки

- Два круга ревью нашли среди прочего: кнопка теряла значок при перерисовке во время загрузки набора; боковая панель из `effect` открывалась заново; пустой `iconSet` окна и SVG с расширенным `DOCTYPE`.
- Снимки витрины нашли две ошибки замены имён, пропущенные обоими кругами: сломанную раскладку истории «Presets» и имена кита в строках «Glyph» о лигатуре шрифта.
- Роль, проверявшая первый план, запустила `fetch-material-icons.mjs --help`. Скрипт не разбирает ключи и перезаписал рисунки. Правки отложены в stash `rt3648-accidental-material-redownload`.

## Что не сделано

- Вес против 0.51.0 всё ещё больше: +1434 байт, с частью `button` +6907. Разбор по частям — в плане эпика.
- Часть `button` в набор проверки веса не входит: это отдельное решение о проверке.
- Диалог берёт набор по узлу с фокусом. Safari и Firefox на macOS не всегда ставят фокус на кнопку, тогда набор называют входом `iconSet`.
- Выпуск кита ждёт слова владельца: минорный, с ломающими изменениями.

## Как проверить

`pnpm run check:kit-weight` пишет «185800 байт при пороге 185800»; `node tools/check-icon-map.mjs` — расхождений нет.
