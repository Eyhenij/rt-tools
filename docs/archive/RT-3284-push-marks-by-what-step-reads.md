# Текстовый коммит поверх проверенного кода гнал набор заново

Задача RT-3284 · запись от 13.11.2026

Папка задачи лежала по адресу `docs/tasks/RT-3284-push-marks-by-what-step-reads/`.

## Просьба владельца

> исправляй это ебаное говно сейчас же

> ты сука запускаешь набор который потом повторит гейт пуша?

Сказано 13.11.2026 о наборе перед отправкой, который идёт там, где ему нечего проверять.

## Что сделано

Зелёная отметка проверки привязана к той части дерева, которую проверка читает. Профиль дерева называет пути, которые шаг не читает. Для шагов сборщика и линтера стилей это каталог `docs/`, файлы `.md` в корне и таблица назначений. Коммит только этих путей отметку шага не снимает. Проверки текстов и дерева профиль не называет, и после такого коммита они идут заново.

## Решения по ходу

- **Что шаг читает, называет дерево, а не пакет.** Пакет не знает, что читают шаги чужого дерева. Отклонено: список текстовых путей в самом пакете.
- **База осталась в ключе отметки.** Слияние базы по-прежнему снимает отметки шагов сборщика: что затронуто, сборщик решает по базе.
- **Ключ считается по индексу, а не по вершине.** Отметке верят только на чистой копии, там они совпадают.
- **Объявление вынесено в файл рядом с профилем.** Профиль стоял на пределе длины; туда же ушёл признак ветки из одних текстов.
