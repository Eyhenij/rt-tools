# RT-3368 — пакет протокола чата ассистента

Задача RT-3368, запись от 2026-11-18.

Что решали: общий слой чата ассистента для двух приложений на одном наборе событий AG-UI. Ниже разбор задачи дословно и решения по ходу работы.


### The owner request

Поручение пришло от запустившей сессии дословно так:

```text
Чат ассистента должен работать в двух приложениях на одном наборе событий AG-UI. Сегодня кит содержит только вид, а редьюсер и разбор событий записаны в каждом приложении отдельно. Владелец принял схему и план общего слоя; это первая задача кита из шести. Бэкенд второго приложения и его контракты менять нельзя.

Задача: добавить в монорепозиторий кита отдельный пакет протокола чата ассистента без Angular-вида. Вид `rt-ai-chat` и текущий публичный API кита не меняются.

В пакете: типы событий AG-UI (начало и конец запуска, ошибка запуска, сообщение по кускам, вызов инструмента, шаг, свои события, снимок сообщений); редьюсер запуска, превращающий события в состояние переписки; порт запуска (отправка новых сообщений, инструментов и контекста, чтение событий, остановка); порт бесед (список страницами по курсору, сообщения, оценка, прочтение, архивация); классификация ошибок по кодам. Разбора кадров SSE и сетевого кода в пакете нет: транспорт подставляет приложение.

Условия. Публичный API растёт только добавлением, новые поля необязательные. Выпуск минором после проверки. Записанные потоки (обычный ответ, серверный инструмент, браузерный инструмент, ошибка, обрыв) входят в тесты как эталоны. Пуш, PR и выпуск только после слова владельца. В файлах и текстах кита названий приложений не пиши: везде «второе приложение».

Признак готовности: записанные потоки дают в редьюсере пакета то же состояние, что нынешний редьюсер второго приложения.
Не входит: вид панели, транспорт, браузерные инструменты и контроллер запуска (следующие задачи), бэкенд.
```

### What the tree already has

- Пакеты без фреймворка: `projects/auth-contract` и `projects/cms-contract`. Сборка двумя tsc, esm и cjs, потом `tools/finalize-utils-package.cjs`. Тесты на node с порогом покрытия 100%.
- Вид `rt-ai-chat` в `projects/ui-kit-v2`. План эпика вида говорил, что протокол в кит не входит. Для общего слоя владелец это решение пересмотрел.
- Образец: редьюсер, разбор потока и классификация ошибок второго приложения. Их читали, не правили.

### What the rules already say

- Закон «code-structure»: явные типы, префиксы `I`, `T`, `E`. Закон «verifiability»: сценарий в названии теста и покрытие.
- В пакетах без фреймворка линтер запрещает импорты Angular, RxJS и NestJS (`eslint.config.mjs`).

### Questions and answers

Вопросов владельцу нет. Ответы о дереве и ключе задачи дала запустившая сессия.

### Decisions

- **Пакет `@rt-tools/ai-chat-protocol`, из зависимостей только `tslib`.** Типы событий AG-UI объявлены в пакете строковыми литералами. Rejected: `@ag-ui/core`, он тянет схемы и `zod`, а обоим приложениям это ни к чему.
- **Порты — интерфейсы на `Promise` и `AsyncIterable`.** Rejected: `Observable`, он тянет RxJS в пакет без фреймворка.
- **Читатель события из сырого JSON входит в пакет.** Он чистый и не знает кадров SSE. Без него записанные потоки каждое приложение превращало бы в события по-своему. Разбор кадров остаётся транспорту.
- **Коды серверных ошибок — строки контракта второго приложения.** Менять их нельзя.
- **Снимок сообщений заменяет сохранённые сообщения и сохраняет неотправленные.** Образец это событие не читает, так что поведение новое. На записанных потоках образца оно состояния не меняет.


## Решения по ходу работы

- **Дерево заведено отдельно от главной копии.** Главная копия стояла на чужой ветке. Ушло в историю: это ход работы, в правило не просится.
- **Редьюсер собран таблицей обработчиков по типу события.** Один `switch` не проходил предел сложности линтера, а таблица не даёт собрать новый тип события без обработчика. Требование к коду пакета описано в `docs/specs/ai-chat-protocol/spec.md`.
- **Эталонные состояния сняты запуском редьюсера второго приложения на тех же потоках.** Сверка одноразовая, скрипт остался вне репозитория. В тестах пакета лежат записанные потоки и состояния, их читает `docs/specs/ai-chat-protocol/scenarios.md`.
- **Событие ссылки на запуск стало общим событием с именем и значением.** Редьюсер берёт ссылку только при непустом строковом `referenceId`. Правило описано в спеке пакета.
