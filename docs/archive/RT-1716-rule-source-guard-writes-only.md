# RT-1716 — тело интерпретатора без записи путей не отдаёт

**Ветка:** `RT-1716-rule-source-guard-writes-only` · **Разобрано:** 2026-09-03

## Что было не так

Гард места правки берёт цели записи у помощника, а тот из тела интерпретатора вынимает всё
путеподобное: разбирать чужой язык нечем, и решает по вынутому зовущий. Тело, в котором нет ни
одного вызова записи, при этом отдавало свои пути наравне с телом, которое пишет.

Цена была названа в самом помощнике прямо — «чтение файла интерпретатором судится наравне с
записью в него», — и платилась редко: путь разложенной копии в чтении встречался нечасто. На
разборе груза о слое правил он встречается в каждом втором вызове: за один заход так отбито три
вызова подряд, и ни один ничего не писал. Один из них лишь подключал сам этот помощник, чтобы
посмотреть, что он отдаёт.

## Что сделано

- **Пути из тела берутся только там, где в теле есть вызов записи:** запись файла, перенаправление,
  копирование, перенос, снятие.
- **Тело, которое пишет, отдаёт свои пути целиком.** Путь и вызов записи стоят там разными
  строками, и связать их нечем — сузить дальше значило бы вернуть дыру.
- Статья и адрес в домене места правки, три сценария SC-AK-858: чтение проходит, запись отбита,
  путь строкой выше записи берётся.

## Чем это подтверждено

Набор гарда места правки — 23 зелёных. Весь shell-набор пакета зелёный, сверка раскладки сходится,
проверки спек, адресов и слога чисты. Живой прогон помощника: чтение разложенного файла молчит,
запись в него отдаёт путь.

## Что осталось открытым

Признак записи внутри тела — список слов, а не разбор языка: тело, которое пишет незнакомым
способом, своих путей не отдаст. Расширяется он тем же способом, каким расширяется всякий такой
список, — по промаху.
