# RT-3153 — запись событий для метрик пакета правил

Задача RT-3153 эпика RT-3151, ветка `RT-3153-metrics-events`, PR в `RT-3152-metrics-catalog`,
07.11.2026. Папка задачи разобрана в эту запись. Разбор всего эпика лежит в записи RT-3152.

## Просьба владельца

Слова владельца по этой задаче: «Принято с первого раза (Recommended)» про главное число, «поменяй
спеку и гарды, пусть отправляют аналитику сами + агент в конце каждой сессии», «Только числа
(Recommended)», «В этом эпике (Recommended)» про роли и команды.

## Решения по ходу работы

- Метки лежат в каталоге наблюдений. Каталог сам себя игнорирует: в новом дереве `git add -A` иначе
  унёс бы подписи в историю.
- Запись `empty=0` пишется наравне с `empty=1`: без неё отчёт не отличит ноль от старых записей.
- Подпись дерева не читает каталог наблюдений: своя запись выглядела бы новым содержимым.
- Подпись берётся с копии вызова, а не с корня проекта: хуки стоят в основной копии.
- Строка запуска пишется на каждую проверку набора и всегда в основную копию: тяжёлые шаги идут из
  второй, и их минуты иначе терялись.
- Зелёная проверка с отметкой не запускается и строки не даёт.
- Подпись передачи ставит хук после вызова. Проверка до вызова только объявляет ветку: следующая
  проверка ещё может отказать, а вызов может упасть.
- Передача требует проверяющего и готовой заявки. Первая подпись ветки остаётся.
- Счётчик правок делится на до и после передачи.
- Заявка без подписи считается отдельной строкой и в главное число не входит. Сначала она не
  считалась вовсе, и 229 заявок пропадали из отчёта молча.
- Хостинг спрашивается о коммитах только по заявкам с подписью. Иначе сотня заявок стоила двух
  минут и обрывала отчёт пределом в 120 секунд.
- Чтение идёт от прошлого дня чтения, лимит 1000. Оборванное чтение и дерево без функции чтения
  названы разными строками.
- Старая заявка, дочитанная вторым чтением, посчитанный итог не меняет.
- Итог пишется в наблюдения в день чтения: номера заявок лежат только в файле учёта.
- Приговор роли читается на конце роли, событием `SubagentStop`. 14 из 15 вызовов шли в фоне, и
  приговора при вызове не было. Форма события проверена по описанию, вживую её покажет только
  первая сессия после попадания хука в main.
- Отказ шлюза по уже загруженному правилу не считается: запись загрузок гибнет при сжатии окна, а
  наблюдения его переживают. Нового события для этого не понадобилось.
- Правило объявили 27 проверок из 36: у остальных нет своего правила пакета.

## Цена

Первая версия прошла 67 своих проверок и не работала на настоящем дереве. Подделка хостинга не
поймала потерю коммитов и метку эпика на заявке, чтение настоящего GitHub поймало оба. Роли нашли
ещё шесть промахов: обрыв отчёта, заголовок роли в трёх строках, фоновые роли, запуски из второй
копии, подпись до вызова, подписи в истории нового дерева.

Настоящий путь проверка → метка → слияние → отчёт появится только после попадания хуков в main.
Отчёт на клоне настоящего дерева прошёл за 20 секунд: заявок без передачи 229, с подписью 2. Эти две
подписи положены рукой настоящим кодом на вершину при слиянии, поэтому «2 из 2» доказывает чтение
и не доказывает ветку изменения. Её на настоящем GitHub показала роль: «1 из 2».

Первая запись набора из второй копии ушла в основную из-за вызова git без корня. Четыре тестовые
строки сняты из файла наблюдений за 07.11 в тот же ход.
