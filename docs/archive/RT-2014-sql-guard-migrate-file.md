# RT-2014 — страж записи молчал на доставке файла рядом с миграцией

**Ветка:** `RT-2014-sql-guard-migrate-file` · **Разобрано:** 11 сентября 2026 года

## Что было не так

Страж записи в хранилище пропускал без вопроса команду, где доставка файла в базу стояла рядом с
миграцией на местный адрес:

```
DATABASE_URL=postgres://app@localhost:55432/app pnpm exec prisma migrate deploy \
    && psql -d app -f /tmp/fix.sql
```

Второе звено кладёт в базу файл, содержимого которого страж не видит. Отдельной командой такой
вызов он считает записью и спрашивает подтверждение; в паре с миграцией — молчал.

## Почему так выходило

Досрочный выход на местном адресе существует нарочно: на местной базе миграции гоняют постоянно, и
вопрос на каждой обесценил бы тот единственный, который важен. Выходить он имеет право только когда
запись в команде одна — сама миграция, — и вторую он искал сам: по глаголам SQL и по командам,
кормящим трубу. Доставку файла флагом он не искал, хотя десятком строк выше основная ветка стража
называет её записью по определению.

## Что сделано

Признак «в команду залит файл» вынесен в свою функцию и спрашивается из обоих мест — из общего
определения записи и из досрочного выхода. Набор проб получил обе стороны: цепочка с доставкой файла
спрашивает, миграция рядом со снятием дампа проходит.

## Чем это подтверждено

Сценарий SC-AK-1061. Со снятым условием набор даёт 39 ok и 1 провал — краснеет ровно проба про
доставку файла; с правкой 40 ok, 0 провалов.

## Решения по пути

- **Описание не правилось.** Сценарий SC-AK-1061 обещает ровно это словами — «миграция рядом со
  второй записью теряет пропуск». Расходился с ним код, а не описание.
- **Имя файла в пробе про дамп взято не `copy.sql`.** Слово `copy` страж считает глаголом записи и
  находит его прямо в пути, отчего проба краснела бы по причине, к дампу не относящейся. Это
  отдельная шероховатость стража: путь к файлу судится теми же образцами, что и текст запроса.

## Что осталось за работой

Разбор запроса и адресация строк не трогались: дефекта там не найдено. Страж в этом дереве не
разложен — он назван в списке пропусков, — поэтому правка живёт исходником пакета и приедет
потребителям следующим выпуском.
