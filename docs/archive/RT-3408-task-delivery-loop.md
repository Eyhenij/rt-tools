# RT-3408 — каждая задача идёт через живую проверку и два круга ревью

Задача RT-3408, запись от 2026-11-19.

## Просьба владельца

> включи task-delivery-loop в task flow

Просьба пришла через запустившую сессию, с условиями: цикл грузится первым на каждой задаче, два
круга ревью до отправки, без исключений; цикл говорит именами этого дерева — его ролями, стендами
и набором перед отправкой.

## Что решили

- **Цикл — правило дерева, а не ресурс пакета.** Он называет витрину, стенд, роли и набор перед
  отправкой этого дерева; у дерева-потребителя их нет.
- **Цикл требует гейт правил, без нового хука.** Ветки карты `.claude/rt-kit/gate-map.sh`: правка
  папки задачи или плана эпика и команды заведения задачи, взятия ветки, отправки и открытия PR.
  Случаи — `tools/tests/gate-map-loop.test.sh`.
- **Готовые команды — шаблон `task-delivery-loop-run`.** Проверка спек отказывает правилу без
  шаблона.
- **Кто вливает, цикл не решает.** Слияние остаётся за человеком по правилу `git-workflow`; цикл
  называет, чего ждёт PR.

## Что нашли круги ревью

- **Первый круг.** Готовый вызов открытия PR шёл через переменную `$GH`, а проверки поставки
  читают только текст команды — вызов набран целиком. Гейт пропускал частые формы команд —
  разобраны. Черновик стоял для любой базы — только для `main`. Описание задачи и её разбор
  говорили, откуда пришёл цикл, — убрано.
- **Второй круг.** Гейт пропускал ещё дюжину форм — 36 случаев. Статья о находках спорила со
  статьёй `task-flow` о находках рядом с предметом — сужена до находок о diff. База ветки и ожидание
  ответа спорили с цепочкой веток и ночной работой — приведены к их правилам.
- **Списано в обоих кругах.** Круги не считает ни одна проверка. Это сказано в правиле и в теле PR;
  проверка кругов — правка пакета, не этой задачи.

## Цена

Круги ревью держатся текстом и телом PR: гейт требует загрузить цикл, но не проверяет, что круги
прошли.
