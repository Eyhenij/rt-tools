# RT-2041 — отказ набора по двусмысленному имени был написан и ниоткуда не вызывался

**Ветка:** `RT-2041-ambiguous-names-unwired` (вне эпика, по слову владельца) · **Разобрано:** 2026-10-03

## Просьба владельца

> Взять RT-2015, Взять RT-2041

Ответ на ревизию доски. Эпик задачи (#2028) был закрыт, поэтому задача переведена в работу вне
эпика: строка о связи с эпиком в её теле заменена словом владельца.

## Вопросы и ответы

**Как довести задачу: отказ в sync, предупреждение в doctor или признать тест проверкой?**
«Отказ в sync и sync --check».

## Решения

- **Отказ устроен так же, как отказ по ресурсу без нужного вида.** План установки собирает список
  одноимённых ресурсов. Непустой список отбивает `sync` целиком, а `sync --check` считает его
  расхождением.
- **Отклонено:** предупреждение в `doctor` — установка проходила бы молча; признать тест
  пакета вызовом — правило дерева этого не допускает.
- **Сценарий SC-AK-1186:** два закона `access` в разных слоях — установка называет оба и не пишет
  ни одного файла.

## Проверки

- Тесты пакета: 29 наборов зелёные.
- `pnpm run agent-kit:check` — дерево совпадает с пакетом, то есть в настоящем наборе
  одноимённых ресурсов нет. `npm run check:specs` — без расхождений.
