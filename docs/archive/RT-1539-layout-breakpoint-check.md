# RT-1539 — правка вида проверяется на каждом пороге раскладки

**Ветка:** `RT-1539-layout-breakpoint-check` · **Разобрано:** 2026-08-29

## Что было не так

Две записи груза об одном. Правка раскладки была замерена на двух крайних ширинах — телефон и
широкий экран — и объявлена готовой. На всём промежутке между порогами три поля отбора стояли
разной высоты: набор компонентов рисует свой элемент на узком экране всегда в среднем размере,
а соседние поля были на ступень ниже. Ни один замер этого не показал, потому что замеряли там,
где раскладка уже устоялась. Нашёл это владелец, а не проверка.

Вторая половина — про приём. Замер по одной ширине за вызов даёт числа разных минут: между
вызовами страница перерисовывается, и сравнивать их нельзя. Готового приёма снять все пороги
одним заходом в паттерне не было, и каждый исполнитель собирал его заново — обычно на двух
ширинах, потому что на восемь вызовов никто не идёт.

## Что сделано

- Закон о проверяемости получил статью: правка вида проверяется на каждом пороге раскладки, а
  не на одной ширине, и пара вокруг порога проверяется целиком — одна ширина говорит лишь про
  ту сторону, на которую попала.
- Паттерн `browser-verification-measure` получил раздел «Замер по всем порогам разом»: ширины
  гоняются пачкой в одном заходе, каждая своим кадром, замер снимается со всех сразу. Ответ
  читается по трём признакам — равные высоты соседей одной строки, отсутствие поперечной
  прокрутки, ни одной левой границы за правым краем. Третьего на снимке не видно вовсе:
  элемент за краем выглядит отсутствующим.
- Оговорка о полосе прокрутки: ширина кадра меньше заказанной, и сравнивают с шириной из
  ответа, а не с числом из списка.

## Чем это подтверждено

Предел веса выдержан, раскладка сходится с пакетом v0.18.0.

## Что осталось открытым

Проверки на исполнение статьи нет и не будет: признака «смотрел ли на порогах» у машины не
существует — она видит вызовы инструмента, а не ширину, на которой снят замер. Список порогов
статья тоже не называет: у каждого дерева он свой.
