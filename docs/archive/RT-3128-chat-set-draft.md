# RT-3128 — метод setDraft у чата

Задача RT-3128, ветка `RT-3128-chat-set-draft`, вне эпика. Папка задачи разобрана в эту запись
6 ноября 2026 года.

## Просьба владельца

Передано сессией приложения:

> У чата нужен открытый метод `setDraft(text: string): void`. Метод заменяет содержимое поля ответа
> и ставит фокус с курсором в конце. Он работает в классическом и rich-композере, выбранные файлы не
> трогает, при закрытом поле ничего не делает. Вид чата не меняется, кадр не нужен.

## Ответы владельца

- Куда отнести задачу: «Работа вне эпика».
- Показ с кнопкой снаружи отвергнут: показывать надо настоящий случай, экраном.
- Экран `QuickReplies`: «Одобряю (Recommended)».

## Решения

- Метод работает и в поле мессенджера. Поручение называет два поля, а у чата их три: без третьего
  метод молча ничего не сделал бы в режиме мессенджера.
- Закрытым считается поле из `composerDisabled`: загрузка и обновление закрывают поле так же, как
  отправка.
- Следование ленты вынесено в `RtChatThreadFollow`: файл чата перешёл лимит 500 строк. Поведение не
  менялось.
- Показ стоит на странице переписки, историей `QuickReplies`. Кнопка у поля ответа открывает готовые
  ответы, подсказки стоят в боковой панели. История с кнопкой снаружи удалена. Пары наборов у показа
  нет: вторая половина повторила бы тот же показ.

## Замеры

- Нажатие на ответ ставит текст в поле, курсор на позиции 39 при длине текста 39, панель закрывается.
- Нажатие на подсказку заменяет текст: длина 47, курсор на 47, поле в фокусе.
- Число сообщений в ленте после нажатий не изменилось: гостю ничего не уходит.
- Сверки экрана с кадром по числам нет: вид метод не меняет, показ сверен с кадром по снимку.
