# RT-3155 — приёмник хранит числа метрик

Задача RT-3155 эпика RT-3151, ветка `RT-3155-metrics-intake`, PR в `RT-3153-metrics-events`,
07.11.2026. Папка задачи разобрана в эту запись. Разбор всего эпика лежит в записи RT-3152.

## Просьба владельца

Карточка задачи: приёмник принимает старую и новую запись, а повторная отправка дня не меняет итог.
Слово владельца про содержимое отправки: «Только числа (Recommended)».

## Решения по ходу работы

- Числа идут строкой дня. Карточка писалась до договорённости и называет новые колонки наблюдений.
  Договорённость заменила их таблицей `MetricsDay`: с приложений уходят только числа.
- Прежний груз наблюдений не меняется. Его шлёт команда человека, старая и новая версия пакета шлют
  его одинаково.
- Строка замещается условным обновлением по штампу, а не чтением перед записью. Две отправки одной
  копии приходят разом, и чтение пропустило бы старую строку.
- Равный штамп принимается. Отправка повторяет окно целиком, и повтор не должен выглядеть отказом.
- Дневная строка описана в подобласти учёта правил: там уже лежат наблюдения, их снятие за год и
  отправка тем же токеном.
- Сквозной тест читает токен из файла стенда: команда печатает его один раз.
- Критик подал на вход настоящему разбору путь в признаке копии, текст в версии и сумму в имени
  ресурса, и всё это легло. Теперь признак, версия и имя судятся по форме. Отказ на чужое слово вида
  `ruleLoads:имя-клиента` приёмник не даёт: его список имён отстаёт от пакета, и новое имя отказало
  бы всю строку каждому дереву. Такие слова отсекает отправитель.
- Срок хранения не снимал день `9999-12-31`, а штамп из будущего закрывал день навсегда. Теперь день
  и штамп не позже завтрашнего, это закрыло и падение на штампе вне диапазона дат.
- В список добавлены числа, без которых не считаются метрики договорённости: разложенные и мёртвые
  правила, заменённые разделы пакета, обрывы чтения итогов, код сбоя отправки, отказы с правилом, приговоры
  ролей, сравнённые отказы.
- Причина сбоя отправки едет числом со следующей дошедшей строкой. Роль предлагала хранить последний
  отказ дерева в отдельной записи приёмника. Это новая таблица ради одного состояния экрана, а отказ
  по токену и сбой сети она всё равно не видит: такое дерево читается как молчащее.
- `Postmortem.resource` и `RecordTransition` читает только раздел «Качество», поэтому они ушли в
  RT-3156.

## Цена

- Операции чтения пока нет, поэтому сквозной тест читает таблицу из базы стенда напрямую.
- Имя ресурса на входе судится только по форме, слово из дерева может пройти приёмник.
- Первый запуск упал на занятом порту базы: контейнер запуска CI держал 55462. Запуск на свободных
  портах прошёл.
