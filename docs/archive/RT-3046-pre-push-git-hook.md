## Что было

- Проверка перед push стояла только на инструментах агента. Push из терминала вне сессии, из другой
  сессии через `git -C` или из среды без хуков агента уходил без проверок.
- В соседнем дереве так ушла ветка кита, её влили, и главная ветка кита стала красной.
- Шаблон git-хука в пакете был один — сообщения коммита. Хука перед push не было ни в пакете, ни в
  этом дереве.

## Решение

- Шаблон `pre-push.sh` рядом с шаблоном сообщения коммита: тот же набор из профиля, что у проверки
  сессии, красный набор отменяет push. В этом дереве хук подключён строкой `.husky/pre-push`.
- Проверка сессии на зелёном наборе пишет вершину в отметку, и push этого коммита второй раз набор
  не гоняет. Иначе push из сессии ждал бы пятнадцатиминутный набор дважды и обрывал бы сессию.
- Хук пропускает только push вершины рабочей копии: набор судит дерево, на котором копия стоит.
  Удаление ветки и запуск в конвейере он не судит.
- Отметка — свой файл, а не отметки соседнего PR #3094 по каждой проверке: тот PR не влит, а задача
  не ждёт чужой работы.
- `git push --no-verify` обходит хук по устройству git. Отказ на этот ключ — работа проверки сессии,
  записано находкой рядом с планом эпика.
