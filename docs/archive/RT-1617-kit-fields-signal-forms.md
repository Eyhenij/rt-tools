## Что было не так

Поле набора под сигнальной формой Angular 22 не запускалось вовсе:
`TypeError: Cannot read properties of undefined (reading 'pipe')`.

Разведка по коду `@angular/forms` 22.0.5 (точка входа `signals`) назвала причину:

- Директива `[formField]` объявляет провайдер `NgControl` и отдаёт по нему свой переходник
  `InteropNgControl` — значит ранний выход по пустому контролу не срабатывает.
- У переходника `control` указывает на него самого, а свойства `events` нет вовсе. Строка
  `control.events.pipe(...)` в запуске поля читает `pipe` у `undefined`.
- Значение, отключённость и признак касания через сигнальную форму ходили: набор ставит
  `valueAccessor` руками, и директива этот путь принимает. Падало только чтение состояния.
- Состояние у переходника есть целиком — `invalid`, `touched`, `dirty`, `errors`,
  `hasValidator(Validators.required)`, — и его геттеры зовут сигналы поля, то есть реактивны
  из `computed`.

## Решения с доводами

- **Состояние поля читается вычислением, а не подпиской, когда контрол его не рассылает.**
  Переходник сигнальной формы событий не шлёт вовсе. Прежняя привязка осталась на подписке: у
  реактивного контрола геттеры сигналами не являются.
- **Своего `NG_VALUE_ACCESSOR` набор не объявляет и в этой работе.** Он спровоцировал бы цикл
  внедрения при самоссылке; путь через `valueAccessor`, ставящийся руками, сигнальная форма
  принимает.
- **Договор `FormValueControl` не вводится.** Пока поле отдаёт доступ к значению, директива
  формы выбирает его и до договора не доходит; ввод договора означал бы снятие прежнего пути,
  то есть слом обратной совместимости.

  достаёт его доступом; вопрос встанет, если понадобится поле без формы вовсе.
