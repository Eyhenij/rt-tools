# Запись указателя называется именем файла

Задача RT-1299, ветка `RT-1299-index-row-names-file`. Заявки нет: правка лежит местной веткой —
владелец на эту ночь просил держать ветки у себя.

## Разбор просьбы

Владелец разбор не вёл: заход шёл сам, записи груза брались из приёма одна за другой. Запись
пришла от соседнего дерева и говорила о ресурсе `rules/doc-style.md`:

> Правило требует сверять указатель каталога с содержимым и молчит о том, чем запись считается
> названной. Форма живёт только в пояснении внутри самой проверки — там её не прочитает никто,
> кто пишет указатель. Два указателя дерева называли записи ссылкой с заголовком, имени файла в
> обратных кавычках в строке не стояло вовсе: для читателя записи названы, для сверки строка
> пуста. Семнадцать записей были невидимы.

## Что решено

Статья, а не ловушка: у неё есть место исполнения — там, где сверка берёт из строки таблицы
первое имя в кавычках, — и правило уже несёт соседнюю статью о самой сверке. Стоят они теперь
рядом: требование сверять и форма, в которой сверка видит запись.

Сказано и то, что ссылка с заголовком законна. Без этого статья читалась бы как запрет ссылок в
указателе, а они там и нужны — читатель ходит по ним.

## Цена

Запись груза осталась в приёме новой: она принадлежит соседнему дереву, а токен двигает только
свои записи. Работа при этом сделана здесь — ресурс живёт в этом дереве.

Второй форме сверка не учится: ссылка с заголовком несёт адрес, и отличить в ней запись
каталога от любой другой ссылки строки нечем. Пишущий указатель по-прежнему обязан назвать имя
сам — правило теперь об этом говорит, а поймать промах нечем, кроме сверки, которая молчит.
