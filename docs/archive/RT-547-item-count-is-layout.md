# Правка числа элементов в контейнере — правка раскладки

RT-547 · местная ветка, заявка не открывалась · 30 августа 2026 года

## Откуда работа

Разбор происшествия из дерева-потребителя: число элементов в ряду шапки выросло с четырёх до
восьми. Ряд был без переноса и без узкой раскладки — документ стал вдвое шире вьюпорта и
прокручивался вбок на каждой странице сайта. Прод простоял так сорок четыре минуты, нашёл
владелец, открыв сайт с телефона.

Правка меняла число элементов, а не стили, и потому не читалась как правка вёрстки: проверка
свелась к кодам ответа.

Пятая работа ночи; ветка стоит на RT-549.

## Что теперь верно

Правило проверки браузером называет правку числа элементов в контейнере правкой раскладки и
называет замер, которым она закрывается: ширина документа против ширины вьюпорта на узком экране.
Взгляд на снимок замером не является — снимок показывает то, что влезло в кадр.

## Решения по ходу

- **Статья легла в правило, а не в паттерн.** Паттерн отвечает «чем мерить», правило — «что
  требует замера».

## Чем подтверждено

`npm run check:specs` — расхождений нет; привязка статьи стоит в компаньоне с вердиктом «не
проверяется ничем»: ширина документа в тексте правки не видна. `pnpm run agent-kit:check` —
разложенное сходится с пакетом v0.22.0, `node tools/check-file-size.mjs` — длиннее предела 0.
