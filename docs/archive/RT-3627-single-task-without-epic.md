# RT-3627 — задача, чей разбор дал одну, заводится без эпика

Задача RT-3627 эпика RT-3624, запись от 2026-11-25. Прежний адрес:
`docs/tasks/RT-3627-single-task-without-epic/`.

## Просьба владельца

> сейчас рабочий процесс занимает слишком много времени, довольно простые правки идут по несколько часов, сделай анализ на какие шаги сколько времени уходит по текущему task flow и как можно оптимизировать весь процесс

План эпика, П3: «Разбор дал ровно одну задачу — ветка и PR идут прямо в main. Меняет закон `delivery`». Порядок —
«RT-3629 (Recommended)» 25.11. План задачи — «Одобряю план RT-3627 (Recommended)». О RT-3565 (эпик RT-3564, та же
починка движка) — «Закрыть этой работой (Recommended)».

**Снимает ли это слово владельца на саму работу?** Нет. Работу заказывает владелец, строка копии в таблице остаётся.
Снимается второе слово — «эту задачу вне эпика».

## Что решили и почему

- **Признак — строка разбора** «**Задач в разборе:** 1», её читает одна функция у движка и у команды. Флаг без проверки
  отвергнут: он не отличается от флага, набранного ради обхода отказа.
- **Строка карточки одна**, «Работа вне эпика — разбор дал одну задачу», и читается на своём месте: слова в предложении,
  ограда, комментарий и образец в скобках — не строка. Второй вид строки отвергнут: три читателя разошлись бы.
- **Первой чинится движок.** Он держал всякую работу вне эпика на втором шаге, и поверх готовых задач завели RT-3497,
  RT-3566 и RT-3390.
- **Копия с открытым эпиком одиночную не заводит**: открытая карточка с меткой эпика. Строка копии с номером самой
  задачи — не эпик. Прочерк — ответ владельца, он держит и одиночную.
- **Ветка одиночной растёт от main без чужих коммитов** — прежним классом отказа; новый класс потребовал бы строк
  таблицы решений. Отказ называет эпик для задачи, которой эти коммиты нужны.
- **Отказ «открыта другая одиночная» вычеркнут**: второй независимый заказ снова получал бы эпик из одной.
- **Один разбор отвечает за одну карточку**: команда заведённой карточки переименовывает черновик. Решение третьего
  чтения плана «не переименовывать» отменено первым кругом ревью.
- **Вызов читается как оболочка** в защите копии: название со словами `task:new` отбивало законный `--single`.

Списано: база PR одиночной, чужие коммиты, влитые после взятия ветки, и формы `worktree add -b`, `checkout -B` — предел
назван в спеке `delivery-epic`; имя скрипта в кавычках и цикл вокруг вызова — таких вызовов в журналах нет.

## Что осталось вне задачи

- Строка RT-3565 в плане RT-3564: слово об отложенной задаче ставит владелец, отметкой о слиянии эпик не кончится.
- Измерение часа одиночной до main — первые три карточки `single: true` после слияния RT-3624, карточка до PR эпика.
- Две находки по ходу — в `docs/plans/delivery-speed-findings.md`.

## Чем подтверждено

- Живой отказ в дереве по числу 2, карточек 1887 до и после; у RT-3618 `outside` «Завести вне эпика».
- `single-task` 53, `guard-epic-base` 59, `guard-tree-assignment` 65, `task-flow-script` 353 — без провалов.
- 72 испорченных варианта из 72 краснят свои наборы на отправленном коде. Набор перед отправкой зелёный.

## Цена

- План переписан после двух чтений ролями: первая редакция читала черновик, которого у выданного номера не бывает, и
  мерила по задачам, где эпик был настоящим.
- Первый круг нашёл, что чтение карточки движком проверял только двойник порта: сломать его можно было на всех наборах.
- Чтение вызова защитой писалось трижды. Две первые редакции пропускали одно и ложно отбивали другое.
- Набор рядом со вторым кругом ушёл впустую дважды: пробный файл роли в копии, потом находки.
