# RT-3691 — при слиянии проверенной базы проверка хода работы пропускает выбор стороны в блоке конфликта

Задача RT-3691 вне эпика, запись от 2026-11-26. Прежний адрес: `docs/tasks/RT-3691-merge-base-engine-conflict/`.

## Просьба владельца

> Задача вне эпика от main

Это ответ владельца в меню 26.11. Вопрос был такой: слияние `main` в ветку эпика RT-3602 отказано, проверка хода
работы пускает конфликт в файлах движка только в задаче, чей план их называет, а проверка поставки не даёт взять
ветку задачи до слияния. Выбранный вариант: задача вне эпика на предложение, отправленное в приёмник; ветка от
`main`; план называет файл проверки; два круга ревью; выпуск пакета; затем `main` вливается в эпик и берётся
RT-3674. План задачи одобрен словом «Одобряю план RT-3691».

## Что решили при разборе

- **Слияние проверенной базы пропускает разрешение конфликта.** База проверенная, когда сливаемая голова лежит в
  удалённой главной ветке или в удалённой ветке эпика, которую называет план эпика. Любое слияние отвергнуто:
  ветка, которую никто не смотрел, пронесла бы правку движка мимо плана.
- **Разрешение — выбор стороны.** Строка, которой нет ни в одной стороне, отказана, как раньше.

## Что решили по ходу

- **Хук берёт движок из `tools/` папки проекта сессии.** Обе роли на плане нашли: у этой сессии папка проекта —
  главная копия на `00422d2cf`, а не эта копия. Проба стала звать сам хук. Пока каталог сессии был в главной
  копии, движок главной копии мерял задачу вне эпика на втором состоянии, и строку состояния выше он отказывал.
  Когда каталог сессии стал этой копией, правки охраняемых файлов по плану прошли; строку состояния этот движок
  не пускал до конца задачи.
- **Шаг 1.1 «Проба отказа до правки» был зелёным до работы.** `plan-red` не записал одобрение. Шаг заменён в
  неотправленном коммите плана по слову владельца «Работай по процессу».
- **Обе стороны подряд — только в тексте `.md`.** В коде две стороны объявляют имя дважды, а упавший движок хук
  пропускает целиком. Две функции, добавленные сторонами в одно место кода, слиянием не сохранить.
- **Превышение `projects/agent-kit/assets/checks/flow-guard-run.mjs` на 7 строк сверх бюджета** — на находки
  ревью.
- **Первый круг ревью** закрыл: падение чтения слияния на каталоге среди планов, давшее «пропустить всё»;
  обрезанный закрывающий маркер; `git -c` с фильтром; абсолютный путь и `git -C`; `origin/main` при другом
  `origin/HEAD`; чтение слияния на каждый вызов.
- **Второй круг ревью** закрыл: слияние нескольких веток сразу проверяет все головы; база сверяется с полным
  именем удалённой ветки; планы эпиков читаются из `HEAD`, а не из того, что принесла сливаемая голова; выбор
  стороны с `GIT_*`, `--git-dir`, `--work-tree`, `--namespace` отказан.
- **Порядок слияния `main` в RT-3602:** сначала `git checkout --ours` разложенных копий движка, затем блок
  источника правкой под сторону, затем раскладка. Пока в копиях движка маркеры, движок сливаемого дерева падает.
- **Подделка локальных ссылок, `MERGE_HEAD`, планов и фильтра `git config`** записана в спеке как обход по умыслу,
  того же класса, что неподсудный `git merge`. Дыры, которые стояли до задачи, ушли предложением в приёмник.

## Цена

- Слияние `main` в RT-3602 пройдёт, когда правка будет в движке, который судит ту сессию. У этой сессии это движок
  главной копии.
- Два разбора промахов 26.11: путь предложен без проверки, какой движок судит; вопрос владельцу о правке,
  которую процесс уже называет.
