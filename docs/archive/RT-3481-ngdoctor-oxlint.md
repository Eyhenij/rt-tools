# RT-3481 — находки oxlint в utils, core и ките

Задача RT-3481 эпика RT-3476, запись от 2026-11-23. Прежний адрес:
`docs/tasks/RT-3481-ngdoctor-oxlint/`.

## Просьба владельца

> Продолжи работу по эпику ng doctor

Просьба эпика RT-3476. Задача снимает 21 находку четырёх правил oxlint, которого Angular Doctor
запускает внутри себя: `eqeqeq` 11, `no-thenable` 7, `no-extra-boolean-cast` 2,
`no-useless-spread` 1. План одобрен: «Одобряю plan.md RT-3481».

## Согласия владельца

Правка `rt-toolbar.component.ts`, `rt-workspace-details.component.ts`, `rt-day-stamp.pipe.ts`,
`rt-pdf-viewer.component.ts` и `ai-chat-chart.schema.ts`: сравнения `== null` и `!= null` — через
`isNil` из utils, просмотрщик PDF обходит ключи словаря без копии, условия JSON Schema графиков
чата переписаны с `if`/`then` на `anyOf` и `not`.

- **Без вида:** «Подтверждаю, вид не меняется»

Смена JSON публичной схемы `RT_AI_CHAT_CHART_SCHEMA` — и вместе с ней схемы блока
`RT_AI_CHAT_CHART_BLOCK_SCHEMA`, которая встраивает её полем `spec`: «Подтверждаю смену JSON
(Recommended)».

Владелец спросил: «разве у нас используется oxlint?» — дерево само его не запускает: это
зависимость Angular Doctor и один из его источников находок. Проверку живости источника владелец
отдал «Отдельной задачей эпика» — RT-3514.

## Что нашли

- Одиннадцать сравнений `== null` проверяли «нет значения»; в utils уже есть `isNil`.
- Ключ `then` требует сам JSON Schema для условия. Помощник, что собирает ключ так, чтобы сканер
  его не видел, — обход правила (goal-critic, проверка вопросов); правило выполнено по сути через
  `anyOf` и `not`.
- Копия ключей просмотрщика PDF не нужна: цикл удаляет только текущий ключ, а удаление во время
  обхода `Map` безопасно.
- После задачи в пороге нет ни одного правила oxlint, и `check:ngdoctor` не отличает источник без
  находок от источника, который не запустился.

## Что решили и почему

- **Проверки «нет значения» — через `isNil` из utils;** core и кит уже требуют utils той версии,
  где он есть.
- **Условия схемы — помощники `implies` и `either`:** `anyOf: [{ not: A }, B]` и
  `anyOf: [{ allOf: [A, B] }, { allOf: [{ not: A }, C] }]`. Принятие то же, список ошибок отказа
  длиннее; README кита и обзор секции в витрине это называют, строку для журнала выпуска ставит
  выпуск кита.
- **Порог записан с `--source-gone oxlint`;** живость источника — RT-3514, сразу следующей.
- **Проверки шагов зелёные только на полном прогоне инструмента,** а сверка порога идёт с
  коммитом `c1b5286af`, не с именем ветки.

## Чем подтверждено

- `pnpm run check:ngdoctor`: «score 87.25, 1400 findings of 14 rules — equal to the threshold»;
  оценка 84.25 → 87.25, правил в пороге 18 → 14.
- Сверка старой и новой схемы валидатором Ajv: 19 200 графиков в живой проверке, по 200 000
  случайных в обоих кругах ревью, 50 000 через схему секции — 0 расхождений.
- Тесты utils 300, core 41, админки 57, кита 4343; набор перед отправкой зелёный, с гейтом кадров
  витрины. Сквозной тест SC-MB-442 на ширине 768 в первом прогоне набора дал кадр на 3 px выше;
  отдельно на той же вершине и во втором прогоне набора — зелёный.
- Два круга ревью тремя ролями.

## Цена

- Схема графиков чата у потребителя меняет текст JSON и список ошибок отказа; провайдер модели
  должен принимать `anyOf`, `allOf` и `not`.
- До RT-3514 `check:ngdoctor` не заметит, если oxlint внутри инструмента замолчит.
