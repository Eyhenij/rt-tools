# RT-3450 — проверка библиотек принимает запуск тестов сборщиком Angular

Задача RT-3450 вне эпика, запись от 2026-11-20. Прежний адрес: `docs/tasks/RT-3450-lib-test-runner-forms/`.

## Просьба владельца

Решение владельца, переданное запустившей сессией: оставить сборщик Angular, а проверку библиотек
поправить в пакете, не ослабляя её.

> Вместо файла `vitest.config.mts` принимать как равноправную форму запуск тестов сборщиком Angular:
> цель `test` в `project.json` на исполнителе `@angular/build:unit-test`, существующий файл в
> `options.tsConfig` и собственный `tsconfig.spec.json` у библиотеки.

Выпуск версии в задачу не входит: его делает запустившая сессия.

## Что сделано

- `lib-manifests.mjs`: `checkTestRunner` принимает собственный `vitest.config.mts` либо форму
  сборщика целиком. Любой неполный набор — отказ, текст называет обе формы.
- `lib-common.mjs`: `vitest.config.mts` убран из `REQUIRED_FILES`, добавлен `ANGULAR_TEST_EXECUTOR`.
- Тексты паттерна `lib-layers-new`, ловушка проверки тестов и комментарий в `lib-domains.mjs`
  приведены к двум формам; команда подсчёта либ без тестов считает по `project.json`.
- Сценарий SC-AK-1598 в спеке раскладки и в `tests/checks-lib-layers.test.sh`: принятие, каждый
  отказ, обе формы сразу.

## Решения

- **Номер сценария 1598.** Номер 1140 уже занят другим сценарием.
- **`options.tsConfig` проверяется как существующий файл, не как собственный файл библиотеки.**
  Слова владельца требуют существования файла; ссылка на чужой файл принимается.
- **Токены Nx в `tsConfig` не раскрываются.** В дереве таких значений нет.
- **Генератор домена в пакете не лежит.** Править там нечего.

## Промахи

- Первые правки сделаны скриптом до заведения ветки задачи; хук их пропустил, они вошли в ветку.
- Состояние в `progress.md` записать не удалось: проверка состояния ссылалась на скрипт, которого
  в дереве нет.
