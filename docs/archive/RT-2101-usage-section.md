# RT-2101 — раздел «Использование»: таблица скилов, период, панель сессий

**Ветка:** `RT-2101-usage-section` · **Разобрано:** 2026-09-14 · эпик RT-2097, задача 4 из 4, стоит на `RT-2100-usage-read`

## Просьба владельца

> рализуй модуль аналитики полностью без остновок и вопросок, все примеры я тебе дал, работай автономно врежиме ночной работы

Ответы владельца по замыслу — в записи RT-2098. Вопросов в этой задаче не задавалось: сессия ночная.

## Что сделано

- В общей выборке списка появился период `from`/`to`; в адрес он попадает только парой, остальные разделы его не шлют.
- `GET /api/usage` отвечает страницей: `page`, `size`, `sort` из `loads | skill | sessions | denials`, `dir`; итог считается окном в том же запросе. Период, не названный запросом, — последние тридцать дней по часам приёмника, ответ называет оба дня.
- Договорённость `IUsageRow`, `IUsageSessionRow`, `IUsagePage` переехала в общую либу; модель админки объявляет сторону `Api` псевдонимом.
- Раздел «Использование»: семь либ `usage/{util,api,data-access,ui,shell,feature/list,feature/sessions-aside}`, пункт меню под правом `usage:read`, маршруты `usage` и `usage/:skill` в выходе `ro`, подписи в словаре приложения.
- Фильтр периода в общем ui — два `rt-date-picker`; показывает период из ответа, когда адрес его не называет. База хранилища списка получила зацепку `pageRead` — единственное место, где раздел читает то, что страница несёт помимо строк.
- Стенд сквозного набора шлёт строки наблюдений через приём; `usage-section.spec.ts` закрывает SC-MB-348…SC-MB-352. Сценарии приёмника SC-MB-353 (период по умолчанию) и SC-MB-354 (страница) добавлены; договорённость влита в поддомен `docs/specs/message-bus/usage/`.
- На ветке RT-2099 исправлено расхождение проверки слоёв: приложение читает предел строк из util наблюдений, а не через перевыпуск из feature. Исправление влито вперёд в RT-2100 и RT-2101 — обе ветки несут коммиты слияния.

## Умолчания вместо вопросов

- **Операция использования отвечает страницей, раздел наследует базу списка целиком.** База читает страницу; ответ целиком потребовал бы вторую базу. Цена ошибки: постраничность одного запроса.
- **Период — в общей выборке, пустой у остальных разделов.** Цена ошибки: два поля одного общего типа.
- **Период по умолчанию считает приёмник — тридцать дней по своим часам.** Один расчёт на стороне, у которой часы приёма. Цена ошибки: одна функция.
- **Фильтр периода — два выбора дня, в адрес уходит только пара.** Полупустой период ничего не перечитывает. Цена ошибки: один компонент общего ui.
- **Род скила показан словом словаря, признак сессии — как есть.** Владелец сказал: сессии по хэшу и количеству.
- **Панель сессий не листается.** У скила за период сотни сессий самое большее; список идёт целиком.

## Решения по ходу

- **Две новые сцены приёмника — SC-MB-353, SC-MB-354.** Сцены раздела называют человека; юнит-тест под их номером обещал бы сквозной путь, которого не проходит.
- **Страница использования расширяет общий запрос страницы целиком, с признаком дерева.** Иначе — второй тип для одного списка.
- **Стенд сеет строки через приём, не через хранилище.** Строка мимо приёма проверяла бы хранилище, а не путь.
- **Кадры всех разделов сняты заново.** В шапке появился пункт; расхождение каждого кадра измерено по строкам пикселей и лежит только в полосе шапки.
- **Ячейки таблицы операций в спеке — без обратных кавычек.** Проверка спек читает ячейку в кавычках как имя процедуры и ищет её декоратор.
- **Двойник `pageRead` в базе хранилища объявлен пустым методом с отключённой парой правил линтера.** Абстрактный метод заставил бы каждый раздел писать пустое тело.
