# RT-1766 — импорты из соседнего пакета не сверялись с опубликованной версией соседа

**Ветка:** `RT-1766-published-neighbour-imports` · **Разобрано:** 2026-09-06

## Что было не так

Пакет можно было опубликовать с импортом символа из соседнего пакета, которого в
опубликованной версии соседа нет: в дереве сборка и типы читают исходники соседа, и всё зелёное,
а у потребителя пакет не собирается. Так вышли два кита: один с `EListSortOrder` из утилит,
второй с `EPosition` из ядра.

Задача лежала в очереди с 2026-09-03 и взята после конца эпика RT-907 при действующем слове
владельца работать без остановок. Груз приёма к этой минуте разобран.

## Что сделано

- Проверка `check:package-imports`: импорты из соседей читаются из исходников пакета, экспорты
  соседа — из типов наибольшей опубликованной версии под диапазон манифеста; пакет забирается из
  реестра и кладётся в кэш под каталогом зависимостей. Отказ называет пакет, символ, соседа и его
  версию.
- Два режима: в гейте пуша и конвейере символ, который есть в исходниках соседа в дереве, ждёт
  публикации соседа и проверку не роняет; в конвейере публикации строгий шаг перед публикацией
  роняет её на любом недостающем символе.
- Проба на фикстуре без сети, 23 случая; поддомен спека «Проверки публикации» с привязками и
  сценариями SC-AK-893…902; проверка замка после публикации привязана там же.

## Решения

- **Гейт пуша терпит символ, ждущий публикации соседа.** Сегодня второй кит импортирует из ядра
  символ, которого в опубликованном ядре 0.4.0 нет, а ядро 0.5.0 ещё не вышло: без этого режима
  проверка красила бы любую правку кита до выпуска ядра. Порядок публикации стережёт строгий шаг
  конвейера.
- **Экспорты соседа читаются из типов, а не из сборки JavaScript.** Типы перечисляют интерфейсы
  и типы, которых в JavaScript нет.
- **Диапазон манифеста разбирается своим кодом.** Библиотека semver прямой зависимостью не
  стоит; формы диапазона — те, что пишут скрипты подъёма версии.
- **Спек — новый поддомен, а не поддомен проверок дерева.** Тот стоит у предела длины, а
  проверка замка после публикации до сих пор не была привязана ни к одному спеку.

## Цена решения

Первый прогон проверки на машине ходит в реестр за каждой версией соседа; дальше версии лежат в
кэше. Обход цепочки `export *` сперва брал `.js` рядом с `.d.ts` и находил пустой список имён —
поймано на настоящем дереве, а не пробой: проба покрывала только типы без соседних файлов.
