# Находки эпика об экранах админки в слое правил

Задача RT-863, PR #864. Заведена после того, как эпик RT-779 кончился и владелец прочитал
накопленные им находки разом.
Прежний адрес записи — `docs/tasks/RT-863-agent-kit-findings-from-admin-epic/`.

## Что решал владелец

**Об объёме.** Все шесть находок эпика, а не только три от последней задачи.

**Об адресе находки о разборе кадра числами.** Пакету, статьёй о разборе кадра, — а не
уточнением в правило этого дерева.

**О версии.** Поднять на один минор.

## Куда уехала каждая находка

| Находка                                                        | Ресурс пакета               |
| -------------------------------------------------------------- | --------------------------- |
| Гард уборки стоит только на машине исполнителя                 | закон о поставке, статья    |
| Паттерн панели называл законным обход готового                 | паттерн панели, перечень    |
| Оставленный свой стенд отравляет следующий прогон              | правило проверок, ловушка   |
| Растр браузера не назван — кадр не сходится сам с собой        | правило проверок, статья    |
| Маска закрывает содержимое, но не ширину                       | правило проверок, статья    |
| Разбор упавшего кадра начинается с чисел, а не с картинки      | правило проверок, ловушка   |

## Что оказалось не так, как думали

**Версия пакета веткой не поднимается.** Рабочий процесс публикации сам поднимает её доводом
`minor`, пишет журнал изменений, ставит метку и публикует; правка манифеста веткой дала бы
подъём дважды. Отсюда же второе: запускать публикацию из ветки задачи нельзя — процесс коммитит
подъём и ставит метку на ту ветку, на которой запущен, то есть опубликовал бы невлитое.

**Надстройка дерева над паттерном панели не снимается правкой пакета.** Она держит имена
компонентов кита, а пакет их назвать не может. Правка закрывает другое: перечень пакета больше
не ставит свою разметку первой и не учит обходить готовое раньше, чем спросить. В предложении
это записано строкой «чем закрывается» — иначе приехавшая редакция и надстройка, которую она
закрыла, не сопоставляются ничем.

**Привязка статьи в мёртвый код проверкой не принимается.** Три довода браузеру стоят ключом
настройки прогонщика, а ключ нигде больше не зовётся — местом исполнения он не считается. Статья
получила вердикт с причиной вместо якоря.
