# RT-3114 — main влита в ветку эпика, набор перед отправкой идёт одним циклом

Задача RT-3114 эпика RT-3043, ветка `RT-3114-main-into-epic-push-set`, 05.11.2026. Папка задачи
разобрана в эту запись. Порядок эпика лежит в `docs/plans/cargo-2026-11.md`.

## Просьба владельца

> влей сначала все пр от treble

После слияния восьми PR ветка эпика разошлась с main в шести файлах. На вопрос, что делать с этим
до слияния #3113, владелец ответил:

> Задачу сейчас, #3113 подождёт

## Что было

Эпик вынес цикл набора перед отправкой в общий файл `push-set.sh`, чтобы проверка в сессии и git-хук
шли одним кодом. Main за это время дописала в старый цикл отметки зелёных шагов, базу ветки из стопки
и запуск тяжёлых шагов заранее. Взять одну сторону значило потерять правку другой.

## Решение

- Отметки и база стопки вошли в общий цикл, поэтому git-хук тоже их читает.
- Тяжёлые шаги заранее запрашивает только проверка в сессии: у неё предел времени хука. Git-хук
  запускает их сам.
- Команда запуска заранее оставлена со своим циклом: она печатает ход работы построчно.
- Шесть сценариев эпика заняли номера, выданные в main, и получили новые: SC-AK-1261…1266.

## Как шла работа

Ветка задачи не создавалась от ветки эпика без main, а слить main в ветку эпика с правкой кода не
давала проверка плана. Слияние сделано в локальной ветке эпика, от него взята ветка задачи, а сама
ветка эпика на GitHub не менялась. Находка лежит в `docs/plans/cargo-2026-11-findings.md`.
