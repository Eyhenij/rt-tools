# Задача эпика не закрывалась слиянием в ветку эпика, в Deployed ничто не переносило

Задача RT-2143 · ветка `RT-2143-board-epic-flow` · работа вне эпика, по слову владельца

## Разбор просьбы

> давай задача «закрыта» честно означает «влита в ветку эпика», можно ли настроить автоматизацию:
> по мержу в main двигать тикеты которые уезжают в колонку deployed??

На вопрос инструментом владелец выбрал «Да, все три шага»: закрытие задач при слиянии их PR в
ветку эпика, перенос карточек в Deployed по удавшейся выкатке, поле прогресса подзадач в виде
доски.

Что было: хост закрывает задачу по «Closes #…» только при слиянии в ветку по умолчанию, и #2134
осталась открытой после слияния #2135 в ветку эпика; запись прошлого RT-2085 говорила, что в
Deployed ничто не переносит; поле «Sub-issues progress» у доски было, в вид не выведено.

## Решения по ходу и доводы

- **Задача закрывается при слиянии её PR в любую ветку, кроме главной.** Слияние в ветку цепочки —
  та же дорога в эпик; признак — база влитого PR из события. Отвергнуто перечисление «Closes» в PR
  эпика: прогресс стоял бы на нуле до самого конца.
- **Deployed ставит выкатка, а не слияние в главную.** Слияние здесь ничего не выкатывает; карточка
  в Deployed после выкатки значит «стоит на узле». Шаг не роняет выкатку.
- **Задача ещё открытого эпика остаётся в Done.** Сухой запуск без этого условия унёс бы в Deployed
  #1899 — задачу эпика RT-1896, влитую только в его ветку. Родитель читается из подзадач хоста:
  открыт — карточка ждёт эпика.
- **Токен доски — секрет из токена машинной учётной записи.** Разовый токен прогона доску
  пользователя не читает. Секрет поставлен из файла, значение нигде не печаталось.
- **Колонка `deployed` названа в настройках доски.** Команда переноса и новый отбор читают один
  объект; без имени отбор отказывал бы честно, кодом 2.
- **Переопределение образца названо полным идентификатором ресурса.** Файл `git-workflow-commit.md`
  раскладка не подобрала: у ресурса приставка свойства, `git-workflow-commit.github.md`.

## Что осталось

- Живое подтверждение обоих действий приходит после слияния: первый PR задачи в ветку эпика и
  первая выкатка. Файлы конвейера разобраны разборщиком, отбор проверен сухим запуском и набором
  сцен; переключатель действия регистрируется главной веткой, и ручным запуском с ветки его не
  проверить.
