# RT-3037 — проверка путей считала мёртвыми файлы рабочей копии вне истории

Задача RT-3037, ветка `RT-3037-doc-paths-copy-files` от `RT-3036-pr-base-refresh`, 02.11.2026.
Работа вне эпика. Папка задачи разобрана в эту запись.

## Просьба владельца

Из разбора PR #3014:

> tools/doc-paths-allowlist.json:33/37: две записи под RT-2994 к задаче не относятся.
> Убери их; если путь мёртв из-за общего правила дерева — вынеси отдельной задачей, не
> закрывай чужим номером.

## Что было

- `tools/check-doc-paths.mjs` судит адрес под `.claude/…` по диску того, кто её запустил. В копии с
  именем `.claude/rt-kit/tree-name` есть, в свежей копии и на раннере — нет. С `.claude/handoff/` то
  же: папку создаёт хук передачи при первом закрытии сессии.
- Измерение 02.11.2026 на свежей копии `origin/main` до PR #3014: пять расхождений, все на этих двух
  адресах — в таблице назначений и в спутниках правил `task-flow`, `turn-conduct`, `turn-entry`.

## Решение

- Обе строки — в списке исключений под RT-3037, у каждой своя причина. Так уже стояла строка
  `.claude/rt-kit/browser-device-id` под RT-1871.
- Отвергнуто: научить проверку пропускать всё, что покрыто `.gitignore`. Тогда она пропускала бы и
  мёртвые ссылки на результаты сборки. Цена выбранного: каждый новый файл копии вне истории требует
  своей строки.
- Вопрос владельцу не ушёл: проверка вопросов его отклонила, а в правилах ответа нет. Взят
  рекомендованный вариант.

## Как закрылось

- Обе строки под RT-3037 уже стояли в ветке PR #3014 — их перенесли туда с номера RT-2994 по
  разбору этого PR. Владелец влил PR #3014 02.11.2026 коммитом `b71bbc781`, и строки пришли в main.
- Ветка этой задачи строк списка не меняет. После слияния main свежая копия ветки даёт «documents
  checked 1056, no divergences».
