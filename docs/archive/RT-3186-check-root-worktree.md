# RT-3186 — проверка плана во второй рабочей копии судила по истории главного дерева

Задача RT-3186 вне эпика, ветка `RT-3186-check-root-worktree` от `main`, 11.11.2026. Папка
`docs/tasks/RT-3186-check-root-worktree/` разобрана в эту запись.

## Просьба

Слово владельца: «продолжай, заведи задачу на ошибку с root».

Ошибку нашли, когда доводили до PR ветку RT-3140 во второй рабочей копии. Сессия была запущена в
главном дереве и переехала в копию. Путь проекта у проверок остался путём главного дерева. Слияние
`origin/main` в RT-3140 встало на конфликте, и любое его разрешение проверка плана блокировала словами
«there is no plan», хотя папка задачи была разобрана коммитом ветки.

## Причина

`rt_is_app_code_default` писала в общую переменную `root` путь `CLAUDE_PROJECT_DIR`. Проверка плана
хранит в `root` корень копии, где идёт правка. Внутри исключения для конфликта слияния признак
вызывался после присваивания, и признак разобранной папки читался из истории главного дерева.

## Решения

- **Переменные признака получили свою приставку.** `local` в файле умолчаний не используется ни
  одной функцией, поэтому взят тот же способ, что у соседей: свои имена.
- **Путь во второй копии того же репозитория считается кодом этой копии.** Раньше такой путь лежал
  вне пути проекта, и признак отвечал «не код»: правка инструментом во второй копии не судилась
  вовсе. Чужой репозиторий и путь вне репозитория по-прежнему вне требования. Одна копия
  узнаётся по общему каталогу git.
- **Относительный путь команды берётся от каталога вызова.** Раньше он приклеивался к пути проекта
  сессии, то есть к другому дереву.
- **Ветка, корень и план берутся из копии, где лежит файл правки.** Каталог вызова может
  остаться в дереве сессии, пока инструмент пишет во вторую копию по полному пути. Первая версия
  правки брала ветку из каталога вызова, и такая правка получала отказ по ветке дерева сессии. Это
  нашла роль `product-strategist` до открытия PR. Каталог вызова остаётся запасным, когда у файла нет
  рабочей копии.
- **Признак кода общий для нескольких проверок.** Проверки начала работы, линтера по следам правки,
  якорей и единообразия во второй копии того же репозитория теперь судят правку, где раньше
  молчали. Их наборы зелёные.
- **Другие проверки, которые берут корень из пути проекта, не тронуты.** Push по правилу поставки
  идёт из копии, где стоит сессия, и проверка push не пропускает чужую копию намеренно.
