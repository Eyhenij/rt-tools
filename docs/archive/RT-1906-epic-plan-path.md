# RT-1906 — сверка очереди работ читала замысел эпика по первому пути в теле карточки

**Ветка:** `RT-1906-epic-plan-path` · **Эпик:** нет · **Разобрано:** 2026-09-08

## Просьба владельца

`npm run check:board` давала четырнадцать строк подряд о том, что задачи эпика #1870 в его замысел
не входят. Все четырнадцать ложные: состав в замысле записан, и каждая задача в нём есть. Тело
карточки эпика называет два документа — сначала решение, следом замысел, — а сверка брала первый
путь с каталогом. Решение таблицы состава не несёт, состав выходил пустым. Ложные строки хоронили
настоящие: рядом стояли «у задачи нет исполнителя» и «замысел эпика не лежит на диске».

## Что сделано

- Из тела карточки берутся все пути на документы. Замыслом считается первый из лежащих на диске, у
  которого читается таблица с колонкой задач. Приём не зависит ни от языка тела, ни от имени
  каталога замыслов: проверка едет пакетом, а каталог — имя дерева.
- Разведены две строки отказа: «ни одного из названных документов нет на диске» ведёт заводить
  замысел, «лежат, а состава не несут» — писать таблицу.
- Статья спека со строкой компаньона и сценарием `SC-AK-919`; две пробы набора сверки.

## Чем подтверждается

- `bash projects/agent-kit/tests/checks-board.test.sh` — `63 ok, 0 провалов`; на прежней проверке
  обе новые пробы краснеют.
- `npm run check:board` — 4 расхождения против 17 до правки.
- `bash projects/agent-kit/tests/run.sh` — `ВСЕ НАБОРЫ ЗЕЛЁНЫЕ`; `pnpm run check:all` — код 0.

## Что осталось открытым

- Вторая сторона связи читается так же грубо: принадлежность эпику сверка узнаёт по любому
  упоминанию его номера в теле задачи, а не по строке, которую сама же предписывает. Тело этой
  задачи называло номер эпика в объяснении — и сверка записала её в эпик. Заведено отдельной
  задачей.
- Замысел эпика #1896 и правда не лежит на диске главной ветки: он живёт в невлитой ветке, и это
  работа того, кто её ведёт.
