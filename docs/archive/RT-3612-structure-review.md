# RT-3612 — ревью смотрит структуру кода, команда считает переделки

Задача RT-3612 эпика RT-3603, запись от 2026-11-25. Прежний адрес: `docs/tasks/RT-3612-structure-review/`.

## Просьба владельца

> Ты … должен следить за зацеплением. Ты … должен следить за изолированностью кода, блоков, модулей

> заведи новый эпик: сделай анализ видео https://www.youtube.com/watch?v=g1vNWD9skHU и опиши план как следует писать качественный код по принципам изложенным в этом видео, встрой эти принципы в наш task flow

Шестая задача эпика. Ответ владельца на план: «Одобряю план RT-3612». О вехе G эпика 25.11: «Сравнивать с 142»,
«Превышений меньше 18»; о задачах без коммита круга: «сделай анализ самостоятельно, что нужно делать в идеальном
варианте».

## Что решили при разборе

- **Команда лежит в `tools/`, а не в пакете.** Заголовок коммита круга и заголовок слияния — порядок этого дерева.
- **Строки круга считаются без разложенных копий, папки задачи, архива и планов.** С копиями медиана двадцати была
  275,5, без них — 177,5.
- **След берётся из первой версии плана.** Строка, дописанная после кода, прятала бы файл вне следа.
- **Строку с планом и выводом зацепления получает только `qa-engineer`.** Общий текст запроса читают три роли, а
  `goal-critic` плана не получает.

## Что решили по ходу

- **Роль на образце зовётся отдельным процессом `claude -p --agent qa-engineer`.** Подроль сессии держит текст,
  загруженный при её старте, и нового раздела не знала.
- **Веха G пересмотрена словом владельца.** База — 142, медиана 15 задач до эпика; первая половина — превышения меньше 18:
  новых циклов и обходов не было и до эпика, их отказывает `check-coupling`.
- **Круг без правок оставляет пустой коммит.** Так команда отличает «круг ничего не нашёл» (0 строк) от «круга не было».
- **Признак копии повторяет форму заголовка движка.** Прежний ловил шесть исходников пакета, а движок по «Границам» не
  правится.

## Что изменили круги ревью

- **Текст роли.** Фраза о плане снова условная; адрес находки — строка файла, а не диффа; связь блоков названа;
  важность модуля с двумя обязанностями — «medium or higher, never low or minor», под обе шкалы.
- **Конвейер.** Грань `structure` сверяет «Границы» по файлам из «What was done»: диффа в конвейере нет. Разбор не
  строкой отказан.
- **Команда.** Самый ранний коммит круга; задача, влитая дважды, — один раз; итог без счёта проверки — «not counted», а
  не 0; файл учёта доски не вне следа; экспорты без вызова сняты.
- **Второй круг нашёл регрессию первого.** Первый круг сузил признак копии до первой строки, и копии с front matter —
  агенты и `SKILL.md`, 116 из 283 — стали правкой круга. Признак снова читает заголовок после front matter; числа
  вернулись к записанным. Там же: превышением считается и рост сверх числа плана; коммит, чей заголовок кончается
  другой задачей, — её коммит (таких заголовков в истории 327).
- **Третий круг** — по правилу о блокирующей находке во втором. Блокирующих не нашёл. Разбор вывода `check-coupling`
  вынесен в свой модуль: две роли в двух кругах назвали команду модулем с двумя обязанностями по правилу самой задачи;
  второй круг отбросил это бюджетом, и это было неверно. Заготовка плана планом не считается; задачи без плана
  названы строкой «without a plan»; роль называет строку плана, как её называет план, с английским именем в скобках.
- **Отчёт вехи эпика** — карточка RT-3656: запуск на двадцатом слиянии после выпуска, пороги и что сверить рядом.

## Цена

- **Семь запусков роли на образце.** С шестого роль зовётся без настроек пользователя и отвечает по-английски. Шестой
  назвал строки плана по-русски, и признак шага 1.4 его не принял. После правки текста роли седьмой дал `5`, и его
  ответ стал образцом.
- **Пять первых запусков.** Подроль сессии держала старый текст; отдельный процесс дважды ответил по-русски
  вопреки роли, а такой ответ проверка текстов не пускает в дерево. Каждый запуск — около шести минут.
- **Отдельный процесс роли крутит `turn-exit-guard`:** восемь отказов готовому ответу ревью. Записано в находки эпика.
- **Связи набора команды 0 → 2 при плане 1:** набору нужна и `check-coupling.mjs`.
- **Третий файл кода при бюджете в два и связи команды 0 → 2 при плане 1:** вынесенный в третьем круге разбор
  зацепления.
- **Регрессия первого круга стоила третьего круга.** Правка признака копии не была проверена на копиях с front
  matter, хотя в дереве их 116.
- **`tools/doc-paths-allowlist.json` вне следа:** адреса записанного ответа — файлы дерева образца.
- **Два красных прогона набора перед отправкой.** Сначала `projects/agent-kit/README.md` вырос до 501 строки при
  пределе 500. Потом сжатая строка потеряла форму, которую ищет свой же случай SC-AK-1970: после правки README не был
  прогнан набор ролей. Каждый прогон — около 20 минут, из них 12 — сценарии хуков.
- **Отправку отказала проверка состава набора.** Сессия запущена в главной копии, та стоит на `main` без
  `check-coupling`, и проверка отправки собирает набор по ней. Я поправил проверку состава так, чтобы она читала
  профиль своего дерева, — и тем заглушил верный отказ: гард по-прежнему не запускал `check-coupling`. Три роли
  показали это на разовых деревьях, правка откачена. Причина — задача RT-3658, разбор —
  `2026-11-25-push-judged-by-main-copy-seventh-time.md` в приёмнике.
