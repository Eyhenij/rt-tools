# RT-3180 — порог одной колонки и панель сведений поверх окна у рабочего стола

Задача RT-3180 вне эпика, ветка `RT-3180-workspace-overlay-breakpoint`, стоит на ветке RT-3179,
12.11.2026. Правила работы стали описанием второго кита «workspace-breakpoint».

## Просьба владельца

Передана сессией приложения 09.11.2026, текст задачи дословно:

> На планшете шириной 768 `rt-workspace` показывает одну колонку: список пропадает, а панель
> сведений выезжает поверх разговора без затемнения. Закрыть её можно только уходом к списку. Порог
> зашит в стилях: `@media(width<=768px)`, входа для него у компонента нет.
>
> Одобренные кадры приложения на 768 показывают другое. Список и разговор стоят рядом, а сведения
> открываются боковой панелью шириной 540 с затемнением и кнопкой «Закрыть».
>
> - У `rt-workspace` есть вход порога одной колонки. Без него поведение прежнее.
> - Выше этого порога список и разговор стоят рядом.
> - Пока панели не хватает места третьей колонкой, она открывается поверх разговора боковой панелью
>   заданной ширины.
> - У такой панели есть затемнение и кнопка «Закрыть». Она закрывается щелчком по затемнению и
>   клавишей Esc.
> - На телефоне вид прежний.
> - История в сторибуке на 768 и 375, светлая и тёмная тема.

Порядок от той же сессии: макет, код, сторибук с наложением на кадр, показ владельцу. Пуш, PR и
выпуск идут только после слова владельца «одобряю». Три правки кита выходят одним выпуском.

## Что сделано

- У рабочего стола два новых входа: порог одной колонки и ширина панели поверх окна, по умолчанию 540. Без входа порога вид прежний.
- Выше порога список и середина стоят рядом. Сведения открываются боковой панелью кита с
  затемнением и кнопкой «Закрыть», закрываются щелчком по затемнению и клавишей Esc.
- Ширина места страницы открыта у сервиса порогов: рабочий стол считает порог по ней.
- Истории витрины на 768 и 375 в обеих темах, в витрину добавлено окно «Планшет» 768 на 720.

## Решения по ходу работы

Куда ушло решение, сказано в конце строки.

- **Порог из входа считает компонент, а не стили:** число из входа в медиазапрос не подставить.
  Описание «workspace-breakpoint».
- **Панель поверх окна — боковая панель кита:** затемнение, Esc и ловушка фокуса там уже есть. Слой
  внутри рабочего стола затемнял бы только сам стол. Описание «workspace-breakpoint».
- **У панели поверх окна нет шапки:** в одобренном кадре сведения идут от верхнего края, вход
  заголовка не заведён. Описание «workspace-breakpoint».
- **Поля содержимого боковой панели сняты:** шаблон сведений писан под колонку без полей. Код
  стилей рабочего стола.
- **В кадрах после одобрения поправлены поля середины и полосы кнопок:** кадр держал поля 16 со всех
  сторон, а стили рабочего стола дают полосе 8 сверху и 16 по бокам. Этого вида задача не меняет.
  Только в макете.
