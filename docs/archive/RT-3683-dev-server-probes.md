# RT-3683 — Пробы стража dev-server-guard сходятся под нагрузкой

Задача RT-3683, запись от 2026-11-26. Прежний адрес: `docs/tasks/RT-3683-dev-server-probes/`.

## Решения разбора

- **Сервер пробы живёт, пока идёт проба, и гасится с ней.** Гонок две: сервер жил 10 секунд и мог
  умереть до вопроса стража, а `wait_for_port` ждал файл порта 5 секунд, и его неудачу никто не
  проверял — пустой `PORT` давал свободный порт и «allow». Вывод сервера уходит в `/dev/null`, чтобы
  сверка не ждала его открытый вывод; номер процесса берётся `SRV=$!` сразу после `&`, и тут же ставится
  ловушка `EXIT`, которая гасит сервер; предел жизни — две минуты (`120000)`), страховка от сироты. Сбой
  ожидания проверяет сама проба после вызова `wait_for_port`, а не функция набора. `wait_for_port` в `lib.sh` берёт предел вторым аргументом, по умолчанию прежние
  5 секунд; пробы ждут 30 секунд, а неудача ожидания печатает в stdout слова «the stand server did not
  start» и выходит с кодом 3 — поток ошибок пробы сверка выбрасывает. Ловушка перед `kill` печатает
  «the stand server died», если сервер уже мёртв, и ответ `lsof` по непустому порту: следующий красный прогон
  назовёт причину словами. Отвергнуто: поднять только предел жизни — медленный старт остаётся гонкой, а без ловушки
  сервер переживает пробу на весь предел.
- **Починку доказывают опыты под нагрузкой, а не один зелёный прогон CI.** Скрипт папки `variant.mjs`
  портит пробы четырежды: задержка 11 секунд после запуска сервера, старт сервера через 6 секунд,
  сервер без файла порта, сервер, погашенный сразу после порта; и три сверки разом — нагрузка. Задача
  закрыта, когда в прогоне CI на PR эпика зелёные SC-AK-1563 и шаг Hook suites, с номером прогона;
  красный SC-AK-1563 после починки — новый разбор по словам проб, а не перезапуск. Шаги CI после Hook
  suites на коде эпика ещё не шли: их зелень — признак эпика, не этой задачи.

## Решения по ходу

- **Ловушка пробы называет причину только при сбое.** Первая редакция печатала сырой ответ `lsof` в
  каждом прогоне — номер процесса и адрес ломали сравнение снимков на четырёх строках. Теперь `lsof`
  пишет одну ровную фразу, когда не видит порт. Довод: следующий красный прогон CI назовёт причину, а
  снимок останется ровным.
- **Признак задачи сужен до SC-AK-1563 и шага Hook suites.** Шаги CI после Hook suites на коде эпика ещё
  не шли; их зелень — признак эпика. Довод: product-strategist, третье чтение плана.
- **Отменено:** первая редакция разбора считала, что выход оболочки пробы гасит сервер сам, и чинила
  только предел жизни. Роли показали вторую гонку — ожидание порта в 5 секунд без проверки — и сервер,
  переживающий пробу; решение заменено ловушкой и долгим ожиданием со словами о сбое.
- **Цена:** 162 минуты активной работы по `pnpm run session:time --branches RT-3683-dev-server-probes`:
  ожидание ролей 64,6, проверки по ходу 58,6 — пять чтений плана ролями и опыты по 2–11 минут под
  нагрузкой.

## Чем подтверждено

Путь полный: правка задевает таблицу решений и обвязку наборов. Ревью шло в два круга, на каждом три роли: `qa-engineer`, `goal-critic` и `product-strategist`.

- **Второй круг:** исправлений нет. Снимок `--snapshot-save`/`--snapshot-compare` дал 1017 строк и 0 изменений.

Остальное:
- **План.** Роли прочли его трижды, затем дважды прочли правки. Метка одобрения — «Одобряю (Recommended)». `plan-red`: семь проверок красные до работы.
- **Шаги.** Все семь совпали на `07c74cf6f` и заново на `f31393e37`. Под нагрузкой ревьюеров (load 25–122) опыт шёл 6–11 минут без расхождений.
- **Набор перед отправкой** против `origin/RT-3624-delivery-speed`: зелёный.

Списано:
- Сбой обвязки стоит в отчёте сверки на месте решения: «the hook decided «the stand server did not start»». Хук в этом случае не запускался.
- Сирота живёт до 2 минут при SIGINT одному bash или SIGKILL.
- Слова ловушки обрезаются по 300 знакам при длинном stderr стража. У этих строк он пуст.
- На машине без `lsof` или без `node` ловушка назовёт не ту причину. В CI есть оба.
- `--mutate` при умершем сервере по-прежнему засчитывает «allow».

Не сделано здесь: в снимке проб строка `git-guard-delivery.sh:pr_create_wrong_number` порой меняется от запуска к запуску — в её тексте хеш временного коммита.
