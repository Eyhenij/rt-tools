# RT-2029 — аудит описаний давал ложное зелёное и ложное красное

**Ветка:** `RT-2029-spec-audit-false-green` · **Разобрано:** 2026-09-10

## Просьба владельца

> бери все жалобы и предложения из приёмника, верифицируй их по соотвтевию общему направлению
> развития пакетов, заведи эпик и под задачи и бери в работу

Задача эпика #2028. Девять записей приёмника от дерева `4cb9f399b4a9`, все об одном: пустой или
неразобранный вход давал зелёное.

## Что было не так

Аудит описаний отвечал не о том, что лежит в дереве, а о том, что он сумел разобрать. Пять мест:

- Заголовок сценария, который выражение не взяло, для обхода был обычной строкой текста. Номер
  брался из одной-трёх цифр — вся тысячная серия этого дерева не считалась: 54 сценария, их
  отметки покрытия и ссылки на них из тестов.
- Адрес привязки требовал у имени файла расширение. Описание образа, конфиг прокси и файл сборки
  объявлены одним словом, и статья, исполняемая ровно там, стояла под вердиктом «не проверяется».
- Строка корней процедур возвращала пустоту и при отсутствии строки, и при строке без путей. Шапка,
  назвавшая процедуры словами, оставляла три процедуры с их правами непроверенными при зелёном
  выводе.
- Живость символа считалась упоминаниями: объявление плюс файл теста рядом давали порог в два.
  Функция, покрытая тестом и не зовомая из приложения, числилась живой.
- Метка права при процедуре бралась первым совпадением в сыром тексте, и образец вызова из
  пояснения подменял настоящую метку.

## Что сделано

- Строка, начатая как заголовок сценария и не взятая выражением, называется расхождением с файлом
  и номером строки. Номер расширен до четырёх цифр, префикс — до шести букв.
- Адрес привязки принимает имя файла в двух видах: с расширением и целиком без точки.
- Строка корней процедур получила третье состояние: объявлена и не разобрана. Слово «нет»
  принимается с пояснением после него.
- Живость привязки считается по файлам, которые не тесты. Исключение не действует для обвязки
  тестов и для файлов, опубликованных через `public-api.ts`.
- Снятие пояснений переехало в общий модуль; разбор процедур пользуется им наравне с разбором
  привязок.
- Две статьи в закон о проверяемости, две в правило описаний, все с привязками.
- Карта проверок берёт помощников аудита описаний, а не только файл с приставкой `check-`.

## Почему так, а не иначе

- **Исключение теста действует только для кода приложения.** Помощник, объявленный в самой
  обвязке тестов, тестами и зовётся по назначению: судимые той же мерой, статьи правила о тестах
  покраснели бы разом.
- **Символ опубликованного файла считается живым.** У кита, который ставят другие деревья, зовут
  его снаружи, и по видимым здесь вызовам весь публичный набор читался бы мёртвым кодом.
- **Дерево называет файлы обвязки списком, а не каталогом.** Первым заходом туда попал весь
  каталог витрины, и красными стали компоненты, которые истории зовут по-настоящему.
- **Слово «нет» принимается с пояснением.** Пятнадцать законных шапок пишут «none — операции
  объявлены контроллерами»; требование одного слова сделало их неразобранными разом.

## Чем проверено

- `npm run check:specs` — расхождений 0, сценариев 1514 против 1460 до правки.
- `bash projects/agent-kit/tests/run.sh` — «ВСЕ НАБОРЫ ЗЕЛЁНЫЕ», код выхода 0.
- Семь проб выражения адреса: три имени без расширения новая форма берёт, прежняя не берёт ни
  одного; четыре обычных берут обе.

## Что нашлось по дороге

Статья о двусмысленных именах не исполняется: функция `ambiguousNames` написана, покрыта тестом
и не зовётся ни установкой файлов, ни `doctor`. Набор с двусмысленным именем проходит молча.
Заведена задача #2041, статья стоит под вердиктом с её номером.

## Записи груза

Девять записей чужого дерева. В состояние «в работе» они не переводятся: по правилу разбора
груза чужую запись двигает публикующий, и только шагами «сделано» и «выпущено».
