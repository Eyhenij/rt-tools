# RT-3309 — правило защиты области пускает рамку Метрики

Задача RT-3309 вне эпика, ветка `RT-3309-auth-metrika-frame-src` от main, 14.11.2026. Папка
`docs/tasks/RT-3309-auth-metrika-frame-src/` разобрана в эту запись.

## Просьба

> Да, отдельной задачей

Ответ на вопрос, пускать ли рамку `mc.yandex.ru` в `frame-src` области продукта, после проверки
счётчиков на узле входа. Затем:

> возьми RT-3309 в работу

## Откуда взялось

На узле входа страница входа области с настоящим номером Метрики показала в консоли отказ
рамки `https://mc.yandex.ru/` по `frame-src 'self' https://www.google.com`. Хиты и `watch` ушли,
рамка `metrika/match.html` — нет. На стенде с выдуманным номером рамку Метрика не просит: настройки
тег берёт по номеру.

## Что сделано

- Область `rt` объявляет все заголовки защиты: `frame-src 'self' https://mc.yandex.ru`, остальные
  — прежние значения Keycloak, прочитанные из API администратора стенда.
- Сценарий SC-AUTH-117 и сквозной тест: заголовок страницы входа с кодом 200.
- Вопрос Q-2 спека закрыт, решение о рамке переписано.
- Руководство подключения показывает блок для области продукта; файл области продукта лежит в
  его дереве.

## Решения

- **Карта заголовков объявлена целиком.** Карта из файла области заменяет стандартную, и
  пропущенный заголовок перестал бы уходить.
- **Добавлен только `https://mc.yandex.ru`.** Другие хосты Метрики ничего не просил.
- **Тест ловит ответ с кодом 200.** Первый ответ адреса входа — переадресация без заголовков
  защиты; первая версия теста поймала её и упала с пустым списком.

## Что показал стенд

- Сквозной набор входа: 17 из 17. Один запуск между ними упал на двух тестах раскладки — приложение
  не дошло до Keycloak; запуск начался строкой «Keycloak mounts the theme of another tree», то есть
  общий стенд в ту минуту пересоздавало соседнее дерево.
