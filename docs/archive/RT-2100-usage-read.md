## Что сделано

- Право `usage:read` в закрытом наборе; миграция `20260914210000_grant_usage_read` дописывает его роли владельца; стенд сквозного набора называет его в своей роли.
- Период чтения — два дня включительно, не длиннее четырёхсот; разбор чистый, отказ называет параметр.
- `GET /api/usage?tree=&from=&to=` — строка на скил: род, загрузки, отдельные сессии, отказы гейта; самые загружаемые первыми, при равных — по имени; скил с одними отказами — правило. `GET /api/usage/:skill/sessions` — день, признак сессии, сколько раз, свежий день первым. Обе под `usage:read`; дерево по признаку, неизвестное — 404; пустой период — пустой список.
- Оба запроса и миграция права проверены на одноразовой базе восемью строками: числа, порядок и права роли сошлись.

## Умолчания вместо вопросов

- **Запросы своим текстом, не группировкой клиента хранилища.** Клиент не считает отдельные сессии; договорённость велит считать хранилищем. Цена ошибки: один запрос переписать на группировку клиента.
- **Текст запроса подтверждён стендом, а не двойником.** Спека контроллера проверяет решение — период, право, дерево, пустой ответ, подставленные значения; числа читает сквозная спека раздела в RT-2101. Пока — ручная проба на одноразовой базе. Цена ошибки: неверный счёт увидится задачей позже.
- **Род скила с одними отказами — «правило».** Гейт правил отказывает по правилу; строка рода не несёт. Цена ошибки: одно слово.
- **Дерево названо признаком, как в списке сводок.** Цена ошибки: один параметр.

## Решения по ходу

- **Поиск дерева по признаку живёт в data-access наблюдений.** Либа feature наблюдений по границам модулей не видит data-access деревьев.
- **Двойник хранилища запоминает текст и значения запроса.** Спека сверяет подставленные дерево, период и скил, а не исполняет SQL.
