# RT-3434 — шаг меряется после разбора папки, одно несовпадение перед PR не снимает отметку

Задача RT-3434 эпика RT-3471, запись от 2026-11-22. Прежний адрес: `docs/tasks/RT-3434-step-after-archive/`.

## Просьба владельца

> продолжай RT-3471, эпик (четвёртая часть переделки проверок)

Слово владельца от 21.11.2026 перенесло задачу в эпик RT-3471. Карточка #3434: после разбора папки
команда `step` отказывала «the task folder differs from the commit of the plan», а движок звал
работу назад в «этап-идёт» и требовал ту же команду. Перемер перед PR снимал отметку с первого
несовпадения и показывал только «получено 0». Точка B эпика для задачи: разобранная задача не
откатывается в «этап-идёт», снятая перед PR отметка возвращается.

План одобрен владельцем 22.11 ответом «Одобряю план RT-3434».

## Что сделано

- Команда `step N.M` на разобранной папке возвращает папку из истории на время замера, меряет
  шаг на ходе работы своего замера, пишет отметку и убирает папку со всем, что в неё записала
  проверка. `step --done` меряет сделанные шаги так же, как перемер.
- Шаг, который история не отмечает сделанным, и папка, правленая после плана, отказаны с ходом
  `git revert --no-edit <коммит разбора>`; проверка шагов этот ход пропускает.
- Запись о возврате лежит в каталоге git своей копии: процесс, корень, отпечаток каждого файла
  до его текста. Старт движка убирает папку мёртвого запуска; правленую оставляет и называет
  каждый раз; второй шаг при живом запуске отказан.
- Перемер перед PR повторяет несовпавший шаг в его группе, пока самый долгий первый прогон
  группы помещается в остаток бюджета 1500 с; отметка снимается только со второго несовпадения.
- Под строкой несовпавшего шага — команда, три последние строки вывода и ошибок, а у проверки
  `… | grep` — строки провала до последней трубы.
- Отказ конца хода без папки и хук открытия PR называют шаги по номерам с командой замера.

## Что решили и почему

- **Примитивы возврата лежат в источнике истории `git.mjs`.** `flow-step.mjs` упирался в предел
  500 строк, а новый модуль `flow-*.mjs` проверка шагов отказывает: след плана его не называет.
- **`tee` ставится только перед замыкающим `grep`.** В `case`, `((`, `[[`, `>|`, с обратной косой
  и `PIPESTATUS` труба под `tee` меняет смысл команды.
- **Шаг, который перемер не может повторить, теряет отметку после одного прогона.** Это шаг за
  пределом 540 с или группа, не помещённая в остаток бюджета: PR отказан всё равно.
- **Правила разбора называют одно исключение — откат, который назвал движок.** Иначе правка
  внутри папки после разбора невозможна.

## Чем подтверждено

- Живая проверка на ветке RT-3423 с разобранной папкой: старый движок отказывал `step 4.1`, новый
  — «получено 1 · совпало», папки и записи после нет, состояние «работа-отдана». Перемер перед PR
  там же: 9 шагов из 9 за 218 с. После второго круга: `step 4.1` совпал, `.DS_Store` в месте
  папки отказан по имени.
- Наборы: движок — 261 ok, шаг после разбора — 45 ok, род стражей — 15 ok; `nx affected -t lint
  typecheck test test-hooks` зелёный; `sync --check` сходится; аудит спеков чистый.
- Два круга ревью тремя ролями; подтверждённые находки исправлены в ветке.

## Цена

- Повтор числа процесса может выдать мёртвый запуск за живой: папка останется до следующего старта.
- После отката измеритель разбора считает выполненным старый коммит разбора; отказ открытия PR
  по папке называет свой ход.
- Пока идёт замер, `git add -A` вернёт возвращённую папку в индекс.
- `step` из подкаталога ищет корень от каталога вызова.

Эти четыре записаны находками эпика.
