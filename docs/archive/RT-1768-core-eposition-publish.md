# RT-1768 — core 0.4.0: переименование EPosition доведено до реестра

**Ветка:** `RT-1768-core-eposition-publish` · **Разобрано:** 2026-09-03

## Что было не так

Потребитель не собирался: `@rt-tools/ui-kit@0.5.0` импортирует `EPosition` из `@rt-tools/core`, а
опубликованный core 0.3.1 экспортирует только `POSITION_ENUM`. Переименование лежало на main,
версия пакета там оставалась 0.3.1.

## Что сделано

- Опубликован core 0.4.0 (переименование экспорта — ломающее, в 0.x идёт минором). Бамп
  переписал зависимость от core в store и ui-kit; ui-kit-v2 в каскаде не было — его зависимость
  поднята здесь руками, а сам пакет добавлен в список `update-version-core.cjs`.
- Лок-файл синхронизирован, core 0.4.0 добавлен в `minimumReleaseAgeExclude`.
- Правило `task-flow` и его холодная часть сжаты до предела длины, два перечня сценариев записаны
  долгом за RT-1767: без этого гейт пуша красный на самой главной ветке.
- Следом публикуются store, ui-kit и ui-kit-v2 с зависимостью `^0.4.0`, чтобы у потребителя не
  оказалось двух копий core.

## Чем подтверждено

`npm view @rt-tools/core version` → 0.4.0. Сверка импортов из core по опубликованным d.ts:
ui-kit просил только `EPosition`, ui-kit-v2 и store — символы, которые есть и в 0.3.1.
