# Grill

## The owner request

> 1. `rt-thread-list`: the decorative empty-state preview rows (`emptyPreviewRows`, currently icons
>    `user`, `users`, `user`) become configurable through a signal input (suggested name
>    `emptyPreviewIcons: readonly string[]`, default the current three; keep the `offset` pattern:
>    middle row offset). Follow the kit's input naming / typing conventions (icon name type if one
>    exists, e.g. from `iconsName`).
> 2. `rt-ai-chat` (rich-editor entry): pass icons into its `<rt-thread-list>`; for an AI chat the
>    default preview icons are `sparkle`, `bot`, `sparkle` (both exist in the kit icon set — verify).
>    Expose an input on `rt-ai-chat` too if that fits the kit's API canon, default the AI icons.
> 3. Tests, README/spec/changelog entries the repo rules require.
> 4. Run the repo's checks, build the ui-kit-v2 dist.
> 5. Commit and push the branch. No merge, no publish in this run.

## What the tree already has

- `rt-thread-list` draws three decorative preview rows in its empty state from the constant
  `emptyPreviewRows`: icons `user`, `users`, `user`, the middle one shifted by the modifier `offset`.
- The icon name type is `IRtIcon.Name` from `@rt-tools/ui-kit-v2/core`; `sparkle.svg` and `bot.svg`
  lie in `projects/ui-kit-v2/src/assets/icons`.
- `rt-ai-chat` passes its texts and states into the nested `<rt-thread-list>` by inputs; every text
  input defaults to the kit's own value.
- The assistant chat has a spec `docs/specs/ui-kit-v2/ai-chat/`; the thread list has none, its
  inputs are listed in `Overview.mdx` and `CONTEXT.md` next to it.
- The changelog is generated by the publish workflow from the commit subjects.

## What the rules already say

- The default look of the second kit does not move: a new input defaults to what is drawn today.
- An input is a signal input with an explicit type; its row goes into the inputs table of
  `Overview.mdx`.

## Questions and answers

The work came as a ready order with the owner's authorization; every question is closed by the
request or by assumption.

- **Does the task change the behaviour?** Yes: two new inputs; the assistant chat's empty list of
  conversations draws other icons.
- **Does it need an edit of a law or a rule?** No — question closed by assumption.
- **One task or several?** One: the second input only passes into the first.
- **What is not part of the task?** The texts of the empty state, its layout, merge and publish.
- **What shows the task is closed?** Specs of both components pass, the kit builds, the branch is pushed.
- **Is there a sample?** The text inputs of `rt-ai-chat` passed into `rt-thread-list`.

## Decisions

- **The input is `emptyPreviewIcons: readonly IRtIcon.Name[]`.** — the kit types icon names by
  `IRtIcon.Name`; a bare `string` would accept a name the set does not have. Rejected: `string[]`.
- **Every second row is shifted.** — the current three keep their look: the middle row is shifted.
- **`rt-ai-chat` takes the same input with `sparkle`, `bot`, `sparkle` by default.** — an assistant's
  empty list of conversations shows assistant marks, and the consumer can still set its own.
