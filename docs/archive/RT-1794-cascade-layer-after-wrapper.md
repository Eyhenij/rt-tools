# RT-1794 — проверка слоя каскада не видела правил после обёртки

**Ветка:** `RT-1794-cascade-layer-after-wrapper` · **Разобрано:** 2026-09-05

## Что было не так

Проверка судила две вещи: сколько в файле обёрток слоя и нет ли правил до первой. Правила,
стоящие за закрывающей скобкой, она не читала вовсе и печатала про такой файл «все в подслое
rt-kit.components». Файл при этом выглядит обёрнутым, а часть его правил живёт вне слоя и
выигрывает у всего, что приложение объявит своим.

Нашлось это соседней работой — RT-1771, где два правила вынесены из слоя нарочно: они спорят с
неслоевым правилом чужой библиотеки и в слое проигрывают. Вынос по делу и вынос по недосмотру
дерево различить не могло.

## Что сделано

Проверка читает хвост за закрывающей скобкой. Правило там без отметки — расхождение; с отметкой
`rt-layer-outside` в пояснении рядом — принятый вынос, и число таких файлов стоит в итоге
проверки.

- Отметка выбрана вместо строки списка принятого: её читает тот, кто правит файл, а список —
  только тот, кто его открыл. Со списком следующий вынос по делу пришлось бы вносить туда
  задним числом.
- Заодно заведён первый набор сценариев по проверкам самого дерева: своя обвязка с одноразовым
  деревом, команда `npm run test:checks` и строка в наборе гейта пуша. Прежде проверки дерева
  гонялись только на нём самом — то есть на одном наборе входов, который сегодня зелёный.
- Набор проверен обратной стороной: со сломанной строкой разбора хвоста краснеют 4 пробы из 14.

## Цена решения

Отметка судится по всему хвосту файла, а не по соседству с правилом: пояснение с отметкой,
оставленное в конце файла, оправдает любое правило после него. Разделить их нечем, кроме разбора
CSS, а он стоит дороже самой проверки.
