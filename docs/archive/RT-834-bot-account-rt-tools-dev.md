# Работа подписывается и заводится записью `rt-tools-dev`, обход с чужим исполнителем снят

Задача RT-834, PR #835; вне эпика — просьба владельца пришла отдельной строкой.
Прежний адрес записи — `docs/tasks/RT-834-bot-account-rt-tools-dev/`.

## Просьба владельца

> вмержил, подтяни main и работай из аккаунта rt-tools-dev

Вопросов владельцу не задавалось: просьба однозначна, а всё, чего она касается, читается в
дереве. Метка `chore` у репозитория не заведена — задача взяла `refactoring`, ближайшую из
существующих.

## Что было верно на день работы

- Токен в `~/.config/rt-tools-bot-token` владелец подменил сам: он отвечал `rt-tools-dev`,
  число 317887029. Прежний остался рядом с суффиксом `.agent-backup`.
- Имена дерева при этом называли прежнюю запись `rt-tools-agent` и её число `314674161` в трёх
  местах — профиль поставки, настройка проверок и компаньон правила поставки.
- Прежняя запись была ограничена хостингом с 14 августа 2026 года: заведённое ею не видел
  никто, кроме неё самой, поэтому исполнителем задач приходилось ставить владельца, а компаньон
  правила это отступление и объявлял.
- Команда заведения задачи читает логин бота из настройки проверок и отказывала на скрытом
  имени — завести задачу, не тронув имя, было нечем.

## Решения и куда они ушли

| Решение                                                           | Куда ушло                                                                  |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Подпись коммита называет новую запись и её число                  | `RT_COMMIT_EMAIL` в профиле поставки — его же читает гард поставки на пуше |
| Логин бота в настройке проверок назван новой записью              | ключ `board.bot`: оттуда его берут команда заведения задачи и сверка борды |
| Утверждение об ограничении переписано в прошедшем времени         | компаньон правила поставки — обход с чужим исполнителем назван снятым      |
| Личность записи читается ответом хостинга, а не узнаванием строки | там же: вызов `gh api user` и то, с чем сверять его ответ                  |
| Имя бота в настройке правится до заведения задачи, а не после     | порядок захода; альтернатива — завести задачу через веб — отвергнута       |

Задача через веб отвергнута потому, что заведённая мимо команды она не попадает на борду и
гардом не отбивается: сверять её состояние было бы нечем.

## Чем подтверждено

Не рассуждением, а делом: задача RT-834 и её ветка заведены уже новой записью — команда
ответила колонкой «📋 Backlog» и исполнителем `rt-tools-dev`, а гард поставки пропустил пуш,
сверив почту коммита с профилем.
