# RT-3090 — сторож главной ветки берёт её имя из профиля дерева

Задача RT-3090, ветка `RT-3090-main-branch-setting` от ветки `RT-3100-shell-arrow-in-quotes`,
работа вне эпика по слову владельца. Папка задачи `docs/tasks/RT-3090-main-branch-setting/`
разобрана в эту запись.

## Просьба владельца

> RT-3090 (Рекомендуется)

Владелец выбрал её из трёх описанных задач. В очереди задача звучит так: сторож главной ветки не
читает `RT_MAIN_BRANCH` из профиля дерева и угадывает имя по указателю удалённого репозитория. В
дереве с главной веткой `develop` и без удалённого репозитория коммит в `develop` проходил, а
коммит в несуществующую `main` отбивался. Предложение пришло из дерева, которое ставит пакет.

## Решения по ходу

- **Настройка читается из собственного профиля дерева, а не через значение пакета.** Значение
  пакета всегда `main`: прочитанное через него, дерево на `master` без настройки потеряло бы
  угадывание.
- **Профиль берётся у дерева, где идёт коммит.** Сторож уже смотрит ветку именно там.
- **Сценарии лежат в отдельном наборе `git-guard-main.test.sh`.** Набор сторожей поставки упёрся
  в предел длины.

## Проверено

- Набор сторожа главной ветки: 4 проверки, 0 провалов; три падали до правки.
- Соседние наборы без провалов: сторожа поставки — 110, наблюдения — 28.
- Разложенные копии сходятся с пакетом v0.33.1.
