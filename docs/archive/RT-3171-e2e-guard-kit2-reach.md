# RT-3171 — проверка покрытия судит правку второго кита по тому, что рисует приложение

Задача RT-3171, ветка `RT-3171-e2e-guard-kit2-reach` от `main`, работа вне эпика по слову
владельца, 08.11.2026. Папка задачи разобрана в эту запись.

## Просьба

Ответы владельца в меню, дословно:

> Починить проверку (Recommended)

> Отдельный PR проверки (Recommended)

Первый — на вопрос, как быть с проверкой покрытия, которая на правку календаря второго кита
требовала сквозной тест в примере входа, где календаря нет. Второй — на вопрос, как довести
исправление до хуков сессии: они берутся из основной рабочей копии, а там стояла старая проверка.

## Что сделано

- Функция профиля `rt_kit2_reaches`: правка второго кита задевает приложение, если меняет
  компонент, который оно называет, компонент внутри такого или файл кита вне компонентов.
  Витрина, эталонные снимки, спеки и тексты кита не задевают ни одно приложение.
- Проверка покрытия при открытии PR требует набор приложения только по этой функции. Набор перед
  push по-прежнему гоняет оба набора на любую правку кита.
- Три сценария проверки; статья правила `testing` в надстройке.

## Решения с причинами

- **Что рисует приложение, считается по коду, а не по списку.** Список «компонент → приложение»
  отставал бы от кода с первой новой кнопкой.
- **Компонент внутри компонента считается.** Поле рисует кнопку-иконку внутри, и правка кнопки
  меняет экран поля.
