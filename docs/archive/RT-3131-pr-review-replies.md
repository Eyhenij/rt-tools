# RT-3131 — исполнитель молчал под замечаниями PR

Задача RT-3131 эпика RT-3129, ветка `RT-3131-pr-review-replies` от `RT-3129-pr-product-flow`,
06.11.2026. Папка `docs/tasks/RT-3131-pr-review-replies/` разобрана в эту запись. Порядок эпика
лежит в `docs/plans/pr-product-flow.md`.

## Просьба владельца

> ты обязан уточнить у человека нужно ли тебе отвечать в пр под комментами, и если человек сказал
> "да" - ты обязан ответить, заведи задачу под это и заведи новый эпик по улучшению продуктового
> флоу, правки нужно делать в agent kit чтобы новая документация стала доступна для всех проектов

Про уже влитые PR с девятью замечаниями (#3126, #3115, #3116, #3117, #3119) владелец ответил:
«Нет, не отвечать». Правило действует со следующих PR.

## Что было

Владелец оставлял замечания к PR, исполнитель вносил правки и не писал под ними ни строки. В
обсуждении не было видно, что закрыто и чем, и владелец перечитывал весь дифф заново.

## Решение

- В правиле поставки всех трёх вариантов хостинга появилась статья: на замечания к PR исполнитель
  спрашивает человека, отвечать ли, а после «да» отвечает под каждым.
- Вызовы хостинга легли разделом в паттерн открытия PR: у каждого варианта свой клиент.
- Слово действует на один PR и не переносится на следующий, как статья про слияние своего PR.
- Правило поставки стояло у предела веса, поэтому статья получилась короткой, а доводы ушли в паттерн.
- Файл привязок говорит, что машина этого не проверяет: правка по замечанию выглядит как любая другая.

## Цена решения

Каждый PR с замечаниями получает лишний вопрос владельцу. Проверки нет, и пропуск вопроса останется
незамеченным, пока владелец сам его не увидит. Вызовы GitLab и Azure написаны без запуска на живом
хостинге: дерево живёт на GitHub, и проверить их здесь нечем.
