# RT-3154 — числа уходят без команды человека

Задача RT-3154 эпика RT-3151, ветка `RT-3154-metrics-send`, PR в `RT-3155-metrics-intake`, 07.11.2026.
Папка задачи разобрана в эту запись. Разбор всего эпика лежит в записи RT-3152.

## Просьба владельца

Карточка задачи: человек забывает отправлять данные, поэтому приёмник видит приложения неровно.
Слово владельца про содержимое отправки: «Только числа (Recommended)».

## Решения по ходу работы

- Уходит только строка дня. Разборы, предложения и сводка несут текст и по-прежнему уходят командой
  человека.
- Числа считает тот же код, что и отчёт: `guardsOf`, `runsOf`, `usageOf`, `outcomeMetricOf`. Второй счёт
  разошёлся бы с первым молча.
- Имя, которого пакет не везёт, уходит словом `own`. Приёмник судит только форму имени.
- Ключ вне формы отправитель выбрасывает сам: иначе один странный род запуска стоил бы дереву целого дня.
- Причина сбоя едет числом со следующей дошедшей строкой. Отдельной записи в приёмнике нет.
- Учёт итогов лежит в общем каталоге git, иначе две копии считают один PR дважды.
- Тихий запуск соблюдает 15 минут и останавливается на отказанном токене. Команда человека пробует
  всегда.
- Проверка платит за запуск одним `find` по метке: процесс не стартует, пока срок не вышел.
- Правка каталога наблюдений и двух ключей настройки отказана проверкой места правки: там уже
  разбираются цели записи. Удаление файла записью не считается, этот путь открыт.
- Подписи передачи и счётчики правок лежат в общем каталоге, как и учёт. PR, переданный из второй
  копии, иначе выпадал из главной метрики.
- Чтение итогов идёт под общим замком: чтение и запись разделяет запрос к хостингу, две копии считали
  бы один PR дважды. Вторая выходит без чтения.
- Числа дерева считаются только на сегодня, а приём замещает день целиком. Поэтому они лежат в метке
  и едут со вчерашней строкой. Код сбоя держится в строках своего дня.
- Отказанная строка закрывает только свой день. Сбой сети или приёма останавливает всё окно.
- Хук отмечает запуск до процесса: дерево с адресом без токена иначе запускало бы процесс на каждое
  наблюдение.
- Копия без сборки берёт команду основной. Команды нет или она не отработала: это называет начало
  сессии.
- Строка не уходит, если в именах ключей есть корень или адрес дерева. Последнее звено пути не судится:
  копия по имени `testing` закрыла бы правило пакета.
- Дерево без функции итогов говорит о себе ключом `outcomesUnread`, а не пропуском.
- Тихая отправка читает наблюдения без уборки: снятое по сроку называет отчёт.
- В строке дня число принятых идёт без вычета откатов. Откат приходит на другой день, разность по дням
  разошлась бы с разностью за один день. Вычитает раздел.
- День уходит под версией своих записей: иначе последний день перед обновлением попал бы в счёт после.
- Адрес без токена на этой машине называют `doctor` и начало сессии: настройка лежит в истории, токен
  нет, и вторая машина дерева иначе молчала бы.

## Цена

- На дереве этой задачи адрес приёма боевой, а приёмник ещё не выкачен. После слияния эпика и до выкатки
  тихие попытки будут получать 404 раз в 15 минут. Вреда нет, сбой виден в `agent-kit doctor`.
- Сквозной набор админки этой цепочки не проверяет: пакет в нём не собирается. Цепочку держит сценарий
  с настоящей сборкой и локальным приёмом. На настоящем приёмнике она проверена на стенде один раз.
- Смена ключа `observe` на выключение наблюдением не становится: записи в эту минуту нет.
- Проверка места правки видит не все формы записи. В каталог наблюдений проходят `rm`, `truncate` и
  `perl -i`, в настройку проходят `cp` и `git checkout`. Менять разбор целей записи здесь я не стал: он
  общий для всех проверок.
- После слияния основная копия этого дерева не шлёт, пока пакет в ней не собран заново: сборка там
  старая и не знает `send`. Начало сессии это называет, шаг записан в план RT-3157.
- Настоящий выход агента на `SessionEnd` не наблюдался. Если процесс не переживёт выход, строку дошлёт
  следующий `SessionStart`.
