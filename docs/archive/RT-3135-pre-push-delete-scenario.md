# RT-3135 — сценарий удаления ветки не зависит от ветки по умолчанию на машине

Задача RT-3135, ветка `RT-3135-pre-push-delete-scenario` от `main`, работа вне эпика по слову
владельца. Папка задачи `docs/tasks/RT-3135-pre-push-delete-scenario/` разобрана в эту запись.

## Просьба владельца

> отправь через терминал, а на ошибку отдельный тикет и в работу

Сказано про сценарий сторожа SC-AK-1261. Он стал красным на чистом `main` после эпика RT-3043
и не пускал отправку правок по ревью PR #3124.

## Решения по ходу

- **Причина в сценарии, а не в хуке.** Отладочная копия сценария показала ответ самого git:
  «refusing to delete the current branch: refs/heads/main». Удалённый в фикстуре — голый
  репозиторий, и его текущая ветка — ветка по умолчанию на машине. Системный gitconfig Apple
  ставит `init.defaultBranch` в `main`, поэтому git отбивал удаление раньше, чем хук что-то решал.
  На машине с веткой `master` по умолчанию тот же сценарий зелёный.
- **Сценарий удаляет ветку, которая не текущая у удалённого.** Он проверяет то же — удаление не
  судится — и больше не зависит от машины. Вторая строка сценария проверяет, что ветка правда
  ушла с удалённого. Отвергнуто: разрешить удаление текущей ветки настройкой удалённого —
  сценарий проверял бы настройку, которой у настоящего хостинга нет.
- **Хук не тронут.** Он пропускает удаление так, как говорит спецификация.

## Проверено

- Сценарии git-хука перед пушем: 42 проверки, 0 провалов. До правки на этой машине — 1 провал.
- Хук без пропуска нулевого sha: обе строки SC-AK-1261 красные, значит сценарий стережёт пропуск.
  Хук после пробы возвращён, правок в нём нет.
