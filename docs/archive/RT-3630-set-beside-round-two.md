# RT-3630 — набор перед отправкой идёт рядом со вторым кругом

Задача RT-3630 эпика RT-3624, запись от 2026-11-25. Прежний адрес:
`docs/tasks/RT-3630-set-beside-round-two/`.

## Просьба владельца

> сейчас рабочий процесс занимает слишком много времени, довольно простые правки идут по несколько часов, сделай анализ на какие шаги сколько времени уходит по текущему task flow и как можно оптимизировать весь процесс

Карточка: «Набор ждёт конца второго круга, хотя круг часто ничего не меняет в коде: 8–15 минут на ветку.
Готово, когда набор запускается вместе со вторым кругом, и круг без правок не запускает его второй раз».
План — «Одобряю план RT-3630 (Recommended)» 25.11, с числами: посылка карточки не подтвердилась, выигрыш
меньше минуты на ветку, к вехе эпика работа не ведёт.

## Что решили и почему

- **Набор начинается сообщением второго круга**, над закрытыми текстами и влитой базой. Он меняет «набор после
  последнего круга» из RT-3408; число кругов и состав набора прежние.
- **Запуск, под которым сменилась копия, не зелёный: код 101** — прежде он кончал словами «the set is green».
  Отдельная копия для запуска отвергнута: ей нужны свои пакеты, а строка шага несёт базу по ветке.
- **Снятие: `INT`, `TERM` шагу, `TERM` оставшимся, `KILL`**, по 10 секунд — стенд сквозных уходит только по
  `INT`, nx убирает сценарии по `TERM`, а `KILL` через 5 секунд оставлял 89 процессов.
- **Процессы шага ищутся по родителю и по группе** — сирота без родителя видна только по группе.
- **`tools/tests/run.sh` не читает записей задач, планов и архива** — 1139 = 1139 = 1139 на целой копии, без
  них и с мусором на их месте. Такой же ключ тяжёлых шагов отвергнут: приёмник берёт исходник пакета правил.
- **После правок второго круга тексты и база сверяются заново** — иначе ветка уходит с прежней спекой.

Списано: правка, поставленная и убранная внутри одного шага; окно между запуском шага и записью номера;
временный файл вывода после снятия; `KILL` самому запуску.

## Что осталось вне задачи

- `check:ngdoctor` обходит пакеты рабочей копии, стоящей внутри этой: 359–426 секунд вместо 6–8;
  `check-doc-paths` красный в новой копии. Обе — в `docs/plans/delivery-speed-findings.md`.
- `rt_push_touched` не зовёт сквозные и образы на правку `projects/agent-kit/src`.
- Кэш ответов сценариев защит между запусками.

## Чем подтверждено

- `push-ahead-copy.test.sh` — 55 зелёных, 27 поломанных вариантов из 27 он роняет.
- Живое снятие на `test-hooks`: 114 процессов до, 0 после, 6 секунд; порты стенда сквозных свободны через 5.
  На сквозных снятие мерили до последней переписки запуска.
- Роли и набор второго круга: разница 2 секунды. Повторный набор после коммита записей: 45 секунд, код 0,
  в копии вне дерева; прежде 118.
- Из 57 вторых кругов с 19.11 без правок вне записей прошли 6.

## Цена

- План читали четырежды: расширенный ключ тяжёлых шагов пропускал бы сквозные на правке пакета правил.
- Первый круг ревью нашёл 11 серьёзных, второй 5: снятие висло на одном сбое таблицы процессов, после правок
  второго круга не сверялись тексты. Снятие выросло больше всего остального кода работы.
- `pkill` по имени снял такой же запуск в соседнем проекте; рамка ревью теперь велит снимать по номеру.
- Числа живых запусков легли одним коммитом с отметкой шага 4.1, и замер перед PR их не увидел: папка
  возвращалась, проверка шага заменена. Записи чисел ложатся коммитом раньше отметки.
