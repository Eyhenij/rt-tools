# Признак вызова слепнул на подстановке переменной

Задача RT-1047, заявка #1048, ветка `RT-1047-guard-signal-env-prefix`, 24 августа 2026.

## Просьба владельца, его словами

> почини дыру в признаке гарда

Перед этим он остановил работу: «не делай никаких работ пока не выяснишь как ты обошёл гард».
Повод — коммит, уехавший в главную ветку за подписью постороннего человека.

## Чем оказалась дыра

Гарды узнают свой вызов по началу команды: имя стоит в начале строки либо сразу за
разделителем. Присваивание переменной окружения перед именем под этот признак не подпадало, и
гард не отказывал и не предупреждал — он не считал вызов вызовом.

Замер шести форм, старый гард против нового:

| Вызов                          | старый     | новый |
| ------------------------------ | ---------- | ----- |
| `git push …`                   | судит      | судит |
| `GH_TOKEN="$T" git push …`     | не доходит | судит |
| `gh pr create …`               | судит      | судит |
| `GH_TOKEN="$T" gh pr create …` | не доходит | судит |
| `GH_TOKEN="$T" gh pr ready …`  | не доходит | судит |
| `GH_TOKEN="$T" gh pr merge …`  | не доходит | судит |

Последняя строка дороже прочих: запрет на слияние агентом снимался подстановкой токена.

## Почему это не было видно

**Слепящую форму требует соседняя проверка того же набора.** Личность вызова, открывающего
заявку, видна из команды только явной подстановкой токена, и гард поставки требует её прямо.
То есть форма, обязательная по одному требованию, снимала проверку по другому. Обе стороны
написаны верно, а вместе давали дыру, которой не видно ни из одной.

Обход выходил непреднамеренным: исполнитель набирал ровно то, чего от него требуют, и получал
зелёный ход вместо отказа.

## Решения по ходу и доводы

- **Чинился признак, а не гард подписи.** Тот же образец несли десять мест в пяти хуках, и
  слепота у них общая: починка одного оставила бы обойдённым запрет слияния.
- **Образец объявлен одним местом, а не переписан копиями.** Разойдясь, копии чинятся по одной
  и молчат о том, что остальные остались слепыми.
- **Признак ошибается в сторону лишнего срабатывания.** Гард, не узнавший вызов, молчит и
  выглядит исправным; сработавший на лишнем виден сразу и правится.
- **Значение присваивания берётся без пробелов.** Образец, разбирающий кавычки, ошибается в
  другую сторону — считает вызовом то, что им не является.
- **Одна строка с разделителями осталась непереведённой намеренно.** Она ищет подстановку
  токена, а не вызов: предмет другой, и общий образец ей не подходит.
- **Гард сервера разработки правку получил, хотя это дерево его не раскладывает.** Он стоит в
  отказах дерева; правка верна для тех, кто его берёт.

## Что осталось за работой

- **Коммит с чужой подписью в главной ветке не тронут.** Чинится только переписыванием истории
  с силовой отправкой, а та рвёт основание у открытых веток и рабочих копий. Решение владельца.
- **Признак тяжёлых шагов набора гейта.** Правка одних хуков тянет за собой снимки витрин,
  сборку образов и сквозной набор: текстовой считается ветка, у которой каждый задетый файл —
  либо `.md`, либо лежит под `docs/`. Заведено отдельной задачей по слову владельца.
