# RT-2407 — CI на PR падает на сохранении кэша, хотя проверки прошли

**Ветка:** `RT-2407-ci-cache-post-step` (вне эпика по слову владельца) · **Разобрано:** 2026-10-02

## Просьба владельца

> Задачи вне эпиков

Ответ на вопрос, что брать этой копии после RT-2471; RT-2407 была названа в варианте ответа.

## Что нашли

- Признак повторился 2 октября: запуск 36994703590, первая попытка упала только на шаге
  «Post Cache node_modules», вторая прошла целиком.
- Шаг кэша вычислил путь хранилища `~/setup-pnpm/node_modules/.bin/store/v11`. `pnpm/action-setup`
  по умолчанию ставит pnpm в `~/setup-pnpm`, и хранилище лежит внутри этого каталога.
- На машине три раннера: этого дерева и двух других проектов. Раннер другого проекта начал задание
  в 10:59 UTC, и `~/setup-pnpm` пересоздан в ту же минуту. Общий каталог в домашней папке стирался
  под работающим заданием этого дерева.

## Решения

- **pnpm ставится в каталог инструментов своего раннера** — `dest: ${{ runner.tool_cache }}/setup-pnpm`
  в `ci.yml`. Так требует статья правила `git-workflow`: на машине с несколькими раннерами путь от
  домашней папки общий, и каталог установки у каждого проекта свой.
- **Не временный каталог задания.** Его очищают перед каждым заданием, и хранилище, поднятое из
  кэша, пропадало бы вместе с ним.
- **Конвейеры других проектов не тронуты.** Они принадлежат своим деревьям.

## Проверки

- `pnpm exec prettier --check .github/workflows/ci.yml`: файл разбирается и отформатирован.
- Запуск CI на PR идёт по файлу конвейера из ветки и проверяет новый путь.
