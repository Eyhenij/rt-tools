# RT-3422 — аудит очереди считает отставание прода без диффа, отказ сравнения — заметка

Задача RT-3422 эпика RT-3302, запись от 2026-11-21. Прежний адрес: `docs/tasks/RT-3422-board-audit-422/`.

## Просьба владельца

> я ухожу спать, переключайся в ночной автономный режим, доведи все задачи эпика до завершения и сам эпик до пр в main

Слово владельца от 19.11.2026; задача — строка 21 плана эпика RT-3302. Карточка: аудит очереди
работ падал со стеком и не печатал итога. Он сравнивал выкаченную версию с главной веткой, хостинг
отвечал HTTP 422 «Sorry, this diff is taking too long to generate», ошибку никто не ловил. 19.11
аудит упал так дважды подряд перед PR задачи. Карточка просит: ответ 422 не обрывает аудит, строка
об отставании называет, что сравнить не удалось, остальные строки печатаются, сценарий `SC-AK-1600`
ждёт итога аудита, а не падения.

План одобрен владельцем 21.11 ответом «Одобряю plan.md RT-3422 (Recommended)».

## Что нашли

- Отказ шёл от построения диффа. Прод отставал на сотни коммитов, и для REST-сравнения хостинг
  строил дифф целиком. Запрос со страницей из одного коммита 21.11 всё равно вернул 300 файлов.
- GraphQL-сравнение `ref.compare(headRef).behindBy` считает только коммиты: 487 за 2,2 с.
- Записанный вывод аудита кончался стеком, а стек называл строки node 22.22.3. На node 20 набор
  на записанных ответах был красным ещё до правки: 9 ok и 1 провал.
- Первые слова отказа GraphQL «Something went wrong while executing your query» хостинг говорит и о
  пропавшем коммите. Отказ по времени отличают только слова «result of a timeout». Это замер
  ревьюера на хостинге 21.11.

## Что решили и почему

- **Отставание меряется, а не прощается заметкой.** Одна заметка оставила бы аудит зелёным в том
  самом состоянии, ради которого строка писалась.
- **Перехват узкий и внутри замера отставания.** Заметку даёт только отказ по времени. Пропавший
  коммит, другой 422, 500, отказ по правам и сбой другого запроса ломают аудит одной строкой, без
  стека. Уже насчитанные расхождения при этом печатаются, код выхода 1. Последняя выкатка
  спрашивается отдельным шагом, чтобы заметка её не прятала. Спросить было некого: заход
  автономный. Цена ошибки: если владелец сочтёт заметку расхождением, меняется одна строка вызова.
- **К записанным ответам добавлены два настоящих.** Это GraphQL-сравнение и состояние последней
  выкатки, оба прочитаны под машинным токеном. Полную перезапись не делали: она стёрла бы 43 ответа.
  Прежняя запись REST-сравнения с ответом 422 оставлена как свидетельство отказа.
- **Набор на записанных ответах сверяет строку отставания, последнюю строку и код выхода.** Весь
  вывод не сверяется: после строки отставания идут строки, которые аудит судит по файлам дерева, и
  они меняются с каждым слиянием.
- **Второе сравнение аудита, отставание ветки PR от базы, вынесено в задачу RT-3461.** Оно молча
  превращает отказ в ноль.

## Чем подтверждено

  node 22.22.3 и на node 20.11.0.
- В записанном выводе строк стека 0; `pnpm run agent-kit:check` — exit 0.
- Живой аудит на хостинге на коде после второго круга: 75 с, код 1, 55 расхождений. Строка

- Два круга ревью: в первом подтверждены пять находок, во втором пять; все исправлены в ветке.

## Цена

Отказ 422 вживую не воспроизвёлся: на GraphQL-сравнение хостинг отвечает числом. Слова отказа по
времени взяты из ответа хостинга о пропавшем коммите и из описания его ошибки, а не из записанного
отказа. Если хостинг скажет иначе, аудит сломается одной строкой, а не заметкой.
