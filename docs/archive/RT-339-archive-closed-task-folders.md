# Разбор папки закрытой задачи, README архива и форма имени записи

Задача #339, отчёт #340, слияние 2026-08-10. Запись собрана из разбора просьбы и хода работы
при закрытии задачи; после выкатки не правится.

Папка самой задачи разобрана не её отчётом, а следующей работой — #343: отчёт был слит раньше,
чем до разбора дошли руки.

## С чего началось

Задача #336 завела гард, отбивающий слияние, пока ветка везёт папку своей задачи. Её
собственный отчёт #337 был слит через веб-интерфейс — гард видит только команды агента, — и
папка `docs/tasks/RT-336-guard-task-folder-on-pr/` уехала в главную ветку.

Сверка очереди работ, научившаяся в той же задаче видеть вложенные папки, назвала сразу шесть
папок закрытых задач. Владелец завёл две задачи: #338 на ярус проверки в CI и эту — на разбор
накопленного.

## Ответы владельца

**Что уезжает в архив из каждой папки.** По правилу, пофайлово: `grill.md` всегда;
`progress.md` — только если в нём есть решения по ходу с причинами; `plan.md` удаляется.
Каждая папка читается, и выбор по `progress.md` показывается в отчёте.

**Как называются записи в архиве.** `RT-<номер>-<slug>.md` — тем же номером, что у задачи,
ветки и отчёта: читается как одно, и от записи есть дорога к PR и коммитам. Правило требует
«говорящее имя» и один файл вместо папки из трёх; номер этому не мешает.

**У архива есть README.** Короткий: что сюда попадает, что нет, и строка на каждую запись.
Без указателя архив становится свалкой — ровно тем, от чего правило предостерегает.

**Поведение не меняется.** Правка только в `docs/**`, код не трогается. Договорённость о
продукте не требуется — подтверждено владельцем.

**Шесть папок разбираются одной веткой.** Делить стоит то, что откатывается порознь; шесть
папок порознь никто откатывать не будет.

**Чем видно, что закрыто:** `npm run check:board` молчит по папкам; в `docs/archive/` есть
запись на каждую из шести работ, и в каждой — слова владельца; `npm run check:docs` зелёный.

## Решения по ходу

- **Объём работы урезан с шести папок до одной: остальные пять уже были разобраны.** Задача
  заводилась по неверной картине. Ветка отставала от главной на четыре коммита, а сверка
  очереди читает рабочее дерево — её шесть строк описывали отставшее состояние, а не главную
  ветку. Проверено было только то, что у ветки нет коммитов сверх главной; обратное
  направление не смотрели. В главной ветке к тому моменту уже лежал отчёт #335 задачи #334:
  он завёл каталог архива и разобрал пять папок. Неразобранной оставалась одна — папка задачи
  #336, уехавшая слиянием через веб. Шесть записей, собранных вслепую, снесены; главная ветка
  влита. Затронутый этап замысла: 2.

- **Каталог архива уже существовал, и заводить его не понадобилось.** Замысел требовал завести
  его первым этапом — он был заведён отчётом #335 с девятью записями. От этапа осталось
  только README, которого у каталога не было. Затронутый этап замысла: 1.

- **Форму имени записи владелец выбирал по неверным данным и пересмотрел её, увидев
  сложившуюся.** Сначала он выбрал `RT-<номер>-<slug>.md`, не зная, что в дереве уже лежат
  девять записей, названных транслитом смысла работы без номера. Увидев расхождение, выбрал
  переименовать все девять под форму с номером. Slug взят из имени ветки каждой работы —
  тогда запись, ветка, задача и отчёт читаются как одно. Ссылок на прежние имена в дереве не
  было: тексты и проверки называют только каталог. Затронутый этап замысла: 2.

- **README архива заведён без таблицы-указателя.** Замысел требовал строку на каждую запись.
  Владелец выбрал обойтись без неё: указатель расходится с каталогом молча, а имена файлов и
  так говорят, о чём работа была. Затронутый этап замысла: 1.
