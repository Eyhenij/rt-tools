# RT-3518 — проверка Angular Doctor видит файл, который инструмент потерял молча

Задача RT-3518 эпика RT-3476, запись от 2026-11-23. Прежний адрес:
`docs/tasks/RT-3518-ngdoctor-oxlint-tree-run/`.

## Просьба владельца

> Продолжи работу по эпику ng doctor

Просьба эпика RT-3476. Задачу вставил владелец на плане RT-3514 словом «Завести задачу в эпик
(Recommended)»: образец RT-3514 показывает, что источник находок запускается, но не что он прошёл
каждый файл дерева. Устройство одобрено словом «Да, так (Recommended)», план — «Одобряю plan.md
RT-3518».

## Согласия владельца

Ветка RT-3518 против главной несёт 252 файла кита из влитых в эпик RT-3480 и RT-3481; сама
RT-3518 кит не трогает. Проверка согласий судит задачу эпика против главной, поэтому владелец
ответил и для этой записи:

- **Без вида:** «Подтверждаю, вид не меняется»

## Что нашли

- Инструмент 0.3.0 теряет один файл дерева молча тремя путями: oxlint, упавший на файле, ничего не
  печатает, и пустой вывод читается как «находок нет»; шаблон, который линтер не разобрал, даёт
  сообщение без правила, и оно выбрасывается; файл, который не прочёлся, пропускается, а
  `filesScanned` всегда равен `filesTotal`.
- Модули инструмента резолвятся только от его пакета: из корня дерева приходят другие версии
  парсера и eslint, а oxlint и `fast-glob` не резолвятся вовсе.
- Непрочитанный файл oxlint инструмента отдаёт находкой `oxlint/unknown` с пустым полем файла.
- Правила `zone-js`, `deprecated-animations` и `tailwind-v3-syntax` законно дают находки в
  `package.json` и в стилях. Инструмент читает эти файлы тоже молча, а в список `.ts` и `.html`
  они не входят.
- По файлам инструмента у oxlint на дереве 0 находок, поэтому сверка числа находок двух прогонов
  oxlint сейчас ничего не ловит.

## Что решили и почему

- **После скана проверка сама проходит по тем же файлам** модулями инструмента: читает каждый
  файл, разбирает каждый шаблон, прогоняет oxlint с настройкой, которую записал инструмент.
  Отказ называет файл. Сделано так, потому что числа вывода 0.3.0 потерю не показывают.
- **Список файлов копирует шаблоны и исключения 0.3.0 дословно.** На другой версии проход сразу
  отказывает и просит сверить список.
- **Шаблон красный только на сообщении с `fatal: true`.** Директива `eslint-disable` потерей не
  считается.
- **Упавший oxlint ищется делением списка пополам.** Если падают обе половины, отказ говорит, что
  падает запуск, а не файл: иначе на дереве было бы около 4500 запусков.
- **«Вне списка» судится только по существующим `.ts` и `.html`.** Находки без файла, на каталоге,
  в `package.json` и в стилях законны.
- **Красный проход отказывает и `--write`.**
- **Проход вынесен в `tools/check-ngdoctor-pass.mjs`,** потому что файл проверки вырос до 579
  строк при пределе 500.

## Чем подтверждено

- `pnpm run check:ngdoctor`: «the pass read every file: 2689 files, 596 templates, oxlint 2288
  files», «score 87.25, 1400 findings of 14 rules — equal to the threshold».
- Живая проверка на дереве с настоящим инструментом. Шаблон `<p>use {x}</p>` назван строкой «the
  template linter cannot parse», файл с правами 000 — строкой «the pass cannot read», код выхода 1.
- Критик цели воспроизвёл все три потери на копии дерева с настоящим инструментом. Падение oxlint
  он воспроизвёл обёрткой, которая падает на одном файле, и каждый раз файл был назван.
- Набор `check-ngdoctor`: 73 ok в локали `C.UTF-8` и без локали; шаг 1.1 → 10, шаг 1.2 → 0.
  Обратная правка каждого исправления ревью краснит ровно один сценарий.
- Два круга ревью тремя ролями.

## Цена

- Каждый `check:ngdoctor` дольше примерно на 0.8 с: 6.1–6.3 с против 5.4–5.6 с.
- Новая версия инструмента требует сверить проход с её списком файлов и настройкой oxlint.
- Не видно: oxlint, упавший только в прогоне инструмента и отработавший в проходе; потерянный
  `package.json` или стиль, которые инструмент читает для трёх правил; поле `angularDoctor` в
  `package.json`, которое инструмент читает как свою настройку.
