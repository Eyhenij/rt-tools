# RT-3621 — страж хода работы судит правку без команды timeout

Задача RT-3621 эпика RT-3686, запись от 2026-11-26. Прежний адрес: `docs/tasks/RT-3621-guard-without-timeout/`.

## Просьба владельца

Ответ владельца в меню 25.11, когда ночная работа кончилась: «Взять задачу из очереди». Взята
#3621, её тело:

> На Mac без GNU coreutils нет команды `timeout`, и стражи пакета правил, которые зовут движок через
> `timeout 60 node …`, молча пропускают любую правку … Что нужно: страж без `timeout` либо зовёт
> движок без предела времени, либо берёт `gtimeout`, либо отказывает с понятным текстом — но не
> пропускает молча. То же для других хуков пакета, где стоит `timeout`.

Ответы владельца: план — «Одобряю план»; эпик — «Завести эпик (Recommended)».

## Что решили при разборе

- **Движок зовётся под первым ограничителем машины: `timeout`, `gtimeout`, perl `alarm`; без них —
  без предела.** Отказ «поставьте coreutils» остановил бы всю работу на голом Mac. Цена ошибки:
  повисший движок держит вызов до предела хука у хозяина.
- **Функция в самом хуке, не общий файл.** Других вызовов `timeout` в хуках пакета нет:
  `dispatch.sh` ставит предел через perl, остальные только разбирают это слово в команде.
- **Хук конца хода без perl отпускает ход с записью «движок упал» в журнал** — так требует его
  спека; правки там нет.

## Решения по ходу

- **Эпик RT-3686 из одной задачи.** Движок не ведёт задачу вне эпика: выход «эпик-заведён» ищет эпик
  по карточке. Ветка эпика несёт ещё снятие 21 записи архива по сроку и адрес папки разборов в
  описании ночной работы — без них главная ветка была красной, и ветка эпика не уходила.
- **Проверка шага повторяет красную проверку задачи.** На этой машине `timeout` есть с 24.11
  (`~/.local/bin/timeout` → `gtimeout`), и обычный прогон зелёный без правки; план переписан трижды
  по ревью ролей до одобрения.
- **Первый круг ревью:** каталоги случаев убираются по выходу, отметка perl видит вызов записи
  плана, вид «gtimeout и perl» держит порядок, ограничитель без права на запуск не выбирается
  (`rt_runs`). Списано: выбор ограничителя в трёх местах — `dispatch.sh` и хук дерева вне выходов.
- **Второй круг ревью:** дерево случаев R8 убирается, виды «timeout рядом» и «без права на запуск».
- **Набор перед отправкой:** файл набора вырос до 545 строк при пределе 500 — помощники вынесены в
  `flow-step-guard-lib.sh` (превышение новых файлов кода: 1 при бюджете 0). Под бегуном случаи
  стояли после `unset TMPDIR`, обёртка `mktemp` бегуна отказывала, и дерево случая ложилось в папку
  тестов — блок перенесён выше, каталог PATH берётся абсолютным. SC-AK-1946 был красным и на ветке
  эпика: на машине стоит пустой каталог `/tmp/x`; путь цели теперь из `mktemp -u`.

## Цена

Набор перед отправкой — четыре прогона: предел длины файла, случаи под бегуном, SC-AK-1946.
Одобрение плана — после трёх кругов чтения ролями. Итог: набор стража 142 из 142 под PATH без
`timeout` и `gtimeout`, наборы записи плана 28 и 139; со старым хуком падают ровно новые случаи.
Живая проверка разложенного хука без ограничителей — отказ за 11 с, с ними — за 4 с.
