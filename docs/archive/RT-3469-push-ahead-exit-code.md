# RT-3469 — фоновый запуск набора перед отправкой кончается кодом набора

Задача RT-3469 эпика RT-3471, запись от 2026-11-22. Прежний адрес: `docs/tasks/RT-3469-push-ahead-exit-code/`.

## Просьба владельца

> обязан сам следить за проверками и ci

Слово владельца от 21.11.2026 о наборе перед отправкой, оставленном без слежения. Карточка RT-3469
просит: фоновый запуск набора отдаёт код самого набора, а вызов, где команда после набора прячет
его код, отказан с готовой формой. 21.11 сессия получила уведомление «exit code 0» над строкой
«push ahead: red» в журнале.

План одобрен владельцем 22.11 ответом «Одобряю план RT-3469».

## Что сделано

- Новая проверка `push-ahead-call-guard.sh` судит фоновый вызов Bash, который запускает
  `git-guard-push-ahead.sh`. Отказ получает вызов, который не кончается кодом набора. Проходят:
  - набор один или с перенаправлением своего вывода;
  - цепочка `&&` до конца вызова;
  - `exit $?` или `rc=$?` и `exit $rc` в конце;
  - `|| exit N` и `if ! набор; then …; exit N`;
  - хвост после `set -e`;
  - конвейер, который кончает вызов под `set -o pipefail`.
- Проверка разбирает команду как оболочка: кавычки, heredoc, `$(…)`, циклы и группы, приклеенные
  перенаправления, обёртки `bash -c`, `eval`, `source`, `env`, `sudo`, `timeout`, `pnpm exec` и
  другие. Текст, который только называет скрипт, проходит.
- Отказ — строка таблицы решений. Он называет, что спрятало код, и готовую форму: набор один,
  журнал вне рабочей копии `"${TMPDIR:-/tmp}/push-ahead-$(basename "$PWD").log"`, итог — последняя
  строка `push ahead:` журнала.
- Готовая форма стоит в 11 текстах отказов таблицы, в двух текстах проверки отправки эпика и в
  шаблоне цикла доставки.
- Описание набора перед отправкой получило правило, сценарии SC-AK-1814…1816 и SC-AK-1821 и
  исправленные коды выхода.

## Что решили и почему

- **Отказ любой команде после набора, кроме выхода с его кодом.** План сужал отказ до вызовов, где
  код не виден нигде. Критик первого круга показал: признак карточки — отказ вызову с
  `; echo "exit=$?"`. Код, напечатанный в вывод, не заменяет код уведомления. Меню с вариантом
  «как в плане» проверка вопросов не пропустила: вариант ослабляет проверку против карточки.
- **Судится только фоновый вызов.** Уведомление с одним кодом бывает только у него; у вызова на
  переднем плане вывод стоит в результате.
- **`exit ${PIPESTATUS[0]}` не засчитывается.** Вызовы Bash здесь идут в zsh, массива там нет, и
  выход — 0. Критик второго круга показал это на живом вызове.
- **Журнал готовой формы один на копию и лежит вне неё.** Файл в дереве делает копию грязной, и
  набор не начинается.

## Цена

- Цель плана «не больше 0,05 новых отказа на сто вызовов в день» не выполнена. На записях выходит
  0,21–1,32, и 21.11 поднимается с 4,77 до 5,61 — за порог вехи эпика. Почти все отказанные
  вызовы печатали `$?`: так раньше учили тексты и шаблон. Сколько отказов останется после
  слияния, покажет отчёт за три дня. Решение «строго по карточке или по метрике» вынесено
  владельцу в теле PR.
- Цикл повтора `if набор; then exit 0; fi; done; exit 1` отказан, хотя на красном кончается
  красным: 3 вызова 17.11. Записан находкой эпика.
- Скрипт, названный только через переменную (`bash $S`), не узнаётся.
- Строка следа плана о `real-hooks.test.sh` и `push-inputs.json` была условной: сверки строки
  новой проверки не потребовали, файлы не правились.
