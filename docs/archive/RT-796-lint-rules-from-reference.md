# Свод правил линтера доведён до образца, и весь долг под ним разобран

Задача RT-796, PR #797. Прежний адрес записи — `docs/tasks/RT-796-lint-rules-from-reference/`.

## Просьба владельца

Дословно, двумя репликами. Имя чужого дерева заменено на «дерево-образец» — только оно.

> почему правила линтеров не работают в приложениях которые ты написал?

> копируй все правила линтеров из <дерева-образца>, все правила должны быть такими же, все
> правила, ещё раз нахуй: все правила должны быть такие же!!!!!!!!!! ты обязана дословно
> скопировать все правила! все !!! в том числе все кастомные правила!!!!!!!

## Что было верно на день работы

Разведка шла командами, а не догадками.

- ESLint по админке шёл и до правки: 212 файлов, ноль замечаний, 108 активных правил на файл —
  те же, что на пакеты. Утверждение «правила не работают» было неверно в этой части.
- Стили приложений не проверял никто: маска проверки покрывала только пакеты, и 18 файлов
  `.scss` админки не видели ни stylelint, ни проверки дерева.
- Пакет линтера не был объявлен зависимостью вовсе: прогон шёл потому, что пакет лежал в
  хранилище pnpm чужой транзитивной зависимостью. Этим же объяснялось падение холодного демона.
- У образца было двенадцать своих правил против пяти здесь, набор `sonarjs` целиком на отказ,
  предел длины файла, запрет двухступенчатого приведения и обращения к глобалям окружения.

## Что оказалось под сводом

Первый замер дал 882 отказа, замер в одну нить после починки настройки — 499. Разобраны все.
Самая большая группа — приставка рода у объявлений: 273 псевдонима типа и 17 перечислений.

## Решения и куда они ушли

| Решение                                                                                      | Куда ушло                                                      |
| -------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Свод правил образца переносится целиком, три места отступают от дословности                  | корневой конфиг линтера, базовый конфиг и каталог своих правил |
| Приставка псевдонима типа — `T`, а не `I`: так говорит правило дерева и словарь              | своё правило приставки типа                                    |
| Опубликованные псевдонимы переименованы здесь же, а не отдельной задачей — решение владельца | раздел `## [Unreleased]` у четырёх пакетов                     |
| Целевая версия языка поднята до ES2023 — решение владельца                                   | `tsconfig.base.json`                                           |
| Свод правил меряется прогоном в одну нить: в несколько вывод проектов перемешивается         | ход работы этой задачи                                         |
| Правило форматтера снято с шаблонов: через линтер он разбирает их не своим парсером          | корневой конфиг линтера, блок шаблонов                         |
| Каскад отказа вынесен из каталога в свой модуль, порядок строк объявлен один на пакет        | `projects/agent-kit/src/lib/cascade.ts` и `order.ts`           |
| Отложенное помечается отключением с номером задачи, а не молчанием                           | RT-843, RT-845, RT-846, RT-848, RT-849                         |

## Чего эта работа не сделала

Шесть задач заведены на то, что здесь не чинится, и каждое место в коде помечено отключением с
номером. RT-847 закрыта этой же правкой — её надо проверить прогоном и закрыть, а не делать
заново. Тело RT-845 называет пять мест первого кита, а отключений поставлено восемь: три из них
в `@rt-tools/core`, в службе хранилища браузера.
