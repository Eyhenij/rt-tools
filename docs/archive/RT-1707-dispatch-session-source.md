# RT-1707 — вход в сессию через диспетчер

**Ветка:** `RT-1707-dispatch-session-source` · **Разобрано:** 2026-09-03

## Что было не так

Диспетчер сверял образец объявления с именем инструмента. У входа в сессию имени инструмента нет
вовсе — там образец называет род запуска: запуск, продолжение, сжатие, очистку. Сверка с пустым
именем не совпадала ни разу, и через диспетчер не звался ни один хук входа: заход стартовал без
свода законов, без словаря, без состояния работы и без передачи прошлого захода.

Молчание при этом полное — нулевой код и пустой вывод, то есть ровно то, что в правиле входа
названо неотличимым от неработающего. Замер на этом дереве до правки: `echo '{"source":"startup"}'
| bash .claude/hooks/dispatch.sh SessionStart` — ноль байт при пяти разложенных хуках входа.

## Что сделано

- **Род запуска читается наравне с именем инструмента** — тем же одним вызовом разборщика, что и
  остальные поля.
- **Предмет сверки выбирается по событию:** имя инструмента там, где оно есть; род запуска — где
  его нет. Порядок именно такой: имя инструмента судится прежде, и род запуска его не подменяет.
- Статья и адрес в домене диспетчера, сценарий SC-AK-856 — четыре проверки.

## Чем это подтверждено

Живой прогон после правки: 32 835 байт вместо нуля. Набор диспетчера — 28 зелёных, весь
shell-набор пакета зелёный, сверка раскладки сходится, проверки спек и адресов чисты.

## Что осталось открытым

Прямые подписки хуков входа, заведённые в дереве вместо диспетчера, эта правка не снимает: они
лежат в настройке агента, и снимать их — работа того дерева, которое их завело.
