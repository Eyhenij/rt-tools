# RT-3475 — экшен выкатки сервера называется «Deploy message-bus: приёмник и админка»

Задача RT-3475 вне эпика, запись от 2026-11-21. Прежний адрес: `docs/tasks/RT-3475-deploy-workflow-name/`.

## Просьба владельца

> ты можешь переименовать этот экшен как-то иначе? сейчас непонятно что это за deploy

Слово владельца от 21.11.2026. Он запускал выкатку сервера перед выпуском `@rt-tools/agent-kit`
0.38.0 и спросил, не выпускает ли она пакет. Имя выбрано в меню: «Deploy message-bus: приёмник и
админка».

План одобрен владельцем 21.11 ответом «Одобряю (Recommended)».

## Что нашли

- Экшен `.github/workflows/deploy.yml` собирает два образа — приёмник message-bus и его админку — и
  поднимает их на сервере с миграцией базы. Пакетов npm он не трогает.
- Проверки доски и команды правила выкатки находят экшен по файлу `deploy.yml`, а не по имени.
- Старое имя стояло в `docs/PROD.md` дважды и в надстройке правила выкатки.

## Что решили и почему

- **Меняется только имя, файл прежний.** Проверки доски ищут выкатку по файлу.
- **Имя стоит в кавычках.** С «: » без кавычек YAML не разбирается, и выкатка перестала бы
  запускаться: это нашли роли на плане.
- **«Deploy Auth» не переименован.** Владелец назвал один экшен.

## Чем подтверждено

- Разбор YAML экшена отдаёт «Deploy message-bus: приёмник и админка».
- Новое имя в `docs/PROD.md` 2 раза, в надстройке правила выкатки и в разложенном правиле — по 1.
- `check:board` называет последнюю выкатку, как до правки; `agent-kit:check` и `check-doc-paths` — 0.
- Два круга ревью тремя ролями; подтверждённые находки исправлены в ветке.

## Цена

Новое имя в списке Actions видно только после слияния в main: хостинг берёт имя из главной ветки.
Проверка — `gh api repos/Eyhenij/rt-tools/actions/workflows/deploy.yml --jq .name`.
