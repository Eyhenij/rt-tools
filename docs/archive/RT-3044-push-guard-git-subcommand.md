## Что было

- Проверка `git-guard-push-tests.sh` искала слово `push` в любом месте команды. Несколько push-ей
  считались по строкам, поэтому `--all`, `--mirror`, две ветки и цикл в несколько строк проходили.
- Инструмента вкладки терминала сессии не было ни в шапке `rt-hook`, ни в списке инструментов.
- Статья «несколько push-ей одной командой отбиваются» в описании стояла верно, код её не держал.

## Решение

- Push — подкоманда `push` того же вызова `git`, после его ключей и до ближайшего разделителя
  команд. Значение ключа в кавычках может содержать пробелы: так передаётся заголовок запроса.
- Несколько получателей — `--all`, `--mirror` или больше двух слов после `push` без ключей. Ключ со
  значением отдельным словом это слово пропускает. Push с `--delete` получателей не считает: ветку
  он не отправляет, удаление слитой ветки — задача RT-3055.
- Номера сценариев SC-AK-1237…1239, а не 1234…1236 из плана: `pnpm run spec:next-id AK` назвал 1236
  занятым в соседних ветках.
- Первые тесты проходили и на старой проверке: красный набор отбивал любой push. Случаи получателей
  теперь гоняются на зелёном наборе.
