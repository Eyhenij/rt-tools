## Что было

- Проверка `git-guard-push-tests.sh` искала слово `push` в любом месте команды. Несколько push-ей
  считались по строкам, поэтому `--all`, `--mirror`, две ветки и цикл в несколько строк проходили.
- Инструмента вкладки терминала сессии не было ни в шапке `rt-hook`, ни в списке инструментов.
- Статья «несколько push-ей одной командой отбиваются» в описании стояла верно, код её не держал.

## Решение

- Push — подкоманда `push` того же вызова `git`, после его ключей. Команда разбирается так, как её
  читает оболочка: разбор на perl внутри проверки, слова с кавычками, `$( )`, обратные кавычки,
  строка `bash -c` и слова `eval` — как команды, тело heredoc — данные. Цикл считается от `for`,
  `while`, `until` до `done`; push внутри `if` и после `done` — один push.
- Несколько получателей — `--all`, `--mirror`, `--branches`, ссылка с `*` или две ссылки после
  удалённого хранилища. Слово в кавычках и `$( )` — одна ссылка, ссылка на `:` удаляет и не
  считается. Push с `--delete` получателей не считает, удаление слитой ветки — задача RT-3055.
- Первая версия разбирала команду шаблонами grep и sed и была зелёной на 52 случаях. Ревью
  владельца по PR #3083 нашло семь форм push, которые она пропускала, и пять законных push-ей,
  которые она отбивала. Шаблоны заменены разбором слов; все 22 новых случая сначала прогнаны на
  прежней версии, 21 из них там красный.
- Второе ревью нашло ещё три обхода и два ложных отказа. `time -p`: ключ обёртки стал именем
  команды. Heredoc без кавычек: в нём исполняются `$( )` и обратные кавычки. `--repo` с двумя
  ссылками. Определение функции без вызова отказывало как push. Переключение ветки внутри
  `bash -c` и `eval` проходило. Обёртки теперь снимаются вместе с ключами и их значениями, тело
  функции разбирается при вызове, переключение ветки ищет тот же разбор. `xargs`, `parallel` и
  `find -exec` считаются циклом. 22 новых случая; 15 из них на прежней версии красные.
- Перед третьим push владелец велел прогнать ревью кода самому. Независимый рецензент нашёл ещё
  обходы. Апостроф в heredoc внутри `"$( )"` прятал весь текст за собой, а это обычная форма
  коммита перед push. Перенос строки с отступом, `fi }` в теле функции и `$'…'` тоже прятали push.
  Функция, передающая `"$@"`, оболочка с командами во входе и вызовы функций, растущие без
  предела, проходили без проверки. Всё это исправлено, на каждый случай есть тест. Команду,
  которую разбор прочесть не может, а в её тексте есть push, проверка теперь запрещает.
- Разбор вынесен в `push-sign.sh` рядом с проверкой: с ним внутри проверка выросла до 585 строк
  при пределе 500.
- `git push --repo origin a b` по документации git отправляет `b` в хранилище `a`: первое слово
  после ключей перекрывает `--repo`. Проверка всё равно считает обе ссылки получателями — признак
  ошибается в сторону лишнего отказа, а не в сторону незамеченного push.
- Три статьи и сценарии SC-AK-1237…1239 лежат в своём поддомене `docs/specs/agent-kit/push-sign/`.
  Дописанные в описание проверок поставки, они подняли его сценарии до 519 строк при пределе 500.
  Набор перед push этого не заметил, отказала только `node tools/check-file-size.mjs`, найденная
  разбором по правилам.
- Номера сценариев SC-AK-1237…1239, а не 1234…1236 из плана: `pnpm run spec:next-id AK` назвал 1236
  занятым в соседних ветках.
- Первые тесты проходили и на старой проверке: красный набор отбивал любой push. Случаи получателей
  теперь гоняются на зелёном наборе.
