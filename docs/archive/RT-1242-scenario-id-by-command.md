# Наибольший номер сценария ищется командой, а не по хвосту файла

Задача RT-1242, заявки нет — ветка местная, слияния не было.

## Откуда взялась работа

Запись груза из приёма, своё дерево, ресурс паттерна заведения домена. Повод: номера в файле
сценариев идут не по порядку — правки вставляли их к соседям по смыслу, — и за одну работу
шесть новых номеров из одиннадцати легли на занятые. Поймала это сверка спеков, а не чтение, и
переписывать пришлось заодно заголовки тестов.

Владелец разбор не вёл: заход шёл сам, задачи брались из приёма одна за другой.

## Решение и довод

Пункт встал в «Частые промахи» паттерна и имени команды не называет: команда поиска у каждого
дерева своя, а паттерн переносится между ними. Правило `spec-driven` при этом не тронуто — там
сказано о выдаче номера, здесь о его поиске, и слияние этих двух утверждений дало бы статью,
которую нельзя приложить ни к тому, ни к другому.

## Цена

Пункт говорит «командой» и не говорит какой. Дерево, у которого такой команды нет, прочитает
его как указание завести — и это верно; дерево, у которого она есть, ищет её имя само.
