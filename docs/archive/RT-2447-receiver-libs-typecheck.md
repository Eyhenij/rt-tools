# RT-2447 — ошибка типов в спеках библиотек приёмника не ловилась отдельной проверкой

**Ветка:** `RT-2447-receiver-libs-typecheck` (поверх RT-2448, вне эпика по слову владельца) · **Разобрано:** 2026-10-01

## Просьба владельца

> Взять обе по очереди

Ответ на вопрос, брать ли две задачи, оставшиеся от предложений по правилам: сначала RT-2448,
потом RT-2447.

## Решения и куда они ушли

- **Цель typecheck выводит плагин Nx, а не строка в каждом файле проекта.** Ушло в
  `tools/nx-plugins/spec-typecheck.cjs` и в `nx.json`; компаньон правила testing называет плагин.
  Признаки — настройка Vitest и настройка спек рядом, поэтому библиотека, заведённая позже, получает
  цель сама. Отвергнуто: строка в 111 файлах проектов — новая библиотека осталась бы без неё.
- **Проверка запускается с корнем репозитория в rootDir.** Настройки спек наследуют корень сборки, и
  без этого библиотека, импортирующая соседа, падала на месте файла, а не на типах.
- **45 ошибок исправлены в спеках, а не заглушены.** Проверка родилась зелёной, без списка
  разрешённых ошибок.
- **Заготовки ответа сервера получили поля, которые модель приобрела позже,** со значениями,
  которые маппер читает так же, как их отсутствие: тесты проверяют то же, что проверяли.
- **Две настройки спек переведены на модули ES2022.** Эти спеки читают import.meta, а Vitest
  запускает их как модули.

## Проверки

- `pnpm exec nx run-many -t typecheck --all`: 115 проектов из 115.
- Спеки 22 исправленных библиотек: зелёные.
- Все проверки `pnpm run check:all`: 375 задач из 375 и линтер стилей прошли. Из них 111 — новые проверки типов.
