# RT-3097 — пустой ход по уведомлению своей фоновой задачи

Задача RT-3097, ветка `RT-3097-turn-exit-own-notification` от ветки `RT-3092-push-gate-ahead`,
работа вне эпика по слову владельца. Папка задачи `docs/tasks/RT-3097-turn-exit-own-notification/`
разобрана в эту запись.

## Просьба владельца

> RT-3097 (Рекомендуется)

Владелец выбрал её из трёх задач с описанием. В очереди она звучит так: сторож выхода из хода
возвращает ход, который разбудило уведомление о своей фоновой задаче, пока вторая своя задача ещё
идёт.

## Что нашли

Уведомление, которое будит простаивающий сеанс, записывается от имени владельца с пометкой
`task-notification`. Разбор хода принимал его за реплику владельца, в ходе не было ни одного вызова,
и сторож возвращал ход как пустой: пять возвратов за час в этом же сеансе. Уведомление, пришедшее
посреди хода, записывается вложением и хода не начинает.

## Решения по ходу

- **Ход отпускается, только пока идёт другая своя задача.** Уведомление о последней задаче
  просит действовать по её итогу, и такой ход судится как раньше. Отвергнуто: считать любое
  уведомление служебным сообщением — тогда ход после последнего итога слился бы с предыдущим и
  ушёл бы по его работе.
- **Правила хода при открытом эпике вынесены в отдельное описание `exit-epic`.** С новым сценарием
  файл сценариев сторожа перерос предел длины, а по правилу описание делится, а не сжимается.
- **Ветка стоит на RT-3092, а не на RT-2895.** Проверка одобрения кита читает ветку целиком от
  главной и требовала одобрений календаря в записи этой задачи. Календарь этой работе не нужен, а
  набор проверок заранее из RT-3092 нужен.
- **Запуск считается завершённым по любому уведомлению с его вызовом** — успех, провал, снятие или
  остановка, в том числе пришедшему вложением посреди хода.

## Проверено

- Набор сторожа: 109 проверок, 0 провалов; три новые строки SC-AK-1247 — один пропуск и два
  возврата. До правки сторожа строка пропуска падала.
- Разложенные копии сторожа сходятся с пакетом v0.33.1.
