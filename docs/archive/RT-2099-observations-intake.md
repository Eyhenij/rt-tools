## Что сделано

- Таблица `observation`: строка на каждую строку наблюдения, с деревом, признаком рабочей копии и днём; индексы по «дерево — день» и «дерево — копия — день». Миграция `20260914200000_observation_rows` написана `migrate diff` на одноразовом контейнере.
- `POST /api/intake/observations` под токеном дерева: голова груза — общей проверкой, дни и строки — своим чистым разбором. Незнакомое событие, строка без признака сессии, нечитаемое время, поле длиннее 200 байт — отказ 400 с местом строки; строк больше предела — 413 без единой строки. День копии замещается целиком, все дни груза одной сделкой.
- Ночное снятие строк старше года: один таймер до 03:10 по всемирному времени, взводится заново после снятия; строка журнала на дерево со счётом; отказ хранилища — строка журнала.
- Предел строк — настройка `OBSERVATION_LINES_CAP` (умолчание 5000), названа в сводке подъёма; разбор отказов перечисляет четыре рода груза.

## Умолчания вместо вопросов

- **Таймер вместо планировщика.** Зависимости-планировщика в дереве нет, одна ночная работа её не оправдывает; момент считает чистая функция от «сейчас», проверяется вызовом. Цена ошибки: тело службы заменить декоратором планировщика — один файл.
- **Пределы: 5000 строк на груз, 200 байт на текстовое поле.** Окно прогона в три дня даёт сотни строк; имя ресурса — имя файла. Цена ошибки: два числа.
- **Час снятия 03:10 UTC.** Цена ошибки: одно число.

## Решения по ходу

- **Читатель предела строк живёт в util и реэкспортируется через feature.** Приложение по границам модулей видит только feature-либу домена, а контроллер читает ту же функцию.
- **Снятие идёт по одному дереву, счёт — из самого снятия.** Групповой счёт до снятия — второе число, которое может разойтись; типизированный агрегат клиента хранилища к тому же отверг аннотацию, а сборка поймала две ошибки типов, которых прогон спек не видит.
- **Ответ приёма — `{ tree, days, rows }`, всегда 200.** Дни ложатся на место прежних — это правка, а не заведение записи.
