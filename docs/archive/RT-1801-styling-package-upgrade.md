# RT-1801 — подъём пакета оформления шёл в общем обновлении, а снятые свойства искали взглядом

**Ветка:** `RT-1801-styling-package-upgrade` · **Разобрано:** 2026-09-05

## Что было не так

Подъём пакета оформления попал в общее обновление вместе с семнадцатью другими пакетами.
Поломка вида нашлась через два дня, и связать её с обновлением стоило дня разведки: коммит правил
один файл со списком версий, а сломалось оформление в семнадцати чужих файлах. Пакет снимает
свойства между версиями молча: снятое свойство делает объявление недействительным, а не
ошибочным, и все проверки остаются зелёными. Обход экранов ловил это только там, куда
посмотрели. Пришло грузом из приёма: предложения
a4a6a8007225b73a50a76a849160f0930fe0e7773e70f8f84591b110162e19c0 и
db26b67fe7db7954069bf993a7dd54da9fc556ef7929905709168b354a6829a0.

## Что сделано

Правило зависимостей получило статью: пакет, который везёт оформление, поднимается своей
задачей — своя ветка откатывается одна. Паттерн подъёма получил шаг между установкой снимка и
сборкой: имена свойств из дерева ищутся командой в поставленных исходниках пакета, ненайденное
заменяется по правилу самого пакета, а не своим значением с прежним числом.

- Привязка статьи в компаньоне дерева — «не исполняется»: дерево пакетов оформления не читает,
  оно их публикует. Форма законная, ею отмечена соседняя статья.
- Раскладка сходится, сверка спеков код 0, слог без находок.

## Цена решения

Проверки дерева на снятые свойства не заведено, и не будет: у дерева свои пакеты оформления, и
оно само их объявляет. Шаг паттерна держится памятью того, кто поднимает версию.
