# RT-1557 — часть файла находок называется задачей, которая её завела

**Ветка:** `RT-1557-findings-part-name` · **Заявка:** #PR · **Разобрано:** 2026-08-29

## Что было не так

Предложение соседнего дерева, заявка #852. Паттерн разбора говорит: файл находок не влезает в
предел длины — заводится следующая часть. Чем эта часть называется, не сказано, и молчание
закрывается очевидным — порядковым номером. Он верен ровно до второго рабочего дерева: один
эпик ведут несколько деревьев разом, «следующую часть» каждое видит своей, и две ветки заводят
файл с одним именем. Всплывает это при вливании главной ветки — конфликтом на весь файл, где
обе стороны верны и сложением не разрешаются.

Половина предложения отпала: оно требовало ещё и нумерацию находок от задачи, а у нынешней
формы файла находок номеров нет вовсе — строка на находку, номеров у строк нет.

## Что сделано

- Статья в паттерне разбора: часть — `<имя замысла>-findings-<КЛЮЧ>-<номер>.md`. Номер задачи
  занят ею одной и двум деревьям достаться не может.
- Первая часть номера не несёт и задним числом не переименовывается: переименование правит
  ссылки во всех текстах ради ровного ряда имён.
- Та же строка правится в образце находок — там, где он говорит о делении по длине.

## Чем это подтверждено

`agent-kit:sync` положил 2 файла без отказа, `check-file-size` — 1465 файлов, долг 0,
`check:docs` — 439 документов, расхождений нет.

## Что осталось открытым

Порядок между частями не задан намеренно: находки друг друга не продолжают, и владелец читает
их разом. Имя части не стережёт ни одна проверка — правило держится образцом.
