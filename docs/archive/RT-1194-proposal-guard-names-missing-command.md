# Отказ гарда предложений называл команду, которой в дереве нет

Задача RT-1194, заявка #1195. Прежний адрес —
`docs/tasks/RT-1194-proposal-guard-names-missing-command/`. Запись собрана из разбора просьбы и
решений по ходу при закрытии задачи; после выкатки не правится. Работа заведена находкой разбора
закрытой задачи RT-1192, а не отдельной просьбой владельца.

## Что было

Отказ `proposal-guard` печатал одну строку на все деревья — `npx agent-kit propose`. В дереве,
где пакет живёт исходниками, бинаря с таким именем нет: npm отвечал отказом установки, `pnpm
exec` — «команда не найдена». Работал только вызов собранного входа. Исполнитель, послушавший
отказ буквально, терял ход — что и случилось в день находки.

Опознание отправки при этом было исправно: образец засчитывает и вызов через собранный вход.
Врала ровно подсказка, ради которой отказ печатается.

## Решения

- **Команда выводится из того, что лежит в дереве.** Бинарь в зависимостях — зовётся он; бинаря
  нет, а собранный вход есть — зовётся вход. Отвергнуто: печатать обе формы всегда — исполнитель
  выбирает наугад ровно там, где ошибся бы и без подсказки.
- **Опознание отправки не тронуто** — оно работало.

## Решения по ходу

- **Сценарии стали судить текст отказа, а не только вердикт.** Восемь прежних проверяли BLOCK и
  PASS и текста не читали — потому промах и дожил до дерева. Добавленная проверка поднимает два
  дерева: с бинарём в зависимостях и с собранным входом.
- **Пять отбитых предложений доделаны тем же заходом** — по слову владельца, до этой задачи. Всем
  пяти дописано поле «ближайшее»; приём принял все пять.

## Цена решения

Дерево, поставившее пакет как-то иначе — ни зависимостью, ни сборкой в `dist/`, — получит
прежнюю общую форму. Такой случай не разбирался: живого дерева с ним нет.
