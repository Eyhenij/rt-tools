# Три гарда правки не видели записи командой оболочки

Задача RT-1928. Запись собрана из папки задачи при её разборе; после выкатки не правится.

Работа начата с груза. Ключ записи полностью:
`fe80c61f139244bff4fe9fe348742b020dcdca3c00d52a3bb932c53ab4750535` — предложение стороннего
дерева, в приёмнике `556ab517-f778-4fd8-b51c-28d46eefe5c6`.

## Просьба владельца

> **место:** строка `# rt-hook: PreToolUse Edit|Write|MultiEdit|…` в шапке каждого из трёх
>
> **повод:** заход в авто-режиме получает указание править файлы через `sed`, `python3` и
> heredoc. Ни один из трёх гардов такой правки не видит. Проба на дереве-потребителе: тот же
> ввод с именем `Edit` даёт отказ, с именем `Bash` даёт тишину. Так в дерево уехал шаблон формы
> со своим словарём стилей вместо общего. Промах нашёл владелец глазами через две недели.
>
> **ближайшее:** шапка `docs-guard.sh` — приём в пакете уже есть, и три гарда правки его не взяли
>
> Гард правки судит и правку командой оболочки. Имя файла берётся из текста команды тем же
> разбором, каким его берёт гард пары «правка и её документ».

## Что было не так

Гард слога, гард якорей и гард входа из передачи объявляли только имена инструментов правки.
Тот же текст, поданный командой оболочки, проходил молча: документ, написанный heredoc, уезжал
мимо договорённости о слоге целиком, разметка — без единого якоря, а заход из передачи правил
файлы, не загрузив правила ведения работ.

Приём разбора путей в пакете уже был — `write-targets.sh`, помощник `rt_write_targets`. Его
брали гард места правки и гард экзамена, а эти трое — нет.

## Решения

- **Разбор путей объявлен один раз, а не тремя разборами в трёх гардах.** Три разбора разошлись
  бы молча: каждый чинится порознь, и ни один не говорит, что остальные слепы.
- **У разбора появился свой набор проб.** До этого он проверялся только через гарды, которые его
  зовут: по красному набору гарда не видно, промах в разборе или в самом гарде. Набор закрывает
  перенаправление, дописывание, `tee`, правку на месте, копирование, тело толкователя, чтение и
  заглушённый вывод.
- **Судится запись, а не всякое упоминание пути.** Чтение файла правкой не считается, иначе
  каждый поиск по дереву будил бы три гарда, и их выключили бы в первый же день.
- **Новый текст правки командой — тело самой команды.** Записываемое стоит внутри неё, и находки
  проверки называют те самые строки, которые уедут в файл.
- **Гард якорей получил поддомен спеки, а не строку в спеке гардов.** Спека гардов подошла к
  пределу длины: два сценария в ней дали бы 501 строку при пределе 500. Заодно у гарда впервые
  появилась спека и набор проб — их не было вовсе.
- **Правится источник пакета, а не разложенная копия.** Копия несёт шапку раскладки, и правка в
  ней теряется на следующей раскладке, до тех пор выглядя применённой.
