# RT-2242 — проверка либ бэкенда читала одну семью

**Ветка:** `RT-2242-lib-check-family-list` (от `RT-2240-cargo-triage-september`) · **Разобрано:** 2026-09-18

## Просьба владельца

> заводи эпик на разбор жалоб и предложений из приёмника и заводи задачи под каждый груз, бери в рработу в этом рабочем дереве

Ответ владельца о числе задач: «Пять задач, девять отметить». Эта задача вторая в стопке эпика
RT-2240. Груз: предложение `043330f3efc027785a2d861e7bcf244b4ad746096c2f7b4c26c5b59ef36d6c3c` к

## Что было не так

Проверка расположения либ читала семью бэкенда из ключа `apiFamily` одной строкой и обходила один
каталог. В дереве завелось второе серверное приложение со своей семьёй, и назвать её было нечем:
двенадцать либ обход не видел, а строка вывода осталась прежней — «36 либ бэкенда, расхождений
нет». Молчание читалось как «всё верно».

## Решения

- **Ключ `apiFamily` принимает строку и список** — строка читается как список из одного, дерево с
  одной семьёй ничего не меняет. Отклонено: новый ключ `apiFamilies` — две настройки об одном.
- **Обход идёт по каждой семье списка, итог называет семьи поимённо** — пропущенная семья иначе
  неотличима от пройденной без расхождений. Отказ пустого обхода называет корень каждой семьи.
- **Объявленная серверная семья без каталога отказом не судится** — умолчание пакета `api` стоит
  у деревьев без бэкенда, и отказ покраснел бы у них на ровном месте.
- **Ключ `apiFamily` этого дерева не тронут** — вторая серверная семья в main ещё не лежит и
  назовёт себя с эпиком чата.
- **Признак этапа снят с разложенной копии в `tools/`, а не с пути исходников** — из `projects/…`
  проверка не находит настроек дерева и отвечает пропуском.

## Цена

Четыре модуля проверки, сценарий SC-AK-1131 (набор вырос с 17 до 22), утверждение с привязкой и
строка истории в описании домена hooks. Строка итога с именами семей тестом не покрыта: для неё
нужен домен бэкенда без единого расхождения, а фикстура набора такого не держит.
