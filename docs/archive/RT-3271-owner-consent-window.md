# RT-3271 — согласие владельца одним окном, без угадывания

Задача RT-3271 эпика RT-3302, ветка `RT-3271-owner-consent-window` от ветки эпика
`RT-3302-checks-rework-3`, 16.11.2026. Бывший адрес — `docs/tasks/RT-3271-owner-consent-window/`.
Что стало правилом:

- проверка конца эпика спрашивает владельца окном и не читает запись разговора — подобласть
  `docs/specs/agent-kit/epic-stop/`, сценарии SC-AK-979, 981, 982, 1558–1561;
- новая работа после конца эпика берётся по слову владельца в окне — статья правила `turn-conduct`
  о конце эпика;
- цитаты одобрения кита владелец подтверждает в окне на открытии PR — правило `kit-approval` и его
  спутник;
- случай SC-AK-1039 судит только стражей, которые отказывают.

## Просьба владельца

Задача #3271 заведена по эпику RT-3302. Её текст:

> Проверки ищут согласие владельца в тексте разговора по словам. Настоящее «да» не засчитывается, и
> владельца переспрашивают: 13.11.2026 — три раза об одном решении. Постороннее «да» засчитывается:
> на настоящей записи разговора проверка конца эпика пускает восемь посторонних ответов из двадцати
> трёх.
>
> На создание задачи, новую ветку и открытие PR проверка возвращает приложению решение «спросить».
> Владелец видит окно «разрешить / запретить» на конкретную команду. Чтение согласия из записи
> разговора удалить из проверки конца эпика, проверки разбора и проверки одобрения.

Работа шла без владельца по его слову «работай дальше в автономном режиме» (16.11.2026). План
владелец одобрил утром: «Одобряю plan.md RT-3271».

## Решения

- **Вопросы закрыты решениями по умолчанию**, у каждого — откуда и цена ошибки: владельца не было.
- **Проверка одобрения кита перешла на окно.** Запись одобрения обязательна, цитаты подтверждает
  владелец в окне на `gh pr create`. Решено после разбора плана ролью `goal-critic`: проверка стояла
  и на открытии PR, это пункт задачи. Цена — набор перед отправкой окна не имеет и проверяет только
  наличие записи.
- **Чтения слов владельца движком хода работы вынесены в задачу RT-3352.** Их заказал владелец в
  RT-3329; слово «стоп» остаётся — это остановка, а не согласие.
- **Перенос колонки в работу больше не судится**: иначе одно решение «взять задачу» давало три окна.
- **Судится только запуск команды.** На записи 13.11 два отказа из шести достались чтению
  `task-new.mjs` и скрипту, правившему саму проверку.
- **Прогон на настоящей записи 13.11 — признак готовности.** Настоящих отказов в ней 8, а не 13:
  пять раз фраза отказа стояла в выводе других команд. Было `ask 0 pass 2 deny 6 of 8`, стало
  `ask 6 pass 2 deny 0 of 8`.
- **Проверки шагов с ожиданием «= 0» заменены с `|| true`**: `grep -c` при нуле выходит с кодом 1, а
  форма числа требует кода 0. Шаги 1.1, 1.2, 3.1, 4.1.
- **Окно в приложении живым вызовом не проверено**: эпик в дереве не кончился. Опора — документация
  хуков Claude Code: решение «ask» показывает окно и в режиме auto.
