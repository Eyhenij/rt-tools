# Постмортемы

Разбор происшествия, у которого нет исправляемого кода: исполнитель сделал не то, слой правил
это не отбил, и владелец заплатил заходом. Читают это, когда похожее случилось снова, — чтобы
не разбирать во второй раз с нуля.

Запись делается в тот же заход, когда происшествие случилось. Через день механизм промаха
пересказывается уже приглаженно: остаются выводы, а из них правило не выводится.

## Что сюда попадает

- **Механизм промаха по шагам** — что исполнитель принял за данность, откуда взял, чем
  подтвердил. Не «был невнимателен», а последовательность, которую можно повторить.
- **Что было доступно до промаха** — файлы, команды и уже прочитанное, где ответ лежал.
  Отсюда видно, промах это или нехватка данных.
- **Чем ловилось** — какая проверка сработала, какая промолчала, какая сработала поздно.
- **Что из этого ушло в слой правил** — предложение в `.claude/rt-kit/proposals/` или правка
  закона, правила, паттерна. Запись без этой строки — жалоба, а не разбор.

## Чего здесь нет

- **Разбора дефекта в коде.** У него есть спека, и объясняет его она.
- **Оценок исполнителя.** Разбирается механизм, а не намерение: правило пишется по механизму.
- **Правок задним числом.** Запись правится, только если описывала произошедшее неверно.

## Как называется запись

`<год>-<месяц>-<день>-<короткое имя>.md`. Имя называет промах, а не задачу, на которой он
случился: задача закроется, а промах повторится на другой.
