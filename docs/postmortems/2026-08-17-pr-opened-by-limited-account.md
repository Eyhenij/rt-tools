# PR открыт машинной записью, хотя правило уже называло это невозможным

17 августа 2026 года, задача RT-793. Работа была готова, набор гейта зелёный; PR открылся
номером 811, метки, исполнитель и ревьювер встали, и владельцу был назван этот номер. Владелец
ответил, что открытого PR не видит. Ограничение машинной записи было к тому моменту описано в
спутнике правила поставки отдельным разделом — с признаком, с двумя проверочными вызовами и с
готовым обходом.

## Механизм по шагам

1. Правило поставки прочитано целиком, паттерн коммита и PR — тоже. В паттерне сказано:
   «PR открывают токеном учётной записи машинной работы». Это и было взято за данность.
2. Спутник правила — `implementation.md` рядом — за этот ход не открывался ни разу. Именно там
   лежат два раздела: об ограничении записи хостингом и о том, что PR, открытый ею, владельцу не
   виден. Оба написаны за три дня до этого захода.
3. Первая попытка открыть PR отказала по исчерпанному пределу запросов машинной записи. Это был
   тот самый признак — квота у неё срезана до анонимной, — и он был прочитан как «сегодня
   исчерпали», а не как «запись ограничена».
4. Отказ обойдён вызовом REST вместо языка запросов. Обход сработал: PR завёлся.
5. Ответ хостинга прочитан — номер, черновик, автор, метки, ревьювер. Всё сошлось, потому что
   читалось токеном той же записи, которая PR и открыла.
6. Проверка чужими глазами не делалась вовсе. Токеном владельца PR запрашивался — и отвечал «не
   найдено», — но это было списано на задержку хостинга, а не прочитано как ответ.

## Что было доступно до промаха

- `.claude/skills/git-workflow/implementation.md`, раздел «PR, открытый машинной записью,
  владельцу не виден — и это то же ограничение»: признак, два вызова для проверки и обход —
  открывать `gh pr create` без токена записи.
- Там же разделом выше — об ограничении самой записи и о том, что заведённое ею для остальных не
  существует.
- Передача захода, лежащая вне дерева, называла тот же признак с другой стороны: заведение
  задачи падает на исполнителе по умолчанию, потому что хостинг не разрешает машинное имя.
- Профиль дерева `.claude/rt-kit/project.sh` говорит прямо: «Исполнителем задач при этом стоит
  владелец, а не машинная запись: хостинг её ограничил, и заведённое ею для остальных не
  существует».

Ответ лежал в трёх местах, два из которых за этот же заход читались — профиль целиком и
передача целиком. Нехваткой данных это не было.

## Чем ловилось

- **Правило поставки** — не ловит: его статья говорит про запрет автору быть ревьювером, а не
  про видимость. Ограничение живёт в спутнике, и загрузка правила спутник не приносит.
- **Ответ хостинга на открытие** — не ловит по устройству: он приходит той же записи, которая
  открыла, и для неё PR существует.
- **Сверка очереди работ** — поймала бы: PR машинной записи в её списке не появится. Не звалась.
- **Владелец** — поймал сразу, первой же фразой. Он и есть тот, кому PR был невидим.

Между открытием невидимого PR и словом владельца прошло около двадцати минут, за которые
исполнитель успел назвать номер, обновить тело PR, перевести колонку задачи и записать номер в
ход работы — четыре следа, каждый из которых пришлось переписывать.

## Что из этого следует

- **Раздел правила и спутник рядом с ним — один текст, а не два.** Правило говорит, что должно
  быть верно; спутник говорит, чем это верно здесь и что здесь сломано. Прочитанное правило без
  спутника даёт готовый приём, который в этом дереве не работает, — и выглядит при этом
  исполненным по правилу.
- **Отказ по пределу запросов — признак, а не помеха.** Обойдённый другим вызовом, он унёс с
  собой единственный сигнал о том, что запись ограничена. Отказ, обходимый вторым способом,
  сперва читается: почему отказал именно этот путь.
- **Заведённое проверяется той стороной, которой оно предназначено.** Ответ хостинга своей же
  записи полнотой не является: PR открывается для владельца, значит и читается его глазами —
  вызовом без токена записи, до того как номер назван вслух.

Предложение отправлено: раздел о загрузке правила должен приносить спутник вместе с ним —
сегодня их две разные загрузки, и вторая забывается ровно в тех местах, где дерево расходится с
пакетом. Что закрывается: ничего из надстроек этого дерева — они и так говорят об ограничении,
их просто не читают вместе с правилом.
