# Словарь проекта

Слова, которые в этом дереве значат что-то определённое. Читается перед тем, как написать спек,
правило, комментарий, тело коммита или описание PR: слово отсюда употребляется в том
значении, что здесь, а слово не отсюда либо заводится здесь же, либо заменяется простым.

Термины одного домена живут в разделе «Терминология» его спека — здесь только те, что проходят
сквозь весь проект.

Разделы ниже везёт пакет: это слова слоя правил, и значат они одно и то же везде, где он стоит.
Предметные слова дерево дописывает своими разделами через надстройку — они сливаются сюда по
заголовкам, и правка пакета их не трогает.

## Слой правил

| Термин                    | Что это                                                                                                                                                          |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Закон                     | Файл в каталоге конституции. Говорит, что должно быть верно, и не знает ни путей, ни имён файлов. Верен для любого приложения этого класса                       |
| Законы приложения         | Слой законов, верных только для этого приложения: деньги, локали, доступ. Предметность в них законна — она их предмет                                            |
| Правило                   | Скил с `kind: rule`. Привязывает закон к этому дереву: чем это здесь названо и где лежит                                                                         |
| Паттерн                   | Скил с `kind: pattern`. Готовый код и порядок действий; стоит при правиле                                                                                        |
| Компаньон                 | Файл `implementation.md` рядом с правилом: имена и пути этого дерева. Пакет знает приём, но не знает имён — их пишет проект                                      |
| Спек                      | Описание домена: как он работает. Говорит об установившемся, а не о предстоящем                                                                                  |
| Домен                     | Предмет, у которого свой спек. Выросший домен делится на поддомены, а не на соседние домены                                                                      |
| Сценарий                  | Наблюдаемое поведение под номером `SC-<ПРЕФИКС>-<НОМЕР>`. Номер стоит в заголовке теста                                                                          |
| Привязка                  | Строка `` `файл:символ` `` в компаньоне или в спутнике спека — место, где утверждение исполняется                                                                |
| Спутник                   | Файл рядом со спеком или правилом: компаньон, перечень сценариев                                                                                                 |
| Договорённость о продукте | Как продукт себя поведёт, записанное до кода. Единственное место, где спек говорит о будущем; после выкатки вливается в спек домена, а директория удаляется      |
| Ресурс                    | Единица того, что везёт пакет правил: закон, правило, паттерн, гард, проверка, роль, команда, конвейер, шаблон, умолчание, документ                              |
| Раскладка                 | Перенос ресурса из пакета в дерево по его роду и настройке слоя                                                                                                  |
| Разложенный файл          | Файл в дереве с шапкой пакета. Правится не на месте, а надстройкой: правка на месте теряется на следующей раскладке                                              |
| Надстройка                | Файл дерева, который сливается с разложенным по заголовкам разделов                                                                                              |
| Наблюдение                | Строка о событии слоя правил: правило загружено, гейт отбил, гард отказал. Пишет гард, живёт в дереве, наружу уезжает счётчиками. Журналом не называется         |
| Сводка                    | Что наблюдения говорят за отрезок дней: чем пользовались, чем ни разу, обо что спотыкались                                                                       |
| Предложение               | Готовая формулировка правки правил с адресом: пакет, компаньон или дерево. Приносит разбор закрытой задачи или слово посреди работы, отправляет человек командой |
| Слово                     | Реплика человека посреди работы о слое правил: что мешает, чего не хватило, что сработало не так. Ложится блоком в файл предложений, а не живёт до конца захода  |

## Работа

| Термин          | Что это                                                                                                                                                                                                                                                                       |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Задача          | Единица работы в очереди работ. Заводится до ветки, и номер её стоит в имени ветки и в заголовке PR                                                                                                                                                                           |
| PR              | Заявка на слияние: то же название, что у задачи, переведённое в сделанное. Отчётом, пул-реквестом и мёрдж-реквестом не называется — ни в файлах, ни в разговоре                                                                                                               |
| Очередь работ   | Доска, на которой видно состояние каждой задачи. Ветки она не видит                                                                                                                                                                                                           |
| Папка задачи    | Одна работа от разбора до слияния: разбор просьбы, замысел, ход работы. Умирает со слиянием — разбирается, и объясняющее решение уезжает в архив                                                                                                                              |
| Разбор          | Расспрос владельца до первой правки. Записывается его словами и задним числом не переписывается                                                                                                                                                                               |
| Замысел         | Файл папки задачи: след задачи и этапы с признаками готовности. После написания не правится — с ним сверяют результат при приёмке                                                                                                                                             |
| Ход работы      | Файл папки задачи: «Где стоим», решения по ходу с причинами, записи заходов. Единственное место, где отмечается сделанное. Журналом не называется                                                                                                                             |
| След задачи     | Раздел замысла: какие спеки, законы, правила и части кода работа задевает                                                                                                                                                                                                     |
| Заход           | Одна сессия работы над задачей. Работа живёт дольше одного захода, и между ними её состояние держит только ход работы                                                                                                                                                         |
| Заполнение окна | Доля места захода, которую он уже занял: вход, запись в кэш, прочитанное из кэша и вывод последнего ответа, делённые на размер окна. Не «расход» и не «бюджет»: речь о месте, а не о деньгах                                                                                  |
| Передача        | Текст, которым заход закрывается: рабочее дерево, ветка, задача, где лежит ход работы, что сделано, следующий шаг, особенности захода. Кладётся вне дерева и не коммитится                                                                                                    |
| Эпик            | Серия задач одной темы, выполняемых в назначенном порядке. Живёт в двух местах сразу: карточка в очереди работ с меткой эпика и замысел рядом с ней — что за возможность разрабатывается, какие задачи входят и в каком порядке. Шире одной ветки. Линией работ не называется |
| Архив           | Записи о состоявшемся: что объясняет закрытое решение. После выкатки не правится                                                                                                                                                                                              |

## Проверки

| Термин                | Что это                                                                                                                     |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Гард                  | Хук агента, который отбивает действие до того, как оно сделано, и говорит, чем отказ снимается                              |
| Гейт                  | Требование, которое пропускает действие один раз за сессию после того, как выполнено: загружено правило, пройдены проверки  |
| Отказ в пользу работы | Устройство гарда, при котором любая его поломка пропускает действие. Сломанный гард не имеет права остановить работу совсем |
| Прогон                | Запуск набора сценариев. «Тесты гоняются», а не «запускаются в работу»                                                      |
| Сверка                | Проверка, которая ничего не правит, а называет расхождения: раскладки с пакетом, спеков с кодом, очереди работ с ветками    |
| Замер                 | Число, снятое с работающего приложения. Взгляд на экран замером не является                                                 |

## Так не пишем

| Так не пишем                | Пишем так                                                                                      |
| --------------------------- | ---------------------------------------------------------------------------------------------- |
| спека (о тесте)             | тест — файл рядом с исходником; спек — документ. Одна буква разницы, а значения противоположны |
| таска, тикет                | задача                                                                                         |
| пул-реквест, мёрдж-реквест  | PR, а действие — слияние                                                                       |
| отчёт (о заявке на слияние) | PR; отчёт — сводка данных, и слово занято ею                                                   |
| джоба, пайплайн             | конвейер и его шаг                                                                             |
| хендофф                     | передача                                                                                       |
| бэклог                      | очередь работ                                                                                  |
| линия работ                 | эпик                                                                                           |
| контекст-виндоу             | окно захода, а его доля — заполнение окна                                                      |
| скилл, скилы                | правило, паттерн или скил без закона — по тому, что это на самом деле                          |

## Киты и витрина

| Термин        | Что это                                                                                                                                                              |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Кит           | Пакет компонентов, который уезжает потребителю. Их два — `@rt-tools/ui-kit` и `@rt-tools/ui-kit-v2`, — они разведены намеренно и общего кода не имеют вовсе          |
| Витрина       | Стенд, на котором компоненты кита показаны вживую. У каждого кита своя, со своим портом и своей обвязкой; приём, снятый с одной, на второй неверен молча             |
| История       | Один показ компонента на витрине: набор входов, при которых он нарисован. Не «стори» и не «кейс»                                                                     |
| Обёртка       | Демонстрационный компонент рядом с историей. Держит изменяемое состояние, которого сигнальному входу кита не дать, и в пакет не едет                                 |
| Ось           | Один вход компонента со всеми его значениями. Компонент покрыт, когда каждая ось показана целиком, а не когда до значения можно доехать переключателем               |
| Матрица       | Показ, в котором значения оси разложены рядом и подписаны. Оси перемножаются только там, где видно влияют друг на друга                                              |
| Снимок        | Кадр истории, сверенный с эталоном. Отвечает на вопрос «выглядит ли так же, как раньше», и молчит о том, почему разошлось                                            |
| Эталон        | Закреплённый кадр, с которым сверяется снимок. Снимается после того, как на кадр посмотрели глазами, и пересъёмывается по одному                                     |
| Обход историй | Прогон, открывающий каждую историю и проверяющий, что в кадре вообще что-то есть. Зелёные снимки на это не отвечают: пустой кадр сам стал эталоном                   |
| Токен         | Переменная оформления `--rt-*`. Оформление берётся токеном, а не значением на месте. Токен доступа к чему-либо называется полным именем, коротко — только оформление |

## Разбор происшествий

| Термин       | Что это                                                                                                                                                            |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Происшествие | Заход, в котором исполнитель сделал не то, а слой правил этого не отбил. Дефект в коде происшествием не является: его объясняет спека                              |
| Постмортем   | Запись в `docs/postmortems/` о происшествии: механизм промаха по шагам, что было доступно до него, чем ловилось и что из этого ушло в слой правил                  |
| Механизм     | Последовательность, которую можно повторить: что принято за данность, откуда взято, чем подтверждено. Пишется вместо оценки исполнителя — правило выводится из неё |

## Домены этого дерева

Домен здесь — пакет под `projects/` или приложение под `apps/`, и спек его лежит в
`docs/specs/<домен>/`. Часть пакета своим доменом не становится: она поддомен.

| Термин         | Что это                                                                                                                                |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Публичный вход | Файл `public-api.ts` пакета. Символ, до которого потребителю нет дороги отсюда, ему не поставлен, чем бы он ни был помечен в исходнике |
| Потребитель    | Приложение, поставившее пакет из реестра. Внутри дерева его нет, и проверить правку на нём нечем — отсюда витрина и снимки             |
| Выпуск         | Отправка пакета в реестр. Отдельное решение владельца, а не хвост работы: слияние PR пакета не публикует                           |

## Приём груза

| Термин         | Что это                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Приём          | Служба, принимающая груз от деревьев, где стоит слой правил. Закрытая: без токена дерева она не отдаёт ничего, кроме пробы живости             |
| Груз           | То, что уезжает с дерева одним прогоном отправки: сводка наблюдений со снимком надстроек, предложения и разборы происшествий                    |
| Род груза      | Один из трёх: сводка, предложения, разборы. У каждого своя операция приёма — общая «принять что-нибудь» перекладывала бы разбор формы на приём  |
| Дерево         | Репозиторий, откуда груз приезжает. Две рабочие копии одного репозитория — одно дерево: считаются деревья, а не машины и не люди                |
| Признак дерева | Короткое значение, которым дерево называет себя в грузе. Считается хешем от адреса репозитория: адрес по нему не восстанавливается              |
| Токен дерева   | То, чем дерево представляется приёму. Приём держит только хеш; сам токен печатается один раз, при выдаче, и второй раз показать его неоткуда    |
| Отзыв токена   | Пометка о том, что токен больше не принимается. Токен не удаляется: по нему читается прежний груз                                               |
| Запись месяца  | Свод одного дерева за один календарный месяц. Одна на пару «дерево — месяц»: нашлась — дописывается, не нашлась — заводится                     |
| Снимок надстроек | Состояние дерева на момент отправки: какие разделы каких ресурсов пакета оно замещает, дописывает и снимает. Содержимого правок в нём нет     |
| Невыбранное    | Ресурс пакета, который дерево не разложило вовсе. Отказ от ресурса — такой же ответ о тексте пакета, как правка его раздела                     |

## Админка приёма

| Термин              | Что это                                                                                                                                    |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Админка             | Приложение, которым человек читает принятый груз. Правок груза в ней нет вовсе: приём принимает, админка читает                            |
| Учётная запись      | Имя и пароль одного человека. Заводится, меняет пароль и отключается командой строки запуска приёма — из веба записей не заводят           |
| Вход                | Состояние, в котором приём знает, кто спрашивает. Живёт сроком, обрывается выходом и не заменяет токена дерева                             |
| Раздел              | Экран админки со своим адресом. В раздел ведёт пункт меню, и пункт заводится вместе со своим экраном                                       |
| Список              | Страница раздела: строка на запись, тулбар над ней и переключатель страниц под ней. Собран таблицей кита, а не своей разметкой             |
| Тулбар              | Полоса над списком: отбор, поиск и действия над списком целиком. Действий над одной записью в ней нет                                      |
| Панель подробностей | Панель с одной записью целиком, выезжающая по нажатию на строку. Не «модалка» и не «попап»                                                 |
| Отбор               | Условие, сужающее список. Сужает показанное, а не доступ: вошедший видит груз всех деревьев                                                |
| Выборка             | Страница, её размер, порядок и отбор вместе. Живёт в адресе раздела, чтобы переживать перезагрузку и передаваться ссылкой                  |
